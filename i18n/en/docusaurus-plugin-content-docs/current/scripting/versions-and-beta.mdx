## Version scheme

All script modules use semantic versions (major.minor.patch with an optional suffix). This number is separate from the Minecraft product version (for example `1.19.60`) and goes up when the API surface changes. Modules come in three tracks (Source: ms-learn, `creator/Documents/scripting/versioning.md`).

| Track | Example | Rule |
|---|---|---|
| stable | `1.1.0` | A finished API. Within the same major, minor and patch are backward compatible. A dependency of `1.3.0` must work even if `1.8.0` fills it in |
| beta | `1.3.0-beta` | No compatibility guarantee. Properties and methods can disappear even on a minor bump, and the beta number goes up with each release. The "Beta APIs" experiment must be turned on in the world |
| internal | `1.4.0-internal` | Does not work in custom packs and has no support |

Use stable where possible, and a published pack lists the highest version supported at release time as its dependency. A major bump (v2) is a cleanup that breaks backward compatibility, and existing packs that specify `1.x.x` will keep being supported to work as they are for a long time (Source: ms-learn, `v2-overview.md`).

## Specifying versions in the manifest

```json
"dependencies": [
  { "module_name": "@minecraft/server",    "version": "2.4.0" },
  { "module_name": "@minecraft/server-ui", "version": "2.0.0" }
]
```

To follow the latest beta, use the string `"beta"` instead of a number.

```json
"dependencies": [
  { "module_name": "@minecraft/server", "version": "beta" }
]
```

With `"beta"` you do not need to fix the version on every update, but if the world's Beta APIs experiment is off, the whole script does not load. A pinned specific `x.y.z-beta.*` version breaks with every game update. If you use a wrong version, the content log prints the list of available versions, so pick from that list.

## Installing type definitions

The npm `@minecraft/server` provides types for stable and beta, and for release and Preview variants. It is types only, so it is not needed to run (Source: ms-learn, `creator/Documents/scripting/developer-tools.md`).

```powershell
npm i @minecraft/server
npm i @minecraft/server-ui
npm i @minecraft/server@beta @minecraft/server-ui@beta   # beta types
```

## APIs changed in v2

If you open your code with the 2.0.0-beta types (`npm i @minecraft/server@2.0.0-beta`), you can see right away what changed. The changes in the official overview are as follows (Source: ms-learn, `v2-overview.md`).

- `Entity.applyKnockback` takes the horizontal force as a `VectorXZ` and the vertical strength as a separate argument. To convert a V1 direction vector, normalize it and multiply by the old horizontal strength.
- `Dimension.runCommandAsync` was removed (most were not actually asynchronous). If you need async, use `system.runJob`.
- Entity `getComponents/getComponent/hasComponent` throw an exception if the entity is invalid. `EntityComponent.getEntity` and `EntityInventoryComponent.container` also throw an exception instead of returning `undefined`.
- The `isValid()` method of several classes became a read-only property `isValid`.
- `EffectType.getName` and `Effect.typeId` always include the `minecraft:` prefix.
- The `minecraft:air` item was removed (it is still valid as a block).
- `world.afterEvents.worldInitialize` was only renamed to `worldLoad`, and `world.beforeEvents.worldInitialize` was replaced by `system.beforeEvents.startup`.

## Beta and version rules from community notes

The two sections below are practical rules from the community research and a timeline of changes by release.


`*confirmed*`, `*single report*` and `**conflicting**` are reliability marks for reports. The basis of this page is community reports, and they may differ from the official Mojang documentation.

#### Module versions and beta

- **`"version": "beta"`**: Using `"beta"` without a number for `@minecraft/server`, `@minecraft/server-ui` and so on always resolves to the latest beta. It was added in the Preview and reached the release around 2025-10-28 (1.21.120). Even if an API moves from beta to stable it keeps working, but it can break if the API you use changes. `"stable"` sometimes auto-upgrades but is not reliable. *confirmed*
- **Beta APIs experiment toggle**: Beta modules/features require the "Beta APIs" experiment on in the world. If it is off, the manifest requires it so the whole script does not load, and the script itself cannot detect this (workaround: a tick.json function raises a score every tick and the script clears it; warn if the value grows). In some cases other experiments such as "Upcoming creator features" and "Experimental creator camera features" also had to be on for main.js to load. On Aternos, turn on Beta APIs under servers > world > options. Most script add-on bundles distributed for servers require Beta APIs, and there is a report that this setting is an obstacle for mobile users (*single report*).
- **Compatibility expectations of stable** (**conflicting**): There are both opinions that stable scripts do not break on updates and that they can break on updates if a deprecated API is removed. Stable APIs need no experiment toggle.
- **Marketplace packs cannot use experimental/beta APIs**; they use only stabilized APIs such as DDUI.
- **Invalid versions** (`1.0.0-beta` and so on) print "requested invalid version" with a list of available versions to the log (for example server 0.1.0, 1.19.0, 2.6.0, 2.7.0-beta, 3.0.0-alpha). Modules you do not use (gametest and so on) also cause version conflicts, so remove them.
- **Pairing server / server-ui**: A conflict such as `[@minecraft/server] 2.1.0 requested by pack vs 1.3.0 requested by server-ui-bindings` is an incompatible combination. Examples: server 2.1.0 + server-ui 2.0.0, server 2.6.0 + server-ui 1.3.0 (works), server 2.10.0 + server-ui 2.2.0 (26.50), server 2.11.0 + server-ui 2.3.0 (the latest stable of 2026-11). The beta pair is `2.12.0-beta.1.26.60-stable` + `2.4.0-beta.1.26.60-stable`. server 2.6.0 + server-ui 1.0.0 conflicts on `server-bindings`.
- **The highest v1 version is 1.19.0**, and v2 breaks backward compatibility. Packs that stay on 1.x can use features blocked in 2.x such as writing `EntityScaleComponent.value` (see the [scale workaround for entity components](./entities-and-components.mdx)).
- **`3.0.0-alpha`** mirrors the latest 2.x beta as is. Also, 2.x versions are always promoted to the latest internally, so type autocomplete and runtime behavior can differ (developer statement).
- **Education Edition** lags a few versions (as of 1.21.130 only server 2.4.0 stable is supported, and beta modules break with every update).
- Old pinned betas (`server 1.13.0-beta`, `server-ui 1.2.0-beta`) do not work on current versions.
