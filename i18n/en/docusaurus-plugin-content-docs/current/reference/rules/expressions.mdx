| EXP-01 | The operators you can use are `=`, `<`, `>`, `not`, `and`, `or`, `+`, `-`, `*`, `/` and the string truncation `'%.Ns' *`. | EXP-02 | `%` is not an operator. `((#c % 10) = 3)` raises an `Invalid expression` assert every time the screen opens. | EXP-03 | There are no `>=` and `<=`. A failed expression leaves the property at its default, so written to `#visible` it looks always true. Write `(a > b) or (a = b)` (the wiki also writes this form as the standard but there is no measurement record). In the CN evaluator `<=` is read as two operators and the whole expression becomes null. `(not (#v < a))` is also an alternative. On Windows 1.26.65.1 `((#v - 0) >= 10)` gave no value and `(not ((#v - 0) < 10))` was true at 10 ([measurement record](../../design/json-ui-claims.mdx#21-operators)). | measured, code (source) | Windows 1.26.65.1 | BC-facts, BW-intro, CN-run |
| EXP-04 | `<` and `>` work. The evidence is the CN evaluator, AP's use of `>`, and that expressions containing `<` in S14 were evaluated without an error. But the result that `962 < #c < 964` and `0.9 < (#c / 1000) < 1` in S14 were true is a **chained comparison so it is not evidence of a range check** (EXP-28, Appendix A C-41). The earlier record that `<` is `Invalid expression` (S9) is not followed. On Windows 1.26.65.1 `<` worked, and at 10 `(((#v - 0) > 5) and ((#v - 0) < 17))` was true while the chained `(5 < (#v - 0) < 7)` was a wrong true. `((5 < (#v - 0)) and ((#v - 0) < 7))`, with literals on the left, gave no value (cause not isolated, [measurement record](../../design/json-ui-claims.mdx#21-operators)). | EXP-05 | Even `'%.6s' * #text = 'x'` without parentheses worked because the product (truncation) is computed before the comparison. Still, write the parentheses explicitly. | working pack | - | AP 4.4 |
| EXP-06 | An expression that is too deep (`((#c + #t + (#c * #t)) = 964963)`) fails. Split it into step-by-step view bindings and put the intermediates in properties. But the CN evaluator computes up to 512 levels of nesting, so the cause of the failure may be types, not depth. If `#c` and `#t` are chest quantities they are strings (EXP-17), and string `+` is concatenation. | measured, inferred | unknown | BC-S14, CN-run |
| EXP-07 | **Containment check**: `(not ((#s - 'X') = #s))`. If `X` is contained, the erased result differs from the original. It is independent of position so there is no need to compute field boundaries. | working pack | - | BA chapters 2 and 3.3, AP 4.1, BW-form, BW-title |
| EXP-08 | **Prefix check**: `(('%.Ns' * #s) = 'X')`, N is the byte length of X. Short flags (`t`/`f`) must be cut and compared at **length+1** so that a long value starting with `f` is not mistaken: `(('%.2s' * #v) = 'f')`. | code (source), working pack | - | BC 4.1-(4), BC 6.2-2, AP 4.4 |
| EXP-09 | `'%.Ns'` cuts in **UTF-8 bytes.** Hangul is 3 bytes and letters and digits are 1 byte. Padding and truncation of fixed-width fields are computed by bytes. | EXP-10 | There was a record that `'%.Ns' * X` does not cut if `X` is a string literal, but it is wrong (measurement below). | EXP-11 | **Taking L bytes after N bytes** is done in three steps. | working pack | - | BA 3.2, AP 4.5 |
| EXP-12 | String `-` erases **every occurrence.** So padding characters (`$`, etc.) and reserved characters must not appear in the body, and the encoder must remove them in advance. On Windows 1.26.65.1 `'xaxbx' - 'x'` was `ab` and `'abab' - 'ab'` was an empty string ([measurement record](../../design/json-ui-claims.mdx#22-string-minus-and-leading-characters)). | measured, working pack | Windows 1.26.65.1 | BA 3.2, AP 4.5 |
| EXP-13 | The trick of erasing only the first N bytes, `(('@' + s) - ('@' + ('%.3s' * s))) - '@'`. | EXP-15 | The engine decides the type of an expression result **by its appearance.** A string that looks like a number (`'0'`, `'3/17'`, `'12'`) becomes a number and string comparison goes wrong. | EXP-16 | The sure way to turn a string into a number is `(#v - 0)`. `(#v + 0)` becomes concatenation (`'350'`). That several working packs (BA progress, AP item ID) and S9 (2026-09-14) worked with `* 1` was most likely because the operand was already a number (`'042'` cut with `'%.3s'` is immediately the integer 42, EXP-30). Recheck old packs' `* 1` expressions on the latest version. The `(0 + #v)` the wiki lists as an alternative works too: with a chest slot count of 4, `((0 + #inventory_stack_count) = 4)` was true in game (EXP-17). | measured, working pack, code (source), inferred | unknown | BC-S12, BC-S9, BC-facts, BA-original, AP 4.5, Appendix A C-04, BW-type, CN-run, CPR |
| EXP-17 | The `#inventory_stack_count` of a chest slot is a **string** inside expressions. In a slot holding 4, `(#count = 4)` was false while `(#count = '4')`, `((0 + #count) = 4)` and `((#count - 0) = 4)` were true. To compare with a number, convert first with `0 +` or `- 0` (EXP-16). With a count of 1 the value is empty, so `(0 + #count)` is 0 (TXT-12). Even binding it directly to `text` as vanilla does does not display (so the lang key workaround of TXT-12 is needed). | measured | unknown | BC-facts, CN-run, CPR |
| EXP-18 | Arithmetic is integer-centered. **A decimal literal with a leading digit is an integer** (EXP-27): `0.3` is 0 and `0.001` is 0, so `((#v = #v) * 0.3)` was 0 and `(#t * 0.001) = 1` was false. The true result of `0.9 < (#c / 1000) < 1` in S14 is a chained comparison (EXP-28) so it is not evidence for decimal division. | EXP-19 | A boolean is `true` 1 and `false` 0 in arithmetic. Make a factory length 0/1 with `((#mode = 'on') * 1)`. | measured | unknown | BC-facts, BC-S11, BW-type |
| EXP-20 | There are no floor and remainder operations, so you cannot pack several fields into one number and divide them back out. Compare values whole or by range. | EXP-21 | A chest screen using `(#count / 19)` and `('' + #count)` together exited the client as soon as it opened, and it was normal when both were removed. | EXP-22 | String + integer is concatenated but **in string + float the float part is empty and only the string is left.** To show a float as text, split ranges with a comparison chain or send it through an integer channel. | EXP-24 | UTF-8 byte counts: U+0000~U+007F 1 byte (letters and digits), **U+0080~U+07FF 2 bytes (including `§`)**, U+0800~U+FFFF 3 bytes (Hangul, private-use-area glyphs), U+10000 and above 4 bytes (most emoji). | EXP-25 | The format specifiers the wiki documents: `'%.Ns'` (first N bytes), `'%N.Ms'` (first M bytes padded with leading spaces to N bytes), `'%-N.Ms'` (trailing spaces), `'%Ns'` and `'%-Ns'` (space padding only).
