| ANI-03 | A **progress bar** binds `#clip_ratio` (0~1) and decides the clipped side with `clip_direction`. `clip_ratio`, `clip_direction` and `clip_pixelperfect` are not in the official schema but are properties vanilla uses. On Windows 1.26.65.1, `(#v * .01)` with `#v` 50 drew half the bar. The engine clamps the value to [0, 1] and reads a non-number as 0.0 (ANI-50). | ANI-11 | Attach an animation with `"anims": [ "@ns.name" ]` or reference it directly in a property value (`"alpha": "@hud.anim_title_text_alpha_in"`). **You can also attach an animation of another namespace to a vanilla element.** | vanilla, working pack | VN hud_screen.json:2272, AP 4.5 |
| ANI-12 | Every time a factory newly creates a control, the animation plays **from the beginning again.** That is why a toast slides in each time a title is sent. | ANI-13 | If you shrink the height of a vanished item to 0 with a `size` animation, the next items of a stack panel rise smoothly. | working pack | AP 4.5 |
| ANI-14 | The value of `destroy_at_end` in vanilla uses the name of the control the factory created (`hud_title_text`), the name of its base definition (chat: child name `chat_item`, value `chat_grid_item`) and a variable (`$toast_control`). | ANI-15 | A flipbook icon is made with `"uv": "@ns.anim"` (`anim_type: aseprite_flip_book`) + `"uv_size"` + the Aseprite JSON next to the texture (`frames[].frame`, `duration`). In the code the engine reads `frames` only as an array (`frames[].duration`, `frame.x`, `frame.y`) and has no code that reads the Hash (object) format. The frame `w` and `h` are not read. The texture and JSON have the same name without an extension, and `aseprite_flip_book` is applied only to the `uv` of an image. | vanilla, working pack, code | VN 2 uses, AP 4.7, BW-ase, 2026-11-24 Windows 1.26.65.1 decompilation |

No place was found where the animation parser reads `start_event` or `activated`. | vanilla, code | BW-doc Animations table, VN, 2026-11-24 Windows 1.26.65.1 decompilation |

| ANI-22 | An image chooses how to draw in the order 9-slice, `clip_ratio`, `tiled`, `fill`, `keep_ratio`, stretching. `clip_pixelperfect` (default on) clips in original pixel units. `color` can be `#rrggbb` as well as `[r,g,b,a]`. | code | CN |

| ANI-38 | In a window inserted into the entity chest screen with `modifications`, with the panel around the window at `layer` 50 and the `input_panel` inside it at 100, only the `inventory_item_renderer` icons were not drawn, while names, counts and backgrounds were. Lowering both to 1 drew the icons. This agrees with a community report that an item renderer at layer 100 hid items while 4 and 50 were fine (ANI-06). | ANI-39 | The colors of `gradient_renderer` cannot be changed by binding. To change colors, prepare one gradient per color and choose with `#visible`, or bind `#color` on an image with a white-to-transparent texture. | measured | CPR |

| ANI-48 | `clip_ratio` clips only when `clip_direction` is present. An image with `clip_ratio: 0.5` and no `clip_direction` was not clipped. | ANI-50 | A `#clip_ratio` value is read as a float, clamped to [0, 1] and then written to the image. So 2 is clamped to 1.0 and an image with a direction disappears, and a negative value becomes 0. A ratio of 0, static or bound, drew one square the height of the bar (20x20 px, the whole texture) at the center instead of the bar. The cause is unknown. This differs from the record where 0 looked like a full bar with `textures/ui/White`, but `White` could not be checked the same day, so whether it depends on the texture was not settled. An expression of constants only without a `#` property (`(.25)`) had its binding dropped (BND-05). | measured, code | 2026-11-24 Windows 1.26.65.1 measurement and decompilation |
