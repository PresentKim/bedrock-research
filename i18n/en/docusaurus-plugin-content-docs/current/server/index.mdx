This section covers the server side. Its topics are official BDS operation and configuration, the network protocol (RakNet, NetherNet), how a server sends resource packs, defining custom blocks, items and recipes from server code without a BP (the Dragonfly case), camera, HUD, fake blocks and chunks sent to a single player, and server performance. JSON UI and Ore UI, which run on the client, are covered in other sections; this section explains the channels the server uses to load data into that UI.

The `SpawnParticleEffect` item in [rendering/particles.mdx](../rendering/particles.mdx) says "custom server" without naming software, so it is not in the table.

Endstone and LeviLamina run on BDS, so the BDS route (Script API, `world_resource_packs.json`) applies to them as is. [server-software.mdx](server-software.mdx) describes Endstone as "a wrapper that puts Python/C++ plugins on top of BDS" and LeviLamina as "a BDS mod loader and API", and its introduction says custom software either implements the protocol directly or "wraps BDS". The same page also records that Endstone's ScriptSDK needs a `.whl` plugin and that `config/commands.json` did not work on Endstone 0.10, so you cannot assume every BDS setting carries over unchanged.

PocketMine-MP, Nukkit and PowerNukkitX have almost no dedicated coverage in the wiki. Other pages name them in comparisons or examples, and the `mentioned` cells in the table are all there is.

## Reading order

If you operate BDS, read server software, performance, and pack delivery in that order. If you build a custom server, start with the protocol basics, then move to resource pack delivery and custom content. The version scheme and pack manifest are in the basics section.
