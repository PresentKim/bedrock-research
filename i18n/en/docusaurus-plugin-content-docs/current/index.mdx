# Bedrock development wiki

This wiki collects the research needed for Minecraft Bedrock Edition development in one place. It centers on JSON UI and also covers Ore UI, server UI, the Script API, add-on content, rendering, servers and protocols, tools, engine internals analysis, and case studies.

This wiki excerpts the referenced information into the body and lists the source and license in a table at the bottom of each page. Rule IDs (`LAY-12`, `NB-07`, `C-31`, `D-05`) use the same values as the original material.

## Verification level marks

The `{...}` at the end of a rule or fact is the kind of evidence. Every page uses these marks.

| Mark | Meaning | Confidence |
| --- | --- | --- |
| `{measured}` | There is a record measured in game | High |
| `{vanilla}` | Actually used in the vanilla resource pack or data files | High |
| `{working pack}` | A distributed, working pack uses it that way | Medium-high |
| `{code}` | Confirmed by reading source, compiled output, binaries, or type definitions. Game behavior is not guaranteed | Medium |
| `{code (source)}` | The rule tables split `code`. The reconstructed engine Cinnabar (`CN`), pack and tool sources, or scripts shipped with the game were read | Medium |
| `{code (binary)}` | The rule tables split `code`. The actual client binary was read (`NB`, decompilation). The build read is in the evidence environment cell of the rule tables | Medium (for expression and variable rules `CN` is the most direct) |
| `{installed}`, `{verified}`, `{docs}`, `{record}` | Taken from the install folder, repository files, external documents, or records with no measurement conditions | Medium |
| `{community confirmed}` | Several people in the community confirmed it, or a community report was confirmed by documents or code | Medium |
| `{inferred}` | Judged from the evidence above | Low |
| `{single report}` | Only one person in the community reported it | Low |
| `{unverified}`, `{conflict}` | The evidence is unconfirmed or the sources disagree. Measure before use | Needs checking |
| `{needs measurement}` | Not verified in game | Needs checking |

The priority of judgments is `measured`, `vanilla`, `working pack`, `code`, `inferred`, in that order. When sources of the same level disagree, the later measurement wins, and if they still disagree the item stays `conflict` and is judged in the [conflict table](./json-ui/conflicts.mdx). This legend and priority are the reference for the whole wiki, and other pages point here. Community reports are marked `{community confirmed}`, `{single report}`, and `{conflict}`. Examples not verified in game are noted separately on the page.
