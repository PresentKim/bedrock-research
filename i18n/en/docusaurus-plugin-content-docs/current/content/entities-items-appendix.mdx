# Entity and item appendix

This collects the full changes by version, reference links and open questions that the [Entities](./entities.mdx) and [Items](./items.mdx) pages could not cover. The evidence is the community research notes from 2025-10-22 to 2026-11-13 (Source: private research). The verification level notation is the same as on the other pages. Note numbers are omitted and dates are kept in the text.

## Changes by version

- **1.20.0**: the item `minecraft:knockback_resistance` component was removed.
- **1.20.30**: digger `use_efficiency` introduced.
- **1.20.40**: food format for the `can_always_eat` workaround (without custom components).
- **Around 1.16**: the way of running commands by using an item was removed.
- **1.20**: `minecraft:variable_max_auto_step` has existed since then.
- **1.20.50**: minimum format needed for item tags (`minecraft:is_sword` and so on). `1.20.5` is not a valid format.
- **1.21.40**: a claim that the damage_sensor `"no"` form changed in this changelog (conflicting).
- **1.21.44**: mobs do not pick up items when mob griefing is off (behavior change, single report).
- **1.21.50**: a report that from this format on damage_sensor `deals_damage` became a string enum (broken from 1.21.50 to 1.26.0, and conflicting with a later report that `false` worked again).
- **1.21.50.25**: `minecraft:cannot_be_attacked` added.
- **1.21.60**: the `minecraft:` group form of `menu_category`. The "minecraft:weapon ... 1.21.60" error (`minecraft:weapon` cannot be used).
- **1.21.60~1.21.80 (~1.21.131)**: reports that player knockback feels lighter.
- **1.21.90**: climate variant mobs use the `minecraft:climate_variant` property. Item custom components V2 (`"ns:comp": {}`), `minecraft:custom_components` dropped, `description.category` removed (use `menu_category` instead). `remove_in_peaceful` was added in 1.21.90.20 and dropped in .25.
- **1.21.100**: `on_rider_enter_event`/`on_rider_exit_event` in `minecraft:rideable`. Raise to this or higher to avoid schema warnings. The `was_upgraded_to_1_21_100` upgrade pattern of the wolf.
- **1.21.100**: the format needed for the `kinetic_weapon` item component.
- **1.21.110**: the item format the DurabilityManager template requires. A report that `fire_resistant` works from this format.
- **1.21.114**: a report of custom door pathfinding failure.
- **1.21.120**: `fire_resistant`, `enchantable` (`/enchant`), the recommended format for custom components. The bug of items disappearing in lava was fixed. The `type` attack cooldown is accepted in this format.
- **1.21.12x**: `minecraft:copper_horse_armor`.
- **1.21.130 (2025-12, spears/Mounts of Mayhem)**: spear variables and controllers were added to player.entity.json so old copies break. `camel_husk` `spawn_with_rider`. bedrock-samples lagged behind for a while. Spear cooldown/reach (`type` attack cooldown) introduced, the `shield_patterns` first-person bug.
- **2026-01 game update**: baby mob models were added, which affects packs that override vanilla mobs and the baby armor display. The parts of an attachable that have translucent pixels became invisible.
- **26.0 / 1.26.0 (around 2026-02)**: the problem of item textures larger than 16x16 was solved, the `minecraft:damage` display bug (MCPE-180073) was solved (needs the new format), the `/reload all` pack breakage was solved, and a report that hiding with `menu_category` `none` worked. aux ID calculation rules (v26.0).
- **2026-02-11**: a report that the `can_always_eat` bug was fixed (conflicting with a report that it still does not work on 2026-05-25).
- **26.10**: a mention that the custom block tag recipe problem was fixed.
- **1.26.10**: `minecraft:pushable` is no longer parsed. The custom shield template became official with @minecraft/server 2.6.0. Confirmation that Holiday Creator Features food `on_consume` is invalid. The latest format (1.26.10) is needed for spawn egg baby interaction. Item catalog format 1.26.10.
- **1.26.13**: a `saturation_modifier` string gives "invalid numeric value".
- **Preview 26.20**: splitting spawn without a runtime ID (spawn-on-death).
- **1.26.20**: entity version upgrade system (`entity_version.upgrades`, beta). bridge. does not support this format. A report that the `minecraft:angry` broadcast did not work in this format.
- **After 26.2(x)**: a report that `move_to_block` is broken.
- **2026-04-24**: shooter bugs MCPE-228333/228332 fixed.
- **2026-05-02**: `slot.armor.body` of `minecraft:wearable` stopped working (MCPE-238263).
- **2026-05-07**: the wearable stack size bug (MCPE-236344) fixed.
- **1.26.30**: ball physics components (`bounciness`, `friction_modifier`, `air_drag_modifier`, `buoyant`, `pushable_by_entity`). `deals_damage: "no"` fails and `false` works. No change in the move_to_block tag format. The `interact_button` onUse bug persists. From 26.30.28 `record` custom sounds (Beta APIs, `format_version: "beta"`).
- **1.26.40 (2026-08, game 26.44)**: the latest entity format. The `recipe_smithing_transform` base must be equipment and needs `durability` (MCPE-242206).
- **2026-08 stable patch**: projectile damage proportional to speed (6 -> 100 or more when power exceeds 50).
- **Around 2026-08-11**: custom music disc playback time and ejecting fixed (the description is still broken).
- **26.x "tiny takeover"**: baby animals look gigantic when used with old health display packs.
- **26.40**: a report that custom template smithing and the `minecraft:transform_materials` tag addition work (conflicting), and the result `transformable_items` needs one of durability/enchantable/wearable.
- **format 1.26.50**: smithing `addition` `{"tag": ...}` still does not work. `interactions` of `minecraft:interact` must be an array.
- **26.50**: a report that the lang key of custom item tooltips uses the `tile.` prefix.
- **Preview 1.26.70.21 (2026-10)**: atomic client entities.
- **State in 2026-10~11**: a remark that item mesh support is gone (large textures need a model + an attachable), the custom entity render distance limit of about 64 blocks remains, attachable locators are still impossible, and the bundle weight modifier is still ignored.

## Supplement: detailed reports that were summarized away on this page

The detailed items trimmed while writing the [Entities](./entities.mdx) and [Items](./items.mdx) bodies were restored in the section order of the research notes. Some sentences may overlap with the body.

### 1. Entity file basics, format_version, error resolution

- **Atomic client entities**: appeared in Preview 1.26.70.21 (see [https://gist.github.com/theaddonn/79745d88f86710003b18efc5919c0b66](https://gist.github.com/theaddonn/79745d88f86710003b18efc5919c0b66)). Animations must be duplicated per piece and are not shared. It seems related to companions or persona pieces, and the release is slow and may be behind a treatment. (unverified)

### 2. Component groups, events, timers

- **Event debugging**: put `say` in an event with `queue_command` to see whether it fires. Hit in survival mode to check `hurt_by_target`. The Content Log history is Settings > Creator > "Content Log History".
- **`minecraft:entity_sensor`**: detects nearby entities. See [https://wiki.bedrock.dev/entities/detecting-other-entities](https://wiki.bedrock.dev/entities/detecting-other-entities) . There is no filter that checks scoreboard values, so use tags or properties. Using `has_component` on a behavior component (`behavior.look_at_player`) did not work as expected. "No player nearby" is made with the `distance_to_player` filter. (One reporter's entity-sensor item has low confidence per the caveats.)
- **`minecraft:environment_sensor`**: fires an event with time-of-day or light filters. Repeated firing breaks things like `minecraft:breathable` (bubble flicker), so add a filter so that it fires only once. Filter list: [bedrock.dev/docs/stable/Entities](https://bedrock.dev/docs/stable/Entities), [https://learn.microsoft.com/en-us/minecraft/creator/reference/content/entityreference/examples/filterlist?view=minecraft-bedrock-stable](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/entityreference/examples/filterlist?view=minecraft-bedrock-stable)
- **Checking "is holding something"**: the `any_slot_empty` filter (https://[bedrock.dev/docs/stable/Entities#any_slot_empty](https://bedrock.dev/docs/stable/Entities#any_slot_empty)).

### 4. Health, damage, invulnerability

- damage_sensor `deals_damage` format 1.21.0: true/false in some versions.
- For letting projectiles pass with damage_sensor `deals_damage`, use `"no"` and avoid `"no_but_side_effects_apply"` (the projectile may explode). Around the Creaking release the damage_sensor behavior changed, so a very old format (1.16.100) may behave differently.
- **`knockback_filters`/`damage_filters`**: accept `none_of`/`all_of` lists and several can be given as an array. The friend filter of `knockback_roar` did not work for one user.
- **Damage cause list**: [https://learn.microsoft.com/en-us/minecraft/creator/reference/content/vanillalistingsreference/addonentitydamagesources?view=minecraft-bedrock-stable](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/vanillalistingsreference/addonentitydamagesources?view=minecraft-bedrock-stable)
- **Max health is set only in entity JSON**: it cannot be set with scripts, and there is a report that script setters do not update the UI. For players, set both `"value"` and `"max"` of `minecraft:health` in a player.json group (for example 22/22) and fire it with `player.triggerEvent('evt')`. This method is not compatible with other add-ons that modify player.json. Health Boost increases in units of 2 hearts and milk cancels it (refresh with tick.json).

### 5. AI, targeting, combat

- **Detection range stops at 16 blocks**: adjust `follow_range`, `max_dist`/`within_radius` and the look_at distance. There was no answer.
- **If the `nearest_attackable_target` filter is wrong**, the mob attacks the nearest entity after killing the target.
- **Do not use `delayed_attack` and `melee_attack` together on one mob**: after killing an entity that transforms on death, the mob stopped and the attack animation failed.
- **The `on_attack` event of `behavior.delayed_attack` does not fire (a bug)**: use a timer component. For a dodgeable scheduled damage attack, see the ravager.
- **`filters` of `behavior.look_at_entity` is ignored**: it looks at the nearest entity. The workaround is nearest_attackable_target with a family filter + look_at_target.
- **`behavior.barter`**: has control flags. (untested hint)

### 6. Movement, navigation, pathfinding, physics

- **Vanilla pathfinding range is short (about 16 blocks)**: for far routes, put a target or checkpoints that move step by step. `follow_range` does not extend the pathfinding range.
- **Making it walk to a destination**: spawn an invisible target entity at the destination and make the mob aim at it. Other entities are teleported step by step. Scripts have no pathfinding API. A* exists but is slow, and doing A*/Dijkstra with commands is impractical. Instead, check obstacles with `if block ^ ^ ^0.25 air` and steer with facing teleports. Another way is giving `applyKnockback`/`applyImpulse` along the route.
  - If pushed away from the target block, it can freeze for a few seconds.
  - Opening doors: `move_to_block` + `on_reach`. Selective custom doors need script pathfinding. Navigation has only door/iron-door options.
- **`navigation.walk.blocks_to_avoid`**: avoidance by tag works with `[{"tags": "query.any_tag('trapdoors')"}]`. Making blocks not count as obstacles or letting them be passed through is impossible (also with scripts), and only avoidance is supported. A block cannot declare "cannot be walked on" from its side, and that is the job of the entity-side `behavior.avoid_block`.
- **Behaving like a block (rotation/placement)**: `minecraft:body_rotation_blocked` and `minecraft:rotation_axis_aligned` (https://[bedrock.dev/docs/beta/Entities#minecraft%3Arotation_axis_aligned](https://bedrock.dev/docs/beta/Entities#minecraft%3Arotation_axis_aligned)).
- **`rail_movement` entities are lifted above rails** ([https://bedrock.dev/entities/non-mob-runtime-identifiers](https://bedrock.dev/entities/non-mob-runtime-identifiers)). Fix it with `tryTeleport` with the keep-velocity option.

### 7. Riding (rideable) and seats

- **Rotation snapping**: the rotation jumps when a custom mount passes a certain angle. `lock_rider_rotation`/`minecraft:rotation_locked_to_vehicle` jump or turn slowly. Minecarts are fine but no method was found.
- **Happy ghast / ghastling**: a moving platform (elevator) you can stand on. If it is too fast the player falls through. You can stand on top with `"minecraft:is_collidable": {}`.

### 8. Projectiles

- **Some components need a runtime ID**: the only answer was to ask theaddon for the list. Avoid runtime_identifier if possible.
- **Arrow improvement tips**: remove the "conditional bandwidth" component, turn off arrow inaccuracy, and enlarge the hitbox slightly. (single report)

### 9. Breeding, taming, age

- **Script taming**: after spawning, `entity.getComponent("minecraft:tameable").tame(player)`, and fire `minecraft:on_tame` if needed. The entity needs follow_owner, tameable and sittable (owner_hurt* to fight). Setting the owner with scripts skips the food taming logic and eating particles but hearts appear. You can also spawn it tamed by adding the tamed group with an event. One per person taming: `EntityIsTamedComponent` (https://jaylydev.github.io/scriptapi-docs/latest/classes/_minecraft_server.EntityIsTamedComponent-1.html). Releasing the owner is done with the tame component.
- **Entity leash**: `minecraft:leashable` `on_leash`/`on_unleash`. When the leash breaks, `on_unleash_interact_only: false` is needed for `on_unleash` to fire (MicrosoftDocs/minecraft-creator issue 962). Leash knot behavior changed and broke the wiki's movement detection trick. Use an egg/snowball/arrow/experience orb, not a minecart.
- **Custom sheep**: even with a sheared-state behavior, it cannot be sheared with a dispenser. (no answer)

### 10. Spawn rules, despawn, persistence

- **Spawning on custom blocks** (conflicting): there is a report (SmokeyStack) that mobs cannot spawn on custom blocks. On the other hand there is also a report that if the custom block is defined in `blocks.json` (with geometry and material_instances removed) or is `minecraft:geometry.full_block`, spawn rules treat it as "solid". Spawning not working on custom blocks in a custom biome was reported as a bug (2026-03-17).
- **Hardcoding of the monster `brightness_filter`**: behind it is the engine's light limit, so even removing it does not make mobs spawn in bright places. (unverified, tester's finding)
- **Peaceful**: `monster` type mobs despawn. A workaround idea was to put them on the player with the parrot_tamed family.
- **The torch spawner behaves strangely on custom mobs**: not resolved.

### 11. Inventory, equipment, names, boss bar, loot

- **Entity inventory title "Unknown"**: an entity name lang entry is needed (`tile.x.name` did not work). There is also a report that `nameable` is needed. It also appears when a custom UI uses it. (One reporter's explanation of the cause is unverified per the caveats)
- **Equipment of non-player entities cannot be read or written by scripts**: the `equippable` component supports only the player type. Use `/replaceitem` as a substitute (setEquipment may work), and enchantments of other entities (such as piercing on a pillager's crossbow) cannot be read either. Scripts cannot add components to vanilla spawned entities.
- **The count of a dropped item cannot be changed**: despawn it and spawn it again with the new count. Canceling cactus damage on an item entity hides it on the client but it can still be picked up, a bug. There is a report that modifying entity/item.json (gravity, name tag) no longer works (2026-08-08, not resolved).

### 12. Entity animations and animation controllers (behavior view)

- **Children of `animation_controllers` are valid only in format 1.8.0**: in 1.10.0 and above put the controller ID as a short name in `animations` and reference it in `animate` ("client_entity child 'animation controllers' not valid there"). The controller name prefix is `controller.animation.<name>`.
- **Animation not found**: check the folder name, a short name mismatch and renaming (a Blockbench/McBlend export was fine but it played after renaming). Blockbench animations may contain `NaN`, so change it to `0`.
- **Random attack animation**: controller `pre_animation: ["variable.attack_rand = math.die_roll_integer(1, 0, 2);"]`, an `attack_selector` state, a `query.is_delayed_attacking && variable.attack_rand == N` transition, and return to idle if `!query.is_delayed_attacking`. Another way is `math.random_integer(1, 5) == 1 && query.is_delayed_attacking`. For walk variants, put an intermediate state that sets a variable with `math.random` on entry.
- **Making a walk animation stop at the last pose**: update the walk animation anim_time with `query.modified_distance_moved / <n>` and wrap it in a `query.modified_move_speed > 0.01` state. Stretch and shrink with the speed using `anim_time_update` (for example `q.modified_distance_moved * 0.08`). If walking does not play on a replaced cow, use `pre_animation` `variable.tcos0 = (Math.cos(query.modified_distance_moved * 38.17) * query.modified_move_speed / variable.gliding_speed_value) * 57.3;`.
- **An animation that played "once when a target is first detected" replays at random**: the target seems to be reset. It is more stable to tie it to a specific behavior/event in the BP than to use only Molang states.
- **Rotation correction and wrapping**: blending between 0 and 360 jumps backward, so keep a continuous value beyond 360 in chained animations. Normalize interpolation differences to +-180. `rotation.y = -q.body_y_rotation`, which turns part of it independently against body rotation, was unstable (not resolved). `q.bone_orientation_trs().r.y` is limited to -90..90. Euler order is X, Y, Z.
- **Making the body follow the head in a cutscene**: add `- query.target_y_rotation` to the body/root (including legs), and subtract it from the head if you play it with `playAnimation`.
- **Molang keyframe interpolation (without frame definitions)**: `v.time = (v.time ?? 0) + q.delta_time;` (delta_time prevents frame rate mismatch), `v.smooth_time = math.hermite_blend(v.time)`, `v.ypos = math.lerp(v.start, v.end, v.smooth_time)`. Segment formula: `v.segment = math.min(math.floor(v.t),2); v.local_t = v.t - v.segment;`. If only one branch runs, use a `? :` chain. `q.life_time` can have bugs in easing, so use your own time variable. There is also a 2-layer structure where the client reads `v.animation_state` from an entity scoreboard value set by the server's command manager.
- **BP (server) animations/controllers**: they run only commands and Molang and do not run client animations. `/event entity @s ...`, timeline timestamp commands, `/effect` and `/replaceitem` are possible. An RP controller cannot run `/scriptevent` or commands. For a delayed repeating sound, play the sound inside a BP animation and have a controller turn it on and off. A BP animation controller runs every time the entity loads, so it can be used as an "on load" event. `q.property` placed in `variables` of a server-side controller gave an error (fixed by moving it outside). A value can be passed with `query.scoreboard` in `/playanimation`, and `query.scoreboard` works only in a BP.
- **Entity sounds**: play them with animations (`sound_effects`). The entity events (`ambient`, `hurt`, `death`, `step`) in `sounds.json` must be valid LevelSoundEvent names ("Event name 'cracked' is not a valid LevelSoundEvent"). A custom entity sound must be in both sound_definitions.json and the client file `sound_effects`. Muting rider footsteps was not resolved. The allay interaction sound is removed by overriding `mob.allay.item_given` in `sound_definitions.json`. Put repeating sounds in a `loop: true` animation.
- **Animation key query notes**: `query.equipped_item_all_tag('slot.weapon.mainhand','tag')`, `query.is_item_name_any('slot.weapon.mainhand', 0, 'ns:item')`, `query.entity_biome_has_any_tags`, `query.entity_biome_has_any_identifier`, `query.is_riding_any_entity_of_type('id')`, `query.is_in_water_or_rain`. `query.foo` is only a placeholder and not a real query. For early termination of a controller, `q.state_time` and `q.all_animations_finished`. A transition per held item `query.is_item_name_any(...)` goes with quotes in the RP animation controller, not the BP. `query.client_max_render_distance` cannot be used outside an entity context. If a render controller is applied outside an entity, it cannot read entity-only queries, so put them in variables. On a renamed armor stand, the `query.is_name_any('Alex')` transition did not fire, and there was a `;` at the end of that expression. A leftover quote in a transition expression gives "unrecognized token".
- **Armor stand poses are hardcoded in runtime ID variables (12~13)**: to add poses, put a `pose_index` property and a `math.mod(...)` event on your own entity or copy the armor stand geo. For an armor stand given equipment by a dispenser, the method of setting runtime_identifier to armor_stand, putting items in and reverting worked.
- **Reusing animations**: if bone names match the player (`rightItem`, `leftItem`, head and so on), vanilla humanoid/player animations can be reused. The held item position is decided by the `rightItem`/`leftItem` bones. Items held in a special way such as bows, crossbows, spears and shields need `"enable_attachables": true` in the client entity. Bridge does not preview animations. Bone visibility toggle: `1*(query.is_item_equipped(0)||query.is_item_equipped(1))` scale.

### 13. Render distance, dithering, shadows, hitboxes (entity-side limits)

- **Shadows**: the size follows the hitbox/scale component. Removal: [https://wiki.bedrock.dev/visuals/remove-shadows](https://wiki.bedrock.dev/visuals/remove-shadows) . To remove the shadow when invisible, `minecraft:renders_when_invisible` + infinite invisible `spell_effects`.
- **Solid entities (can be stood on)**: in the latest format put `"minecraft:is_collidable": {}` on the entity. The alternative is [https://wiki.bedrock.dev/entities/solid-entities](https://wiki.bedrock.dev/entities/solid-entities) (the stackable method also needs player.json). The happy ghast file is an example of a solid mount that can fly. (One reporter's solid-entity item has low confidence per the caveats)
- **Appearance swapping techniques (render controller arrays, overlays, overlapping two geometries, dynamic alternate geometries)**: only the parts related to behavior are written. Listing two render controllers on one entity draws two geometries overlapped. Texture overlay (the first is the base and the next is the overlay, like horses/llamas) also works. To use a custom model for only a specific variant like the tuxedo cat, see [https://wiki.bedrock.dev/entities/render-controllers#dynamic-alternate-geometries](https://wiki.bedrock.dev/entities/render-controllers#dynamic-alternate-geometries) . Texture animation needs `query.life_time` in the entity file and a render controller texture array.

### 14. Player entity (player.json / player.entity.json)

- **A custom player.json breaks rotation**: `getRotation()`/`getViewDirection()` jittered within about 30 degrees, and reverting to the sample pack version fixed it. `player.setRotation` briefly changes the value read within that tick.
- **Right click detection**: attach a BP animation controller to `minecraft:player` in player.json (`description.scripts.animate` + `animations`, the controller is in `animation_controllers/`), and use `on_entry: "/function ..."` on a state and the transition query `query.is_item_name_any('slot.weapon.mainhand','ns:item') && query.is_using_item`. Without `&&` it fires as soon as you hold it. Defining the controller twice (player.json and player.ac.json) gives a content log error.
- **Respawn screen detection**: [https://wiki.bedrock.dev/commands/on-player-death](https://wiki.bedrock.dev/commands/on-player-death) (commands) or script events.
- **Broken by the 1.21.130 spear update**: Mojang added `variable.melee_spear_equipped`, two spear controllers, a changed first-person controller and so on. Packs that override with an old copy break spear animations, swing/attack, swimming, devices, hand animations and first person, and "Unknown variable" appears. The fix is to start from the latest vanilla file in the local install (`...\Content\data\resource_packs\vanilla_1.21.130\entity\player.entity.json`, or `C:/XboxGames/MinecraftforWindows/Content/data`) and add your own animations, scripts and controllers again. Also bring the animation controllers and first-person animation files. You must use the latest player.json shared by the community for 1.21.130 and above so that spear animations and Editor skins do not break. A copy that was not updated for Mounts of Mayhem also gives spear animation errors. (confirmed)
- **There was a period when bedrock-samples lagged behind**: the 1.21.130.3 player client entity had no `first_person_item_rotation_factor`, gave spear errors and had broken empty-hand swings. pre_animation/initialize were also missing. MCBVanillaResourcePack (https://[github.com/ZtechNetwork/MCBVanillaResourcePack](https://github.com/ZtechNetwork/MCBVanillaResourcePack)) also lacked `variable.melee_spear_equipped`. Use the files in the game install folder. The bug where `/reload all` broke packs was fixed in 26.0.
- **Variables needed for spear animations**: `variable.melee_spear_equipped`, `variable.first_person_item_rotation_factor = 0.625` and so on in the player `initialize`. Spears have a separate animation controller file. After editing, restart the whole game. `query.equipped_item_any_tag('slot.weapon.mainhand','minecraft:is_spear')` was suggested for spear detection. The spear attachable error `q.item_slot_to_bone_name(c.item_slot) returned a bone name that doesn't exist` means the `spear` bone is missing and is related to a min_engine_version mismatch. A custom player render controller can break the vanilla attachable offset (spear).
- **paper doll (pause screen) errors**: "query.property/has_property does not have an actor" comes from the paper doll model. Block it with `!variable.is_paperdoll`/`!query.is_in_ui` (there is also a report that `q.is_in_ui` did not help). The paper doll ignores player.json variables and queries and shows all or hides all of the extra geometry. While the paper doll is visible, using `/playanimation` and particles creates copies, so block them with `variable.is_paper_doll`/`q.is_in_ui`. An example first-person extra render controller condition: `!variable.is_paperdoll && !variable.map_face_icon && !query.is_spectator && query.property('addon:extra') != 'x'`.
- **Invisible player**: an invalid render controller (for example `controller.render.player.dc15s`) shows in the content log. Delete leftover render controllers for guns. "friendly name 'geometry.default' not found" / "minecraft:player | geometry not found?" occurs when the geometry short name in player.entity.json and the render controller reference do not match or have a typo. If a cape is not rendered, add a new geometry key (`Geometry.default_custom`) and have the render controller point to it. The default model cannot be replaced, so add one and hide the default.
- **Custom player models and item position**: keep the `leftItem`/`rightItem` pivots the same as the default player geo (leftItem pivot [6,15,1] parent leftArm, rightItem pivot [-6,15,1] locator `lead_hold`). Do not move bones, and move the position with animations referenced by the player RP file. Adding bones breaks item placement. The workaround is to render the vanilla geometry as it is with an empty texture, overlay the custom geometry on top, and match the item position by animating a transparent arm. To attach armor you need the same bone names and structure (vanilla armor attachables control part visibility of the player render controller as in `parent_setup: "variable.boot_layer_visible = 0.0;"`).
- **First-person/third-person state**: animation states are stored separately but Molang variables are shared. When `blend_weight` using `v.is_first_person` was off, adding `+ 0.001` worked. First/third person can be distinguished with controller tags.
- **A custom player controller that reads blocked/private Molang variables** (for example `variable.first_person_rotation_factor`) breaks hit animations and the third-person bow.
- **There is a mention that the player model registration limit is about 1.14MB**. 20 entries pointing to the same model had no lag, but many different models cause lag spikes. `q.get_item_equipped_name` is more stable than `q.get_item_any`. (single report)

### 15. Scripts and entity integration

- **Per-entity animation for only some players**: play a 0-scale or outline animation with `entity.playAnimation(name, { players: [...] })`. Outline through walls example: [https://github.com/JuanLuci/Player-Outline](https://github.com/JuanLuci/Player-Outline) . The invisible variable `t.invi` trick is client-side, so it breaks when used with armor and may be patched.
- **Scripts and animations**: scripts cannot drive animation controllers directly. Use the `stopExpression`/controller option of `playAnimation` or the way (FMBE style) where a variable set by a script is read in pre-animation Molang. A method that worked was `player.inputInfo.getMovementVector()` + `stopExpression: "v.movement_x=...; return 0;"` + a random controller name per call (`"animation_controller_set_"+rand`, length 0.05) to push variables into the attachable (the property method has about 1 tick of delay). The server `player.playAnimation(name, {blendOutTime, stopExpression})` moves only third person. Vanilla first-person animations cannot be changed or triggered by scripts, so use attachables or a modified client player.
- **Floating text**: to avoid distance and occlusion problems, use the Script API TextPrimitive (https://[stirante.com/script/server/2.8.0/classes/TextPrimitive.html](https://stirante.com/script/server/2.8.0/classes/TextPrimitive.html)) instead of an entity. Before, an entity that is spawned once and teleported was the only way (collision/push problems).
- **Click detection**: [https://github.com/mittens4all/Detect-Click/releases/tag/v1.0.0](https://github.com/mittens4all/Detect-Click/releases/tag/v1.0.0) or `world.afterEvents.playerAttack`. Hotbar slot change: `world.afterEvents.playerHotbarSelectedSlotChange`.
- **Explosion detection (without damage)**: `explosionAfterEvent`. To detect an effect (for example nausea) on tagged entities, use `effectAdd` without `getEntities`.
- **Entity direction difference**: in an `anchored eyes` particle test a non-player entity faced differently from the `^^^` direction, but others could not reproduce it. (single report)

- **Dummy entities**: good for keeping tags or states even after other entities are removed. They have few components and need no resource pack, and a modified armor stand with gravity and damage turned off also works.

### 17. Item JSON basics: format_version, icon, name, creative menu

- **`minecraft:icon`**: a string component inside `components`, not `description` (`"minecraft:icon": "electrite_spear"`). Do not use the `textures.default` object form. The value is a key of `textures/item_texture.json` and uses lowercase only (uppercase gives "Missing referenced asset"). Usually no namespace is put in the key (`portal`, not `floating_dimensions:portal`). If you did use a namespace in the key, opinions split between matching it in icon the same way, that it becomes `:`, and that you should use `.`. Format 1.10 has no BP icon and defines it in the RP item file (vanilla `appleEnchanted`). "requires either an icon atlas or icon texture" means there is no icon.
- **Using vanilla textures**: vanilla keys can be used without an RP, as in `"minecraft:icon": "diamond"`. However, a texture array (pickaxes and so on) defaults to the first one and the index cannot be specified, so add an entry to your own RP item_texture.json (a short name per texture pointing to the same png). A name like `tripwire_hook` does not exist. Find vanilla texture names in the bedrock-samples resource_pack (for example heart of the sea `textures/items/heartofthesea_closed`). Data-driven bundles have separate texture keys (`bundle_white`). The name tag texture is `textures/items/name_tag.png`.
- **`minecraft:display_name` is an object**: `{"value": "..."}`, and the value can be a translation key. It supports `§` codes and `\n`. In lang it is `item.<ns:id>.name=...`. Imitating line-break lore: `item.zxx:light_soul_ring.name=§cLight Soul Ring§r\nHold on screen to activate§r`, `~LINEBREAK~` in a custom name. Name concatenation: `"%item.bucketCustomFish.name%entity.blaze.name"`. Trailing spaces in a lang value are trimmed, so attach `§r`. `pack.name`/`pack.description` are also translated in the BP and RP lang.
- **Custom groups**: `item_catalog/crafting_item_catalog.json` (`minecraft:crafting_items_catalog`, `categories[].category_name` construction/equipment/items/nature, `groups[].group_identifier {name, icon}`, `items[]`). `icon` must be an item identifier. Do not mix it with `menu_category`. Only one catalog file is allowed. [https://wiki.bedrock.dev/items/item-catalog](https://wiki.bedrock.dev/items/item-catalog) (#expandable-groups), MS doc `craftingitemcatalogdocumentation`.

### 18. Custom components and item scripts

- **Registration**: `system.beforeEvents.startup.subscribe(({itemComponentRegistry}) => itemComponentRegistry.registerCustomComponent("ns:name", { onUse, onUseOn, onHitEntity, onMineBlock, onConsume, onCompleteUse, onBeforeDurabilityDamage }))`. The old `world.beforeEvents.worldInitialize` pattern is outdated. Both the method shorthand `onUse(event){}` and `onUse: (event)=>{}` are valid. One reporter wrote the durability hook name as `beforeOnDurabilityDamage`, while another reporter's registration list has `onBeforeDurabilityDamage`.
- **`onHitEntity` event**: attackingEntity, hadEffect, hitEntity, itemStack (stirante.com/script/server/2.3.0/classes/ItemComponentHitEntityEvent.html). To detect a hit with a specific item, use the script `entityHitEntity` followed by `triggerEvent`, or an entity `damage_sensor` + `has_equipment` filter (specific entities only).
- **Script pitfalls**: `source.dimension.runCommand('spreadplayers ~ ~ 10 50 @s')` fails because @s becomes the dimension, so use `source.runCommand` or wrap it in `system.run(...)`. Writing `runcommand` in lowercase is a "Not a function" TypeError. Raycasting is `player.getBlockFromViewDirection()`, `getHeadLocation()`/`getViewDirection()`. 5x5 fire example: `afterEvents.itemUse` -> `getBlockFromViewDirection()?.block.location` -> loop -2..2 -> `dimension.getTopmostBlock({x,z})` -> `setBlockType(top.above().location,"minecraft:fire")`. On Realms, `runCommand` instead of the removed `runCommandAsync`.
- **Item NBT is not exposed to scripts**: shulker box item contents, ominous bottle effect level, goat horn sound. Place a shulker with a dispenser/block placement and read the block `minecraft:inventory`, or burn the item entity to drop the contents. To change contents it must be placed as a block. Part of the values can be checked with `data` of the `hasitem` selector, and data/aux is found with a `testfor @s[hasitem={item=...,location=slot.weapon.mainhand,data=N}]` loop.

### 20. Tools, durability, mining, enchantments

- **`minecraft:digger`**: needs `use_efficiency` (since 1.20.30) and `destroy_speeds`. Example: `{"block":{"tags":"q.any_tag('minecraft:is_pickaxe_item_destructible')"},"speed":7}`. An empty digger does nothing. To match vanilla, match the speed (netherite 9, [https://minecraft.wiki/w/Breaking#Mining_efficiency](https://minecraft.wiki/w/Breaking#Mining_efficiency), calculator "Calculators/Breaking Speed"). Also attach the `minecraft:is_pickaxe`, `minecraft:is_tool` and `minecraft:digger` tags to the item. [https://wiki.bedrock.dev/blocks/tool-based-destruction](https://wiki.bedrock.dev/blocks/tool-based-destruction) , [https://wiki.bedrock.dev/blocks/block-tags#digger-example](https://wiki.bedrock.dev/blocks/block-tags#digger-example)

### 21. Armor, trims, dyeing

- **In creative a custom armor stays in the hand while also going into the slot (MCPE-240759)**: Java also leaves it in the hotbar, so vanilla Bedrock may be the odd one.
- **Stack size of wearables**: the client did not move wearable stacks of an "illegal" size, so stacking custom armor/skulls/pumpkins was impossible. It was confirmed fixed on 2026-05-07 as MCPE-236344.
- **`minecraft:dyeable`**: parts of the texture with alpha 1 are not dyed (dyeing only part of the icon is alpha-based, see dog armor). Players cannot be stopped from dyeing it. [https://learn.microsoft.com/en-us/minecraft/creator/documents/addcustomitems?view=minecraft-bedrock-stable#dyeable-custom-items](https://learn.microsoft.com/en-us/minecraft/creator/documents/addcustomitems?view=minecraft-bedrock-stable#dyeable-custom-items)

### 22. Weapons: bows, crossbows, spears, maces, shields, guns, throwing

- **Templates**: a template that reproduces shooter with scripts (multishot and durability support). The 1.20.60 bow template no longer worked on 2025-11-07 and estrongel uploaded an updated version.
- **Custom spears in the stable release**: they use the vanilla spear item (it is in the vanilla pack). The vanilla spear JSON is in bedrock-samples (wooden/stone/netherite_spear.json, `behavior_pack/items/iron_spear.json`), but the vanilla spear attachable exists only in the real vanilla RP and not in the samples. The new spear also changed the first-person/fist animation of packs that override player animations.
- **Custom trident template**: it worked until Script API 1.19 (before 2.0.0), and few changes are needed to update it. Riptide outside water was not confirmed.
- **Mace-type items**: copy the mace JSON and rename every reference. The custom mace template (script 2.4.0, no experimental features): a `slot: "all"` enchantable to receive mace enchantments, a manager.js whitelist to remove enchantments not on the list, canceling fall damage with a teleport after the hit, and for the smash `playerSwingStart`, range 6 and checking `!attacker.isOnGround`. Wind Burst applyImpulse is inconsistent. Lunge needs beta swing detection or a `player.json` animation controller based on `variable.attack_time` (`/tag @s add ghastly` on entry, animate with `query.is_item_name_any('slot.weapon.mainhand', 0, 'custom:x')`).
- **No hit animation when an axe-type custom tool converts a block**: there was a suggestion to add `minecraft:use_animation`. (suggested) An item with the `minecraft:is_hoe`/`is_axe` tag strips/tills but does not fire the custom component `onUseOn` (`is_shovel` does fire it). Sound and particles occur, but there is no durability loss or animation, so scripts are needed, and removing the tag brings `onUseOn` back. The is_hoe/is_axe animations are also missing on blocks.

### 23. Attachables

- **First person and third person have different coordinate systems**: put a separate first-person-only animation (`c.is_first_person`). In the attachable `scripts.animate` you must use `c.is_first_person`/`context.is_first_person`, and `query.is_first_person` and `variable.is_first_person` do not work (negate with `!`). Giving the rotation/position of the bone `rightItem` as `c.is_first_person ? a : b` is also a correct method. The Blockbench first-person preview is only a starting point, so fit each axis in game by binary search and check with `/reload all`. Third person can be fit by treating it like a briefly thrown entity. The pivot position matters too. Example values: root bone (`root_item`) third person `rotation [90,0,0]`, `position [0.5,22.5,-0.5]`, first-person root rotation -180, third person 0. The default first-person player animations in bedrock-samples are a position reference (`animation.player.first_person...`, the map animation).
- **`/playanimation` and `playAnimation` do not apply to attachables**: an attachable is treated as a different entity from the player, so player animations (for example a crossbow arm pose) cannot be played. First-person animations and scopes are made with the animation controller in the attachable file. Workarounds are to play a dummy animation that sets a variable and have the attachable controller read it, or to switch with a BP player.json entity property + the attachable `"scripts":{"pre_animation":["variable.animation_a = c.owning_entity -> q.property('property:name');"]}` + `v.animation_a` (enum `== 'value'`, bool, `>= 3`). The same method can also change per-item render controllers and models. Properties introduction: [learn.microsoft.com/en-us/minecraft/creator/documents/introductiontoentityproperties](https://learn.microsoft.com/en-us/minecraft/creator/documents/introductiontoentityproperties)
- **If an attachable and a client entity share an ID**, the attachable takes priority and overrides an entity with the same ID (cod, salmon, rabbit). There is also a report that for vanilla items that are also entities (ender pearl, arrow, snowball, egg, throwable items) the client entity with the same identifier overrides the attachable. Make the animations and models of the two files the same and split parts with `q.is_attached` / `!q.is_attached`. Example: `{"controller.render.item_default": "query.is_attached"}`, `{"controller.render.thrown_item": "!query.is_attached"}`. A&S copies the entity file into an attachable with a check condition. The ender pearl attachable is placed in attachables with the identifier `minecraft:ender_pearl`, and the flying model modifies ender_pearl.entity. The thrown trident client entity can be overridden, but using a texture mesh made the model disappear, and overriding by identifier worked.
- **The vanilla two-file method**: the held display and the worn layer (for example `netherite_helmet.json`, `netherite_helmet.player.json`). The worn layer uses `parent_setup` (for example `v.chest_layer_visible = 0.0;`, `variable.helmet_layer_visible = 0.0`), geometry `geometry.player.armor.chestplate`, materials `armor`/`armor_enchanted`, textures `textures/models/armor/...` and the render controller `controller.render.armor`. When using a whole set with one model, hide unrelated bones with the part visibility of the attachable render controller. Armor is an attachable so it can also have animations. There is only one attachable per identifier, so if you want a large armor icon, combine the item attachable and the armor attachable and pick the geometry/texture with a render controller. To show it only when equipped, use a custom armor variable (or scale 0), or inflate the cubes and seat them over the second layer. [https://wiki.bedrock.dev/items/custom-armor#attachable-json](https://wiki.bedrock.dev/items/custom-armor#attachable-json)
- **Vanilla armor on custom geometry entities**: put `"enable_attachables": true` in the RP client entity `description`. Vanilla armor follows humanoid geometry, so for non-humanoid models make per-part attachables and geometry (helmet, chestplate, leggings and boots separately) in RP `attachables/`. To apply to only one entity, use a unique attachable identifier (for example `minecraft:diamond_helmet.jenny`) and the `item` map Molang condition `"item": {"minecraft:diamond_helmet": "query.owner_identifier == 'ns:jenny'"}` (reusing the vanilla identifier changes every mob wearing that armor, Mojang sample `resource_pack/attachables/diamond_helmet.player.json`). The item ID must be exact (`minecraft:diamond_chestplate`, not `diamond_chest`). If wrong, nothing shows even in the content log. Animate the vanilla `animation.armor.chestplate.offset` / `animation.armor.helmet.offset` and use `armor`/`armor_enchanted` for body armor and `entity_alphatest`/`entity_alphatest_glint` for helmets. If the chestplate shoulders do not follow NPC animations, you need your own geometry used as an attachable. Detecting a non-player wearer: `q.owner_identifier != 'minecraft:player'`. Hiding armor parts by property: `"part_visibility":[{"head":"q.has_property('test:your_property') ? q.property('test:your_property') != 1 : true"}]`.
- **Dyed armor on custom entities**: needs a custom render controller that handles normal/dyed x enchanted/unenchanted and a dedicated material (`custom_armour.render_controllers.json` shared by thediamondblue1). Remaining unresolved: leather armor dye color, netherite trim, and the turtle helmet effect on custom entities. T-Rex armor worked only with copper and the cause was not found.
- **Equipping gear with UI/scripts (Jenny companion)**: reads the entity `minecraft:inventory`/equippable and copies durability and enchantments. Shows a form with buttons only for armor in the player's inventory, and returns it when removed.

### 25. Recipes, smithing, item tags

- **Recipe rules**: only shaped recipes can give back container items. A shapeless recipe cannot give several results. There is no ingredient `count`. For mirrored duplicates, `assume_symmetry:false`. A creative-only recipe is impossible. The furnace recipe `output` is the string `"ns:item"`, not `{ "item": ... }`. Several recipes can output the same item. Potions are specified by data value (https://minecraft.wiki/w/Potion#Metadata). For crafting by wood type, use the item tag (`minecraft:logs`) rather than scripts. Web tool [https://crafting.thedestruc7i0n.ca/](https://crafting.thedestruc7i0n.ca/) (set to Bedrock 1.21), introductions [https://wiki.bedrock.dev/guide/loot-table#crafting-recipes](https://wiki.bedrock.dev/guide/loot-table#crafting-recipes) , [https://wiki.bedrock.dev/guide/custom-item](https://wiki.bedrock.dev/guide/custom-item)
- **Lists**: [https://wiki.bedrock.dev/items/item-tags#list-of-vanilla-tags](https://wiki.bedrock.dev/items/item-tags#list-of-vanilla-tags) (auto-generated with a script that loops over ItemTypes), and vanilla item groups moved to [https://wiki.bedrock.dev/items/vanilla-item-groups](https://wiki.bedrock.dev/items/vanilla-item-groups) . Mojang adds tags to vanilla only when needed. There are no dynamic tags, so use non-overlapping items + dynamic properties. Novelty API (mcpedl.com/novelty) accessory compatibility is a single item tag.
