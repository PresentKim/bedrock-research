# Building menu screens from an entity inventory

Server form buttons draw item icons only from a texture path or a numeric ID, and a script often cannot settle the numeric ID ([item numeric ID plan section 3](./item-aux-id.mdx#3-what-a-script-can-do)). An entity inventory screen has the engine draw the real items in the entity slots, so vanilla items, custom items and other packs' items all come out right.

This page covers restyling the chest screen of a container entity with a resource pack and using it as a menu like the research screen.

Status: tested on 1.26.63 mobile (2026-11-14). The tests covered screen routing, the icon grid, client-side selection, elements drawn from slot names and durability, a button that reaches the script, and ways to open the screen. On 2026-11-15 a 2048 test covered `modifications` routing, picking by entity name, animation replay and flicker (sections 2.2 and 8). Several players and other devices remain (section 5).

## 1. Compared with a server form

| Topic | Server form | Entity inventory screen |
| --- | --- | --- |
| Opening | The script opens it directly | A script cannot force it open. One player action is needed (section 3) |
| Icons | Texture path, or numeric ID | The engine draws the entity slots. Every item, 3D, glint |
| Icon count | As many as buttons | As many as entity inventory slots (more slots are readable even on the 27-slot screen, HOST-16) |
| Changing content | Close and reopen the form | Slot changes by the script show at once in the open screen |
| Text, conditions, textures, bars | Passed as form text | Passed as slot item names, lore and durability (section 2.4) |
| Input that reaches the script | Button index | Slot actions only. Buttons go through a slot quick move (section 2.5) |
| In-screen actions | Client-side with radio toggles | The same |

## 2. Setup

### 2.1 Entity

```json
"minecraft:inventory": {
  "container_type": "container",
  "inventory_size": 27,
  "private": false,
  "can_be_siphoned_from": false
}
```

- It opens through `chest_screen.json` only with `container_type: "container"` and `private: false` (HOST-16).
- A menu entity gets `minecraft:physics` (no gravity, no collision), `minecraft:pushable` (not pushable) and `minecraft:damage_sensor` (no damage).
- The resource pack entity uses an empty geometry with no bones so it is invisible.

### 2.2 Screen routing

The example add-ons insert their own window into the vanilla chest panels (`chest.small_chest_panel`, `pocket_containers.panel`) with `modifications` and pick it by the entity name (`$container_title`). They do not redeclare the screen definition `small_chest_screen`.

With two add-ons that redeclare the same screen, only one was used, by pack order: another test add-on's `chest_screen.json` was above, and the vanilla screen came out instead of the redeclaring one (measured, HOST-49). So the examples use neither the redeclaration of `small_chest_screen` that replaces `$screen_content` (HOST-18) nor a slot 0 marker item. Slot 0 of the examples is empty. The rule for identifying a screen by a slot item's durability is HOST-17.

A window that uses only `modifications` is drawn inside the chest panel that another add-on keeps on its vanilla side, even when that add-on redeclares the screen and is above it. This was checked only in the [JSON UI tester](../tools/jsonui-tester.mdx) (jsonui-tester) static simulation (*unverified*).

#### 2.2.1 Naming convention

The script names the menu entity's `nameTag` with the shared prefix `§b§w`, made only of format codes, plus a suffix that differs per example. `$container_title` of an entity chest screen is this nameTag (HOST-19).

| Example | Entity name |
| --- | --- |
| 2048 (section 8) | `§b§w§2§0` |
| Entity Menu Lab (section 6) | `§b§w§m§l`. Only the menu mode gets the name; the lock experiment entity has no name, so the vanilla chest screen opens |
| Research screen (section 7) | `§b§w§r§s` |
| Matchmaking (`entity-matchmaking`) | `§b§w§m§m` |

The menu entity's name tag was not visible in first person (measured). Whether it shows in third person or to other players was not tested (*unverified*, section 8.4).

#### 2.2.2 Hiding vanilla (shared by the four examples)

`chest_screen.json`:

```json
"small_chest_panel/root_panel": {
  "$bwiki_title": "$container_title",
  "visible": "(not (('%.6s' * $bwiki_title) = '§b§w'))"
}
```

`pocket_containers.json` (the 2048 example file; only the `modifications` value on `panel` differs per example):

```json
"panel": {
  "$bwiki_title": "$container_title",
  "modifications": [
    {
      "array_name": "controls",
      "operation": "insert_back",
      "value": [ { "e2048_overlay@e2048.overlay": {} } ]
    }
  ]
},

"header_area": {
  "ignored": "(('%.6s' * $bwiki_title) = '§b§w')"
},

"background_panel": {
  "ignored": "(('%.6s' * $bwiki_title) = '§b§w')"
},

"half_screen": {
  "ignored": "(('%.6s' * $bwiki_title) = '§b§w')"
}
```

- `$container_title` cannot be used in binding expressions, but it can be compared in `ignored` and `visible` property expressions. Declare the copy variable `$bwiki_title` and compare the copy (measured, HOST-48).
- `('%.6s' * $bwiki_title)` cuts the first 6 bytes of the name. `§` is 2 bytes in UTF-8, so `§b§w` is 6 bytes. That this prefix comparison works in a property fixed at creation time was checked only in jsonui-tester, and there is a community report that prefix comparisons on `$container_title` work. It was not checked in game (*unverified*).
- On mobile the copy variable goes on `panel`, and `header_area`, `background_panel` and `half_screen` are left out with `ignored`. The grey background disappeared and the window floated over the world like the classic UI (measured, with the 2048 test pack comparing the full name).
- On desktop the path key `small_chest_panel/root_panel` is hidden with `visible`.
- These properties override vanilla definitions, so they compete with other packs that write the same properties (MOD-13). The four examples write this part byte for byte the same, so the values are the same whichever example is on top. Competition remains with packs that write other values (*inferred*).

#### 2.2.3 Inserting the window

Each example inserts only its own `overlay` into the same two panels with `modifications` (`small_chest_panel` in `chest_screen.json`, `panel` in `pocket_containers.json`). The `overlay`s of several examples stack in the same panel.

```json
"small_chest_panel": {
  "modifications": [
    {
      "array_name": "controls",
      "operation": "insert_back",
      "value": [ { "e2048_overlay@e2048.overlay": {} } ]
    }
  ]
}
```

The `overlay` is built only when the full name matches. This is the definition in the 2048 example (`rp/ui/e2048.json`).

```json
"overlay": {
  "type": "panel",
  "size": [ "100%", "100%" ],
  "layer": 50,
  "$bwiki_title": "$container_title",
  "controls": [
    {
      "host": {
        "type": "panel",
        "size": [ "100%", "100%" ],
        "ignored": "(not ($bwiki_title = '§b§w§2§0'))",
        "controls": [
          {
            "cover": {
              "type": "input_panel",
              "modal": true,
              "size": [ "100%", "100%" ],
              "layer": 100,
              "controls": [
                {
                  "sync_grid": {
                    "type": "grid",
                    "size": [ 162, 54 ],
                    "layer": 1,
                    "grid_rescaling_type": "horizontal",
                    "maximum_grid_items": 27,
                    "collection_name": "container_items",
                    "grid_item_template": "e2048.empty_cell"
                  }
                },
                { "window@e2048.factory_window": { "layer": 2 } }
              ]
            }
          }
        ]
      }
    }
  ]
}
```

- `ignored` does not see the control's own `$` declarations and is evaluated in the parent scope (FILE-34). So the copy variable goes on the parent `overlay` and the child `host` compares it. In game only the setup with the copy on the parent was tested (measured).
- When `ignored` is true the control is not built, so a chest with another name has none of that example's controls. In jsonui-tester the control count of a mobile ordinary chest went from 3,569 when hidden only with `visible` to 2,207 (*unverified*, static simulation).
- `sync_grid` is the empty grid that stops flicker when slots change (section 8.3).
- In a jsonui-tester check with the resource packs of all four examples loaded, each name showed only its own window with vanilla hidden, and a plain unnamed chest showed only vanilla. They were not turned on together in game (*unverified*, static check only).

### 2.3 Icon grid and selection

- Each cell's `inventory_item_renderer` reads `#item_id_aux` of `container_items` at its `collection_index`.
- Cells are radio toggles as in the research screen (`radio_toggle_group`, `toggle_group_forced_index`). Selecting one shows a border and a large detail icon. Selection is handled only on the client and does not reach the server.
- The toggles keep items in their slots. The toggle takes the cell press, so the item did not move.
- `lockMode` does not protect items in entity slots. In the test, items with none, inventory and slot locks in a vanilla chest screen could all be taken out at once. The lock only worked in the player inventory: an inventory lock let the item move within the inventory, and a slot lock did not let it move.
- A locked item's tooltip gets a "cannot be moved" line. That line also goes into the `#hover_text` of section 2.4.

### 2.4 Drawing from slot names, lore and durability

`#hover_text` of `container_items` is read per slot. Different slots on one screen gave different values. When the script changed a slot item, the value in the open screen changed at once (lore updated every second, the name updated on every button press, HOST-17).

`#hover_text` holds every line the tooltip shows:

- The name. A renamed item is white italic, and an item with a rarity has that color (the totem of undying is yellow).
- Vanilla description lines (a storage line on a chest, the attack damage line on a sword).
- The lore (purple italic).
- The lock notice line.

So a data item that carries a value is an item with no vanilla description lines (paper) with only a name, and it is not locked. Then `(#hover_text - '§o' - '§f' - '§r')` leaves just the name. With locked items the lock line was attached, and both the texture path and the number conversion failed.

| Drawn | Expression | Result |
| --- | --- | --- |
| Label | `#hover_text` to `#text` | Name, lore and description lines in tooltip format |
| Name and lore of the selected slot | The same label inside the cell toggle's checked control | The selected slot's value |
| Visibility | `(not ((#hover_text - 'STATE_ON') = #hover_text))` to `#visible` | Switched every second with the name |
| Texture | `('textures/blocks/wool_colored_' + (#hover_text - '§o' - '§f' - '§r'))` to `#texture` | The wool color followed the name |
| Bar (name) | `(1 - ((#hover_text - '§o' - '§f' - '§r') * .1))` to `#clip_ratio` | Filled by the name 0 to 10 |
| Bar (durability) | `(1 - (#item_durability_current_amount * .004))` to `#clip_ratio` | Shrank with the iron sword's remaining durability |

![Entity Menu Lab screen. The bow is selected, so the large icon, name, lore and lock line show on the right. The wool texture follows the name blue and the name bar is 70 percent full for 7. The six bars given constant values are empty](/img/design/entity-menu-lab.png)

Bars have two conditions.

- Real literals start with a dot. `0.1` evaluates to 0 (EXP-27) and the bar stayed empty. With `.1` it filled.
- Put `#clip_ratio` in through a binding that reads a slot value. In the test, a fill with `clip_direction` stayed empty whenever its ratio came from any of these:
  - `property_bag` values 0 and 0.5
  - expressions that use no slot value, `(1 - 1)` and `(5 * .1)`
  - a changed size, `clip_pixelperfect` or direction
  - a bar placed outside the rows that read slots

  A fill with no `clip_direction` showed.

![v1.5.0 screen. Only the fill with no clipping shows green. The clipped bars are empty both with property_bag 0.5 and with constant expressions](/img/design/entity-menu-lab-clip.png)

No way to turn a number into text was found. `('v' + #item_durability_total_amount)` drew only `v`, and a number binding put straight into `#text` drew nothing. Put numbers meant for the screen into the name or lore as text.

A variable inside a size array such as `[160, "$line_h"]` gave a height of 0 and the rows overlapped. Pass a whole-array variable such as `"size": "$line_size"`.

### 2.5 A button that reaches the script

In JSON UI, the only direct path to a script is a server form button. What reaches the server from a container screen is a slot action, so the visible button is mapped to a quick move of a hidden slot.

```json
"start_button": {
  "type": "button", "size": [ 144, 20 ], "layer": 2,
  "default_control": "default", "hover_control": "hover", "pressed_control": "pressed",
  "bindings": [ { "binding_type": "collection_details", "binding_collection_name": "container_items" } ],
  "button_mappings": [
    { "from_button_id": "button.menu_select", "to_button_id": "button.container_auto_place", "mapping_type": "pressed", "consume_event": false },
    { "from_button_id": "button.menu_ok", "to_button_id": "button.container_auto_place", "mapping_type": "focused", "consume_event": false }
  ]
}
```

1. The button sits at `collection_index: 26` inside a stack panel with `collection_name: "container_items"`.
2. The script keeps a button item with a marker name in slot 26.
3. A press quick-moves that item into the player inventory.
4. Every 2 ticks the script checks slot 26. When the marker item is gone, it counts a press and refills the slot.
5. `world.afterEvents.playerInventoryItemChange` deletes the marker item that entered the player inventory.

Writing the result of a press into a data item name makes the open screen react at once. In the test, every press changed the slot 12 name `Pressed N` and the label showed it.

Pressing the slot itself stopped being detected after 2 presses on a touch screen. The item seems to go onto the cursor and only swap with the item in the slot (related to "the cursor is not filled on touch" in HOST-20). A quick move does not pass through the cursor.

## 3. Ways to open the screen

The Script API has no function that opens a container screen. On Discord the answer "it cannot be forced open" came up again and again (2025-10-23, 2026-03-09, 2026-09-10). So one player action is always needed.

| Method | How | Result on 1.26.63 mobile |
| --- | --- | --- |
| C: tap a visible entity | Spawn the entity in front of the player, who taps it | Opens. The entity has to be visible to be found, which is awkward for a menu |
| C2: entity in the line of sight | While the menu item is held, an invisible 1.2x1.2 entity moves every tick to 1.2 blocks along the view direction from the eyes, 0.6 blocks down. Tapping the middle of the screen taps that entity | Opens with one tap. Switching to another item removes the entity. The best usability |
| C3: ride + inventory button | The script seats the player on an invisible entity with `Rideable.addRider`. When the player presses the inventory button, the entity's screen opens instead of the player inventory | Opens. Sneaking gets off. Getting off removes the entity |

The menu entity opens with C2.

Seating the menu entity on the player is not used. An entity with the `parrot_tame` family can ride the shoulder seats of the vanilla player.json, but in the test a tap never hit the riding entity.

C2 position in the line of sight:

```js
function spotInFront(player, distance, drop) {
  const view = player.getViewDirection();
  const eye = player.getHeadLocation();
  return { x: eye.x + view.x * distance, y: eye.y + view.y * distance - drop, z: eye.z + view.z * distance };
}
```

The C3 entity has `minecraft:rideable` with `family_types: ["player"]` and seat `position: [0, 0, 0]`. While riding, the hint `action.hint.exit.<entity identifier>` showed untranslated. Add this key to the resource pack language file.

Other workarounds mentioned on Discord were not tested.

- Put an entity inside a furniture block with a hit box a little larger than the block, so tapping the block taps the entity (2025-10-22, 2026-03-09).
- A 26.50 preview mention that interacting with a custom block that has a container opens the inventory screen (2026-08-21). Whether it reached a stable release was not checked.
- A report that a seat far from the entity center opens the screen and closes it at once (2026-05-05). C3 put the seat at the center.

## 7. Example: research screen

This example draws the same window as the [server form research screen](./server-form-research-screen.mdx) (two tabs on top, an 8x6 grid with page arrows on the left, details and a start button on the right) as an entity inventory screen. Every third of the 120 research entries starts out done, and a research really runs when the materials are there.

![Research screen example. To do 110 and Done 10 tabs on top, the 8x6 grid with page arrows on the left, the Pick a research. hint on the right, and the Researched Item 117. message below](/img/design/entity-research-screen.png)

### 7.1 Slot layout

The entity has 243 slots (HOST-16).

| Slot | Content |
| --- | --- |
| 0 | Unused (empty) |
| 1 to 48 | The 48 cells of the current page of the To do tab |
| 49 to 96 | The 48 cells of the current page of the Done tab |
| 97, 98 | Tab heads (icon, `To do N`, `Done N`) |
| 99 to 102 | Previous and next page buttons per tab |
| 103 to 124 | To do tab details: icon and name, status, description, 8 materials, 8 rewards, start button, done note, message |
| 125 to 146 | Done tab details (same layout) |
| 147 to 242 | One pick button slot per cell |

### 7.2 Compared with the server form version

| Topic | Server form research screen | Entity research screen |
| --- | --- | --- |
| Icons | Numeric IDs | The engine draws the slot items |
| Picking a cell | Cell toggles. The server sends 20 detail buttons for every cell up front | A press quick-moves the cell's pick slot, and the script fills the 22 detail slots with that research |
| Switching tabs | Radio toggles | The same |
| Pages and starting | Form buttons. The form closes and opens again | Quick move buttons. The screen stays open and only slots change |
| Material and reward counts | Button text | The slot item amount, drawn with `#inventory_stack_count` |

Picking goes through the server, but the delay before the details changed was barely noticeable. The selection mark (yellow border) checks the cell item's lore for `SELECTED`.

### 7.3 Decisions

- **Keep pick buttons in slots apart from the icon slots.** Quick-moving the icon slot item emptied the slot for a moment, the empty-cell rule hid it, and the row shrank and grew back. Each cell gets its own hidden pick slot, and the cell keeps its size even when empty.
- **Pass the start button state through the button slot item.** Every half second the script counts the materials and adds or removes `READY` in the button item's lore. With `READY` the button draws a green `Start research`, without it a grey `Not enough materials`.
- **Show the first tab's content when the screen opens.** The first tab's content is visible while the second tab toggle is off (`(not #toggle_state)`), and the first tab toggle has `toggle_default_state: true`.

## 8. 2048 test: animation replay and flicker

This test draws 2048 with entity slots to check whether the tile slide animations can replay on every move in an open chest screen (mobile 1.26.63, 2026-11-15). The screen opens with C2 and is inserted the way section 2.2 describes. The example add-on Entity 2048 (section 8.5) is that test pack tidied up, and the code below is copied from its files. The example add-on differs from the test pack in names, identifiers and the prefix convention of section 2.2. The example add-on itself was not opened in game (*unverified*).

### 8.1 Slot layout

The entity has `inventory_size: 243`.

| Slot | Content |
| --- | --- |
| 1 to 16 | Mover layer. Old value at the old position. Name example `L2at5` (left by 2 cells, marker a, value 2 to the 5th) |
| 17 to 32 | Result layer. New value at the new position. Name examples `Mbt6` (merged), `Pat1` (spawned), `Nat3` (unchanged) |
| 33, 34 | Score, status text |
| 36 to 40 | Up, down, left, right and New buttons (quick move buttons, section 2.5) |

Mover codes are `S0` (stays) or a direction `U`, `D`, `L`, `R` followed by a distance of 1 to 3. Result codes are `N`, `M` and `P`. Empty cells have no item. Data items are paper with only a name, read with `(#hover_text - '§o' - '§f' - '§r')` (section 2.4).

### 8.2 Animation replay

To replay an animation from the start in an open screen, make the factory build its control again (measured, ANI-37).

This is `factory_mover_cell` from `rp/ui/e2048.json` with only two keys kept. The real file lists every key.

```json
"factory_mover_cell": {
  "type": "stack_panel",
  "size": [ 30, 30 ],
  "factory": {
    "name": "e2048_mover",
    "control_ids": {
      "S0at1": "@e2048.ft_S0_1",
      "S0bt1": "@e2048.ft_S0_1"
    }
  },
  "property_bag": {
    "#k": [],
    "#kS0at1": [ "S0at1" ],
    "#kS0bt1": [ "S0bt1" ]
  },
  "bindings": [
    {
      "binding_type": "collection",
      "binding_collection_name": "container_items",
      "binding_name": "#hover_text",
      "binding_condition": "always"
    },
    {
      "binding_type": "view",
      "binding_condition": "always",
      "source_property_name": "('#k' + (#hover_text - '§o' - '§f' - '§r'))",
      "target_property_name": "#collection_length"
    }
  ]
}
```

- In each cell one `stack_panel` factory looks up `property_bag` with `('#k' + name)` to set `#collection_length` (COL-22, COL-23) and builds the one control of that key from `control_ids`. For an empty cell `#k` is an empty array, so nothing is built. The real pack has a generator make keys for 13 mover codes and 3 result codes times 13 values and 2 markers.
- On every move the script flips the marker in the names between `a` and `b`. Even when the same tile stays in the same place the key changes, so the factory builds a new control and that control's `anims` played from the start (measured).
- Keeping one variant panel per marker and switching only `#visible` showed no slide. Being hidden and shown again does not replay an animation (measured).

The tile animations:

- A mover tile goes to its destination with `offset` over 0.12 seconds and reaches `alpha` 0 at 0.17 seconds.
- A result tile stays at `alpha` 0 for 0.12 seconds and then shows. A merged cell grows from `size` 28 to 34 and back, and a spawned cell grows from 0.
- Waiting steps are `alpha` and `size` animations with equal `from` and `to`, chained with `next`.
- The result layer is on a layer above the mover layer.

### 8.3 Flicker and the empty grid

At the moment a slot item changed, the cells of a `container_items` grid were drawn above other controls for one frame. Grey cells came up over our window for an instant, and the whole board seemed to flicker (measured, HOST-50).

| Setup behind the window | Result |
| --- | --- |
| Vanilla chest screen not hidden | No flicker was seen. The vanilla chest screen showed next to the window |
| Vanilla hidden with `visible: false`, no grid | The whole board flickered grey |
| Vanilla hidden, grid of 27 `common.pocket_ui_container_item` cells | The whole board flickered |
| Vanilla hidden, grid of 1 vanilla cell | Only that cell's area flickered |
| Vanilla hidden, `container_items` grid of 27 empty panel cells | No flicker |
| Vanilla not hidden, whole screen covered with an opaque backdrop | No flicker, but with the whole screen covered it no longer looked like a form |

All of these are measured. Forcing a layout pass with a label whose width changed on every move did not remove the flicker (measured). So a grid of empty panel cells goes behind the window. That grid is `sync_grid` inside `cover` of the `overlay` in section 2.2.3, and its cell template is:

```json
"empty_cell": {
  "type": "panel",
  "size": [ 18, 18 ]
}
```

- The tests in the table hid vanilla with `visible: false`. How the flicker behaves with the setup that leaves the mobile vanilla out with `ignored` (section 2.2.2) was not checked (*unverified*).
- Whether the grey drawn without a grid is the hidden vanilla cells, and why an empty grid makes the flicker go away, is not known.
- With vanilla cells visible, the flicker may have gone unnoticed because the vanilla cells or background covered it (*inferred*).

### 8.4 Container title and name tag

- The title of an entity chest screen is the nameTag (measured, HOST-19). `minecraft:inventory` and the Script API `Container` and `EntityInventoryComponent` have no field or function that sets the title apart from the nameTag (Microsoft Learn documentation).
- Community reports disagree on whether the language file's `entity.<id>.name` becomes the title when there is no nameTag (**conflicting**).
- A custom block can give a title with `container.title` (a language key or text) of `minecraft:block_entity`, and opens on tap with `show_ui_on_interaction` (on by default). A user reports it as an experimental feature in 26.50 and 26.60 (*single report*).
- `minecraft:nameable` has no field that hides the name tag (`allow_name_tag_renaming`, `always_show`, `default_trigger`, `name_actions`). There is a report that a behavior-pack-only entity with no client entity file draws no name tag (*single report*).
- A candidate for hiding the name tag is `Entity.nameplateRenderDistance` (writable from `@minecraft/server` 2.8.0). Whether 0 hides it was not tested (*unverified*).

### 8.5 Example add-on

<AddonDownload id="entity-2048" />

1. Turn on the behavior pack "Bedrock Wiki Entity 2048 BP" in a new world. The resource pack turns on with it as a dependency.
2. Take "2048" from the end of the items category of the creative inventory, or use `/give @s bwiki:entity_2048`.
3. Hold the item and tap the middle of the screen to open the 2048 screen. The direction buttons on both sides slide the tiles, and New starts a new board.
