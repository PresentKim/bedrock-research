A design doc is a record of building one screen or technique and confirming JSON UI rules in game along the way. Each doc gives the goal, the setup, the measured results and the open items, and most attach an example add-on you can import and turn on right away. Evidence levels follow the legend of the [full rule ID table](../reference/rules.mdx).

## Example add-ons

Each add-on is downloaded from the download box inside its doc. Test items are in the creative inventory, and the server form examples can run together in one world, as can the entity inventory examples (see each doc). For what works and which version was measured, see the measurement records in each doc.

| Add-on | Shows | Doc |
| --- | --- | --- |
| `json-ui-performance` | A server form button list drawn by a screen router with a 2-column grid | [Grid button list](./json-ui-performance/grid-button-list.mdx) |
| `collection-view-order` | A list with `always` compared with one without | [Filling the first frame without always](./json-ui-performance/collection-view-order.mdx) |
| `hud-expression-cost` | The cost of one shared HUD cell expression compared with fixed expressions per cell | [Binding expression caching](./json-ui-performance/binding-expression-caching.mdx) |

| `entity-menu-lab`, `entity-research-screen`, `entity-2048`, `entity-matchmaking`, `entity-matchmaking-figures` | A menu, a research screen, 2048 and matchmaking built from entity inventory screens | [Building menu screens from an entity inventory](./invui/entity-inventory-ui.mdx) |
| `touch-probes`, `json-ui-claims` | Windows that measure which key and touch input reaches a screen | [Intercepting user input](./invui/input-interception.mdx) |
