# Deep research on little-known elements

What is known about JSON UI covers only what the vanilla files and the community use. The client reads more names than that. This plan picks elements the client reads but vanilla rarely uses or nobody has written down how to use, checks their real behavior with probe packs, and records the ones that can be used.

## 1. How they are found

1. Collect every property, binding and renderer name the vanilla `resource_pack/ui` uses, including keys inside `property_bag`.
2. Among the names the client (Windows 1.26.63, Android 1.26.52) reads while parsing JSON UI, pick those missing from step 1, and check that the parsing code really reads them.
3. Search this wiki, the community chat records and other documentation sites for those names, and drop the ones whose usage is already known.
4. Lay out the rest in a probe pack and check them in game. Only measured results move into rules and sub pages.

Step 2 gives the evidence level `code`. Usage is not written down until it is checked in game.

## 4. What is left

- Put the unmeasured candidates in a probe pack and check them. For elements whose behavior is hard to guess, like the toggle manager, compare one cell per value.
- Look again at the remaining `progress_bar_renderer` keys with a large bar to see pixel differences.
- Only one touch input device was measured. PC and consoles were not tested.
