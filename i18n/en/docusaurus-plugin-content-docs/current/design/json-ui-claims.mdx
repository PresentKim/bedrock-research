# Measuring unverified JSON UI claims

The [JSON UI](../json-ui/index.mdx) chapter still had claims from community reports and code reading marked `unverified`, `inferred`, `conflicting` or *single report*. This page records the ones that could be measured on Windows, measured with one add-on. Each rule entry carries a short form of its result; the numbers and conditions are here.

- Target: Windows 1.26.65.1, a single-player world, GUI 480x253 (client 1920x1009, scale 4). Measured on 2026-11-18.
- Anything the vanilla files of the official samples `preview` branch (1.26.70.24) already show (for example an expression in a collection `binding_name`, a state variable expression in `ignored`) was not measured.
- Other platforms, Ore UI and DDUI internals, anything that needs multiplayer, Marketplace policy and rumours about future versions were left out.

## 1. Method

- The add-on picks a window by the server form title `§b§wjc:N`. A router (`collection_panel`) goes into `main_screen_content` of `server_form.json` with `insert_back`, and the first 10 bytes of the title are looked up as a `property_bag` key. This is the same scheme as the other server form examples, and they work together in one world.
- The script sends the input strings as button texts. The cells of a window are `stack_panel` cells with a fixed `collection_index`; a label receives `#form_button_text` as `#v` and draws the result of a view expression into `#text`.
- Measurement used MCP tools: edit the JSON, reload the UI (`ui_reload`), then read control tree rects, the content log and the text in screen captures. Rects are client pixels; one GUI unit is 4 pixels.
- A label whose result is only a number showed nothing (section 2.4), so numbers and booleans were read wrapped as `('R' + expression)`.

## 2. Expressions

### 2.1 Operators

| Expression | Input | Result | Related |
|---|---|---|---|
| `('R' + (#v != '5'))` | `5` | `R` (no value) | EXP-02 |
| `('R' + ((#v - 0) >= 10))` | `10` | `R` (no value) | EXP-03 |
| `('R' + (not ((#v - 0) < 10)))` | `10` | `Rtrue` | EXP-03 |
| `('R' + ((#v - 0) % 5))` | `17` | `R` (no value) | D-07, C-06 |
| `('R' + ((#v - 0) - (((#v - 0) / 5) * 5)))` | `17` | `R2` | EXP-38, C-48 |
| same expression, divisor 3 | `-7` | `R-1` (`-7 / 3` is `R-2`) | EXP-38 |
| `('R' + (5 < (#v - 0) < 7))` | `10` | `Rtrue` (wrong true) | C-41 |
| `('R' + (((#v - 0) > 5) and ((#v - 0) < 17)))` | `10` | `Rtrue` | EXP-04 |
| `('R' + ((5 < (#v - 0)) and ((#v - 0) < 7)))` | `10` | whole label empty | see below |
| `('R' + (#v < 'c'))`, `>`, `< 'a'` | `b` | `Rtrue`, `Rfalse`, `Rfalse` | D-10 |
| `('R' + ((#v - 0) + 1))` | `2147483647` | `R-2147483648` | D-27 |
| `(translate('gui.ok', #v))` | `b` | empty | D-21 |

- Every time the window loaded, the content log printed `JSON UI parse failure: Invalid expression.` 6 times. Six rows also gave no value (`!=`, `>=`, `%` twice, the `and` comparison with a literal on the left, `translate`). The log has no control path, so lines and rows were not matched one by one.
- Only the expression that joins a comparison with the literal on the left (`(5 < x)`) through `and` failed; writing the same thing as `(x > 5)` worked. The cause was not separated.

### 2.2 String minus and leading characters

| Input and expression | Result |
|---|---|
| `abab` - `'ab'` | empty string |
| `xaxbx` - `'x'` | `ab` |
| `' x'` - `'zz'` | ` x` (leading space kept) |
| `':x'` - `'zz'` | `:x` |
| `'-x'`, `'+x'`, `'1x'`, `'#x'`, `'/x'`, `'<x'` - `'zz'` | empty |
| `'Info: a'`, `'nancy'`, `'0x12'`, `'inf'` - `'zz'` | empty |
| `'' + '1x'`, `'' + 'Info: a'`, `'' + '0x12'` | empty |
| `'§r' + '1x'`, `'z' + '1x'`, `'z' + '/x'` | `1x`, `z1x`, `z/x` |

- String `-` removes every occurrence (EXP-12, D-08).
- A label was empty when the result started with `-`, `+`, a digit, `#`, `/`, `<`, `inf`, `nan` or `0x` (EXP-48). Results starting with a space or `:` showed as they were. A `/` in the middle showed without doubling. `\` was not measured.

### 2.3 `'%.Ns'` cuts

| Input | N | Result |
|---|---|---|
| `§cAB` | 1, 2, 3, 4 | broken, broken, `§c` (blank), `§cA` |
| `가나다` | 2, 3, 4, 6 | broken, `가`, `가` + broken, `가나` |
| `😀xy` | 2, 4, 5 | broken, emoji box, emoji + `x` |
| `abcdef` | `%7.4s`, `%-7.4s`, `%9s`, `%-9s`, `%09s`, `%4.2s` | all `abcdef` unchanged |
| `abcdef` | `%.4s` | `abcd` |

- `§` cuts as 2 bytes, Hangul as 3 bytes, emoji as 4 bytes (EXP-24). Cutting in the middle of a character dropped that piece and also the character concatenated right after it (`']'`).
- Formats with a width or padding neither cut nor pad; they returned the input unchanged. The only working format was `'%.Ns'` (EXP-25, C-05).
- `(('%.3s' * 'abcdef') + (#v - #v))` was `abc`: a literal is cut too. With no `#` property in the same expression, the binding failed with `Must define a source property name in the binding!` (C-42, BND-05).
- A format built at run time worked. `(('%.' + #v + 's') * 'abcdef')` (`#v` is `3`), `('%.' + $n + 's')` (`$n` is 3) and `('%.' + '3' + 's')` all gave `abc` (EXP-43, D-04).

### 2.4 Numbers

| Expression | Input | Result |
|---|---|---|
| `((#v - 0) * 2)`, `((#v - 0) * $two)` | `4` | `8`, `8` |
| `(#v * 1)` | `4` | empty string |
| `((#v * 1) + 1)`, `((#v * 1) = 4)` | `4` | `1`, `false` |
| `(#v - 0)`, `((#v - 0) = 4)` | `4` | `4`, `true` |
| `(#v + 1)` | `4` | `41` (concatenated) |
| `(#v + $zero)`, `((#v + $zero) + 1)`, `$zero` is JSON `0.0` | `4` | `4`, `5` |
| `((#v - 0) * 0.3)`, `* 1.5` | `10` | `0`, `10` |
| `(((#v - 0) * .3) = 3)` | `10` | `true` |
| `((#v - 0) * .3)`, `(((#v - 0) * .5) * 2)` | `10` | no value in the label |
| `((#v - 0) / 4)` | `10` | `2` |

- Multiplying by a literal worked (unlike a 2026-09 single community report).
- `* 1` does not convert to a number; it makes an empty string (D-01). `- 0` converts.
- `(#v + $zero)` with the JSON variable `0.0` became a number, so `+ 1` gave `5`. Adding an integer to a string concatenates (`41`). Even so, the content log printed `Expected variable not found in ancestor tree: '$zero'` for those rows (D-02).
- A decimal literal with a leading digit becomes an integer (`0.3` is 0, `1.5` is 1, `100.0` is 100). `.3` computes as a decimal (D-03, EXP-27).
- A float result did not show in a label even after `'R' +`. Integers and booleans showed when concatenated; a number alone in `#text` showed nothing.
- A parenthesized string value in `property_bag` is evaluated. Reading `"#pb": "('A' + 'B')"` through a label with `text: "#pb"` showed `AB`, `"plain"` showed `plain`, and `"(1 + 2)"` was a number and stayed empty.

The entities are `bwiki:juc_weight` (spawn events `w0`, `w2`, `w3`), `juc_bits` (`b0`, `b1`, `b13`, `b0b13`, `all`), `juc_acc`, `juc_creak` (`m0`, `m2`, `m3`), `juc_creak2`, `juc_named` and `juc_mer`; call them as in `/summon bwiki:juc_bits ~ ~ ~3 0 0 b13`. Check the sound with `/playsound juc.flat` and the language with `/tellraw @s {"rawtext":[{"translate":"juc.fb.en_only"}]}`. This add-on overrides the vanilla `controller.animation.player.crossbow`, so while it is on, holding a crossbow always gives the aiming pose.

The particles of section 6.7 are `bwiki:juc_camrot`, `juc_dist`, `juc_dist_expire`, `juc_loop`, `juc_render_counter`, `juc_lifecount` and `juc_coalesce`; spawn them with `/particle bwiki:juc_loop ~ ~1 ~3` or `/scriptevent bwiki:juc_particle bwiki:juc_coalesce variable.r0 1`. The entities are `bwiki:juc_pfx` (particle variables), `juc_xray`, `juc_uvent` and `juc_mfile` (gives an error because its material is missing). The sounds are `/playsound juc.obj` and `/playsound juc.insounds`. Holding a blaze rod or a bone shows the attachables with bone names `Head` and `head`. The biome test file covers the flat world with red fog, so it is not in the add-on.
