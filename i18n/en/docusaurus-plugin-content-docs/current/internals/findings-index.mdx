## 2. Re-confirmed things already known

This is not new information, but the evidence changed from reconstructed code (`CN`) to the actual binary.


This is not new information, but the evidence changed from reconstructed code (`CN`) to the actual binary. The guide records the source as `NB`.

- A factory reads `control_name` first and reads `control_ids` only when it is empty (NB-06, COL-28 and COL-43).
- `insert_location` defaults to `back` and puts the item in front only when the value is `front` (NB-06, CN-43).
- When `array_name` is empty and `control_name` is present, `controls` is the target (NB-03, CN-10).
- A view binding reads its own control when `source_control_name` is absent, and turning on both scopes together makes it act on the sibling range (NB-09, BND-24 and BND-25). The only new fact is the error message in that case (`resolve_ancestor_scope and resolve_sibling_scope cannot both be set!`).
- Of the 31 `button.menu_*` entries, 27 are also used by vanilla (excluding the 4 in R-09).
- The candidate values `horizontal`, `vertical` and `none` for `grid_rescaling_type` match the official enum (NB chapter 4).


## 3. What reverse engineering could not yet obtain


Each page of the engine internals chapter lists these under "What remains" at the end. In summary: the binding expression evaluator (operators, `'%.Ns'`), string resolution and defaults for `binding_type`, the stage where `$x|default` is applied, the condition function for the `#hyperlink` prefix list, and the functions that read `grid_rescaling_type`, `propagate_alpha` and `clip_direction`. The expression rules (guide chapter 5) still rest on measurement and `CN`.


## 4. Evidence levels and usage

| Level | Meaning in this chapter |
| --- | --- |
| `code` | The compiled output was read. It means the engine reads it that way, and does not guarantee the result on the game screen |
| `inferred` | Judged from only part of a function or from type names |
| `measured` | The same topic was verified in game on Windows 1.26.52 (`OL`, `MS`, `DF`) |

When a rule is at the `code` level, verify it in game before using it. When the binary result and the in-game measurement differ, follow the measurement.
