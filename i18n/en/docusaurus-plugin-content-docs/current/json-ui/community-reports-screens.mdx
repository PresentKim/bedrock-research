These are notes by screen type from community conversations (Bedrock OSS and Add-Ons, 2025-10-22 ~ 2026-11-13). They cover decorating server forms and chest screens with JSON UI, tips for each vanilla screen, Script API forms and DDUI, Ore UI modification, and renderers.

The reliability markers and the source tags at the ends of items are the same as in the header of the community reports and cross-check page: *confirmed* means confirmed by several people, *single report* is one person's report, *unverified* is a guess, and **conflicting** means the reports disagree.

## Customizing server form (ActionFormData / ModalFormData) JSON UI

### Structure
- **Name mapping**: the server form screen is `third_party_server_screen` (server_form.json). The default long form = ActionForm and `custom_form` = ModalForm. The message form appears to be in dialog_common (panel two button) (unverified). The Modal form code is in server_form.json and its controls come from settings_common.json and common.json (about 1400 lines).
- **When the ModalForm does not show**: if `$screen_content` points only at `long_form`, the ModalForm is not rendered. Use `"server_form.custom_main_screen_content"` or delete that line.
- **Form bindings**: the body is `#form_text` (only inside `server_form_factory`), the title is `#title_text` (can be used outside the factory too. To use it in a factory control, the declaration `{"binding_name": "#title_text"}` is needed), and `#submit_button_text` (outside. It can be used as a stand-in for a modal form's body). The button collection is `form_buttons` and uses `#form_button_text`, `#form_button_texture`, `#form_button_texture_file_system`, `#form_button_length` (the count) and `#form_button_contents` (an array, so use `#form_button_length` for the count). There is also an explanation that `#title_text` is a property of each item of `form_buttons`.
- **Form title translation**: if there is a lang key like `ActionFormData().title('container.waystone')`, it is translated automatically. In bindings, compare with `#title_text = 'container.waystone'`. `form.title("%ui.ns.title")` also works.
- **Full screen**: `main_screen_content` has size [0,0] so `%` sizes do not work. Put `"main_screen_content": {"size":["100%","100%"]}` in server_form.json and set the form size to 100%. The long_form template is `common_dialogs.main_panel_no_buttons`.
- **Background**: long_form changes its background with `$custom_background`. To remove the background, make the texture transparent or edit the template.

### Choosing a form by title (routing)
- **Basic method**: make `"$screen_content"` of `third_party_server_screen@common.base_screen` point at a panel that has a `server_form_factory` factory (`control_ids`: `long_form`/`custom_form`). For each variant, attach `#visible` and `#enabled` with a `#title_text` binding. Example: `('%.15s' * #title_text = '§c§h§e§s§t')`, prefix `@zelisce/chest_form`. Without the prefix it is the vanilla form. wiki: `json-ui/modifying-server-forms`. PocketMine, Endstone and the Script API all use the same method. *confirmed*
- **Creating only one with a factory**: make `server_form.form_factory` a `collection_panel` and put a `factory.control_ids` map + `property_bag` `{"#§1": ["actionform1"], ...}`. If you bind `#collection_length` to `('#' + '%.3s' * #title_text)`, only the matching control is created. If the collection length is 0 nothing is created, so it acts like an `ignored` for bindings. There is a report that 200 or more forms loaded instantly, but it was still slow in some environments. The fastest is `ignored: true`. Choosing this way means `#form_text` cannot be read inside, so fetch it from a sibling "grabber" element with `source_control_name`.
- **Coexistence among add-ons that change long_form**: there is no standard. If the vanilla form comes up on top because of the vanilla form `#visible` binding in the wiki tutorial, give your own root a high `layer` (for example 15).
- **Collision warning**: a chest GUI triggered by a Unicode title also triggers on renamed items (a shulker named "27"). Make the title filter strict.

### Buttons
- **Required bindings**: a button needs `"bindings":[{"binding_type":"collection_details","binding_collection_name":"form_buttons"}]` and `collection_index`. Without them `selection` becomes undefined/canceled. Hidden buttons must keep this binding for it to work. The mapping is `button.form_button_click`. *confirmed*
- **`collection_index`**: starts at 0 (index 50 needs 51 buttons). After header/label/divider appeared in 1.21.x, button indices shifted (the first index can be a label). Fix: `"type": "collection_panel"` + `collection_name` without the factory binding. The last item is `(#collection_index = (#form_button_length - 1))`.
- **Connecting button data**: bind `#form_button_text`/`#form_button_texture` to a label/image with `binding_type: collection` and `binding_collection_name: form_buttons`, and give each button a `collection_index`. To make a child show the texture of button N, use `binding_name_override: "#texture"`. Conditional display by button text: `(not (#form_button_text - 'marker' = #form_button_text))`. ID encoding example: `§f§l§a§g§<id>§r`.
- **Empty and ghost buttons**: `(not (#form_button_text = ''))` -> `#visible`, and `binding_condition: "once"` on the collection binding. There is also a way to set `#maximum_grid_items` with a number in `#form_body` (`(#form_text * 1)`). Show only when the button has a texture: `#form_button_texture` -> `#texture`, `not ((#texture = '') or (#texture = 'loading'))`. The empty first button of server_form was due to an unpaired element (unresolved).
- **The form always closes**: a button whose pressed name is `button.form_button_click` always closes the screen, and changing it breaks behavior. A button cannot be prevented from closing the form, so imitate it by reopening (recursive show). The last hovered button is not remembered. The only way to send the clicked index is submit. Several JSON UI buttons of the same form share the same result so the script cannot tell them apart.
- **A carousel inside a form**: if you use a custom button id such as `button.menu_left`/`button.menu_right` for arrows, unlike `form_button_click` it does not close the form. Only the CONFIRM button sends `form_button_click`, and a counter-based image_cycler/label_cycler changes things on screen. To keep the form open after a click on mobile, set the `$pressed_button_name` of `inventory_slot_button_internal` to an empty string or remove button_mappings.
- **ModalForm data**: only the submit button sends data. If you need selection state, use a modal form toggle. The form content cannot be changed after it is shown and must be resent. Real-time two-way needs DDUI.
- **A form that cannot be closed**: hooking `button.menu_cancel` -> `button.null` (global) on `third_party_server_screen` makes every form unclosable. So hook it only on an individual form's main panel (it must be an `input_panel`). There is also a way to block ESC by mapping `button.menu_cancel` to itself (`mapping_type: global`). It closed with `to_button_id: "button.close"`, and `button.back` did nothing. You cannot open another form with a JSON UI mapping.
- **Controller focus**: a button needs `focus_enabled: true` (default false). To remove the initial focus, turn focus off. Use `default_focus_precedence`. To show only the keyboard focus border, overlap two buttons (the upper with focus off, the lower with it on). A text-only panel has nothing to focus so controller scrolling does not work, so wrap it in a focusable custom button. Console L1 is `button.menu_tab_left`, R3 is `button.controller_secondary_select_right` and there is no R2. Giving `third_party_server_screen` `"gamepad_cursor": true` shows the cursor.
- **Button icons**: the problem of the icon disappearing on hover is fixed by raising the image `layer` and making the label layer higher than that. Strip `§r` with `(not ((#form_button_text - '§r') = #form_button_text))`.
- **Radial menu**: there is no circular hitbox, but you can build a wheel UI of more than 6 cells with the `selection_wheel` of the emote screen. A radial menu is built with a collection_panel that gives each button a collection_index (otherwise all do the same action).
- **URL images**: Script API form buttons accept only paths. With the Endstone plugin https://github.com/zelisce/URL-Image-Fix (via https://github.com/EndstoneMC/endweave) you can use URL images like `form.button("Test","https://cdn.example.com/x.png")`. It also works with only the RP, without the plugin: put a `profile_image_renderer` control next to the button image and bind `('{"type":7,"url":"' + #texture + '"}')` to `#profile_image_options` (`source_control_name: image`, `resolve_sibling_scope`). Example: https://github.com/zelisce/SAPI-with-URL-Images. Only PNG works and GIF does not. `profile_image_renderer` is in the renderer section below on this page.
- **Crash reports**: there is a report that a literal "Info" string in a custom button killed the server form (unconfirmed), and a report that in 1.26.52.3 the `$pressed_button_name: "button.sub_command"` + `#sub_command` chat button died with 0xc0000005 on a third-party server.

### Grid, factory, performance
- **Grid**: `type: grid`, `grid_item_template` (must be a top-level named control. For example `common.grid_item_for_inventory`), `grid_rescaling_type: horizontal`, `collection_name: form_buttons`, and the binding `#form_button_length` -> `#maximum_grid_items` (+`binding_condition: once`). It needs a fixed width (for example `[150,"100%c"]` and no factory. Vertical fill/rescale does not work and can crash. Cells are 18x18. Wrapping in a panel removes the gaps. There are `grid_fill_direction` and `grid_dimension_binding`. A dynamic `grid_dimension` is an array so it cannot be bound, but a dynamic grid whose size is decided to fit the remaining space works.
- **Grid key names**: the real key is `grid_dimensions` (`grid_dimension` gives a type error). Explicit child positions are given with `grid_position: [x,y]`, not `collection_index`. The collection index of a grid made of children is also decided by `grid_position`. A grid cannot rotate, so swap rows and columns. The "Unknown property [orientation]" after turning a stack_panel into a grid is harmless.
- **Hidden grid items**: even hidden they take up space, and there is a bug of redrawing on close. Put buttons that will always be hidden (tabs, navigation) at the end of the collection. To hide the front, hide the first row (`(#collection_index > 6)`) and pull it up by putting a `{"size": [0,-40]}` panel before the grid (the script corrects the index). Wrapping with panel height `100%c - <child height>` also works. Buttons of different sizes cannot be mixed in a grid, so build them directly with a stack_panel (a horizontal stack inside a vertical stack, `size ["fill", 30]`).
- **Factory**: use `"factory":{"name":"buttons","control_name":"ns.button"}`, `collection_name: "form_buttons"` and `{"binding_name":"#form_button_length","binding_name_override":"#collection_length"}`. `max_children_size` is needed. `#collection_length` is not a boolean and if it is N, N are created. A custom collection name gives only `#collection_index` with no data. `factory.name` is used only to name or connect hidden game factories (title, actionbar, item name). `type: factory` takes its name from the element name. Created children inherit `collection_name`.
- **The `control_ids` rule**: the keys of `control_ids` are chosen by the string of `#collection_length`. For `['a','b']` both are created in order. You cannot use `$var` as a control name in a value as is (`"('test@hud.' + $content)"` is unconfirmed). Using `control_ids` where only a `control_name` factory works gives "Unknown property [control_ids]" (cause unconfirmed).
- **Factory bugs**: a child factory under a server form is not filled until input or resize (work around it with a toggle that triggers it. Grids do not have this problem). Elements inside a factory are reevaluated only on interaction. Pull values out with a data_control outside the factory or substitute with visibility. A factory inside a factory, `use_child_anchors`, and chained `next` animations inside a factory/grid (speeding up after the first loop) are known bugs. Experienced developers consider that in server forms factories lose the body, toggles reload elements, and fetching bindings from elsewhere is unstable.
- **Performance figures**: even 100 buttons can slow down. A button factory of more than 3000 (the vanilla long_form stack_panel) freezes for about 60 seconds even when hidden. So split into pages. There is a case where a form took about 30 seconds to open even with many pages. A grid loads even 10k buttons instantly (leaving empty cells). Hidden elements also cost parsing. Using many collection factories and attaching a string subtraction filter freezes the form. Hidden forms also remain loaded, so merge forms with different styles into one toggle. Lag occurs only on the client. The glitch where all button texts show after alt-tab is also due to a heavy factory.
- **Optimization case**: merging 3 elements per store card into 1, deferring expensive content of tabs not opened first (button text, 3D block rendering), and opening with the lightest tab took 1.6 seconds down to 0.8 seconds. JSON UI cannot put work in a "queue" and elements update only when a binding changes. About 75 elements is fine. The "NPC UI" route (editing NPC NBT to lift the button limit) and Soulsteel's auto-refresh technique were counted as the most optimized methods.

### Dropdown pagination (tabs/pages)
- **Method**: put all tabs/pages in one form. Put a hidden dropdown at form index 0 and decide the current view by its options. The options use `dropdown.radio_selected` and are rendered as tabs and arrows. Read `#dropdown_option_text` at `custom_form` index 0, attach a view id to each element, and decide display with a binding that compares against the selected view. Elements without a tag show on all pages. It is a radio group, not a toggle, and an actionform-style button is needed inside the modal form.
- **A page gate implementation example**: attach a page id like `[view:shop_1]` to the element text, and a state reader control reads the index 0 dropdown (`"text": "__page_state__"`). Put `$view_id|default: ""` in the template, copy `#current_view` from `source_control_name: page_state_reader`, and bind `(($view_id = '') or ($view_id = #current_view))` to `#visible`. A page is made as `name@namespace.page_gate`. Hidden pages must also keep observing the state to reappear. Tags like `[target:..][x:..][y:..]` are a convention JSON UI parses directly. Another implementation (`nperma:pagination`) accumulates toggle values into `#x`/`#z` and shows a page with `($pan_cuy = ((#x/19) - (#z/19)))`.
- **Multi-tab server form (Chest-UI `server_form.json`)**: give the custom screen `"force_render_below": true`, `render_game_behind` and the exit animations `screen.exit_pop`/`screen.exit_end`. Tab generator: https://g07hn-1.github.io/tabgenerator/.

### Modal form controls
- **Toggle and slider**: the toggle is `settings_common.option_toggle` (copied from vanilla `server_form.json`). The slider gives `common.slider` `$slider_name`, `$slider_steps` and `property_bag {"#slider_steps","#slider_value"}`. The template is in `ui_template_toggles.json` and the slider code in `ui_common.json`. To place controls directly, delete the factory and its bindings and, leaving `collection_name`, give each child a `collection_index`. The problem that sliders with different `collection_index` behave like one and break when `$slider_name` is changed is unresolved.
- **custom_form factory**: uses the `control_ids` of `generated_contents` (label, toggle, slider, step_slider, dropdown, input, header, divider), and every control needs a `collection_name: "custom_form"` binding. Long form fragments use `form_buttons`.
- **Text input size and length**: use `input_box@common.multiline_text_edit_box` (`size`, `max_length`, `$text_edit_box_content_binding_name: "#custom_input_text"`). Example: `"text_field@common.multiline_text_edit_box": {"$text_box_name":"notes_field","$text_edit_text_control":"notes","$text_edit_box_label_anchor_point":"top_left","max_length":412,"size":["100%","130px"]}`. The max length is `"$max_text_edit_length": 100` (also in the form's `option_text_edit`). `common.scrollable_multiline_text_edit_box` scrolls but there is a case where it lost clicks and the placeholder. The default text box limit is 100 characters. The `max_length` of the jigsaw UI can also be changed (unconfirmed).
- **Dropdown**: a dropdown is a radio toggle. Give `$toggle_name` and `$toggle_state_binding_name` the same name and use `$radio_toggle_group: true`. The vanilla dropdown binding (`#chat_coordinate_dropdown`) is screen-specific. The toggle binds as `#($dropdown_name)`, and if the name is wrong the dropdown freezes.
- **Text box**: giving `$shadow: true` hides the caret (vanilla template). The search box is `common.text_edit_box`, `$text_edit_box_clear_to_button_id`. Reading the box content: `{"binding_type":"view","source_control_name":"display_text","source_property_name":"#item_name","target_property_name":"#text"}` (breaks if several boxes have the same name). Vanilla exposes `$text_edit_box_content_binding_name`. If you put a dummy `edit_box` with the same `text_box_name` as the chat box inside a button, the chat text is set (the emoji panel trick. Probably works only with hardcoded boxes).
- **Toggles in general**: mouse hover is needed before a click (a known mouse problem).

### Scrolling
- **`common.scrolling_panel`**: you must reference it (`"form@common.scrolling_panel"`) for the scroll to show. Variables: `$scrolling_pane_size` (applies only when `size: "$scrolling_pane_size"` is specified), `$scrolling_pane_offset`, `$scrolling_content`, `$scroll_size`, `$show_background`, `$touch` (mobile style. If the scroll box becomes blurry, `"$touch": false`), `$scroll_bar_contained`, `$scroll_track_offset` (deleting it fixes the initial offset), `$scroll_bar_left/right_padding_size`, `$scroll_view_port_size`/`$scroll_view_port_offset` (keep [0,0]), `$scrolling_content_anchor_from/to` (default top_left).
- **Scroll textures**: use `$scroll_track_image_control`, `$scroll_box_mouse_image_control`, `$scroll_box_touch_image_control` and `$scroll_background_image_control` (control references). The textures are `ScrollRail`, `ScrollHandle`, `ScrollGutterWithBG`, `ScrollBox` and `newTouchScrollBox`. To hide the scrollbar, `"$scroll_bar_and_track_size": [0,0]`. Clipping differs slightly with resolution.
- **A hand-made scroll view**: not recommended (the vanilla one has necessary button mappings). To make one, copy `scroll_view_control` from vanilla ui_common.json. Give child names to the `scrollbar_track`, `scrollbar_box`, `scroll_content`, `scroll_view_port` and `scroll_box_and_track_panel` properties, and the viewport must be smaller than the content. Map `button.menu_select` pressed + `button_up_right_of_first_refusal` to the box and `button.scrollbar_skip_track` to the track.
- **Horizontal scrolling and others**: the start direction of horizontal scrolling (left/right) is hardcoded. Work around it by putting the slider value into `anchored_offset_value_x` or with animation, and there is also a way to put elements below the scrollbar box (thread 1252224040433614958). A scroll that starts from the bottom is unstable. The problem of a scroll showing even in a scroll panel holding an empty grid is unresolved. If a hidden scroll panel intercepts input, hide or disable the panel itself (`visible` + `enabled`), not the contents.
- **Scrollbars outside the form**: in long_form adjust `$scroll_bar_left/right_padding_size`, `$scroll_size` and `$scrolling_pane_size/offset`. The body label size is `["100%","default"]`. Scroll text sample: https://skyls.de/samples/ui3/RP/ui/server_form.json.
- **A 2D drag panel**: `draggable: "both"` on `scrollbar_box`, the draggable_box and control_layer_panel sizes `["100%c","100%c"]`, `clips_children` on the outer panel, `$scrolling_size` `["200%c - 100%","200%c - 100%"]`. With `contained: true` it drags only down and right, so use false to center it. Controller dragging is unresolved.

### Screen flags and animation
- **Walking with a form open**: give the screen element `"is_showing_menu": false, "absorbs_input": false, "force_render_below": true` (+`render_only_when_topmost`, `low_frequency_rendering`, `render_game_behind`, `$is_full_screen_layout`). For touch, branch with `$touch`/`$is_pregame`. Moving while a button is on screen works only on touch devices and not on console/PC. Overlapping a server form over the HUD also breaks PC/console.
- **Hiding the HUD under a form**: by default the HUD disappears. To hide it again, give the screen `force_render_below: false`. To show an image above a form, use layers (form -1/-99, image 99999. Extreme values go outside the game screen), and putting it inside server_form.json is better.
- **Turning off screen animations**: give `third_party_server_screen` `"$screen_animations": []`/`$background_animations`. Example: a length-0 offset animation on `["@server_form.exit_wait"]` + `screen.exit_pop`/`end_event screen.exit_end`. Per-element screen animations cannot be turned off. NPC dialogue opens without open/close screen animations (used for inventory-slot-shaped forms). The inventory exit animation comes from the live_player_renderer animation.
- **Exit animation**: use `"play_event": "screen.exit_pop"`, `"end_event": "screen.exit_end"` and `destroy_at_end`. In server forms `exit_pop` works and `exit_push` does not. The form closes before the animation ends and there is no way to delay it. You can make a full-screen "video" form with an aseprite animation JSON.
- **NPC dialogue vs server form**: the NPC screen differs from server forms. Scene transitions are smooth but must be predefined and buttons are up to 6. The length of NPC `#student_button_text` is hardcoded. Several forms cannot be stacked on one client.
- **Hover text**: in a custom control `{"type":"custom","renderer":"hover_text_renderer","allow_clipping":false,"layer":200}`, put the `#form_button_text` collection binding in as `#hover_text` (`binding_name_override: "#hover_text"`). `common.hover_text` does not translate lang keys (the game gives translated text). It shows per state with `ignored: "$default_state"`. Putting it inside a button can lose the texture, so add an image background. If a `clips_children` panel clips it, give the child `allow_clipping: false`. Custom hover text loses the automatic screen-edge position adjustment so long text overflows. To show hover text without a container item, put a child `hover@common.hover_text` in an invisible `button@common_buttons.light_text_button` (`$pressed_button_name: ""`, `$border_visible: false`, empty texture, `sound_volume: 0`) and give the text through `#hover_text` in `property_bag` (giving it through a binding does not work). This text is not translated.

## Containers / Chest UI

### Principle
- **Entity-based**: a custom container UI is made by showing an entity with `minecraft:inventory` (`container_type: container`, for example `inventory_size: 30`) and letting JSON UI recognize a name key (for example `§t§e§s§t§r`) as `$container_title`. The slot count must match the UI. Buttons are imitated with slots and the script detects clicks. The "GUI" (container screen) updates in real time and the "UI" (server form) must be reopened. *confirmed*
- **Block-based is not possible**: a block cannot directly show a custom UI. Put a large hitbox entity in or around the block with collision 0, not pushable and knockback resistant. TPS lag arises in proportion to the number of entities. An entity container's title is the name tag, and "unknown" shows if there is no name. A custom block entity `container` supports `title` and `$container_title` works in custom containers, so the UI can be changed per container without the item name toggle hack. For block entity containers, edit `data_driven_container_screen.json` of the 26.60 samples, and for custom entity inventories `chest_screen.json` (there was a case where a 36-slot inventory showed only 27 slots before fixing).
- **Toggle state does not persist**: closing a container screen returns a custom toggle to its default (no solution). There is an opinion that driving slot group display by the item name (`#hover_text`) is easier than a toggle.
- **Vanilla containers**: renaming can change the UI but not for the crafting table. A copper chest is told apart by a screen id like `ui:container.chestDoubleCopper0`, and renaming returns it to the ordinary screen. Shulker color and oxidation stage cannot be detected with pure RP (set the name with a script). A container UI name can be changed only by the item name and not by the block name.
- **Click detection**: map `button.drop_one`/`button.drop_all` to buttons (`button.menu_select` -> `button.drop_all`) and decide the target slot with `property_bag {"#collection_name":"container_items","#collection_index":"$i"}`. Detect it in the script as an item drop, which is better than the cursor component that fails on mobile. The target to modify is `small_chest_panel` (modifying `small_chest_screen` kills it. There is also a case where replacing it with an empty panel crashed).
- **Blocking quick move**: shift-click quick move cannot be removed. Delete the item as soon as it is gained or revert it with an inventory change event. There is no script API to bind keys to the UI, so use `button_mappings`.
- **Player inventory preview**: cannot be seen in a custom chest JSON UI form. Work around it with an entity container (for example a llama inventory). A server form cannot show the inventory or dress armor by dragging (work around it by showing the inventory's armor list as buttons and equipping). The `inventory_items` collection is screen-specific so it cannot be reused with `flying_item_renderer`.
- **Slot text**: read the item name or lore as `#hover_text`. In a container it is wrapped as `§o§f<name>§r§r§r` (`§o` only when the name was changed. With lore it is `'§o§f' + name + '§r\n§5§o' + lore`), so strip it: `(#hover_text - ('%.6s' * #hover_text))` or `(#hover_text - '§' - 'r' - 'o' - 'f')`. Making a dynamic texture from the name: `('textures/ui/EXPbar' + (#hover_text - '%.6s' * #hover_text))`. Detect slot state by the item name the script decides (not a lang key).
- **`#hover_text` caution**: it becomes empty on click or interaction, so keep a snapshot with a `visibility_changed` override. Using a drop mapping avoids this problem. The lore and durability of hidden items can be used as a text/display channel. Do not poll; update only changed slots. You can hide the default stack count and change 1000 to 1K. Reports of failure (an attempt to build `#entity_id` from hover text failed because of formatting codes) and success (chest_boat) are mixed. There is also a failure report where trying to preserve the collection `#hover_text` with `visibility_changed` + `binding_name_override` made even the label disappear. `#inventory_stack_count` has no value when the item is 1, and number comparison has to be like `(0 + #inventory_stack_count) = 4` (`#inventory_stack_count = 4` is always false). **conflicting**
- **A progress bar trick**: if you set the item name to a number (anvil/script) and use it as the `#clip_ratio` of a hidden chest slot (`collection_index`, `container_items`), you do not need a separate item per frame. To put a progress bar in a chest UI, insert `progress_bar@common.progress_bar` into `small_chest_panel` (or `_top_half`). There is no way to put arbitrary label text in a chest UI, so work around it with a hidden item whose durability is read as a number (heavy).
- **Size and resolution**: the UI scales up and down with resolution and the position cannot be fixed. Fit the smallest resolution or provide an alternative. The vanilla chest UI showed only 27 of 54 cells unless the UI was fixed. For the slot count limit there are the report that a block `minecraft:inventory` is at most 54 and an entity inventory 255/256 (vanilla has no UI that large), and the claim that a block entity UI is 32 by default and more needs JSON UI. **conflicting** Attempts to change the chest grid size by container title (`variables` + `$slot_count`, `$grid_size`, `$grid_dims`) did not work (no answer). The survival inventory cannot be replaced or have slots added and only its look can be changed. You also cannot change the inventory screen with scripts.
- **A container detection variable example**: `{"requires":"(('%.15s' * $container_name) = '§t§o§m§b§r')","$screen_content":"chest.custom"}` as an `insert_back` into `variables` in the `small_chest_screen` modifications.

### Herobrine643928 Chest-UI and alternatives
- **Chest-UI**: https://github.com/Herobrine643928/Chest-UI is the standard library for making chest-shaped forms with ActionFormData + JSON UI. The license is CC BY 4.0, so commercial use, modification and redistribution are allowed with attribution (repository LICENSE checked). There are reports that it cannot scroll and that misuse breaks other UI. The layouts it uses in `ui/_global_variables.json` must be turned on (`$disable_9_slots_layout`, etc. true = off). Old copies have the flags off and leave a "dur#00" afterimage. The generic_9..54 textures are taken from bedrock-samples. To make an item vault, items must be stored directly in a dynamic property or structure. It is not a 1:1 chest UI.
- **The typeIds problem**: it depends on `typeIds.js`/`typeids.ts`/`constants.js`, which map vanilla items to aux/type ids. Adding a custom item in any BP shifts vanilla ids, and it goes stale with every new release. Upstream updated around 2025-11-18 (issue #27). It lagged behind even in 1.26.13. Fixes: rebuild from https://github.com/Mojang/bedrock-samples/blob/main/metadata/vanilladata_modules/mojang-items.json, generate at runtime with `ItemTypes.getAll()`, or use real texture paths instead of aux ids. A wrong texture is usually a typeId error.
- **The 1.21.130 broken texture fix**: change the `aux_id` binding `(#form_button_texture * 1)` in chest-server_form.json to `((#form_button_texture - (#form_button_texture % 65536)) / 65536)` -> `#item_id_aux` (https://github.com/stievenw/Chest-UI/blob/main/RP/ui/furnace_server_form.json, forks https://github.com/Herobrine643928/Chest-UI/forks). *confirmed*
- **Alternatives and forks**: Sprixvy Chest-Form (TypeScript): https://github.com/Sprixvy/Chest-Form/tree/typescript. `form.button(slot, name, typeId, { amount, description: [...], durability, enchanted })`, and the result has `type` 'container'|'inventory' and `slotIndex`. Unpublished forks support dynamic slot counts, unclickable empty slots, `ui.glassBorder()` and durability bars. syylaxx was making a dynamic slot replacement and bakedpotato4173 a dynamic grid in the `.body('10:10')` style. The chest menus on big servers that look like DDUI (CubeCraft) are JSON UI chest forms using a packet trick (confirmed by clearing the pack cache and reconnecting).
- **Chest UI Editor (minato4743)**: https://minato.beyondbedrock.org/web-apps/chest-ui-editor/ (beta: `/chest-ui-editor-beta/`, another address https://minato-mba.github.io/web-apps/chest-ui-editor/). It places slots, images, text, buttons, 0-9 progress bars, ON/OFF indicators, tabs and scrolling slot lists, and exports as ZIP and reloads it. Block container support is planned after block containers and title become stable. v2 (2026-05-16) added multiple screens, dynamic grids and scrolling, and v3 (2026-09-21) added `anchor_from`/`anchor_to`/`offset` and v2->v3 migration. It is expected that Ore UI chest screens will override RP chest UI in the future.

## Tips by vanilla screen

- **File names**: mostly the same as the screen name. start_screen.json (start_screen / start_screen_content), progress_screen.json (world loading), hud_screen, chat_screen, inventory_screen, furnace_screen (the blast furnace derives from here), redstone_screen.json (hopper, dispenser, dropper, crafter), online_safety_screen.json, `ui_art_assets_common.json` (the Minecraft title), trade_2_screen.json (the villager progress bar), enchanting_screen.json, horse_screen.json, scoreboards.json, `store_data_driven_screen.json` (the Marketplace store), disconnect_screen.json, `hud_crosshair_overlay.json`.
- **Pocket vs classic**: pocket screens use their own content files. The smithing table is `smithing_table_screen@common.inventory_screen_common` and `$pocket_screen`/`$use_smithing_table_2_ui` choose the `smithing_table_pocket`/`smithing_table_2_pocket` panels. The furnace's `#is_recipe_book_layout` exists only in Classic. Forcing Classic with a variable makes the inventory the creative layout. Some packs force the Classic layout by making the `$screen_content` of the desktop and pocket UI the same (for example the Colourful Ore UI pack).
- **Inventory**: `inventory_screen` and `crafting_screen` both extend `crafting.inventory_screen_base`, so use the bindings of inventory_screen.json. Around 2026-02 in stable, the inventory/crafting UI was refactored and elements moved to common files, and custom crafting UIs broke (no `recipe_book2` base. Server forms and NPC are unchanged). To turn off tabs, `toolbar_panel` `ignored: true`. The translucent "shadow" strip is the `shadow_stack` of `tab_content/.../items_panel`. The "Nature" tab label is hardcoded in `#hover_text`, so empty it with the lang `craftingScreen.tab.nature=§z`. Detect creative by modifying the inventory UI (`#is_creative_mode`). To block inventory interaction, give `force_render_below: true`, `is_showing_menu: false` and `absorbs_input: false`, but it blocks other containers too. The E key is hardcoded. A custom crafting table screen can be made with JSON UI alone. The recipe book divider is `center_fold` (texture `textures/ui/recipe_back_panel`). Also refer to `inventory_screen.json` and `inventory_screen_pocket.json`. To fill the player list grid horizontally, give `"grid_fill_direction": "horizontal"`.
- **Pause screen**: put children in `pause_screen_content`, not in `pause_screen`/`root_panel` (otherwise the buttons disappear). The logo `textures/ui/title.png` can be replaced and can be animated with aseprite_flip_book on `title_image` in `ui_art_assets_common.json`. `"quit_button": {"size":[48,48]}`. Button textures are `textures/ui/button_borderless_light`, `...lighthover` and `...lightpressed`. Hiding the store/server buttons: `"menu_background/button_panel/store_button_panel": {"ignored": true}`. The feedback web link is hardcoded. You cannot run a command with the pause menu "shop" button (unconfirmed). If you replace `pause_screen` wholesale and resume/quit do not work, the world is locked until restart, so map `button.menu_cancel` and `button.controller_start` to `button.menu_continue`. There is a report that using a pack that removes the Marketplace button turns off achievements. *single report*
- **Start screen**: the buttons are in `main_buttons_panel` (`main_buttons_and_title_panel@start.main_buttons_stack_panel`) inside `main_buttons_stack_panel`. Hide the original with `"main_buttons_panel": {"ignored": true}` and `insert_front` your own stack panel into `start_screen_content` (using references like `floating_play@start.play_button`). The Store button is a "buy game" button, so show it, hide the shop button, and then edit the win10 trial conversion screen. A custom screen can be reached only through an existing screen's button id (Deesee UI uses the trial-conversion screen as an info window).
- **Chat screen**: to hide the coordinate copy header, set `chat_header/title_panel/chat_header_content_area` `ignored: true` and remove the `chat_header/title_panel/title` binding (it still copies with ctrl+alt+c and it is an RP so it can be bypassed). Hiding command autocomplete: render `commands_panel`/`auto_complete_panel` conditionally with `#auto_complete_text` (collection `auto_complete`). Add buttons by modifying `chat_screen.json`. The copy button (coordinate copy) is hardcoded and cannot be reused.
- **Other screens**: to change only the enchanting table background, define `dialog_background_opaque` in `ui_common.json` (namespace `common`) with `"texture":"$opaque_background_texture"` as the default, and set `$opaque_background_texture` in `enchanting_panel` of `enchanting_screen.json` (namespace `enchanting`). The chest background is `dialog_background_opaque` through `$dialog_background` of `common_panel`. Close button: global is `textures/ui/close_button_default`, and per panel `{"namespace":"chest","small_chest_panel":{"$close_button_default_texture":"textures/ui/your_texture"}}`. Hiding the disconnect "An error has occurred": insert a `(#title_text - 'disconnectionScreen.title.errorOccurred')` -> `#text` binding into `disconnect_screen.json`. Removing the loading modal: `world_convert_modal_progress_screen_content`. Scoreboard sidebar: `anchor_from`/`anchor_to` `left_middle` on `scoreboard_sidebar` in `scoreboards.json`. If names are cut at about 100 width, set the `size` and `max_size` of `scoreboard_sidebar_player` to `["default","default"]` (a fixed 200 has no effect).
- **Marketplace store text color**: override `store_data_driven_screen.json` (keys `store.editorial.tab.about`/`notes`). The global color is `_global_variables.json` (`"$title_text_color":[0.5,0.5,0.5]`). Changing the purchase button to download is not allowed.
- **Resource pack screen label color**: giving `resource_packs.gray_label` a `color` does not change it. Give `input_button_panel` `"$default_glyph_color": [1, 1, 1]` (confirmed to work). [supplement 2026-10-29]
- **Item tooltips**: the tooltip is in `highlight_slot_panel` (`hover_text_renderer`) of `ui_common.json` and not in the HUD. The border is `textures/ui/purpleBorder.png` and is hardcoded based on screen size. For a custom tooltip, give the `highlight_slot_panel/highlight` modifications an `$item_collection_name` + `#hover_text` binding and choose the frame with a `§` marker code. Empty slot check: `(not (#hover_text = '') and (... = #hover_text))`. A tooltip background that follows the cursor can be changed with ordinary JSON UI (cases of custom inventory/crafting table/anvil/beacon screens). A custom tooltip made with an input_panel jitters. The vanilla "Attack Damage" line cannot be removed (only the label is emptied with lang). The "Dyed" line is also hardcoded and cannot be changed completely. Lore put into lang with `\n` also shows in the name of the held item, and lore tooltips cover the inventory on mobile. Hiding enchantment description lines: `/gamerule showtags false`. Tooltips (26.50): static text is lang `tile.<item id>.tooltip=<text>` (custom uses the namespace id, items also take the `tile.` prefix. In the 26.70.22 preview, `item.<id>.tooltip` and `~LINEBREAK~`), and dynamic text is `ItemStack.setLore()`. The tooltip text color can collide with a custom background.
- **Loading tips and screens**: the loading tip JSON keys are `loading_messages`, `beginner_loading_messages`, `mid_game_loading_messages`, `late_game_loading_messages`, `realms_loading_messages`, `addons_loading_messages`, `creative_loading_messages` and `editor_loading_messages`. An item can be written like `{ "message": "...", "condition": "$marketplace_not_disabled" }`. The dimension loading screen `overworld_loading_progress_screen` appears to be hardcoded and cannot be chosen per dimension.

Global resources and the old settings section still open the old JSON UI. Textures: new textures are in `textures/ui` and `textures/gui` is used only partly (classic touch). If you override `gui`, the old ones come back with glitches. The touch inventory button is 4 textures, not just gui.png. The mobile ellipsis is 2 textures.

## Script API forms (`@minecraft/server-ui`)

- **Basics**: there is no separate "JS UI". Script UI is the server-ui forms (ActionFormData, ModalFormData, MessageFormData), and adding UI to vanilla screens needs JSON UI. server-ui 2.0.0 stable, 2.1.0-beta (2025-11). As of 2026-07-06: stable 2.1.0, beta 2.2.0-beta.1.26.32-stable, preview beta 2.2.0-beta.1.26.40-preview.29. Docs: https://stirante.com/script/server-ui/. The `addButtonList`/`getSelectedButtonId` that AI invented do not exist. After 26.60 stable (2026-10-28): stable 2.3.0, beta 2.4.0-beta.1.26.60-stable, preview 2.4.0-rc.1.26.70-preview.21, preview beta 2.5.0-beta.1.26.70-preview.21.
- **ModalForm values**: `formValues` has an item (null/undefined) for every element including header/divider/label. The index matches element order. It was first changed to skip non-input elements and reverted for server backward compatibility. To filter, use `values.filter(v => v != null)` (this keeps `false` toggle values. `!== undefined || !== null` is always true). Values arrive only after Submit and there is no real-time dropdown callback.
- **Text field and slider**: `ModalFormData.textField(label, placeholder, { defaultValue, tooltip })` (the new module. The old string third argument is an error). `defaultValue` must be a string or RawMessage and a number throws, so `String(Math.floor(n))`. The slider takes an options object `{defaultValue, valueStep}`. Raise length limits with JSON UI or split into several fields.
- **Display timing**: when opening a form from a command or event, open it inside `system.run` or after `await null` (a `beforeEvents` handler). A form opened in `playerInteractWithBlock` fires repeatedly, so block it with `isFirstEvent`. If chat or the HUD is open it fails with `cancelationReason === FormCancelationReason.UserBusy` ("UserBusy". Renamed from `userBusy`), so try again: `forceShow(form, player, maxRetries=300)`. Import `FormCancelationReason` from `@minecraft/server-ui`, not `@minecraft/server`. A chat command trigger closes chat late, so a `/` custom command is better. Use the same retry for the first-spawn welcome screen.
- **Force closing**: close script forms with `uiManager.closeAllForms(player)` (`UIManager.closeAllForms()`, first in beta). It does not work on DDUI forms. There is no feature to hide a ServerForm after some time.
- **Button icons**: `.button(text, iconPath)` accepts a path like `textures/items/...`. For a dynamic list, make buttons from an array (for example `world.getPlayers()`) and map `response.selection` back to the array index. The maximum number of body lines is decided by JSON UI. Cascading ActionForms (a menu calling a menu) are common.
- **Text**: `§` color codes work in the title, header and label. Center alignment in an ActionForm is done with spaces or JSON UI (one person used a `§\` prefix as a key). Custom button shapes and backgrounds need JSON UI.
- **Other script matters**: scripts cannot read translated item names (only keys). They cannot read the inventory search box string either. "Selecting" an entity inventory item is client-only. There is no native API to hide HUD chat. There is no health component `minecraft:hunger` in scripts (`player.hunger` is also unconfirmed).

## Data-Driven UI (DDUI, CustomForm)

### Status and timing
- **History**: it first became known in 2025-11 from traces in server-ui and the JSON schema (`metadata/json_schemas/client/ddui/1.21.130`) of the bedrock-apis/bds-docs preview branch. 2025-12 alpha classes: `DataDrivenScreen.showScreen(player, screenId)`, `DataStore` (the `ddui` constant. getProperty/setProperty/getPropertyPath/setPropertyPath/setClientWritable/subscribe/unsubscribe), `closeAllDataDrivenScreens(player)` (types in bds-docs `types/@minecraft/server-ui-bindings_3.0.0-alpha.d.ts`). It needed an experiment toggle and failed silently without it. It entered preview in 2026-02, beta in 2026-04 and stable in 26.30 (2026-06-16). In 2026-06 the internal DDUI API moved to C++.
- **RP file format (alpha)**: `resource_pack/ddui/root/<file>.json` (the final screen) and `ddui/composition/` (reusable components). It uses `format_version 1.21.130`, `minecraft:ui-root`, `description.identifier`, `attribs.root_point: minecraft:screen` and `layout.markup` tags (`Panel`, `Panel.Text`, `Panel.CloseButton`). Custom RP panels are still internal-pack only. *single report* The format seen in the 26.70.23 preview has `layout` as an array of `component` objects: `{"component":"minecraft:form.panel","style_id":"modalForm","children":[...]}`, with children `minecraft:form.text`, `form.spacing`, `form.close_button`, `primitive_checkbox` (`checked`) and `form.textfield` (`value`, `label`, `max_length`). Whether it replaces the markup format is unknown.
- **What it can do**: in 2026 stable/beta 26.x, DDUI is at the level of replacing the script's ActionForm/ModalForm/MessageBox. All elements can be mixed (button + toggle), the data of an open form updates in real time, and animated content (image loops, video-like frames: jeanmajid/MCPE-DDUIRenderer) also shows. Good for admin panels. Official documentation: https://learn.microsoft.com/en-us/minecraft/creator/documents/scripting/intro-to-ddui.
- **What it cannot do and complaints**: you cannot change size, background, button size, font, tooltip alignment, close button or position with an ordinary RP (the way to replace the Ore UI files themselves with a trusted pack is in the Ore UI modification section below). It is narrow and plain, it was slow at launch, it jitters, the scrollbar loads late, and several Minecraft fonts including a blurry font are mixed. `visible` does not erase children. Color codes work only in the title and label (there is also a report that label color codes do not work). The grid is a "label with squares". The HUD and read-only non-blocking overlays are not yet possible (the HUD later). The `cache screen` proposal caused a crash. Custom fonts can be referenced in layout files but are not public and only hardcoded fonts work.
- **Coexistence with JSON UI**: JSON UI forms and DDUI are incompatible (JSON UI files cannot be used in DDUI). ActionFormData is the simplest for button lists and can be decorated with JSON UI, so it keeps being used. The community consensus is that "once DDUI can be decorated, Action/Modal forms become useless". Old action forms may be deprecated someday.

### The CustomForm API
- **Observable**: values are made with `new ObservableString(text)` / `new ObservableString('', {clientWritable:true})` / `ObservableNumber(0,{clientWritable:true})` (the early form `Observable.create`). Use `setData()`, `getData()` and `subscribe(cb)` (for user input controls). Pass the observable itself to a label (`.label(obs)`. `.label(obs.getData())` does not update).
- **Methods**: `.label(obs)`, `.header(text,{styleId})`, `.textField(label, obs, {description})`, `.dropdown(label, obs, [{label,value}])`, `.toggle`, `.button`, `.spacer()`, `.divider`, `.closeButton()`, `.image()` (use with an observable is still preview. It once did not work in stable. Check the jaylydev docs), `.show()`, `form.close()`. Options `ButtonOptions.disabled`, `ToggleOptions.disabled`. Wait for player loading with `canShow`. In recent previews, custom forms got icons (position cannot be adjusted). `ImageOptions.onClick` has no coordinates (requested).
- **The real-time label pattern**: call `obs.setData(newText)` inside `system.runInterval` and clear the interval in `.show().finally()`. Values must be reread every tick (a captured constant does not change).
- **Form switching**: in a button callback, `form.close()` then `system.run(() => nextForm(player))`. Put the form in a variable and call `form.show()` separately (the result of `.show()` is a Promise so do not assign it).
- **Known problems**: the close button cannot be removed (a bug. A fix is planned). The observable `label` inside a dropdown `DropdownItemData[]` is not updated after `setData()` (the dropdown `description` ObservableString updates. Unresolved). There was an error where the form did not appear after an hour of use, and advice was to wrap `setData` in try/catch, create new observables each time it opens, and try server-ui 2.0.0. Putting all of `ItemTypes.getAll()` in a dropdown freezes the game, so cut it to about 20 and drive it with a search observable. There was no answer on how to control a slider in real time while fading a DDUI screen.

### DDUI styles (preview)
- **`styleId`**: see the 1.26.60.28 preview: https://gist.github.com/theaddonn/b28c71e65b6585910c6a8d58a019a4d4. The `styleId` option of `CustomForm` and controls is used like `new CustomForm(player, 'My Form', { styleId: 'ns:my_form', topCloseButtonVisible: true })`, `form.header(text,{styleId})` and `form.textField(label, new ObservableString('Steve',{clientWritable:true}), {styleId})`. In 1.26.60 a native mod was needed to turn it on. `@minecraft/server-ui` 3.0.0-alpha (tested in 26.70.21) supports it without a mod. Only the look (for example opacity) changes. There is a report that even with module version `alpha` the vanilla styleId renders and behaves the same as `internal` (registering new styles was not tested). *single report*
- **Textures of other packs**: a trick appeared that you can use another pack's texture without the UUID by breaking the query of a DDUI image path like `pack://textures/x.png??packId=`. There is an opinion that it may be blocked soon. [supplement 2026-10-24]
- **Force close key (26.70.22 preview)**: there is "Close Custom Screens" (ALT + key) in the Macros settings. The changelog calls it "Creator Screens". It solves the problem of forms with the top close button removed not closing even with ESC. [supplement 2026-10-28]
- **Style file format (an unpublished demo)**: `"format_version": "beta"`, `"minecraft:ui-style"` (`description.identifier`, for example `ddui_demo:parchment`), and `components` with `minecraft:form_panel` (image, padding), `minecraft:form_label` (color, shadow) and `minecraft:form_textfield` (text_color, caret_color, selection_background_color, text_color_disabled). The script uses `new CustomForm(player, title, { styleId })` and a per-label `styleId`, and reloads at runtime with `/reload ddui`. It was found by static analysis of the game, Education Edition and LeviLamina and uses internal features not in the public API. *unverified* in stable
- **Wanted features (community draft)**: an image/icon next to a button, a size property, more than 3 buttons per row (grid), and flexbox-like layout. The same gist is the draft spec.

## Ore UI modification (unofficial)

- **Only trusted packs are read**: an Ore UI `ui://` request looks at the pack stack first but skips untrusted packs. Only zip/folder packs installed with the game are trusted, and the encrypted access strategy (`DirectoryPackWithEncryptionAccessStrategy`) is always trusted even without a signature. So the `hbui/` files of an encrypted pack the server sends (marketplace format: magic `0x9BCFB9FC`, AES-256-CFB8, IV = the first 16 bytes of the key, gophertunnel `pack.WithContentKey`) or of a local pack with an empty `content.zipe` file in its root (no key needed, files are plaintext) replace the vanilla HTML/JS/CSS. A .mcpack must have `manifest.json` and `content.zipe` at the zip root, and one level deeper the import fails silently. It was tested on Windows and Android 1.26.52. Details: `ore-ui-loading/` in this repository. There is a report that the method of putting only a fake encryption header in `contents.json` failed and only `content.zipe` worked. There is also a remark that Mojang was heard to be going to block this path, but as of 2026-11-13 it had not been observed to be blocked. *unverified*
- **Scope and cautions**: you can change `gameplay.html` (5 routes: death, bedtime, data-driven, trade, pause-menu/dbug-drawer) and the loading screen. The menu-side `index.html` (116 routes: main-menu, play, edit-world, export-world, oreui-settings, etc.) can also be changed with a global resource pack, and needs a game restart to apply. The HUD and inventory are JSON UI so do not apply. The hashed names `gameplay-<hash>.js` and `index-<hash>.js` must be fixed for each game version (if wrong, no Ore UI screen shows. They changed in 26.62.1 too), and if the pack version is not raised the cache remains. CSS class names are also hashes that change per build. There is an opinion that if you only append without modifying existing elements, no hash is needed. The runtime is V8 (not QuickJS). `localStorage` persists across going to and from servers until the game is turned off. The router keeps location at `/hbui/gameplay.html#`, so screens cannot be told apart by URL. Gameface does not send `click` to ordinary divs (use `mousedown`), has no `<audio>`, video works only as WebM, and http/https loading fails. The engine blocks external network access from the UI, so external content must be relayed by the server (a case of showing an external web page through a server proxy). There is a report that iframes do not work. There is a report that changing the `<video>` src dynamically failed. JSON UI dialogs are drawn over Ore UI. In the world list, Ore UI cannot read cheats, whether flat, or the world's pack list. An unencrypted pack reaches Ore UI only through the `common_buttons.light_text_button` textures and colors and `pack://textures/...` paths. Per-platform hbui install paths: https://github.com/8Crafter-Studios/Ore-UI-Customizer-App/blob/69f6ebbb6d7aa689d79e860929ccf61d6d7bed00/src/utils/config.ts#L110 [supplement 2026-10-24..11-05]
- **Hidden vanilla features**: overriding the bundle .js can revive Android's "Export world" and the "Debug" tab of world editing (Flat nether, game version override, spawn biome) (wadudi, `OreUI-ImportExportUnhiderv5.mcpack`, 26.60). [supplement 2026-11-01..03]
- **Community cases**: doomgeneric built with emscripten runs inside Ore UI at about 249fps (tutinoko9900). A Cobblemon-style screen with more than 1,025 buttons (kongsonnyson). A Pokedex synced with a Dragonfly server, dragging, zoom, and nested forms. A React library test. @bedrock-core added an experimental Ore UI host (https://bedrock-core.drav.dev/docs/ui/guides/experimental-ore). - **Local file editing**: the css/js/textures of Ore UI can be edited locally in the game install folder. Examples: `...\Minecraft Preview for Windows\Content\data\gui\dist\hbui\gameplay-theme-<hash>.css` (class `.modalForm`), `hbui\assets\neutral-elevated-control-panel-<hash>.png`, stable `C:\XboxGames\Minecraft for Windows\Content\data\gui\dist\hbui\assets`, UWP package `...\Microsoft.MinecraftUWP_1.26.6301.0_x64__8wekyb3d8bbwe\data\gui\dist\hbui\gameplay-react-<hash>.js`. The hash changes with every update. It applies only to that client and is not an RP feature. css hot-reloads with `/reload all` and Ore UI screens are recompiled every time they open. Android needs the APK rebuilt. There is also a report that editing had no effect at the 2025-12 alpha stage.
- **Reusing assets**: Ore UI assets in `hbui/assets` can be used as JSON UI textures by renaming them and setting nineslice (in Ore UI, nineslice is applied on the script side).

## Renderers (entities, items, structures)

- **`live_player_renderer`**: `{"type":"custom","renderer":"live_player_renderer","property_bag":{"#entity_id":"<id>"}}`. The id is `player.id` and it shows equipment automatically. It always shows the held item and follows the cursor. After the spear update (2025-12), holding some items hid custom attachables, which was fixed with a high layer (10 worked, 100/500 did not, 999 did). It cannot be forced to always render (`hud_player_renderer` is the same). There is no live renderer that renders several entities at once (pass an entity id per button).
- **`live_horse_renderer`**: renders on any screen with `#entity_id` (Script API `entity.id`). The id must be a **string**. If it is only digits it turns into a number and fails, so pass the original through subtitle/`#form_text` (`.body()`). `property_bag {"#look_at_cursor": true}`. It always follows the cursor (in forms. Not in the HUD where the cursor is consumed) and cannot be turned off. It can show a player model with armor. The entity must be spawned near the player and visible, and scale tricks have no effect on UI. To change the model, change the render controller with an entity property or an NPC model.
- **`profile_image_renderer`**: draws a profile image by binding a JSON string (`{"type":N,"userId":"..."}` or `{"type":7,"url":"https://..."}`) to `#profile_image_options`. It can be overridden with `property_bag` and view bindings. As of 2026-10-27 types: 0 none, 1 MinecraftHeadshotByXuid, 2 MinecraftHeadshotByPlayfabId, 3 MinecraftAvatarByXuid (a report that it does not work), 4 MinecraftAvatarByPlayfabId, 5 XboxLiveSmallGamerpicByXuid, 6 XboxLiveSmallGamerpicByUrl, 7 XboxLiveFullClubsImageByUrl (an image from an arbitrary URL), 8 MinecraftSkinByXuid (does not work), 9 MinecraftSkinByPlayfabId. The numbers differ from 2025-02, so they appear to change per version. Whether it is cached is unknown. Type 7 works on all screens including hud_screen. 16:9 worked and a 5:1 banner did not. Even with the same request, some CDNs (the MinIO development CDN) are not drawn while Cloudflare R2 worked. There is a report that only one renderer works at a time. There is also a report that it worked only with a `property_bag`. *single report* (the type table) [supplement 2026-10-26..11-04]
- **`paper_doll_renderer`**: renders yourself (no movement or armor, the cape shows, affected by invisibility and 4D skins). It is taken from `pause_screen.json`. Stop rotation with `starting_rotation: 0` + a drop gesture binding. A specific player's skin is UUID + paper_doll, and `use_skin_by_name` takes a skin uuid. A custom geometry cannot be used in a paper doll. Put in a small panel with `clips_children: true` it can show the player's head. A 3D UI can be made by changing player geometry bones with `query.is_in_ui`. A speedometer is made with player.entity.json + paper doll + `query.ground_speed` (2 render controllers).
- **Item renderer**: `renderer: inventory_item_renderer` (or `item@beacon.item_renderer`, `common.item_renderer`) with `#item_id_aux` (needs property_bag `{"#item_id_aux": 0}`). aux = numeric id * 65536 + data, with enchantment +32768. Blocks work well and items need an offset (not a raw aux id). There is a report that it works only inside a grid layout and not inside scroll panels or factories. The 2026-01 problem where an explicit aux showed as a wrong item (kelp, piston) was worked around with a property bag string (`"#id_aux":"@21954560"` + `(#id_aux - '@')`). With layer 100 the item hid and 4/50 were fine. The `common.item_renderer` of a container ignores layer for many blocks/items (unresolved).
- **aux id cautions**: aux ids shift with the version and installed add-ons so they cannot be computed at runtime across add-ons. There is also no way to get an item id directly (official list: the learn.microsoft.com vanilla list. No spear). Getting the name from an aux id is also impossible. aux is unstable on mobile. A form button usage example: `.button("§f§l§a§g§0§r", "aux:65536")` + `('%.4s' * #texture = 'aux:')`, `(#texture - 'aux:')` -> `#item_id_aux`. In performance the item renderer is better than the structure renderer. There is no dynamic item/block icon API, so refer to texture paths.
- **`3d_structure_renderer`**: give `type:"custom"` the property_bag `#block_position`, `#top_right_block`, `#bottom_left_block` (arrays [x,y,z]), `#include_entities`, `#remove_blocks` and `#include_players`. The area must be loaded, a big area freezes the game, and arrays cannot be manipulated. There is no script API for .mcstructure preview. 3D block rendering is hardcoded, so use the item renderer or pre-taken screenshots (Blockbench).
- **Other renderers**: `bundle_tooltip_renderer` (gameplay_common.json, control `bundle_tooltip`) can make a custom tooltip that is not cut by the screen. But it follows the parent size, pops on touch/small screens, and breaks with a grid of more than 12 cells. `progress.progress_bar_renderer` is the durability bar renderer (fixed look, `#color`). Vanilla `durability_bar` has `property_bag {"drop_shadow": true, "is_durability": true, "round_value": true}` and overrides `#item_durability_visible`/`#item_durability_total_amount`/`#item_durability_current_amount` to `#touch_progress_bar_visible`/`#progress_bar_total_amount`/`#progress_bar_current_amount`. No way to get the durability value out as text was found. `#item_durability_current_amount` is a float, and doing `* 1` in string concatenation gave an empty value. A minimap using the paper doll render path flooded the log when the pause screen opened and came close to crashing. `web_view_renderer` example: https://github.com/Xterionix/extended-bedrock-samples/blob/4289aa5550c18608e25f9487f89b766d82168f7c/resource_pack/ui/code_screen.json#L236.
