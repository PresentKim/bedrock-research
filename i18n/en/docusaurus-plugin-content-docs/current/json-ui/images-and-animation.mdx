Images are drawn by `image` controls. The basics are stretching one texture (`fill`), repeating it (`tiled`), stretching while preserving corners with 9-slice, and showing only part of it (`clip_ratio`). What the engine draws directly (item icons, player models, hearts) is the `custom` type + `renderer`, and what changes over time is animation (`anim_type`).

## The smallest examples

**Example 1. Image.** `texture` is a path from the pack root without an extension. With `uv` and `uv_size` you can use only part of a big texture.

```json
"icon": { "type": "image", "texture": "textures/ui/my_icon",
  "size": [ 16, 16 ], "uv": [ 0, 0 ], "uv_size": [ 16, 16 ], "bilinear": false }
```

**Example 2. 9-slice.** Put `textures/ui/my_panel.json` next to `textures/ui/my_panel.png`. The 4 corner cells stay as they are and only the center stretches.

```json
{ "nineslice_size": 4, "base_size": [ 16, 16 ] }
```

**Example 3. Progress bar.** Bind `#clip_ratio` (0.0~1.0) and decide which side it is cut from with `clip_direction`. Keep the binding condition at `always` or `always_when_visible` (6 uses each in vanilla). To make 0~1 from an integer value (0~100), use a dot-leading real literal like `.01` (EXP-27).

```json
"bar": { "type": "image", "texture": "textures/ui/bar_fill", "size": [ 100, 8 ],
  "clip_direction": "left", "clip_pixelperfect": false,
  "bindings": [
    { "binding_type": "view", "source_property_name": "(#percent * .01)",
      "target_property_name": "#clip_ratio", "binding_condition": "always" } ] }
```

**Example 4. A slide in -> wait -> slide out animation** (see the code of 9.3 below). An animation control has `anim_type` instead of `type`, and is attached with `anims` or referenced directly in a property value as `@namespace.name`.

## Image property table (Bedrock Wiki, MS Learn)

This is organized from the Sprite table of the Bedrock Wiki JSON UI Documentation and the MS Learn `ui_element` table (both list `texture`, `uv`, `tiled`, `keep_ratio`, `bilinear`, `fill`, `grayscale`, `clip_pixelperfect` and `nine_slice_*`).

| Property | Type | Meaning |
| --- | --- | --- |
| `texture` | string | Path from the pack root (for example `textures/ui/White`) |
| `allow_debug_missing_texture` | boolean | Draws a missing-texture image when the texture is absent. Default `true` |
| `uv`, `uv_size` | `[u, v]`, `[width, height]` | The start point and size of the region of the texture to use |
| `texture_file_system` | string | Where to read the texture from. `InUserPackage` (default), `InAppPackage`, `RawPath`, `RawPersistent`, `InSettingsDir`, `InExternalDir`, etc. |
| `nineslice_size` | integer or `[x0, y0, x1, y1]` | 9-slice. Corners fixed, the rest stretches |
| `tiled` | `true`/`false`/`"x"`/`"y"` | Repeats if the control is bigger than the texture. `tiled_scale` is the scale of the repeat unit |
| `clip_direction`, `clip_ratio` | `left`/`right`/`up`/`down`/`center`, 0.0~1.0 | The side clipping starts from and the ratio. Without `clip_direction` nothing is clipped, and the default `clip_ratio` is 1.0 (ANI-48). The wiki says to bind a `#*_ratio` binding to `#clip_ratio` with the `always` condition, and that the furnace progress arrow and fuel image work this way |
| `clip_pixelperfect` | boolean | Clips exactly pixel by pixel where possible. Default `true`, rounding the clip down to texels (ANI-49) |
| `keep_ratio` | boolean | Keeps the ratio when resizing. Default `true` |
| `bilinear` | boolean | Bilinear interpolation when resizing. Default `false` |
| `fill` | boolean | Stretches to the control size. Default `false` |
| `grayscale` | boolean | Draws in grayscale |
| `force_texture_reload` | boolean | Reloads when the texture path changes |
| `base_size` | `[width, height]` | Base size of 9-slice |

The `nine_slice_left/right/top/bottom` of the MS Learn table (including the spelling `buttom`) are names that do not appear in this project's exhaustive vanilla search (they resemble names in the China edition documentation, and the international edition uses the `.json` file approach, DBG-27).

## Easing and animation types

The values and arguments of `anim_type` (Bedrock Wiki Intro): `alpha` (real number, opacity), `offset` (`[x, y]`, position relative to the anchor), `size` (`[width, height]`), `flip_book` (integer, an image that changes frames one at a time), `uv` (array, UV position), `color` (RGB 0.0~1.0), `wait` (number, wait), `aseprite_flip_book` (sprite sheet) and `clip`.

The full list of `easing` (wiki): `linear`, `spring`, `in_quad`, `out_quad`, `in_out_quad`, `in_cubic`, `out_cubic`, `in_out_cubic`, `in_quart`, `out_quart`, `in_out_quart`, `in_quint`, `out_quint`, `in_out_quint`, `in_sine`, `out_sine`, `in_out_sine`, `in_expo`, `out_expo`, `in_out_expo`, `in_circ`, `out_circ`, `in_out_circ`, `in_bounce`, `out_bounce`, `in_out_bounce`, `in_back`, `out_back`, `in_out_back`, `in_elastic`, `out_elastic`, `in_out_elastic`. Of these, vanilla uses only 14 (ANI-10).

Animation properties (wiki table): `anim_type`, `duration` (seconds), `next` (the animation to follow after it ends), `destroy_at_end`, `play_event`, `end_event`, `start_event`, `reset_event`, `easing`, `from`, `to`, `initial_uv`, `fps`, `frame_count`, `frame_step`, `reversible` (run backwards after ending), `resettable`, `scale_from_starting_alpha`, `activated`.

## Images

- **[ANI-01]** The main properties of `image` (vanilla use counts): `texture`, `uv`/`uv_size` (40), `tiled` (44), `keep_ratio` (45), `bilinear` (50), `fill` (48), `color`, `alpha`, `clip_direction` (`left` 21, `down` 3, `up` 1, `right` 1), `clip_ratio`, `clip_pixelperfect` (21), `grayscale` (1), `force_texture_reload` (6), `zip_folder` (3). There are also `allow_debug_missing_texture` (4) and the axis values of `tiled` (ANI-17). `{vanilla}` ([Source](../reference/source-abbreviations.mdx): VN, BW-doc)
- **[ANI-02]** A texture path can be assembled with a variable expression: `"texture": "('textures/my/bg/' + $tab_bg)"`. At runtime, put the path into a `#texture` binding with a view expression: `('textures/my/frames/' + #frame)`. `{working pack, vanilla}` ([Source](../reference/source-abbreviations.mdx): AP 4.9, BA 3.1, VN server_form.json:173)
- **[ANI-03]** A **progress bar** binds `#clip_ratio` (0~1) and decides the clipped side with `clip_direction`. `clip_ratio`, `clip_direction` and `clip_pixelperfect` are not in the official schema but are properties vanilla uses. To make a 0~1 decimal from an integer value, use a dot-leading real literal like `(#v * .01)`. `(#v / 100)` is integer division (EXP-18, EXP-27). On Windows 1.26.65.1, `(#v * .01)` with `#v` 50 drew half the bar. The engine clamps the value to [0, 1] and reads a non-number as 0.0 (ANI-50). Vanilla gives the `#clip_ratio` binding `binding_condition` of `always` (6) or `always_when_visible` (6). `{vanilla, measured, code (source), code (binary)}` ([Source](../reference/source-abbreviations.mdx): VN 33 uses, BC-facts, BA 3.2, BW-doc, CN, 2026-11-24 Windows 1.26.65.1 measurement and decompilation)
- **[ANI-04]** For 9-slice, put a `.json` of the same name next to the texture file and write `nineslice_size` (`[left, top, right, bottom]` or one value) and `base_size`. Vanilla UI JSON does not use `nineslice_size` as a literal property and uses it once through a binding (`#banner_nineslice_size` -> `#nineslice_size`) (LAY-27). For a repeating background, give the image `"tiled": true` (LAY-28, 44 uses in vanilla). `{working pack, vanilla}` ([Source](../reference/source-abbreviations.mdx): BA chapter 5, AP 4.9, VN)
- **[ANI-17]** `tiled` accepts not only `true` (23) but also `"x"` (8) and `"y"` (12), which repeat on one axis only. In the code `"xy"` and `"yx"` also repeat on both axes. The repeat unit scale is `tiled_scale` (3). `{vanilla, code (binary)}` ([Source](../reference/source-abbreviations.mdx): BW-doc Sprite table, VN, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-22]** An image chooses how to draw in the order 9-slice, `clip_ratio`, `tiled`, `fill`, `keep_ratio`, stretching. `clip_pixelperfect` (default on) clips in original pixel units. `color` can be `#rrggbb` as well as `[r,g,b,a]`. `{code (source)}` ([Source](../reference/source-abbreviations.mdx): CN)
- **[ANI-34]** The client drew a grayscale PNG translucently (the window showed through the gray frame). Texture optimization tools convert gray images to grayscale, so keep a pack's PNGs as RGB or RGBA. `{measured}` ([Source](../reference/source-abbreviations.mdx): DF)
- **[ANI-48]** `clip_ratio` clips only when `clip_direction` is present. An image with `clip_ratio: 0.5` and no `clip_direction` was not clipped. An image with only `clip_direction: "left"` and `clip_ratio` omitted drew nothing, because the default is 1.0. `clip_direction` takes `left`, `right`, `up`, `down` and `center`. With `clip_pixelperfect: false`, `left` 0.25 showed the left 75%, `down` 0.5 the lower half and `center` 0.5 the middle 50%. So the part that remains is on the `clip_direction` side. `{measured, code (binary)}` ([Source](../reference/source-abbreviations.mdx): 2026-11-20 Windows 1.26.65.1 measurement and decompilation)
- **[ANI-49]** `clip_pixelperfect` defaults to `true` and rounds the clip edge down to texels of the texture. With texture `textures/ui/White`, the ANI-48 images without `clip_pixelperfect` showed only a 1 GUI wide strip on the left for `left` 0.25, only a 1 GUI row at the bottom for `down` 0.5, and nothing for `center` 0.5. For a bar that shows a ratio by stretching a small texture, give `clip_pixelperfect: false` (Example 3 in the images and animation chapter). `{measured, code (binary)}` ([Source](../reference/source-abbreviations.mdx): 2026-11-20 Windows 1.26.65.1 measurement and decompilation)
- **[ANI-50]** A `#clip_ratio` value is read as a float, clamped to [0, 1] and then written to the image. In the code integers and floats give their value, booleans give 1.0 for true and 0.0 for false, and a missing key or a non-number such as a string gives 0.0. So 2 is clamped to 1.0 and an image with a direction disappears, and a negative value becomes 0. On Windows 1.26.65.1, a `textures/blocks/emerald_block` 80x5 bar (`clip_direction: "left"`, full drawn width 320 px) given `(#v * .01)` with `#v` 50 drew 160 px, half. `(((20.0 - 15) / $max) + #z)` (`"$max": 20.0`, `#z` 0), 0.25 from `property_bag` and a static `"clip_ratio": 0.25` were all 240 px (0.25 clipped, 75% left). A ratio of 0, static or bound, drew one square the height of the bar (20x20 px, the whole texture) at the center instead of the bar. The cause is unknown. This differs from the record where 0 looked like a full bar with `textures/ui/White`, but `White` could not be checked the same day, so whether it depends on the texture was not settled. An expression of constants only without a `#` property (`(.25)`) had its binding dropped (BND-05). `{measured, code (binary)}` ([Source](../reference/source-abbreviations.mdx): 2026-11-24 Windows 1.26.65.1 measurement and decompilation)

ANI-46~ANI-49 are code read by decompiling the native client (Windows 1.26.65.1, partly Android 1.26.52.3) and checked in the Windows 1.26.65.1 game (2026-11-20). The test window is `juc_tester.json` in the add-on `addons/json-ui-claims`. 1 GUI was 4 client pixels. ANI-50 is code read from a decompilation of the Windows 1.26.65.1 client and checked on the HUD in the same game version (2026-11-24). The probe pack is `addons/re9-probes`, and the measurement record is in section 6.8 of [claim measurements](../design/json-ui-claims.mdx).

## Renderers (`custom`)

- **[ANI-05]** With `"type": "custom"` + `"renderer": "name"`, the engine draws. The renderers vanilla 1.26.50.4 uses are 43 kinds (Appendix B). When importing a renderer name list from an external source, check it against the vanilla list. One external list had 10 of 53 not in vanilla. Of the wiki's 41 renderers, 7 (`background_renderer`, etc.) are not in vanilla 1.26.50, and 9 of vanilla's (`locator_bar`, `qr_code_renderer`, etc.) are not in the wiki. `{vanilla}` ([Source](../reference/source-abbreviations.mdx): VN, MJ 4.2, BW-doc)
- **[ANI-06]** An item icon gives `#item_id_aux` to `inventory_item_renderer`. The value is `numeric item ID x 65536 (+ data value)`. If constant, put it in `property_bag`, and if a runtime value, bind it. Numeric IDs partly shift when custom items are registered and can differ per world. The boundary where they shift differs by source (the BC record says 256 and above, the wiki's 1.26.50 table says -1246~851 are stable and only 852~883 shift). Check that version's table or the game before use. Use a texture path when possible. `{working pack, measured, conflict}` ([Source](../reference/source-abbreviations.mdx): AP 4.7, BC-facts, BW-ids, Appendix A C-33)
- **[ANI-07]** In 1.26.50 the vanilla HUD cursor (`cursor_renderer`) lost its instance at the HUD root and is referenced from `hud_crosshair_overlay.json` (the definition remains at `hud_screen.json:608`). HUD modifications that used this as a reference point break. `{vanilla}` ([Source](../reference/source-abbreviations.mdx): VN hud_crosshair_overlay.json:4, MJ 4.1)
- **[ANI-46]** A control with a `type` the engine does not know is not created, and neither are its children. The content log records `Type 'no_such_type' not recognized for control: <control name>`. The type name must match including case, so `Label` gave the same error. `carousel_label`, which appears once in vanilla, is also missing from the engine's type table and was rejected with the same error. `{measured, code (binary)}` ([Source](../reference/source-abbreviations.mdx): 2026-11-20 Windows 1.26.65.1 measurement and decompilation)
- **[ANI-47]** If the `renderer` of a `custom` control is a name the engine does not know, the content log records `Unrecognized renderer: 'foo_renderer'` and no renderer is attached. Unlike an unknown `type` (ANI-46), the control itself is created. `{measured, code (binary)}` ([Source](../reference/source-abbreviations.mdx): 2026-11-20 Windows 1.26.65.1 measurement and decompilation)
- **[ANI-38]** In a window inserted into the entity chest screen with `modifications`, with the panel around the window at `layer` 50 and the `input_panel` inside it at 100, only the `inventory_item_renderer` icons were not drawn, while names, counts and backgrounds were. Lowering both to 1 drew the icons. This agrees with a community report that an item renderer at layer 100 hid items while 4 and 50 were fine (ANI-06). Do not put a window that holds item renderers on a high layer. The limit depends on the sum of the ancestor layers, not on the control's own `layer`. In a chest screen, with the pack's ancestors added up, `inventory_item_renderer` and `live_player_renderer` drew up to a sum of 94 and neither drew from 99 (95 to 98 untested; the ancestors on the vanilla chest panel side were not counted). `live_horse_renderer` drew whatever the sum (mobile, 2026-11-16, section 2.2.3 of [InvUI](../design/invui/entity-inventory-ui.mdx)). `{measured}` ([Source](../reference/source-abbreviations.mdx): E2048)
- **[ANI-39]** The colors of `gradient_renderer` cannot be changed by binding. Putting `[1, 0, 0, 1]` from a `property_bag` into `#color1` with a view binding, or into `#color`, still drew the gradient with the static `color1` (white). The same binding on the `#color` of a white image turned it red. The default gradient runs from top (`color1`) to bottom (`color2`). To change colors, prepare one gradient per color and choose with `#visible`, or bind `#color` on an image with a white-to-transparent texture. `{measured}` ([Source](../reference/source-abbreviations.mdx): CPR)

## Animation

```json
"anim_slide_in":  { "anim_type": "offset", "easing": "out_back", "duration": 0.5,
                    "from": [ "100%c + 40px", 20 ], "to": [ 0, 20 ], "next": "@my_toast.anim_wait" },
"anim_wait":      { "anim_type": "wait", "duration": 4.5, "next": "@my_toast.anim_slide_out" },
"anim_slide_out": { "anim_type": "offset", "easing": "in_back", "duration": 0.5,
                    "from": [ 0, 20 ], "to": [ "100%c + 40px", 20 ], "destroy_at_end": "hud_title_text" }
// Usage: "anims": [ "@my_toast.anim_slide_in" ]  or  "alpha": "@my_toast.anim_fade"
```

- **[ANI-08]** `anim_type` values (vanilla counts): `alpha` 54, `offset` 42, `flip_book` 34, `wait` 30, `size` 7, `color` 3, `aseprite_flip_book` 2, `uv` 1. The wiki and Cinnabar (the 1.26.50 engine enum) also list `clip`, making 9 kinds (ANI-20). Vanilla uses it 0 times. In the Windows 1.26.65.1 code a `clip` animation writes the easing value to the image's `clip_ratio` (Appendix A C-38). It was not measured in game. `{vanilla, code (source), code (binary)}` ([Source](../reference/source-abbreviations.mdx): VN, CN, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-09]** Animation fields: `from`, `to`, `duration`, `easing`, `next` (a reference to the next animation), `destroy_at_end`, `play_event`, `end_event`, `reset_event`, `reversible`, `resettable`, `looping`, and for flipbooks `initial_uv`, `frame_count`, `frame_step` and `fps`. In the code `initial_uv` is the first uv of a `flip_book` or `aseprite_flip_book` property reference. `{vanilla, code (binary)}` ([Source](../reference/source-abbreviations.mdx): VN per-field tally, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-10]** For `easing`, prefer the values vanilla uses: `linear`, `out_cubic`, `in_expo`, `in_quart`, `in_quint`, `out_expo`, `in_sine`, `in_out_back`, `out_sine`, `out_bounce`, `out_back`, `in_out_expo`, `in_out_circ`, `in_bounce`. Of the 32 easings in the external list, 18 are not in vanilla. `in_back` is used by BA. These 32 are the same as the wiki list, and all 14 of vanilla's are among them. `{vanilla, working pack}` ([Source](../reference/source-abbreviations.mdx): VN, MJ 4.2, BA chapter 6, BW-doc)
- **[ANI-11]** Attach an animation with `"anims": [ "@ns.name" ]` or reference it directly in a property value (`"alpha": "@hud.anim_title_text_alpha_in"`). **You can also attach an animation of another namespace to a vanilla element.** `{vanilla, working pack}` ([Source](../reference/source-abbreviations.mdx): VN hud_screen.json:2272, AP 4.5)
- **[ANI-12]** Every time a factory newly creates a control, the animation plays **from the beginning again.** That is why a toast slides in each time a title is sent. In the code too, creating a control creates the `anims` component and stores the current time. `{working pack, code (binary)}` ([Source](../reference/source-abbreviations.mdx): BA chapter 6, BW-intro, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-13]** If you shrink the height of a vanished item to 0 with a `size` animation, the next items of a stack panel rise smoothly. `{working pack}` ([Source](../reference/source-abbreviations.mdx): AP 4.5)
- **[ANI-14]** The value of `destroy_at_end` in vanilla uses the name of the control the factory created (`hud_title_text`), the name of its base definition (chat: child name `chat_item`, value `chat_grid_item`) and a variable (`$toast_control`). Measured on the HUD title factory, the control the factory created was named after the `control_ids` key (`hud_title_text`), and a child name written in the JSON (the part before `@`, as in `juc_d_inst_a@...`) was ignored. `destroy_at_end` destroyed only with `hud_title_text` (about 1 s later), not with that child name or the definition name. A factory control without a destroying animation stayed after the title ended ([measurement record](../design/json-ui-claims.mdx#62-hud-title)). Also stop accumulation with the factory count limit (`max_children_size`). In the Cinnabar reconstruction, `destroy_at_end` erases the nearest among that control and its ancestors whose engine-assigned control name equals the value, and the chat controller gives the lines it creates the name `chat_grid_item` (ANI-21). Then it matches the value in vanilla chat (chat was not measured). `{vanilla, measured, code (source), inferred}` ([Source](../reference/source-abbreviations.mdx): VN hud_screen.json:949 and 2213, AP 4.5, Appendix A C-27, CN, 2026-11-18 Windows 1.26.65.1)
- **[ANI-15]** A flipbook icon is made with `"uv": "@ns.anim"` (`anim_type: aseprite_flip_book`) + `"uv_size"` + the Aseprite JSON next to the texture (`frames[].frame`, `duration`). In Aseprite, export the JSON in the **Array** format (Hash is said not to work). In the code the engine reads `frames` only as an array (`frames[].duration`, `frame.x`, `frame.y`) and has no code that reads the Hash (object) format. The frame `w` and `h` are not read. The texture and JSON have the same name without an extension, and `aseprite_flip_book` is applied only to the `uv` of an image. `{vanilla, working pack, code (binary)}` ([Source](../reference/source-abbreviations.mdx): VN 2 uses, AP 4.7, BW-ase, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-16]** The vanilla title animation times come in as engine variables (`$title_fade_in_time`, `$title_fade_out_time`). It appears that the `/title times` values are reflected here. `{vanilla, inferred}` ([Source](../reference/source-abbreviations.mdx): VN hud_screen.json:2170 and 2185)
- **[ANI-18]** For a control inside a grid, an animation chained with `next` has a bug where after the first animation the duration is divided by the number of items and it speeds up (except `flip_book`). For grid items, use a repeating animation as one stage or use `looping`. The 2026-11-24 decompilation found no code that causes this speedup. `{unverified}` ([Source](../reference/source-abbreviations.mdx): BW-dyn, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-19]** Additional animation fields vanilla uses: `start_event` (1), `scale_from_starting_alpha` (4), `activated` (2). On the control side: `animation_reset_name` (26), `disable_anim_fast_forward` (21). In the code `scale_from_starting_alpha` is a boolean of an alpha animation, and when true the start value is the current alpha. No place was found where the animation parser reads `start_event` or `activated`. `{vanilla, code (binary)}` ([Source](../reference/source-abbreviations.mdx): BW-doc Animations table, VN, 2026-11-24 Windows 1.26.65.1 decompilation)
- **[ANI-20]** There are 9 animation types: `alpha`, `clip`, `color`, `flip_book`, `aseprite_flip_book`, `offset`, `size`, `uv` and `wait` (the 1.26.50 enum). `{code (source)}` ([Source](../reference/source-abbreviations.mdx): CN, C-38)
- **[ANI-21]** `destroy_at_end` erases the nearest among the control that has that animation and its ancestors whose engine-assigned control name equals the value. That name is usually the child name written in the JSON (the part before `@`), but a control created by a factory gets the `control_ids` key as its name (ANI-14). `{code (source)}` ([Source](../reference/source-abbreviations.mdx): CN, C-27)
- **[ANI-37]** To replay an animation from the start in an open screen, make that control get built again. In a `control_ids` factory whose `#collection_length` comes from a `property_bag` dictionary lookup (COL-22, COL-23), every change of the marker in the key value (the slot item name) built the control again and its `anims` played from the start. Turning `#visible` off and on did not replay it. `{measured}` ([Source](../reference/source-abbreviations.mdx): E2048)


## Aseprite sprite animation (the Bedrock Wiki original)

`aseprite_flip_book` makes animation from a sprite sheet exported from Aseprite (or the free alternative LibreSprite). Below is the wiki original (CC BY 4.0). It has the same content as the rules of ANI-15 (Array format, same-named files).

<Excerpt src="bedrock-wiki" title="Aseprite Animations" path="docs/json-ui/aseprite-animations.md">

**Creating an Animation in Aseprite**

Suppose you have a series of frame images named "frameimage" with sequential numbers from 1 to 5.
Import the first image, and Aseprite will automatically recognize the other images with the same name but different numbers.
It will then place them in the correct order and create an animation.

Use the arrow keys to navigate through all frames and the "Enter" key to play or pause the animation.
Press the "Tab" key to open the timeline and select individual frames.
Right-click a frame in the timeline to access various settings.

To export the animation, use the shortcut "Ctrl + E" or navigate to "File" -> "Export to Sprite Sheet".
In the output settings, select the Output file and the JSON Data.
You'll see a dropdown menu with Hash and Array options.
Ensure the Array option is selected, or the export will not work properly.

You should now have two files: the SpriteSheet image and a JSON file.
Ensure both files have the same name but different extensions.

**Using Aseprite Animations in JSON UI**

The `aseprite_flip_book` animation type can only be used for the `uv` property in an element of the type `image`.

```json
{
    "image_element": {
        "type": "image",
        "texture": "textures/wiki/ui/my_sprite_file",
        "uv_size": [32, 32],
        "uv": "@example_namespace.image_uv_animation"
    },

    "image_uv_animation": {
        "anim_type": "aseprite_flip_book",
        "initial_uv": [0, 0]
    }
}
```

Set the `texture` field to the path of the exported files without the extension.
The `uv_size` field should be set to the width and height of a single frame.

## The paper doll and the NetEase skeleton model

This is a comparison of the exhaustive 13 sites of vanilla `paper_doll_renderer` (`VN`), the native binary string search (`NB-12`), and the NetEase (China edition) skeleton model and paper doll documentation (`NE`).

- **[ANI-35]** The international `paper_doll_renderer` draws **only the player skin** that the engine gives through bindings (`#paper_doll_skin`, `#skin_index`, `#classic_skin_index`). The properties vanilla uses are `use_selected_skin` (12, all `false`), `rotation` (`gesture_x` 6, `auto` 1), `camera_tilt_degrees` (8, all `-10`), `starting_rotation` (8, all `30`), `enable_scissor_test` (4, all `true`) and `#skin_rotation` of `property_bag` (2). To rotate it by dragging, put `"gesture_tracking_button": "button.turn_doll"` and its button mapping on an `input_panel`, and the paper doll receives `#gesture_delta_source` and `#gesture_mouse_delta_x` of that panel with a view binding. `{vanilla}` ([Source](../reference/source-abbreviations.mdx): VN pause_screen.json:320, VN pause_screen.json:348, VN day_one_experience_screen.json:201, NB-12)
- **[ANI-36]** The UI 3D model feature of the NetEase documentation, that is, `modelname`, `modelsize`, `animation` and `animation_looped` of `paper_doll` and `netease_paper_doll_renderer` (`skeleton_model_name`, `entity_identifier`, `screen_scale`, `init_rot_x/y/z`, `freedom_gesture`, Python `RenderEntity` and `RenderSkeletonModel`), is **China edition only.** There are 0 `netease` strings in the international binary, the long names of these properties are absent too, and vanilla never uses them. An international pack cannot draw custom models or entities in UI, so use world entities or particles (ALT-01). Short names cannot be judged by binary strings (even `paper_doll_renderer` is 0), so the conclusion rests on the long names. `{code (binary), vanilla, inferred}` ([Source](../reference/source-abbreviations.mdx): NB-12, VN 0 uses, NE-30 paper_doll, NE-bone)

## The `property_bag` keys renderers read

These were measured with a probe pack (`UKP`) that lays out on the HUD the keys `actor_portrait_renderer` and `progress_bar_renderer` read from `property_bag`. The portrait renderer keys appear neither in the vanilla files nor in the Discord records.

```json
"my_portrait": {
  "type": "custom",
  "renderer": "actor_portrait_renderer",
  "size": [ 44, 63 ],
  "property_bag": { "actor_id": -4294967295, "rotate_mode": "auto" }
}
```

- **[ANI-40]** `actor_portrait_renderer` draws the entity whose id is the integer `actor_id` in `property_bag`. In a single player world, a HUD control with `"actor_id": -4294967295` (that player's Script API `Player.id`) drew the player. In the same `property_bag`, `scale_x`, `scale_y` and `scale_z` (0.5) changed the size, `rotate_y` (180) the body direction (the back showed) and `rotate_x` (45) tilted it forward. `translate_x` 0.5 did not move it visibly. An id built with the expression `"(0 + $subtitle_text)"` (the same id in the subtitle) drew nothing. Emote, attack and sneak animations showed as they are, while walking and the view direction were not followed. A cell with `use_live_animation: true` looked the same as one without it. Entity ids differ per world and player, so a static id is for testing. `{measured}` ([Source](../reference/source-abbreviations.mdx): UKP)
- **[ANI-41]** `rotate_mode: "auto"` of `actor_portrait_renderer` keeps the portrait turning. A control made by the title factory (`hud_title_text_factory`) is rebuilt each time the title is sent again, and the angle went back to the start (sent every second, it turned and snapped back). With the title sent once and a long stay time it turned without breaks. The cause is the same as ANI-12. `{measured}` ([Source](../reference/source-abbreviations.mdx): UKP)
- **[ANI-42]** Adding `rotate_mode: "auto"` and `scale_*` 0.6 to the `property_bag` of the NPC edit screen skin list portrait (`npc_interact.skin_model`) from a resource pack changed nothing. Only the hovered skin turned, and the portraits turned along when the real NPC turned its head. The screen seems to write these keys again for each cell. The portraits on this screen cannot be transformed by a pack. `{measured, inferred}` ([Source](../reference/source-abbreviations.mdx): UKP)
- **[ANI-43]** `progress_bar_renderer` also draws from static values in `property_bag` without bindings. A bar with `#progress_bar_total_amount`, `#progress_bar_current_amount` and the visibility keys `#progress_bar_visible` and `#touch_progress_bar_visible` (both `true`) was drawn, and without the visibility keys it was not drawn (touch input device). The default look is a green fill on a gray background. With `is_durability: true` the background turned black and the fill color followed the ratio (orange at 37%, green at 90%). For `is_storage_bar`, used by the vanilla bundle bar, and `drop_shadow` and `round_value`, used by the durability bar, no difference could be judged on a 4px high bar. `{measured, vanilla}` ([Source](../reference/source-abbreviations.mdx): UKP, VN ui_common.json `durability_bar`)

## Drawing URL images from item trim text

These were measured on Windows with a test pack (`UII`) that puts an address text into an item's armor trim material and draws the image at that address in each slot (2026-11-16; the game version was not recorded). The slot control is put into the `controls` of `common.item_renderer` with `modifications`, so inventory, chest and HUD hotbar slots all receive it.

- **[ANI-44]** An item whose trim material (`Trim.Material`) holds any text (for example `URL:https://.../x.png`) kept that text when loaded from a `.mcstructure` chest with `/structure load`. A sword, which is not armor, was the same. In chest, inventory and hotbar slots (the HUD hotbar included), the collection binding `#armor_trim_material` returned that raw text. For an item picked up in the chest screen, the global `#inventory_selected_armor_trim_material` returned the same text, but the HUD has no such global value, so a view expression using it produced not even empty text. Armor with an unregistered material drew no vanilla icon, while the sword was drawn. `{measured}` ([Source](../reference/source-abbreviations.mdx): UII)
- **[ANI-45]** Giving the text `{"type":7,"url":"<address>"}` to `#profile_image_options` of a `custom` control with `renderer: "profile_image_renderer"` drew the image at that address (GitHub raw PNG, Wikimedia JPEG and PNG). PNG transparency was kept. A GIF did not animate and was drawn as a still image. An address with no response drew nothing. Feeding the part after the marker (`URL:`) of the ANI-44 slot value into this text draws a different image per item over the slot icon without putting the images in the pack. `{measured}` ([Source](../reference/source-abbreviations.mdx): UII)
