There are four main ways for a server to put something on a player's screen. Which one to use depends on whether the player must respond, whether items move around, and whether the server can use the Script API.

| What you want to do | Method | Page |
| --- | --- | --- |
| Show a button list, confirmation dialog or input form and receive the response | Server forms (`ActionFormData`, `MessageFormData`, `ModalFormData`) or form JSON | [Server form API and form types](./modal-forms.mdx) |
| Put a checkbox list in a modal form | The `multiselect` row in form JSON (not in the Script API) | [multiselect](./multiselect.mdx) |
| Draw one form in a different shape such as a shop, table or tree | Reskin `server_form.json` in a resource pack | [Reskinning server forms](./reskinning-server-forms.mdx) |
| Show a chest-shaped GUI or open a window where items move | Chest-UI (form based), entity chest | [Chest UI](./chest-ui.mdx) |
| Build screens that look like an inventory, slot badges, and block workstation windows | Vanilla screen values, slot decoration, client behavior | [Inventory-style menus](./inventory-menus.mdx) |
| Draw HUD elements the player does not respond to | Title, subtitle, action bar and scoreboard channels | [HUD and title channels](./hud-and-titles.mdx) |

## Common principles

- Form JSON and titles are both **text channels from the server to the pack**. The server does not know the shape of the screen; it sends text (title, body, button text, icon paths), and the pack reads markers in it to decide the shape.
- The shape of a server form is drawn by the vanilla `server_form.json`. This screen uses the JSON UI approach. `CustomForm` and `MessageBox` (DDUI), drawn with the newer approach (Ore UI), are in the [DDUI server guide](../ore-ui/ddui-server-guide.mdx).
- Server software (Dragonfly, PocketMine, Nukkit) has no Script API, so it builds the same screens directly with packets and JSON. Most `{measured}` items in this section came from such servers.
- Verification levels are written as `{measured}` (verified in game), `{code}` (read from a binary, type definitions or an evaluator), `{vanilla}` (read from the vanilla pack), `{verified}` (confirmed from repository files or commits), `{record}` (appears only in documents and no measurement conditions remain), and `{inferred}`.
