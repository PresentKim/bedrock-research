## What it is

BedrockAdvancements is a tool for designing an advancement tree in a web creator (bedrockadvancements.com/create) and downloading it as an add-on. The analysis covers the web creator, the public documentation, the changelog (2.0.0~2.0.5), and the original `BedrockAdvancements-2.0.3-Beta.mcaddon` on the user's device (researched 2026-10-20). **The main package is All rights reserved and redistribution is forbidden.** This page therefore uses no `Excerpt` and rewrites only the techniques in its own words. The code blocks are not the original but new examples written to explain the techniques (Source: cs-bedrockadvancements).

The key point is that this pack does not "generate" JSON UI. The creator exports only the advancement data, icons, and lang, and the screen is drawn by `ui/ba_screen.json` (712 KB, generated by a build tool from a spec file) in the main RP.

## How it works

```
script -- ActionFormData (title 'CUSTOMUI:BA...', button = fixed-width record) --> server_form
    server_form.json: a wrapper around long_form + one more server_form_factory for its own screen
    ba_screen.json  : interprets records with '%.Ns' slices and contains checks and draws the tree
```

One record line has the structure `[KIND 4][TAB 2][FRAME 24][TOKENS 160][PROGRESS 16][PCT 4][TITLE 120][DESC ...]`. The 4-byte `KIND` (`BAN|` node, `BAT|` tab, `BAL|` label, `BAM|` meta) tells the type, and the other fields are padded with `$` or `.`.

## Key techniques

### 1. Wrapping and adding a factory

It does not edit `long_form` directly and wraps `long_form@server_form.long_form` in a panel with a visibility condition. This reference points to the final merged result in which another UI pack replaced `long_form` entirely, so it works regardless of pack order. The 2.0.2 changelog fix for "screens mixing together when used with a UI pack" is this structure.

```jsonc
// An example newly written to explain the technique (not the original)
"my_hideable_long_form": {
  "type": "panel",
  "bindings": [ { "binding_name": "#title_text" },
    { "binding_type": "view",
      "source_property_name": "((#title_text - 'MYUI:FLAG') = #title_text)",   // visible only when my flag is absent
      "target_property_name": "#visible" } ],
  "controls": [ { "long_form@server_form.long_form": {} } ]
},
"main_screen_content/server_form_factory": {          // a path key overrides only control_ids
  "control_ids": { "long_form": "@server_form.my_hideable_long_form" } }
```

Then it adds one more `server_form_factory` with the same name through `modifications` to create its own screen. Both react to the same form data, and visibility shows only one. The title check is a contains check rather than a prefix check, so metadata (such as the record count per tab) can be carried after the title.

### 2. Fixed-width records and the slice chain

The standard chain that takes L bytes starting at byte N has four steps.

```jsonc
{ "source_property_name": "('%.210s' * #form_button_text)",    "target_property_name": "#head" },   // first 210 bytes
{ "source_property_name": "(#form_button_text - #head)",       "target_property_name": "#rest" },   // the rest
{ "source_property_name": "('%.120s' * #rest)",                "target_property_name": "#raw"  },   // next 120 bytes
{ "source_property_name": "(#raw - '$')",                      "target_property_name": "#text" }    // strip padding
```

- `'%.Ns'` counts UTF-8 bytes. The encoder must cut and pad by bytes for Korean (3 bytes) to line up.
- String `-` erases every occurrence, so the padding character must not appear in the body. Reserved characters are therefore removed from plain text.
- A field that looks like a number is converted to a number by JSON UI, so a letter prefix (`Ta`, `§f3/17`, `P050`) is added.
- Progress is converted as `(#pct_text - 'P')`, then `* 1`, then `/ 100`, then `(1 - value)`, into `#clip_ratio`, and the bar is clipped with it.

### 3. Position-independent tokens

Booleans and bits are carried as tokens of the form `~` + uppercase group + lowercase letter (bit number), and only their presence is checked with `(not ((#form_button_text - '~Fo') = #form_button_text))`. The position need not be known and no token is a prefix of another. The groups are `X` (x, 9 bits), `Y` (y, 11 bits), `U`/`V` (connector length), `H` (canvas height), and `F` (flags: has child, has parent, tooltip left, selected, has progress, challenge, achieved, empty slot).

### 4. Turning numbers into coordinates with a bit spacer stack

In JSON UI the position of a static control cannot be bound. Instead, 11 panels of size 1, 2, 4, ..., 1024 are placed in a vertical stack and each is turned on or off by the bit tokens. A stack panel gives hidden children no space, so the sum of the enabled spacer sizes is the coordinate (0~2047px). The scroll content height is built the same way from the `H` bits of the meta record.

```jsonc
// A newly written example: one bit = one spacer
"y3": { "type": "panel", "size": [1, 8],
        "bindings": [ /* #visible if the token '~Yd' is present */ ] }
```

The cost is high. One node creates hundreds of controls, and sending the nodes of every tab at once made the screen take several seconds to open. So it sends only the nodes of the selected tab, and pressing a tab submits the form and reopens it on that tab.

### 5. Screen composition tips

- Tabs are 28 panels (8+8+6+6) with a baked-in `collection_index`, and the script sends empty records to fix the indexes.
- The same `form_buttons` collection is drawn by 3 factories on different layers (outline layer 3, node 5, hover 20). This is because raising only the layer inside one item would let the next item's outline cover the previous item.
- Node buttons have no `button_mappings` and use only hover and focus. Only tab buttons submit with `button.form_button_click`.
- The tooltip darkens its surroundings with a 4000×4000 black image (alpha 0.3) and draws outside the viewport with `allow_clipping: false`. A background that fits the text width is built by an `alpha: 0` measuring label that grows its parent to `"100%c"`.
- The window shrinks on small screens with `size: [314, "100% - 64px"]` and `max_size: [314, 236]`. Every texture has a 9-slice `.json`.

### 6. Toasts add one more `hud_title_text_factory`

Each time a title arrives, the factory creates the controls anew, so the animation plays from the start. The data is `CUSTOMHUD:ba_toast:` + category + title + icon (`$` padding), and the header translates a lang key (`'ba.toast.' + category`) with a `localize` label. The parent parses the value and the child receives it with `source_control_name` + `resolve_sibling_scope: true`. Slide in, a 4.5 second wait, and slide out are chained with the animation `next` chain, and the script processes the queue at 110 tick intervals. Limit: 2.0.3 had a problem where the vanilla hiding was applied only to `title_frame`, so text flashed briefly in the center (fixed in 2.0.5), and the title channel is single, so another add-on's `setTitle` overwrites it.

### 7. Script operation tips

- When the form is cancelled with `FormCancelationReason.UserBusy`, it reopens up to 20 times at 10 tick intervals.
- Reopening a form returns the scroll to the top, so the open accordion section is placed first.
- Layout calculation (`tabLayout.js`) is kept as a pure function separate from the game API, so the web preview runs the same file as the game.
- The `.mcaddon` the web creator exports has no JSON UI file. The data goes in custom item components (`ba:tab`, `ba:advancement`, `ba:criterion`).

## Comparison

[AdvancementPack](./advancementpack.mdx) gets the same result with the NPC screen and the HUD, and [bedrock-core](./bedrock-core.mdx) uses a 13-byte prefix check and generic form components. BedrockAdvancements is dedicated to a special screen, so its record structure is the most elaborate, but it has the most controls.
