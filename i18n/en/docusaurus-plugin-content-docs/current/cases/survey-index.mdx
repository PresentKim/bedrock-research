## Scope and method of the survey

The additional survey of 2026-10-22 skimmed JSON UI related libraries, tools, documents, and public packs, excluding the 8 already analyzed separately (bedrock-core, AdvancementPack, BedrockAdvancements, Premium Damage Indicator, mcbejsonuimasterAI, Bedrock Wiki, Ore UI Customizer, Cinnabar). The places searched were the GitHub topics `json-ui` and `jsonui`, English, Chinese, Japanese, and Korean web searches, the npm registry, the Microsoft Learn source repository, and the NetEase documentation mirror repository. The comparison baseline is the comprehensive guide (340 rules at the time of the survey, conflicts C-01~C-47) and vanilla `bedrock-samples` `46ba6ea` (1.26.50.4). **Of the 31 candidates checked, 15 got their own analysis document** and the rest are noted only briefly in this table. No in-game measurement was done, and claims were judged by a full vanilla search, schema validation scripts, and running the Cinnabar evaluator (Source: repo-survey). Value is high (changes a guide rule or has several new techniques), medium (some new techniques or useful as a tool), or low (reference or error sample).

The eight findings that most affected the guide are as follows.

1. **`grid_position` is `[column, row]`.** In all 20 vanilla grids, `grid_dimensions [column count, row count]` and the child's first value (column) agree. The `[row, column]` in LAY-29 was wrong.
2. **Numeric item IDs were rearranged in 26.40.** Chest-UI's "26.40 Update" moved the boundary from 256 to 850 and changed the diamond from 335 to 306. C-33 is settled as "the table changes with each version".
3. **The claim that a remainder can be built with integer division** (AsaJS) conflicts with EXP-20 (C-52).
4. **Public schemas and editors are quite wrong against vanilla.** The Blockception schema gives 2,251 false errors in 193 of 205 vanilla files, and the KalmeMarq schema gives 2,224 in 186 files. Use the tools only for autocomplete and navigation and do not trust their error display.
5. **NetEase (China edition) documentation** tells about screen properties, the HUD F1 hiding binding, the `$touch` branch of `scrolling_panel`, and the context-dependent interpretation of a `@name` without a namespace.
6. **Microsoft Learn's JSON UI reference is AI-generated and has many errors**, but its change notes (1.26.0 `priority` binding and scale consolidation, 1.26.30 `§w`) and the cooperative add-on guideline (do not override `ui/`) are usable.
7. **New techniques from server form layout libraries.** StarLibV2 builds 2D layouts from button string keys and applies a live search filter with a text box's `#item_name`.
8. **Animated result effects.** upgrader binds the `aseprite_flip_book` texture of pre-drawn frames to choose an effect per result and lengthens the last frame to stop at the end.

## License handling

MIT, BSD, and CC BY allow short examples with attribution (Chest-UI requires attribution). For GPL-3.0 (AsaJS, StarLibV2), code is not moved into the guide or commercial packs and only the techniques were rewritten. For no-license items (the KalmeMarq and DJStompZone schemas, upgrader, Cermada, the NetEase documentation, GrimUI, Sidebar-HUD, and the unclear w1zardz), no sentences or code were copied and only the facts were rechecked against vanilla. CC BY-ND (Sidebar-Mcbe) forbids distributing modified works, so only a summary was made. For each case page of this wiki, the result of actually opening the `LICENSE` file in the clone is recorded in the registry, and excerpts (`Excerpt`) were made only from material that can be redistributed.

Summary of the new conflict judgments: C-48 `grid_position` is `[column, row]` (resolved), C-49 the offset sign of right and bottom anchors is not flipped (resolved), C-50 a pack file at a vanilla path is merged (resolved), C-51 content-based size and stack layout keep the guide (resolved), C-52 the remainder by integer division (partly resolved, measurement needed), C-53 JSON real number variables (unresolved), C-54 the `#item_id_aux` numbering system (unresolved), C-55 a `@name` without a namespace (unresolved, always `ns.name`), C-56 the search range without `resolve_sibling_scope` (resolved), C-57 registering a copy at a vanilla path in `_ui_defs` (unnecessary, resolved), C-58 the flipbook start frame key is `initial_uv` (resolved), C-59 the `binding_type` default is `global` (resolved), C-60 for the Microsoft Learn reference, adopt vanilla (resolved), C-61 `#anchored_offset_value` on a static control (unresolved), C-62 a grid that leaves `grid_dimension_binding` (unresolved, remove the property), C-63 a lang key whose value is a single space (unresolved). The newly created sections are the input box `#item_name` and search filter, 2D layout by keys, chest-style server form recipes, and the range within which to trust AI-generated documents, NetEase-only names, language servers, editor previews, generator output, expression compilers, and obfuscation tools.

Candidates for next work: checking the roughly 300 engine `$` variables and 22 factory names collected by JsonEncryptor against the value dictionary, and the measurement list (especially the C-52 remainder expression, the C-53 real number variable, and item IDs 850 and 851 after 26.40).
