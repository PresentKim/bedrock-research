# 휴대폰 실측 순서표 (touch-probes v1.0.0)

휴대폰(터치)에서만 잴 수 있는 항목을 재기 위한 순서표다. 결과는 스크린숏이나 화면 녹화와 함께 아래 "적어 보낼 것"을 보내 주면 된다.

이 애드온은 PC 클라이언트를 다른 작업이 쓰고 있어서 아직 PC에서 열어 보지 못했다. 창이 안 열리거나 화면이 깨지면 그 모습을 그대로 찍어 보내 주면 고친다.

## 준비

1. `static/downloads/[bedrock-research]touch-probes_v1.0.0.mcaddon`을 휴대폰으로 옮겨 연다.
2. 새 평지 월드(치트 켬, 크리에이티브)를 만들고 행동 팩 `[bedrock-research]touch-probes-bp`를 켠다. 리소스 팩은 의존성으로 함께 켜진다.
3. 크리에이티브 인벤토리에서 "Touch Probes"(책과 깃펜 아이콘)를 꺼내 들고 사용하면 메뉴가 열린다. 채팅에서 `/scriptevent bwiki:touch_probes k`처럼 마지막 글자로 바로 열 수도 있다(k, l, n, v, p).
4. 모든 시험 창은 20초(초상화 창은 30초) 뒤 스스로 닫힌다. 뒤로 가기가 막혀도 기다리면 된다.

## 1. 버튼 매핑으로 들어오는 터치 입력

메뉴의 "Button mappings, consume_event unset" 창(k)은 버튼 ID 279개를 각각 전역 매핑으로 받는다. 어떤 입력이 들어오면 그 ID 칸이 회색에서 초록으로 바뀌고, 창이 닫힐 때까지 초록으로 남는다. 칸 안의 작은 글자가 ID다(`button.`은 뺐다). 창을 새로 열면 모두 회색으로 돌아간다.

한 동작마다 창을 새로 열고, 그 동작 하나만 한 뒤 스크린숏을 찍는다.

| 순서 | 할 동작 | 적어 보낼 것 |
|---|---|---|
| 1-0 | 창을 열고 아무것도 하지 않음 | 처음부터 초록인 칸 (없으면 "없음") |
| 1-1 | 화면 빈 곳을 한 번 짧게 탭 | 초록이 된 칸 |
| 1-2 | 빈 곳을 1초 이상 길게 누름 | 초록이 된 칸 |
| 1-3 | 빈 곳에서 손가락으로 끌기 | 초록이 된 칸 |
| 1-4 | 두 손가락으로 동시에 탭 | 초록이 된 칸 |
| 1-5 | 안드로이드 뒤로 가기(제스처 또는 버튼) | 초록이 된 칸, 그리고 창이 닫혔는지 |
| 1-6 | 화면에 보이는 X(닫기) 버튼이나 일시정지 버튼이 있으면 누름 | 초록이 된 칸, 창이 닫혔는지 |
| 1-7 | (키보드나 컨트롤러를 연결해 둔 경우만) Esc, E, 숫자 키, 방향키 | 키마다 초록이 된 칸 |

같은 순서를 "consume_event false" 창(l)과 "consume_event true" 창(n)에서도 1-5, 1-6만 반복한다. 세 창에서 뒤로 가기로 창이 닫혔는지 여부를 비교하려는 것이다.

`any` 칸(오른쪽 아래쪽, 278번째 칸 근처)은 어떤 입력에서 켜지는지를 함께 적어 준다.

## 2. HUD 버튼이 터치에서 호버를 받는지 (INP-16)

이 애드온이 켜져 있으면 게임 화면 오른쪽 위(조금 아래)에 회색 `default` 버튼이 보인다. HUD 화면에 `always_accepts_input: true`를 준 상태다.

| 순서 | 할 동작 | 적어 보낼 것 |
|---|---|---|
| 2-1 | 그냥 게임 화면을 봄 | 버튼이 보이는지, 글자(`default`/`hover`/`pressed`) |
| 2-2 | 버튼을 손가락으로 누른 채 유지 | 누르는 동안의 글자와 색 (노랑 `hover`, 초록 `pressed`) |
| 2-3 | 버튼을 짧게 탭하고 손을 뗌 | 아래에 파란 `press received`가 나타났는지, 손을 뗀 뒤 버튼 글자 |
| 2-4 | 버튼 위에서 손가락을 대고 버튼 밖으로 끌기 | 끄는 동안의 글자 |
| 2-5 | 버튼이 있는 상태에서 화면을 끌어 시점 돌리기, 걷기 조작 | 시점과 이동이 평소처럼 되는지 |

## 3. 서버 폼 안의 `$touch` (D-18)

메뉴의 "Touch variables" 창(v)을 연다. 네 줄을 읽어 그대로 적어 준다.

- `$touch (ignored panels)` 옆의 `true` 또는 `false`
- `$pocket_screen (ignored panels)` 옆의 `true` 또는 `false`
- `property_bag #touch:` 뒤의 값
- 넷째 줄(변수를 그대로 글자로 넣은 줄)에 보이는 글자

## 4. 초상화 고정 각과 반대 회전 (InvUI 문서 10.1절)

메뉴의 "Portrait angle compensation" 창(p)을 연다. 플레이어 뒤쪽 4블록에 스티브 인형 엔티티 5개가 생기고, 창에 그 엔티티의 초상화(`live_horse_renderer`) 5칸이 나온다. 인형은 화면 안에서만 뿌리 뼈를 칸마다 다르게 돌린다.

| 칸 | 화면 안 회전 |
|---|---|
| 0 | 없음 |
| 1 | x +16, y +25 |
| 2 | x +16, y -25 |
| 3 | x -16, y +25 |
| 4 | x -16, y -25 |

적어 보낼 것: 스크린숏 한 장, 그리고 정면을 똑바로 보는 칸의 번호(없으면 가장 가까운 칸). 0번 칸이 위에서 내려다보고 옆을 보는 각인지도 적어 준다. 인형이 칸 밖으로 벗어나 보이지 않으면 그 모습도 찍어 준다.

## 5. 여는 시간 (grid-button-list 7절, server-form-research-screen)

게임 안에서 시간을 재는 표시는 없으므로 휴대폰 화면 녹화로 잰다.

1. 휴대폰 화면 녹화를 켠다(가능하면 60fps).
2. `[bedrock-research]json-ui-performance` 애드온의 "JSON UI Optimization Test"를 사용해 버튼 수 메뉴를 연다. 1000을 누르고 목록이 다 그려질 때까지 기다렸다 닫는다. 같은 일을 세 번 한다.
3. `[bedrock-research]server-form-research-screen` 애드온의 "Research Screen Test"로 연구 화면을 세 번 연다. 탭도 두세 번 바꿔 본다.
4. 녹화 파일을 보내 준다. 누른 버튼에서 손을 뗀 프레임부터 새 화면이 다 그려진 프레임까지를 세어 시간으로 바꾼다. 직접 세어 줄 수 있으면 회차마다 숫자로 적어 준다.

두 애드온 파일은 같은 `static/downloads` 폴더에 있다.

## 6. 처음 열 때의 호버(초기 포커스)

창을 열자마자 첫 버튼이 노랗게(호버) 그려지는지 본다. 판은 넷이고, 버튼 A, B, C 셋의 포커스는 모두 켜져 있다.

| 판 | 다른 점 |
|---|---|
| F0 | 아무것도 바꾸지 않음(기준) |
| F1 | 세 버튼 모두 `default_focus_precedence: -20` |
| F2 | A 0, B 5, C 10 |
| F3 | 창 왼쪽 위에 보이지 않는 2x2 미끼 버튼(`default_focus_precedence: 100`) |

메뉴에서 판마다 두 가지로 연다.

- "Focus F0 baseline, server form"처럼 server form이 붙은 것: 2초 뒤 서버 폼 창이 열린다.
- "Focus F0 baseline, chest screen"처럼 chest screen이 붙은 것: 앞에 알렉스 인형이 생긴다. 인형을 탭하면 상자 화면 위쪽에 같은 창이 나온다.

판마다 적어 보낼 것:

1. 창이 열린 직후 노란 버튼이 있는지, 있으면 어느 것인지 (스크린숏 한 장)
2. 열자마자 Button A를 한 번 탭했을 때 오른쪽에 파란 `press`가 나오는지 (첫 탭이 먹히는지)

서버 폼 창은 20초, 상자 화면은 60초 뒤 저절로 닫힌다.
