## 개념

`manifest.json`은 팩을 게임에 알리는 신분증이다. 모든 BP, RP, 스킨팩, 월드 템플릿의 루트에 있다. 최상위 키는 다음과 같다. (출처: bedrock-wiki, concepts/manifest; ms-learn, ManifestReference)

| 키 | 필수 | 설명 |
|---|---|---|
| `format_version` | 예 | manifest 문법 버전. 새 팩은 `3`을 쓴다 |
| `header` | 예 | 이름, 설명, UUID, 버전 |
| `modules` | 예 | 팩이 담는 내용의 종류. BP/RP/스킨팩/월드 템플릿을 결정 |
| `dependencies` | 아니오 | 다른 팩이나 스크립트 모듈 |
| `capabilities` | 아니오 | 엔진 선택 기능 |
| `metadata` | 아니오 | 저자, 라이선스, URL, 생성 도구, product_type |
| `subpacks` | 아니오 | 선택 가능한 변형(주로 텍스처 해상도) |
| `settings` | 아니오 | 플레이어가 조절하는 토글·슬라이더·드롭다운 |

MS Learn 레퍼런스는 이 밖에 `has_education_metadata`(불리언)를 최상위에, `header`에 `platform_locked`와 `pack_optimization_version`(major/minor/patch/preRelease/buildMeta 구조 또는 문자열)을 더 나열한다.

### format_version 1, 2, 3

| 값 | 상태 | 비고 |
|---|---|---|
| `1` | 레거시 | 스킨팩에서만 보인다 |
| `2` | 지원됨 | 버전을 배열 `[1, 0, 0]`로 쓴다. 팩 설정과 `memory_performance_tier` 미지원 |
| `3` | 권장 | 모든 `version`, `min_engine_version`, `base_game_version`이 SemVer **문자열**이어야 한다. 팩 설정과 `memory_performance_tier` 추가 |

format 3에서는 `metadata.authors`가 사실상 필수다(없으면 로드 실패. Microsoft는 의도하지 않은 동작이라 밝혔고 바뀔 예정). 스크립트 모듈 의존성 버전은 manifest format과 무관하게 항상 문자열이다.

```json
"version": [1, 2, 3]   // 배열 방식: format 1, 2에서만
"version": "1.2.3"     // SemVer 문자열: format 2에서 허용, 3에서 필수
```

## UUID

UUID는 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` 형식 36자이고 **v4(무작위)** 여야 한다. uuidgenerator.net, VS Code UUID Generator 확장, bridge. 같은 편집기가 만들어 준다.

- 재사용 금지. 같은 헤더 UUID가 두 팩에 있으면 "Duplicate pack detected"가 나거나 한쪽이 조용히 교체된다.
- 헤더 UUID와 모든 모듈 UUID는 서로 달라야 한다(BP와 RP의 `header.uuid`도 달라야 한다).
- 업데이트해도 UUID를 유지한다. 바꾸면 새 팩으로 취급되어 월드가 업데이트를 받지 못하고, dynamic properties와 스크립트 격리는 팩 UUID에 묶여 있어 값이 사라진다. 대신 `header.version`을 올린다.
- 대소문자는 구분하지 않으나 소문자가 관례다.

## header

| 필드 | 필수 | 설명 |
|---|---|---|
| `name` | 예 | 게임 내 이름. `pack.name` 같은 현지화 키 가능 |
| `description` | 아니오 | 이름 밑 설명. 한두 줄. 현지화 키 가능 |
| `uuid` | 예 | 팩의 정체성 |
| `version` | 예 | 같은 UUID 팩을 다시 임포트할 때 **더 높은 버전만** 기존 것을 교체한다 |
| `min_engine_version` | BP·RP | 지원하는 최소 게임 버전. 팩에 켜 둘 레거시 동작도 결정한다 |
| `pack_scope` | RP 선택 | `"world"` 월드 안에서만, `"global"` 글로벌 목록에서만, `"any"` 기본값 둘 다 |
| `base_game_version` | 월드 템플릿 | 템플릿이 기준한 바닐라 팩 버전 |
| `lock_template_options` | 월드 템플릿 | 월드 옵션 변경 잠금 |
| `allow_random_seed` | 월드 템플릿 | 사용할 때마다 새 시드 |

## modules

팩 종류는 폴더가 아니라 모듈 `type`이 정한다.

| type | 팩 | 설명 |
|---|---|---|
| `data` | 행동팩 | 엔티티, 아이템, 블록, 루트 테이블, 함수 등 서버 정의 |
| `script` | 행동팩 | Script API 진입점. `language`, `entry` 필수. 보통 `data`와 함께 둔다 |
| `resources` | 리소스팩 | 텍스처, 모델, 사운드, UI 등 |
| `skin_pack` | 스킨팩 | |
| `world_template` | 월드 템플릿 | |
| `client_data` | 행동팩 | 옛 클라이언트 스크립팅 잔재. 제거됨, MS 문서에만 남음 |

한 팩에 `data`와 `resources`를 함께 둘 수는 없다. 모듈 필드는 `type`, `uuid`, `version`, `description`(메모), `language`(`"javascript"`만), `entry`다.

```json
{
  "format_version": 3,
  "header": {
    "name": "pack.name",
    "description": "pack.description",
    "uuid": "ee649bcf-256c-4013-9068-6a802b89d756",
    "version": "1.0.0",
    "min_engine_version": "1.26.40"
  },
  "modules": [
    { "type": "data", "uuid": "fa6e90c8-c925-460f-8155-c8a60b753caa", "version": "1.0.0" },
    { "type": "script", "language": "javascript", "entry": "scripts/main.js",
      "uuid": "c05a992e-482a-455f-898c-58bbb4975e47", "version": "1.0.0" }
  ],
  "dependencies": [
    { "uuid": "66c6e9a8-3093-462a-9c36-dbb052165822", "version": "1.0.0" },
    { "module_name": "@minecraft/server", "version": "2.7.0" },
    { "module_name": "@minecraft/server-ui", "version": "2.0.0" }
  ],
  "metadata": { "authors": ["Your Name"], "license": "MIT", "product_type": "addon" }
}
```

리소스팩 예(월드 한정, Vibrant Visuals 지원)는 `header.pack_scope: "world"`, `modules`에 `resources`, `capabilities: ["pbr"]`를 둔다. 스킨팩은 `min_engine_version`, `dependencies`, `capabilities`, `settings`를 쓰지 않는다. 월드 템플릿은 `header`에 `base_game_version`, `lock_template_options`, `allow_random_seed`를 두고 모듈 type을 `world_template`으로 한다.

## dependencies

항목은 팩 의존(`uuid` + `version`)이거나 스크립트 모듈 의존(`module_name` + `version`)이다.

- **팩 의존**: BP가 RP에 의존하면 BP를 월드에 넣을 때 RP가 자동으로 추가되고 없으면 경고한다. `uuid`는 RP의 `header.uuid`와 정확히 같아야 하고 `version`은 RP의 `header.version`과 맞춘다.
- **스크립트 의존**: `script` 모듈이 있는 BP는 임포트하는 API 모듈을 모두 선언해야 한다. 버전이 API 표면을 정한다. `-beta` 접미를 붙일 수 있다(`"2.4.0-beta"`).

## metadata

| 필드 | 설명 |
|---|---|
| `authors` | 저자 배열. format 3에서 필수 |
| `license` | 배포 라이선스 문자열 |
| `url` | 웹사이트 |
| `product_type` | 지원 값은 `"addon"`뿐 |
| `generated_with` | 도구 이름(`[a-zA-Z0-9_-]`, 32자 이하)과 SemVer 문자열 배열 |

## 규칙과 보고 (커뮤니티 2025-10 ~ 2026-11)

- **팩 종류는 폴더가 아니라 `modules`의 type으로 결정**된다: `"type": "data"` = 행동팩, `"type": "resources"` = 리소스팩, `"type": "script"` = 스크립트 모듈. 스크립트를 쓰는 BP에는 `data`와 `script` 모듈을 함께 둔다.
- **BP와 RP의 `header.uuid`는 서로 달라야** 하며, UUID는 유효한 v4여야 한다.
- **스크립트 모듈 예시** *(확인됨)*:

  ```json
  {"type":"script","language":"javascript","uuid":"<uuid>","version":"1.0.0","entry":"scripts/main.js"}
  ```
  `"language"`는 소문자 `"javascript"`, `"entry"`는 실제 메인 파일 경로여야 한다. 엔트리 파일이 없거나 비어 있으면 "could not load main".
- **의존성**: `{"module_name": "@minecraft/server", "version": "2.8.0"}`. RP를 자동 활성화하려면 BP 의존성에 RP의 `header.uuid`를 넣는다. 공유 UI RP를 쓰는 애드온도 의존성이 필요하다.
- **RP 버전을 올리면 BP 쪽 RP 의존성 버전도 같이** 올린다. 불일치 시 엉뚱한 "stack overflow" 로드 오류가 났다.
- **"Pack Manifest version 0 is deprecated"** 경고는 `format_version: 2`가 빠졌다는 뜻. bridge. 2.7.54가 만든 manifest에서는 `format_version: 2`가 있는데도 같은 경고가 났다(미해결).
- **흔한 manifest 오류**: "dependencies/1/version is not compatible with SemVer"는 의존성 버전 문자열 문제다. 잘못된 문자 하나로 "unknown package"가 나고, 파일 이름 오타(`mainfest.json`)는 로그 없이 팩이 안 보인다. RP에 BP의 `"data"` 모듈을 복사하면 임포트가 실패한다. 후행 쉼표는 `Missing '}' or object member name`을 낸다.
- **RP에는 `scripts` 폴더를 둘 수 없다.** RP만으로 된 애드온은 로직을 실행할 수 없다.
- **`"pack_scope": "world"` 팩**은 월드 안에서만 활성화되므로 메인 메뉴의 내 팩 목록에 나오지 않는다.
- **manifest 편집 도구**: https://jaylydev.github.io/manifest-generator/ , 스키마 https://github.com/Blockception/Minecraft-bedrock-json-schemas
- **미해결 질문**: "Provided uuid '/header/uuid' element already exists in pack manifest"의 원인, 26.63 이후 manifest `format_version` 1 지원 여부.
- **`client_data`**는 옛 클라이언트 스크립팅 잔재로 MS 문서에만 남아 있다.
- **`capabilities: ["script_eval"]`**은 `eval`/`new Function()`에 필요하다.
- **참고 manifest**: https://github.com/Mojang/bedrock-samples/blob/main/behavior_pack/manifest.json , 위키 해설 https://wiki.bedrock.dev/guide/project-setup#manifest-explained , MS 레퍼런스 https://learn.microsoft.com/en-us/minecraft/creator/reference/content/addonsreference/packmanifest?view=minecraft-bedrock-stable

### format_version 2와 3 차이

- **v3은 모든 버전을 문자열로**: `"version": "1.0.0"`, `"min_engine_version": "1.26.50"`, 모듈·의존성 버전도 문자열. `format_version` 자체는 숫자 3. v3에서 배열을 쓰면 `[Packs][error] header -> version: expected an object / invalid string`. format 2 + 배열은 계속 로드된다. BP가 RP에 의존하면 두 팩을 일관되게 유지. *(확인됨)*
- **pack settings(`settings`)는 v3 필요**. 26.50(2026-09-15)에서 v3가 정식 사용 가능해졌고, 그 전에는 실험적/프리뷰.
- **manifest v3 + 서브팩**이면 서브팩 슬라이더의 `Resolution: ` 접두사가 사라진다. 스키마: https://github.com/Mojang/bedrock-samples/blob/f5b651000f52b66334c968f3ccf1aca7950cd6ee/metadata/json_schemas/client_server/packaging/3.0.0/Manifest.json
- **함수의 `execute as @e`가 업데이트 후 오류로 표시**되던 것을 manifest `format_version`을 1→2로 올려 해결.
- **v3 + 코스메틱 모델이 서버에서만 보이고 월드/UI에서는 안 보인** 사례(1.26.0.02). *(single report, unanswered)*
- **커스텀 음반(music disc) 예시에서는 manifest `version`이 배열 `[1,0,0]`**이어야 했다(format 2 기준).

### min_engine_version

- **26.x 표기**: 게임 "26.30"은 `[1, 26, 30]`(v3에서는 `"1.26.30"`). 내부는 여전히 1.XX.X 체계다. `[1,26,0]`은 유효, `[2,30,0]` 같은 값은 로드 실패.
- **아직 출시되지 않은 버전**(예: 2026-09-10 시점의 `[1,26,50]`)을 쓰면 팩이 임포트되지 않는다. 출시 버전(예: `[1,26,40]`)을 쓴다. 게임 버전보다 높아도 임포트되지 않는다.
- **너무 낮으면** 옛 명령어 파서가 적용된다: 1.19.50 미만이면 새 `execute`가 "Unexpected @a/@e"로 파싱 실패, 1.19.0이면 `summon x ~~~ 0 0 ninja` 같은 문법도 실패(Blockception 생성 BP가 1.19.0을 사용). 최신 값 권장(예: `[1,21,110]` 이상).
- **옛 manifest(예: 1.21.30)도 26.0 이후 계속 로드**되며, 그보다 새로운 기능만 못 쓴다.
- **`[1,21,130]`으로 올려 몹/스폰 알 누락 항목이 해결**된 사례.
- **반대 사례**: format 2 manifest에 `[1,26,0]`을 썼을 때 팩이 목록에 보이지 않다가 min engine 수정으로 해결된 보고. *(단일 보고)*
- **bridge. 에디터는 `min_engine_version`으로 팩을 인식**하며, 1.26.0은 인식되지 않아 1.26.10/1.26.20을 권장받았다. *(단일 보고)*
- **블록 format 게이팅에는 `min_engine_version`이 영향을 주지 않는다.**
- **핫픽스 번호는 쓰지 않는다**: 0으로 끝나는 최신 릴리스 번호(`"1.26.10"`, format 1/2는 `[1, 26, 10]`)를 쓴다. `26.1` 같은 게임 표기는 실패한다. 26.x 이후에도 `[1, 26, 0]` 형식은 그대로라는 모더레이터 답변이 있다.

### 스크립트 모듈 의존성 버전

- **`"version": "beta"`**: `@minecraft/server`, `-ui`, `-gametest`에 쓰면 런타임에 최신 베타를 자동 선택한다(1.21.120 무렵 안정판에 도입). 고정 베타(`2.6.0-beta`)가 업데이트마다 깨지는 문제를 피하지만 API 파괴적 변경을 막아주지는 않는다. 베타 모듈은 Beta APIs 실험이 필요하다. 전체 재시작 후 오류가 나는 비일관적 사례가 있었고 `"stable"`은 문서화되지 않았다.
- **`"version": "*"`는 안정판에서 무효**다. `"2.6.0"`이나 `"beta"`처럼 명시한다.
- **오류 메시지에 사용 가능한 버전 목록**이 나온다. 일부러 틀린 버전을 넣어 Content Log에서 목록을 확인하는 방법도 쓰인다(2026-07-05 예: server 0.1.0, 1.19.0, 2.8.0, 2.9.0-beta, 3.0.0-alpha / server-ui 0.1.0, 1.3.0, 2.1.0, 2.2.0-beta, 3.0.0-alpha).
- **버전 충돌**: `@minecraft/server` `2.7.0-beta` + `@minecraft/server-ui` `1.3.0` → `version conflict for module [@minecraft/server-bindings]`. server-ui도 `2.1.0-beta`로 맞추면 해결.
- **시기별 권장 안정 조합**: 2025-11 server 2.3.0 + common 1.2.0 / 2026-03 server 2.5.0 / 2026-04-17 server 2.6.0 + server-ui 1.3.0 / 2026-05 server 2.7.0 / 2026-07 server 2.8.0 + server-ui 2.1.0 / 26.50 시점 server 2.10.0 + server-ui 2.2.0(2.3.0은 한 팩에서 스크립트 로드 실패) / 26.60 시점(2026-11-03) server 2.11.0 + server-ui 2.3.0, server-gametest `1.0.0-beta.1.26.60-stable`. BDS 예: server-gametest/net은 `1.0.0-beta.1.26.34-stable` 형식.
- **`server-net`·`server-admin`은 `1.0.0-beta`로만 존재**(Beta APIs 필요). "requested invalid version [2.2.0] of server-net, available 1.0.0-beta". BDS에서는 `config/default/permissions.json`의 `"allowed_modules": ["@minecraft/server-net"]`도 필요하다. `server-gametest`·`server-admin`은 디버깅 시 제거 권장.
- **커스텀 컴포넌트에는 `@minecraft/server` >= 2.0.0** 필요.
- **위키 커스텀 작물 예제의 모듈 버전이 낡아서** manifest 갱신으로 해결.
- **dynamic properties와 스크립트 격리는 팩 UUID에 묶여** 있어 UUID를 바꾸면 dynamic properties가 사라진다. header/module UUID를 고정하라.

### product_type과 업적

- **1.26.50 이전**: `"metadata": {"product_type": "addon"}`을 넣으면 BP/스크립트를 써도 업적이 유지되었다(스크립트·컴포넌트를 제한하지 않음). 위키: wiki.bedrock.dev/guide/project-setup#bp-manifest. *(확인됨)*
- **형식**: `product_type`은 BP manifest의 `metadata`에 문자열로만 쓴다. 객체 `{"addon": {}}`는 "Required '/metadata/product_type/product_type' element is the wrong type in pack manifest"로 거부된다. 치트나 실험 토글이 필요 없는 팩에서만 의미가 있다.
- **1.26.50 이후** *(상충)*: 외부(비 Marketplace) 애드온은 더 이상 업적 친화적일 수 없고 의도된 제한이라는 답변이 있었다(2026-09-19). 이 변경은 변경 로그에 없었고 MCPE-242529("Considered an Exploit")와 피드백 글(https://feedback.minecraft.net/hc/en-us/community/posts/48931692849677-Revert-the-change-of-disabling-achievements-for-third-party-add-ons)이 있다. 이후 26.52에서 수정되어 업적이 다시 유지된다는 보고(2026-10-11)와, 26.60에서도 꺼질 수 있으나 UI 메시지가 깨져 판단이 어렵다는 보고(2026-10-27)가 엇갈린다. 실제 상태는 판마다 확인한다.
- **Marketplace 버튼을 지우는 팩**도 업적을 끈다.
- 그 이전에도 "BP를 켜면 업적이 꺼지고 우회 불가"라는 답변이 있었으나 이는 `product_type` 이전 관행에 대한 것이다. *(대체됨)*
