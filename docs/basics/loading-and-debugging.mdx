## 개념

팩이 "로드되지 않는" 원인은 거의 항상 (1) manifest 오류, (2) JSON 문법 오류, (3) 캐시된 옛 팩, (4) 경로·이름 오류 넷 중 하나다. 진단은 **Content Log**에서 시작한다. Settings > Creator에서 Content Log GUI와 파일 출력을 켜면 파일별 JSON, Molang, Geometry 오류가 나온다. 로그가 깨끗한데도 "One of your resource or behavior packs failed to load"가 뜨는 경우는 흔하며 무시해도 된다.

## 점검 순서 예

1. Content Log를 켜고 로그를 비운 뒤 새 월드를 만들어 팩을 적용하고 게임을 닫는다(닫아야 로그가 flush된다).
2. `manifest.json`이 유효한 JSON인지, 헤더 UUID가 BP와 RP에서 다른지, 버전 형식이 `format_version`과 맞는지 본다.
3. 월드에 들어 있는 팩 사본이 옛 버전이 아닌지 보고, 버전을 올려 다시 시도한다.
4. 개발 폴더에 남은 zip이나 같은 팩 사본이 없는지 확인한다.

## 규칙과 보고

### 리로드와 캐시

- **`/reload`**는 개발 팩의 스크립트·함수를, **`/reload all`**은 추가로 루트 테이블 등을 다시 읽는다. 리소스팩은 리로드되지 않으므로 월드를 다시 열어야 한다. 새 함수/스크립트 파일(.js 포함)을 추가했다면 월드를 닫았다 다시 열어야 한다(2026-02 이후). 키 매크로에 `/reload`를 바인딩하면 편하다.
- **26.0에서 `/reload all`이 리소스팩을 깨뜨리던 버그가 수정**되었다.
- **manifest 편집 후 VV/capabilities 변경은 리로드로 적용되지 않았고** 게임을 완전히 재시작해야 했다.
- **캐시된 옛 팩이 수정을 가린다**: 버전을 올리거나 새 월드에서 테스트하라. 같은 팩 사본이 두 개 있어 엉뚱한 쪽이 장착된 경우도 흔하다. UUID/버전 편집 후 월드의 RP/BP 사본을 지우고 버전을 올린다.
- **"Resource pack has item definitions not found in the behavior pack"**: 월드의 BP 사본이 구버전이었다.
- **에디터 미저장 버퍼**가 유령 임포트 실패를 일으킨 사례, bridge. v2 루트 폴더 문제로 동기화가 안 된 사례가 있다. bridge.의 watch 모드를 공유 com.mojang에 맞추면 저장 시 자동 동기화된다.

### Content Log로 디버깅

- **Settings > Creator에서 Content Log GUI와 파일 출력을 켠다**. 파일별 JSON/Molang/Geometry 오류가 나온다. 잘못된 아이템 ID처럼 로그가 아예 남지 않는 경우도 있다. 로그를 비우고 재시작, 새 월드 생성 후 게임을 닫아야 로그가 flush된다. Ctrl+H로 기록을 볼 수 있다. `console.log`를 보려면 로그 레벨에 info를 포함한다.
- **아이콘이 없고 로그도 없는 아이템**은 보통 BP manifest에 RP 의존성이 없거나 파일 이름이 틀린 경우다.
- **무해한 오류**: `[Blocks] ... Unexpected version for the loaded data`(26.10의 거짓 오류, 26.20에서 수정), "couldn't find version 1.26.10 for blocks", 팩이 원인이 아닌 바닐라 레시피 중복 오류, Education Edition 토글로 인한 레시피 오류, 1.21.130 적대 몹의 `attack_interval is disabled (max <= 0)`(로그 레벨을 warn으로 올리면 숨겨진다), copper_golem TextureSet Inform 메시지(26.0에서 수정되었다고 함).
- **오류 위치**: 메시지의 "line N, column M"부터 확인한다. bridge. v2는 게임이 보고하지 않는 스키마 오류를 보여 줄 수 있다. 검증 보조: https://github.com/Blockception/Minecraft-bedrock-json-schemas , mctools.dev, jsonlint.com.
- **조용한 실패**: 문법 오류가 있는 바닐라 엔티티 덮어쓰기는 오류 없이 바닐라 정의로 되돌아간다. 지오메트리 파일이 없으면 오류 없이 아이템이 아주 작거나 보이지 않는다. "Item is an invalid json object"는 JSON 문법 오류다.
- **미해결**: 버전을 바꿔도 임포트할 때 팩이 중복되는 문제, 두 번째 manifest가 없는데 "Multiple manifests found"가 나는 문제.
- **`Missing referenced asset geometry.x`** 오류는 캐시 또는 다른 팩과의 식별자 충돌인 경우가 많다.
- **Content log 파일이 50~500GB까지** 커질 수 있으니 정리한다.
- **스키마 경고 "this member was found in the input, but is not present in the Schema"**: 오래된 바닐라 BP 파일(`dragon_fireball`의 `conditional_bandwidth_optimization`, `physics`, `pushable`)에서 나오며 덮어써도 없앨 수 없다. 일반적으로는 `min_engine_version`을 추가하면 스키마 오류가 해결되는 경우가 있다.
- **Blockception `.mcattributes`** 파일로 검증 오류를 무시할 수 있다.
- **JSON 함정**: 끝의 쉼표, 닫는 괄호 과다, 곡선 따옴표(“ ”)가 파일 전체를 깨뜨린다. `//` 주석은 게임에서는 대체로 동작한다(에디터는 경고).
- **챗봇이 만든 애드온 파일은 자주 틀린다**. MS 문서, bedrock.dev, wiki.bedrock.dev를 기준으로 삼는다.
