## 버전 체계

모든 스크립트 모듈은 시맨틱 버전(major.minor.patch와 선택 접미사)을 쓴다. 이 번호는 마인크래프트 제품 버전(예 `1.19.60`)과 별개로 API 표면이 바뀔 때 오른다. 모듈은 세 갈래로 나온다(출처: ms-learn, `creator/Documents/scripting/versioning.md`).

| 트랙 | 예 | 규칙 |
|---|---|---|
| stable | `1.1.0` | 완성된 API. 같은 major 안에서 minor·patch는 하위 호환이다. 의존성 `1.3.0`은 실제로 `1.8.0`이 채워 줘도 동작해야 한다 |
| beta | `1.3.0-beta` | 호환성 보장 없음. minor 올림에도 속성·메서드가 사라질 수 있고, 릴리스마다 beta 번호가 오른다. 월드에서 "Beta APIs" 실험을 켜야 한다 |
| internal | `1.4.0-internal` | 커스텀 팩에서 동작하지 않고 지원도 없다 |

가능하면 stable을 쓰고, 공개하는 팩은 출시 시점에 지원되는 가장 높은 버전을 의존성으로 적는다. major가 오르는 것(v2)은 하위 호환을 깨는 정리이며, `1.x.x`를 지정한 기존 팩은 앞으로도 오랫동안 그대로 동작하도록 지원된다(출처: ms-learn, `v2-overview.md`).

## 매니페스트에서 버전 지정

```json
"dependencies": [
  { "module_name": "@minecraft/server",    "version": "2.4.0" },
  { "module_name": "@minecraft/server-ui", "version": "2.0.0" }
]
```

최신 beta를 따라가려면 숫자 대신 문자열 `"beta"`를 쓴다.

```json
"dependencies": [
  { "module_name": "@minecraft/server", "version": "beta" }
]
```

`"beta"`를 쓰면 업데이트마다 버전을 고치지 않아도 되지만, 월드의 Beta APIs 실험을 꺼 두면 스크립트 전체가 로드되지 않는다. 특정 `x.y.z-beta.*` 고정 버전은 게임 업데이트마다 깨진다. 잘못된 버전을 쓰면 콘텐츠 로그가 사용 가능한 버전 목록을 출력하므로 그 목록에서 고른다.

## 타입 정의 설치

npm의 `@minecraft/server`는 stable과 beta, 정식 릴리스와 프리뷰 변형 타입을 모두 제공한다. 타입 전용이라 실행에는 필요 없다(출처: ms-learn, `creator/Documents/scripting/developer-tools.md`).

```powershell
npm i @minecraft/server
npm i @minecraft/server-ui
npm i @minecraft/server@beta @minecraft/server-ui@beta   # beta 타입
```

## v2에서 바뀐 API

2.0.0-beta 타입(`npm i @minecraft/server@2.0.0-beta`)으로 코드를 열어 보면 바뀐 곳을 바로 알 수 있다. 공식 개요의 변경점은 이렇다(출처: ms-learn, `v2-overview.md`).

- `Entity.applyKnockback`이 수평 힘을 `VectorXZ`로 받고 수직 세기는 별도 인자다. V1 방향 벡터는 정규화해서 옛 수평 세기를 곱해 변환한다.
- `Dimension.runCommandAsync`가 제거됐다(대부분 비동기가 아니었다). 비동기가 필요하면 `system.runJob`을 쓴다.
- 엔티티 `getComponents/getComponent/hasComponent`는 엔티티가 무효하면 예외를 던진다. `EntityComponent.getEntity`와 `EntityInventoryComponent.container`도 `undefined` 대신 예외를 던진다.
- 여러 클래스의 `isValid()` 메서드가 읽기 전용 속성 `isValid`로 바뀌었다.
- `EffectType.getName`과 `Effect.typeId`는 항상 `minecraft:` 접두사를 포함한다.
- `minecraft:air` 아이템이 제거됐다(블록으로는 유효하다).
- `world.afterEvents.worldInitialize`는 `worldLoad`로 이름만 바뀌었고, `world.beforeEvents.worldInitialize`는 `system.beforeEvents.startup`으로 대체됐다.

## 커뮤니티 노트가 알려 주는 beta·버전 규칙

아래 두 절은 커뮤니티 조사로 얻은 실전 규칙과 릴리스별 변화 연표다.


`*confirmed*`, `*single report*`, `**conflicting**`은 보고의 신뢰도 표시다. 이 페이지의 근거는 커뮤니티 보고이며 Mojang 공식 문서와 다를 수 있다.

#### 모듈 버전과 beta

- **`"version": "beta"`**: `@minecraft/server`, `@minecraft/server-ui` 등에 숫자 없이 `"beta"`를 쓰면 항상 최신 beta로 해석된다. 프리뷰에서 추가돼 2025-10-28경(1.21.120) 안정판에 도달. API가 beta에서 stable로 옮겨가도 계속 동작하지만 쓰는 API가 바뀌면 깨질 수 있다. `"stable"`은 가끔 자동 업그레이드되지만 신뢰할 수 없다. *confirmed*
- **Beta APIs 실험 토글**: beta 모듈/기능은 월드에서 "Beta APIs" 실험을 켜야 한다. 꺼져 있으면 매니페스트가 요구하므로 스크립트 전체가 로드되지 않고, 스크립트 자체로는 이를 감지할 수 없다(우회: tick.json 함수가 매 틱 점수를 올리고 스크립트가 지움 → 값이 커지면 경고). 일부 경우 "Upcoming creator features", "Experimental creator camera features" 등 다른 실험도 켜야 main.js가 로드됐다. Aternos에서는 servers > world > options에서 Beta APIs를 켠다. 서버용으로 배포되는 스크립트 애드온 묶음은 대부분 Beta APIs를 요구하며, 모바일 사용자에게는 이 설정이 걸림돌이 된다는 보고(*single report*).
- **stable의 호환성 기대**(**conflicting**): stable 스크립트는 업데이트에도 깨지지 않는다는 의견과, 폐기된 API가 제거되면 업데이트 때 깨질 수 있다는 의견이 공존한다. stable API는 실험 토글이 필요 없다.
- **Marketplace 팩은 실험/beta API 사용 불가**; DDUI처럼 안정화된 API만 사용.
- **잘못된 버전**(`1.0.0-beta` 등)은 "requested invalid version"과 함께 사용 가능한 버전 목록을 로그에 출력한다(예: server 0.1.0, 1.19.0, 2.6.0, 2.7.0-beta, 3.0.0-alpha). 안 쓰는 모듈(gametest 등)도 버전 충돌을 일으키므로 제거.
- **server / server-ui 짝 맞추기**: `[@minecraft/server] 2.1.0 requested by pack vs 1.3.0 requested by server-ui-bindings` 같은 충돌은 호환되지 않는 조합. 예: server 2.1.0 + server-ui 2.0.0, server 2.6.0 + server-ui 1.3.0(동작), server 2.10.0 + server-ui 2.2.0(26.50), server 2.11.0 + server-ui 2.3.0(2026-11 최신 안정). beta 짝은 `2.12.0-beta.1.26.60-stable` + `2.4.0-beta.1.26.60-stable`. server 2.6.0 + server-ui 1.0.0은 `server-bindings` 충돌.
- **v1 최고 버전은 1.19.0**, v2는 하위 호환이 깨진다. 1.x에 머무는 팩은 `EntityScaleComponent.value` 쓰기 등 2.x에서 막힌 기능을 쓸 수 있다(→ [엔티티 컴포넌트의 scale 우회](./entities-and-components.mdx)).
- **`3.0.0-alpha`** 는 최신 2.x beta를 그대로 반영한다. 또한 2.x 버전은 내부적으로 항상 최신으로 승격되므로 타입 자동완성과 런타임 동작이 다를 수 있다(개발자 발언).
- **Education Edition** 은 몇 버전 뒤처짐(1.21.130 기준 server 2.4.0 stable만 지원, beta 모듈은 업데이트마다 깨짐).
- 구버전 고정 beta(`server 1.13.0-beta`, `server-ui 1.2.0-beta`)는 현재 버전에서 동작하지 않는다.
