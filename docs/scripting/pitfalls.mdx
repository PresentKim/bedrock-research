## 이 페이지의 사용법

Script API의 문제는 대개 (1) 실행 권한 때문에 월드 변경이 막히거나, (2) 버전과 beta 설정이 어긋나거나, (3) API가 아예 없는 경우다. 이 페이지는 먼저 가장 흔한 실수를 코드로 보이고, 이어 레시피와 "제한과 우회법" 표, 풀리지 않은 질문을 모은다.

## 흔한 실수 5가지

1. before 이벤트에서 월드를 바꾼다 → `system.run`으로 미룬다.

```javascript
// 오류: Native function [Entity::setOnFire] cannot be used in restricted execution
world.beforeEvents.playerInteractWithBlock.subscribe((e) => { e.player.setOnFire(5); });
// 수정
world.beforeEvents.playerInteractWithBlock.subscribe((e) => {
  const p = e.player;
  system.run(() => { if (p.isValid) p.setOnFire(5); });
});
```

2. 모듈 최상위에서 월드에 접근한다 → `world.afterEvents.worldLoad` 안으로 옮긴다.
3. `cancel`을 구조분해로 받는다 → `event.cancel = true`로 쓴다.
4. 아이템을 고치고 되돌려 쓰지 않는다 → `container.setItem(slot, item)`.
5. 매니페스트의 `dependencies`를 `modules` 안에 넣거나 버전이 틀렸다 → 콘텐츠 로그의 버전 목록을 본다.

```javascript
// 3번의 올바른 형태
world.beforeEvents.playerBreakBlock.subscribe((event) => {
  if (event.block.typeId === "minecraft:bedrock") event.cancel = true;
});
```

## 기본 패턴: 쿨다운과 틱 시간

```javascript
const lastUse = new Map();              // playerId -> tick
world.afterEvents.itemUse.subscribe(({ source, itemStack }) => {
  const now = system.currentTick;
  if (now - (lastUse.get(source.id) ?? -999) < 40) return;   // 2초 쿨다운
  lastUse.set(source.id, now);
  source.sendMessage(`${itemStack.typeId} 사용`);
});
world.afterEvents.playerLeave.subscribe(({ playerId }) => lastUse.delete(playerId));
```

일시정지를 존중해야 하면 `system.currentTick`, 실제 시간이 필요하면 `Date.now()`를 쓴다.

## 커뮤니티 노트

아래는 커뮤니티 조사로 모은 패턴 레시피, 알려진 제한과 우회법 표, 미해결 질문이다.


`*confirmed*`, `*single report*`, `**conflicting**`은 보고의 신뢰도 표시다. 이 페이지의 근거는 커뮤니티 보고이며 Mojang 공식 문서와 다를 수 있다.

### 패턴 레시피 모음

- **명령 블록 없는 반복**: 24000틱마다 실행 → `system.runInterval` 또는 tick.json 함수 + 스코어 카운터. 가장 느린 틱 속도에서 매 틱 인터벌이 약 3초에 한 번 돌았다는 관찰.
- **게임모드 플래그 → 머티리얼**: `player.getGameMode()`(enum 대소문자 주의) + `addTag`/`removeTag`를 폴링하거나 `world.afterEvents.playerGameModeChange`(입장 시 이미 그 모드인 플레이어는 놓침), RP player.json에서 `query.all_tags('tag')`로 머티리얼 선택. 필터: `world.getPlayers({gameMode: "Survival"})`, `GameMode.Creative`.
- **들고 있으면 효과**: `runInterval(..., 20)`에서 주손 확인 후 `addEffect('speed', 30, {amplifier:1, showParticles:false})`. 이벤트식: `playerHotbarSelectedSlotChange` + `playerInventoryItemChange`(빈 슬롯 드롭은 슬롯 변경 이벤트가 없으므로 둘 다)로 플레이어별 인터벌을 시작/`clearRun`, run id는 WeakMap. 태그로 아이템 제한은 인벤토리 변경 후 드롭/배출(갑옷은 폴링).
- **킬 카운터/보상**: `entityDie` → `damageSource.damagingEntity` → `objective.addScore(identity, 1)` → `killer.triggerEvent("unlock_level_up")`. 레벨 시스템: `playerSpawn`에서 기본값, 태그→XP 조회 테이블, 다중 레벨업은 `while`. 플레이타임: 매초 점수 증가 대신 입장 시 `Date.now()` 저장, 퇴장 시 차이 합산.
- **클레임/플롯**: 클레임 박스 저장 + 청크별 인덱스(월드 DP), before `playerBreakBlock`/interact 취소, 청크 단위 클레임이 가장 단순, 블록마다 로그를 남기지 말고 볼륨 기반 보호. 플롯은 그리드 배치, DP에 저장해 이탈 시 경계 검사 또는 구조물로 저장. 상자 반대 호퍼 복제 방지는 `facing_direction` 2-3, 4-5 쌍(+ toggle_bit) 확인.
- **커스텀 채팅/랭크/반스팸**: beta `chatSend` 취소 + 서식 재전송, 플레이어 객체가 아닌 `player.id` Map으로 반스팸, 명령어(`!cmd`)만 취소.
- **사망/입장 메시지 커스텀**: `showDeathMessages` 끄고 `entityDie`에서 `world.sendMessage`, 입장은 `playerSpawn`, 퇴장은 `playerLeave`.
- **경험치·킵인벤토리**: 플레이어별 킵인벤토리는 게임룰을 켜고 태그 없는 플레이어 인벤토리를 직접 비우거나 떨어뜨림(태그=면제).
- **리딤 코드**: 비밀 시드에서 결정적 코드(FNV-1a 32bit → xorshift32 → 문자셋)로 목록 저장 없이 검증, 사용한 코드는 월드 DP, 지급 아이템은 ticking area 청크의 미리 채운 상자에서 `container.getItem(slot).clone()`.
- **투사체 발사**: `const head = player.getHeadLocation(), v = player.getViewDirection(); const e = player.dimension.spawnEntity('ns:proj', {x: head.x+v.x, y: head.y+v.y, z: head.z+v.z}); const p = e.getComponent('projectile'); p.owner = player; p.shoot({x: v.x*1.5, y: v.y*1.5, z: v.z*1.5}, {uncertainty: 0});` — 고정 오프셋이 아니라 시선 방향 오프셋, owner를 먼저 설정(자기 피격 방지). owner 읽기는 미룬 콜백에서 throw할 수 있고 `behavior.ranged_attack` 투사체는 owner가 undefined(태그/DP로 사수 기록). 스노볼 `runtime_identifier` 투사체는 owner가 없어 어그로·damagingEntity가 투사체가 됨 → arrow 런타임 id. 커스텀 투사체 엔티티는 버그가 많아 바닐라 `runtime_identifier` 권장(중력을 꺼도 shoot 시 떨어짐). 화살 데미지는 직접 설정 불가(속도/정의 변경 또는 명중 시 추가 데미지). 변신한 투사체는 운동량을 잃으므로 속도 저장 후 `shoot()`. 하늘로 쏜 박힌 투사체는 디스폰되지 않음 → `minecraft:timer` 디스폰 이벤트. JSON의 `"minecraft:projectile": {"lightning": true}`.
- **포털/차원 차단**: 포털 비활성 불가 → 플레이어 근처(~0.3블록) `minecraft:portal` 블록 제거 + `playerDimensionChange`에서 되돌리기(크리에이티브는 이벤트 전에 이동), player.json `minecraft:dimension_bound`(다른 애드온과 충돌, 양쪽 차원 잠금). 커스텀 포털 연결은 월드 DP(충돌 없는 포털 블록 + 20틱 AABB 검사), 포털 프레임 BFS flood fill.
- **엔티티 모방/분신**: 플레이어 장비를 미러링하는 몹(장비 읽기 + 엔티티 equippable — 몹에선 실패 사례), 블록 위 아이템 표시는 주손에 아이템을 든 더미 엔티티(`/replaceitem`, 엔티티 스케일이 아이템도 키움), 시체는 플레이어 스킨 더미 엔티티, 앵무새 계열 투명 엔티티를 어깨에 태워 player.json 수정 없이 파티클/모델 추가(서버에서 지연), 매 틱 텔레포트하는 엔티티로 커스텀 장비 슬롯 흉내.
- **떠 있는 텍스트**: TextPrimitive(권장) 또는 엔티티(한 틱에 많이 스폰 금지, 한 번 스폰 후 텔레포트, 충돌 문제).
- **블록 부수기(비플레이어)**: 블록 경도로 파괴 시간을 계산하고 "block break progress entity"로 금 가는 모습 표시(지연/로드 청크 전환 시 남는 버그, `/reload`로 정리). 나무 벌목·광맥 채굴은 큐 + 방문 Set(`x;y;z` 문자열 키) BFS. 바닐라 같은 벌목(내구도 포함) chop-chop. 3x3 도구 템플릿(before 이벤트, 2.6/2.7 stable).
- **팬덤 패턴**: 주사위(엔티티 속성 + `playAnimation(id, {nextState})`), 대시 공격(타이머 + 속도/데미지/블록 제거 + 애니메이션 하나), 무기 재밍(창 안의 발사 열, 임계치 이후 확률, 아이템별 `jamUntil`), 자바식 무기 쿨다운(스크립트 추적 + JSON UI), 커스텀 마체(`playerSwingStart` + `applyImpulse` 낙하/윈드버스트), 근접 넉백(`entityHitEntity` + 주손 typeId + `applyKnockback`), 몹 끌어당기기(몹→플레이어 정규화 벡터 * 힘), 이중 점프(`playerButtonInput` + 틱 타이밍 + `applyImpulse`), 괭이 없이 경작(`minecraft:is_hoe` 태그 → farmland + 소리), 농지 짓밟기 방지(농지 위 플레이어에 1틱 느린 낙하; 몹은 못 막음), 주민 거래 교체(거래표별 컴포넌트 그룹 + 이벤트, `become_unskilled` 후 `become_*`로 리롤), 떠돌이 상인 라마 제거(`entitySpawn`에서 `minecraft:trader_llama` 제거), 몹 진화 체인(`entitySpawn`에서 태그 → 차원별 `getEntities({tags})`; JSON `timer`가 더 낫다는 의견), 구조물 패턴 소환 감지(레이어가 정확히 일치해야 함).
- **상호작용 아이템 포획**: `world.beforeEvents.playerInteractWithEntity`에서 빈 그물 + 대구면 슬롯을 `new ItemStack("my:fish_net")`으로 교체하고 대상 `remove()`(쓰기는 `system.run`). 열대어는 `minecraft:tropicalfish`, `color`/`color2`/`variant`/`mark_variant` 조합(3072), 값은 `system.run` 전에 읽기, 버킷 이벤트 없음.
- **커스텀 음악 디스크**: 커스텀 음악은 스크립트 필요(바닐라 음악이면 불필요). 새 포맷의 `minecraft:food`에서 음식 효과가 빠졌으므로 `onConsume`/`itemCompleteUse`로 효과 부여. 화면 오버레이(가루눈 얼음 효과)는 스크립트로 불가, 물속 이동 속도 API 없음(속도 효과/물갈퀴).
- **아이템 아이콘 경로**: 창 아이콘은 `textures/items/spear/iron_spear`(단수 `spear`). 아이템 typeId → 텍스처 경로 객체는 직접 생성.
- **수학 유틸**: 정수 난수 `Math.floor(Math.random()*(max-min+1)+min)`(`Math.round` 버전은 양 끝이 불균등), A→B 선은 정규화 벡터로 스텝, 3D 구(8방향 대칭) 돔, 큐빅 베지어 x→y는 Cardano(루프 없음) vs 이분/뉴턴, 크기 `Math.hypot`. 명령 좌표에 소수점이 없으면 x/z에 +0.5. Vec3 라이브러리 피드백: `isSomething()`은 throw하지 말 것.
- **드롭 감지 단일 커맨드**: 비플레이어 드롭 아이템은 회전 정확히 0°, 플레이어 드롭은 플레이어 회전을 상속 → `execute if entity @e[name=...,type=item,ry=-0.01,rym=0.01] as @a at @s positioned ^^^1 rotated as @e[...,type=item,r=3] positioned ^^^-1 if entity @s[r=0.001] run ...`.


### 알려진 제한과 우회법

| 제한 | 우회법 | 출처 |
|---|---|---|
| `chatSend`가 beta 전용 | 커스텀 커맨드, beta + 실험 토글; 다른 팩 핸들러와 중복 주의 | |
| 비-OP의 셀렉터 매개변수 오류(MCPE-230568) | String 매개변수로 이름 받아 조회 | |
| Realms에서 `CommandPermissionLevel.Admin` 불가 | `GameDirectors` + origin/태그 검사 | |
| 하위 커맨드·가변 문자열 인자 없음 | 선택 String 여러 개, `_` 구분, `!prefix` 채팅, 별도 커맨드 | |
| 몹 장비(equippable) 접근 불가 | `replaceitem`/`testfor hasitem` + `successCount`, 인벤토리 커스텀 엔티티 | |
| 플레이어 회전 설정 불가 | `teleport(loc, {rotation \| facingLocation})`, 카메라 고정 + 입력 권한 | |
| 최대 체력·스케일·mark_variant·target 읽기 전용 | player.json 이벤트, health_boost, 속성 + 컴포넌트 그룹, 1.19.0 보조 팩 | |
| 블록 드롭 수정 불가 | 파괴 취소 + `generateLootFromBlock`, 아이템 엔티티 교체 | |
| 제작·거래·낚시·점프·수면·갑옷 착용 이벤트 없음 | 인벤토리 diff, 폴링, 엔티티 JSON → scriptevent | |
| 블록 DP 없음(26.50 이전), 블록 DP ~1 KB | `dimension:x:y:z` 키 월드 DP | |
| DP 문자열 32,767 바이트 | 여러 키로 분할, 압축, 레코드당 키 | |
| ItemStack을 DP에 저장 불가(NBT 손실) | 엔티티 인벤토리 + 구조물(QIDB 등) | |
| 셜커 상자 아이템 내용물 접근 불가 | 블록으로 설치해 읽기, 디스펜서, 숨은 차원 | |
| 컨테이너 UI 강제 열기 불가 | 인벤토리 엔티티/상자 마인카트/Chest-UI 폼 | |
| 언로드 청크 블록 접근 불가 | 임시 ticking area(팩당 ~255 청크), UnloadedUtils | |
| 화염 부여 피해·몹 어그로 취소 불가 | `extinguishFire` + 체력 복원, 공격 비활성 이벤트 | |
| 클라이언트 로드 완료 이벤트 없음 | 지연 + `isValid`, 이동 감지, `UserBusy` 재시도 | |
| 우클릭 허공(빈손), 커스텀 키 입력 없음 | 스윙 + 임시 아이템, `/scriptevent` 키 단축키, HUD 버튼 | |
| `faceLocation`이 일부 면에서 틀림 | EPSILON 보정 코드, `1 - face` 보정 | |
| 클라이언트 설정(FOV, 언어, 카메라 시점) 읽기 불가 | `locale`(취약), Molang 애니메이션 태그 | |
| server-net이 BDS 전용, Realms HTTP 불가 | 웹소켓 `/connect`, 디버거 채널(Hive Mind API) | |
| 애드온 간 스크립트 공유 불가 | scriptevent IPC(MCBE-IPC) | |
| 같은 틱 여러 `setTitle` 소실 | 틱당 하나 큐 | |
| DDUI 표시 후 요소 추가 불가, 폼 연속 열기 실패 | 미리 만들고 `visible` 토글, ≥1틱 지연 | |
| QuickJS 성능(JIT 없음) | 캐시, `runJob`, 이벤트 기반, 할당 최소화 | |


### 미해결 질문

- 커스텀 커맨드 `PlayerSelector`의 비-OP 권한 버그(MCPE-230568)는 언제 고쳐지는가? 하위 커맨드·나머지 문자열 인자 지원 일정은? (Mojang: 파서가 취약, 미정)
- `minecraft:equippable`이 몹에 언제 돌아오는가(Mojang "on radar")?
- `world.beforeEvents.chatSend`는 왜 계속 beta인가(다중 애드온 간섭 추정), stable 대체가 나오는가?
- `entityHurt` before 이벤트에서 i-frame 중 데미지를 낮췄을 때의 이벤트 미발생/이상 동작, 취소 시 넉백·화염 부여 동작은 최종적으로 어떻게 정리되는가?
- after 이벤트 콜백과 `runInterval` 콜백의 정확한 처리 순서, `system.run`이 현재 틱 끝인지 다음 틱인지.
