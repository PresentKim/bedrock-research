이 페이지는 두 자료를 합친다. 앞부분은 가이드 규칙과 커뮤니티 보고를 같은 주제끼리 맞춰 본 대조표(D-01~D-28)이고, 뒷부분과 같은 폴더의 세 페이지는 Bedrock OSS·커뮤니티 서버의 최근 1년(2025-10-22 ~ 2026-11-13) 대화에서 UI 주제를 정리한 노트다. 원문 대화는 공개하지 않았고 이 노트는 대화를 주제별로 다시 쓴 것이다.

커뮤니티 항목 끝의 ``은 작업 단위 id와 날짜이고, `[보충 2026-10-28]`은 2026-10-23 이후 대화를 직접 읽고 더한 항목이다. 신뢰 표시는 다음과 같다: *confirmed*는 여러 사람이 확인, *single report*는 한 사람의 보고, *unverified*는 추측이나 근거가 약한 내용, **conflicting**은 보고가 엇갈림. 원문은 커뮤니티 대화이므로 중요한 내용은 공식 문서나 직접 테스트로 확인하고 쓴다. 가이드의 `실측`과 커뮤니티 보고가 다르면 가이드를 따르되, 커뮤니티 쪽에 버전 정보가 있으면 버전이 바뀐 것일 수 있다.

## 가이드와 커뮤니티 대조

가이드 규칙과 커뮤니티 보고를 같은 주제끼리 맞춰 본 결과다. **같음**은 서로 독립된 근거가 같은 결론을 낸 것, **보강**은 커뮤니티가 가이드에 없는 사실이나 버전 정보를 더한 것, **다름**은 아직 갈리는 것이다. 다름은 게임에서 확인하기 전에는 단정하지 않는다.

## 핵심 요약

1. **JSON UI의 위상**: Mojang은 JSON UI를 공식 지원한 적이 없고 공식 문서 계획도 없다. 단계적으로 폐기(deprecated)되고 있으며 DDUI/Ore UI로 대체되는 중이다. 그래도 2026-10 현재 HUD, 서버 폼, 컨테이너 화면을 꾸밀 수 있는 수단은 JSON UI뿐이다. 버전이 붙어 있지 않아서 릴리스마다 자주 깨진다.
2. **DDUI는 Ore UI 위에서 돈다**: DDUI(`@minecraft/server-ui`의 `CustomForm` + `Observable*`)는 Ore UI(Coherent Gameface 웹 기술) 기반이라 JSON UI 리소스 팩으로는 꾸밀 수 없다. 열린 폼을 실시간으로 갱신할 수 있지만 크기, 배경, 위치, 폰트는 바꿀 수 없다. 26.30 stable(2026-06-16)에 들어갔다.
3. **JSON UI는 스크립트 상태를 직접 읽지 못한다**: scoreboard 값, dynamic property, tag, Molang, 체력을 읽을 수 없다. 스크립트는 title/subtitle/actionbar/chat 텍스트나 폼 title/body/button 텍스트로 데이터를 보내고, JSON UI가 그 문자열을 파싱한다. UI에서 스크립트로 이벤트를 보내는 길도 없다(폼 submit만 가능).
4. **Preserved title 패턴이 HUD 데이터 채널의 표준이다**: 크기 0인 `data_control` 패널에서 `#hud_title_text_string`을 `binding_condition: "visibility_changed"` + `binding_name_override: "#preserved_text"`로 한 번 더 바인딩한다. 그러면 타이틀이 사라진 뒤에도 값이 남는다(wiki `preserve-title-texts`).
5. **문자열 연산**: `'%.Ns' * #text`(앞 N **바이트** 자르기), `-`(부분 문자열 제거), `+`(이어 붙이기)가 사실상 전부다. 연산자는 `and`/`or`/`not`/`=`/`<`/`>`만 쓸 수 있고 `<=`/`>=`/`==`/`&&`/`||`는 없다. `§`는 2바이트, 한글과 이모지는 3바이트 이상이다.
6. **1.21.130(2025-12)에 문자열 곱셈이 제한됐다**: 리터럴 N을 쓰는 `'%.Ns' * #x` 형태만 남았고, 동적 N(`('%.' + #n + 's')`)과 다른 printf 형식은 막혔다. `* 1`로 숫자 변환하는 방식도 불안정해졌다. 지금은 `(0 + #str)`을 쓰는 것이 안전하다.
7. **크래시 위험**: `#size_binding_x/y`나 `#anchored_offset_value_*`에 잘못된 값이 들어가거나, 문자열을 나누거나, prefix가 없는 타이틀에 산술 연산을 하면 게임이 죽는다. 월드가 손상된 사례도 있다. superflat 테스트 월드를 쓰고 산술은 prefix가 맞을 때만 돌게 한다.
8. **`_ui_defs.json` 등록**: 새 UI 파일은 `ui/_ui_defs.json`에 등록해야 한다. 파일 안에 오류가 하나라도 있으면 그 파일 전체가 없는 것처럼 무시된다. Content Log GUI를 켜고 확인한다.
9. **`modifications`는 바닐라 요소에만 쓸 수 있다**: 자기가 만든 요소나 다른 팩의 요소에는 적용되지 않는다. 같은 바닐라 요소를 여러 팩이 수정하면 위에 있는 팩만 이긴다.
10. **서버 폼 버튼**: 버튼에 `{"binding_type":"collection_details","binding_collection_name":"form_buttons"}`와 `collection_index`가 없으면 스크립트 쪽 `selection`이 undefined가 된다. `button.form_button_click`이 눌리면 폼은 항상 닫힌다.
11. **폼 라우팅**: 폼 title에 `§` 플래그 prefix를 넣고 `third_party_server_screen`/`server_form_factory`에서 title로 레이아웃을 고른다. `visible:false`는 요소를 여전히 로드하므로, 많을 때는 factory `#collection_length` 0/1이나 `ignored`로 아예 생성하지 않는다.
12. **커스텀 컨테이너 UI(Chest UI)**: `minecraft:inventory`를 가진 엔티티를 이름 키로 매칭해서 만든다. 블록은 커스텀 UI를 직접 띄울 수 없지만, 커스텀 블록 엔티티 컨테이너는 `title`로 구분해 컨테이너마다 UI를 바꿀 수 있다([화면별 노트](./community-reports-screens.mdx)). 아이템 아이콘은 aux id(`id * 65536 + data`)로 렌더하는데, aux id는 버전과 설치된 애드온에 따라 바뀐다.
13. **성능**: 렉의 주원인은 레이아웃이 아니라 바인딩이다. `binding_condition: "once"`, `ignored: true`(`visible:false`보다 쌈), 페이지 분할, grid(10k 버튼도 즉시 로드)를 쓴다. factory를 줄이고 바인딩 루프를 피한다.
14. **같은 tick 충돌**: 한 tick에 title을 여러 번 보내면 마지막 것만 남는다. 다른 애드온이 같은 title/actionbar를 쓰면 서로 덮어쓴다. 큐를 두고 tick마다 하나씩 보내거나 값을 한 문자열에 묶는다.
15. **Marketplace**: 애드온은 바닐라 UI 파일을 건드릴 수 없다. 월드 템플릿은 가능하며 주로 NPC 화면을 쓴다. DDUI도 Marketplace에서 쓸 수 없다고 보고됐다(2026-04).

## UI 시스템 현황과 로드맵

### JSON UI
- **공식 지원 아님, 폐기 예정**: Mojang(커뮤니티 경유 전달)은 JSON UI가 비공식이고 deprecated이며 메뉴를 하나씩 교체하고 있다고 했다. 공식 문서 계획은 없다. 원래 JSON UI 팀도 없다는 보고가 있다. *confirmed*
- **반대 의견(2025-12)**: "JSON UI는 아직 업데이트되므로 deprecated가 아니다"라는 의견도 있었다. 이후 2026년 공지와 정황으로 보면 점진적 대체가 맞다. **conflicting**(시기에 따라 다름)
- **전망**: 커뮤니티는 1~3년 안에 폐기된다고 본다. Ore UI가 모든 화면을 대체하는 것은 2028년쯤으로 예상한다. Mojang은 Marketplace 콘텐츠를 깨뜨리지 않으려고 Ore UI 전환을 서두르지 않는다고 했다. *unverified*(커뮤니티 추정)
- **이미 Ore UI로 바뀐 화면**: 설정, 월드 목록, 로딩 화면, 사망 화면 등 게임 외 화면이 Ore UI로 바뀌었다. 예전 설정을 열던 button id도 이제 Ore UI 설정을 연다. 2026-01 preview는 서버 "treatments"(kill switch)로 메뉴/설정을 교체했다. 게임플레이 HUD와 서버 폼은 하위 호환을 어느 정도 유지한다.
- **오래된 min engine 버전**: min engine version이 낮게 고정된 월드에서는 JSON UI가 계속 동작한다. Marketplace 맵이 이 방식을 쓴다. 예전 JSON UI 팩이 앞으로도 동작할지는 알 수 없다.
- **중국판**: 중국판(Chinese edition)에는 JSON UI 기능이 더 있다. *single report*

### Ore UI
- **정체**: React 기반 웹 UI다(github.com/Mojang/ore-ui). Coherent Gameface(Cohtml) 위에서 V8로 돈다. 축소된 ~5 MiB React 번들 하나가 느린 원인으로 지목됐다. Gameface는 float를 지원하지 않는다. 2026-10 정식판 UA는 `Cohtml/2.2.8.1 (Windows; Native)`, 주소는 `ui://hbui/gameplay.html`이다.
- **JSON UI와의 관계**: JSON UI로는 Ore UI 화면을 수정하거나 우회할 수 없다. 두 레이어는 겹쳐 쌓일 수 있다. Ore UI는 TTF/OTF, GIF, 비디오를 지원한다. Ore UI 전용 폰트 `mcFive`가 있다. 신뢰된 리소스 팩은 Ore UI 파일을 교체할 수 있다([화면별 노트](./community-reports-screens.mdx)의 Ore UI 수정 절).
- **26.60 stable(2026-10-27)**: Ore UI 로딩이 크게 빨라져 "JSON UI와 비슷하다"는 반응이 나왔다. 모바일에서 버튼 소리가 늦게 난다는 보고가 있다. [보충 2026-10-28]
- **강제로 예전 UI 쓰기**: LeviLauncher나 "Force Close OreUI" 같은 모드로 예전 UI를 강제할 수 있다. 예전 월드 생성 화면은 별도 모드로 Ore UI를 끄거나, VDX legacy console UI 팩을 팩 목록 위쪽에 두면 계속 동작했다는 사례가 있다. *single report*
- **CSS와 메모리**: Ore UI 렌더러의 CSS 제한은 [페이지 환경](../ore-ui/page-environment.mdx)의 커뮤니티 보고 절에 있다. 화면을 열 때 메모리가 튀는 것은 V8을 내장한 웹 런타임이라서라는 설명이 있다.
- **새 메인 메뉴(2026-11-12 목격)**: Marketplace 광고, Realms 배너, 서버, 최근 월드가 있고 로고 글자가 없는 메인 메뉴가 보였다(버전 미상). 하드코딩된 Ore UI로 보이며 8Crafter Ore UI Customizer 플러그인으로 광고를 지울 수 있다는 언급이 있다. *unverified*

### DDUI 로드맵 (Mojang darknavi 발언, 날짜 미정)
- **발언 내용**: 모달 폼은 첫 단계일 뿐이고, 레이아웃 파일이 크리에이터에게 공개될 예정이다. 레이아웃과 스타일은 별도 파일로 나뉘어서 스타일 팩이 스타일과 이미지만 담을 수 있게 된다. 컨테이너(chest 같은) 컴포넌트를 커스텀 화면에 넣을 수 있고, 엔티티 렌더러/paperdoll은 "불합리하지 않다"고 했다. HUD도 계획돼 있다. JSON UI와 DDUI는 한동안 공존한다. *confirmed*(Mojang 발언)
- **커뮤니티 정리**: 레이아웃이 스타일보다 먼저 나온다. 크리에이터가 CSS를 직접 쓰지는 않는다(g07hn: "nope"). 스타일은 웹 표준을 따를 예정이다. 일정은 없다. Mojang 개발자는 "1단계 = 단순 모달 폼, 2단계 = 전체 레이아웃"이라고 했고, 커스텀 RP 패널은 2단계 전까지 내부 팩 전용이다.
- **DDUI 정의**: DDUI는 Ore UI가 아니라 Ore UI 위에서 돌아가는, 애드온이 커스텀 화면을 기술하는 포맷이다("JSON UI 2.0 running on Ore UI"). 서버가 JSON 형태의 데이터를 facet으로 보내 바인딩한다. 레이아웃은 게임 파일(`hbui`, 리소스 팩 `ddui` 폴더)에 있다. 성능은 JSON UI보다 나쁘다는 평가가 있다. wiki는 DDUI를 scripting 아래에 두고 이동할 수 있다고 적었다.
- **server-ui 폼과의 관계**: DDUI가 server-ui 폼을 바로 대체하지는 않고 server-ui는 먼 미래에 deprecated될 것이라는 답이 있었다. 공식 DDUI 스타일은 JS/CSS가 아니라 JSON 컴포넌트 레지스트리 형태가 될 것이라는 의견도 있다. *unverified*(의견)

### Marketplace 규칙
- **애드온 vs 월드**: 애드온은 바닐라 UI 파일을 수정할 수 없고, 월드 템플릿은 수정할 수 있다(주로 NPC 화면). 커스텀 JSON UI는 월드, mashup, dynamic world에서 받아들여지고 애드온에서는 받아들여지지 않는다. 커스텀 UI가 없다는 것이 Marketplace 콘텐츠의 한계로 꼽힌다. 그래서 Marketplace 팩은 엔티티와 render controller로 UI를 흉내 낸다.
- **@bedrock-core/ui 인증**: 버튼 라우터의 `#form_button_texture % 65536` 모듈로 연산이 assert를 일으켜 인증에서 떨어진다. 이 경우 `item_renderer`를 빼고 RP 에셋을 모두 자기 팩에 넣는다.
- **DDUI는 Marketplace 불가**: 2026-04 시점 보고다. *single report*
