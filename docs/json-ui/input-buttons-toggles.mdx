입력 컨트롤은 화면이 사용자의 조작을 받는 부분이다. 세 가지를 다룬다.

- **버튼(`button`)**: 눌림을 `button_mappings`로 **버튼 ID**에 연결한다. 버튼 ID는 엔진이 알아듣는 것(`button.form_button_click`, `button.menu_exit` 등)과 팩이 임의로 정한 것으로 나뉜다. 엔진이 아는 ID는 동작(서버 폼 제출, 닫기)을 일으키고, 모르는 ID는 아무 동작도 하지 않지만 애니메이션 `play_event` 같은 UI 안 이벤트에는 쓸 수 있다.
- **토글(`toggle`)**: 켜짐/꺼짐 상태가 있는 버튼이다. 상태 8개(켜짐·꺼짐 × 기본·호버·잠김·잠김 호버)마다 자식 컨트롤을 정의하고, 현재 상태에 해당하는 하나만 그려진다. 토글 상태는 `#toggle_state`로 다른 컨트롤이 읽는다.
- **입력창·포커스**: 키보드·컨트롤러가 가리킬 대상을 `focus_*` 속성으로 정한다.

## 7.0 가장 작은 예제

**예 1. 바닐라 버튼 템플릿으로 닫기 버튼 만들기.** 직접 만들기보다 바닐라 템플릿(`common_buttons.light_text_button`)을 변수로 재사용한다. `$pressed_button_name`에 엔진이 아는 버튼 ID를 주면 그 동작이 일어난다.

```json
"close_button@common_buttons.light_text_button": {
  "size": [ 64, 32 ],
  "$button_text": "닫기",
  "$pressed_button_name": "button.menu_exit"
}
```

**예 2. 토글 상태로 이미지 보이기/숨기기.** 토글의 `$toggle_view_binding_name`이 토글 컨트롤의 이름이 되고, 다른 컨트롤이 `source_control_name`과 `#toggle_state`로 그 상태를 읽는다.

```json
"my_toggle@common_toggles.light_text_toggle": {
  "size": [ 64, 32 ], "$button_text": "켜기",
  "$toggle_name": "my_toggle",
  "$toggle_view_binding_name": "my_toggle_state" },
"my_image": { "type": "image", "texture": "textures/items/apple", "size": [16, 16],
  "bindings": [ { "binding_type": "view",
    "source_control_name": "my_toggle_state",
    "source_property_name": "#toggle_state",
    "target_property_name": "#visible" } ] }
```

### 7.0.1 Bedrock Wiki의 설명(Buttons and Toggles)과 button_mappings

아래는 Bedrock Wiki(`bedrock-wiki` 0930b39)의 "Buttons and Toggles" 원문(CC BY 4.0)이다. 바닐라 템플릿으로 토글·버튼을 만들고, 호버 글자를 내는 콘텐츠 버튼과 버튼 ID로 애니메이션을 재생하는 방법을 보인다.

<Excerpt src="bedrock-wiki" title="Buttons and Toggles" path="docs/json-ui/buttons-and-toggles.md">

**Toggles**

In this example, we will reference `ui/ui_template_toggles.json`

```json
{
  "our_toggle@common_toggles.light_text_toggle": {
    "size": [
      64,
      32
    ],
    "$button_text": "Click me!",
    "$toggle_name": "wiki_toggle", // Required, but it has no effect unless a hardcoded toggle name is used.
    "$toggle_view_binding_name": "wiki_toggle_state" // The toggle name that allows us to retrieve data.
  }
}
```

And that's it! You now have a working toggle. You can test it by adding it to any screen.

Additionally, you can utilize toggles to control the visibility of UI elements.

```json
{
  "our_toggle@common_toggles.light_text_toggle": {
    "size": [
      64,
      32
    ],
    "$button_text": "Click me!",
    "$toggle_name": "wiki_toggle", // Required, but it has no effect unless a hardcoded toggle name is used.
    "$toggle_view_binding_name": "wiki_toggle_state" // The toggle name that allows us to retrieve data.
  },
  "our_image": {
    "type": "image",
    "texture": "textures/items/apple",
    "size": [
      16,
      16
    ],
    "offset": [
      0,
      20
    ],
    "bindings": [
      {
        "binding_type": "view",
        "source_control_name": "wiki_toggle_state", // // The toggle name specified in the $toggle_view_binding_name
        "source_property_name": "#toggle_state", // The binding data that returns the toggle state as a boolean value
        "target_property_name": "#visible"
      }
    ]
  }
}
```

**Buttons**

Generally, buttons have limited functionality, as they are primarily used in hardcoded instances, such as navigating to a screen or opening a dialog.

In this example, we will reference `ui/ui_template_buttons.json`

```json
{
  "our_button@common_buttons.light_text_button": {
    "size": [
      64,
      32
    ],
    "$button_text": "Click me!",
    "$pressed_button_name": "button.menu_exit" // Required, you can put in any global button names or hardcoded button names.
  }
}
```

And that's it! You now have a working button, clicking on it exits you to the current screen you're in. You can test it by adding it to any screen.

**Advanced Buttons and Toggles**

**Hover Text**

In order to make buttons that shows a text when you hover into it, we will need to use **Content Buttons**.

In this example, we will reference `ui/ui_template_buttons.json` and `ui/ui_common.json`

```json
{
  "our_button@common_buttons.light_content_button": {
    "size": [
      18,
      18
    ],
    "$button_content": "namespace.our_button_content_panel", // Reference our content element.
    "$pressed_button_name": "button.menu_exit" // Required, you can put in any global button names or hardcoded button names.
  },
  "our_button_content_panel": {
    "type": "panel",
    "controls": [
      {
        "our_image": {
          "type": "image",
          "texture": "textures/items/apple",
          "size": [
            16,
            16
          ]
        }
      },
      {
        // You can use any element but we'll just use the hover text when you hover an item in-game.
        "our_hover_text@common.hover_text": {
          "ignored": "$default_state", // Required, this will make the element not visible if the button is in a default state or isn't hovered.
          "property_bag": {
            "#hover_text": "" // You can put your text here. It doesn't support localizing so if that's what you are looking to do, create a custom hover text.
          }
        }
      }
    ]
  }
}
```

**Play Animation**

If you want to play an animation when you click a button, you have to use `$pressed_button_name` in your animation's `play_event` property.

For example:

```json
{
    "example_animation": {
        "anim_type": "offset",
        "easing": "linear",
        "duration": 2,
        "from": [
            0,
            0
        ],
        "to": [
            -50,
            0
        ],
        "play_event": "button.example_button_id"
    },
    "example_button@common_buttons.light_text_button": {
        "$pressed_button_name": "button.example_button_id", // use this button id in play_event property of your animation
        "$button_text": "Play Animation",
        "size": [
            80,
            20
        ]
    },
    "example_label": {
        "type": "label",
        "text": "Example Text",
        "anims": [
            "@namespace.example_animation" // add your animation here
        ],
        "anchor_from": "top_right",
        "anchor_to": "top_right"
    }
}
```

### 7.0.2 `button_mappings`의 구조(Bedrock Wiki Intro와 MS Learn)

`button_mappings`는 객체 배열이고 항목은 `from_button_id`(입력으로 들어오는 버튼 ID), `to_button_id`(실제로 누른 것으로 취급할 ID), `mapping_type`, 선택 `input_mode_condition`을 가진다(MS Learn `ui_element` 참조 표와 같다). `from_button_id`를 생략하면 "이 컨트롤을 누름" 자체가 입력이다.

| `mapping_type` | 뜻 | 바닐라 횟수 |
| --- | --- | --- |
| `pressed` | 컨트롤이 클릭·터치로 눌렸을 때 | 599 |
| `focused` | 컨트롤이 먼저 호버·포커스를 받았을 때(예: Enter로 확정) | 145 |
| `global` | 컨트롤이 화면에 있는 동안 어디서든 그 키가 눌릴 때 | 536 |
| `double_pressed` | 두 번 눌렀을 때 | 20 |

```json
"sample_button@common.button": {
  "$pressed_button_name": "button_id",
  "button_mappings": [
    { "from_button_id": "button.menu_ok", "to_button_id": "$pressed_button_name", "mapping_type": "focused" },
    { "from_button_id": "button.menu_select", "to_button_id": "$pressed_button_name", "mapping_type": "pressed" },
    { "from_button_id": "button.menu_up", "to_button_id": "$pressed_button_name", "mapping_type": "global" }
  ]
}
```

버튼 ID와 키의 대응은 INP-21 표(위키 원문)에 있다. 위키는 컨트롤러 대응도 함께 적는다: `button.controller_select` X/A, `button.menu_secondary_select` Y, `button.menu_exit`·`button.menu_cancel` B, `button.menu_up/down/left/right` 십자키. 여러 입력 방식을 함께 지원하라고 권한다. MS Learn의 `input_mode_condition` 표는 값이 비어 있으므로 값은 INP-02(바닐라 집계: `gamepad`, `gamepad_and_not_gaze`, `not_gamepad`)를 따른다.

## 7.1 버튼

- **[INP-01]** 버튼은 상태별 자식 컨트롤을 `default_control`, `hover_control`, `pressed_control`, `locked_control`로 지정한다. 직접 만들기보다 바닐라 템플릿(`common_buttons.light_text_button` 등)을 `$pressed_button_name`, `$button_text` 같은 변수로 재사용하는 것이 보통이다. `&#123;바닐라&#125;` (출처: VN default_control 34·hover_control 42·pressed_control 36·locked_control 18회, VN server_form.json:211)
- **[INP-02]** `button_mappings`의 항목은 `from_button_id`, `to_button_id`, `mapping_type`(`pressed` 599, `global` 536, `focused` 145, `double_pressed` 20), 선택적으로 `input_mode_condition`(`gamepad`, `gamepad_and_not_gaze`, `not_gamepad`)과 `ignored`를 가진다. `&#123;바닐라&#125;` (출처: VN, 부록B)
- **[INP-03]** 화면별로 엔진이 알아듣는 버튼 ID가 정해져 있다. `&#123;바닐라, 작동팩, 실측&#125;` (출처: VN server_form.json:212·321, npc_interact_screen.json:1222, BC-S14)

| 동작 | `to_button_id` |
| --- | --- |
| 액션 폼 엔트리 누름 | `button.form_button_click` |
| 모달 폼 제출 | `button.submit_custom_form` |
| NPC 대화 버튼 | `button.student_button` |
| 닫기 | `button.menu_exit` |
| 상자 셀에서 한 개 버리기 | `button.drop_one` |

- **[INP-04]** 폼 엔트리를 누르게 하려면 `button.menu_select → button.form_button_click`(`pressed`)과 `button.menu_ok → button.form_button_click`(`focused`) 두 매핑을 주고, 버튼 자신에 `collection_details` 바인딩을 둔다(COL-04). `&#123;코드, 작동팩, 바닐라&#125;` (출처: BC 4.1-(3), BA 5장, VN)
- **[INP-05]** 호버(툴팁)만 감지하고 제출하지 않는 버튼은 `button_mappings`를 비우거나 `$pressed_button_name`을 엔진이 모르는 값(`"unset"`)으로 두고, `focus_enabled`, `focus_magnet_enabled`로 포커스만 받는다. 클릭 소리를 없애려면 `sound_volume: 0`. `&#123;작동팩&#125;` (출처: BA 5장, AP 4.8)
- **[INP-06]** 버튼의 기본/호버/눌림 상태 컨트롤의 가시성은 **버튼 상태 머신이 소유**한다. 앱의 가시성 게이트는 상태 컨트롤 안쪽이나 버튼 바깥에 두고, 같은 컨트롤을 바인딩과 상태 머신이 함께 건드리지 않게 한다. `&#123;실측&#125;` (출처: BC-rules, BC 4.1-(6))
- **[INP-07]** 비활성 버튼은 진짜 버튼(enabled)과 같은 생김새의 비활성 사본(disabled)을 겹쳐 두고, 같은 데이터로 하나만 보이게 한다(`binding_condition: "always"`). 비활성 사본은 포인터 아래에서도 비활성 모양을 유지해야 한다. `&#123;코드, 실측&#125;` (출처: BC 4.1-(6), BC-rules)
- **[INP-08]** 상태 컨트롤 안의 내용 레이어를 배경보다 높게 준다(bedrock-core 관례: 배경 1, 캡션·아이콘 12). `&#123;코드&#125;` (출처: BC 6.5-3, BC-rules)
- **[INP-09]** 버튼 템플릿 안에서는 버튼 상태 변수를 식에 쓸 수 있다: `"visible": "($hover_state or $pressed_state)"`. `&#123;작동팩&#125;` (출처: AP 4.8)

## 7.2 토글

토글 상태 컨트롤 8개(바닐라 이름):

```
checked_control          unchecked_control
checked_hover_control    unchecked_hover_control
checked_locked_control   unchecked_locked_control
checked_locked_hover_control  unchecked_locked_hover_control
```

- **[INP-10]** 토글은 현재 상태가 가리키는 자식 **하나만** 그린다. 정의하지 않은 상태(예: hover)로 들어가면 컨트롤이 사라지므로 **8개 상태를 모두** 정의한다. `&#123;실측, 바닐라&#125;` (출처: BC-S4, VN 8개 이름 각 2회 이상)
- **[INP-11]** 클릭이 동작하려면 `toggle_on_button`, `toggle_off_button`과 `button_mappings`(`button.menu_select`·`button.menu_ok`)가 필요하다. 이것이 없으면 그려지기만 하고 눌리지 않는다. `&#123;실측&#125;` (출처: BC-S4)
- **[INP-12]** 라디오 그룹은 `toggle_name`(그룹 이름), `radio_toggle_group: true`, `toggle_group_forced_index`, `toggle_group_default_selected`로 만든다. `&#123;바닐라, 실측&#125;` (출처: VN radio_toggle_group 59·toggle_group_forced_index 210·toggle_group_default_selected 24회, BC 5장)
- **[INP-13]** **스크립트가 필요 없는 탭**: 라디오 토글 그룹을 만들고 탭 내용을 각 토글의 `checked` 상태 컨트롤 **안에** 넣는다. 바깥에서 상태를 관찰할 필요가 없어 서버에 아무것도 보내지 않는다. 액션 폼 아래와 `modifications`로 넣은 상자 화면 양쪽에서 동작했다. `&#123;실측&#125;` (출처: BC-S4, BC 5장)
- **[INP-14]** 같은 forced index를 공유하는 수동 라디오 피어끼리는 상태가 믿을 만하게 미러링되지 않는다. 각 입력은 자기 상태를 읽는다. 네이티브(모달 폼) 라디오는 그룹의 컬렉션 스코프를 공유하므로, 폼에서 온 값은 별도 데이터 소스로 읽고 라디오는 그 인덱스 컬렉션 아이템 바깥에 둔다. `&#123;실측&#125;` (출처: BC 6.7-3·4, BC-rules)
- **[INP-15]** 접기/펼치기(Disclosure)는 토글 하나와, 그 토글 상태를 따라 보이고 숨는 형제로 만든다. 접힌 행이 아래를 끌어올리는 것은 스택 패널이 숨은 자식에 공간을 주지 않는 성질(LAY-04) 덕이다. `&#123;코드&#125;` (출처: BC 5장)

## 7.3 HUD 위의 입력, 상자에서의 입력

- **[INP-16]** HUD에 그린 버튼이 호버와 스크롤을 받으려면 `hud_screen`에 `always_accepts_input: true`가 필요하다. 마우스에서만 확인되었고 터치·컨트롤러에서 호버가 되는지는 확인되지 않았다. `&#123;작동팩, 미검증&#125;` (출처: AP 3.1)
- **[INP-17]** 상자 화면의 셀을 버튼처럼 쓰려면 모든 입력(클릭, 우클릭, 시프트클릭, Q, 더블클릭, 게임패드)을 `button.drop_one`으로 매핑한다. 누를 때마다 정확히 한 개가 떨어지고 커서는 변하지 않으며, 같은 틱에 `entitySpawn` → `entityItemDrop`(플레이어 포함) 순으로 이벤트가 온다. `&#123;실측&#125;` (출처: BC-S14)
- **[INP-18]** 상자에서 커서로 아이템을 집게 하는 방식은 쓰지 않는다. 인벤토리가 가득 차면 눌림이 사라지고, 커서에 든 아이템은 엔진이 직접 그려 JSON UI로 숨길 수 없다. `&#123;실측&#125;` (출처: BC-S13, BC 4.3-(4))

## 7.4 Bedrock Wiki 대조로 더한 규칙

위키(BW) 문서를 바닐라 1.26.50.4와 대조해 더한 규칙이다. 위키 문장만 있는 것은 `미검증`, 위키의 게임 스크린샷이 있는 것은 `실측`(제3자 기록)으로 표시했다.

- **[INP-19]** 바닐라 토글 템플릿(`common_toggles.light_text_toggle` 등)은 `$toggle_view_binding_name`이 토글 컨트롤의 이름이 되므로, 다른 컨트롤이 `"source_control_name": "<그 이름>"`, `"source_property_name": "#toggle_state"`로 상태를 읽는다(바닐라 61회). `$toggle_name`은 필수지만 엔진이 아는 이름이 아니면 효과가 없다고 한다. `&#123;바닐라, 미검증&#125;` (출처: BW-btn, VN)
- **[INP-20]** 애니메이션 이벤트(`play_event`, `start_event`)에 **버튼 ID**를 쓰면 그 버튼이 눌릴 때 재생된다: 버튼 `"$pressed_button_name": "button.my_anim"`, 애니메이션 `"play_event": "button.my_anim"`. 바닐라에도 `"start_event": "button.menu_achievements"`가 1회 있다. 엔진이 모르는 ID라 서버에는 아무것도 가지 않는다. `&#123;미검증, 바닐라&#125;` (출처: BW-btn, VN)
- **[INP-21]** 기본 키 대응(위키 표): `button.menu_select` 좌클릭, `button.menu_secondary_select` 우클릭·Y, `button.menu_ok` Enter, `button.menu_cancel`·`button.menu_exit` Esc·B, `button.menu_up/down/left/right` 방향키·D-pad, `button.menu_autocomplete` Tab, `button.controller_select` X/A, `button.menu_tab_left/right` 탭 키·범퍼, `button.menu_inventory_cancel` 인벤토리 키. `from_button_id: "any"`도 있다(바닐라 1회, `gamepad_layout_screen.json`). `&#123;미검증, 바닐라&#125;` (출처: BW-intro, BW-doc, VN)
- **[INP-22]** 게임패드·방향키 포커스는 `focus_identifier`로 이름을 붙이고 `focus_change_up/down/left/right`로 다음 대상을 지정한다. 밖으로 못 나가게 하려면 값에 `FOCUS_OVERRIDE_STOP`을 쓴다(바닐라 226회). 컨테이너 단위로는 `focus_container: true`와 `focus_container_custom_*`(`other_focus_container_name`, `focus_id_inside`)를 쓴다. `&#123;바닐라&#125;` (출처: BW-doc Focus 표, VN)
- **[INP-23]** `follows_cursor: true`(바닐라 4회)는 컨트롤이 커서를 따라가게 하고, `draggable`(`vertical`·`horizontal`·`both`, 바닐라 `vertical` 1회)은 입력을 받는 컨트롤(`input_panel`, `button`)에 버튼 매핑과 함께 줄 때 끌 수 있게 한다. `&#123;바닐라, 미검증&#125;` (출처: BW-doc Layout 표, VN)
- **[INP-24]** 버튼의 `#hyperlink`는 엔진의 허용 목록(글자 그대로 일치하는 URL 116개, INP-34)에 있는 것만 연다. 커스텀 URL은 열리지 않는다. 위키의 "약 30개"는 틀렸다. `&#123;코드&#125;` (출처: NB-08, VN `#hyperlink` 사용)

## 7.5 연구 서버 서버 실측으로 더한 규칙

연구 서버 서버(`DF`)를 만들며 Windows 1.26.52 에서 실측한 것이다. 서버 폼 하나로 여러 화면을 그리는 구조에서 얻었다.

- **[INP-31]** 서버 폼 버튼은 끌 수 없다. 버튼 템플릿의 `$pressed_button_name`을 엔진이 모르는 이름(`button.df_noop`)으로 두면 눌러도 폼에 답하지 않고 호버 툴팁은 그대로 떴다(INP-05를 서버 폼에서 확인). 고른 탭·고른 칸처럼 같은 화면을 다시 보낼 뿐인 버튼에 쓴다. `&#123;실측&#125;` (출처: DF)
- **[INP-32]** 바닐라 `common.button`·`common.toggle`은 `focus_enabled`가 켜져 있어 휴대폰에서 폼을 열면 첫 버튼이 호버 상태로 그려졌다. 폼의 모든 버튼에 `$focus_enabled: false`, 라디오 토글에 `$toggle_group_default_selected: -1`과 `$toggle_focus_enabled: false`를 준다. 라디오 토글은 형제끼리만 한 그룹이라 칸마다 부모가 다른 격자에서는 배타적이지 않았다. `&#123;실측&#125;` (출처: DF)

## 7.6 엔진 동작 분석으로 더한 규칙

Android 1.26.52.3 클라이언트의 네이티브 라이브러리를 읽은 것이다(`NB`). 수준은 `코드`다.

- **[INP-33]** 엔진에 있는 `button.menu_*` 버튼 ID는 31개다(`button.menu_emote_slot_0`~`3` 포함). INP-21의 위키 표에 없는 것으로 `button.menu_tertiary_select`, `button.menu_auto_place`, `button.menu_inventory_drop`, `button.menu_inventory_drop_all`, `button.menu_inventory_cancel`, `button.menu_alternate_tab_left`·`_right`, `button.menu_autocomplete`·`_back`, `button.menu_textcursorleft`·`right`, `button.menu_textedit_up`·`down`, `button.menu_clear`, `button.menu_play`, `button.menu_edu_play`가 있다. 이름이 있다는 것까지만 확인했고 어느 키에 대응하는지는 모른다. `&#123;코드&#125;` (출처: NB 4장)
- **[INP-34]** `#hyperlink`는 버튼을 누를 때 엔진의 허용 목록을 통과해야 열린다. 목록은 **글자 그대로 일치해야 하는 URL 116개**다(`https://www.minecraft.net/<언어>/terms/r1~r3` 87개, `https://aka.ms/…` 20개, EULA·저작권 표시·계정 설정 등). 어떤 조건(에디션·플랫폼 판정으로 보임)이 참일 때만 `https://education.minecraft.net/`, `https://aka.ms/`, `ms-windows-store:`로 **시작하는** URL도 통과한다. 팩이나 서버가 넣은 URL은 열리지 않고, 목록의 URL도 조금만 달라지면 열리지 않는다(INP-24의 결론은 맞고 "약 30개"는 틀림). `&#123;코드&#125;` (출처: NB-08)
## 7.7 StarLibV2의 클라이언트 검색 필터(SLB)

StarLibV2(`jb-starlibv2`, GPL-3.0)는 입력창 글자로 서버 폼 버튼을 걸러 내는 방법을 쓴다. 기법만 다시 적었다.

#### SLB 6. 클라이언트 검색 필터 [확인(구조), 미검증(동작)]

- 검색창: 바닐라 `common.text_edit_box`를 상속하고 `$text_box_name`과 `$text_edit_text_control`을 같은 이름(기본 `search_field`)으로 준다. 바닐라 텍스트 입력 템플릿은 `property_bag`에 `"#property_field": "#item_name"`을 두어 입력 글자를 자기 `#item_name`에 쓴다(바닐라 11회, 예: `ui_common.json:1416`).
- 버튼 쪽: view 바인딩 `source_control_name: "search_field"`, `source_property_name: "#item_name"` → `#search`. `(#search = '')`이거나 `#form_button_text`(또는 5장 범위 조각)가 `#search`를 포함하면 보인다.
- 초기값: `property_bag`에 `#default_search`를 두고 `binding_condition: "once"` view로 `#search`에 한 번 복사한다. 그러면 처음에는 그 기본 단어를 가진 버튼만 보이고, 사용자가 입력하면 입력어로 바뀐다 [추론].
- 숨은 항목은 세로 스택에서 공간을 내주므로(LAY-04) 목록이 실제로 줄어든다. 그리드 템플릿을 쓰면 빈칸이 남는다(LAY-31).


### 7.7.1 반영안(미적용)

- **[INP-25 제안]** 입력창의 글자는 바닐라 `common.text_edit_box`의 `property_bag` `"#property_field": "#item_name"`에 따라 그 입력창 컨트롤의 `#item_name`에 들어간다. 다른 컨트롤은 `source_control_name`(입력창 이름 = `$text_box_name`)과 `source_property_name: "#item_name"`으로 읽는다. 액션 폼 버튼을 이 값으로 포함 검사해 숨기면 서버 왕복 없는 검색 필터가 된다. `{바닐라, 작동팩, 미검증}` (출처: VN ui_common.json:1416 외 11회, SLB 6장). 가이드 본문에는 아직 적용되지 않았다.

**실측 필요**: `common.text_edit_box` 입력 중 다른 컨트롤이 읽은 `#item_name`이 글자마다 갱신되는지, 폼을 다시 열면 비워지는지.
