식은 JSON UI에서 값을 **계산하는 유일한 수단**이다. 괄호로 감싼 문자열이고, 두 곳에 쓴다. 하나는 `$변수`를 재료로 쓰는 생성 시점의 식(`ignored`, `requires`, 변수 값, 크기·위치)이고, 다른 하나는 `#속성`을 재료로 쓰는 실행 중의 식(view 바인딩의 `source_property_name`)이다. 이 장은 쓸 수 있는 연산자, 문자열을 자르고 지우는 법, 타입이 숫자와 문자열 사이에서 바뀌는 방식, 클라이언트를 죽이는 식, 그리고 게임 없이 엔진 평가기를 재구성한 Cinnabar의 실행 결과를 다룬다.

## 5.0 식의 개념과 기본 예제

식 하나는 `(왼쪽 연산자 오른쪽)` 꼴이다. 값이 문자열이면 따옴표로 감싸고, 바인딩 이름은 `#`로, 변수 이름은 `$`로 시작한다. 결과는 `target_property_name`이 가리키는 속성에 담긴다. 그 속성이 `#visible`이면 컨트롤이 보이고 숨는다.

**예 1. 값이 12일 때만 보이는 이미지.** `#value`는 어딘가에서 온 바인딩이다. 식의 결과(참/거짓)가 `#visible`에 들어간다.

```json
"badge": {
  "type": "image", "texture": "textures/ui/star",
  "bindings": [
    { "binding_type": "view",
      "source_property_name": "(#value = 12)",
      "target_property_name": "#visible" }
  ]
}
```

**예 2. 제목 문자열에 `boss`가 들어 있을 때만 보이기(포함 검사, EXP-07).** 문자열 빼기가 모든 출현을 지우므로, 지운 결과가 원래와 다르면 `boss`가 들어 있다는 뜻이다.

```json
{ "binding_type": "global", "binding_name": "#title_text" },
{ "binding_type": "view",
  "source_property_name": "(not ((#title_text - 'boss') = #title_text))",
  "target_property_name": "#visible" }
```

**예 3. 접두사 검사(EXP-08).** `'%.Ns' * #s`는 `#s`의 앞 N바이트다. 아래는 제목이 `a1;`로 시작할 때 참이 되는 식이다(`a1;`이 3바이트).

```json
"(('%.3s' * #title_text) = 'a1;')"
```

**예 4. 크기 식(생성 시점).** `size`, `offset`에서는 `100% - 10px`, `100%c + 4px`처럼 단위가 붙는 별도 문법을 쓴다. 이것은 괄호 식(`+ - * / = < >`)과 다르다. 결과표는 5.8.2에 있다.

## 5.0.1 표준 문서가 말하는 연산자

Bedrock Wiki의 "Using Operators" 표(`bedrock-wiki` 0930b39 `json-ui-intro.md`)는 연산자를 이렇게 적는다. 이 표의 뜻과 검증 결과는 5.1의 규칙이 판정한다.

| 연산 | 위키 예 | 이 장의 판정 |
| --- | --- | --- |
| 더하기 `+` | `("100% + 420px")`, `($text + ' my')`, `($index + 2)`, `('#' + $bdg_nm + '_name')` | 문자열 이어 붙이기가 기본이다(EXP-01) |
| 빼기 `-` | `("100% - 69px")`, `($text - ' my')`, `($index - 13)` | 문자열이면 모든 출현 제거(EXP-12) |
| 곱하기 `*`, 나누기 `/` | `($var * 9)`, `(#value / 2)` | 정수 나눗셈(EXP-18) |
| `=`, `>`, `<` | `($var = 12)`, `(#value > 13)`, `($var < 4)` | 동작 |
| 크거나 같음, 작거나 같음 | `(#value > 2 or #value = 2)`, `(#value < 2 or #value = 2)` | 전용 연산자가 없어 `or`로 만든다(EXP-03) |
| `and`, `or`, `not` | `($is_school and $is_open)`, `(not (#name = 'text'))` | 같은 순위(EXP-29) |

MS Learn(`ms-learn` a9fd1c0)의 JSON UI 참조(`JsonUiReference`)는 속성 목록과 타입만 적고 식 문법은 설명하지 않는다. 또 그 문서의 선택지(enum) 표는 값 칸이 모두 `undefined`로 비어 있고, `grid_item_template`을 정수로, `font_scale_factor`를 불리언으로 적는 등 타입 오기가 있다. 식·값은 이 위키의 규칙(바닐라 전수 검색)을 따른다.

### 문자열 서식 지정자(`'%.Ns'` 계열)와 바이트 폭

문자열에 서식 지정자를 곱하면 문자열의 일부를 얻는다. 위키 원문은 다음과 같다.

<Excerpt src="bedrock-wiki" title="Intro to JSON UI - Format Specifiers" path="docs/json-ui/json-ui-intro.md">

**Format Specifiers**

Assuming the variable **$var** is defined as:

```json
"$var": "abcdefghijklmn"
```

The following format specifiers can be used:

-   `%.ns`  
    Truncates the string to the first **n byte**.  
    Example: `('%.7s' * $var)` returns `abcdefg`.

-   `%0ns`  
    Returns the full string if its length is **n or more byte**, otherwise returns `0`.  
    Example:  
    `('%04s' * $var)` returns `abcdefghijklmn`  
    `('%015s' * $var)` returns `0`

-   `%n.xs`  
    Returns **x byte** from the start, padded with **leading spaces** to reach **n byte** in total.  
    Example: `('%7.4s' * $var)` returns `   abcd`.

-   `%-n.xs`  
    Returns **x byte** from the start, padded with **trailing spaces** to reach **n byte** in total.  
    Example: `('%-7.4s' * $var)` returns `abcd   `.

-   `%ns`  
    Adds **spaces to the start** to make the total length **n byte**, if needed.  
    Example: `('%15s' * $var)` returns ` abcdefghijklmn`.

-   `%-ns`  
    Adds **spaces to the end** to make the total length **n byte**, if needed.  
    Example: `('%-15s' * $var)` returns `abcdefghijklmn `.

Remember that the usage of this format is limited.

</Excerpt>

위키의 `%0ns`(길이가 n바이트 미만이면 `0`을 돌려줌)와 위의 패딩 서식 예는 이 프로젝트에서 게임 실측으로 확인하지 못했다(`미검증`). 확인된 것은 `'%.Ns'`뿐이고, 평가기 재구성(Cinnabar)도 `%.Ns` 꼴만 인식한다(EXP-09, EXP-25, 부록A C-05). 위키의 바이트 폭 설명("U+07FF 위는 3바이트")은 U+10000 이상(대부분의 이모지)이 4바이트라는 점에서 EXP-24가 더 정확하다.

## 5.0.2 이 장의 읽는 법

아래 5.1~5.7은 규칙 목록이다. 연산자 표(5.1) → 문자열 다루기(5.2) → 숫자와 타입(5.3) → 위험한 식(5.4) 순으로 읽고, 5.5~5.7은 위키·Cinnabar·실서버에서 더해진 규칙이다. 근거에 관한 주의는 5.1 머리글을 먼저 읽는다.


식은 괄호로 감싼 문자열이다. view 바인딩의 `source_property_name`(`#속성` 사용)과 변수 값·`ignored`·`requires`(`$변수` 사용)에 쓴다.

**근거에 관한 주의.** 바닐라 1.26.50.4의 식 1,467개는 `not`(993), `or`(230), `+`(200), `and`(130), `=`(132)만 쓴다. `-`, `*`, `/`, `<`, `>`, `'%.Ns'`는 바닐라에 **한 번도 없다.** 그래서 이 장의 연산자 의미는 bedrock-core의 인게임 실측과 배포된 팩(BA, AP)의 용례가 근거다. 바닐라로는 "있다/없다"를 판정할 수 없다. 2026-10-21부터는 네이티브 평가기를 재구성한 Cinnabar(`CN`)의 코드와 실행 결과(`CN-run`)도 근거로 쓴다(5.6).

## 5.1 연산자 표

| 연산 | 뜻 | 검증 |
| --- | --- | --- |
| `a = b` | 같음(문자열, 숫자, 불리언) | 바닐라 |
| `not a`, `a and b`, `a or b` | 논리 | 바닐라 |
| `a + b` | 문자열 이어 붙이기. 바인딩 문자열 + 숫자도 이어 붙었다(`'35' + 0` → `'350'`). 숫자 덧셈으로 믿지 않는다 | 바닐라, 실측 |
| `a - b` (문자열) | `a`에서 `b`의 **모든 출현을 제거** | 작동팩 |
| `a - b` (숫자) | 뺄셈. `('35' - 0)`은 숫자 35 | 실측 |
| `a * b` | 곱셈. 불리언은 1/0. 문자열 `*` 숫자는 빈 문자열(EXP-31) | 실측, 작동팩, 코드 |
| `'%.Ns' * #s` | `#s`의 앞 **N바이트** | 작동팩, 코드 |
| `a / b` | 나눗셈. 정수끼리는 정수 나눗셈(EXP-18). 문자열 `/` 문자열은 출현 횟수(EXP-32) | 실측, 코드 |
| `a > b`, `a < b` | 대소 비교. `$v > 'a'`처럼 문자열과도 씀 | 실측, 작동팩 |
| `>=`, `<=` | **없다.** 파싱 실패 → 속성이 기본값에 남음 | 실측, 코드 |
| `%` (나머지) | **없다.** `Invalid expression` assert | 실측 |
| `!=` | 출처에 없음. `(not (a = b))`로 쓴다 | 추론 |

- **[EXP-01]** 쓸 수 있는 연산자는 `=`, `<`, `>`, `not`, `and`, `or`, `+`, `-`, `*`, `/`와 문자열 자르기 `'%.Ns' *`다. 우선순위는 아래 표와 같다(CN 재구성). `&#123;실측, 작동팩, 바닐라, 코드&#125;` (출처: BC-S14, BC-facts, BC 6.2-1, AP 4.7, VN, BW-intro, CN)

| 순위 | 연산자 | 묶는 방향 |
| --- | --- | --- |
| 1(가장 강함) | 단항 `+`, `-`, `not` | 바로 뒤 피연산자에만 붙음(EXP-37) |
| 2 | `*`, `/` | 왼쪽부터 |
| 3 | `+`, `-` | 왼쪽부터 |
| 4 | `=`, `<`, `>` | 왼쪽부터. 사슬 비교 금지(EXP-28) |
| 5 | `and`, `or` | **같은 순위**, 왼쪽부터(EXP-29) |
- **[EXP-02]** `%`는 연산자가 아니다. `((#c % 10) = 3)`은 화면을 열 때마다 `Invalid expression` assert를 낸다. 커뮤니티 예제(Chest-UI 등)의 `(x - x % 65536) / 65536` 같은 식은 쓰지 않는다. `&#123;실측&#125;` (출처: BC-S14, BC-facts, MJ 4.2-7, 부록A C-06)
- **[EXP-03]** `>=`, `<=`는 없다. 실패한 식은 속성을 기본값에 남기므로 `#visible`에 쓰면 항상 참처럼 보인다. `(a > b) or (a = b)`로 쓴다(위키도 이 형태를 표준으로 적지만 실측 기록은 없다). CN 평가기에서 `<=`는 연산자 둘로 읽혀 식 전체가 null이 된다. `(not (#v < a))`도 대안이다. `&#123;실측, 코드, 추론&#125;` (출처: BC-facts, BW-intro, CN-run)
- **[EXP-04]** `<`, `>`는 동작한다. 근거는 CN 평가기와 AP의 `>` 사용, 그리고 S14에서 `<`가 든 식이 오류 없이 평가된 것이다. 다만 S14의 `962 < #c < 964`, `0.9 < (#c / 1000) < 1`이 참이었다는 결과는 **사슬 비교라 범위 검사의 근거가 되지 못한다**(EXP-28, 부록A C-41). 범위는 `((962 < #c) and (#c < 964))`로 쓴다. `<`가 `Invalid expression`이라는 이전 기록(S9)은 따르지 않는다. `&#123;실측, 작동팩, 코드, 충돌&#125;` (출처: BC-S14, BC-facts, BC-S9, AP 4.7, 부록A C-02, CN-run, 부록A C-41)
- **[EXP-05]** 괄호를 생략한 `'%.6s' * #text = 'x'`도 곱(자르기)이 비교보다 먼저 계산되어 동작했다. 그래도 괄호를 명시한다. `&#123;작동팩&#125;` (출처: AP 4.4)
- **[EXP-06]** 너무 깊은 식(`((#c + #t + (#c * #t)) = 964963)`)은 실패한다. 단계별 view 바인딩으로 나눠 중간 속성에 담는다. 다만 CN 평가기는 중첩 512단계까지 계산하므로 실패 원인은 깊이가 아니라 타입일 수 있다. `#c`, `#t`가 상자 수량이면 문자열이고(EXP-17), 문자열 `+`는 이어 붙이기다. `&#123;실측, 추론&#125;` (출처: BC-S14, CN-run)

## 5.2 문자열 다루기

- **[EXP-07]** **포함 검사**: `(not ((#s - 'X') = #s))`. `X`가 들어 있으면 지운 결과가 원래와 달라진다. 위치와 무관해서 필드 경계를 계산할 필요가 없다. `&#123;작동팩&#125;` (출처: BA 2장·3.3, AP 4.1, BW-form, BW-title)
- **[EXP-08]** **접두사 검사**: `(('%.Ns' * #s) = 'X')`, N은 X의 바이트 길이. 짧은 플래그(`t`/`f`)는 **길이+1**로 잘라 비교해야 `f`로 시작하는 긴 값이 오인되지 않는다: `(('%.2s' * #v) = 'f')`. `&#123;코드, 작동팩&#125;` (출처: BC 4.1-(4), BC 6.2-2, AP 4.4)
- **[EXP-09]** `'%.Ns'`는 **UTF-8 바이트** 단위로 자른다. 한글은 3바이트, 영문·숫자는 1바이트다. 고정 폭 필드의 패딩과 자르기는 바이트 기준으로 계산한다. "문자 단위"라는 주장은 틀렸다. `%5.3s`, `%-5.3s` 같은 패딩 서식은 외부 문서만 있고 실측이 없다. `§`는 2바이트, 대부분의 이모지는 4바이트다(EXP-24). 위키가 적은 패딩 서식은 EXP-25를 본다. CN 평가기는 `%.Ns`만 인식하고 `%5.3s`는 자르지 않는다(부록A C-05). `&#123;코드, 작동팩, 충돌&#125;` (출처: BA 3.1 `utf8Length` 인코더, MJ 4.2-9, 부록A C-05, BW-intro, CN-run)
- **[EXP-10]** `'%.Ns' * X`는 `X`가 문자열 **리터럴이면 자르지 않는다.** 바인딩(`#…`)이나 바인딩을 포함한 식(`('%.7s' * (#text - ('%.6s' * #text)))`)에는 된다. CN 평가기는 리터럴도 자른다(`('%.3s' * 'abcdef')` → `'abc'`). 연산자 문제가 아니라 `#`가 없는 바인딩 식은 바인딩이 되지 않는 규칙(BND-05) 때문일 가능성이 크다(부록A C-42). `&#123;실측, 작동팩, 충돌&#125;` (출처: BC-facts, AP 4.5, CN, 부록A C-42)
- **[EXP-11]** **N바이트 뒤 L바이트 꺼내기**는 세 단계로 한다. `&#123;작동팩&#125;` (출처: BA 3.2, AP 4.5)

```json
{ "binding_type": "view", "source_property_name": "('%.210s' * #form_button_text)",   "target_property_name": "#head" },
{ "binding_type": "view", "source_property_name": "(#form_button_text - #head)",       "target_property_name": "#rest" },
{ "binding_type": "view", "source_property_name": "('%.120s' * #rest)",                "target_property_name": "#raw"  },
{ "binding_type": "view", "source_property_name": "(#raw - '$')",                      "target_property_name": "#field" }
```

- **[EXP-12]** 문자열 `-`는 **모든 출현**을 지운다. 그래서 패딩 문자(`$` 등)와 예약 문자는 본문에 나오면 안 되고, 인코더가 미리 제거해야 한다. 같은 이유로 `(#s - #head)`는 `#head`와 같은 문자열이 뒤에 또 있으면 그것까지 지운다. 머리 부분은 충분히 길고 고유하게 만든다. `&#123;작동팩, 추론&#125;` (출처: BA 3.2, AP 4.5)
- **[EXP-13]** 앞 N바이트만 지우는 트릭 `(('@' + s) - ('@' + ('%.3s' * s))) - '@'`은 출처에 실측이 없다. 쓰려면 마지막 `- '@'`가 본문의 `@`도 지운다는 점을 감안해 본문에 없는 문자를 고른다. `&#123;미검증&#125;` (출처: MJ 8장-6)
- **[EXP-14]** 포함 검사 토큰에는 **종결자**를 붙이고(`name.1b;`), 토큰끼리 접두·접미 관계가 생기지 않게 설계한다. `X.1b;`는 `aX.1b;`에도 걸린다. 대문자 그룹 + 소문자 비트(`~Fo`, `~Xa`)처럼 짜면 서로 접두 관계가 없다. `&#123;작동팩&#125;` (출처: AP 4.1, BA 3.3)

## 5.3 숫자와 타입

- **[EXP-15]** 엔진은 식 결과의 타입을 **생김새로** 정한다. 숫자처럼 생긴 문자열(`'0'`, `'3/17'`, `'12'`)은 숫자가 되어 문자열 비교가 틀어진다. 숫자로 해석되면 안 되는 값에는 글자 접두를 붙인다: 플래그는 `t`/`f`, 탭 번호 `Ta`, 진행도 `§f3/17`, 퍼센트 `P050`. 영문이 섞인 문자열(`'a123'`)은 산술을 해도 숫자가 되지 않는다. 원인: 연산 결과 문자열은 다시 해석된다(EXP-30). `&#123;코드, 작동팩&#125;` (출처: BC 4.1-(4), BA 3.1, BW-type, CN-run)
- **[EXP-16]** 문자열을 숫자로 바꾸는 확실한 방법은 `(#v - 0)`이다. `(#v + 0)`은 이어 붙이기(`'350'`)가 된다. `(#v * 1)`은 쓰지 않는다: S12(2026-09-17)에서 0을 냈고, Cinnabar 재구성 평가기에서도 문자열 `*` 숫자는 빈 문자열이다(EXP-31). 여러 작동팩(BA 진행률, AP 아이템 ID)과 S9(2026-09-14)가 `* 1`로 동작한 것은 피연산자가 이미 숫자였기 때문일 가능성이 크다(`'%.3s'`로 자른 `'042'`는 곧바로 정수 42, EXP-30). Bedrock Wiki가 2026-10-05에 적은 "어느 버전부터 `* 1` 변환이 동작하지 않는다"는 버전 변화 설명은 보조 가설로 남긴다. 옛 팩의 `* 1` 식은 최신 버전에서 다시 확인한다. 위키가 대안으로 적은 `(0 + #v)`는 CN 모델에서 동작하지만 게임 실측은 없다. `&#123;실측, 작동팩, 코드, 추론&#125;` (출처: BC-S12, BC-S9, BC-facts, BA-원본, AP 4.5, 부록A C-04, BW-type, CN-run)
- **[EXP-17]** 상자 슬롯의 `#inventory_stack_count`는 식 안에서 **문자열**이고 산술로도 숫자가 되지 않는다. `(#count = '19')`만 참이다. 바닐라처럼 `text`에 직접 바인딩해도 표시되지 않는다(그래서 TXT-12의 lang 키 우회가 필요하다). CN 평가기 모델에서는 `((#count - 0) = 19)`가 참이므로 "산술로도 숫자가 되지 않는다"가 `- 0`에도 해당하는지는 확인이 필요하다. `&#123;실측&#125;` (출처: BC-facts, CN-run)
- **[EXP-18]** 산술은 정수 중심이다. **앞자리가 있는 소수 리터럴은 정수다**(EXP-27): `0.3`은 0, `0.001`은 0이라서 `((#v = #v) * 0.3)`은 0, `(#t * 0.001) = 1`은 거짓이었다. 실수 리터럴은 `.3`처럼 점으로 시작한다. 정수끼리의 나눗셈 `(#v / 100)`·`(#v / 100.0)`도 정수이므로, 정수에서 `#clip_ratio` 같은 0~1 값을 만들려면 `(#v * .01)`을 쓴다(부록A C-16). S14의 `0.9 < (#c / 1000) < 1` 참은 사슬 비교(EXP-28)라 소수 나눗셈의 근거가 되지 못한다. `&#123;실측, 코드&#125;` (출처: BC-S12, BC-S14, BA-원본, 부록A C-16, CN, CN-run)
- **[EXP-19]** 불리언은 산술에서 `true` 1, `false` 0이다. `((#mode = 'on') * 1)`로 팩토리 길이 0/1을 만든다. `&#123;실측&#125;` (출처: BC-facts, BC-S11, BW-type)
- **[EXP-20]** 바닥(floor)·나머지 연산이 없으므로 여러 필드를 숫자 하나에 묶었다가 다시 나눌 수 없다. 값은 통째로 비교하거나 범위로 비교한다. 여러 값은 문자열 필드나 여러 채널로 나눠 보낸다. `&#123;실측&#125;` (출처: BC-S14)

## 5.4 클라이언트를 죽이는 식

- **[EXP-21]** `(#count / 19)`와 `('' + #count)`를 함께 쓴 상자 화면이 열자마자 클라이언트를 종료시켰고, 둘을 빼자 정상이었다. 둘 중 어느 것이 원인인지는 분리되지 않았다. 바닐라는 `(not (#texture = ''))`처럼 빈 문자열 **비교**를 쓰므로 비교는 안전하다. 문자열에 나누기를 하지 말고, 이어 붙일 때는 `('n=' + #x)`처럼 비어 있지 않은 접두를 쓴다. `&#123;실측, 바닐라, 충돌&#125;` (출처: BC-facts, BC-S14, VN server_form.json:159, 부록A C-13)
- **[EXP-22]** 문자열 + 정수는 이어 붙여지지만 **문자열 + float은 아무것도 나오지 않는다.** float을 글자로 보여 주려면 비교 사슬로 구간을 나누거나 정수 채널로 보낸다. 값의 범위를 알면 `(0 + (#f > 0) + (#f > 1) + … + (#f > 9))`처럼 비교 결과를 더해 정수부를 구할 수 있다. 원인: 실수 값의 "글자"가 비어 있다(CN). 리터럴 `1.5`는 정수 1이라 `('n=' + 1.5)`는 `'n=1'`이다(EXP-27). `&#123;실측, 코드&#125;` (출처: BC-facts, BW-type, CN-run)
- **[EXP-23]** 염색 가능한 커스텀 아이템의 `#item_custom_color`는 부호 있는 ARGB 정수다(`0x123456` → `-15584170`). RGB 값으로 비교하면 맞지 않는다. `&#123;실측&#125;` (출처: BC-S14)

## 5.5 Bedrock Wiki 대조로 더한 규칙

위키(BW) 문서를 바닐라 1.26.50.4와 대조해 더한 규칙이다. 위키 문장만 있는 것은 `미검증`, 위키의 게임 스크린샷이 있는 것은 `실측`(제3자 기록)으로 표시했다.

- **[EXP-24]** UTF-8 바이트 수: U+0000~U+007F 1바이트(영문·숫자), **U+0080~U+07FF 2바이트(`§` 포함)**, U+0800~U+FFFF 3바이트(한글, 사설 영역 글리프), U+10000 이상 4바이트(대부분의 이모지). 색 코드가 든 제목을 접두사 검사(EXP-08)할 때 `§a` 하나가 3바이트라는 점을 넣어 N을 센다. 멀티바이트 글자 중간에서 자르면 그 글자는 그려지지 않는다. `&#123;코드, 미검증&#125;` (출처: BW-intro, UTF-8 규격, 부록A C-35)
- **[EXP-25]** 위키가 문서화한 서식 지정자: `'%.Ns'`(앞 N바이트), `'%N.Ms'`(앞 M바이트를 앞쪽 공백으로 N바이트까지 채움), `'%-N.Ms'`(뒤쪽 공백), `'%Ns'`·`'%-Ns'`(공백 채움만). C `printf`와 같은 의미다. 이 프로젝트 출처에서 동작이 확인된 것은 `'%.Ns'`뿐이므로, 고정 폭 필드의 패딩은 지금처럼 인코더(스크립트)가 하고 UI는 자르기만 한다. CN 평가기는 `%.Ns` 꼴만 인식하고 `'%5.3s'`에는 오른쪽 문자열을 통째로 돌려준다. `&#123;미검증, 충돌&#125;` (출처: BW-intro "Format Specifiers", 부록A C-05, CN-run)
- **[EXP-26]** 문자열 빼기로 숫자만 남긴 결과는 그대로 숫자로 쓸 수 있었다: 타이틀 `Count:3`에 `(#count - 'Count:' + 0)`을 `#collection_length`에 넣으면 3개, `Count:15`를 `#maximum_grid_items`에 넣으면 15개가 생겼다. 바인딩 원본 문자열에 `+ 0`을 하면 이어 붙여진다는 S12(`'35' + 0` → `'350'`)와 다르므로, **식의 중간 결과는 생김새로 타입이 다시 정해진다**(EXP-15)는 사례로 본다. 확실히 하려면 `((#count - 'Count:') - 0)`으로 쓴다. `&#123;실측, 추론&#125;` (출처: BW-dyn 스크린샷 2장, BC-S12)

## 5.6 Cinnabar 엔진 재구성으로 더한 규칙

Cinnabar(`CN`)는 26.30 네이티브 클라이언트의 JSON UI 해석기를 재구성한 Rust 코드다. 수준은 `코드`이고, `CN-run`은 이 프로젝트가 그 평가기를 직접 실행한 결과다. 게임 실측과 다르면 실측을 따른다(부록A C-41~C-47).

- **[EXP-27]** **앞자리가 있는 소수 리터럴은 정수다.** `0.3`, `1.0`, `100.0`은 0, 1, 100이다. 실수 리터럴은 `.3`, `.01`처럼 점으로 시작한다. 정수끼리 나눗셈은 정수다. 비율은 `(#v * .01)`로 만든다. `&#123;코드, 실측&#125;` (출처: CN, CN-run, BC-S12 `* 0.3` → 0)
- **[EXP-28]** **비교를 사슬로 쓰지 않는다.** `(a < #v < b)`는 `((a < #v) < b)`라서 항상 참(또는 항상 거짓)이다. `((a < #v) and (#v < b))`로 쓴다. `&#123;코드&#125;` (출처: CN-run)
- **[EXP-29]** `and`와 `or`는 우선순위가 같고 왼쪽부터 계산한다. `a or b and c`는 `(a or b) and c`다. 섞을 때는 괄호를 쓴다. `&#123;코드&#125;` (출처: CN 테스트 E12)
- **[EXP-30]** 연산 결과 문자열은 다시 해석된다. 숫자처럼 시작하면 앞쪽 정수(`'3/17'` → 3, `'10 apples'` → 10), `yes`·`no`·`true`·`false`면 불리언, `#`로 시작하면 속성 이름이다. 그래서 `('%.3s' * #s)`로 자른 `'042'`는 곧바로 정수 42다. `&#123;코드&#125;` (출처: CN-run)
- **[EXP-31]** 문자열 `*` 숫자는 빈 문자열, 숫자 `*` 문자열은 왼쪽 숫자다. `(#s * 1)`과 `(1 * #s)`는 숫자 변환이 아니다. 변환은 `(#s - 0)` 또는 `(0 + #s)`다. `(#s + 0)`은 뒤에 0을 붙인다. `&#123;코드&#125;` (출처: CN-run, EXP-16과 같은 결론)
- **[EXP-32]** 문자열 `/` 문자열은 출현 횟수다(`('a-b-a' / 'a')` = 2). 문자열 `/` 숫자는 항상 1이다. 0으로 나누면 왼쪽 값이 그대로 남는다. `&#123;코드&#125;` (출처: CN-run)
- **[EXP-33]** 숫자 문자열에서 `- '0'`은 모든 `0`을 지운다(`'100'` → 1). 숫자로 바꿀 때는 따옴표 없는 `- 0`을 쓴다. `&#123;코드&#125;` (출처: CN-run)
- **[EXP-34]** 문자열과 숫자를 `=`로 비교하면 둘 다 거짓값('' 와 0)일 때만 참이다. `('2' = 2)`는 거짓, `(true = 'true')`도 거짓이다. 비교 전에 한쪽 타입을 맞춘다. `&#123;코드&#125;` (출처: CN 테스트 E15)
- **[EXP-35]** 괄호 묶음의 결과가 `'#이름'` 문자열이면 그 컨트롤 주머니의 값으로 바뀐다. 그래서 `(('#route_' + #id) = 'x')`처럼 사전 조회 결과를 같은 식 안에서 비교할 수 있다. `&#123;코드&#125;` (출처: CN-run, COL-23 보강)
- **[EXP-36]** 토큰은 공백, 괄호, `$`, `* + - / < = >`에서만 끊긴다. 속성 이름에 `-`를 쓰면 뺄셈이 되므로 `_`를 쓴다. `:`, `.`은 이름에 써도 된다. `&#123;코드&#125;` (출처: CN 테스트 E05)
- **[EXP-37]** 문자열 단항 `-`는 0이다(`(-#s)` → 0). 단항 `-`, `not`은 바로 뒤 피연산자에만 붙으므로 `(not #a = #b)`는 `((not #a) = #b)`다. `&#123;코드&#125;` (출처: CN-run, CN 테스트 E08)

**바로 쓰는 결론** (CN-run 기준, 게임 실측은 부록A A.3)

| 하고 싶은 것 | 쓰는 식 | 피할 식 |
| --- | --- | --- |
| 문자열 바인딩을 숫자로 | `(#v - 0)` | `(#v * 1)`(빈 글자), `(#v + 0)`(뒤에 0이 붙음), `(1 * #v)`(1) |
| 소수 곱하기 | `(#v * .3)`, `(#v * .01)` | `(#v * 0.3)`(정수 0), `(#v / 100.0)`(정수 나눗셈) |
| 범위 검사 | `((a < #v) and (#v < b))` | `(a < #v < b)`(항상 참) |
| 크거나 같음 | `((#v > a) or (#v = a))`, `(not (#v < a))` | `>=`, `<=` |
| 같지 않음 | `(not (#a = #b))` | `!=` |
| 문자열과 숫자 비교 | `((#s - 0) = 35)` | `(#s = 35)`(거짓) |
| 앞 N바이트 | `('%.Ns' * #s)` | `'%5.3s'` 등 다른 서식(자르지 않음) |

## 5.7 연구 서버 서버 실측으로 더한 규칙

연구 서버 서버(`DF`)를 만들며 Windows 1.26.52 에서 실측한 것이다. 서버 폼 하나로 여러 화면을 그리는 구조에서 얻었다.

- **[EXP-44]** 잘라낸 앞부분이 숫자로 시작하면 숫자로 읽힌다(EXP-30, 게임에서도 같다): 본문 `042§r§r§r…`에서 `(#form_text - ('%.12s' * #form_text))`는 본문을 지우지 못하고 깨졌다. 숫자 필드는 글자 뒤에 둔다(`§r§r§r042`). `&#123;실측&#125;` (출처: DF)
- **[EXP-45]** 서버가 본문 앞 12바이트에 칸 수를 `§r§r§r` + 세 자리 숫자로 쓰면 `((('%.12s' * #form_text) - '§r') - 0)` 한 식으로 숫자를 꺼내 `#maximum_grid_items`에 넣을 수 있다. 숫자 글자 하나(`'3'`)를 글자와 `=`로 비교하면 맞지 않았고(EXP-34), 글자 a~f로 바꾸면 맞았다. 본문 라벨은 `(#form_text - ('%.12s' * #form_text))`로 이 12바이트를 뺀다. `&#123;실측&#125;` (출처: DF)
- **[EXP-46]** `%`가 든 식 `(#t - (#t % 65536))`을 `#item_id_aux`에 오래 두었는데 아이템 아이콘은 그려졌고 릴리스 클라이언트의 콘텐츠 로그에 `Invalid expression`도 남지 않았다(EXP-02의 assert는 개발 빌드 기록). `(#t - 0)`으로 바꾼 뒤 폼이 빨라졌다는 체감 보고가 있었지만 재지는 않았다. `&#123;실측, 추론&#125;` (출처: DF)

## 5.8 Cinnabar 평가기 실행 결과(CN-run)

이 절은 Cinnabar(`jb-cinnabar`)가 재구성한 식 평가기를 직접 빌드해 실행한 결과표다. 값은 **게임 실측이 아니다.** 분석 기준 커밋은 `ceb0fb6`(2026-10-21)이고 `crates/json-ui`를 빌드해 시험 코드로 얻었다. 게임과 다르면 게임 실측을 따른다.


2026-10-21, Cinnabar `ceb0fb6`의 `crates/json-ui`를 이 컨테이너에서 빌드해 `probe/`의 테스트로 얻은 값이다. **게임 실측이 아니다.** Cinnabar가 26.30 네이티브 클라이언트를 재구성한 평가기의 답이며, 게임과 다를 수 있다.

바인딩 값: `#s`=문자열 `"35"`, `#z`=`"100"`, `#c`·`#n`=정수 10, `#i`=정수 50, `#f`=실수 2.5, `#t`=true, `#x`=`"hello"`, `#r`=`"042x"`, `#k`=`"3/17"`, `#missing`=없음.
결과 표기: `Int` 정수, `Num` 실수, `Text` 문자열, `Bool` 불리언, `Json(Null)` 잘못된 식(null).

#### 5.8.1 바인딩 식 결과표

| 식 | 결과 | 뜻 |
| --- | --- | --- |
| `(962 < #c < 964)` | `Bool(true)` | **사슬 비교는 범위 검사가 아니다.** `(962 < #c)`가 불리언이 되고 `불리언 < 964`는 항상 참 |

## 5.9 AsaJS의 식 컴파일러에서 배운 기법(ASJ)

AsaJS(`jb-asajs`, GPL-3.0-only, `main` `9f884dc`)는 TypeScript로 팩을 만드는 프레임워크다. 이 위키에 의미 있는 것은 `==`, `!=`, `>=`, `%`, 삼항 `?:` 같은 고급 식을 엔진이 아는 연산자와 보조 view 바인딩으로 바꾸는 **식 컴파일러**다. 이 절은 기법을 한국어로 다시 설명한 것이고 코드는 옮기지 않았다. 표기: `[확인]` 코드에서 직접 확인, `[추론]` 판단, `[미검증]` 게임 확인 필요(AsaJS를 실행하지는 않았다).

#### ASJ 3. 바인딩 식 컴파일러 [확인]

`source_property_name`이 `[`와 `]`로 감싸져 있으면 컴파일 대상이다. 결과는 원래 바인딩 하나와 그 **앞에** 붙는 보조 view 바인딩들(대상 속성 이름은 무작위 `#…`)이다. 보조 바인딩이 먼저 나오므로 같은 컨트롤 안에서 계산 순서가 지켜진다.

##### ASJ 3.1 연산자 변환표

| AsaJS 문법 | 내보내는 JSON UI 식 | 가이드 판정 |
| --- | --- | --- |
| `a == b` | `(a = b)` | 맞음 |
| `a != b` | `(not (a = b))` | EXP-03·5장 표와 맞음 |
| `a >= b`, `a <= b` | `((a > b) or (a = b))`, `((a < b) or (a = b))` | EXP-03과 맞음 |
| `a && b`, `a \|\| b` | `(a and b)`, `(a or b)` (매번 괄호) | 같은 순위 문제(EXP-29)를 괄호로 피함 |
| `-a`, `!a` | `(0 - a)`, `(not a)` | 단항 `-`를 이항으로 바꿔 문자열 단항 `-`=0 문제(EXP-37)는 그대로 |
| `a % b` | 보조 바인딩 `#r = (a - (a / b * b))`, 본식에는 `#r` | 정수 나눗셈 전제(4.1). EXP-20과 충돌 |
| `c ? x : y` | 문자열 트릭(3.3) | **괄호 불일치로 깨짐** |
| `f'안녕 #{#name}!'` | `('안녕 ' + #name + '!')` | 문자열 `+` 이어 붙이기 |
| `0x1F`, `0b101`, `0o17` | 10진수로 바꿈 | 맞음 |
| `1e3`, `1e-2` | `1000`, **`0.01`** | `0.01`은 엔진에서 정수 0(EXP-27) |
| `0.5`, `.5` | 렉서 오류(소수점을 숫자로 읽지 않음) | 실수 리터럴을 쓸 방법이 없음 → `#clip_ratio`용 `(#v * .01)`을 이 문법으로 못 씀 |
| `a < b < c` | `((a < b) < c)` 그대로 | 사슬 비교(EXP-28)를 막지 않음 |

`source_control_name`이 있는 바인딩에서는 식 안의 `#속성`마다 "그 컨트롤에서 이 속성 하나를 읽어 오는" 보조 view 바인딩을 따로 만들고, 식은 자기 컨트롤에서 계산한다. 다른 컨트롤의 값 여러 개를 섞는 식을 안전하게 만드는 방법이다(BND-24, BND-10과 같은 방향).

##### ASJ 3.2 함수

| 함수 | 만드는 식(이 문서의 기호) | 비고 |
| --- | --- | --- |
| `abs(x)`, `negabs(x)` | `((-1 + (x > 0) * 2) * x)` | 불리언 산술(EXP-19). 숫자에만 맞음 |
| `cache_value(c, o, r)` | `((r * c) + ((not r) * o))` | 불리언 곱으로 값 고르기. 문자열이면 빈 글자(EXP-31) |
| `contains(s, t)` | `not ((s - t) = s)` | EXP-07과 같음 |

| `starts_with(#s, #p)` | 보조 `#a = (P + #s)`, `#b = (P + #p)`, 본식 `not ((#a - #b) = #a)`. `P`는 `'asajs:<무작위5>:'` | **새 기법**(4.2) |
| `str_slice(#s, i, j)` | 보조 `#t = (P + #s)`, 서식 `('%.' + (len(P) + i) + 's')`로 머리 잘라 빼기 | 런타임 서식 문자열(4.3) |

| `new(식)`, `int(식)` | 식을 보조 바인딩 하나로 뺌 | 리터럴만 넣으면 BND-05에 걸림 |

파서 안에는 정수를 30개 비트 바인딩으로 푸는 `intToBin`도 있다(사용자 함수 `bin`은 주석 처리) [확인].

##### ASJ 3.3 삼항 연산자의 결함

`c ? x : y`는 조건을 `((0 + c) > 0)`으로 불리언 바인딩 `#L`에 담고, `x`, `y`도 각각 보조 바인딩 `#M`, `#R`에 담은 뒤 "참 쪽"과 "거짓 쪽" 문자열을 더한다. 생각은 이렇다: `('prefix' + #L + #M)`은 참이면 `prefixtrue…`, 거짓이면 `prefixfalse…`이므로, 거짓일 때만 생기는 문자열을 빼고 다시 `'prefixtrue'`를 빼면 참일 때만 `#M`이 남는다. 그런데 생성 문자열의 괄호 수가 맞지 않는다. 이 조사에서 같은 문자열을 Python으로 다시 만들어 세어 보니 최종 식은 여는 괄호 8개, 닫는 괄호 10개였다 [확인]. `dev` 브랜치도 같다. 게임에서는 식 파싱 실패로 대상 속성이 기본값에 남을 것이다(EXP-03과 같은 실패 양상) [추론]. 또한 세 피연산자가 모두 `#`를 포함해야 하고, 결과는 문자열이다(숫자처럼 생기면 EXP-30에 따라 다시 숫자가 됨).

#### ASJ 4. 새 기법 상세

##### ASJ 4.1 정수 나눗셈으로 나머지·비트 만들기 [코드, 추론, 미검증]

- 나머지: `(a - (a / b * b))`. `*`와 `/`는 같은 순위에서 왼쪽부터이므로 `a / b * b`는 `(a / b) * b`다(EXP-01 표).
- 비트 i: `((x / 2^i) - ((x / 2^(i+1)) * 2))`. AsaJS는 i=0..29에 대해 바인딩 30개를 만든다.
- 전제: 두 피연산자가 **정수**여야 한다. 가이드 EXP-18(실측 S12, CN 코드)은 정수끼리 나눗셈이 정수라고 한다. 그렇다면 EXP-20의 "바닥·나머지 연산이 없으므로 숫자 하나에 여러 필드를 묶었다가 나눌 수 없다"는 **`%` 연산자가 없다**는 뜻으로 좁혀야 한다.
- 함정: 컬렉션·타이틀 문자열은 식 안에서 문자열이다. 문자열 `/` 숫자는 1이다(EXP-32). AsaJS는 변환을 넣지 않으므로 문자열 바인딩에 `%`를 쓰면 틀린 값이 나온다. 직접 쓸 때는 `((#v - 0) - (((#v - 0) / 10) * 10))`처럼 먼저 `- 0`으로 숫자를 만든다(EXP-16).
- 음수: 엔진이 0 쪽으로 버리는 나눗셈이면 C의 `%`와 같은 부호(−7 % 3 = −1)가 된다 [추론].

##### ASJ 4.2 고유 접두로 시작 검사·자르기 [코드, 미검증]

`#p`의 길이를 컴파일 시점에 모르면 `'%.Ns'`(EXP-08)를 쓸 수 없다. 둘 다 앞에 다른 곳에 나올 수 없는 접두 `P`를 붙이면, `(P + #s)`에서 `(P + #p)`를 뺐을 때 결과가 바뀌는 경우는 `#s`가 `#p`로 시작할 때뿐이다(빼기는 모든 출현을 지우지만 `P`가 고유하므로 출현은 맨 앞 하나뿐). 같은 원리로 `P`를 붙인 문자열의 앞부분을 잘라 빼면, 잘라 낸 머리가 본문 뒤쪽에 또 있어도 지워지지 않는다(EXP-12의 문제 해결). `P`는 본문에 절대 나오지 않는 문자열이어야 한다.

##### ASJ 4.3 런타임 서식 문자열 [코드, 작동팩(SLB), 미검증]

`('%.' + (len(P) + #i) + 's')`처럼 서식 문자열 자체를 이어 붙여 만든다. StarLibV2는 같은 형태를 `$from`/`$to` 변수로 쓴다. 숫자 + 문자열 이어 붙이기가 `'%.12s'` 같은 문자열을 만들어야 하므로 `+`의 이어 붙이기 동작(5.1 표)에 기댄다. 이 프로젝트 출처에 게임 기록은 없다.

##### ASJ 4.4 자기 참조 view 바인딩으로 반복 [코드, 미검증]

`strlen`은 "카운터 = 0(원본이 바뀔 때)"과 "카운터 = 카운터 + (아직 다 안 셌으면 1)" 두 바인딩을 같은 대상에 건다. 매 평가마다 첫 바인딩도 다시 실행된다면 카운터는 0이나 1에 머문다. 이 설계는 **view 바인딩이 자기 원본 값이 바뀔 때만 다시 쓰고, 사슬은 수렴할 때까지 돈다**는 동작(Cinnabar 재구성 CN-36)을 전제한다. 첫 바인딩의 원본에 `(0 * (#s = 'a'))`처럼 `#s`를 넣는 것도 "`#s`가 바뀔 때만" 초기화되게 하려는 장치다. 반복 횟수 상한·프레임당 처리량은 확인되지 않았다. 게임에서 확인하기 전에는 가이드 레시피로 쓰지 않는다.

##### ASJ 4.5 의존성 미끼 [코드, 미검증]

`((#bait - #bait) + v)`는 값은 `v`지만 `#bait`가 바뀔 때마다 다시 평가된다(4.4 전제). 숫자 미끼면 `0 + v`, 문자열 미끼면 `'' + v`라서 결과 타입이 미끼 타입에 따라 달라진다(문자열 + 숫자는 이어 붙이기).

### 5.9.1 반영안(미적용)

아래는 AsaJS 분석이 가이드에 넣자고 제안한 규칙과 충돌이다. 가이드 본문(5.1~5.7)에는 **아직 적용되지 않았으므로** 제안 번호 그대로 적고, 쓰기 전에 게임에서 확인한다. 병합 기록상 최종 번호는 달라질 수 있다.


- **[EXP-38]** 나머지는 `%` 대신 정수 나눗셈으로 만든다: `(a - ((a / b) * b))`. 두 피연산자가 정수일 때만 맞으므로 문자열 바인딩은 먼저 `(#v - 0)`으로 바꾼다(문자열 `/` 숫자는 1, EXP-32). 계산은 보조 view 바인딩 하나에 담아 재사용한다. `&#123;코드, 추론&#125;` (출처: ASJ 3.1·4.1, CN EXP-18)
- **[EXP-39]** 정수에서 비트 i를 꺼내려면 `((#v / 2^i) - ((#v / 2^(i+1)) * 2))`(2의 거듭제곱은 숫자로 미리 계산해 적는다)를 비트마다 보조 바인딩으로 둔다. PAT-06의 비트 토큰을 문자열 대신 숫자 하나로 보낼 수 있다. `&#123;코드, 추론&#125;` (출처: ASJ 4.1)
- **[EXP-40]** 길이를 모르는 두 런타임 문자열의 시작 검사: 본문에 나오지 않는 고유 접두 `P`를 둘 다에 붙여 보조 바인딩 `#a = (P + #s)`, `#b = (P + #p)`를 만들고 `(not ((#a - #b) = #a))`로 판정한다. 앞부분을 잘라 낼 때도 `P`를 붙인 문자열에서 자르면 같은 머리가 뒤에 있어도 지워지지 않는다(EXP-12 보완). `&#123;코드, 추론&#125;` (출처: ASJ 3.2·4.2)
- **[EXP-41]** 숫자 둘 중 하나를 조건으로 고를 때는 `((#c * #a) + ((not #c) * #b))`, 부호는 `((-1 + ((#x > 0) * 2)) * #x)`로 절댓값을 만든다. 불리언 산술(EXP-19)에 기대며 문자열 피연산자에는 쓰지 않는다(EXP-31). `&#123;코드, 추론&#125;` (출처: ASJ 3.2)
- **[BND-30]** 같은 대상에 "초기화"와 "자기 자신 + 증가" 두 view 바인딩을 걸어 반복 계산(문자열 길이 세기, 뉴턴 제곱근)하는 생성기가 있다. view 바인딩이 원본이 바뀔 때만 다시 쓰고 사슬이 수렴할 때까지 돈다(CN-36)는 전제가 필요하다. 반복 상한과 프레임당 처리는 확인되지 않았으므로 레시피로 쓰지 않는다. `&#123;코드, 미검증&#125;` (출처: ASJ 4.4, CN-36)
- **[DBG-23]** 식 컴파일러가 만든 JSON은 5장 규칙으로 다시 검사한다. AsaJS 4.2.0에서 확인된 문제: 삼항 `?:` 출력의 괄호 불일치, 지수 리터럴(`1e-2`)이 `0.01`(정수 0)로 나감, 리터럴만 든 보조 바인딩(BND-05), 문자열 바인딩에 `%` 적용(EXP-32), 사슬 비교 미검사(EXP-28), 소수점 리터럴을 쓸 수 없음. `&#123;코드&#125;` (출처: ASJ 3.1·3.3·5장)


**기존 규칙 보강안(미적용)**


- **EXP-20**: "바닥·나머지 **연산자**가 없다"로 고치고 EXP-38을 참조로 단다. 정수 나눗셈이 정수라는 EXP-18과 함께 읽으면 나머지·비트 분해는 식으로 만들 수 있다(충돌 C-48).

## 5.10 StarLibV2의 범위 꺼내기와 탭 패딩(SLB)

StarLibV2(`jb-starlibv2`, GPL-3.0, `6bf7875`)는 서버 폼 버튼 문자열을 필드로 쓰는 라이브러리다. 식에 관한 부분만 옮긴다(키 게이트와 2차원 배치는 컬렉션과 팩토리 장, 검색 필터는 입력 장). 코드는 옮기지 않고 기법만 다시 적었다.

#### SLB 5. 범위 꺼내기와 탭 패딩 [확인]

`range_selection_binding`은 `$from`, `$to`(바이트 위치 숫자)를 받아 다음 순서로 계산한다.

1. `('%.' + $to + 's')`로 서식 문자열을 만들어 앞 `$to`바이트를 자른다.
2. 같은 방식으로 앞 `$from`바이트를 잘라 1에서 뺀다.
3. 남은 조각에서 탭 문자(`'\t'`, JSON 문자열 안의 이스케이프)를 모두 지운다.
4. 결과가 빈 문자열이면 숨긴다.

- `$from`, `$to`는 생성 시점에 숫자로 치환되고, 서식 문자열 조립(`'%.' + 10 + 's'`)은 식 안에서 일어난다. 같은 형태를 AsaJS도 쓴다( 4.3).
- 패딩 문자로 탭을 고른 것은 EXP-12(빼기는 모든 출현을 지움)를 피하려는 선택이다. 본문에 탭이 나올 일은 거의 없고 화면에도 보이지 않는다. 가이드의 `$` 패딩(HOST-08)과 같은 역할이다.
- 2단계의 빼기는 머리 문자열이 본문 뒤쪽에 또 있으면 그것도 지운다(EXP-12). 고정 폭 레코드라면 머리가 충분히 길어 실제 문제는 드물다.
- GrimUI는 이 방식으로 버튼 하나에 "기본 글", "옆 글", "제목", "배경 글", "팁" 다섯 구간을 싣는다(`range_controls`).


### 5.10.1 반영안(미적용)



- **[EXP-43]** 서식 문자열은 식 안에서 이어 붙여 만들 수 있다: `(('%.' + $to + 's') * #t)`. 바이트 구간 `[from, to)`는 `((('%.' + $to + 's') * #t) - (('%.' + $from + 's') * #t))`로 꺼낸다. 앞 조각이 뒤에 또 나오면 함께 지워지므로(EXP-12) 머리는 고유하게 만든다. `&#123;작동팩, 코드, 미검증&#125;` (출처: SLB 5장, ASJ 4.3)
- **[HOST-34]** 고정 폭 필드의 패딩 문자로 **탭**(`\t`)을 쓰면 본문과 겹칠 일이 거의 없고, 꺼낸 뒤 `(조각 - '\t')`로 지운다. `$` 같은 보이는 문자를 쓰는 HOST-08의 대안이다. `&#123;작동팩&#125;` (출처: SLB 5장)


## 5.11 타입 변환 예제(Bedrock Wiki 원문과 이 프로젝트의 판정)

위키의 "Type Conversion" 문서(CC BY 4.0)는 문자열과 숫자의 변환을 예제로 보인다. 아래 원문의 `(#str * 1)`은 이 프로젝트에서 **동작하지 않았다**(EXP-16, EXP-31). 위키도 첫 예제 아래에서 "어느 버전부터 `#str * 1`과 `#str * #float` 변환이 동작하지 않지만 `0 + #str`은 된다"고 적는다. 대신 `(#str - 0)`을 쓴다. 숫자를 문자열로 바꾸는 `('Result: ' + #num)`은 정수에서만 동작하고 float은 아무것도 내지 않는다(EXP-22). 불리언을 숫자로 쓰는 산술(`true` 1, `false` 0)은 EXP-19다.

<Excerpt src="bedrock-wiki" title="Type Conversion (String to Number)" path="docs/json-ui/type-conversion.md">

**String to Number**

The following code will create a label that will contain a string data at which will get turned into number.

```json
"label": {
    "type": "label",
    "text": "#text",
    "property_bag": {
        "#str": "10",
        // You don't need to necessarily turn this into a binding
        // property but it alleviate problems later on the line.
        "#float": 1.0
    },
    "bindings": [
        {
            "binding_type": "view",
            "source_property_name": "(#str * 1)",
            "target_property_name": "#integer"
        },
        {
            "binding_type": "view",
            "source_property_name": "(#str * #float)",
            "target_property_name": "#float"
        },
        {
            "binding_type": "view",
            "source_property_name": "('Result: ' + #integer)",
            "target_property_name": "#text"
        }
    ]
}
```

**The Process**

By doing arithmetic operation on strings (except addition), you convert a string into a number.

**Notes:**

-   Instances of strings that is alphanumeric (like `a123`) will not return `123`.
-   Adding a string and float (like `'abc' + 1.2`) will not produce anything.
-   It is not possible to directly display floats—refer to the Float to String part of the documentation.
-   Starting from some version of minecraft the `#str * 1` and `#str * #float` conversions no longer work, however you can still use `0 + #str` method.

</Excerpt>
<Excerpt src="bedrock-wiki" title="Type Conversion (Float to String, Boolean to Number)" path="docs/json-ui/type-conversion.md">

**Float to String**

The following code will create a label that will contain a float data at which will get turned into string.

:::tip
There is no float to number because floats are a sub-child of numbers, so floats are already numbers by itself.
:::

```json
"label": {
    "type": "label",
    "text": "#text",
    "property_bag": {
        "#float": 6.7
    },
    "bindings": [
        {
            "binding_type": "view",
            "source_property_name": "(0 + (#float > 0) + (#float > 1) + (#float > 2) + (#float > 3) + (#float > 4) + (#float > 5) + (#float > 6) + (#float > 7) + (#float > 8) + (#float > 9))",
            "target_property_name": "#integer"
        },
        {
            "binding_type": "view",
            "source_property_name": "('Result: ' + #integer)",
            "target_property_name": "#text"
        }
    ]
}
```

**The Process**

It is not feasible to just add a string and a float as that will produce nothing. Therefore, the binding need to guess where the float lies on between the number 1 to 10.

In this process, it also limits itself into only support floats between 1 to 10 and; the output will not include the decimal number. So in this context, it will only output `6`, not `6.7`.

**Notes:**

-   There is a way to include the decimal but, it requires a more complex expression.
-   The code seen is the simplified version of the concept, there is much more better ways of doing this process.
-   This is great if you know the range of your number reference, otherwise, you will need to guess.

**Boolean to Number**

The following code will create a label that will contain a boolean data at which will get turned into number.

```json
"label": {
    "type": "label",
    "text": "#text",
    "property_bag": {
        "#bool": true,
        "#hahasixseven": false
    },
    "bindings": [
        {
            "binding_type": "view",
            "source_property_name": "(#bool + #hahasixseven)",
            "target_property_name": "#integer"
        },
        {
            "binding_type": "view",
            "source_property_name": "('Result: ' + #integer)",
            "target_property_name": "#text"
        }
    ]
}
```

**The Process**

Any arithmetic operations done between booleans and numbers will always result a number. Internally, `true` is recognized as 1, and `false` is 0. The `boolean` can be an expression as long as it results as a boolean.

</Excerpt>

**Number to String.** 숫자 앞에 글자를 이어 붙인다. 정수만 된다(EXP-22). 원문의 예는 `property_bag`의 `"#num": 10`에 `('Result: ' + #num)`을 적용해 `Result: 10`을 만든다. float은 아무것도 나오지 않는다.
