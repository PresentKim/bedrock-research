## 개념: 조용한 실패를 다루는 법

JSON UI에는 버전 필드와 친절한 오류 창이 없다. 잘못된 속성은 무시되거나 파일 전체가 버려지고, 화면에는 아무것도 그려지지 않는다. 그래서 디버깅은 ① 로그로 화면이 실제로 열렸는지 확인하고 ② 한 번에 하나만 바꾸고 ③ 실패를 마운트·바인딩·레이아웃 중 어디인지 가르는 순서로 한다. Content Log GUI(설정의 크리에이터 항목)를 켜고 `Unknown property` 같은 줄을 찾는 것이 출발점이다. Bedrock Wiki의 Best Practices 문서도 같은 방향으로, 바꿀 속성만 쓰고 `modifications`를 쓰며 식·바인딩 수를 줄이라고 권한다(성능은 JSON UI가 엔티티 다음으로 비싼 서브시스템이다, 출처: bedrock-wiki).

새 UI 파일이 안 보이면 먼저 `ui/_ui_defs.json`에 등록했는지 본다.

```json
{ "ui_defs": [ "ui/my_screen.json", "ui/my_common_elements.json" ] }
```

이 형식은 MS Learn JSON UI 레퍼런스(`ui_defs`: 리소스팩 루트 기준 경로 배열, 사용자 UI 화면에 필수)와 같다. MS Learn은 `ui_defs`, `ui_element`, `ui_global_variables`, `ui_screen` 네 문서를 두며 바닐라 예제에서 자동 생성되어 엉성하다는 평이 있으므로(커뮤니티 보고) 속성 사전은 이 장과 값 사전 페이지로 대조한다. (출처: ms-learn)



## 13.1 로그 읽기

- **[DBG-01]** JSON UI 오류는 조용한 경우가 많다(아무것도 안 그려짐, 버튼이 `canceled`, 수정 전체 무시). Content Log를 켜고, 클라이언트 로그 `Debug_Log<세션>.txt`(Windows: `%APPDATA%/Minecraft Bedrock/logs/`)에서 `Unknown property`, `Type not specified (or @-base not found)`, `Must define a source property name in the binding!`, `Invalid expression`, `Assertion failed` 줄을 찾는다. 레이아웃 줄(`Full re-layout of N controls`)로 화면이 열렸는지 본다. 단 이 수는 팩토리가 셀을 만들기 전에 센 값이라 팩토리 게이트의 효과는 측정하지 못한다. `{실측}` (출처: BC-S8, BC-facts, BC-S12, MJ 8장-8)
- **[DBG-02]** **실험은 한 번에 하나만 바꾸고, 먼저 그 화면이 실제로 열렸는지를 로그로 확인한다**(제목 문자열이 로그에 있는지). 프로브가 아예 실행되지 않은 세션은 아무것도 증명하지 않는다. "될 것 같은 것을 추론하지 말고 되는 것을 복사하라"는 bedrock-core 저자가 일곱 번의 실패 끝에 남긴 교훈이다. `{실측}` (출처: BC-S6, BC-S8, BC 7장-9)
- **[DBG-03]** 실패를 "안 보임" 하나로 뭉뚱그리지 않는다. 프레임(항상 그려지는 테두리), 값 표시(같은 값을 텍스트로), 실제 대상(크기·가시성)을 함께 그려 "마운트 실패 / 바인딩 실패 / 레이아웃 실패"를 구분한다. 게이트는 식과 그 부정을 둘 다 그려(`YES`/`no`) 식 자체가 실패했는지 확인한다. `{실측}` (출처: BC-S6, BC-S14)
- **[DBG-04]** 화면을 망가뜨릴 수 있는 실험(크래시 가능성)은 개발 중인 화면이 아니라 따로 만든 실험 화면에 올린다. `{실측}` (출처: BC-S6)

## 13.3 검증 도구와 스키마의 함정

- **[DBG-05]** 공식 스키마(`@minecraft/bedrock-schemas`)의 `schemas/rp/ui/index.schema.json`은 `namespace`만 검사해서 UI 파일 검증에 쓸모없다. 실제 enum 값은 `forms/ui/ui_element.form.json`에만 있고, `types/rp/ui/UiElement.d.ts`는 enum 멤버가 비어 있다. `{실측, 코드}` (출처: BC-facts)
- **[DBG-06]** 공식 enum과 바닐라 사용은 서로 포함 관계가 아니다. 바닐라는 enum에 없는 타입(`factory`, `collection_panel`, `tooltip_trigger` …), `binding_condition: "none"`, `font_size: "medium"`, `input_mode_condition: "gamepad"`/`"not_gamepad"`를 쓰고, enum의 `grid_rescaling_type: "none"`은 쓰지 않는다. `collection_index`, `localize`, `clip_ratio`, `property_bag`, `modifications`, `variables`, 배열형 `nineslice_size`는 공식 자료 어디에도 없다. `{바닐라, 실측}` (출처: VN, BC-facts, 부록B)
- **[DBG-07]** 속성·값 사전은 **양방향**으로 대조한다. "바닐라가 쓰는 이름이 사전에 있는가"만 보면, 사전에 바닐라에 없는 이름(`resolve_ancestor_scope`, `scroll_box` 타입, `z_order` 등)이 섞여도 잡지 못한다. `{바닐라, 코드}` (출처: MJ 4.2 원인, MJ 8장-3, BW-doc)
- **[DBG-08]** 커뮤니티 팩 검사기의 흔한 오탐: 바닐라 병합 파일의 namespace 없음, `_global_variables.json` 미등록 경고, 높은 레이어 경고. 반대로 `.json`이 아닌 확장자로 등록한 UI 파일은 검사하지 않고 통과시키는 도구도 있다. `{코드, 추론}` (출처: MJ 5장)
- **[DBG-09]** 생성 도구로 만든 "평평한 최상위 정의 + 절대 px" JSON은 어떤 바닐라 화면에도 연결되어 있지 않으면 게임에 뜨지 않는다. 예제로 쓰기 전에 호스트 연결(10장)을 확인한다. `{코드}` (출처: MJ 5장)

## 13.4 근거 관리 원칙

- **[DBG-10]** 근거 우선순위는 ① 대상 팩과 로그 ② 고정한 바닐라 버전 ③ 확인된 외부 출처 ④ 추론이다. 문서에 적을 때 어느 단계의 근거인지 표시한다. 이 가이드의 검증 수준 표기가 그 형식이다. `{코드, 추론}` (출처: MJ 2장·8장-4)

## 13.5 바닐라 대조 방법

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/Mojang/bedrock-samples
cd bedrock-samples && git sparse-checkout set resource_pack/ui
git log -1 --format='%h %cd %s'          # 이 가이드: 46ba6ea 1.26.50.4
cd resource_pack/ui
rg -c '"resolve_ancestor_scope"' . | wc -l          # 이름이 실제로 쓰이는가
rg -o --no-filename '"type"\s*:\s*"[a-z_]+"' . | sort | uniq -c | sort -rn   # 값 분포
rg -n -A10 '"server_form_factory"' server_form.json  # 구조 확인
```

- **[DBG-12]** 새 버전이 나오면 이 가이드가 기대는 바닐라 지점(`server_form.json`의 팩토리 구조, `hud_screen.json`의 `hud_title_text`·`root_panel`·`chat_grid_item`, `npc_interact_screen.json`, `chest_screen.json`의 `small_chest_screen`)을 먼저 diff한다. `{바닐라, 추론}` (출처: VN, MJ 4.1)

## 13.7 Bedrock Wiki 대조로 더한 규칙

위키(BW) 문서를 바닐라 1.26.50.4와 대조해 더한 규칙이다. 위키 문장만 있는 것은 `미검증`, 위키의 게임 스크린샷이 있는 것은 `실측`(제3자 기록)으로 표시했다.

- **[DBG-15]** JSON UI에는 버전 필드가 없다. 바닐라가 바뀌면 팩이 그대로 깨진다. 접점을 줄이는 순서: 바꿀 속성만 쓰기(FILE-21) → `modifications`(MOD-13) → 진입점 하나(MOD-15) → 경로 키 최소화(FILE-27). `{추론}` (출처: BW-best)
- **[DBG-16]** Mojang은 화면을 Ore UI로 옮기고 있고, 평문 리소스팩은 Ore UI 화면의 배치·동작을 고칠 수 없다(버튼 모양·텍스처만 닿는다, ALT-15). 루트에 빈 `content.zipe`를 둔 팩이나 서버가 암호화해 보낸 팩은 게임 중 Ore UI 페이지를 바꿀 수 있다(ALT-11). 새 버전마다 대상 화면이 아직 바닐라 `resource_pack/ui/`에 JSON 파일로 있는지 먼저 확인한다(예: 1.26.50에는 위키가 적은 `feed_screen`, `comment_screen`, `manage_feed_screen` 파일이 없다). 설치본이 있으면 `data/gui/dist/hbui/routes.json`의 `supportedRoutes`도 함께 본다(ALT-11, ALT-13). `{미검증, 바닐라, 코드}` (출처: BW-intro 경고, BW-font, VN, OUC)
- **[DBG-17]** 성능: 위키는 JSON UI를 엔티티 다음으로 비싼 서브시스템으로 꼽는다. 식과 바인딩 수를 줄이고(`(2 * (-1 * $n))` → `(-2 * $n)`), 같은 모양 컨트롤 여러 개는 `#texture` 같은 바인딩 하나로 합치고, 안 쓰는 컨트롤은 지우거나 `ignored: true`로 둔다. `{미검증, 추론}` (출처: BW-best)

## 13.8 이 가이드의 게임 실측에서 얻은 것

- **[DBG-18]** 게임은 개발 팩 폴더(이 측정의 Windows 1.26.52에서는 `%APPDATA%/Minecraft Bedrock/Users/Shared/games/com.mojang/development_*_packs`)와 월드 목록을 **시작할 때** 읽는다. 오래 켜 둔 게임은 새로 넣은 팩이나 복사한 월드를 보지 못하므로, 팩을 처음 넣었으면 게임을 다시 켠다. 월드에 팩을 붙일 때는 월드 편집 화면의 행동 팩·리소스 팩 목록에서 활성화하는 것이 확실하다. `{실측}` (출처: TP)
- **[DBG-19]** 서버 폼에 붙인 프로브 화면이 `visible` 게이트로 모든 폼에서 생성되는 구성에서, 숫자가 아닌 본문(`'pick probe'`)에 대해 `(#v - 0)`·`(#v * 1)`을 `#size_binding_x`에 넣거나, `/ 100`을 `#clip_ratio`에 넣는 식이 있으면 액션 폼을 여는 순간 1.26.52 클라이언트가 종료되었다(1회). `collection_panel` 계산 길이 게이트·경로 사전 조회·`factory_variables` 셀이 든 이전 구성은 같은 시점에 멈췄다(2회). 어느 요소가 원인인지는 분리하지 못했다. 생성될 수 있는 모든 컨트롤의 식은 **엉뚱한 입력(빈 문자열, 다른 폼의 본문)에서도 안전해야 한다**고 보고, 숫자 속성에 넣는 식은 입력 형식을 먼저 확인하는 게이트 안에서만 생성되게 한다(COL-10, EXP-21, LAY-14). `{실측, 추론}` (출처: TP)

## 13.9 다른 엔진·도구 분석에서 더한 규칙

Ore UI 패치 도구(`OUC`)와 Cinnabar 재구성 엔진(`CN`)에서 얻은 방법이다.

- **[DBG-20]** Ore UI 패치 도구(OUC)는 압축 코드에서 번역 키·`data-testid` 같은 안정 문자열을 닻으로 짧은 이름을 다시 뽑고, 실패한 패치는 빼고 나머지만 적용한다. JSON UI 팩도 같은 원칙(안정 이름에만 기대기, 실패를 국소화하기)을 따르면 버전 변경에 덜 깨진다. DBG-15와 같은 결론. `{코드, 추론}` (출처: OUC 4.2)
- **[DBG-21]** 게임 없이 레이아웃·변수·식을 미리 볼 때 Cinnabar JSON-UI 편집기(jsonui.cinnabar.gg)를 쓸 수 있다. 엔진 규칙은 네이티브 재구성이지만 글꼴, HUD, 오류 처리가 바닐라와 다르므로 최종 확인은 게임에서 한다. 비상업 라이선스다. `{코드}` (출처: CN)

## 반영안(미적용)

아래는 추가 자료 조사(survey)에서 나온 규칙 제안이다. 병합 보고서에는 번호가 매겨져 있지만 위 본문의 규칙집에는 아직 반영하지 않았다. 번호는 병합 보고서의 최종 ID이고, 근거 강도는 제안 원문의 검증 수준을 따른다. 쓰기 전에 확인한다.

- **[DBG-23 반영안(미적용), 스키마]** 커뮤니티 UI 스키마는 바닐라에도 오류를 낸다. 1.26.50.4 바닐라 205개 파일을 검증하면 Blockception 최신 소스는 43개 파일 116건(모르는 속성 50종), Bugrock(KalmeMarq)은 186개 파일 2,224건(크기 식·텍스처 경로 정규식), Blockception VS Code 확장 v8.0.46에 든 2025-09 스키마는 193개 파일 2,251건(`"100%c"`, 음수 offset, 크기 식 거부)이다. 스키마 오류는 먼저 바닐라에 같은 형태가 있는지 grep해서 오탐인지 가린다. `{코드}` (출처: jsonui-schemas)
- **[DBG-24 반영안(미적용)]** 스키마를 통과했다고 게임이 받아들이는 것은 아니다. Blockception 스키마는 enum마다 "아무 식별자" 대안을 붙여 `clip_direction: "dwn"`·`font_size: "huge"`를 통과시키고, 앵커 enum에 바닐라에 없는 `left`·`top`·`center_middle`을, `clip_direction` enum에 바닐라가 쓰지 않는 `top`·`bottom`(바닐라는 `up`·`down`)을 둔다. Bugrock은 NetEase 전용 타입·속성 51종을 통과시킨다. 이름과 값은 값 사전과 바닐라 grep으로 확인한다(DBG-07). 생성기·스키마가 내는 이름은 바닐라 사용을 grep한다(예: 스크롤 뷰 역할은 `scrollbar_track`/`scrollbar_box`이고 `scroll_bar_track`이 아니다, 토글 강제 인덱스는 `toggle_group_forced_index`). `{코드, 바닐라}` (출처: jsonui-schemas, EasyUIBuilder, jsonui-lsp, VN)
- **[DBG-25 반영안(미적용)]** 바닐라에도 깨진 값이 남아 있다: `"size": [ "fill%", "100%" ]`(sidebar_navigation.json:881), 원소가 하나인 `"size": [ "100%, 100%" ]`(store_promo_timeline_screen.json:1380), 괄호가 닫히지 않은 `"ignored": "($nx_os or $is_ps4"`(xbl_console_signin_succeeded.json:221), `"max_size": []`(ui_common.json:6551), 그리고 LAY-36의 `"100c%"`. **바닐라에 한두 번 나온 값은 유효하다는 증거가 아니다.** 근거로 쓸 때는 여러 화면에서 같은 의도로 쓰였는지 본다. `{바닐라}` (출처: jsonui-schemas, VN)
- **[DBG-26 반영안(미적용)]** Microsoft Learn의 JSON UI 레퍼런스(`JsonUiReference`, AI 보조 생성, 2025-02-11)는 출처로 쓰지 않는다. 속성 이름 목록으로만 쓰고 타입·의미는 바닐라에서 확인한다. `font_scale_factor`·`default_focus_precedence`를 Boolean, `grid_item_template`을 Integer, `factory`를 String으로 적었고, 중국판 전용 `nine_slice_buttom`·`place_holder_text`·`slider_range`(바닐라 0회)를 섞었으며, enum 표는 `undefined`뿐이다. 또 jsonui-lsp(VS Code 확장 `jsonui-support`, MIT)는 바닐라 1.26.50.4 `ui/` 전체에서 뽑은 "컨트롤 → 타입·`$변수`" 사전으로 바닐라 템플릿이 받는 `$변수` 제안과 정의 이동을 하지만 진단·호버·레이아웃·식 검사는 없고, 마켓플레이스 판(v0.3.1)은 1.21.120.4 사전이다. `{바닐라, 코드}` (출처: web-tutorials, jsonui-lsp)
