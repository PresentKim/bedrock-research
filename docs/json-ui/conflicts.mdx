## 개념: 판정표를 읽는 법

JSON UI 자료는 서로 모순되는 주장이 많다(위키의 오기, 게임 버전 변화, 작성자의 실험 오류). 이 표는 모순마다 ID(C-nn)를 주고 두 주장, 판정 근거, 판정, 관련 규칙을 한 줄로 적는다. 판정 우선순위는 게임 실측과 바닐라 전수 검색이 앞이고, 재구성 엔진(`CN`)이 실측과 다르면 실측을 따른다. **판정** 칸의 `해소`는 한쪽이 맞다고 확정, `부분 해소`는 범위를 나눠 둘 다 맞음, `미해결`은 실측 필요다. 예: C-06은 `%` 연산자를 쓰는 커뮤니티 예제와 `Invalid expression` assert 실측이 부딪쳐 "사용 금지"로 해소되었다. 아래 A.3은 게임에서 확인하면 판정을 확정할 수 있는 28개 실험 목록이다.



출처끼리 주장이 다른 곳을 모두 모았다. 판정 근거는 바닐라 1.26.50.4 전수 검색(`VN`), bedrock-core 실측 원문(`BC-S*`, `BC-facts`), BedrockAdvancements 원본 재확인(`BA-원본`), Bedrock Wiki 문서와 그 수정 이력(`BW`), 네이티브 클라이언트를 재구성한 Cinnabar 코드와 그 실행 결과(`CN`, `CN-run`)다. `CN`이 실측과 다르면 실측을 따른다.
**판정** 칸: `해소` = 한쪽이 맞다고 확정, `부분 해소` = 범위를 나눠 둘 다 맞음, `미해결` = 실측 필요.
