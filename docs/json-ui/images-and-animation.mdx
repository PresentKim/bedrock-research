이미지는 `image` 컨트롤이 그린다. 텍스처 한 장을 늘리고(`fill`), 반복하고(`tiled`), 9-slice로 모서리를 보존하며 늘리고, 일부만 보이게(`clip_ratio`) 하는 것이 기본기다. 엔진이 직접 그리는 것(아이템 아이콘, 플레이어 모델, 하트)은 `custom` 타입 + `renderer`이고, 시간에 따라 변하는 것은 애니메이션(`anim_type`)이다.

## 9.0 가장 작은 예제

**예 1. 이미지.** `texture`는 팩 루트부터의 경로이고 확장자가 없다. `uv`, `uv_size`로 큰 텍스처의 일부만 쓸 수 있다.

```json
"icon": { "type": "image", "texture": "textures/ui/my_icon",
  "size": [ 16, 16 ], "uv": [ 0, 0 ], "uv_size": [ 16, 16 ], "bilinear": false }
```

**예 2. 9-slice.** `textures/ui/my_panel.png` 옆에 `textures/ui/my_panel.json`을 둔다. 모서리 4칸은 그대로 두고 가운데만 늘어난다.

```json
{ "nineslice_size": 4, "base_size": [ 16, 16 ] }
```

**예 3. 진행 막대.** `#clip_ratio`(0.0~1.0)를 바인딩하고 어느 쪽에서 잘릴지 `clip_direction`으로 정한다. 바인딩 조건은 `always`나 `always_when_visible`로 둔다(바닐라 각 6회). 정수 값(0~100)에서 0~1을 만들 때는 `.01`처럼 점으로 시작하는 실수 리터럴을 쓴다(EXP-27).

```json
"bar": { "type": "image", "texture": "textures/ui/bar_fill", "size": [ 100, 8 ],
  "clip_direction": "left", "clip_pixelperfect": false,
  "bindings": [
    { "binding_type": "view", "source_property_name": "(#percent * .01)",
      "target_property_name": "#clip_ratio", "binding_condition": "always" } ] }
```

**예 4. 슬라이드 인 → 대기 → 슬라이드 아웃 애니메이션**(아래 9.3 코드 참고). 애니메이션 컨트롤은 `type` 대신 `anim_type`을 가지고, `anims`로 붙이거나 속성 값에 `@네임스페이스.이름`으로 직접 참조한다.

## 9.0.1 이미지 속성표(Bedrock Wiki, MS Learn)

Bedrock Wiki JSON UI Documentation의 Sprite 표와 MS Learn `ui_element` 표(둘 다 `texture`, `uv`, `tiled`, `keep_ratio`, `bilinear`, `fill`, `grayscale`, `clip_pixelperfect`, `nine_slice_*`를 적는다)에서 정리했다.

| 속성 | 타입 | 뜻 |
| --- | --- | --- |
| `texture` | 문자열 | 팩 루트부터의 경로(예: `textures/ui/White`) |
| `allow_debug_missing_texture` | 불리언 | 텍스처가 없을 때 누락 표시 이미지를 그림. 기본 `true` |
| `uv`, `uv_size` | `[u, v]`, `[폭, 높이]` | 텍스처에서 쓸 영역의 시작점과 크기 |
| `texture_file_system` | 문자열 | 텍스처를 읽을 위치. `InUserPackage`(기본), `InAppPackage`, `RawPath`, `RawPersistent`, `InSettingsDir`, `InExternalDir` 등 |
| `nineslice_size` | 정수 또는 `[x0, y0, x1, y1]` | 9-slice. 모서리는 고정, 나머지는 늘어남 |
| `tiled` | `true`/`false`/`"x"`/`"y"` | 컨트롤이 텍스처보다 크면 반복. `tiled_scale`은 반복 단위 배율 |
| `clip_direction`, `clip_ratio` | `left`/`right`/`up`/`down`, 0.0~1.0 | 잘림 시작 쪽과 비율. 위키는 `#*_ratio` 바인딩을 `#clip_ratio`에 `always` 조건으로 바인딩하라고 적고, 화로의 진행 화살표·연료 그림이 이 방식이라고 한다 |
| `clip_pixelperfect` | 불리언 | 가능한 한 픽셀 단위로 정확하게 자름 |
| `keep_ratio` | 불리언 | 크기를 바꿀 때 비율 유지. 기본 `true` |
| `bilinear` | 불리언 | 크기를 바꿀 때 쌍선형 보간. 기본 `false` |
| `fill` | 불리언 | 컨트롤 크기에 맞게 늘림. 기본 `false` |
| `grayscale` | 불리언 | 흑백으로 그림 |
| `force_texture_reload` | 불리언 | 텍스처 경로가 바뀔 때 다시 불러옴 |
| `base_size` | `[폭, 높이]` | 9-slice 기준 크기 |

MS Learn 표의 `nine_slice_left/right/top/bottom`(철자 `buttom` 포함)은 이 프로젝트의 바닐라 전수 검색에 나오지 않는 이름이다(중국판 문서의 이름과 비슷하며 국제판은 `.json` 파일 방식을 쓴다, DBG-27).

## 9.0.2 이징과 애니메이션 타입

`anim_type`의 값과 인자(Bedrock Wiki Intro): `alpha`(실수, 투명도), `offset`(`[x, y]`, 앵커 기준 위치), `size`(`[폭, 높이]`), `flip_book`(정수, 프레임을 하나씩 바꾸는 이미지), `uv`(배열, UV 위치), `color`(0.0~1.0의 RGB), `wait`(숫자, 기다림), `aseprite_flip_book`(스프라이트 시트), `clip`이다.

`easing`의 전체 목록(위키): `linear`, `spring`, `in_quad`, `out_quad`, `in_out_quad`, `in_cubic`, `out_cubic`, `in_out_cubic`, `in_quart`, `out_quart`, `in_out_quart`, `in_quint`, `out_quint`, `in_out_quint`, `in_sine`, `out_sine`, `in_out_sine`, `in_expo`, `out_expo`, `in_out_expo`, `in_circ`, `out_circ`, `in_out_circ`, `in_bounce`, `out_bounce`, `in_out_bounce`, `in_back`, `out_back`, `in_out_back`, `in_elastic`, `out_elastic`, `in_out_elastic`. 이 중 바닐라가 쓰는 것은 14개뿐이다(ANI-10).

애니메이션 속성(위키 표): `anim_type`, `duration`(초), `next`(끝난 뒤 이어질 애니메이션), `destroy_at_end`, `play_event`, `end_event`, `start_event`, `reset_event`, `easing`, `from`, `to`, `initial_uv`, `fps`, `frame_count`, `frame_step`, `reversible`(끝난 뒤 거꾸로 실행), `resettable`, `scale_from_starting_alpha`, `activated`.

## 9.1 이미지

- **[ANI-01]** `image`의 주요 속성(바닐라 사용 횟수): `texture`, `uv`/`uv_size`(40), `tiled`(44), `keep_ratio`(45), `bilinear`(50), `fill`(48), `color`, `alpha`, `clip_direction`(`left` 21, `down` 3, `up` 1, `right` 1), `clip_ratio`, `clip_pixelperfect`(21), `grayscale`(1), `force_texture_reload`(6), `zip_folder`(3). 그 밖에 `allow_debug_missing_texture`(4)와 `tiled`의 축 값(ANI-17)이 있다. `&#123;바닐라&#125;` (출처: VN, BW-doc)
- **[ANI-02]** 텍스처 경로는 변수 식으로 조립할 수 있다: `"texture": "('textures/my/bg/' + $tab_bg)"`. 런타임에는 `#texture` 바인딩에 view 식으로 경로를 넣는다: `('textures/my/frames/' + #frame)`. `&#123;작동팩, 바닐라&#125;` (출처: AP 4.9, BA 3.1, VN server_form.json:173)
- **[ANI-03]** **진행 막대**는 `#clip_ratio`(0~1)를 바인딩하고 `clip_direction`으로 잘리는 쪽을 정한다. `clip_ratio`, `clip_direction`, `clip_pixelperfect`는 공식 스키마에 없지만 바닐라가 쓰는 속성이다. 정수 값에서 0~1 소수를 만들 때는 `(#v * .01)`처럼 점으로 시작하는 실수 리터럴을 쓴다. `(#v / 100)`은 정수 나눗셈이다(EXP-18, EXP-27). 바닐라는 `#clip_ratio` 바인딩에 `binding_condition`을 `always`(6) 또는 `always_when_visible`(6)로 준다. `&#123;바닐라, 실측, 코드&#125;` (출처: VN 33회, BC-facts, BA 3.2, BW-doc, CN)
- **[ANI-04]** 9-slice는 텍스처 파일 옆에 같은 이름의 `.json`을 두고 `nineslice_size`(`[왼, 위, 오른, 아래]` 또는 한 값)와 `base_size`를 적는다. 바닐라 UI JSON은 `nineslice_size`를 리터럴 속성으로 쓰지 않고 바인딩(`#banner_nineslice_size` → `#nineslice_size`)으로 1회 쓴다(LAY-27). 반복 배경은 image에 `"tiled": true`를 준다(LAY-28, 바닐라 44회). `&#123;작동팩, 바닐라&#125;` (출처: BA 5장, AP 4.9, VN)

## 9.2 렌더러(`custom`)

- **[ANI-05]** `"type": "custom"` + `"renderer": "이름"`이면 엔진이 그린다. 바닐라 1.26.50.4가 쓰는 렌더러는 43종이다(부록B). 렌더러 이름 목록을 외부 자료에서 가져올 때는 바닐라 목록과 대조한다. 한 외부 목록은 53개 중 10개가 바닐라에 없었다. 위키 렌더러 목록 41개 중 7개(`background_renderer` 등)는 바닐라 1.26.50에 없고, 바닐라의 9개(`locator_bar`, `qr_code_renderer` 등)는 위키에 없다. `&#123;바닐라&#125;` (출처: VN, MJ 4.2, BW-doc)
- **[ANI-06]** 아이템 아이콘은 `inventory_item_renderer`에 `#item_id_aux`를 준다. 값은 `숫자 아이템 ID × 65536 (+ 데이터 값)`이다. 상수면 `property_bag`에 넣고, 런타임 값이면 바인딩한다. 숫자 ID는 커스텀 아이템이 등록되면 일부가 밀려 월드마다 다를 수 있다. 밀리는 경계는 출처마다 다르다(BC 기록은 256 이상, 위키의 1.26.50 표는 -1246~851 안정, 852~883만 밀림). 쓰기 전에 그 버전의 표나 게임에서 확인한다. 가능하면 텍스처 경로를 쓴다. `&#123;작동팩, 실측, 충돌&#125;` (출처: AP 4.7, BC-facts, BW-ids, 부록A C-33)
- **[ANI-07]** 바닐라 HUD의 커서(`cursor_renderer`)는 1.26.50에서 HUD 루트의 인스턴스가 빠지고 `hud_crosshair_overlay.json`에서 참조된다(정의는 `hud_screen.json:608`에 남아 있다). 이것을 기준점으로 쓰던 HUD 수정은 깨진다. `&#123;바닐라&#125;` (출처: VN hud_crosshair_overlay.json:4, MJ 4.1)

## 9.3 애니메이션

```json
"anim_slide_in":  { "anim_type": "offset", "easing": "out_back", "duration": 0.5,
                    "from": [ "100%c + 40px", 20 ], "to": [ 0, 20 ], "next": "@my_toast.anim_wait" },
"anim_wait":      { "anim_type": "wait", "duration": 4.5, "next": "@my_toast.anim_slide_out" },
"anim_slide_out": { "anim_type": "offset", "easing": "in_back", "duration": 0.5,
                    "from": [ 0, 20 ], "to": [ "100%c + 40px", 20 ], "destroy_at_end": "hud_title_text" }
// 사용: "anims": [ "@my_toast.anim_slide_in" ]  또는  "alpha": "@my_toast.anim_fade"
```

- **[ANI-08]** `anim_type` 값(바닐라 횟수): `alpha` 54, `offset` 42, `flip_book` 34, `wait` 30, `size` 7, `color` 3, `aseprite_flip_book` 2, `uv` 1. 위키와 Cinnabar(1.26.50 엔진 enum)는 `clip`도 적어 9가지다(ANI-20). 바닐라 사용은 0회이고 무엇을 자르는지는 확인되지 않았다(부록A C-38). `&#123;바닐라, 코드&#125;` (출처: VN, CN)
- **[ANI-09]** 애니메이션 필드: `from`, `to`, `duration`, `easing`, `next`(다음 애니메이션 참조), `destroy_at_end`, `play_event`, `end_event`, `reset_event`, `reversible`, `resettable`, `looping`, 플립북용 `initial_uv`, `frame_count`, `frame_step`, `fps`. `&#123;바닐라&#125;` (출처: VN 필드별 집계)
- **[ANI-10]** `easing`은 바닐라가 쓰는 값을 우선한다: `linear`, `out_cubic`, `in_expo`, `in_quart`, `in_quint`, `out_expo`, `in_sine`, `in_out_back`, `out_sine`, `out_bounce`, `out_back`, `in_out_expo`, `in_out_circ`, `in_bounce`. 외부 목록의 이징 32개 중 18개는 바닐라에 없다. `in_back`은 BA가 쓴다. 이 32개는 위키 목록과 같고, 바닐라 14개는 모두 그 안에 있다. `&#123;바닐라, 작동팩&#125;` (출처: VN, MJ 4.2, BA 6장, BW-doc)
- **[ANI-11]** 애니메이션은 `"anims": [ "@ns.이름" ]`로 붙이거나 속성 값에 직접 참조한다(`"alpha": "@hud.anim_title_text_alpha_in"`). **다른 namespace의 애니메이션을 바닐라 요소에 붙일 수도 있다.** `&#123;바닐라, 작동팩&#125;` (출처: VN hud_screen.json:2272, AP 4.5)
- **[ANI-12]** 팩토리가 컨트롤을 새로 만들 때마다 애니메이션은 **처음부터 다시** 재생된다. 타이틀을 보낼 때마다 토스트가 슬라이드인 하는 이유다. `&#123;작동팩&#125;` (출처: BA 6장, BW-intro)
- **[ANI-13]** 사라진 항목의 높이를 `size` 애니메이션으로 0까지 줄이면 스택 패널의 다음 항목이 부드럽게 올라온다. `&#123;작동팩&#125;` (출처: AP 4.5)
- **[ANI-14]** `destroy_at_end`의 값은 바닐라에서 팩토리가 만든 컨트롤 이름(`hud_title_text`), 그 기반 정의 이름(채팅: 인스턴스 `chat_item`, 값 `chat_grid_item`), 변수(`$toast_control`)가 모두 쓰인다. 어떤 이름과 맞춰야 실제로 파괴되는지는 확인되지 않았다. 팩토리 개수 한도(`max_children_size`)로 누적을 함께 막는다. Cinnabar 재구성에서 `destroy_at_end`는 그 컨트롤과 조상 중 인스턴스 이름이 일치하는 가장 가까운 것을 지우고, 채팅 컨트롤러는 만든 줄에 인스턴스 이름 `chat_grid_item`을 준다(ANI-21). 그렇다면 바닐라 채팅의 값과 맞는다. `&#123;바닐라, 코드, 추론&#125;` (출처: VN hud_screen.json:949·2213, AP 4.5, 부록A C-27, CN)
- **[ANI-15]** 플립북 아이콘은 `"uv": "@ns.anim"`(`anim_type: aseprite_flip_book`) + `"uv_size"` + 텍스처 옆 Aseprite JSON(`frames[].frame`, `duration`)으로 만든다. Aseprite에서는 JSON을 **Array** 형식으로 내보낸다(Hash는 동작하지 않는다고 한다). 텍스처와 JSON은 확장자 없이 같은 이름이고, `aseprite_flip_book`은 image의 `uv`에만 건다. `&#123;바닐라, 작동팩&#125;` (출처: VN 2회, AP 4.7, BW-ase)
- **[ANI-16]** 바닐라 타이틀 애니메이션 시간은 엔진 변수(`$title_fade_in_time`, `$title_fade_out_time`)로 들어온다. `/title times` 값이 여기에 반영되는 것으로 보인다. `&#123;바닐라, 추론&#125;` (출처: VN hud_screen.json:2170·2185)


## 9.3.1 Aseprite 스프라이트 애니메이션(Bedrock Wiki 원문)

`aseprite_flip_book`는 Aseprite(또는 무료 대안 LibreSprite)에서 내보낸 스프라이트 시트로 애니메이션을 만든다. 아래는 위키 원문(CC BY 4.0)이다. ANI-15의 규칙(Array 형식, 같은 이름 파일)과 같은 내용이다.

<Excerpt src="bedrock-wiki" title="Aseprite Animations" path="docs/json-ui/aseprite-animations.md">

**Creating an Animation in Aseprite**

Suppose you have a series of frame images named "frameimage" with sequential numbers from 1 to 5.
Import the first image, and Aseprite will automatically recognize the other images with the same name but different numbers.
It will then place them in the correct order and create an animation.

Use the arrow keys to navigate through all frames and the "Enter" key to play or pause the animation.
Press the "Tab" key to open the timeline and select individual frames.
Right-click a frame in the timeline to access various settings.

To export the animation, use the shortcut "Ctrl + E" or navigate to "File" -> "Export to Sprite Sheet".
In the output settings, select the Output file and the JSON Data.
You'll see a dropdown menu with Hash and Array options.
Ensure the Array option is selected, or the export will not work properly.

You should now have two files: the SpriteSheet image and a JSON file.
Ensure both files have the same name but different extensions.

**Using Aseprite Animations in JSON UI**

The `aseprite_flip_book` animation type can only be used for the `uv` property in an element of the type `image`.

```json
{
    "image_element": {
        "type": "image",
        "texture": "textures/wiki/ui/my_sprite_file",
        "uv_size": [32, 32],
        "uv": "@example_namespace.image_uv_animation"
    },

    "image_uv_animation": {
        "anim_type": "aseprite_flip_book",
        "initial_uv": [0, 0]
    }
}
```

Set the `texture` field to the path of the exported files without the extension.
The `uv_size` field should be set to the width and height of a single frame.

## 9.7 종이 인형과 NetEase 골격 모델

바닐라 `paper_doll_renderer` 13곳 전수(`VN`), 네이티브 바이너리 문자열 검색(`NB-12`), NetEase(중국판) 골격 모델·종이 인형 문서(`NE`)를 대조한 것이다.

- **[ANI-35]** 국제판 `paper_doll_renderer`는 엔진이 바인딩으로 주는 **플레이어 스킨만** 그린다(`#paper_doll_skin`, `#skin_index`, `#classic_skin_index`). 바닐라가 쓰는 속성은 `use_selected_skin`(12, 모두 `false`), `rotation`(`gesture_x` 6, `auto` 1), `camera_tilt_degrees`(8, 모두 `-10`), `starting_rotation`(8, 모두 `30`), `enable_scissor_test`(4, 모두 `true`), `property_bag`의 `#skin_rotation`(2)이다. 끌어서 돌리려면 `input_panel`에 `"gesture_tracking_button": "button.turn_doll"`과 그 버튼 매핑을 두고, 종이 인형이 view 바인딩으로 그 패널의 `#gesture_delta_source`·`#gesture_mouse_delta_x`를 받는다. `&#123;바닐라&#125;` (출처: VN pause_screen.json:320, VN pause_screen.json:348, VN day_one_experience_screen.json:201, NB-12)
- **[ANI-36]** NetEase 문서의 UI 3D 모델 기능, 곧 `paper_doll`의 `modelname`·`modelsize`·`animation`·`animation_looped`와 `netease_paper_doll_renderer`(`skeleton_model_name`, `entity_identifier`, `screen_scale`, `init_rot_x/y/z`, `freedom_gesture`, Python `RenderEntity`·`RenderSkeletonModel`)는 **중국판 전용**이다. 국제판 바이너리에 `netease` 문자열이 0개이고 이 속성들의 긴 이름도 없으며, 바닐라도 한 번도 쓰지 않는다. 국제판 팩은 UI에 커스텀 모델·엔티티를 그릴 수 없으므로 월드 엔티티나 파티클(ALT-01)을 쓴다. 짧은 이름은 바이너리 문자열로 판정할 수 없어(`paper_doll_renderer`도 0개) 결론은 긴 이름에 기댄다. `&#123;코드, 바닐라, 추론&#125;` (출처: NB-12, VN 0회, NE-30 paper_doll, NE-bone)
