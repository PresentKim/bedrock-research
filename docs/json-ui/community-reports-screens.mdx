커뮤니티(Bedrock OSS·Add-Ons, 2025-10-22 ~ 2026-10-23) 대화 중 화면 종류별 노트다. 서버 폼과 상자 화면의 JSON UI 꾸미기, 바닐라 화면별 팁, Script API 폼과 DDUI, Ore UI 수정, 렌더러를 다룬다.

신뢰 표시와 `` 형태의 출처 표기는 커뮤니티 보고와 대조 페이지의 머리말과 같다: *confirmed*는 여러 사람이 확인, *single report*는 한 사람의 보고, *unverified*는 추측, **conflicting**은 보고가 엇갈림이다.

## 서버 폼 (ActionFormData / ModalFormData) JSON UI 커스터마이즈

### 구조
- **이름 대응**: 서버 폼 화면은 `third_party_server_screen`(server_form.json)이다. 기본 long form = ActionForm, `custom_form` = ModalForm이다. 메시지 폼은 dialog_common(panel two button)에 있는 것으로 보인다(미검증). Modal form 코드는 server_form.json에 있고 컨트롤은 settings_common.json과 common.json에서 가져온다(약 1400줄).
- **ModalForm이 안 보일 때**: `$screen_content`가 `long_form`만 가리키면 ModalForm이 렌더되지 않는다. `"server_form.custom_main_screen_content"`를 쓰거나 그 줄을 지운다.
- **폼 바인딩**: 본문은 `#form_text`(`server_form_factory` 안에서만), 제목은 `#title_text`(factory 밖에서도 쓸 수 있음. factory 컨트롤에서 쓰려면 `{"binding_name": "#title_text"}` 선언 필요), `#submit_button_text`(밖. modal 폼의 본문 대용으로 쓸 수 있음). 버튼 collection은 `form_buttons`이고 `#form_button_text`, `#form_button_texture`, `#form_button_texture_file_system`, `#form_button_length`(개수), `#form_button_contents`(배열이므로 개수에는 `#form_button_length`)를 쓴다. `#title_text`는 `form_buttons` 각 항목의 속성이라는 설명도 있다.
- **폼 title 번역**: `ActionFormData().title('container.waystone')`처럼 lang 키가 있으면 자동 번역된다. 바인딩에서는 `#title_text = 'container.waystone'`으로 비교한다. `form.title("%ui.ns.title")`도 된다.
- **전체 화면**: `main_screen_content` 크기가 [0,0]이라 `%` 크기가 안 먹는다. server_form.json에 `"main_screen_content": {"size":["100%","100%"]}`를 넣고 폼 크기를 100%로 한다. long_form 템플릿은 `common_dialogs.main_panel_no_buttons`다.
- **배경**: long_form은 `$custom_background`로 배경을 바꾼다. 배경을 없애려면 텍스처를 투명하게 하거나 템플릿을 고친다.

### Title로 폼 고르기 (라우팅)
- **기본 방식**: `third_party_server_screen@common.base_screen`의 `"$screen_content"`가 `server_form_factory` factory(`control_ids`: `long_form`/`custom_form`)를 가진 패널을 가리키게 한다. 변형마다 `#title_text` 바인딩으로 `#visible`과 `#enabled`를 건다. 예: `('%.15s' * #title_text = '§c§h§e§s§t')`, prefix `@zelisce/chest_form`. prefix가 없으면 바닐라 폼이다. wiki: `json-ui/modifying-server-forms`. PocketMine, Endstone, Script API 모두 같은 방식이다. *confirmed*
- **factory로 하나만 생성**: `server_form.form_factory`를 `collection_panel`로 만들고 `factory.control_ids` map + `property_bag` `{"#§1": ["actionform1"], ...}`를 둔다. `#collection_length`를 `('#' + '%.3s' * #title_text)`에 바인딩하면 맞는 컨트롤만 생성된다. collection length 0이면 생성하지 않으니 바인딩용 `ignored`처럼 동작한다. 폼 200개 이상이 즉시 로드됐다는 보고가 있지만 일부 환경에서는 여전히 느렸다. 가장 빠른 것은 `ignored: true`다. 이렇게 고르면 안에서 `#form_text`를 못 읽으므로 형제 "grabber" 요소에서 `source_control_name`으로 가져온다.
- **long_form을 바꾸는 애드온끼리의 공존**: 표준이 없다. wiki 튜토리얼의 바닐라 폼 `#visible` 바인딩 때문에 바닐라 폼이 위에 뜨는 경우, 자기 루트에 높은 `layer`(예: 15)를 준다.
- **충돌 주의**: 유니코드 title로 트리거하는 chest GUI는 이름 바꾼 아이템에도 걸린다(이름이 "27"인 셜커). title 필터를 엄격하게 한다.

### 버튼
- **필수 바인딩**: 버튼에 `"bindings":[{"binding_type":"collection_details","binding_collection_name":"form_buttons"}]`와 `collection_index`가 있어야 한다. 없으면 `selection`이 undefined/canceled가 된다. 숨긴 버튼에도 이 바인딩을 유지해야 동작한다. mapping은 `button.form_button_click`. *confirmed*
- **`collection_index`**: 0부터 시작한다(index 50에는 버튼 51개 필요). 1.21.x에 header/label/divider가 생긴 뒤 버튼 index가 밀렸다(첫 index가 label일 수 있음). 해결: factory 바인딩 없이 `"type": "collection_panel"` + `collection_name`. 마지막 항목은 `(#collection_index = (#form_button_length - 1))`.
- **버튼 데이터 연결**: 라벨/이미지에 `binding_type: collection`, `binding_collection_name: form_buttons`로 `#form_button_text`/`#form_button_texture`를 바인딩하고 버튼마다 `collection_index`를 준다. 자식이 N번 버튼의 텍스처를 보이게 하려면 `binding_name_override: "#texture"`. 버튼 텍스트로 조건 표시: `(not (#form_button_text - 'marker' = #form_button_text))`. ID 인코딩 예: `§f§l§a§g§<id>§r`.
- **빈 버튼/유령 버튼**: `(not (#form_button_text = ''))` → `#visible`, 그리고 collection 바인딩에 `binding_condition: "once"`. `#form_body`의 숫자(`(#form_text * 1)`)로 `#maximum_grid_items`를 정하는 방법도 있다. 버튼에 텍스처가 있을 때만 보이기: `#form_button_texture` → `#texture`, `not ((#texture = '') or (#texture = 'loading'))`. server_form의 빈 첫 버튼은 짝이 맞지 않는 요소 때문이었다(미해결).
- **폼은 항상 닫힌다**: pressed 이름이 `button.form_button_click`인 버튼은 무조건 화면을 닫고, 바꾸면 동작이 깨진다. 버튼이 폼을 닫지 못하게 막을 수 없으니 다시 열어서(재귀 show) 흉내 낸다. 마지막으로 hover한 버튼은 기억하지 못한다. 클릭한 index를 보내는 방법은 submit뿐이다. 같은 폼의 JSON UI 버튼 여러 개는 같은 결과를 공유해서 스크립트가 구분하지 못한다.
- **폼 안 캐러셀**: 화살표에 `button.menu_left`/`button.menu_right` 같은 커스텀 button id를 쓰면 `form_button_click`과 달리 폼을 닫지 않는다. CONFIRM 버튼만 `form_button_click`을 보내고, 카운터 기반 image_cycler/label_cycler로 화면 안에서 바뀐다. 모바일에서 클릭 후에도 폼을 열어 두려면 `inventory_slot_button_internal`의 `$pressed_button_name`을 빈 문자열로 하거나 button_mappings를 지운다.
- **ModalForm 데이터**: submit 버튼만 데이터를 보낸다. 선택 상태가 필요하면 modal form toggle을 쓴다. 폼 내용은 표시한 뒤 바꿀 수 없고 다시 보내야 한다. 실시간 양방향은 DDUI가 필요하다.
- **닫을 수 없는 폼**: `button.menu_cancel` → `button.null`(global)을 `third_party_server_screen`에 걸면 모든 폼이 닫히지 않게 된다. 그래서 개별 폼의 main panel(`input_panel`이어야 함)에만 건다. `button.menu_cancel`을 자기 자신에 매핑(`mapping_type: global`)해 ESC를 막는 방법도 있다. `to_button_id: "button.close"`로 닫고, `button.back`은 아무것도 안 했다. JSON UI 매핑으로 다른 폼을 열 수는 없다.
- **컨트롤러 포커스**: 버튼에 `focus_enabled: true`가 필요하다(기본 false). 처음 포커스를 없애려면 포커스를 끈다. `default_focus_precedence`를 쓴다. 키보드 포커스 테두리만 보이게 하려면 버튼 두 개를 겹친다(위는 포커스 끔, 아래는 켬). 텍스트만 있는 패널은 포커스할 요소가 없어 컨트롤러 스크롤이 안 되므로 포커스 가능한 커스텀 버튼으로 감싼다. 콘솔 L1은 `button.menu_tab_left`, R3는 `button.controller_secondary_select_right`이고 R2는 없다. `third_party_server_screen`에 `"gamepad_cursor": true`를 주면 커서가 보인다.
- **버튼 아이콘**: hover하면 아이콘이 사라지는 문제는 이미지 `layer`를 올리고 라벨 layer를 그보다 높게 해서 고친다. `§r`은 `(not ((#form_button_text - '§r') = #form_button_text))`로 떼어낸다.
- **원형 메뉴**: 원형 히트박스는 없지만 emote 화면의 `selection_wheel`로 6칸 넘는 휠 UI를 만들 수 있다. radial 메뉴는 버튼마다 collection_index를 준 collection_panel로 만든다(안 그러면 모두 같은 동작).
- **URL 이미지**: Script API 폼 버튼은 경로만 받는다. Endstone 플러그인 https://github.com/zelisce/URL-Image-Fix(https://github.com/EndstoneMC/endweave 경유)를 쓰면 `form.button("Test","https://cdn.example.com/x.png")`처럼 URL 이미지를 쓸 수 있다. 플러그인 없이 RP만으로도 된다: 버튼 이미지 옆에 `profile_image_renderer` 컨트롤을 두고 `('{"type":7,"url":"' + #texture + '"}')`를 `#profile_image_options`로 바인딩한다(`source_control_name: image`, `resolve_sibling_scope`). 예제: https://github.com/zelisce/SAPI-with-URL-Images. PNG만 되고 GIF는 안 된다. 이 페이지 아래 렌더러 절에 `profile_image_renderer`가 있다.
- **크래시 보고**: 커스텀 버튼의 리터럴 "Info" 문자열이 서버 폼을 죽였다는 보고(미확인), 1.26.52.3에서 `$pressed_button_name: "button.sub_command"` + `#sub_command` 채팅 버튼이 서드파티 서버에서 0xc0000005로 죽었다는 보고가 있다.

### Grid, factory, 성능
- **Grid**: `type: grid`, `grid_item_template`(최상위 이름 컨트롤이어야 함. 예: `common.grid_item_for_inventory`), `grid_rescaling_type: horizontal`, `collection_name: form_buttons`, 바인딩 `#form_button_length` → `#maximum_grid_items`(+`binding_condition: once`). 고정 너비(예: `[150,"100%c"]`)가 필요하고 factory는 필요 없다. 세로 채우기/리스케일은 안 되고 크래시가 날 수 있다. 셀은 18x18이다. 패널로 감싸면 간격이 사라진다. `grid_fill_direction`, `grid_dimension_binding`이 있다. 동적 `grid_dimension`은 배열이라 바인딩할 수 없지만, 남은 공간에 맞춰 크기가 정해지는 동적 grid는 된다.
- **Grid 키 이름**: 실제 키는 `grid_dimensions`다(`grid_dimension`이면 타입 오류). 명시적 자식 위치는 `collection_index`가 아니라 `grid_position: [x,y]`로 준다. 자식으로 만든 grid의 collection index도 `grid_position`으로 정해진다. 그리드는 회전할 수 없으니 행과 열을 바꾼다. stack_panel을 grid로 바꾼 뒤 나는 "Unknown property [orientation]"은 무해하다.
- **숨긴 grid 항목**: 숨겨도 공간을 차지하고 닫을 때 다시 그리는 버그가 있다. 늘 숨길 버튼(탭, 내비게이션)은 collection 끝에 둔다. 앞쪽을 숨기려면 첫 행을 숨기고(`(#collection_index > 6)`) grid 앞에 `{"size": [0,-40]}` 패널을 넣어 끌어올린다(스크립트가 index를 보정). panel 높이 `100%c - <자식 높이>`로 감싸는 방법도 있다. 크기가 다른 버튼은 grid에서 섞을 수 없으니 stack_panel(세로 stack 안에 가로 stack, `size ["fill", 30]`)으로 직접 만든다.
- **Factory**: `"factory":{"name":"buttons","control_name":"ns.button"}`, `collection_name: "form_buttons"`, `{"binding_name":"#form_button_length","binding_name_override":"#collection_length"}`를 쓴다. `max_children_size`가 필요하다. `#collection_length`는 boolean이 아니고 N이면 N개를 만든다. 커스텀 collection 이름은 데이터 없이 `#collection_index`만 준다. `factory.name`은 숨은 게임 factory(title, actionbar, item name)의 이름을 짓거나 연결할 때만 쓴다. `type: factory`는 요소 이름에서 이름을 가져온다. 생성된 자식은 `collection_name`을 상속한다.
- **`control_ids` 규칙**: `control_ids` 키는 `#collection_length`의 문자열로 골라진다. `['a','b']`면 둘 다 순서대로 생성된다. 값에 `$var`를 컨트롤 이름으로 그대로 쓸 수 없다(`"('test@hud.' + $content)"`는 미확인). `control_name` factory만 되는 곳에 `control_ids`를 쓰면 "Unknown property [control_ids]"가 난다(원인 미확인).
- **Factory 버그**: server form 아래 자식 factory는 입력이나 리사이즈 전까지 채워지지 않는다(그것을 일으키는 토글로 우회. grid는 이 문제가 없음). factory 안 요소는 상호작용할 때만 다시 평가된다. factory 밖 data_control로 값을 뽑거나 visibility로 대신한다. factory 안 factory, `use_child_anchors`, factory/grid 안 `next` 연쇄 애니메이션(첫 루프 뒤 빨라짐)은 알려진 버그다. 경험 많은 개발자는 서버 폼에서는 factory가 본문을 잃고, toggle이 요소를 다시 로드하며, 다른 곳에서 바인딩 가져오기가 불안정하다고 본다.
- **성능 수치**: 버튼 100개도 느려질 수 있다. 3000개 넘는 버튼 factory(바닐라 long_form stack_panel)는 숨겨도 약 60초 멈춘다. 그래서 페이지로 나눈다. 페이지를 많이 나눠도 폼이 열리는 데 약 30초 걸린 사례가 있다. grid는 10k 버튼도 즉시 로드한다(빈 칸이 남음). 숨긴 요소도 파싱 비용이 든다. collection factory를 많이 쓰고 문자열 빼기 필터를 걸면 폼이 멈춘다. 숨긴 폼도 로드된 채 남으므로 스타일이 다른 폼들을 토글 하나로 합친다. 렉은 클라이언트에서만 생긴다. alt-tab 뒤 모든 버튼 텍스트가 보이는 글리치도 무거운 factory 탓이다.
- **최적화 사례**: 상점 카드당 요소 3개를 1개로 합치고, 처음 열리지 않는 탭의 비싼 내용(버튼 텍스트, 3D 블록 렌더)을 미루고, 가장 가벼운 탭으로 열었더니 1.6초가 0.8초가 됐다. JSON UI는 작업을 "큐"에 넣을 수 없고 요소는 바인딩이 바뀔 때만 갱신된다. 요소 약 75개는 무난하다. "NPC UI" 경로(NPC NBT를 고쳐 버튼 제한 해제)와 Soulsteel의 auto-refresh 기법이 가장 최적화된 방법으로 꼽혔다.

### Dropdown 페이지네이션 (탭/페이지)
- **방식**: 폼 하나에 모든 탭/페이지를 담는다. 폼 index 0에 숨긴 dropdown을 두고 그 옵션으로 현재 뷰를 정한다. 옵션은 `dropdown.radio_selected`를 써서 탭과 화살표로 렌더한다. `custom_form` index 0에서 `#dropdown_option_text`를 읽고, 각 요소에 뷰 id를 붙여 선택된 뷰와 비교하는 바인딩으로 표시를 정한다. 태그 없는 요소는 모든 페이지에 보인다. toggle이 아니라 radio 그룹이고, modal form 안에 actionform 스타일 버튼이 필요하다.
- **멀티 탭 서버 폼(Chest-UI `server_form.json`)**: 커스텀 화면에 `"force_render_below": true`, `render_game_behind`, exit 애니메이션 `screen.exit_pop`/`screen.exit_end`를 준다. 탭 생성기: https://g07hn-1.github.io/tabgenerator/.

### Modal form 컨트롤
- **Toggle과 slider**: toggle은 `settings_common.option_toggle`(바닐라 `server_form.json`에서 복사)이다. slider는 `common.slider`에 `$slider_name`, `$slider_steps`, `property_bag {"#slider_steps","#slider_value"}`를 준다. 템플릿은 `ui_template_toggles.json`, slider 코드는 `ui_common.json`에 있다. 컨트롤을 직접 배치하려면 factory와 그 바인딩을 지우고 `collection_name`은 남긴 채 자식마다 `collection_index`를 준다. `collection_index`가 다른 slider가 하나처럼 동작하고 `$slider_name`을 바꾸면 깨지는 문제는 미해결이다.
- **custom_form factory**: `generated_contents`의 `control_ids`(label, toggle, slider, step_slider, dropdown, input, header, divider)를 쓰고, 컨트롤마다 `collection_name: "custom_form"` 바인딩이 필요하다. long form 조각은 `form_buttons`를 쓴다.
- **텍스트 입력 크기와 길이**: `input_box@common.multiline_text_edit_box`(`size`, `max_length`, `$text_edit_box_content_binding_name: "#custom_input_text"`)를 쓴다. 예: `"text_field@common.multiline_text_edit_box": {"$text_box_name":"notes_field","$text_edit_text_control":"notes","$text_edit_box_label_anchor_point":"top_left","max_length":412,"size":["100%","130px"]}`. 최대 길이는 `"$max_text_edit_length": 100`(폼의 `option_text_edit`에도 있음)이다. `common.scrollable_multiline_text_edit_box`는 스크롤되지만 클릭과 placeholder를 잃은 사례가 있다. 텍스트박스 기본 제한은 100자다. jigsaw UI의 `max_length`도 고칠 수 있다(미확인).
- **Dropdown**: dropdown은 radio toggle이다. `$toggle_name`과 `$toggle_state_binding_name`에 같은 이름을 주고 `$radio_toggle_group: true`를 쓴다. 바닐라 dropdown 바인딩(`#chat_coordinate_dropdown`)은 화면 전용이다. toggle은 `#($dropdown_name)`으로 바인딩하는데, 이름이 잘못되면 dropdown이 멈춘다.
- **텍스트 박스**: `$shadow: true`를 주면 caret이 숨는다(바닐라 템플릿). 검색 박스는 `common.text_edit_box`, `$text_edit_box_clear_to_button_id`. 박스 내용 읽기: `{"binding_type":"view","source_control_name":"display_text","source_property_name":"#item_name","target_property_name":"#text"}`(같은 이름의 박스가 여럿이면 깨짐). 바닐라는 `$text_edit_box_content_binding_name`을 노출한다. 버튼 안에 채팅 박스와 같은 `text_box_name`을 가진 더미 `edit_box`를 두면 채팅 텍스트가 설정된다(emoji 패널 트릭. 하드코딩된 박스에서만 될 것).
- **Toggle 일반**: 클릭 전에 마우스 hover가 필요하다(알려진 마우스 문제).

### 스크롤
- **`common.scrolling_panel`**: 참조(`"form@common.scrolling_panel"`)해야 스크롤이 보인다. 변수: `$scrolling_pane_size`(`size: "$scrolling_pane_size"`를 명시해야 적용), `$scrolling_pane_offset`, `$scrolling_content`, `$scroll_size`, `$show_background`, `$touch`(모바일 스타일. 스크롤 박스가 흐려지면 `"$touch": false`), `$scroll_bar_contained`, `$scroll_track_offset`(지우면 초기 offset이 고쳐짐), `$scroll_bar_left/right_padding_size`, `$scroll_view_port_size`/`$scroll_view_port_offset`([0,0] 유지), `$scrolling_content_anchor_from/to`(기본 top_left).
- **스크롤 텍스처**: `$scroll_track_image_control`, `$scroll_box_mouse_image_control`, `$scroll_box_touch_image_control`, `$scroll_background_image_control`(컨트롤 참조)을 쓴다. 텍스처는 `ScrollRail`, `ScrollHandle`, `ScrollGutterWithBG`, `ScrollBox`, `newTouchScrollBox`. 스크롤바를 숨기려면 `"$scroll_bar_and_track_size": [0,0]`. 클리핑은 해상도에 따라 약간 다르다.
- **직접 만든 scroll view**: 권하지 않는다(바닐라 것에 필요한 button mapping이 있음). 만들려면 바닐라 ui_common.json의 `scroll_view_control`을 복사한다. `scrollbar_track`, `scrollbar_box`, `scroll_content`, `scroll_view_port`, `scroll_box_and_track_panel` 속성에 자식 이름을 주고, viewport가 content보다 작아야 한다. box에는 `button.menu_select` pressed + `button_up_right_of_first_refusal`, track에는 `button.scrollbar_skip_track`을 매핑한다.
- **가로 스크롤과 기타**: 가로 스크롤 시작 방향(왼쪽/오른쪽)은 하드코딩이다. 슬라이더 값을 `anchored_offset_value_x`에 넣거나 애니메이션으로 우회하고, 스크롤바 박스 아래에 요소를 두는 방법도 있다(thread 1252224040433614958). 아래에서 시작하는 스크롤은 불안정하다. 비어 있는 grid가 든 스크롤 패널에도 스크롤이 보이는 문제는 미해결이다. 숨긴 스크롤 패널이 입력을 가로채면 내용물이 아니라 패널 자체를 숨기거나 비활성화(`visible` + `enabled`)한다.
- **폼 바깥 스크롤바**: long_form에서 `$scroll_bar_left/right_padding_size`, `$scroll_size`, `$scrolling_pane_size/offset`을 조정한다. 본문 라벨 크기는 `["100%","default"]`. 스크롤 텍스트 샘플: https://skyls.de/samples/ui3/RP/ui/server_form.json.
- **2D 드래그 패널**: `scrollbar_box`에 `draggable: "both"`, draggable_box와 control_layer_panel 크기 `["100%c","100%c"]`, 바깥 패널 `clips_children`, `$scrolling_size` `["200%c - 100%","200%c - 100%"]`. `contained: true`면 아래/오른쪽으로만 드래그되니 가운데로 하려면 false. 컨트롤러 드래그는 미해결이다.

### 화면 플래그와 애니메이션
- **폼을 연 채 걷기**: 화면 요소에 `"is_showing_menu": false, "absorbs_input": false, "force_render_below": true`(+`render_only_when_topmost`, `low_frequency_rendering`, `render_game_behind`, `$is_full_screen_layout`)를 준다. 터치용은 `$touch`/`$is_pregame`으로 분기한다. 화면에 버튼을 띄운 채 이동하는 것은 터치 기기에서만 되고 콘솔/PC에서는 안 된다. HUD 위에 서버 폼을 겹치는 것도 PC/콘솔을 깨뜨린다.
- **폼 아래 HUD 숨기기**: 기본으로 HUD가 사라진다. 다시 숨기려면 화면에 `force_render_below: false`를 준다. 폼 위에 이미지를 띄우려면 layer(폼 -1/-99, 이미지 99999. 극단값은 게임 화면 밖으로 감)를 쓰는데, server_form.json 안에 넣는 편이 낫다.
- **화면 애니메이션 끄기**: `third_party_server_screen`에 `"$screen_animations": []`/`$background_animations`를 준다. 예: `["@server_form.exit_wait"]`에 길이 0 offset 애니메이션 + `screen.exit_pop`/`end_event screen.exit_end`. 요소별 화면 애니메이션은 끌 수 없다. NPC 대화는 화면 열기/닫기 애니메이션 없이 열린다(인벤토리 슬롯 모양 폼에 활용). 인벤토리 exit 애니메이션은 live_player_renderer 애니메이션에서 나온다.
- **Exit 애니메이션**: `"play_event": "screen.exit_pop"`, `"end_event": "screen.exit_end"`, `destroy_at_end`를 쓴다. 서버 폼에서는 `exit_pop`은 되고 `exit_push`는 안 된다. 폼이 애니메이션이 끝나기 전에 닫히는데 늦출 방법은 없다. aseprite 애니메이션 JSON으로 전체 화면 "비디오" 폼을 만들 수 있다.
- **NPC 대화 vs 서버 폼**: NPC 화면은 서버 폼과 다르다. 장면 전환은 매끄럽지만 미리 정의돼야 하고 버튼은 최대 6개다. NPC `#student_button_text` 길이는 하드코딩이다. 폼 여러 개를 한 클라이언트에 쌓을 수 없다.
- **Hover text**: 커스텀 컨트롤 `{"type":"custom","renderer":"hover_text_renderer","allow_clipping":false,"layer":200}`에 `#form_button_text` collection 바인딩을 `#hover_text`로 넣는다(`binding_name_override: "#hover_text"`). `common.hover_text`는 lang 키를 번역하지 않는다(게임이 번역된 텍스트를 줌). `ignored: "$default_state"`로 상태별로 보인다. 버튼 안에 넣으면 텍스처를 잃을 수 있으니 이미지 배경을 추가한다. `clips_children` 패널이 잘라 먹으면 자식에 `allow_clipping: false`. 커스텀 hover text는 화면 끝 자동 위치 조정을 잃어 긴 텍스트가 넘친다.

## 컨테이너 / Chest UI

### 원리
- **엔티티 기반**: 커스텀 컨테이너 UI는 `minecraft:inventory`를 가진 엔티티(`container_type: container`, 예: `inventory_size: 30`)를 띄우고, 이름 키(예: `§t§e§s§t§r`)를 JSON UI가 `$container_title`로 알아보게 해서 만든다. 슬롯 수는 UI와 맞아야 한다. 버튼은 슬롯으로 흉내 내고 스크립트가 클릭을 감지한다. "GUI"(컨테이너 화면)는 실시간으로 갱신되고, "UI"(서버 폼)는 다시 열어야 한다. *confirmed*
- **블록 기반 불가**: 블록은 커스텀 UI를 직접 띄울 수 없다. 블록 안이나 주변에 큰 hitbox 엔티티를 두고 충돌 0, 밀리지 않음, 넉백 저항을 준다. 엔티티 수에 비례해 TPS 렉이 생긴다. 엔티티 컨테이너 제목은 name tag이고, 이름이 없으면 "unknown"이 뜬다. preview에서는 커스텀 블록 엔티티 `container`가 `title`을 지원하고 `$container_title`이 커스텀 컨테이너에서 동작한다.
- **바닐라 컨테이너**: 이름을 바꾸면 UI를 바꿀 수 있지만 제작대는 안 된다. copper chest는 `ui:container.chestDoubleCopper0` 같은 화면 id로 구분되는데, 이름을 바꾸면 일반 화면으로 돌아간다. 셜커 색과 산화 단계는 순수 RP로 감지할 수 없다(스크립트로 이름 설정). 컨테이너 UI 이름은 아이템 이름으로만 바꿀 수 있고 블록 이름으로는 안 된다.
- **클릭 감지**: 버튼에 `button.drop_one`/`button.drop_all`을 매핑하고(`button.menu_select` → `button.drop_all`) `property_bag {"#collection_name":"container_items","#collection_index":"$i"}`로 대상 슬롯을 정한다. 스크립트에서 아이템 드롭으로 감지하는데, 모바일에서 실패하는 cursor 컴포넌트보다 낫다. 수정 대상은 `small_chest_panel`이다(`small_chest_screen`을 고치면 죽음. 빈 패널로 바꿔 크래시 난 사례도 있음).
- **빠른 이동 막기**: shift-click 빠른 이동은 없앨 수 없다. 얻는 즉시 지우거나 인벤토리 변경 이벤트로 되돌린다. 키를 UI에 묶는 script API는 없으니 `button_mappings`를 쓴다.
- **플레이어 인벤토리 미리보기**: 커스텀 chest JSON UI 폼에서는 볼 수 없다. 엔티티 컨테이너(예: 라마 인벤토리)로 우회한다. 서버 폼은 인벤토리를 보이거나 드래그로 방어구를 입힐 수 없다(인벤토리의 방어구 목록을 버튼으로 보여 장착시키는 방식으로 우회). `inventory_items` collection은 화면 전용이라 `flying_item_renderer`와 재사용할 수 없다.
- **슬롯 텍스트**: 아이템 이름이나 lore를 `#hover_text`로 읽는다. 컨테이너에서는 `§o§f<name>§r§r§r`로 감싸이므로(`§o`는 이름을 바꿨을 때만. lore가 있으면 `'§o§f' + name + '§r\n§5§o' + lore`) 떼어 낸다: `(#hover_text - ('%.6s' * #hover_text))` 또는 `(#hover_text - '§' - 'r' - 'o' - 'f')`. 이름에서 동적 텍스처 만들기: `('textures/ui/EXPbar' + (#hover_text - '%.6s' * #hover_text))`. 슬롯 상태는 스크립트가 정한 아이템 이름으로 감지한다(lang 키 말고).
- **`#hover_text` 주의**: 클릭이나 상호작용을 하면 비므로 `visibility_changed` override로 스냅숏을 남긴다. 드롭 매핑을 쓰면 이 문제를 피한다. 숨긴 아이템의 lore와 내구도를 텍스트/표시 채널로 쓸 수 있다. 폴링하지 말고 바뀐 슬롯만 갱신한다. 기본 스택 수를 숨기고 1000 → 1K처럼 바꿀 수 있다. hover text에서 `#entity_id`를 만들려는 시도는 서식 코드 때문에 실패했다는 보고와 성공 보고(chest_boat)가 섞여 있다. collection `#hover_text`를 `visibility_changed` + `binding_name_override`로 보존하려다 라벨까지 사라졌다는 실패 보고도 있다. `#inventory_stack_count`는 아이템이 1개면 값이 없고, 숫자 비교는 `(0 + #inventory_stack_count) = 4`처럼 해야 한다(`#inventory_stack_count = 4`는 늘 false). **conflicting**
- **진행바 트릭**: 아이템 이름을 숫자로 정하고(모루/스크립트) 숨긴 chest 슬롯(`collection_index`, `container_items`)의 `#clip_ratio`로 쓰면 프레임마다 아이템을 따로 둘 필요가 없다. chest UI에 진행바를 넣으려면 `small_chest_panel`(또는 `_top_half`)에 `progress_bar@common.progress_bar`를 삽입한다. chest UI에 임의 라벨 텍스트를 넣을 방법은 없어서 내구도를 숫자로 읽는 숨긴 아이템으로 우회한다(무거움).
- **크기와 해상도**: UI는 해상도에 따라 확대/축소되고 위치를 고정할 수 없다. 가장 작은 해상도에 맞추거나 대안을 준다. 바닐라 chest UI는 UI를 고치지 않으면 54칸 중 27칸만 보였다. 컨테이너 제목으로 chest grid 크기를 바꾸려는 시도(`variables` + `$slot_count`, `$grid_size`, `$grid_dims`)는 동작하지 않았다(답 없음). 생존 인벤토리는 교체하거나 슬롯을 추가할 수 없고 겉모습만 바꿀 수 있다. 스크립트로 인벤토리 화면을 바꿀 수도 없다.
- **컨테이너 감지 변수 예**: `small_chest_screen` modifications의 `variables` `insert_back`으로 `{"requires":"(('%.15s' * $container_name) = '§t§o§m§b§r')","$screen_content":"chest.custom"}`.

### Herobrine643928 Chest-UI와 대안
- **Chest-UI**: https://github.com/Herobrine643928/Chest-UI는 ActionFormData + JSON UI로 상자 모양 폼을 만드는 표준 라이브러리다. 스크롤이 안 되고, 잘못 쓰면 다른 UI를 깨뜨린다는 보고가 있다. `ui/_global_variables.json`에서 쓰는 레이아웃을 켜야 한다(`$disable_9_slots_layout` 등. true = 끔). 오래된 사본은 플래그가 꺼져 "dur#00" 잔상이 생긴다. generic_9..54 텍스처는 bedrock-samples에서 가져온다. 아이템 금고를 만들려면 아이템을 dynamic property나 structure에 직접 저장해야 한다. 1:1 상자 UI는 아니다.
- **typeIds 문제**: 바닐라 아이템을 aux/type id로 매핑하는 `typeIds.js`/`typeids.ts`/`constants.js`에 의존한다. 아무 BP에서나 커스텀 아이템을 추가하면 바닐라 id가 밀리고, 새 릴리스마다 낡는다. upstream은 2025-11-18쯤 갱신했다(issue #27). 1.26.13에서도 뒤처졌다. 해결: https://github.com/Mojang/bedrock-samples/blob/main/metadata/vanilladata_modules/mojang-items.json에서 다시 만들거나, `ItemTypes.getAll()`로 런타임에 생성하거나, aux id 대신 실제 텍스처 경로를 쓴다. 잘못된 텍스처는 대개 typeId 오류다.

## Script API 폼 (`@minecraft/server-ui`)

- **기본**: "JS UI"는 따로 없다. 스크립트 UI는 server-ui 폼(ActionFormData, ModalFormData, MessageFormData)이고, 바닐라 화면에 UI를 더하려면 JSON UI가 필요하다. server-ui 2.0.0 stable, 2.1.0-beta(2025-11). 2026-07-06 기준 stable 2.1.0, beta 2.2.0-beta.1.26.32-stable, preview beta 2.2.0-beta.1.26.40-preview.29다. 문서: https://stirante.com/script/server-ui/. AI가 지어낸 `addButtonList`/`getSelectedButtonId`는 존재하지 않는다. 26.60 stable 이후(2026-10-28): stable 2.3.0, beta 2.4.0-beta.1.26.60-stable, preview 2.4.0-rc.1.26.70-preview.21, preview beta 2.5.0-beta.1.26.70-preview.21.
- **ModalForm 값**: `formValues`는 header/divider/label을 포함한 모든 요소에 항목을 가진다(null/undefined). index는 요소 순서와 맞는다. 처음에는 입력이 아닌 요소를 건너뛰도록 바꿨다가 서버 하위 호환 때문에 되돌렸다. 거를 때는 `values.filter(v => v != null)`을 쓴다(`false` toggle 값은 유지. `!== undefined || !== null`은 늘 true). 값은 Submit 뒤에만 오고 실시간 dropdown 콜백은 없다.
- **Text field와 slider**: `ModalFormData.textField(label, placeholder, { defaultValue, tooltip })`(새 모듈. 예전 문자열 세 번째 인자는 오류). `defaultValue`는 문자열이나 RawMessage여야 하고 숫자는 throw하니 `String(Math.floor(n))`. slider는 옵션 객체 `{defaultValue, valueStep}`를 받는다. 길이 제한은 JSON UI로 늘리거나 여러 필드로 나눈다.
- **표시 타이밍**: 명령이나 이벤트에서 폼을 열 때는 `system.run` 안에서 열거나 `await null` 뒤에 연다(`beforeEvents` 핸들러). `playerInteractWithBlock`에서 연 폼은 반복 발생하니 `isFirstEvent`로 막는다. 채팅이나 HUD가 열려 있으면 `cancelationReason === FormCancelationReason.UserBusy`("UserBusy". `userBusy`에서 이름이 바뀜)로 실패하므로 다시 시도한다: `forceShow(form, player, maxRetries=300)`. `FormCancelationReason`은 `@minecraft/server`가 아니라 `@minecraft/server-ui`에서 import한다. 채팅 명령 트리거는 채팅이 늦게 닫히니 `/` 커스텀 명령이 낫다. 첫 스폰 환영 화면에도 같은 재시도를 쓴다.
- **강제 닫기**: `uiManager.closeAllForms(player)`(`UIManager.closeAllForms()`, 처음엔 beta)로 스크립트 폼을 닫는다. DDUI 폼에는 통하지 않는다. 시간이 지나면 ServerForm을 숨기는 기능은 없다.
- **버튼 아이콘**: `.button(text, iconPath)`는 `textures/items/...` 같은 경로를 받는다. 동적 목록은 배열(예: `world.getPlayers()`)에서 버튼을 만들고 `response.selection`을 배열 index로 되돌린다. 본문 최대 줄 수는 JSON UI가 정한다. 계단식 ActionForm(메뉴가 메뉴를 부름)이 흔하다.
- **텍스트**: 제목, header, label에서 `§` 색 코드가 된다. ActionForm 가운데 정렬은 공백이나 JSON UI로 한다(한 사람은 `§\` prefix를 키로 씀). 커스텀 버튼 모양이나 배경은 JSON UI가 필요하다.
- **기타 스크립트 사항**: 스크립트는 번역된 아이템 이름을 읽지 못한다(키만). 인벤토리 검색창 문자열도 읽지 못한다. 엔티티 인벤토리 아이템 "선택"은 클라이언트 전용이다. HUD 채팅을 숨기는 네이티브 API는 없다. 스크립트에 체력 컴포넌트 `minecraft:hunger`는 없다(`player.hunger`도 미확인).

## Data-Driven UI (DDUI, CustomForm)

### 현황과 시기
- **역사**: 2025-11 server-ui의 흔적과 bedrock-apis/bds-docs preview 브랜치의 JSON 스키마(`metadata/json_schemas/client/ddui/1.21.130`)로 처음 알려졌다. 2025-12 alpha 클래스: `DataDrivenScreen.showScreen(player, screenId)`, `DataStore`(`ddui` 상수. getProperty/setProperty/getPropertyPath/setPropertyPath/setClientWritable/subscribe/unsubscribe), `closeAllDataDrivenScreens(player)`(타입은 bds-docs `types/@minecraft/server-ui-bindings_3.0.0-alpha.d.ts`). 실험 토글이 필요하고 없으면 조용히 실패한다. 2026-02 preview, 2026-04 beta, 26.30 stable(2026-06-16)에 들어갔다. 2026-06 내부 DDUI API가 C++로 옮겨졌다.
- **RP 파일 형식(alpha)**: `resource_pack/ddui/root/<file>.json`(최종 화면)과 `ddui/composition/`(재사용 컴포넌트). `format_version 1.21.130`, `minecraft:ui-root`, `description.identifier`, `attribs.root_point: minecraft:screen`, `layout.markup` 태그(`Panel`, `Panel.Text`, `Panel.CloseButton`)를 쓴다. 커스텀 RP 패널은 아직 내부 팩 전용이다. *single report* 26.70.23 preview에서 보인 형식은 `layout`이 `component` 객체 배열이다: `{"component":"minecraft:form.panel","style_id":"modalForm","children":[...]}`, 자식은 `minecraft:form.text`, `form.spacing`, `form.close_button`, `primitive_checkbox`(`checked`), `form.textfield`(`value`, `label`, `max_length`). markup 형식을 대체하는지는 불명이다.
- **할 수 있는 것**: 2026 stable/beta 26.x에서 DDUI는 스크립트의 ActionForm/ModalForm/MessageBox를 대체하는 수준이다. 모든 요소를 섞을 수 있고(버튼 + toggle), 열린 폼의 데이터를 실시간으로 갱신하며, 애니메이션 콘텐츠(이미지 루프, 비디오 같은 프레임: jeanmajid/MCPE-DDUIRenderer)도 보인다. 관리자 패널에 좋다. 공식 문서: https://learn.microsoft.com/en-us/minecraft/creator/documents/scripting/intro-to-ddui.
- **할 수 없는 것과 불만**: 일반 RP로 크기, 배경, 버튼 크기, 폰트, 툴팁 정렬, 닫기 버튼, 위치를 바꿀 수 없다(신뢰된 팩으로 Ore UI 파일 자체를 교체하는 방법은 아래 Ore UI 수정 절에 있다). 좁고 밋밋하며, 출시 때 느렸고, 떨림이 있으며, 스크롤바가 늦게 로드되고, 흐린 폰트를 포함한 여러 Minecraft 폰트가 섞여 쓰인다. `visible`이 자식을 지우지 않는다. 색 코드는 제목과 label에서만 된다(label 색 코드가 안 된다는 보고도 있음). 그리드는 "사각형이 있는 라벨"이다. HUD나 읽기 전용 비차단 오버레이는 아직 안 된다(HUD는 나중에). `cache screen` 제안은 크래시를 냈다. 커스텀 폰트는 레이아웃 파일에서 참조할 수 있지만 공개되지 않았고 하드코딩 폰트만 된다.
- **JSON UI와의 공존**: JSON UI 폼과 DDUI는 호환되지 않는다(JSON UI 파일을 DDUI에 쓸 수 없음). ActionFormData는 버튼 목록에 가장 간단하고 JSON UI로 꾸밀 수 있어서 계속 쓰인다. "DDUI가 꾸밀 수 있게 되면 Action/Modal 폼은 쓸모없어진다"는 것이 커뮤니티 합의다. 예전 action form은 언젠가 deprecated될 수 있다.

### CustomForm API
- **Observable**: 값은 `new ObservableString(text)` / `new ObservableString('', {clientWritable:true})` / `ObservableNumber(0,{clientWritable:true})`(초기 형태 `Observable.create`)로 만든다. `setData()`, `getData()`, `subscribe(cb)`(사용자 입력 컨트롤용)를 쓴다. label에는 observable 자체를 넘긴다(`.label(obs)`. `.label(obs.getData())`는 갱신 안 됨).
- **메서드**: `.label(obs)`, `.header(text,{styleId})`, `.textField(label, obs, {description})`, `.dropdown(label, obs, [{label,value}])`, `.toggle`, `.button`, `.spacer()`, `.divider`, `.closeButton()`, `.image()`(observable과 함께 쓰는 것은 아직 preview. stable에서 한때 동작하지 않음. jaylydev 문서 확인), `.show()`, `form.close()`. 옵션 `ButtonOptions.disabled`, `ToggleOptions.disabled`. `canShow`로 플레이어 로딩을 기다린다. 최근 preview에서 custom form에 아이콘이 생겼다(위치 조정 불가). `ImageOptions.onClick`에는 좌표가 없다(요청됨).
- **실시간 라벨 패턴**: `system.runInterval` 안에서 `obs.setData(newText)`를 부르고 `.show().finally()`에서 interval을 지운다. 값은 tick마다 다시 읽어야 한다(캡처한 상수는 바뀌지 않음).
- **폼 전환**: 버튼 콜백에서 `form.close()` 뒤 `system.run(() => nextForm(player))`. 폼을 변수에 담고 `form.show()`는 따로 부른다(`.show()`의 결과는 Promise라 대입하지 않음).
- **알려진 문제**: 닫기 버튼을 지울 수 없다(버그. 수정 예정). dropdown `DropdownItemData[]` 안 observable `label`은 `setData()` 뒤 갱신되지 않는다(dropdown `description` ObservableString은 갱신됨. 미해결). 한 시간 쓰고 나면 폼이 안 뜨는 오류가 있었는데, `setData`를 try/catch로 감싸고, 열 때마다 observable을 새로 만들고, server-ui 2.0.0을 써 보라는 조언이 있었다. `ItemTypes.getAll()` 전체를 dropdown에 넣으면 게임이 멈추니 약 20개로 자르고 검색 observable로 구동한다. DDUI 화면을 페이드하면서 slider를 실시간으로 제어하는 방법은 답이 없었다.

## Ore UI 수정 (비공식)

- **신뢰된 팩만 읽는다**: Ore UI의 `ui://` 요청은 팩 스택을 먼저 보지만 신뢰되지 않은 팩은 건너뛴다. zip/폴더 팩은 게임과 함께 설치된 것만 신뢰되고, 암호화 접근 전략(`DirectoryPackWithEncryptionAccessStrategy`)은 서명이 없어도 항상 신뢰된다. 그래서 서버가 보내는 암호화 팩(마켓플레이스 형식: magic `0x9BCFB9FC`, AES-256-CFB8, IV = 키 앞 16바이트, gophertunnel `pack.WithContentKey`)이나, 루트에 빈 `content.zipe` 파일을 둔 로컬 팩(키 불필요, 파일은 평문)의 `hbui/` 파일이 바닐라 HTML/JS/CSS를 대체한다. .mcpack은 zip 루트에 `manifest.json`과 `content.zipe`가 있어야 하고 한 단계 깊으면 import가 조용히 실패한다. Windows와 Android 1.26.52에서 시험됐다. 상세: 이 저장소의 `ore-ui-loading/`.
- **범위와 주의**: `gameplay.html`(라우트 5개: death, bedtime, data-driven, trade, pause-menu/dbug-drawer)과 로딩 화면을 바꿀 수 있다. 메뉴 쪽 `index.html`(라우트 116개: main-menu, play, edit-world, export-world, oreui-settings 등)도 전역 리소스 팩으로 바꿀 수 있고, 게임을 재시작해야 적용된다. ## 렌더러 (엔티티, 아이템, 구조물)

- **`live_player_renderer`**: `{"type":"custom","renderer":"live_player_renderer","property_bag":{"#entity_id":"<id>"}}`. id는 `player.id`이고 장비를 자동으로 보인다. 늘 들고 있는 아이템을 보이고 커서를 따라간다. 스피어 업데이트(2025-12) 뒤 일부 아이템을 들면 커스텀 attachable이 숨겨졌는데, 높은 layer(10은 됐고 100/500은 안 됐고 999는 됨)로 고쳤다. 항상 렌더하게 강제할 수 없다(`hud_player_renderer`도 마찬가지). 여러 엔티티를 동시에 렌더하는 live 렌더러는 없다(버튼마다 entity id 전달).
- **`live_horse_renderer`**: 어떤 화면에서든 `#entity_id`(Script API `entity.id`)로 렌더한다. id는 **문자열**이어야 한다. 숫자만 있으면 숫자로 바뀌어 실패하므로 subtitle/`#form_text`(`.body()`)로 원본을 넘긴다. `property_bag {"#look_at_cursor": true}`. 커서를 늘 따라가고(폼에서. 커서가 소비되는 HUD에서는 아님) 끌 수 없다. 플레이어 모델을 방어구와 함께 보일 수 있다. 엔티티는 플레이어 근처에 스폰되어 보이는 상태여야 하고, 스케일 트릭은 UI에 영향이 없다. 모델을 바꾸려면 엔티티 property나 NPC 모델로 render controller를 바꾼다.
- **`profile_image_renderer`**: `#profile_image_options`에 JSON 문자열(`{"type":N,"userId":"..."}` 또는 `{"type":7,"url":"https://..."}`)을 바인딩해서 프로필 이미지를 그린다. `property_bag`과 view 바인딩으로 덮어쓸 수 있다. 2026-10-27 기준 type: 0 없음, 1 MinecraftHeadshotByXuid, 2 MinecraftHeadshotByPlayfabId, 3 MinecraftAvatarByXuid(안 된다는 보고), 4 MinecraftAvatarByPlayfabId, 5 XboxLiveSmallGamerpicByXuid, 6 XboxLiveSmallGamerpicByUrl, 7 XboxLiveFullClubsImageByUrl(임의 URL 이미지), 8 MinecraftSkinByXuid(안 됨), 9 MinecraftSkinByPlayfabId. 2025-02의 번호와 달라서 버전마다 바뀌는 것으로 보인다. 캐시 여부는 모른다. type 7은 hud_screen을 포함한 모든 화면에서 된다. 16:9는 됐고 5:1 배너는 안 됐다. 요청이 같아도 일부 CDN은 그려지지 않고 Cloudflare R2는 됐다. `property_bag`이 있어야 됐다는 보고도 있다. *single report*(type 표) [보충 2026-10-26..11-04]
- **`paper_doll_renderer`**: 자기 자신을 렌더한다(움직임과 방어구 없음, 망토 보임, 투명화와 4D 스킨 영향). `pause_screen.json`에서 가져온다. `starting_rotation: 0` + drop gesture 바인딩으로 회전을 멈춘다. 특정 플레이어 스킨은 UUID + paper_doll, `use_skin_by_name`은 스킨 uuid를 받는다. paper doll에는 커스텀 geometry를 쓸 수 없다. 작은 패널에 `clips_children: true`로 넣으면 플레이어 머리를 보일 수 있다. 플레이어 geometry 뼈를 `query.is_in_ui`로 바꿔 3D UI를 만들 수 있다. 속도계는 player.entity.json + paper doll + `query.ground_speed`(render controller 2개)로 만든다.
- **아이템 렌더러**: `renderer: inventory_item_renderer`(또는 `item@beacon.item_renderer`, `common.item_renderer`)에 `#item_id_aux`(property_bag `{"#item_id_aux": 0}` 필요). aux = 숫자 id * 65536 + data, 마법 부여는 +32768. 블록은 잘 되고, 아이템은 offset이 필요하다(raw aux id가 아님). grid 레이아웃 안에서만 되고 스크롤 패널이나 factory 안에서는 안 된다는 보고가 있다. 2026-01에 명시 aux가 엉뚱한 아이템(켈프, 피스톤)으로 보인 문제는 property bag 문자열(`"#id_aux":"@21954560"` + `(#id_aux - '@')`)로 우회했다. layer 100이면 아이템이 숨고 4/50은 괜찮았다. 컨테이너의 `common.item_renderer`는 많은 블록/아이템에서 layer를 무시한다(미해결).
- **aux id 주의**: aux id는 버전과 설치된 애드온에 따라 밀려서 애드온을 가로질러 런타임에 계산할 수 없다. 아이템 id를 직접 얻을 방법도 없다(공식 목록: learn.microsoft.com 바닐라 목록. 스피어 없음). aux id에서 이름을 얻는 것도 불가능하다. 모바일에서는 aux가 불안정하다. 폼 버튼 사용 예: `.button("§f§l§a§g§0§r", "aux:65536")` + `('%.4s' * #texture = 'aux:')`, `(#texture - 'aux:')` → `#item_id_aux`. 성능은 아이템 렌더러가 구조물 렌더러보다 낫다. 동적 아이템/블록 아이콘 API는 없으니 텍스처 경로를 참조한다.
- **`3d_structure_renderer`**: `type:"custom"`에 property_bag `#block_position`, `#top_right_block`, `#bottom_left_block`(배열 [x,y,z]), `#include_entities`, `#remove_blocks`, `#include_players`를 준다. 영역이 로드돼 있어야 하고, 큰 영역은 게임을 멈추게 하며, 배열은 조작할 수 없다. .mcstructure 미리보기용 script API는 없다. 3D 블록 렌더는 하드코딩이라 아이템 렌더러나 미리 찍은 스크린샷(Blockbench)을 쓴다.
- **기타 렌더러**: `bundle_tooltip_renderer`(gameplay_common.json, 컨트롤 `bundle_tooltip`)로 화면에 잘리지 않는 커스텀 툴팁을 만들 수 있다. 다만 부모 크기를 따르고 터치/작은 화면에서 튀며, 12칸 넘는 grid는 깨진다. `progress.progress_bar_renderer`는 내구도 바 렌더러다(모양 고정, `#color`). 바닐라 `durability_bar`는 `property_bag {"drop_shadow": true, "is_durability": true, "round_value": true}`에 `#item_durability_visible`/`#item_durability_total_amount`/`#item_durability_current_amount`를 `#touch_progress_bar_visible`/`#progress_bar_total_amount`/`#progress_bar_current_amount`로 override한다. 내구도 값을 텍스트로 꺼내는 방법은 나오지 않았다(float 출력 추정). paper doll 렌더 경로를 쓰는 미니맵은 일시정지 화면을 열 때 로그가 폭주해 크래시 직전까지 갔다. `web_view_renderer` 예: https://github.com/Xterionix/extended-bedrock-samples/blob/4289aa5550c18608e25f9487f89b766d82168f7c/resource_pack/ui/code_screen.json#L236.
