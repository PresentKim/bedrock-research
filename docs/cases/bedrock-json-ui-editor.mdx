## 이것은 무엇인가

w1zardz의 `bedrock-json-ui-editor`는 순수 HTML/CSS/JS(`app.js` 1,528줄) 한 페이지 앱이다. JSON UI 파일 하나를 붙여 넣으면 컨트롤 트리와 미리보기를 보여 주고, 미리보기에서 상자를 끌거나 화살표로 밀면 `offset`을 다시 써 준다. 목적은 이미 있는 HUD·스코어보드 요소의 **위치 미세 조정**이고 새 화면 설계 도구가 아니다. 분석 기준은 커밋 `9cb4896`(2026-08-29)이다. 저장소에는 `LICENSE` 파일이 없고 README에 "MIT"라고만 적혀 있다(클론에서 확인). 라이선스가 불명확하므로 코드와 문장을 옮기지 않고 사실만 적는다(출처: cs-w1zardz-editor). 앱 자체를 실행해 보지는 않았고 코드를 읽어 정리했다.

## 기능

| 기능 | 내용 |
| --- | --- |
| 미리보기 화면 | 데스크톱 427×240, 폰 520×240, 태블릿 320×240 **UI 픽셀**로 그리고 창 폭에 맞게 확대한다. 게임 스크린샷을 반투명하게 깔 수 있고 화면 밖은 빗금으로 표시한다 |
| HUD 안내선 | 핫바 182×22(하단 중앙, y −2), 체력·허기 81×9(하단 중앙 ±50, y −25), 로고 27×27(우하단), 채팅 200×60(좌상단 +2,+2), 사이드바 96×90(우측 중앙 x −1) |
| 텍스트 폭 추정 | 공백 4, 일반 글자 6, 팩 글리프(U+E000–F8FF) 9, BMP 밖 10 UI 픽셀, 줄 높이 10 |
| 바인딩 텍스트 | `#`·`$`로 시작하는 `text`는 사용자가 정한 예시 문자열로 그림 |
| 상속 | `이름@ns.base`에서 namespace를 버리고 같은 파일 안에서 `base`를 찾아 얕게 합침 |
| 편집 | 끌기, 화살표(Shift는 ×10), 0.5~20px 단계 스냅, 실행 취소, 클립보드 복사·파일 저장 |

## 레이아웃 해석이 엔진과 다른 곳

앵커 계산 자체(위치 = 부모 위치 + `anchor_from` 비율 × 부모 크기 − `anchor_to` 비율 × 자기 크기 + offset)는 우리 LAY-16과 같다. 나머지는 다르다.

| 항목 | 이 편집기 | 가이드와 바닐라 |
| --- | --- | --- |
| `anchor_to` 생략 | `anchor_from`과 같다고 본다. `anchor_from` 생략은 `center` | 바닐라는 99.6%가 둘 다 적는다. 도구마다 가정이 다르다(반영안 LAY-45) |
| `"100%c"` | 가장 큰 자식 × 계수 | 스택 진행 축에서는 보이는 자식의 합(LAY-03) |
| `"50%cm"` | 가장 큰 자식 × 0.5 | 계수 무시, 최대값 자체(LAY-37) |
| `"100%sm"` | 부모 크기 × 계수로 대체(자체 주석에 근사라고 적음) | 가장 큰 형제 |
| `"default"` | 모든 타입에서 내용 크기 | 패널은 100%, 라벨은 텍스트 크기(LAY-03, C-36) |
| `"fill"` | 숫자로 읽지 못해 20픽셀 | 스택에서 남은 공간, 진행 축 밖은 0(LAY-39) |
| 스택 자식 | 자기 `offset`·앵커도 그대로 적용 | `offset` 무시, `use_child_anchors` 없으면 앵커도 무시(LAY-38) |
| 숨은 스택 자식 | 자리를 준다 | 숨은 자식은 자리를 차지하지 않는다(LAY-04) |
| `"wrap_content"` | `%c`처럼 처리 | 바닐라 205개 파일에서 0회. 엔진에서의 뜻은 근거 없음 |
| 크기 식 | `%` 항 하나와 `px` 항 하나만 읽는다 | 여러 항, 부호가 다음 부호까지 이어짐(LAY-35) |

그래서 이 도구의 미리보기는 **앵커와 고정 픽셀 offset으로 놓이는 HUD 요소**에서만 믿을 수 있고, `%c`, `fill`, 스택 패널 안 위치는 엔진 규칙(LAY-03, LAY-37, LAY-38)으로 직접 계산하거나 게임에서 확인해야 한다. 이 판정이 충돌 C-51(해소: 가이드 유지)이다. 가이드 쪽 근거는 바닐라 용례와 Cinnabar 재구성의 테스트(G06, G07, S04)다.

HUD 안내선 수치는 작성자가 스크린샷에 맞춘 값이다. 바닐라 `hud_screen.json`의 `hotbar_panel`은 `["100%c", 22]`, `bottom_middle` 앵커, offset 없음이고 슬롯은 20×22, 보스 체력 막대는 182×20이다. 핫바 폭 182는 대략 맞지만 y −2의 근거는 바닐라에서 찾지 못했다(미검증). 화면 크기 세 가지는 "높이 240 UI 픽셀"을 기준으로 종횡비만 바꾼 값이고 JsonForge는 384×216을 가정한다. 실제 UI 픽셀 크기는 창 크기와 GUI 배율에 따라 달라지므로 어느 값도 고정이 아니다. 바닐라 `ui_common.json` 주석은 최소 가상 화면을 포켓 320×210, 데스크톱 376×250으로 적는다(반영안 LAY-47).

## 쓰는 법

1. 배포 주소를 연다. 설치가 필요 없고 오프라인으로도 동작한다.
2. 앵커와 픽셀 offset으로 놓인 HUD 컨트롤을 고를 때만 미리보기 위치를 믿는다.
3. 대상 기기와 배율의 게임 스크린샷을 깔아 GUI 배율·기기 차이를 줄인다.
4. 내보낸 JSON에 `wrap_content` 같은 바닐라에 없는 값이 들어가지 않았는지 스키마 검사로 확인하되, 스키마 검사가 거짓 오류를 많이 낸다는 점도 알아 둔다(디버깅 규칙).

## 우리 규칙과의 관계

| 규칙 ID | 관계 |
| --- | --- |
| LAY-03, LAY-37, LAY-38, LAY-04 | 이 도구가 어긴 엔진 규칙의 근거(가이드 유지, C-51) |
| LAY-16, LAY-17 | 앵커·offset 계산은 일치 |
| LAY-47, LAY-45(반영안) | 화면 UI 픽셀 크기, `anchor_to` 생략 기본값 |
| DBG-28, DBG-29 | 편집기 미리보기는 근사로만 쓴다 |

## 한계와 실측 과제

미리보기를 엔진과 대조하려면 기기·배율별 화면 UI 픽셀 크기, 기본 글꼴 글자 폭(일반 6, 공백 4)과 줄 높이(10), `wrap_content`가 오류를 남기는지를 게임에서 재야 한다. 배포 페이지가 저장소 `9cb4896`과 같은 판인지도 확인하지 않았다.
