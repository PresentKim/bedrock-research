## 이것은 무엇인가

Premium Damage Indicator v1.1은 제작자 GAVTI가 MCPEDL에 올린 애드온(`Premium_Damage_Indicator_v1.1.mcaddon`, 54.54 KB, 게시 2026-09-15, 갱신 2026-09-28, 지원 버전 표기 26.30)이다. 타격마다 대미지 숫자가 떠오른다(일반 흰색, 치명타·철퇴 빨간색). **이 애드온은 JSON UI를 전혀 쓰지 않는다.** `ui/` 폴더도 없다. 대미지 숫자를 HUD가 아니라 **월드 공간 파티클**로 그리고, 숫자 글리프 아틀라스(PNG 한 장)를 파티클 UV로 잘라 쓰며 스크립트가 글자 하나당 파티클 하나를 공격한 플레이어에게만 띄운다. 그래서 이 페이지는 "JSON UI가 맞지 않을 때 무엇을 쓰나"의 재료다.

분석은 첨부 파일 7개를 모두 열람해 했고 MCPEDL 페이지에는 소개 한 문단뿐이라 구현 설명이 없었다. 파일의 라이선스 표기가 없어 코드를 옮기지 않고 사실만 다시 썼다(출처: cs-damage-indicator). 게임 안 실측은 하지 않았다. manifest의 `min_engine_version`은 `[1, 26, 40]`이고 MCPEDL은 "26.30"이라 표기가 어긋난다. 26.30 클라이언트에서 실제로 로드되는지는 실측이 필요하다.

## 구성과 흐름

| 경로 | 내용 |
| --- | --- |
| BP `manifest.json`, `scripts/main.js`(6.1 KB) | `@minecraft/server` 2.9.0, 이벤트 구독, 치명타 판정, 파티클 배치 |
| RP `particles/damage_glyph.json` | 파티클 `pdi:damage_glyph`(format_version `1.26.10`) |
| RP `textures/particle/pdi_damage_glyphs.png` | 1024×64 RGBA 글리프 아틀라스 |

스크립트는 `playerSwingStart`, `entityHitEntity`, `entityHurt`를 기록해 `entityHurt` 원인이 근접 공격이나 철퇴 강타이고 공격자가 플레이어일 때 다음 틱에 ±4틱 이내 기록과 맞춰 치명타를 OR 결합한 뒤 `event.damage`를 소수 둘째 자리로 반올림해(`-7`, `-12.5`) 글자마다 `attacker.spawnParticle("pdi:damage_glyph", pos, vars)`를 부른다. 치명타 판정은 `isFalling`이고 물·등반이 아닐 때 등의 서버 상태 휴리스틱이라 빗나갈 수 있다. 화살·폭발 등은 표시하지 않는다.

## 핵심 기법

### 1. 글리프 아틀라스를 Molang 변수로 고른다

아틀라스는 가로 1024, 세로 64로 64px 정사각 셀 16칸이 있고 `0`~`9`, `-`, `.`의 12칸만 쓴다. 글자를 흰색으로 그려 두고 색은 파티클 틴트로 입히므로 텍스처 한 장으로 여러 색을 낸다. 파티클 정의 하나가 모든 글자를 처리한다.

```jsonc
// 기법을 설명하기 위해 새로 쓴 예시 (원문 아님)
"minecraft:particle_appearance_billboard": {
  "facing_camera_mode": "lookat_xyz",
  "uv": { "texture_width": 1024, "texture_height": 64,
          "uv": ["variable.glyph * 64", 0], "uv_size": [64, 64] }
}
```

스크립트는 `MolangVariableMap`에 `variable.glyph`(0~11), `variable.scale`(일반 1.0, 치명타 1.13), `setColorRGBA("variable.tint", …)`를 넣는다. `setColorRGBA`는 `variable.tint.r/.g/.b/.a` 네 개로 풀린다. 그라디언트에서 RGB는 이 변수를, **알파만** 0 → 1 → 1 → 0 키프레임(수명 앞 8%에 나타나고 뒤 28%에서 사라짐)으로 주어 색 지정과 페이드를 분리한다. 반투명이 필요하므로 `material: particles_blend`를 쓴다(`particles_alpha`는 컷아웃). 크기는 수명 동안 `sin(0→π)`로 최대 10% 부풀었다 돌아와 톡 튀는 효과를 낸다. 움직임은 `initial_speed [0, 0.22, 0]`, `linear_acceleration [0, 0.08, 0]`, `linear_drag_coefficient 0.9`로 천천히 떠올랐다 감속한다.

### 2. 글자 배치

공격자의 시선을 XZ 평면으로 정규화한 `view`에서 `right = (-view.z, 0, view.x)`를 구하고, 글자를 `(i - (len-1)/2) * 0.155`만큼 `right`로 밀어 가운데 정렬한다. 시작점은 피해자 머리에서 공격자 쪽으로 0.28 당기고 0.08 아래다. 연타 시 후보 오프셋 9개 중 최근 5개 위치와 가장 먼 것을 고른다.

### 3. 공격자에게만 보이기

`world.spawnParticle`이 아니라 `attacker.spawnParticle`을 쓴다. 코드 주석이 "Only the attacker sees the indicator"라고 밝힌다. `Player.spawnParticle`은 그 플레이어 클라이언트에만 보내는 API라 멀티플레이에서 남의 숫자가 보이지 않는다(추론).

## JSON UI HUD 재스킨과의 비교

| 항목 | 이 애드온(월드 파티클) | JSON UI HUD 재스킨 |
| --- | --- | --- |
| 위치 | 피해자 머리 위 3D 공간 | 화면 고정 좌표. 엔티티를 따라가지 못함 |
| 데이터 통로 | `MolangVariableMap`으로 숫자 직접 전달 | `setTitle`/`setActionBar` 문자열 + 플래그 접두사 |
| 다른 애드온과 충돌 | 없음 | title/actionbar는 슬롯 하나라 덮어씀 |
| 동시 표시 | 제한 없음 | 채널당 하나 |
| 숫자 렌더링 | 텍스처 글리프 + UV | 라벨 텍스트(문자열 + float 결합은 안 나옴, TXT-06) |
| 상호작용 | 불가(표시 전용) | 클릭·포커스·스크롤 가능 |
| 가려짐·거리 | 블록·엔티티 뒤로 가려지고 거리에 따라 작아질 수 있음(추정) | 항상 최상단, 거리 무관 |
| 필요 파일 | 파티클 JSON 1 + PNG 1 | `ui/hud_screen.json` 수정 등 |

바닐라 UI 파일을 하나도 건드리지 않으므로 팩 호환 문제가 원천적으로 없다. 반면 bedrock-core의 상자 화면이 "스택 수량 → 번역 키 → 글리프"로 한 슬롯에 한 글자를 그리듯, 이 애드온은 "Molang 변수 → UV 오프셋 → 글리프"로 한 파티클에 한 글자를 그린다. 둘 다 텍스트를 직접 못 그리는 표면에 숫자 코드로 글자를 고른다. 문자표도 고정(64자 대 12자)이고 문자표 밖 글자는 버린다. 파티클 정의는 정적이고 런타임은 값만 바꾸므로 "모양은 고정, 값만 바뀐다" 원칙과 같다([bedrock-core](./bedrock-core.mdx) 참고).

## 우리 규칙과의 관계

| 규칙 ID | 관계 |
| --- | --- |
| ALT-01 | 3D 위치를 따라가는 표시는 JSON UI로 만들 수 없다. 파티클이나 엔티티를 쓴다(지지) |
| HOST-14 | 타이틀 채널이 하나라 겹치는 알림에 약하다는 대조 근거 |
| TXT-06 | 라벨에 float 숫자를 직접 그릴 수 없다는 제약이 파티클 선택의 한 이유 |

## 한계

글자 수만큼 파티클이 생겨 범위 공격으로 여러 마리를 치면 파티클 수가 빠르게 는다. 파티클은 깊이 테스트를 받아 가려질 수 있다. 위의 가려짐·거리·치명타 정확도·`@minecraft/server` 2.9.0 안정판에 모든 이벤트가 있는지는 모두 실측이 필요하다.
