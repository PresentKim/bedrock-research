## 이것은 무엇인가

LeGend077(Chest-UI 원작자)이 커뮤니티에서 답해 온 예제를 모은 저장소다(HEAD `d4ff500` 2026-02-28, 커밋 59개). **manifest가 없는 스니펫 모음**이라 팩으로 설치해 확인할 수 없고 어느 버전에서 동작했는지 적혀 있지 않다. JSON 파일 7개(`custom_progress_bar.json`, `custom_heart_or_hunger_like_progress_bar_icons.json`, `size_offset.json`, `custom_slider.json`, `custom_toggle.json`, `custom_npc_screen_layout_reference_file.json`, `scroll_panel_template.json`)와 README 스니펫 28개(그중 13개는 커뮤니티 링크뿐)로 이루어져 있다. 클론의 `LICENSE`를 열어 확인한 라이선스는 MIT(Copyright 2025 LeGend)라 발췌할 수 있다(출처: cs-json-ui-examples). 근거 수준은 "작동팩"이 아니라 **"예제, 미검증"**이다. 바닐라와 Cinnabar로 뒷받침되는 부분만 수준을 올린다.

## 파일별 기법

### HUD 타이틀로 체력 막대 (`custom_progress_bar.json`)

`#hud_title_text_string`을 `#preserved_text`로 받아 `hp:` 접두일 때만 값을 갱신하는 위키 "Preserve Title Texts" 패턴이다(새 기법 아님). 값은 `((#preserved_text - $update_string) * $one)`이고 막대는 `clip_direction: left`, `#clip_ratio` ← `(($max_health - #health) / $max_health)`에 `"$max_health": 20.0`을 쓴다. **Cinnabar 해석에서는 `((20.0 - #health) / 20.0)`이 정수 나눗셈이라 0**이 된다(C-53). 점으로 시작하는 리터럴을 곱하는 방식(`.05`)이 안전하다(EXP-27, ANI-03).

### 하트 아이콘 10개

아이콘 칸 하나가 `$condition`(2, 4, …, 20)을 받아 `((#health_value = $condition) or (#health_value > $condition))`이면 가득 찬 하트, `(#health_value = $condition_half)`이면 반 하트를 보인다. 값은 한 번 계산한 `data_control`에서 `source_control_name` + `resolve_sibling_scope: true`로 읽는다. `>=` 대신 `or`로 푼 것은 EXP-03과 맞는다.

### 슬라이더로 크기·위치 움직이기 (`size_offset.json`)

시작 화면에 `modifications insert_back`으로 정적 슬라이더 4개와 패널 하나를 넣고, 슬라이더 값을 패널의 `#size_binding_x/y`와 `#anchored_offset_value_x/y`로 연결한다. 다음이 그 바인딩과 `property_bag`이다.

<Excerpt src="json-ui-examples" title="json-ui-examples, size_offset.json" path="size_offset.json">

```jsonc
"property_bag": {
  // max value is 1.0 - meaning 100% of size of element.
  "#size_binding_x": 0.0,
  "#size_binding_y": 0.0,
  // these are offsets related to anchoring and parent's size. max value is 1.0
  "#anchored_offset_value_x": 0.0,
  "#anchored_offset_value_y": 0.0
},
"bindings": [
  { "binding_type": "view", "source_control_name": "size_x",
    "source_property_name": "( (#slider_value + 1) / 10 )",
    "target_property_name": "#size_binding_x" },
  { "binding_type": "view", "source_control_name": "offset_x",
    "source_property_name": "( ( #slider_value ) / 10 )",
    "target_property_name": "#anchored_offset_value_x" }
]
```

</Excerpt>

주석은 크기 바인딩 값을 "요소 크기의 비율(최대 1.0)", 오프셋을 "앵커와 부모 크기에 관련"이라 설명하는데 이는 LAY-10(부모 크기의 배수)과 같은 해석이다. 가이드와 다른 점 둘이 있다.

1. **정적 컨트롤의 앵커 오프셋.** 가이드 표는 정적 컨트롤에서 `#anchored_offset_value`가 안 된다고 한다(BC-S12 실측). Cinnabar는 `use_anchored_offset: true`이고 `anchor_from`이 `center`가 아니면 값 × 부모 크기만큼 민다. 이 예제는 `top_left` 앵커를 쓴다(충돌 C-61, 미해결. 가설: S12가 중앙 앵커였다).
2. **정적 슬라이더.** HOST-12는 슬라이더를 정적으로 배치하면 안 된다고 하나 근거(BC-S8·S9)는 **서버 폼 아래에 숨긴 채 생성된 슬라이더**의 assert다. 시작 화면에 정적으로 두는 이 예제와 바닐라 설정 화면까지 금지하는 근거는 아니므로 HOST-12의 범위를 서버 폼 하위 화면으로 명시하는 보강이 제안되었다. 슬라이더 값 타입도 주의: Cinnabar에서 사용자가 움직인 뒤 값은 실수지만 `property_bag` 초기값 `5`는 정수라 첫 프레임에는 `((5 + 1) / 10)` = 0이 된다. 단계 슬라이더의 `#slider_value`는 0~1 비율이 아니라 단계 번호다.

### 그 밖의 파일

- `custom_slider.json`: `#slider_value` → `(#val * 1)` → `/ 10` → `#alpha`. 바인딩 alpha가 0과 1만 적용된다는 실측(LAY-13, C-45)과 같은 실험 대상이다.
- `custom_toggle.json`: `"$toggle_view_binding_name@$template_toggle": {}`로 자식 이름과 기반 정의를 둘 다 변수로 준다(FILE-15, FILE-36). 상태 텍스처 8개 변수는 바닐라 `common.toggle` 그대로다.
- `custom_npc_screen_layout_reference_file.json`: `npc_screen_contents`에서 `remove control_name: "student"` 후 `insert_front`로 자기 패널을 넣는다. 바닐라에서 `student`가 `npc_screen_contents`가 **직접 선언한 자식**이라 MOD-05에 걸리지 않는다. 제목에 `MENU`가 있으면 자기 레이아웃, 없으면 바닐라 학생 패널을 보인다(EXP-07, HOST-15).
- `scroll_panel_template.json`(fumeko 기여): 바닐라 `common.scrolling_panel`을 거의 그대로 복사하고 크기·오프셋 변수 11개를 노출한다. 역할 컨트롤 이름을 `scroll_view` 속성으로 지정하며 트리 위치는 자유롭다(LAY-42와 맞는 작동 예).

## 실측 필요

`top_left` 앵커 정적 패널의 `#anchored_offset_value`(중앙 앵커와 비교), 3x3 핫바 스니펫과 `grid_dimension_binding`을 지운 판의 비교, 단계 슬라이더 `#slider_value`의 타입과 범위, 닫을 수 없는 폼이 Esc·B·뒤로가기를 모두 막는지, `grayscale: true`와 `color` 틴트의 차이, `prevent_touch_input`이 HUD 버튼의 터치 표시를 막는지.
