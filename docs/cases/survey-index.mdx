## 조사의 범위와 방법

2026-10-22의 추가 조사는 이미 따로 분석한 8건(bedrock-core, AdvancementPack, BedrockAdvancements, Premium Damage Indicator, mcbejsonuimasterAI, Bedrock Wiki, Ore UI Customizer, Cinnabar)을 뺀 JSON UI 관련 라이브러리·도구·문서·공개 팩을 훑었다. GitHub 토픽 `json-ui`·`jsonui`, 영어·중국어·일본어·한국어 웹 검색, npm 레지스트리, Microsoft Learn 원본 저장소, NetEase 문서 미러 저장소를 찾아본 곳이다. 대조 기준은 종합 가이드(조사 시점 규칙 340개, 충돌 C-01~C-47)와 바닐라 `bedrock-samples` `46ba6ea`(1.26.50.4)다. **후보 31건을 확인해 그중 15건은 자료별 분석 문서를 따로 썼고** 나머지는 이 표에 짧게만 적었다. 게임 실측은 하지 않았고 주장은 바닐라 전수 검색, 스키마 검증 스크립트, Cinnabar 평가기 실행으로 판정했다(출처: repo-survey). 가치는 상(가이드 규칙을 바꾸거나 새 기법이 여럿), 중(새 기법 일부나 도구로서 쓸모), 하(참고·오류 표본)다.

가이드에 가장 큰 영향을 준 발견은 여덟 가지다.

1. **`grid_position`은 `[열, 행]`이다.** 바닐라 그리드 20곳이 모두 `grid_dimensions [열 수, 행 수]`와 자식의 첫 값(열)이 맞는다. LAY-29의 `[행, 열]`은 틀렸다.
2. **아이템 숫자 ID가 26.40에서 다시 배치됐다.** Chest-UI의 "26.40 Update"가 경계를 256에서 850으로 옮기고 다이아몬드를 335에서 306으로 바꿨다. C-33이 "버전마다 표가 바뀐다"로 정리된다.
3. **정수 나눗셈으로 나머지를 만들 수 있다는 주장**(AsaJS)이 EXP-20과 충돌한다(C-52).
4. **공개 스키마와 편집기는 바닐라 기준으로 많이 틀린다.** Blockception 스키마는 바닐라 205개 파일 중 193개에서 거짓 오류 2,251개를, KalmeMarq 스키마는 186개 파일에서 2,224개를 낸다. 도구는 자동 완성·탐색용으로만 쓰고 오류 표시는 믿지 않는다.
5. **NetEase(중국판) 문서**가 화면 속성, HUD F1 숨김 바인딩, `scrolling_panel`의 `$touch` 분기, namespace 없는 `@이름`의 문맥 의존 해석을 알려 준다.
6. **Microsoft Learn의 JSON UI 레퍼런스는 AI 생성이라 틀린 곳이 많지만**, 변경 기록(1.26.0 `priority` 바인딩과 배율 통합, 1.26.30 `§w`)과 협력형 애드온 지침(`ui/` 덮어쓰기 금지)은 쓸 만하다.
7. **서버 폼 레이아웃 라이브러리의 새 기법.** StarLibV2는 버튼 문자열 키로 2차원 배치를 만들고, 텍스트 상자의 `#item_name`으로 실시간 검색 필터를 건다.
8. **애니메이션 결과 연출.** upgrader는 미리 그린 프레임의 `aseprite_flip_book` 텍스처를 바인딩해 결과별 연출을 고르고 마지막 프레임을 길게 해 끝에서 멈춘다.

## 라이선스 처리

MIT·BSD·CC BY는 출처를 밝혀 짧은 예제를 쓸 수 있다(Chest-UI는 출처 표기 필수). GPL-3.0(AsaJS, StarLibV2)은 코드를 가이드나 상업 팩에 옮기지 않고 기법만 다시 썼다. 라이선스 없음(KalmeMarq·DJStompZone 스키마, upgrader, Cermada, NetEase 문서, GrimUI, Sidebar-HUD, w1zardz 불명확)은 문장·코드 복사 없이 사실만 바닐라로 다시 확인했다. CC BY-ND(Sidebar-Mcbe)는 변형 배포 금지라 요약만 했다. 이 위키의 각 사례 페이지는 클론에서 실제 `LICENSE` 파일을 열어 확인한 결과를 레지스트리에 적었고, 발췌(`Excerpt`)는 재배포가 가능한 자료에서만 했다.

## 가이드 반영안의 규모

| 항목 | 반영 전 | 반영안 적용 후 |
| --- | --- | --- |
| 규칙 | 340개 | 406개(+66), 기존 규칙 74개 보강 |
| 충돌 | C-01~C-47 | C-01~C-63(+16), 기존 C-04·C-06·C-33·C-37 갱신 |
| 실측 필요 목록 | 28개 | 58개 |
| 출처 약어 | 13개 | +18 |

새 충돌 판정 요약: C-48 `grid_position`은 `[열, 행]`(해소), C-49 오른쪽·아래 앵커 offset 부호는 뒤집히지 않음(해소), C-50 바닐라 같은 경로 팩 파일은 병합(해소), C-51 내용 기준 크기·스택 배치는 가이드 유지(해소), C-52 정수 나눗셈 나머지(부분 해소, 실측 필요), C-53 JSON 실수 변수(미해결), C-54 `#item_id_aux` 번호 체계(미해결), C-55 namespace 없는 `@이름`(미해결, 항상 `ns.이름`), C-56 `resolve_sibling_scope` 없을 때 검색 범위(해소), C-57 바닐라 경로 사본의 `_ui_defs` 등록(불필요, 해소), C-58 플립북 시작 프레임 키는 `initial_uv`(해소), C-59 `binding_type` 기본값은 `global`(해소), C-60 Microsoft Learn 레퍼런스는 바닐라 채택(해소), C-61 정적 컨트롤의 `#anchored_offset_value`(미해결), C-62 `grid_dimension_binding`을 남긴 그리드(미해결, 속성을 지운다), C-63 값이 공백 하나인 lang 키(미해결). 새로 생긴 절은 입력창 `#item_name`과 검색 필터, 키로 짜는 2차원 배치, 상자 모양 서버 폼 레시피, AI 생성 문서·NetEase 전용 이름·언어 서버·편집기 미리보기·생성기 출력·식 컴파일러·난독화 도구를 믿는 범위다.

다음 작업 후보: JsonEncryptor가 모은 엔진 `$` 변수 약 300개와 팩토리 이름 22개를 값 사전과 대조하는 일, 실측 목록(특히 C-52 나머지 식, C-53 실수 변수, 26.40 이후 아이템 ID 850·851)이다.
