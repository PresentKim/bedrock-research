## 이것은 무엇인가

Cinnabar는 배드락 에디션 호환 비공식 클라이언트다(Rust Bevy/wgpu 클라이언트 + Go 코어). 서버가 보내는 리소스팩 UI를 바닐라처럼 그려야 하므로 **바닐라 JSON UI 해석기를 1:1로 다시 구현**했고, 커밋 기록에 따르면 식 평가기, 변수 스코프, `ignored`, 바인딩 규칙은 26.30 네이티브 클라이언트를 재구성해 옮긴 것이다(커밋 메시지 "26.30 reconstruction", "Port `UIEval`/`ExprToken`/`UiExpression::evaluate`"). 분석 대상은 `cinnabar-mc/cinnabar` `dev` 커밋 `ceb0fb6`(2026-10-21)의 `crates/json-ui`(약 4.7만 줄)이고 클론 HEAD는 그 뒤의 `df826f5`다. 클론의 `LICENSE`를 열어 확인한 라이선스는 **PolyForm Noncommercial 1.0.0**이다. 비상업 목적의 사용·수정·배포는 허용되지만 마켓플레이스 판매용 팩 제작 같은 상업 목적에는 이 소프트웨어(웹 편집기 포함)를 쓸 권리가 없다(출처: cs-cinnabar). 이 페이지는 동작 규칙을 한국어로 다시 썼고 발췌에는 라이선스가 머리에 표시된다.

수준 표기에서 이 자료는 `코드`이고 `CN`이라 부른다. 게임 실측이 아니라 재구성 코드라서 실측과 다르면 실측을 따른다(충돌 C-41~C-47). 이 프로젝트가 평가기를 직접 빌드해 식을 실행한 결과는 `CN-run`이다.

## 바닐라와 같은 것, 다른 것

| 영역 | 같게 만든 것 | 신뢰도 |
| --- | --- | --- |
| 식 평가 | 토큰 분리, 리터럴 타입(int32·float32·문자열·불리언), 우선순위, 타입별 연산, 결과 재해석 | 높음(네이티브 재구성, 실서버 팩 회귀 시험) |
| 변수, `ignored` | 프레임 스코프, `\|default` 조회, 통째 치환만, 바깥 스코프 평가 | 높음 |
| 바인딩 | 종류·조건 enum, 모르는 값의 대체, `view` 검색 범위 | 높음 |
| 상속, JSON 읽기, 팩 병합 | 속성 단위 통째 교체, jsoncpp 규칙, `modifications` 11개 연산 | 중상 |
| 레이아웃 | 크기 식, `%c`/`%cm`/`%sm`, 스택·그리드·스크롤 | 중(저자들이 "생략한 size"와 "anchor_to 기본"을 측정 필요로 남김) |

다른 점(근거로 쓰면 안 되는 것): 기본 게임 HUD는 Java 스타일로 자체 구현, OreUI 화면은 자체 코드, 글꼴은 자체 오픈 글꼴이라 글자 폭이 다름, 고유 확장(`cinnabar_transform`, `cinnabar_filter` 등)은 자체 화면에서만 켜짐, 판정할 수 없는 `ignored`는 남기고 긴 식·깊은 상속은 진단 후 버리는 등 관대하며 바닐라의 assert·크래시는 재현하지 않음(EXP-21류 크래시 식은 판정 불가), 같은 레이어 그리기 순서가 문서 순서로 고정(바닐라는 보장 안 함, LAY-19), 정의를 `namespace`+이름만으로 찾아 "다른 경로 파일 재선언 무시"(FILE-22)와 "`modifications`는 경로 단위"(MOD-02)를 구분하지 않음, `modifications` 대상이 없으면 진단만 남기고 나머지 적용(바닐라는 파일 전체 무효, MOD-05).

## 처리 순서

바닐라와 같이 단계가 나뉜다. 어느 단계에서 무엇이 정해지는지 알면 "왜 이 값은 바인딩으로 못 바꾸나"가 설명된다.

1. **JSON 읽기**: `_ui_defs.json`이 나열한 파일만, 경로를 정렬·중복 제거해 한 번씩 읽는다.
2. **팩 병합**: 팩 순서대로 같은 이름 정의에 속성을 합치고 `modifications`를 적용한다.
3. **상속 평탄화**: `@base` 체인을 펼친다.
4. **해석(resolve)**: 컨트롤마다 `ignored`를 바깥 스코프에서 판정, 자기 `$` 선언과 선택된 `variables`로 스코프 프레임 구성, 속성의 `$변수`·상수 식 치환, 팩토리 선언 기록. **여기까지가 생성 시점이고 `#바인딩`을 모른다.**
5. **바인딩(bind)**: 속성 주머니(`property_bag`)를 만들고 `view` 바인딩을 수렴할 때까지 돌려 컴포넌트에 반영한다. 팩토리·그리드가 인스턴스를 만든다.
6. **레이아웃**: 아래에서 위로 크기를, 위에서 아래로 위치를 정한다.
7. **그리기 명령**: 레이어 순으로 펼친다.

## 핵심 규칙 (FILE, MOD, BND, LAY 관련)

### JSON 읽기와 팩 병합

- jsoncpp 규칙이다. 주석과 앞자리 0은 되지만 **뒤따르는 쉼표와 따옴표 없는 키는 오류**다. 오류가 나면 그 앞까지 읽은 멤버만 로드되고, 같은 경로의 첫 파일이 실패하면 뒤 팩의 덮어쓰기도 받지 않는다(FILE-30). 경로는 정렬 순으로 읽어 마지막이 이긴다(FILE-31). 키에 `@`가 없고 점이 있으면 점 앞이 namespace다(FILE-32).
- 같은 이름 재선언은 속성 단위로 합치되 객체 값은 멤버 단위로 깊게 합친다. `@` 상속에서 파생 정의가 적은 속성은 객체여도 통째로 교체한다(FILE-37). 다른 `@base`를 적으면 기존 정의를 버린다(MOD-19). 최상위 `null`은 기반 값을 지우지만 컨트롤 배열 안 인라인 참조의 `null`은 기반 값을 그대로 둔다(FILE-38).
- `modifications`는 일반 속성 병합이 끝난 뒤 적용되고 11개 연산을 모두 안다. `where` 객체는 멤버 하나라도 같으면 일치하며 `where: {}`는 아무것도 고르지 않고 조건이 없으면 첫 원소를 고른다. 한 번의 `modifications` 안에서 뒤 연산은 원래 원소만 고를 수 있다(MOD-17, MOD-18).

### 변수와 `ignored`

- 조회는 확정값을 먼저, 없을 때만 가장 가까운 `이름|default`를 쓴다(FILE-33). 속성 값은 문자열 전체가 `$이름`일 때만 변수다(FILE-10).
- **`ignored`는 그 컨트롤의 `$` 선언을 보지 않고 바깥 스코프에서 먼저 평가된다**(FILE-34). 결과가 불리언이면 그대로, 정수면 0이 아닐 때 생성 안 함, 문자열이면 생성한다(FILE-35). 바닐라 대조: `ignored`가 `$변수`를 읽는 최상위 정의 103개를 참조하는 146곳 중 그 변수를 넘기는 곳은 2곳(둘 다 `|default`)뿐이다. 팩토리가 주는 `$title_text` 등은 바깥 스코프로 들어가 만들어진 컨트롤의 `ignored`가 읽을 수 있다(FILE-17).
- 자식 키도 변수가 될 수 있다(FILE-36). `variables`는 배열·단일 객체 모두 되고 `requires`의 선택 규칙은 불리언은 그대로, 수는 0이 아니면, 문자열은 비어 있지 않으면이다.

### 식 평가기

| 규칙 | 내용 | 규칙 ID |
| --- | --- | --- |
| 리터럴 | `0.3`, `1.0`, `100.0`은 **정수**(0, 1, 100)다. `.3`처럼 점으로 시작해야 실수다 | EXP-27 |
| 우선순위 | 단항 → `* /` → `+ -` → `= < >` → `and or`(같은 순위, 왼쪽부터) | EXP-01, EXP-29 |
| 사슬 비교 | `962 < #c < 964`는 항상 참(왼쪽부터 묶여 불리언 < 수) | EXP-28, C-41 |
| 없는 연산자 | `<=`, `>=`, `!=`, `%`는 식 전체가 null | EXP-02, EXP-03 |
| 문자열 `*` | 왼쪽이 `%.Ns`면 오른쪽 글자의 앞 N**바이트**, 아니면 오른쪽 글자 통째(숫자면 빈 글자) | EXP-09, EXP-16 |
| 문자열 `-` | 오른쪽 글자의 **모든 출현**을 지움 | EXP-12 |
| 나눗셈 | 문자열이면 출현 횟수, 정수끼리는 **정수 나눗셈**(`i32::wrapping_div`) | EXP-18 |
| 결과 재해석 | `+ - *`가 만든 문자열이 숫자처럼 보이면 다시 정수·실수·불리언이 됨 | EXP-15, EXP-30 |
| `#이름` 결과 | 식 결과가 `#이름` 문자열이면 같은 컨트롤 주머니에서 그 값을 읽음(사전 조회) | COL-23 |

나눗셈 구현은 다음과 같다. 정수끼리의 나눗셈이 정수라는 점이 나머지를 `(a - (a / b * b))`로 만들 수 있다는 주장(AsaJS)의 근거다.

<Excerpt src="cinnabar" title="Cinnabar, divide" path="crates/json-ui/src/predicate/ops.rs">

```rust
/// `/`: text counts non-overlapping matches (1 for no needle); a zero divisor
/// keeps the left side; else numeric division, integer when neither is float.
fn divide(lhs: Operand, rhs: Operand) -> Operand {
    if lhs.is_string() {
        let needle = rhs.text();
        if needle.is_empty() {
            return Operand::Int(1);
        }
        return Operand::Int(lhs.text().matches(needle).count() as i32);
    }
    if rhs.is_string() || rhs.float() == 0.0 {
        return lhs;
    }
    numeric(&lhs, &rhs, i32::wrapping_div, |a, b| a / b)
}
```

</Excerpt>

바로 쓰는 결론: 문자열 바인딩을 숫자로는 `(#v - 0)`, 소수 곱하기는 `(#v * .01)`, 범위 검사는 `((a < #v) and (#v < b))`, 크거나 같음은 `(not (#v < a))`, 같지 않음은 `(not (#a = #b))`, 앞 N바이트는 `('%.Ns' * #s)`(`'%5.3s'` 등 다른 서식은 자르지 않음, C-05와 충돌)다.

### 바인딩

- `binding_type`은 모르면 로그 후 `global`, `binding_condition`은 모르면 로그 후 `none`이다(BND-22). 의미: `none` 데이터 갱신마다, `once` 처음 한 번, `always` 매 업데이트, `always_when_visible`·`visible` 보일 때, `visibility_changed` 가시성이 바뀔 때만(BND-23).
- `source_control_name`이 없으면 자기 주머니를 읽고 없는 속성은 전역에서 읽는다. 이름이 있는 view는 전역으로 떨어지지 않는다(BND-24). 검색 범위: 기본은 화면 루트부터 너비 우선 첫 일치, `resolve_sibling_scope`는 부모부터(부모 자신 포함), `resolve_ancestor_scope`는 가장 가까운 같은 이름의 조상(BND-25, BND-20).
- 불리언 대상(`#visible`, `#enabled`, `#toggle_state` 등)은 JSON 불리언만 받는다. `'false'` 문자열을 그대로 바인딩하면 숨지 않는다(BND-27). 식 바인딩은 주머니에는 컨트롤러의 원래 답을, 컴포넌트에는 식 결과를 준다(BND-26). 주머니의 `property_bag_for_children`은 자손 값을 덮지 않는다(BND-28). `##`로 시작하는 `text`는 리터럴이다(BND-29).
- 크기 바인딩: `#size_binding_x/y`는 **부모의 비율**(`v × 100%`), `_absolute` 접미는 픽셀이고 바인딩하지 않은 축은 선언값을 유지한다. 이것이 C-14의 부분 해소 근거다.

### 레이아웃

- `"fill"`, `"default"`는 소문자 그대로일 때만 키워드다. 단위 없는 숫자 문자열은 0이다(LAY-34). 부호는 다음 부호까지 이어진다(LAY-35). `%c/%cm/%sm`은 `%` 뒤에 쓴다. 바닐라 `progress_screen.json`의 `"100c%"`는 부모 기준 `%`다(LAY-36). `%cm`, `%sm`은 계수를 무시하고 최대값 자체다(LAY-37).
- 스택 패널은 숨은 자식에게 공간을 주지 않고 자식의 `offset`을 무시하며 `use_child_anchors`가 없으면 앵커도 무시한다. 생략한 진행 축 크기는 `100%c`다(LAY-04, LAY-38). `use_priority`는 낮은 `priority`부터 남기고 넘치는 자식을 숨긴다(LAY-40).
- 그리드 칸은 자기 `anchor`·`offset`을 무시한다(LAY-41). 스크롤 뷰는 역할 컨트롤을 이름으로 너비 우선 검색하며 넷 중 하나라도 없으면 스크롤하지 않는다(LAY-42). 앵커는 이름에 `left/right/top/bottom`이 들어 있는지로 판정하고 기본은 `center`다(LAY-43).

## 쓰는 법과 한계

엔진 규칙이 의심스러울 때 평가기를 직접 돌려 식의 결과를 확인하는 도구로 쓸 수 있다(비상업 목적에 한함, DBG-21). 단 관대한 구현이라 바닐라의 assert나 크래시는 재현하지 않고, 자체 글꼴이라 텍스트 폭 비교에는 쓰지 못한다. [엔진 동작 분석](../json-ui/index.mdx)에서 확인된 항목(NB-01~03, NB-09, NB-10)은 실제 컴파일 결과라 CN보다 직접적이다. 이 프로젝트는 `NB`가 읽지 못한 식·변수 규칙에서 CN을 가장 직접적인 근거로 쓴다.
