## 이것은 무엇인가

BedrockAdvancements는 웹 크리에이터(bedrockadvancements.com/create)로 발전과제 트리를 설계하고 애드온으로 내려받는 도구다. 분석 대상은 웹 크리에이터와 공개 문서, 변경 내역(2.0.0~2.0.5), 그리고 사용자 기기의 `BedrockAdvancements-2.0.3-Beta.mcaddon` 원본이다(2026-10-20 조사). **본체는 All rights reserved이며 재배포가 금지**되어 있다. 그래서 이 페이지는 `Excerpt`를 쓰지 않고 기법만 한국어로 다시 썼다. 코드 블록은 원문이 아니라 기법을 설명하려고 새로 쓴 예시다(출처: cs-bedrockadvancements).

핵심은 이 팩이 JSON UI를 "생성"하지 않는다는 점이다. 크리에이터는 발전과제 데이터, 아이콘, lang만 내보내고 화면은 본체 RP의 `ui/ba_screen.json`(712 KB, 빌드 도구가 스펙 파일에서 생성)이 그린다.

## 어떻게 동작하나

```
스크립트 ── ActionFormData(제목 'CUSTOMUI:BA…', 버튼 = 고정 폭 레코드) ──▶ server_form
    server_form.json: long_form을 감싼 래퍼 + 내 화면용 server_form_factory 하나 더
    ba_screen.json  : '%.Ns' 슬라이스와 포함 검사로 레코드를 해석해 트리를 그린다
```

레코드 한 줄은 `[KIND 4][TAB 2][FRAME 24][TOKENS 160][PROGRESS 16][PCT 4][TITLE 120][DESC …]` 구조다. 4바이트 `KIND`(`BAN|` 노드, `BAT|` 탭, `BAL|` 라벨, `BAM|` 메타)로 종류를 가르고, 나머지 필드는 `$` 또는 `.`로 패딩한다.

## 핵심 기법

### 1. 감싸기와 팩토리 추가

`long_form`을 직접 고치지 않고 `long_form@server_form.long_form`을 가시성 조건이 붙은 패널로 감싼다. 이 참조는 다른 UI 팩이 `long_form`을 통째로 바꾼 최종 병합 결과를 가리키므로 팩 순서와 무관하게 동작한다. 2.0.2 변경 내역의 "UI 팩과 함께 쓰면 화면이 뒤섞이는 문제" 수정이 이 구조다.

```jsonc
// 기법을 설명하기 위해 새로 쓴 예시 (원문 아님)
"my_hideable_long_form": {
  "type": "panel",
  "bindings": [ { "binding_name": "#title_text" },
    { "binding_type": "view",
      "source_property_name": "((#title_text - 'MYUI:FLAG') = #title_text)",   // 내 플래그가 없을 때만 보임
      "target_property_name": "#visible" } ],
  "controls": [ { "long_form@server_form.long_form": {} } ]
},
"main_screen_content/server_form_factory": {          // 경로 키로 control_ids만 덮는다
  "control_ids": { "long_form": "@server_form.my_hideable_long_form" } }
```

그리고 같은 이름의 `server_form_factory`를 `modifications`로 하나 더 추가해 내 화면을 생성하게 한다. 둘 다 같은 폼 데이터에 반응하고 가시성으로 하나만 보인다. 제목 판별을 접두 검사가 아니라 포함 검사로 해서 제목 뒤에 메타데이터(탭별 레코드 개수 등)를 실을 수 있다.

### 2. 고정 폭 레코드와 슬라이스 체인

N번째 바이트부터 L바이트를 꺼내는 표준 체인은 다음 네 단계다.

```jsonc
{ "source_property_name": "('%.210s' * #form_button_text)",    "target_property_name": "#head" },   // 앞 210바이트
{ "source_property_name": "(#form_button_text - #head)",       "target_property_name": "#rest" },   // 나머지
{ "source_property_name": "('%.120s' * #rest)",                "target_property_name": "#raw"  },   // 다음 120바이트
{ "source_property_name": "(#raw - '$')",                      "target_property_name": "#text" }    // 패딩 제거
```

- `'%.Ns'`는 UTF-8 바이트 단위다. 인코더가 바이트 기준으로 자르고 패딩해야 한국어(3바이트)가 맞는다.
- 문자열 `-`는 모든 출현을 지우므로 패딩 문자는 본문에 나오면 안 된다. 그래서 예약 문자를 평문에서 제거한다.
- 숫자처럼 보이는 필드는 JSON UI가 숫자로 바꾸므로 문자 접두(`Ta`, `§f3/17`, `P050`)를 붙인다.
- 진행률은 `(#pct_text - 'P')` → `* 1` → `/ 100` → `(1 - 값)` → `#clip_ratio`로 변환해 막대를 자른다.

### 3. 위치 무관 토큰

불리언과 비트는 `~` + 대문자 그룹 + 소문자(비트 번호) 토큰으로 싣고 `(not ((#form_button_text - '~Fo') = #form_button_text))`로 존재만 검사한다. 위치를 몰라도 되고 서로 접두 관계가 생기지 않는다. 그룹은 `X`(x 9비트), `Y`(y 11비트), `U`/`V`(연결선 길이), `H`(캔버스 높이), `F`(플래그: 자식 있음, 부모 있음, 툴팁 왼쪽, 선택됨, 진행도 있음, 도전, 달성, 빈 슬롯)다.

### 4. 비트 스페이서 스택으로 숫자를 좌표로

JSON UI에서 정적 컨트롤의 위치는 바인딩할 수 없다. 대신 크기가 1, 2, 4, …, 1024인 패널 11개를 세로 스택에 넣고 비트 토큰에 따라 각각 켜고 끈다. 스택 패널은 숨은 자식에게 공간을 주지 않으므로 켜진 스페이서 크기의 합이 곧 좌표(0~2047px)다. 같은 원리로 스크롤 콘텐츠 높이도 메타 레코드의 `H` 비트로 만든다.

```jsonc
// 새로 쓴 예시: 비트 하나 = 스페이서 하나
"y3": { "type": "panel", "size": [1, 8],
        "bindings": [ /* 토큰 '~Yd'가 있으면 #visible */ ] }
```

비용이 크다. 노드 하나가 수백 개의 컨트롤을 만들어, 모든 탭의 노드를 한꺼번에 보냈더니 화면이 열리는 데 몇 초가 걸렸다. 그래서 선택한 탭의 노드만 보내고 탭을 누르면 폼을 제출한 뒤 그 탭으로 다시 연다.

### 5. 화면 구성 요령

- 탭은 `collection_index`를 박은 패널 28개(8+8+6+6)이고, 스크립트가 빈 레코드를 보내 인덱스를 고정한다.
- 같은 `form_buttons` 컬렉션을 layer가 다른 팩토리 3개로 그린다(외곽선 layer 3, 노드 5, 호버 20). 한 아이템 안에서 layer만 올리면 다음 아이템의 외곽선이 앞 아이템을 덮기 때문이다.
- 노드 버튼에는 `button_mappings`가 없고 호버와 포커스만 쓴다. 탭 버튼만 `button.form_button_click`으로 제출한다.
- 툴팁은 4000×4000 검정 이미지(alpha 0.3)로 주변을 어둡게 하고 `allow_clipping: false`로 뷰포트 밖에 그린다. 텍스트 폭에 맞춘 배경은 `alpha: 0` 측정용 라벨이 부모를 `"100%c"`로 키워 만든다.
- 창은 `size: [314, "100% - 64px"]`, `max_size: [314, 236]`으로 작은 화면에서 줄어든다. 모든 텍스처에 9-slice `.json`이 붙는다.

### 6. 토스트는 `hud_title_text_factory`를 하나 더

타이틀이 올 때마다 팩토리가 컨트롤을 새로 만들어 애니메이션이 처음부터 재생된다. 데이터는 `CUSTOMHUD:ba_toast:` + 카테고리 + 제목 + 아이콘(`$` 패딩)이고, 헤더는 lang 키(`'ba.toast.' + 카테고리`)를 `localize` 라벨로 번역한다. 부모가 파싱한 값을 자식이 `source_control_name` + `resolve_sibling_scope: true`로 받는 패턴이다. 슬라이드 인, 4.5초 대기, 슬라이드 아웃을 애니메이션 `next` 체인으로 잇고 스크립트가 110틱 간격으로 큐를 처리한다. 한계: 바닐라 숨김을 `title_frame`에만 걸어 가운데에 글자가 잠깐 번쩍이는 문제가 2.0.3에 있었고(2.0.5에서 수정), 타이틀 채널은 하나라 다른 애드온의 `setTitle`에 덮인다.

### 7. 스크립트 운영 요령

- `FormCancelationReason.UserBusy`로 폼이 취소되면 10틱 간격으로 최대 20번 다시 연다.
- 폼을 다시 열면 스크롤이 맨 위로 돌아가므로 열린 아코디언 섹션을 맨 앞에 둔다.
- 레이아웃 계산(`tabLayout.js`)을 게임 API와 분리한 순수 함수로 두어 웹 미리보기가 게임과 같은 파일을 실행한다.
- 웹 크리에이터가 내보내는 `.mcaddon`에는 JSON UI 파일이 없다. 데이터는 커스텀 아이템 컴포넌트(`ba:tab`, `ba:advancement`, `ba:criterion`)에 담는다.

## 우리 규칙과의 관계

| 규칙 ID | 관계 |
| --- | --- |
| MOD-09, FILE-20 | 감싸기와 경로 키의 근거(지지) |
| HOST-03, HOST-14, HOST-15 | 제목 플래그, 타이틀 채널 공유 위험 |
| EXP-09, EXP-12 | `'%.Ns'` 바이트 단위, `-`의 전체 제거 |
| LAY-04, LAY-05, LAY-06, LAY-10~LAY-11 | 숨은 자식의 무공간, 정적 위치 비바인딩, 반응형 크기 |
| LAY-20, LAY-22~LAY-24 | 레이어 3중 팩토리, 클리핑, 측정 라벨 |
| BND-06, BND-10 | `once`, 부모 한 번 파싱 |
| COL-06, COL-10 | 고정 인덱스, 생성 비용 |
| C-04, C-16 | `* 1` 숫자 변환과 정수 나눗셈 소수 변환은 이 팩의 원본 식이 실측 충돌의 한쪽 근거다 |

## 비교

[AdvancementPack](./advancementpack.mdx)은 NPC 화면과 HUD로 같은 결과를 내고, [bedrock-core](./bedrock-core.mdx)는 접두 13바이트 판별과 범용 폼 컴포넌트를 쓴다. BedrockAdvancements는 특수 화면 전용이라 레코드 구조가 가장 정교하지만 컨트롤 수가 가장 많다.
