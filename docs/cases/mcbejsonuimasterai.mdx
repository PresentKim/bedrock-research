## 이것은 무엇인가

mcbejsonuimasterAI는 GitHub `boredape874` 1인이 2026-04-25~2026-10-04에 만든 저장소다(HEAD `527276c`, 커밋 87개, 파일 1,231개, 문서 87개 약 7만 단어, 스킬 28개, Node CLI 63개, MCP 서버, 브라우저 편집기 Studio). **"JSON UI를 AI가 다루게 하는 작업 환경"이지 "JSON UI 엔진 규칙서"가 아니다.** 주로 OpenAI Codex용이다. 강점은 바닐라 버전 고정(`v1.26.50.4` / `46ba6ea`, 15개 파일만 커밋)과 이름 대조, 1.26.50 변경 추적 같은 정적 근거 관리다. 클론 루트에 `LICENSE`가 없고 `NOTICE.md`는 일부 코드가 MIT인 gamezaSRC/JSON-UI-Web-Editor에서 왔다고만 밝히므로 기본적으로 저작권 보유로 보고 문장·코드를 옮기지 않았다. 사실은 바닐라로 다시 확인했다(출처: cs-mcbejsonuimasterai).

## 구성

두 층으로 나뉜다. **지식층**(스킬 28개, 문서 87개, 속성 사전 `data/jsonui-spec.json`, 참조 자료)은 "무엇이 맞는 이름인가, 어떤 패턴이 있는가"를 찾는 곳이고, **도구층**(63개 CLI)은 레이아웃을 YAML IR로 쓰면 solver가 좌표를 풀고 compiler가 JSON UI를 뽑으며 검사기·미리보기로 확인한다. 바인딩·애니메이션은 사람이 생성물 위에 손으로 덧붙이라고 한다. 모든 스킬에 "Evidence first, skill second" 블록이 있다: 대상 팩과 Content Log → 고정 바닐라(`vanilla-name-check`) → 등록된 외부 출처 → 그래도 없을 때만 스킬 내용(이때는 "inferred"로 표시). 이 원칙은 우리 가이드의 수준 표기와 방향이 같다.

## 가치 있는 것

- 바닐라 1.26.10.4 → 1.26.50.4 변경 문서(`docs/83`)가 가장 가치 있다. 표본 점검이 모두 맞았다: `server_form.json` `custom_form` 팩토리에 `multiselect` 추가, HUD 자막이 `subtitle_container_factory`로 변경, HUD 루트의 `curor_rend@cursor_renderer` 제거, 인벤토리 닫기 버튼 id가 `button.menu_inventory_exit`로, 탭 factory가 `#*_tab_visible` 전역 바인딩으로, 채팅 라벨 폭 `100% - 3px`. 특히 `multiselect` 컨트롤은 RP에 생겼지만 공개 Script API(`@minecraft/server-ui` 2.2.0~2.4.0-beta)에 보내는 메서드가 없다.
- 서버 폼 계약 추적 체크리스트(제목 → 팩토리 → 컬렉션 → 인덱스 → 응답)와 `ModalForm` 하나에서 드롭다운으로 페이지를 바꾸는 패턴(미검증)이 있다. 숨긴 dropdown을 필드 0에 두고 `('%.4s' * #dropdown_option_text)`로 view 키를 읽어 상주 gate 패널이 내용을 켜고 끈다.
- 이름 대조 도구 `vanilla-name-check`는 실제 이름(`common.close_button`, `#title_text`)은 찾고 지어낸 이름·오타(`common.close_buton`)는 거부한다. 단 15개 파일만 색인해 `start_screen` 같은 실제 이름도 NOT FOUND로 낸다.

## 틀렸거나 근거 없는 것

바닐라 207개 파일 전수 검색으로 대조한 결과다.

| 주장 | 실제 |
| --- | --- |
| `resolve_ancestor_scope`가 바닐라 1.26.50에서 "추가 확인"됨 | 바닐라 0회. `resolve_sibling_scope`는 53회(C-07) |
| `scroll_box`가 컨트롤 타입 | 바닐라 타입은 `scroll_view`·`scrollbar_box`·`scroll_track`. `scroll_box`는 `ui_common.json`의 컨트롤 이름(LAY-02) |
| `grid_fill_direction` 값 `left_to_right` 등 네 가지 | 바닐라는 `vertical`만(LAY-26) |
| `grid_rescaling_type: none`이 바닐라에서 확인됨 | 바닐라는 `horizontal` 21회, `vertical` 1회뿐 |
| `modifications` 항목 키 `target_control`, 배열 `button_mappings` | 근거 없다고 했으나 엔진은 `target_control`을 실제로 읽는다(NB-02). 배열 범위는 C-64 |
| `(x - x % 65536) / 65536`을 소개 | `%`는 연산자가 아님(EXP-02). Chest-UI의 우연한 동작(EXP-38) |
| `(#form_text * 1)`이 앞 숫자를 숫자로 | `* 1`은 0, `(#v - 0)`만 동작(S12, C-04) |
| `%5.3s` 같은 패딩 서식, 문자 단위 자르기 | 출처·테스트 없음. 같은 저장소의 다른 문서는 "바이트 폭"이라 모순 |
| `binding_type` 표 | `none`이 빠짐(바닐라 1회) |

`data/jsonui-spec.json`에는 바닐라에 0회인 속성(`z_order`, `clip_offset`, `alignment`, `pixel_perfect`, `gradient_direction`, `use_uuid`, `animation_looped`, `precached_grid_item_count`, `toggle_on_hover`, `slider_timeout` 등)도 있다. 원인은 테스트가 "바닐라가 쓰는 이름이 스펙에 다 있는가"만 보고 반대 방향("스펙의 이름이 바닐라에 있는가")은 보지 않기 때문이다. 그래서 스펙은 오타 잡기에는 쓸 만하지만 "유효한 이름 목록"으로는 틀린다(DBG-07, 양방향 대조).

전반적으로 원본 측정 지식은 거의 없다. 게임 내 측정을 언급하는 파일은 3개뿐이고 런타임 주장 대부분은 "not verified"로 정직하게 표시했지만 엔진 의미는 비어 있다. `%`·`>=` 없음, `#size_binding`, `#visible`은 생성을 막지 않는다는 것, 폼 버튼에 `collection_details`가 없으면 `canceled`라는 것 등이 빠져 있다.

## 도구를 돌려 본 결과

- `npm run check`는 68개 테스트 중 64개 통과(2개는 PowerShell 필요, 2개는 Linux 글꼴로 이미지 비교 허용 오차 초과). Studio 테스트는 27/27이다.
- IR → solve → compile → validate는 성공하지만 생성 `ui.json`은 모든 요소가 평평한 최상위 정의 + 절대 px이고 `$변수`·바인딩·템플릿·modifications가 없으며 어떤 바닐라 화면에도 연결되지 않아 그대로는 게임에 안 뜬다.
- `validate-pack`은 AdvancementPack에 8개 파일의 "namespace 없음" 오류를 냈지만 바닐라 파일 병합용 파일의 오탐이다(FILE-05). `_global_variables.json` 미등록 경고도 오탐(자동 로드, FILE-04). `.r4ui`는 존재만 확인하고 내용을 검사하지 않는다. 레이어 119~201이 높다는 경고는 소음이다(LAY-21).
- 미리보기와 `final-rp:render`는 와이어프레임이거나 회색 이미지로 "배드락처럼 보이는지" 판단용이 아니다.

정리하면 **이름 대조 도구는 쓸모 있고 팩 검사기·렌더러는 실제 커뮤니티 팩에 그대로 쓰기엔 오탐이 많다**(DBG-23, DBG-24).

## 우리 규칙과의 관계와 가져올 것

| 규칙 ID | 관계 |
| --- | --- |
| DBG-07, DBG-24, DBG-26 | 양방향 대조, 도구 통과가 유효를 뜻하지 않음, AI 생성 문서 신뢰 범위 |
| LAY-02, LAY-26, BND-01, C-07 | 이 저장소의 틀린 주장이 반박되는 규칙 |
| EXP-02, EXP-16, EXP-25 | `%`, `* 1`, 패딩 서식 주장 |
| FILE-04, FILE-05 | 검사기 오탐 사례 |

규칙으로 가져올 것(바닐라로 재확인): 1.26.50 변경 주의 목록, 바닐라가 바인딩 이름을 변수 식으로 만든다는 사실(`"$toggle_state_binding_name": "('#' + $dropdown_name)"`), 스펙 사전의 양방향 대조, 근거 단계 표시(대상 팩 → 고정 바닐라 → 외부 출처 → 추론). 가져오지 말 것: 스펙을 유효 속성 목록으로 쓰는 것, `scroll_box` 타입, `grid_fill_direction` 네 값, `resolve_ancestor_scope`, `%` 예제, `* 1` 변환, 패딩 서식, IR/solver 출력을 완성 예제로 싣는 것.
