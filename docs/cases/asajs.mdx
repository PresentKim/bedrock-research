## 이것은 무엇인가

AsaJS는 Node/TypeScript로 리소스팩 UI를 코드로 만드는 프레임워크다(npm `asajs` 4.2.0, 옛 이름 jsonui-scripting, 작성자 Asaki Yuki). `Label({...})`, `Panel(...)`, `Modify("start", "start_screen_content").insertChild(...)` 같은 코드를 실행하면 `build/ui/*.json`, `_ui_defs.json`, `manifest.json`을 쓰고 게임의 `development_resource_packs`에 링크를 건다. 분석 기준은 `main` 커밋 `9f884dc`(2026-03-02)다. 클론의 `LICENSE`를 열어 확인한 라이선스는 **GPL-3.0**이다(출처: cs-asajs). 발췌에는 라이선스가 머리에 표시된다. 서버 폼을 가로채는 기능은 없어서 화면 호스트 기법과는 관련이 없고, 의미 있는 것은 **바인딩 식 컴파일러**다.

## 어떻게 동작하나

| 단계 | 내용 |
| --- | --- |
| 요소 생성 | `Panel/Label/Image`가 정의 하나가 된다. 이름이 없으면 무작위 16자, namespace는 무작위(파일 하나가 namespace 하나) |
| 속성 변환 | `#`로 시작하는 키는 `property_bag`으로, `anchor` 하나는 `anchor_from`·`anchor_to`로 복제, `$x\|d`는 `$x\|default`로 |
| 바닐라 수정 | `Modify(ns, 이름)`이 내장 경로표(`"start": "ui/start_screen.json"` 등)로 **바닐라와 같은 경로** 파일에 `modifications`를 쓴다 |
| 바인딩 기본값 | `binding_collection_name`만 있으면 `collection_details`, 다른 키도 있으면 `collection`, `source_property_name`이 있으면 `view` |
| 난독화(선택) | 요소·바인딩·변수 이름을 무작위 문자열로 바꾼다 |
| 설치 | `build/`를 `development_resource_packs/asajs-build-<무작위>`에 링크하고 `global_resource_packs.json`에 팩을 추가한다 |

생성 manifest는 `min_engine_version` `[1, 21, 80]`이고, 바닐라 정의 목록·바인딩 이름 1,476개·버튼 ID 946개·아이템 aux ID 표는 빌드 스크립트가 외부 API에서 받아 생성한다.

## 바인딩 식 컴파일러

`source_property_name`이 `[`와 `]`로 감싸져 있으면 컴파일 대상이다. 자체 문법(`==`, `!=`, `>=`, `<=`, `&&`, `||`, `!`, `%`, `?:`, `f'...#{식}...'`, 함수 호출)을 바닐라 엔진이 아는 연산자만 쓰는 식과 **보조 view 바인딩 여러 개**로 바꾼다. 보조 바인딩이 본 바인딩 앞에 나오므로 같은 컨트롤 안에서 계산 순서가 지켜진다.

| AsaJS 문법 | 내보내는 식 | 판정 |
| --- | --- | --- |
| `a == b`, `a != b` | `(a = b)`, `(not (a = b))` | EXP-03과 맞음 |
| `a >= b`, `a <= b` | `((a > b) or (a = b))`, `((a < b) or (a = b))` | EXP-03의 우회와 같음 |
| `a && b`, `a \|\| b` | `(a and b)`, `(a or b)` | 매번 괄호로 순위 문제(EXP-29)를 피함 |
| `-a` | `(0 - a)` | 문자열 단항 `-` 문제(EXP-37)는 그대로 |
| `a % b` | 보조 `#r = (a - (a / b * b))` | 정수 나눗셈 전제. EXP-20과 충돌(C-52) |
| `f'안녕 #{#name}!'` | `('안녕 ' + #name + '!')` | 문자열 `+` |
| `1e-2` | `0.01` | 엔진에서 정수 0(EXP-27) — 결함 |
| `0.5`, `.5` | 렉서 오류 | 실수 리터럴을 쓸 수 없음 |
| `a < b < c` | `((a < b) < c)` | 사슬 비교(EXP-28)를 막지 않음 |

`source_control_name`이 있는 바인딩에서는 식 안의 `#속성`마다 그 컨트롤에서 속성 하나를 읽는 보조 view 바인딩을 따로 만들고 식은 자기 컨트롤에서 계산한다. 다른 컨트롤의 값 여러 개를 섞는 식을 안전하게 만드는 방법이다.

### 함수들

`abs(x)`는 `((-1 + (x > 0) * 2) * x)`(불리언 산술, EXP-19), `cache_value(c, o, r)`는 `((r * c) + ((not r) * o))`, `contains(s, t)`는 `not ((s - t) = s)`(EXP-07), `translatable(#k)`는 `'%' + #k`(현지화 라벨이 `%토큰`을 번역하는 성질 이용, TXT-17), `bind(v, #bait)`는 `((#bait - #bait) + v)`(미끼가 바뀔 때 다시 평가시키는 의존성 장치)다. `strlen`, `sqrt`, `vector_length`는 자기 참조 view 바인딩으로 반복 계산한다. 파서 안에는 정수를 30개 비트 바인딩으로 푸는 `intToBin`도 있다.

## 핵심 기법

### 1. 고유 접두로 길이를 모르는 문자열의 시작 검사

`'%.Ns'`(EXP-08)는 `N`을 컴파일 시점에 알아야 한다. 둘 다에 본문에 나올 수 없는 접두 `P`를 붙이면 `(P + #s)`에서 `(P + #p)`를 뺐을 때 결과가 바뀌는 경우는 `#s`가 `#p`로 시작할 때뿐이다(빼기는 모든 출현을 지우지만 `P`가 고유해 출현이 맨 앞 하나뿐). 저장소 `starts_with`의 해당 분기다.

<Excerpt src="asajs" title="AsaJS, starts_with" path="src/compilers/bindings/Function.ts">

```ts
const source_str_bind = RandomBindingString()
const start_str_bind = RandomBindingString()

return {
	genBindings: [
		{ source: `${prefix} + ${source_str}`, target: source_str_bind },
		{ source: `${prefix} + ${start_str}`, target: start_str_bind },
	],
	value: `not ((${source_str_bind} - ${start_str_bind}) = ${source_str_bind})`,
}
```

</Excerpt>

`prefix`는 `'asajs:<무작위 5자>:'`다. 같은 원리로 접두를 붙인 문자열에서 앞부분을 잘라 빼면 잘라 낸 머리가 뒤에도 있어도 지워지지 않아 EXP-12(`-`는 모든 출현을 지움)의 문제가 해결된다.

### 2. 나머지와 비트를 정수 나눗셈으로

나머지는 `(a - (a / b * b))`, 비트 i는 `((x / 2^i) - ((x / 2^(i+1)) * 2))`다. 정수끼리의 나눗셈이 정수라는 EXP-18이 맞다면 가능하다. 그렇다면 EXP-20의 "바닥·나머지 연산이 없어 숫자 하나에 여러 필드를 묶었다 나눌 수 없다"는 `%` **연산자가 없다**는 뜻으로 좁혀야 한다. 저자 S14가 시험한 것은 `%` 연산자(`Invalid expression`)뿐이고 나눗셈 기반 식의 게임 기록은 없다(충돌 C-52, 이 프로젝트가 Cinnabar 평가기 `divide`가 `i32::wrapping_div`임을 확인해 부분 해소). 함정: 컬렉션·타이틀 문자열은 식 안에서 문자열이라 문자열 `/` 숫자는 1이다(EXP-32). 문자열 채널에는 `((#v - 0) - (((#v - 0) / 10) * 10))`처럼 먼저 `- 0`으로 숫자를 만든다(EXP-16).

### 3. 런타임 서식 문자열과 자기 참조 반복

`('%.' + (len(P) + #i) + 's')`처럼 서식 문자열을 이어 붙여 만든다. StarLibV2도 같은 형태를 쓴다. `strlen`은 "카운터 = 0(원본이 바뀔 때)"과 "카운터 = 카운터 + 1(아직 다 안 셌으면)" 두 바인딩을 같은 대상에 걸어, view 바인딩이 원본이 바뀔 때만 다시 쓰고 사슬이 수렴할 때까지 돈다는 동작(Cinnabar 재구성 CN-36)에 기댄다. 반복 상한과 프레임당 처리량은 확인되지 않았다.

## 생성 결과에서 확인된 결함

- 삼항 `c ? x : y`는 최종 식의 괄호가 맞지 않는다(조사에서 같은 문자열을 Python으로 다시 만들어 세어 확인).
- `modifications`의 `insert_back` 등에서 `value`를 배열이 아닌 객체로 낸다(`insert_front`만 배열). 객체가 받아지는지는 확인되지 않았다.
- `replaceChild`는 넘긴 자식을 버리고 속성 객체만 `value`로 쓴다.
- `new('lit')`, `int(3)`, `str_slice('lit', …)`는 `#` 없는 view 바인딩을 만들어 BND-05에 걸린다(그 컨트롤의 `bindings` 전체가 버려짐).
- 문자열 바인딩에 `%`를 그대로 쓰면 EXP-32로 틀린 값이 나온다. 타입 정의 속성 328개 중 바닐라에 없는 이름이 46개다(쓰지 않으면 출력되지 않음).
- `fixInventoryItemRenderer`가 `property_bag`의 `#item_id_aux`를 `"(N / 1)"` 문자열로 감싼다. `property_bag` 값이 식으로 평가되는지는 미확인.

## 우리 규칙과의 관계

| 규칙 ID | 관계 |
| --- | --- |
| EXP-18, EXP-20, C-52 | 나머지의 가능 여부를 가르는 충돌 근거(반영안 EXP-38) |
| EXP-07, EXP-08, EXP-12 | `contains`, `starts_with`, 접두 자르기의 근거 |
| EXP-03, EXP-19, EXP-27, EXP-28, EXP-32 | 생성기가 지키거나 어긴 규칙 |
| BND-05, BND-30(반영안) | 보조 바인딩 결함, 자기 참조 반복 |
| MOD-02 | 바닐라 경로 사본에 modifications를 쓰므로 지킨다 |
| TXT-17 | `'%' + #key` 번역 라벨 |

## 반영안(미적용)

병합 기록의 최종 번호다. EXP-38 나머지(`{코드, 추론, 충돌}`), EXP-39 고유 접두 시작 검사, EXP-19 보강(불리언 선택·절댓값), BND-30 자기 참조 반복(`{코드, 미검증}`), DBG-31 식 컴파일러 출력 점검. 실측이 필요한 것: `(#v - ((#v / 5) * 5))`가 17에서 2가 되는지, 초기화+자기 증가 바인딩이 길이를 세는 데 몇 프레임 걸리는지, `modifications`의 `value`에 객체를 줘도 되는지, 이어 붙인 서식 문자열이 자르기로 동작하는지.
