## 이것은 무엇인가

upgrader는 `hash2444`의 확률형 "업그레이더" 서버 폼 팩이다(`/upgrader` 명령, CS2식 화면). 아이템을 넣고 더 비싼 목표를 고르면 확률 원호(초록)와 바늘이 돌아 성패를 보여 준다. 화면 전체가 **`ActionFormData` 하나를 리소스팩이 재스킨**한 것이다. 저장소 `0119a5a`(2026-09-23)에는 README, SETUP-HELP.md, `Upgrader-v1.0.2.mcaddon`, 미리보기 PNG만 있고 소스는 mcaddon 안에 있다(RP `min_engine_version` 1.21.110, BP `@minecraft/server` 2.1.0, `@minecraft/server-ui` 2.0.0). 클론에 `LICENSE`가 없으므로 코드와 이미지를 복사하지 않고 기법만 요약한다(출처: cs-upgrader).

근거 수준에 주의한다. 저장소는 올라온 지 하루 된 v1.0.2이고 README 그림은 게임 화면이 아니라 렌더링한 미리보기다. 그래서 "게임에서 이렇게 보였다"는 기록은 없고 작동팩 수준은 "배포된 팩이 이렇게 짰다"까지만 뜻한다.

## 화면 구조

1. `server_form.json`이 `long_form`을 같은 경로에서 `@` 없이 재선언한다(`type: panel`, `controls` 두 개). 바닐라 모양은 제목에 플래그가 없을 때, 자기 화면 `upgrader.root`는 있을 때 보인다. Chest-UI와 같은 방식이라 두 팩은 함께 쓸 수 없다(반영안 MOD-21).
2. `upgrader.root` 안에 단계별 `collection_panel`(`collection_name: form_buttons`)이 여럿 있고 각 패널의 `#visible`은 제목 **정확 일치**로 정한다(회전 `…§2`, 결과 `…§3`, 본 화면 `…§1`).
3. 각 패널의 자식은 `collection_index`가 고정(0, 1, 2, …, 22회)이고 `anchor_from/to: top_left`와 절대 `offset`으로 놓인다. 화면 전체가 좌표가 고정된 캔버스다. 텍스트는 `#form_button_text` → `#entry_text`, 아이콘은 `#form_button_texture` → `#texture`다.
4. 배경은 UI JSON 안의 리터럴 `"nineslice_size": 8`을 쓰고 `panel.png` 옆에는 사이드카가 없다. 바닐라는 이 리터럴을 쓰지 않고 Cinnabar는 사이드카에서만 읽는다(LAY-27, 효과는 실측 필요).

## 스크립트에서 UI로 가는 프로토콜

| 항목 | 값 |
| --- | --- |
| 제목 | `MARKER` = `§u§p§g§q§r` + 화면 코드(`§1` 본 화면, `§2` 회전, `§3` 결과). 글자마다 `§`를 붙여 리소스팩이 없어도 제목에 안 보인다 |
| 본문 | 항상 폴백 문장("리소스팩이 꺼져 있어 기본 레이아웃으로 보인다"). 커스텀 화면은 본문 칸을 그리지 않는다 |
| 버튼 0 | 확률 ID `"000"`~`"100"` → 원호 텍스처 |
| 버튼 1 | 결과 ID `"00"`~`"99"` → 바늘·회전 시트 |
| 버튼 2~7 | 확률 글, 배수 글, 입력 가치, 목표 가치, 예약, 안내문 |
| 버튼 8~ | 입력 슬롯(최대 3), 목표, 실행 버튼, 닫기 |
| 역매핑 | 버튼마다 `layout[i] = {kind}`를 만들어 `selection` 번호를 동작으로 되돌린다. 텍스트 전용 버튼은 `kind: "none"`이라 눌러도 무해하다 |

번호는 0을 채운 고정 폭 문자열로 보내므로 경로 결합 결과가 파일명과 정확히 맞는다(`arc_037`). Cinnabar로 확인하면 문자열 `'037'`은 그대로 붙지만 정수 37이면 `arc_37`이 된다. 값이 연산을 한 번이라도 거치면 숫자로 재해석되어 0이 빠진다(EXP-30).

## 핵심 기법

### 1. 회전은 미리 그린 프레임으로

JSON UI에는 이미지 회전 속성이 없다. 그래서 확률 원호 101장(`arc_000`~`arc_100`), 멈춘 바늘 100장(`needle_00`~`needle_99`), 회전 시트 100장(`spin_00`~`spin_99`, 각 1280×1280에 128px 프레임 100칸)을 준비하고 번호를 경로에 이어 붙여 고른다.

```jsonc
// 기법을 설명하기 위해 새로 쓴 예시 (원문 아님)
"arc_entry": {
  "type": "image",
  "bindings": [
    { "binding_type": "collection", "binding_collection_name": "form_buttons",
      "binding_name": "#form_button_text", "binding_name_override": "#upg_id" },
    { "binding_type": "view",
      "source_property_name": "('textures/ui/upgrader/arc/arc_' + #upg_id)",
      "target_property_name": "#texture" } ]
}
```

각도나 비율을 계산하는 대신 결과 수만큼 그림을 미리 그린다(1% 단위, 반영안 ANI-29).

### 2. 바인딩 텍스처와 `aseprite_flip_book`

회전 바늘은 `anim_type: aseprite_flip_book` 애니메이션을 `uv`에 걸고 `uv_size [128, 128]`, `disable_anim_fast_forward: true`를 준 이미지이며 `texture`를 `('textures/ui/upgrader/spin/spin_' + #upg_roll)`로 바인딩한다. 사이드카 `spin_NN.json`(Aseprite Array 형식)은 그 칸을 **감속 순서로 고른 프레임 목록**(141~144프레임, 대부분 20ms, 끝으로 갈수록 40·60·80·100·200ms)이고 마지막 프레임은 결과 칸 NN이다. 결과 100가지마다 사이드카가 따로 있으므로 텍스처를 바꾸면 같은 컨트롤이 결과에 맞는 회전 프로그램을 재생한다. 바닐라 팁 화면(`game_tip_screen.json`)도 `"texture": "#texture"` + `aseprite_flip_book` + `disable_anim_fast_forward: true`를 쓴다(반영안 ANI-30).

### 3. 마지막 프레임을 길게 해서 끝에서 멈추기

플립북은 끝나면 처음으로 돌아가 스스로 반복한다. 마지막 프레임의 `duration`을 3,600,620ms(약 1시간)로 길게 주어 사실상 끝에서 멈춘다. 일부 시트는 3,600,600ms로 맞춰 전체 길이가 정확히 3,604,000ms가 되게 했다. Cinnabar의 플립북은 `ms % 전체 길이`로 항상 루프하므로 "약 1시간 동안 마지막 칸에 머문다"는 뜻이다(반영안 ANI-26의 근거 중 하나). `disable_anim_fast_forward`는 폼이 열릴 때 이미 지난 시간만큼 건너뛰지 않게 한다(바닐라 21회).

### 4. 단계 전환과 폴백

- 제목은 정확 일치(`#title_text = MARKER§N`)로 단계를 나누고 `long_form` 전환에는 포함 검사를 쓴다. 접두 뒤에 한 글자 코드만 붙으므로 정확 일치가 안전하다(반영안 HOST-40).
- 회전 폼을 연 뒤 스크립트가 매 틱 경과 시간을 세어 `random.click`을 재생하고, 시간(4초 + 여유 10틱)이 지나면 `uiManager.closeAllForms`로 닫고 결과 폼을 연다. 결과 처리는 회전을 보여 주기 전에 확정한다. 입력 아이템 제거는 4틱 뒤에 하는데 작성자 주석에 따르면 폼에서 폼으로 바뀔 때 Bedrock이 핫바가 보이는 일반 게임 화면을 한 프레임 보여 주기 때문이다(미검증).
- 본문에 폴백 안내문을 넣고 커스텀 화면은 본문을 그리지 않는다. 폼을 닫거나 접속을 끊어도 받을 상품은 동적 속성에 남아 다음 접속 때 지급한다(반영안 HOST-39).

## 우리 규칙과의 관계

| 규칙 ID | 관계 |
| --- | --- |
| ANI-15, ANI-19, ANI-08, ANI-20 | 플립북 텍스처 바인딩, `disable_anim_fast_forward`, 회전은 프레임 이미지로 |
| COL-06 | 고정 인덱스 + 절대 `offset`으로 화면 전체를 만든 대규모 예 |
| EXP-07, EXP-30 | 포함 검사와 정확 일치 구분, 숫자 재해석 |
| HOST-10, HOST-15, HOST-34 | 폼 재오픈 초기화, 접두사와 단계 코드, 글자마다 `§` 플래그 |
| MOD-20, MOD-21(반영안) | `long_form` 재선언 팩끼리 공존 불가 |
| LAY-27 | 리터럴 `nineslice_size` 효과는 실측 필요 |

## 실측이 필요한 항목

`#texture`를 바꾸면 새 사이드카로 다시 시작하는지 경과 시간을 이어 가는지, 마지막 프레임 duration 3,600,000ms 정지와 상한, 폼 → 폼 전환 사이에 게임 화면이 한 프레임 보이는지, 리터럴 `nineslice_size`가 사이드카 없이 9-slice로 그리는지, 팩 전체가 1.21.110·26.x에서 그려지는지(저장소에 게임 화면 기록 없음).
