JSON 스키마는 VS Code 같은 편집기에서 자동 완성과 오류 밑줄을 주는 가장 흔한 "검증 도구"다. 이 페이지는 공개된 JSON UI 스키마 네 종류와, 애드온 전체를 다루는 Blockception 스키마를 어떻게 설치하고 어디까지 믿을 수 있는지 정리한다. 조사 방법은 스키마 네 종류로 바닐라 1.26.50.4의 UI 파일 205개(`_ui_defs.json`, `_global_variables.json` 제외)를 그대로 검증하는 것이었다. 바닐라는 게임이 실제로 읽는 파일이므로 바닐라에서 나는 오류는 대부분 스키마의 오탐이다(출처: tool-repo-analyses, jsonui-schemas 분석).

## KalmeMarq 스키마 설치

라이선스 파일이 없으므로 스키마 본문은 옮기지 않고 사용법만 적는다. 공개된 설정 예(README)는 `json.schemas`에 네 스키마를 파일 패턴과 함께 건다.

```json
"json.schemas": [
  {
    "url": "https://kalmemarq.github.io/Bugrock-JSON-UI-Schemas/ui.schema.json",
    "fileMatch": ["*.ui.json", "*.uidx", "ui/**/*.json",
                  "!_global_variables.json", "!_ui_defs.json", "!/textures/**/*.json"]
  },
  {
    "url": "https://kalmemarq.github.io/Bugrock-JSON-UI-Schemas/ui_defs.schema.json",
    "fileMatch": ["ui/_ui_defs.json"]
  },
  {
    "url": "https://kalmemarq.github.io/Bugrock-JSON-UI-Schemas/global_variables.schema.json",
    "fileMatch": ["ui/_global_variables.json"]
  }
]
```

`ui.sprite.schema.json`은 `textures/**/*.json`(9-slice 스프라이트 정의)에 걸고, `flipbook_textures.json`, `item_texture.json`, `terrain_texture.json`, `texture_list.json` 등은 제외한다. 저장소에는 `ui.schema.json`, `old_ui.schema.json`, `ui.sprite.schema.json`, `ui_defs.schema.json`, `global_variables.schema.json`이 있고 README에 화면별 도입 버전 표가 있다.

## Blockception 스키마 설치

BSD-3-Clause이므로 설정 조각을 옮겨도 된다. 저장소 `vscode-settings.example.json`을 `.vscode/settings.json`으로 복사하거나 `.code-workspace`의 `settings` 안에 `json.schemas` 배열을 넣는다. UI 스키마의 원본은 `source/resource/ui/`(속성마다 파일 하나)이고 빌드 결과는 `resource/ui/ui.json`이다(출처: tool-blockception-schemas, `README.md`).

## 결함 요약

- KalmeMarq와 DJ: 크기 식 정규식이 항 하나만 허용해 `"100% - 4px"`를 거부하고, 텍스처 정규식이 `/`를 거부한다. 바닐라에 있는 속성 이름 4개(DJ는 18개)가 스키마에 없다.
- Blockception 최신: `additionalProperties: false`라 모르는 속성은 전부 오류이고, enum은 "아무 식별자"를 허용하는 대안 때문에 무력하며, 바닐라 속성 이름 50개가 없다. 확장에 묶인 판은 크기에 `100%c`, 음수, 식을 거부한다.
- zelisce: 크기 정규식이 소수와 음수를 거부하고 `*`, `/`를 허용한다.

## 스키마가 알려 준 엔진 사실

1. `grid_position`은 `[열, 행]`(x, y)이다. 바닐라 그리드 20곳에서 `grid_dimensions`가 `[열 수, 행 수]`이고 자식의 첫 값이 열이다(예: `trade_screen.json`의 `[4, 1]` 그리드에 `[3, 0]`). 가이드 초판의 `[행, 열]`(LAY-29)은 틀렸다.
2. 크기와 위치 식에는 `+`, `-`만 쓴다. 바닐라의 크기 문자열 551종(12,806회) 가운데 `*`나 `/`가 든 것은 0개이고, 소수 계수(`56.25%x`)와 음수(`-50% + 10px`)는 쓴다(LAY-44).
3. 스키마 통과가 게임 허용을 뜻하지 않고, 스키마 오류가 게임 오류를 뜻하지도 않는다. 네 스키마 모두 바닐라에 오탐을 내거나 바닐라에 없는 값(`clip_direction: "dwn"`, `anchor_from: "left"`, NetEase 전용 속성)을 통과시킨다(DBG-23~25).
4. 바닐라에도 깨진 값이 있다: `"size": [ "fill%", "100%" ]`(sidebar_navigation.json), 원소가 하나뿐인 `"size": [ "100%, 100%" ]`, 괄호가 닫히지 않은 `"ignored"` 식, 빈 `"max_size": []`. 따라서 "바닐라에 한 번 나온다"는 그 값이 유효하다는 증거가 아니다.

## 쓰는 요령

스키마는 오타 잡기와 자동 완성용으로 쓰고, 최종 판정은 게임의 콘텐츠 로그나 [JSON UI 테스터](./jsonui-tester.mdx)로 한다. 크기 식 오류가 한꺼번에 쏟아지면 그 스키마의 크기 정규식 문제이므로 해당 규칙만 끄거나 Blockception 최신 소스를 직접 가리킨다.

#### 문서 자체의 오류와 공백 (2026-08 docs feedback 스레드)
- **월드젠·데이터 문서**: 지그소 template pool 페이지가 없는 `legacy`/`list` 요소를 나열하고, 지그소 구조물 폴더명이 구식이다. 루트 테이블 적용 방법 설명이 빈약하고, 엔티티 이벤트 목록에 바닐라 이벤트가 많이 빠졌다. animationsreference/volumereference 페이지는 비었거나 404다. attachable 1.8/1.10 문서가 없다. `aggregate_feature`의 `early_out` 유효성과 순차 배치 여부에서 문서끼리 충돌한다.
- **Script API 문서**: stable인데도 `Dimension.getBlocks`가 없다. `applyImpulse`/`applyKnockback`의 단위가 없고 `is_sleeping`은 모호하다. stable/experimental 탭이 타입과 일치하지 않고, 릴리스 전후 몇 주는 stable과 어긋난다. 예제가 금방 낡는다.
- **파티클 사운드**: 문서는 파티클 사운드 이벤트가 `sound_definitions.json`에서 재생된다고 하지만, 실제로는 바닐라 `sounds.json`의 기존 `individual_event_sounds`만 동작했다. (single report)
- **문서에 없는 동작**
  - 모루에서 이름을 바꾸면 아이템 텍스처가 바뀔 수 있다(MCPE-188505).
  - `query.lod_index`는 bedrock.dev에만 있다.
  - custom component 매개변수는 객체 2단계까지만 중첩된다(`{"one": {"two2": {"three": "ERROR"}}}`). 오류 메시지는 이 제한을 말해 주지 않는다.

- **이미지**: `docs/public/assets/images/<page path>/`에 두고, `<WikiImage>`에서는 `/public/...` 접두사를 뺀다(파일명만 써도 된다).
- **리디렉션과 섹션**: 페이지 이름을 바꾸면 `redirects.yaml`(`.vitepress` 밖으로 옮겨졌다)에 항목을 추가한다. 섹션은 `section.yaml`(title, 선택적 `categories`)로 정의한다. front matter에는 `category`, `mentions`, `nav_order`, `tags`, `description`이 있다. categories가 없는 섹션에서 `category`를 지정하면 빌드 오류가 난다.
- **스타일**: 파일 경로는 `<CodeHeader>path</CodeHeader>`로 쓰고, 제목에 `:`를 넣지 않고, 수동 `---` 구분선을 쓰지 않고, 대소문자를 일관되게 쓴다. PR 전에 로컬에서 띄워 본다. Prettier v3.4.0의 리스트 포맷 변경은 `prettier-plugin-markdown-list-tabwidth`로 되돌린다. Mermaid는 라이트/다크 테마를 지원한다.
- **검색**: Algolia를 쓴다. 2025-11에 크롤링을 고쳤고, 2026-04에 이름에 슬래시가 든 페이지가 인덱스에서 빠졌다.
- **저장소 크기**: 거대 GIF(최대 41.9MB)를 줄였다. `git clone --filter=blob:none`을 쓴다. 옛 `bedrock-examples` submodule 커밋을 push하지 않는다.
- **라이선스**: MIT/CC-BY("Bedrock OSS")다. SPDX 헤더는 큰 코드 기여에만 붙이고, 그 밖의 기여자는 `mentions`에 적는다.
- **트래픽**: 2025-12에 4.3만 클릭, 2026-04에 약 4.5만/월로 감소 추세이고 AI 크롤러가 늘었다. 기여 방향 메모: 긴 `/execute` 체인 글은 스크립팅이 있는 Bedrock에서는 쓸모가 제한적이라는 평을 받았다.
- **서버 소프트웨어 목록 등재 기준(2026-10)**: 3개월 이상 됐고, 자체 README나 사이트가 있고, 스타 약 15개 수준이고, 최근 3개 프로토콜 버전 중 하나를 지원하거나 최근 커밋이 있고, fork 원본과 분명히 달라야 한다. Geyser 등은 "Crossplay Software" 섹션으로 옮긴다. 중단된 소프트웨어(PocketMine, Nukkit, BDSX)는 역사 기록으로 남긴다.
