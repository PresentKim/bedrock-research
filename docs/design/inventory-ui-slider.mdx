# 인벤토리 UI로 슬라이더 구현하기

[엔티티 인벤토리로 메뉴 화면 만들기](./entity-inventory-ui.mdx)와 같은 방식(보이지 않는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그리는 방식)으로 만든 화면에 슬라이더를 넣어 본 시험의 기록이다. 그 문서와 예제 애드온에는 슬라이더가 없고, 슬라이더 시험은 아래 두 시험 팩에서 따로 했다. 시도한 방법마다 무엇을 했는지, 무엇이 나왔는지, 왜 안 됐는지를 적고, 마지막에 지금 쓰는 구성과 예제 애드온을 둔다.

시험 팩은 둘이다.

- IIP: 상자 화면 입력 시험 팩 v1.0.0~v1.3.0. 토글, 슬라이더, 글 입력을 처음 시험했다.
- IUC: InvUI 컴포넌트 갤러리 팩 v1.0.0~v1.5.1. Ore UI 컴포넌트를 상자 화면에 옮긴 갤러리이고, 슬라이더 시험은 대부분 여기서 했다.

표기는 다음과 같다.

- 실측: 게임에서 확인했다. 모두 모바일 1.26.63, 2026-11-16이다.
- 테스터: `mcbe-json-ui-tester` 정적 시뮬레이션으로 확인했다.
- 모의: `@minecraft/server`를 흉내 낸 Node 실행으로 확인했다.
- *추론*: 시험으로 원인을 따로 가리지 않은 설명이다.

## 1. 상자 화면에서 슬라이더가 어려운 이유

- 상자 화면에서 서버로 가는 통로는 칸 조작뿐이다. 버튼은 숨긴 칸의 빠른 이동으로 바꿔 서버에 알린다([엔티티 인벤토리 메뉴](./entity-inventory-ui.mdx) 2.5절). 서버가 아는 것은 "몇 번 칸 버튼이 눌렸다"뿐이다.
- 화면 안 슬라이더(`slider`)는 끌리고 값(`#slider_value`)도 다른 컨트롤이 읽지만, 그 값을 서버로 보내는 통로가 없다(IIP v1.0.0, 실측).
- 입력창의 글은 읽을 수 없었다. 입력창의 `#item_name`, 입력창 안 글 라벨의 `#text`, 전역 `#item_name`, 입력창의 `#text` 네 경로가 모두 비었다(IIP v1.1.0, 실측). 그래서 글 입력으로 값을 넘기는 방법도 쓸 수 없다.
- 휴대폰에는 호버가 없다. 칸에 `from_button_id` 없는 매핑을 단 Hover slider는 칸을 탭할 때만 바뀌었다(IIP v1.2.0, 실측). 손가락이 지나가는 칸을 서버가 알 방법이 없다.

## 2. 시도와 결과

### 2.1 탭 슬라이더

- 시도: 막대 위에 단계마다 칸 버튼을 하나씩 둔다. 누른 칸이 값이고, 서버는 값을 칸 이름으로 돌려주어 손잡이와 채움을 그린다.
- 결과: 누른 자리로 손잡이가 왔다(IIP v1.0.0, 실측). Ore UI 모양으로 바꾼 뒤에도 동작했다(IIP v1.3.0, 실측).
- 한계: 끌기가 없다. 단계 수만큼 칸 번호를 쓴다. 누를 때마다 서버를 한 번 오가므로 손잡이가 조금 늦게 움직인다.

### 2.2 드래그 슬라이더와 Apply 버튼

- 시도: 화면 안 슬라이더를 끌고, `#slider_value`에 맞는 "Apply k" 버튼 하나만 보이게 한다. Apply를 누르면 그 칸 버튼이 서버로 간다.
- 결과: 손잡이가 끌렸다. 값은 단계 번호였다(`index` 줄에 8, `fraction` 줄은 빔). "Apply 8"을 누르자 서버가 8을 받았다(IIP v1.0.0, 실측). 직접 만든 Ore UI 모양 슬라이더와 Apply도 동작했다(IIP v1.3.0, 실측).
- 한계: 끌고 나서 Apply를 한 번 더 눌러야 한다.

끌기와 보내기를 슬라이더 하나로 하려고 같은 시험 팩에서 세 가지를 더 해 보았다.

| 시도 | 결과(실측) | 원인 |
| --- | --- | --- |
| Drag + ping: 슬라이더를 칸에 넣고 누를 때 빠른 이동도 보냄(IIP v1.2.0) | 끌리지만 서버가 만짐을 받지 못했다 | 가리지 않았다 |
| Ping first: 빠른 이동 매핑을 슬라이더 매핑보다 앞에 둠(IIP v1.3.0) | 만질 때마다 서버가 받았지만 손잡이가 끌리지 않았다 | 앞의 매핑이 누름을 가져가 슬라이더가 받지 못한 것으로 보인다(*추론*) |
| Named ping: `slider_track_button`을 `button.container_auto_place`로(IIP v1.3.0) | 서버가 받지 못했고 손잡이도 끌리지 않았다 | 가리지 않았다 |

### 2.3 화면 안 그림

슬라이더 값을 서버로 보내기 전에 화면 안 그림부터 맞춰야 했다.

- 엔진 손잡이를 그대로 쓰면 손잡이는 손가락을 따라가고 초록 채움은 단계에 맞춰 따로 움직였다(IUC v1.2.1, 실측).
- 기본 막대와 호버 막대가 같은 컨트롤이면 손가락이 슬라이더 위에 있는 동안 어두운 바탕이 사라졌다(IUC v1.1.0, 실측). IUC v1.2.0부터 호버 막대(`bar_hover`)를 따로 둔다.
- 그래서 IUC v1.3.0부터 엔진의 손잡이와 채움은 빈 패널로 두고, 단계마다 손잡이와 채움을 하나씩 그려 `(#slider_value = k)`일 때만 보이게 한다. 끄는 동안 값은 화면 안에서 바로 보인다(테스터).

### 2.4 터치 시작 신호로 단계 버튼 바꾸기

- 시도: 막대 전체를 덮는 칸 버튼이 터치 시작을 서버에 보내면, 서버가 그 자리를 단계 버튼 11개로 바꾼다. 손을 뗀 자리의 단계 버튼이 눌림으로 잡히는지 본다(IUC v1.2.0에 넣음).
- 결과: 막대를 누르면 서버가 "touch start"를 받아 단계 버튼으로 바꿨지만, 손을 떼는 자리의 단계 버튼은 눌림으로 잡히지 않았다(IUC v1.3.0, 실측).
- 원인: 터치에서 칸 버튼은 탭이 끝나야 서버에 닿는다. 서버가 시작 신호를 받았을 때 손은 이미 떨어져 있다(IUC v1.3.0 실측 결과에서 본 설명).

### 2.5 탭 칸 위로 끌기

- 시도: 탭 슬라이더의 한 칸을 누른 채 다른 칸으로 끌고 가서 뗀다.
- 결과: 어느 칸도 눌림으로 잡히지 않았다(IUC v1.4.0, 실측).
- 원인: 터치에서 서버가 아는 것은 누르고 같은 칸에서 뗀 탭뿐이다(같은 실측에서 본 설명).

### 2.6 슬라이더 위나 아래에 숨은 단계 버튼 겹치기

- 시도: 같은 슬라이더 위(레이어 20) 또는 아래(슬라이더 레이어 12, 버튼 1)에 단계 자리마다 보이지 않는 칸 버튼 11개를 둔다. 칸 버튼은 `consume_event: false`로 매핑한다(IUC v1.4.1). 칸 버튼은 단계 경계에 맞게 놓였다(테스터).
- 결과: 칸 버튼이 위인 줄은 슬라이더가 움직이지 않고 값만 서버로 갔다. 슬라이더가 위인 줄은 슬라이더만 움직이고 서버로는 아무것도 가지 않았다(IUC v1.4.1, 실측).
- 원인: 위에 있는 컨트롤이 터치를 가져간다. 위치로 받는 `pressed` 매핑은 `consume_event: false`여도 누름을 아래 컨트롤에 넘기지 않는다(같은 실측).

### 2.7 SliderLab 1차: 서버에 닿는 다섯 가지

IUC v1.4.2의 SliderLab 페이지는 다섯 줄을 한 화면에 두었다.

| 줄 | 구성 | 결과(IUC v1.4.2, 실측) |
| --- | --- | --- |
| A | 슬라이더 아래에 단계마다 숨은 칸 버튼. 지금 단계의 버튼 하나만 보이고, 매핑은 `mapping_type: "global"`, `consume_event: false` | 슬라이더 밖에서 손을 떼면 지금 단계 값을 보냈고 값이 맞았다. 슬라이더 위에서 떼면 아무것도 가지 않았다 |
| B | A의 단계 버튼 매핑에 `button_up_right_of_first_refusal` | A와 같다. A와 B가 같은 틱에 각자 값을 보냈다 |
| C | 칸에 넣은 슬라이더. 드래그 매핑 뒤에 빠른 이동 매핑 | 아무것도 보내지 않았다 |
| D | 칸에 넣은 슬라이더. `slider_selected_button`을 `button.container_auto_place`로 | 아무것도 보내지 않았다 |
| E | 칸에 넣은 슬라이더. `slider_deselected_button`을 `button.container_auto_place`로 | 아무것도 보내지 않았다 |

- global 매핑은 화면 어디서 손을 떼든 보이는 단계 버튼을 모두 누른다(실측). 그래서 보이는 버튼을 지금 단계 하나로 줄이면 그 버튼이 곧 지금 값이다.
- 슬라이더 위에서 뗀 손이 가지 않은 것은 슬라이더의 드래그 매핑이 그 입력을 가져갔기 때문으로 보았고(*추론*), 2차 시험에서 드래그 매핑을 바꿔 보았다.
- C, D, E가 보내지 않은 원인은 가리지 않았다.

### 2.8 SliderLab 2차: 드래그 매핑 비교

- 시도: 네 줄 모두 A의 global 단계 버튼을 두고, 슬라이더 드래그 매핑만 달리했다. A: 바닐라대로(`button_up_right_of_first_refusal: true`). B: 그것을 뺌. C: `consume_event: false`를 더함. D: 둘 다(IUC v1.4.3).
- 결과: 값은 대체로 잘 갔다. 네 줄이 같은 틱에 같이 보냈다. 한 슬라이더를 건드린 뒤에는 다른 줄의 슬라이더를 끌어도 같은 값으로 함께 움직였다. B, C, D는 거의 늘, A도 몇 번 그랬다(IUC v1.4.3, 실측).
- 원인: 한 화면에 슬라이더가 여럿이면 서로 값이 섞인다. 왜 섞이는지는 가리지 않았다.

### 2.9 SliderLab 3차: 한 번에 한 줄

- 시도: A~D 중 고른 줄 하나만 보이게 하고, 슬라이더와 상관없는 빈 칸 버튼("Tap here")을 두었다(IUC v1.4.4).
- 결과: A, C, D는 끌고 뗀 값이 서버로 잘 갔다. B만 제대로 동작하지 않았다(IUC v1.4.4, 실측).
- 원인: B가 안 된 원인은 가리지 않았다. B와 D의 차이는 `consume_event: false`뿐이다.

### 2.10 드래그 매핑과 아래 탭 칸

- 시도: Slider 페이지의 드래그 슬라이더에서 Apply를 없애고, global 단계 버튼과 SliderLab C 매핑(드래그 매핑에 `consume_event: false`)을 쓰는 `releaseSlider`로 바꿨다(IUC v1.4.5).
- 결과: 드래그 슬라이더를 끌다가 탭 슬라이더 위에서 손을 떼면 탭 슬라이더도 눌렸다(IUC v1.4.6, 실측).
- 원인: 드래그 매핑의 `consume_event: false`가 손을 뗀 입력을 아래 탭 칸에 넘긴 것으로 보았다.
- 그래서 드래그 매핑을 바닐라 그대로(SliderLab A)로 되돌렸다(IUC v1.4.7). 그래도 끌다가 탭 슬라이더 위에서 떼면 탭 칸이 눌렸다(IUC v1.4.8, 실측). 바닐라 매핑에서 탭 칸이 눌리는 원인은 가리지 않았다. 매핑만으로는 막을 수 없었으므로 서버에서 거른다(2.11절).
- 바닐라 매핑으로 되돌린 Slider 페이지에서는 슬라이더 위에서 손을 떼면 값이 서버로 가지 않았다(IUC v1.4.9, 실측). 슬라이더가 손을 뗀 입력을 먼저 가져가는 것으로 보인다(*추론*, `button_up_right_of_first_refusal`). 아래 탭 칸 문제는 서버 거르기가 맡으므로, 드래그 매핑을 다시 C(`consume_event: false`)로 돌렸다(IUC v1.5.1).

### 2.11 서버에서 탭 거르기

- 시도: 서버는 탭 칸 눌림을 바로 적용하지 않고 그 틱 끝까지 들고 있다. 같은 틱에 드래그 값이 바뀌었으면 그 탭은 끌기가 끝난 손으로 보고 버린다(IUC v1.4.9).
- 결과: 탭과 드래그 값 변화가 같은 틱이면 탭이 버려지고, 드래그 값이 그대로면 탭이 적용됐다(IUC v1.4.9, 모의). 게임에서 이 거르기를 따로 확인한 기록은 없다(*미검증*).
- 한계: 끌었지만 값이 바뀌지 않은 채(같은 단계로 돌아와) 탭 칸 위에서 떼면 그 탭은 적용된다(*추론*, 규칙에서 나오는 결과).

### 2.12 드래그 분할 경로(DragLab)

슬라이더와 따로, 손가락이 지나간 칸을 서버가 알 수 있는지 DragLab 페이지에서 시험했다. 왼쪽 칸에 표시 막대기 64개를 두고, 오른쪽 칸 11개에 바닐라 상자 칸 매핑(`take_all_place_all`, `shape_drawing` 등)을 달았다. 서버는 매 틱 칸 내용을 읽어 지나간 칸과 틱을 적는다.

| 시도 | 결과(실측) | 원인 |
| --- | --- | --- |
| 막대기 칸을 탭한 뒤 끌기(IUC v1.4.5) | 서버가 지나간 칸을 거의 매 틱 차례로 받았다(`1@t1159 2@t1159 3@t1161 ... 11@t1174`, 칸마다 5개, 손에 9개) | 바닐라 드래그 분할이 칸마다 아이템을 나눠 놓는다 |
| 막대기 칸을 누른 채 바로 끌기(IUC v1.4.5) | 아무것도 놓이지 않았다 | 터치에서는 첫 탭으로 아이템을 집어야 분할이 시작되는 것으로 보인다(*추론*) |
| 이미 지나간 칸을 다시 지나기(IUC v1.4.5) | 바뀌지 않았다 | 한 번 끄는 동안 같은 칸에는 다시 놓지 않는다 |
| 칸이 아닌 곳에서 멈추기(IUC v1.4.5) | 아이템을 쥔 상태가 남아 Reset이 눌리지 않았다 | 손에 남은 아이템이 다음 누름을 가져간 것으로 보인다(*추론*) |
| 막대기가 들어온 칸을 서버가 바로 비우기(IUC v1.4.8) | 칸마다 32개씩 놓다가 막대기가 떨어져 멈췄다 | 비운 칸의 아이템은 돌아오지 않으므로 손의 막대기가 줄어든다 |
| 칸을 비울 때 막대기 칸을 64개로 다시 채우기(IUC v1.4.9) | 끄는 도중에 서버가 막대기 칸을 다시 채우자 손에 쥔 상태가 풀려 끌기가 끊겼다 | 집어 온 칸을 서버가 다시 채우면 손에 쥔 상태가 풀린다. 다른 칸을 비우는 것으로는 끊기지 않았다 |

- 끌기가 끝나고 20틱 동안 칸 변화가 없으면 서버가 칸을 비우고 막대기를 되돌리게 했다(IUC v1.4.6, 모의).
- 정리하면 드래그 분할은 "지나간 칸을 한 번씩, 지나간 순서대로" 알려 준다. 칸을 비우면 막대기가 바닥나고 다시 채우면 끌기가 끊기므로, 한 번 끄는 동안 같은 칸을 다시 지나는 것은 서버가 알 수 없다(IUC v1.4.9, 실측).
- 슬라이더는 값을 되돌릴 때 지나간 칸을 다시 지나므로 이 경로로는 만들 수 없다(*추론*).
- 각 칸을 한 번씩 순서대로 지나는 입력에는 맞는다. 3x3 점을 지나가며 그리는 잠금 패턴(PatternLock)은 저장, "Wrong pattern", "Unlocked"이 맞게 나왔다(IUC v1.4.8, 실측). 이 구성은 [인벤토리 UI로 강화 컴포넌트 구현하기](./inventory-ui-enhanced-components.mdx)에서 다룬다.

## 4. 최종 구성

슬라이더 하나에 두 가지를 둔다.

1. 화면 안 슬라이더. 끄는 동안 손잡이와 채움, 값 글은 `#slider_value`로 화면 안에서 그린다(2.3절).
2. 단계마다 숨은 칸 버튼 하나. 매핑은 `button.menu_select`를 `button.container_auto_place`로 보내는 global 매핑이고, 버튼은 `(#slider_value = k)`일 때만 보인다. 손을 떼면 보이는 버튼 하나가 눌려 지금 값이 서버로 간다.

드래그 매핑에는 `consume_event: false`를 준다(SliderLab C). 바닐라 그대로(A)는 슬라이더 위에서 손을 떼면 값이 가지 않았다(2.10절). C는 손을 뗀 자리의 탭 칸도 누르지만 A도 그랬으므로(2.10절), 어느 쪽이든 서버 거르기(2.11절)를 함께 둔다. 슬라이더 여럿이 섞이는 일은 A가 가장 적었다(2.8절). C로 여러 슬라이더를 한 화면에 둔 구성은 다시 확인해야 한다.

예제 애드온 생성기(`tools/lib.mjs`의 `releaseSlider`)가 만드는 슬라이더다. 손잡이, 막대, 단계별 그림 컨트롤은 줄였다.

```json
"ius_slider": {
  "type": "slider",
  "size": [ 198, 18 ],
  "layer": 3,
  "slider_name": "ius_slider",
  "slider_track_button": "ius_slider",
  "slider_direction": "horizontal",
  "slider_steps": 11,
  "slider_box_control": "knob",
  "default_control": "bar",
  "hover_control": "bar_hover",
  "background_control": "track",
  "background_hover_control": "track_hover",
  "progress_control": "fill",
  "progress_hover_control": "fill_hover",
  "always_handle_pointer": true,
  "focus_enabled": true,
  "property_bag": { "#slider_steps": 11, "#slider_value": 0, "#slider_timeout": 0.25 },
  "button_mappings": [
    { "from_button_id": "button.menu_select", "to_button_id": "ius_slider", "mapping_type": "pressed", "button_up_right_of_first_refusal": true, "consume_event": false }
  ]
}
```

단계 4의 숨은 칸 버튼이다. 단계 0~10마다 하나씩, 슬라이더와 같은 자리에 슬라이더보다 낮은 레이어로 둔다. 칸 번호(`collection_index`)는 단계마다 다르다.

```json
"ius_slider_step4": {
  "type": "stack_panel",
  "collection_name": "container_items",
  "size": [ 198, 18 ],
  "layer": 1,
  "controls": [
    {
      "button": {
        "type": "button",
        "size": [ 198, 18 ],
        "collection_index": 34,
        "default_control": "default",
        "hover_control": "hover",
        "pressed_control": "pressed",
        "bindings": [
          { "binding_type": "collection_details", "binding_collection_name": "container_items" },
          { "binding_type": "view", "binding_condition": "always", "source_control_name": "ius_slider", "source_property_name": "(#slider_value = 4)", "target_property_name": "#visible" }
        ],
        "button_mappings": [
          { "from_button_id": "button.menu_select", "to_button_id": "button.container_auto_place", "mapping_type": "global", "consume_event": false }
        ]
      }
    }
  ]
}
```

- 버튼의 `default`, `hover`, `pressed`는 빈 패널이라 보이지 않는다.
- 보이기 바인딩은 `source_control_name`으로 슬라이더의 `#slider_value`를 읽는다.

서버 규칙은 두 가지다.

1. global 매핑은 화면 어디서 손을 떼든 지금 단계 버튼을 누른다. 다른 버튼을 누를 때도 같은 값이 다시 오므로, 지금 값과 같은 값은 무시한다.
2. 드래그 값이 바뀐 틱에 들어온 탭 칸 눌림은 끌기가 끝난 손으로 보고 버린다(2.11절, 게임에서는 *미검증*).

예제 애드온 `bp/scripts/pages/slider.js`의 처리다. `holdTap`은 탭을 들고 있고, `settleTap`은 틱 끝에 들고 있던 탭과 드래그 값 변화를 비교한다.

```js
tick: (state) => {
  const { tap, dropped } = settleTap(state);
  if (dropped !== undefined) return `tap ${dropped * 10} ignored, it was the end of a drag`;
  if (tap === undefined) return undefined;
  state.value = tap;
  return `slider ${state.value * 10}`;
},
press: (state, slot) => {
  if (slot < STEPS) {
    holdTap(state, slot);
    return undefined;
  }
  const step = slot - DRAG.step;
  if (step === state.drag) return undefined;
  state.drag = step;
  markDragMoved(state);
  return `drag slider ${step * 10}`;
},
```

- 서버의 처음 드래그 값은 슬라이더의 처음 값(`#slider_value` 0)과 같게 둔다. 다르면 화면을 열고 처음 손을 뗄 때 단계 버튼이 0을 보내 값이 바뀐 것으로 잡히고, 같은 틱의 첫 탭이 버려진다(*추론*, 규칙에서 나오는 결과).
- 한 화면에 이 슬라이더를 여럿 두면 2.8절처럼 값이 섞일 수 있다. 예제의 TwoHandleSlider 페이지가 슬라이더 둘을 두므로, 이 페이지에서 섞이는지 볼 수 있다(*미검증*).

1. 새 월드에서 행동 팩 `[bedrock-research]inventory-ui-slider-bp`로 시작하는 팩을 켠다. 리소스 팩은 의존성으로 함께 켜진다. 다른 엔티티 인벤토리 예제와 같은 월드에 켜도 된다([엔티티 인벤토리 메뉴](./entity-inventory-ui.mdx) 2.2.2절).
2. 크리에이티브 인벤토리 아이템 분류의 맨 뒤에서 "Inventory UI Slider"(비교기)를 꺼낸다. `/give @s bwiki:inventory_ui_slider_test`를 써도 된다.
3. 아이템을 든 채 화면 가운데를 누르면 슬라이더 화면이 열린다.
4. 위 줄의 `<` `>`나 Pages로 페이지를 바꾼다. 맨 아래 줄은 서버가 마지막으로 처리한 것이다.

| 페이지 | 내용 |
| --- | --- |
| Slider | 탭 슬라이더(누를 때마다 서버로)와 최종 구성 슬라이더(4절). 드래그 슬라이더를 끌다 탭 슬라이더 위에서 떼면 맨 아래 줄에 "ignored"가 나와야 한다 |
| TextSlider | 단어가 붙는 탭 슬라이더(난이도 넷)와 최종 구성 슬라이더(날씨 셋). 끄는 동안 단어가 바로 바뀌고, 손을 떼면 서버가 받은 단어가 옆에 나온다 |
| TwoHandleSlider | 가까운 손잡이를 옮기는 탭 막대와 최종 구성 슬라이더 둘(Low, High). 두 값이 엇갈리면 서버가 정렬하고 "swapped"를 붙인다 |
| XYSlider | 10x10 탭 격자. 누른 칸이 X, Y 값이다 |

- 화면의 글은 영어다.
- `tools/gen-ui.mjs`가 `rp/ui/ius.json`을 만들고, `tools/check-page.mjs`가 페이지의 UI 버튼과 스크립트 버튼 목록이 같은지 확인한다.
- 이 예제는 IUC의 Slider, TextSlider, TwoHandleSlider, XYSlider 페이지를 옮긴 것이다. TextSlider와 TwoHandleSlider는 IUC에서 드래그와 Apply였고, 예제에서 최종 구성으로 바꿨다. 예제 애드온 자체는 아직 게임에서 돌려 보지 않았다(*미검증*).

실측은 연구 저장소의 시험 팩(IIP, IUC)으로 했다.
