# HUD에 아이템 아이콘과 개수를 동적으로 그리기

바라보는 블록의 이름과 아이콘, 상자 안의 아이템과 개수를 화면 위에 띄우는 패널(Java의 WAILA·Jade 같은 것)은 JSON UI에서 어려운 기능으로 꼽힌다. 글자는 쉽게 보낼 수 있지만 **아이템 아이콘**은 문자열로 바로 그릴 수 없기 때문이다.

결론부터 적으면, 아이템의 숫자 ID를 아는 쪽(아이템 목록을 클라이언트에 직접 보내는 커스텀 서버)은 플레이어 인벤토리를 건드리지 않고 아이콘과 개수를 그릴 수 있다. 핵심은 두 가지다.

1. 서버가 아이템의 **런타임 ID × 65536**을 고정 폭 글자 칸으로 부제목에 싣는다.
2. 팩은 그 값을 바인딩이 아니라 **제목 팩토리가 주는 변수**(`$subtitle_text`)에서 잘라 `property_bag`의 `#item_id_aux`에 넣는다. 바인딩으로 꺼내면 아이콘이 비었다.

Script API 애드온처럼 숫자 ID를 모르는 쪽은 지금도 인벤토리 거울이나 텍스처 경로를 쓴다(2절).

## 1. 왜 어려운가

- 아이템 아이콘은 `inventory_item_renderer`(`"type": "custom"`, `"renderer": "inventory_item_renderer"`)에 `#item_id_aux`를 줘서 그린다. 값은 `숫자 아이템 ID × 65536 (+ 데이터 값)`이다(ANI-06). 블록 아이템은 인벤토리에서 입체로 그려지므로 텍스처 하나로 대신하기 어렵다.
- HUD에 데이터를 넣는 통로는 제목, 부제목, 액션바 같은 **문자열**뿐이다([HUD와 타이틀](../server-ui/hud-and-titles.mdx)). 그 문자열에서 숫자를 꺼내 렌더러 입력으로 넣어야 하는데, 이 경로가 막히는 곳이 많다(4절).
- 숫자 ID는 커스텀 아이템이 등록되면 일부가 밀려 월드마다 다를 수 있다(ANI-06). Script API에는 아이템의 숫자 ID를 직접 얻는 방법이 없다는 것이 커뮤니티의 결론이다(커뮤니티 보고).
- 반대로 `container_items`, `hotbar_items` 같은 엔진 컬렉션은 칸마다 `#item_id_aux`와 `#inventory_stack_count`를 준다(COL 장의 엔진 컬렉션 표). 그래서 공개 애드온은 "보여 줄 아이템을 실제 인벤토리 칸에 넣는" 길을 택했다.

## 2. 세 가지 방법

| 방법 | 원리 | 쓸 수 있는 곳 | 대가 |
| --- | --- | --- | --- |
| 인벤토리 거울 | 스크립트가 플레이어 인벤토리 칸에 보여 줄 아이템을 넣고, 팩이 그 칸을 컬렉션 바인딩으로 읽는다 | Script API 애드온 | 플레이어의 실제 아이템을 옮긴다. 백업과 복원이 필요하다 |
| 숫자 ID를 제목에 싣기 | 서버가 런타임 ID × 65536을 부제목에 글자로 싣고, 팩이 제목 팩토리 변수에서 잘라 렌더러에 넣는다 | 아이템 목록을 직접 보내는 커스텀 서버(Dragonfly 등) | 칸마다 고정 식을 만들어야 한다. 형식을 바이트 단위로 맞춰야 한다 |
| 텍스처 경로 | `image`에 아이템 텍스처 경로를 준다 | 어디서나 | 평면 그림만 된다. 블록 아이템의 입체 아이콘은 안 된다 |

### 2.1 인벤토리 거울 (공개 WAILA 애드온)

공개 WAILA 애드온(r4isen1920/WAILA, MIT)의 스크립트는 플레이어 인벤토리의 9~26번 칸에 있던 아이템을 직렬화해 dynamic property에 백업하고(크기 한도 때문에 여러 조각으로 나눠 저장), 그 칸에 표시할 아이템을 넣었다가 나중에 되돌린다(출처: waila-r4isen1920 `InventoryMirror.ts`). 팩은 `hotbar_items` 같은 인벤토리 컬렉션의 정해진 칸을 `collection_index`와 `collection` 바인딩으로 읽어 `#item_id_aux`와 `#inventory_stack_count`를 렌더러로 옮긴다.

- 숫자 ID를 몰라도 되고 Script API만으로 된다.
- 대신 플레이어의 아이템을 실제로 움직인다. 백업과 복원이 어긋나면 아이템을 잃을 수 있으므로 백업 저장, 접속 종료 처리, 다른 애드온과의 충돌을 따로 챙겨야 한다.
- 이 애드온의 옛 버전은 제목에서 숫자를 읽어 `property_bag`에 넣는 렌더러를 썼고, 지금은 인벤토리를 읽는 렌더러로 대체되었다(팩의 `item_aux_renderer` 정의에 "Deprecated" 주석이 있다).

### 2.2 텍스처 경로

아이템 텍스처 경로(`textures/items/...`)를 `image`의 `texture`로 주면 아이콘 비슷한 그림을 그릴 수 있다. aux id가 버전과 애드온에 따라 밀리는 문제를 피하는 방법으로 커뮤니티가 권한다(커뮤니티 보고). 평면 그림이라 블록 아이템, 색이 입혀진 아이템처럼 렌더러가 그리는 모양은 나오지 않는다.

### 2.3 서버 폼에서는 바인딩 경로도 된다

서버 폼 버튼은 사정이 다르다. 버튼 이미지 문자열 `#form_button_texture`에 `aux:65536` 같은 값을 실어 `(#texture - 'aux:')`를 `#item_id_aux`로 바인딩하는 방법이 Chest-UI 계열에서 동작한다(PAT-11, 커뮤니티 보고). 아래 4절의 "바인딩으로는 안 된다"는 **HUD 제목 채널**의 결과다.

## 3. 숫자 ID를 제목에 싣는 방법

Dragonfly 기반 서버에서 실측으로 만든 구성이다(출처: 비공개 조사). 서버는 플레이어가 바라보는 블록을 광선 검사로 찾고, 패널 내용을 제목과 부제목으로 보낸다. 팩은 바닐라 제목을 가리고 그 자리에 패널을 그린다.

### 3.1 데이터 형식

**제목**에는 패널용 표식 접두어와 이름·정보 줄을 싣는다. 팩은 접두어로 패널 제목인지 가리고, 바닐라 제목 라벨은 숨긴다.

**부제목**에는 아이콘과 칸을 고정 폭으로 싣는다.

| 위치(바이트) | 길이 | 내용 | 예 |
| --- | --- | --- | --- |
| 0 | 1 | 문자열 표식 `i` | `i` |
| 1 | 11 | 0번 칸 아이템: 런타임 ID × 65536을 왼쪽에 `x`로 채움. 빈 칸은 `xxxxxxxxxx0` | `xxxxx327680` (런타임 ID 5) |
| 12 | 8 | 0번 칸 개수: `§f` + 숫자를 `~`로 채움. 1개면 `~`만 | `§f12~~~` |
| 20 | 11 | 1번 칸 아이템 | `xxxxxxxxxx0` |
| 31 | 8 | 1번 칸 개수 | `~~~~~~~~` |

- 칸 하나는 19바이트(아이템 11 + 개수 8)다. `n`번 칸의 아이템은 `1 + 19n`바이트, 개수는 `12 + 19n`바이트에서 시작한다.
- 팩의 자르기 `'%.Ns'`는 **바이트** 단위다. `§`는 2바이트이므로 `§f12`는 4바이트다. 위치로 자르는 앞쪽 칸은 ASCII로 두고, 한글처럼 여러 바이트인 글자는 맨 뒤에만 둔다.
- 0으로 채우거나 값을 더해 보내면 아이템으로 읽히지 않았다. 채움 글자(`x`, `~`)를 팩에서 지우는 방식이 동작했다.
- 부제목 맨 앞 `i`는 부제목을 문자열로 유지한다. 숫자만 보내면 부제목을 문자열로 다루는 바닐라 검사가 깨져 회색 칸과 "expected a string" 경고가 났다.

서버 쪽 칸 만들기의 예(Go):

```go
func itemField(runtimeID int32) string {
	if runtimeID == 0 {
		return "xxxxxxxxxx0"
	}
	n := strconv.Itoa(int(runtimeID) * 65536)
	return strings.Repeat("x", 11-len(n)) + n
}

func countField(count int) string {
	s := ""
	if count > 1 {
		s = "§f" + strconv.Itoa(count)
	}
	return s + strings.Repeat("~", 8-len(s))
}
```

런타임 ID는 서버가 클라이언트에 보낸 아이템 목록의 번호다. Dragonfly는 `world.ItemRuntimeID(item)`로 얻는다.

### 3.2 바닐라 제목에 붙이기 (`ui/hud_screen.json`)

바닐라 제목 라벨은 패널 제목일 때 숨기고, `root_panel`에 같은 이름의 엔진 팩토리 `hud_title_text_factory`를 한 번 더 선언한다(COL-14). 이 팩토리가 만든 컨트롤은 제목과 부제목을 **변수** `$title_text`, `$subtitle_text`로 받는다(COL-17).

```json
{
  "namespace": "hud",

  "hud_title_text": {
    "modifications": [
      {
        "array_name": "bindings",
        "operation": "insert_front",
        "value": [
          { "binding_type": "global", "binding_name": "#hud_title_text_string", "binding_name_override": "#text" }
        ]
      },
      {
        "array_name": "bindings",
        "operation": "insert_back",
        "value": [
          { "binding_type": "view", "source_property_name": "(not ('%.6s' * #text = 'panel:'))", "target_property_name": "#visible" }
        ]
      }
    ]
  },

  "root_panel": {
    "modifications": [
      {
        "array_name": "controls",
        "operation": "insert_front",
        "value": [
          {
            "item_hud_host": {
              "type": "panel",
              "size": [ "100%", "100%" ],
              "factory": {
                "name": "hud_title_text_factory",
                "control_ids": { "hud_title_text": "panel@item_hud.panel" }
              }
            }
          }
        ]
      }
    ]
  }
}
```

### 3.3 아이콘과 개수 칸 (`ui/item_hud.json`)

아래 예는 실측 구성을 두 칸짜리로 줄여 다시 쓴 것이다. 식과 구조는 실측 구성과 같지만, 이 형태 그대로 게임에서 시험하지는 않았다.

```json
{
  "namespace": "item_hud",

  "panel": {
    "type": "stack_panel",
    "orientation": "horizontal",
    "size": [ "100%c", 18 ],
    "anchor_from": "top_middle",
    "anchor_to": "top_middle",
    "offset": [ 0, 26 ],
    "ignored": "(not ('%.6s' * $title_text = 'panel:'))",
    "controls": [
      { "slot0@item_hud.slot": { "$index": 0 } },
      { "slot1@item_hud.slot": { "$index": 1 } }
    ]
  },

  "slot": {
    "type": "panel",
    "size": [ 18, 18 ],
    "$index|default": 0,
    "$aux|default": "0",
    "variables": [
      {
        "requires": "($index = 0)",
        "$aux": "((((('%.11s' * ($subtitle_text - ('%.1s' * $subtitle_text))) - 'xxxxxxxx') - 'xxxx') - 'xx') - 'x')"
      },
      {
        "requires": "($index = 1)",
        "$aux": "((((('%.11s' * ($subtitle_text - ('%.20s' * $subtitle_text))) - 'xxxxxxxx') - 'xxxx') - 'xx') - 'x')"
      }
    ],
    "controls": [
      {
        "icon": {
          "type": "custom",
          "renderer": "inventory_item_renderer",
          "size": [ 16, 16 ],
          "property_bag": { "#item_id_aux": "$aux" }
        }
      },
      {
        "count": {
          "type": "label",
          "anchor_from": "bottom_right",
          "anchor_to": "bottom_right",
          "font_scale_factor": 0.75,
          "shadow": true,
          "localize": false,
          "$count|default": "",
          "variables": [
            {
              "requires": "($index = 0)",
              "$count": "((((('%.8s' * ($subtitle_text - ('%.12s' * $subtitle_text))) - '~~~~~~~~') - '~~~~') - '~~') - '~')"
            },
            {
              "requires": "($index = 1)",
              "$count": "((((('%.8s' * ($subtitle_text - ('%.31s' * $subtitle_text))) - '~~~~~~~~') - '~~~~') - '~~') - '~')"
            }
          ],
          "text": "$count"
        }
      }
    ]
  }
}
```

`_ui_defs.json`에 `ui/item_hud.json`을 등록한다(FILE-01).

식 읽는 법:

- `($subtitle_text - ('%.20s' * $subtitle_text))`는 앞 20바이트를 뗀 나머지다. 거기서 `'%.11s' *`로 11바이트를 자르면 1번 칸 아이템 칸이 된다(EXP 장의 자르기).
- `- 'xxxxxxxx' - 'xxxx' - 'xx' - 'x'`는 채움 글자를 지운다. 8, 4, 2, 1개 묶음을 차례로 빼는 이 식이 실측에서 동작했다.
- 남은 숫자 글자를 `property_bag`의 `#item_id_aux`에 넣으면 렌더러가 그 아이템을 그린다. 빈 칸은 `0`(공기)이 되어 아무것도 그리지 않는다.
- 개수는 `§f`로 시작하므로 숫자로 바뀌지 않고 글자로 보인다.

### 3.4 칸이 많을 때

- 바인딩 식에는 `$변수`를 쓸 수 없고, 변수 블록의 식을 다른 식 안에 넣으면 계산되지 않았다. 그래서 **칸 번호마다 고정 식**을 미리 만들어 두고 `variables`의 `requires`로 골라 끼운다. 칸이 28개면 아이템 식 28개와 개수 식 28개다. 손으로 쓰지 말고 생성기로 만들고, 서버의 칸 폭 상수와 팩의 식이 같은지 시험으로 확인한다.
- 줄 단위로 칸이 비면 그 줄 전체를 `ignored`로 만들지 않는다(예: 두 번째 줄의 첫 칸이 비면 두 번째 줄을 만들지 않음). `ignored`는 생성 시 한 번 평가되지만, 제목이 바뀌면 팩토리가 컨트롤을 다시 만들므로 새 제목마다 다시 판정된다(FILE-17, COL-17).

### 3.5 보내는 쪽 규칙

- 부제목을 제목보다 먼저 보낸다. 아이콘이 든 부제목은 그 제목과 짝을 맞춰 도착해야 했다.
- 나타나기·사라지기 시간은 0으로, 머무는 시간은 길게(예: 60초) 보내고, 내용이 바뀌었을 때만 다시 보낸다. 바뀌지 않아도 머무는 시간이 끝나기 전(예: 30초마다)에 다시 보낸다.
- 제목은 한 번에 하나만 보인다. 레벨 업 같은 일반 제목을 보낼 때는 그 제목이 끝날 때까지 패널을 보내지 않는다. 늘 떠 있어야 하는 글자는 사이드바 스코어보드 같은 다른 채널로 옮긴다([HUD와 타이틀](../server-ui/hud-and-titles.mdx)의 6절).
- 시선 추적은 움직이거나 돌 때와 짧은 주기마다 한다. 작물은 단계에 따라 높이가 자라는 상자로, 충돌 상자가 없는 블록은 칸 전체로 판정하면 클라이언트 조준선과 맞는다.

## 4. 함정

| 증상 | 원인과 해결 |
| --- | --- |
| 아이콘이 비어 있다 | `#hud_subtitle_text_string` **바인딩** 식으로 칸을 꺼내면 자르기, 고정 폭, 더하고 빼기, 채움 글자 지우기 어느 형식으로도 아이콘이 비었다. 제목 팩토리 변수 `$subtitle_text`에서 꺼내 `property_bag`에 넣는다 |
| 회색 칸과 "expected a string" | 부제목을 숫자만으로 보냈다. 맨 앞에 글자(`i`)를 붙인다 |
| 개수나 숫자 글자가 안 보인다 | 숫자로 바뀐 값은 라벨에 보이지 않았다(`" 219"`, `"1,532/4,096"`). `§f`로 시작하는 칸으로 보내고, 식에서 글자로 만들려면 `'§r' + 값`을 쓴다 |
| 개수 식이 계산되지 않는다 | 개수 식은 **라벨 자신의** `variables`에 둔다. 부모 패널에 둔 식이나 `text` 안의 `('§r' + $변수)`는 계산되지 않았다 |
| 한 글자 플래그 비교가 안 맞는다 | 숫자 한 글자는 숫자로 바뀌어 글자 비교가 어긋났다. 플래그는 `a`~`k` 같은 글자로 쓰고, 변수 블록에서는 식이 아니라 고정 글자로 고른다 |
| "Must define a source property name" | `#바인딩`을 하나도 쓰지 않는 view 바인딩 식이 있다. 변수만 쓰는 계산은 바인딩이 아니라 변수로 둔다 |
| 칸 위치가 한 칸씩 밀린다 | 앞쪽 칸에 여러 바이트 글자가 섞였다. 위치로 자르는 칸은 ASCII만 쓴다 |

## 5. Script API 애드온이라면

- 숫자 ID를 얻는 공개 API가 없으므로 3절의 방법을 쓰려면 아이템 이름과 숫자 ID를 잇는 표가 필요하다. 이런 표(`typeIds` 등)는 커스텀 아이템이 추가되면 바닐라 ID가 밀리고 릴리스마다 낡는다는 보고가 있다(커뮤니티 보고). `ItemTypes.getAll()`로 런타임에 표를 만들자는 제안도 있었지만, 그 순서가 클라이언트의 숫자 ID와 같은지는 확인되지 않았다(*unverified*).
- 그래서 Script API 애드온은 지금도 인벤토리 거울(2.1절)이나 텍스처 경로(2.2절)가 현실적이다. 인벤토리 거울을 쓴다면 플레이어 아이템의 백업과 복원을 가장 먼저 설계한다.
