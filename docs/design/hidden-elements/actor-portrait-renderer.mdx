# actor_portrait_renderer로 엔티티 초상 그리기

`actor_portrait_renderer`는 월드에 있는 엔티티 하나를 UI 컨트롤 안에 그리는 렌더러다. 바닐라는 NPC 화면(`npc_interact_screen.json`의 `skin_model`) 한 곳에서만 쓰고 `property_bag`을 적지 않는다. 어떤 엔티티를 어떻게 그릴지는 `property_bag`의 키로 정하는데, 이 키들은 바닐라 파일에도, 커뮤니티 기록에도 나오지 않는다. 이 문서는 [잘 알려지지 않은 요소 심층 조사](./index.mdx)의 하위 기획으로, 그 키들을 HUD에서 실측한 결과와 쓰는 법을 정리한다.

## 1. 결론

- 정적 `property_bag`에 정수 `actor_id`를 적으면 그 엔티티를 그린다. 값은 Script API의 `entity.id`(월드에 저장되는 엔티티 고유 ID)다. 플레이어, 돼지, 말, 고양이, 갑옷 거치대를 그렸고 수레와 보트는 그리지 않았다.
- `scale_*`, `rotate_*`, `translate_x`, `translate_y`로 크기, 방향, 위치를 바꾸고, `rotate_mode: "auto"`로 계속 돌릴 수 있다. 이 값들은 바인딩으로 런타임에 바꿀 수 있다.
- **한계: 애드온에서 동적으로 쓰기는 어렵다.** JSON UI 계산식은 32비트 정수만 다루는데, 이 렌더러는 64비트 정수 ID를 요구한다. 엔티티 ID는 늘 32비트 범위를 벗어나고, 바인딩이나 식을 지나면 아래 32비트만 남는다. 문자열과 실수는 렌더러가 받지 않는다(4절).
- **쓸 수 있는 방식: 정적 ID.** 사설 서버 소프트웨어처럼 엔티티 ID를 정할 수 있는 쪽에서 특정 엔티티의 ID를 리소스 팩의 `property_bag`에 JSON 정수로 미리 적어 두고, 그 ID로 엔티티를 쓰면 그릴 수 있다.
- 제목 팩토리로 만든 컨트롤은 제목을 다시 보낼 때마다 새로 만들어져 회전이 되감긴다.
- NPC 편집 화면은 칸마다 이 키들을 다시 써서 팩이 적은 값을 덮어쓴다.
- 엔티티를 그리는 렌더러 여섯 가운데 정수 ID로 엔티티를 고르고 변환을 마음대로 주는 것은 이 렌더러뿐이다. 내 모습만 그리면 되면 ID가 필요 없는 플레이어 렌더러가 낫다(7절).

## 2. property_bag 키

| 키 | 값 | 실측 |
| --- | --- | --- |
| `actor_id` | JSON 정수(64비트) | `entity.id` 문자열의 숫자를 JSON 정수로 적으면 그 엔티티를 그렸다. 같은 숫자를 JSON 문자열이나 소수로 적으면 렌더러가 받지 않는다. 바인딩이나 식으로 넣어도 그리지 않았다. 계산식은 32비트 정수만 다뤄 64비트 ID를 담지 못한다(4절) |
| `scale_x`, `scale_y`, `scale_z` | 숫자, 기본 1 | 0.5로 절반 크기. `scale_y`만 줄이면 위아래로 납작해진다 |
| `rotate_x`, `rotate_y`, `rotate_z` | 숫자(도), 기본 0 | `rotate_y` 180은 등을 보였고, `rotate_x` 45는 앞으로 기울었다. `rotate_z`는 화면 앞뒤 축으로 돌아 45는 기울고 90은 눕는다 |
| `translate_x`, `translate_y` | 숫자, 기본 0 | 1이 UI 1픽셀이다. `translate_x` 양수는 오른쪽, `translate_y` 양수는 아래쪽이다. `rotate_y` 90과 함께 줘도 화면 기준으로 움직인다 |
| `translate_z` | 숫자, 기본 0 | 50을 줘도 변화가 없었다 |
| `rotate_mode` | 문자열 | `"auto"`면 계속 돈다(5절) |
| `use_live_animation` | 불리언 | `true`, `false`, 키 없음 사이에 차이가 보이지 않았다. 플레이어가 고개를 위(-60)로 들든 아래(60)로 숙이든 셋 다 정면을 봤다 |
| `skin` | 문자열(JSON) | `"{\"variant\":3}"`은 말 털색을, `"{\"variant\":5}"`는 고양이 털색을 바꿨다. `"{\"mark_variant\":2}"`는 말에 흰 무늬를 넣었다 |

감정 표현, 공격, 웅크리기 애니메이션은 키와 상관없이 모든 칸에 보였다. 걷기와 시점 방향은 어느 칸도 따르지 않았다. 그려지는 크기는 엔티티 크기에 비례해서, 같은 칸에서 고양이는 아주 작고 말은 플레이어만큼 크다.

## 3. HUD에 내 초상 그리기

```json
"portrait": {
  "type": "custom",
  "renderer": "actor_portrait_renderer",
  "size": [ 44, 63 ],
  "enable_scissor_test": true,
  "layer": 2,
  "property_bag": { "actor_id": -4294967295, "rotate_mode": "auto" }
}
```

- 크기는 컨트롤 크기를 따른다. 위 크기에서 플레이어 전신이 칸 아래쪽에 맞춰 그려졌다.
- 플레이어 ID는 월드마다 다르다. 이 문서의 시험에서는 `-4294967295`와 `-8589934591`이었다. 4.1절의 규칙으로 보면 앞의 것은 그 월드를 처음 불러온 세션에, 뒤의 것은 둘째 세션에 처음 들어온 플레이어다 *(추론)*. ID가 다르면 아무것도 그리지 않는다. 예제 애드온은 액션바에 내 ID를 띄워 맞는지 알려 준다.
- HUD에 띄우는 방법은 [HUD 아이템 아이콘](../hud-item-icons.mdx) 3.2절처럼 `hud_title_text_factory`를 `root_panel`에 한 번 더 선언하고, 제목 글자로 패널을 고른다.

## 4. 엔티티 ID와 사용의 한계

### 4.1 엔티티 ID가 정해지는 규칙

- 월드를 불러올 때 게임은 `level.dat`의 `worldStartCount`(32비트로 보면 음수)를 그 세션의 위쪽 32비트로 쓰고, 파일에는 1 줄인 값을 바로 저장한다.
- 엔티티 ID는 `worldStartCount x 2^32 + 그 세션에서 만든 순번`이고, 순번은 1부터 센다.
- 한 번 정해진 ID는 월드를 다시 들어와도 바뀌지 않는다.

| 관찰 | 값 |
| --- | --- |
| 파일이 -102일 때 들어간 세션에서 소환한 돼지 | `-438086664191` = -102 x 2^32 + 1 |
| 그 세션에서 이어 소환한 수레, 보트 | -102 x 2^32 + 2, + 3 |
| 그 세션에 들어간 직후의 파일 | -103 |
| 앞선 세션에서 소환한 돼지 | 위쪽 값 -98, -99, -101 |
| 같은 월드의 플레이어 | `-8589934591` = -2 x 2^32 + 1(둘째 세션에 처음 들어온 것으로 보인다) |

그래서 플레이어를 포함한 모든 엔티티 ID는 32비트 정수 범위(-2147483648 ~ 2147483647)를 벗어난다.

### 4.2 런타임에 바꿀 수 있는 것

변환 키는 바인딩으로 런타임에 바꿀 수 있다. 스크립트가 `updateSubtitle`로 부제목만 0, 45, 90으로 바꾸자, 부제목을 숫자로 바꿔(`(('' + #s) + 0)`) 바인딩한 칸이 제목을 다시 보내지 않고도 따라 바뀌었다.

| 키 | 결과 |
| --- | --- |
| `rotate_x`, `rotate_y`, `rotate_z` | 45, 90에 따라 돌았다 |
| `translate_x`, `translate_y` | 값만큼 옮겨졌다 |
| `scale_x`, `scale_y`, `scale_z` | `((('' + #s) + 0) * .01)`에 25를 보내자 0.25배가 됐다 |

```json
"bindings": [
  { "binding_name": "#hud_subtitle_text_string", "binding_name_override": "#s", "binding_type": "global" },
  { "binding_type": "view", "source_property_name": "(('' + #s) + 0)", "target_property_name": "rotate_y" }
]
```

바인딩 대상은 `#`이 없는 키 이름(`rotate_y`)이어야 한다. `#rotate_y`에 쓰면 바뀌지 않았다.

### 4.3 actor_id를 런타임에 넣을 수 없는 이유

바인딩이 다루는 정수는 32비트다. 정수를 읽는 순간 아래 32비트만 남기므로, 64비트 엔티티 ID는 바인딩을 지나면 다른 값이 된다.

| 바인딩 식으로 읽은 값 | 결과 |
| --- | --- |
| `property_bag`의 `-8589934591` | `1` |
| `property_bag`의 `2147483648` | `-2147483648` |
| `2147483647 + 1` | `-2147483648` |
| `65536 * 65536` | `0` |
| 리터럴 `2147483648`, `4294967296` | 빈 값 |
| 부제목 문자열 `12`를 `('' + #s)`로 바꾼 뒤 1을 더함 | `13` |
| 부제목 문자열 `-8589934591`을 같은 방법으로 바꿈 | 빈 값 |

`actor_id`에 넣어 본 방법은 정적 정수와 그 정수를 담은 변수만 그렸다.

| 넣은 방법 | 결과 |
| --- | --- |
| JSON 정수, JSON 정수를 담은 변수(`"$id": -8589934591`) | 그렸다 |
| `variables`의 `requires`로 고른 JSON 정수 | 그렸다 |
| JSON 문자열 `"-8589934591"`, 소수 `-8589934591.0` | 빈 칸 |
| 문자열 변수(`$subtitle_text`), `"($subtitle_text * 1)"` 같은 식 | 빈 칸 |
| 문자열 바인딩, 따옴표로 감싼 문자열 바인딩(`('"' + #s + '"')`) | 빈 칸 |
| 숫자로 바꾸려는 식(`('' + #s)`, `(#s - 0)`, `(#s * 1)`) | 빈 칸 |
| 같은 `property_bag`이나 다른 컨트롤의 64비트 정수를 식 없이 옮김(`"source_property_name": "#src"`) | 빈 칸. 같은 방법으로 90을 `rotate_z`에 옮기면 동작했다 |

클라이언트 코드(Android 1.26.52.3)에서 읽은 처리도 같다 *(코드)*.

- 렌더러는 `property_bag`의 `actor_id` 하나로만 엔티티를 고른다. 값의 JSON 종류가 정수인지만 보고 64비트로 읽은 뒤, 레벨에서 그 ID의 엔티티를 찾는다.
- 찾은 엔티티의 `ActorTypeComponent` 형식에 몹 비트(`0x100`)가 있어야 그린다. 수레와 보트를 그리지 않은 실측과 맞다.
- `property_bag`의 `actor_id`에 64비트 정수를 쓰는 엔진 코드는 NPC 화면 콜백(5절)뿐이다. 이 값은 C++이 직접 써서 바인딩을 거치지 않는다.

`live_horse_renderer`의 `#entity_id`는 문자열을 받아 엔진이 정수로 바꿔 읽으므로 바인딩으로 넘길 수 있다. `actor_portrait_renderer`는 정수만 받으므로 같은 방법이 통하지 않는다.

### 4.4 쓸 수 있는 방법

- **ID가 바뀌지 않는 엔티티:** 엔티티 ID는 다시 들어와도 그대로다. 맵이나 서버에서 NPC 같은 엔티티를 한 번 소환해 `entity.id`를 읽고, 그 값을 리소스 팩에 적으면 계속 그려진다.
- **후보 ID 고르기:** 후보 ID를 JSON 정수로 적어 두고, 스크립트가 제목이나 부제목으로 보낸 ID와 같은 후보를 `requires`로 고른다. 제목 팩토리는 제목이 올 때마다 컨트롤을 새로 만들므로 그때 고른 값이 들어간다.

```json
"variables": [
  { "requires": "($subtitle_text = '-4294967295')", "$bag": { "actor_id": -4294967295 } },
  { "requires": "($subtitle_text = '-8589934591')", "$bag": { "actor_id": -8589934591 } }
]
```

- 단일 플레이어 월드 주인의 ID는 `-k x 2^32 + 1` 꼴이고, 지금까지 본 k는 1과 2다. 그래서 후보 몇 개로 대부분의 주인을 덮을 수 있을 것으로 본다. 새 월드에서 처음 들어갈 때의 k는 재지 않았다.
- 여러 플레이어 월드에서 나중에 들어온 플레이어는 위쪽 값이 그때까지 월드를 불러온 횟수만큼 커지고, 순번도 그 세션에 먼저 만들어진 엔티티 수만큼 커진다. 후보로 덮을 수 없다.

## 5. 회전이 되감기는 이유

시험 팩이 처음에 아이템을 든 동안 1초마다 제목을 다시 보냈더니, `"auto"` 칸이 돌다가 처음 각도로 되감기기를 되풀이했다. 제목이 다시 오면 제목 팩토리가 컨트롤을 새로 만들고, 새 컨트롤은 회전을 0부터 시작한다(ANI-12와 같은 원인). 제목을 처음 한 번만 보내고 유지 시간을 길게 두자 끊기지 않고 돌았다.

돌리는 초상은 내용이 자주 바뀌지 않는 컨트롤에 둔다. 제목으로 다른 정보를 자주 보내야 하면 초상은 다른 팩토리나 고정 컨트롤로 뺀다. 부제목만 바꾸는 `updateSubtitle`은 4.2절처럼 같은 칸의 값을 바꿨다.

## 6. NPC 화면

NPC 편집 화면의 외형 목록은 칸마다 NPC 외형을 이 렌더러로 그린다. 리소스 팩이 `npc_interact.skin_model`에 `property_bag { "rotate_mode": "auto", "scale_*": 0.6 }`를 더해도 바뀌지 않았다. 대신 호버한 외형만 돌았고, 초상은 실제 NPC가 고개를 돌리면 따라 돌았다. 화면이 칸마다 외형의 변환, `rotate_mode`(호버한 칸만 `"auto"`), `actor_id`(그 NPC)를 다시 써 넣는다 *(코드)*. 이 값들은 NPC의 `NpcComponent`에서 읽어 C++이 직접 쓴다. 이 화면의 초상은 팩으로 바꿀 수 없다. NPC 대화 화면은 시험하지 않았다.

## 7. 다른 엔티티 렌더러와의 차이

엔티티나 캐릭터를 그리는 다른 렌더러와 비교한 것이다. 각 렌더러가 읽는 키와 동작은 클라이언트 코드(Android 1.26.52)에서 읽었고, 이 절의 내용은 `actor_portrait_renderer` 줄의 실측 말고는 게임에서 시험하지 않았다 *(코드)*.

| 렌더러 | 그리는 것 | 고르는 방법 | 회전 | 바닐라 쓰임 |
| --- | --- | --- | --- | --- |
| `actor_portrait_renderer` | 월드의 몹 | `property_bag`의 정수 `actor_id`(정적 값만) | `property_bag`의 크기, 회전, 이동(바인딩으로 런타임 변경 가능)과 `rotate_mode: "auto"`. 커서를 보지 않는다 | NPC 화면 |
| `live_horse_renderer` | 월드의 몹 | `#entity_id`(문자열만. 정수로 적으면 그리지 않는다) | 늘 커서를 본다. 끄는 키가 없다 | 말 화면 |
| `live_player_renderer` | 로컬 플레이어 | 고를 수 없다 | 정면 고정. `#look_at_cursor: true`면 머리와 몸이 커서를 본다 | 인벤토리 화면 |
| `hud_player_renderer` | 로컬 플레이어 | 고를 수 없다 | 비스듬히 고정. 플레이어 상태가 바뀐 뒤 몇 초만 그린다 | HUD 인형 |
| `paper_doll_renderer` | 월드 엔티티가 아니라 스킨으로 만든 모델 | 선택한 스킨, `#skin_idx`와 `#pack_id`, `#skin_name`, `#player_uuid` | `rotation`(`auto`, `gesture_x`, `custom_y`), `#custom_rot_y`, `#set_target_rotation`. 애니메이션은 `#animation_to_play`로 고른다 | 일시 정지 화면, 스킨 화면 |
| `equipment_preview_renderer` | 스스로 만든 갑옷 거치대가 입은 아이템 | `#item_id_aux`, 염색 색, 갑옷 장식 | 고정 각도 | 대장장이 작업대 |

### 7.1 렌더러별 키와 조건

**`live_horse_renderer`**
- 읽는 키: `property_bag`의 `#entity_id` 하나. 문자열이어야 하고 엔진이 10진 정수로 바꿔 읽는다. JSON 정수로 적으면 읽지 못해 아무것도 그리지 않는다. 바닐라 말 화면은 이 값을 바인딩으로 받는다.
- 조건: 찾은 엔티티가 몹 분류여야 그린다. 아이템 엔티티, 투사체 같은 것은 그리지 않는다. 말 화면인지는 검사하지 않으므로 다른 화면에서도 `#entity_id`만 주면 그릴 것으로 보인다 *(추론)*.
- 회전: 머리와 몸이 늘 커서 쪽을 본다(가로, 세로 거리를 40으로 나눈 값의 아크탄젠트 x 20도). 마우스가 아닌 입력에서는 고정된 거리로 계산한다. 크기는 컨트롤 너비를 따른다.

**`live_player_renderer`**
- 그리는 것: 로컬 플레이어만. ID를 받지 않는다. 플레이어에 연결된 엔티티도 함께 그리는 반복이 있다 *(무엇인지 확인 못 함)*.
- 읽는 키: `property_bag`의 `#look_at_cursor`(불리언 `true`일 때만 켜짐). 바닐라 PC 인벤토리 화면은 `true`, 포켓 인벤토리 화면은 키가 없다.
- 회전: 정면을 보도록 180도 돌린다. `#look_at_cursor`면 머리와 몸이 커서를 보고, 아니면 고정이다. 크기는 너비와 높이 중 작은 값이다. 잠자기 같은 플레이어 상태에 따라 0.6배로 줄이고 기울이는 분기가 있다 *(상태 이름은 추론)*.

**`hud_player_renderer`**
- 그리는 것: 로컬 플레이어만. 읽는 키가 없다.
- 회전: 몸과 머리를 -22.5도 돌린 비스듬한 고정 자세다.
- 조건: 플레이어 상태가 바뀌면 타이머를 3초로 두고 그 동안만 그린다. HUD 왼쪽 위에 잠깐 나타나는 인형이 이것이다.

**`paper_doll_renderer`**
- 그리는 것: 월드 엔티티가 아니라 스킨으로 만든 플레이어 모델이다. 월드가 없는 메뉴에서도 그린다.
- 스킨 고르기: 컨트롤 속성 `use_selected_skin`(기본 참), `use_uuid`, `use_skin_by_name`과 `property_bag`의 `#skin_idx`, `#pack_id`, `#skin_name`, `#player_uuid`.
- 회전: 컨트롤 속성 `rotation`이 `auto`(누적 시간 x 30도), `gesture_x`(끌기), `custom_y`(`#custom_rot_y` 값)를 고르고, `starting_rotation`, `camera_tilt_degrees`가 시작 각도와 카메라 기울기를 정한다. `#set_target_rotation`을 주면 그 각도까지 돌았다가 원래 방식으로 돌아간다. 바닐라는 `#skin_rotation`으로 `auto`를 켠다.
- 애니메이션: `#animation_to_play`, `#animation_to_play_when_done`, `#sound_to_play`로 고른다. `#disable_head_follow_mouse`면 머리가 커서를 보지 않는다.

**`equipment_preview_renderer`**
- 그리는 것: 렌더러가 스스로 만든 `minecraft:armor_stand`가 입은 아이템이다.
- 읽는 키: `#item_id_aux`, `#item_custom_color`, `#armor_trim_pattern`, `#armor_trim_material`.
- 회전: 고정 각도다. 바닐라 대장장이 작업대는 `rotation_x` 30, `rotation_y` -30을 준다.

### 7.2 무엇을 쓸까

| 하고 싶은 것 | 맞는 렌더러 |
| --- | --- |
| 정해진 엔티티 하나를 원하는 각도와 크기로, 또는 계속 돌리며 | `actor_portrait_renderer` |
| 화면이 알려 주는 몹(문자열 ID)을 커서를 보는 모습으로 | `live_horse_renderer` |
| 내 모습을 여러 플레이어 월드에서도 ID 없이 | `live_player_renderer`, `paper_doll_renderer` |
| 월드 밖 메뉴에서 스킨 미리 보기, 끌어서 돌리기, 애니메이션 고르기 | `paper_doll_renderer` |
| 갑옷이나 장식 아이템 미리 보기 | `equipment_preview_renderer` |

- 정수 ID로 몹을 고르고 크기와 방향을 마음대로 바꾸는 것은 `actor_portrait_renderer`뿐이다. 대신 ID를 리소스 팩에 미리 적어야 한다(4.3절).
- `live_horse_renderer`는 ID를 문자열로 받으므로 바인딩으로 바꿔 줄 수 있을지도 모른다. 늘 커서를 보므로 HUD 초상에는 맞지 않는다.
- 플레이어를 그리는 세 렌더러는 ID가 필요 없지만 변환 키가 없다.

## 8. 예제 애드온

<AddonDownload id="actor-portrait" />

1. 파일을 열어 가져온다(모바일은 파일을 눌러 Minecraft로 연다). 새 단일 플레이어 월드에서 행동 팩 `[bedrock-research]actor-portrait-bp`로 시작하는 팩을 켠다. 리소스 팩은 의존성으로 함께 켜지고 실험 토글은 필요 없다.
2. 크리에이티브 인벤토리 아이템 분류의 맨 뒤에서 "Actor Portrait"(망원경)를 꺼낸다. `/give @s bwiki:actor_portrait_test`를 써도 된다.
3. 든 동안 HUD 왼쪽 위에 초상 넷이 나온다. Still은 그대로, Auto는 계속 돌고, Back은 절반 크기로 등을 보이고, Tilt는 앞으로 기운다. 내려놓으면 사라진다.

- v1.1.0은 4.4절의 후보 방식을 쓴다. 스크립트가 제목 `apt`의 부제목으로 내 `entity.id`를 보내고, 칸마다 `-k x 2^32 + 1`(k = 1~32) 후보 32개 가운데 부제목과 같은 값을 `requires`로 골라 `actor_id`에 넣는다. 내 ID가 후보에 없으면 초상이 비고, 액션바가 그 사실을 알려 준다.
- 내려놓으면 `title @s clear` 명령으로 제목을 지운다. 보였는지는 플레이어 동적 속성에 적어 두므로 스크립트를 다시 읽어도 지운다. v1.0.0은 Script API 2.0.0에 없는 `clearTitle`을 불러 오류가 나서 제목이 남았다.
- 가운데의 `apt` 글자와 그 아래 ID는 바닐라 제목과 부제목이다. 다른 HUD 예제와 함께 켜도 되도록 숨기지 않는다.
- v1.1.0은 아직 게임에서 돌려 보지 않았다. 후보를 `requires`로 고르는 방식과 제목 지우기 방식은 각각 시험 팩으로 확인했다(4.3절, 9절).
- 화면의 글은 영어다.

## 9. 실측 기록

연구 저장소의 시험 팩(`ui-key-probe` v1.0.0~v1.0.1, 출처 약어 `UKP`)으로 터치 입력 기기에서 2026-11-17에 실측했다. 시험 팩은 위 네 칸 말고도 `translate_x`, `use_live_animation`, 식으로 만든 ID 칸과 NPC 화면 수정을 함께 담았다. 예제 애드온은 그중 동작을 확인한 키만 옮긴 것이다. 예제 애드온 v1.0.0도 같은 기기에서 돌려 네 칸이 모두 기획대로 그려지는 것을 확인했다(위 그림).

2026-11-20에 Windows 1.26.65.1 단일 플레이어 월드에서 시험 팩으로 v1.0.0의 제목이 남는 원인(`clearTitle` 호출 오류)과 `title @s clear`로 고친 방식(`/reload` 뒤에도 지워짐), 4절의 ID 규칙과 주입 방법, 2절의 `rotate_z`, `translate_*`, `skin`, `use_live_animation`, 몹이 아닌 엔티티, 4.2절의 런타임 변환을 쟀다. 4.3절의 코드 내용은 Android 1.26.52.3 클라이언트 라이브러리를 역컴파일해 읽었다.

## 남은 일

- 새 월드에 처음 들어갈 때 주인의 ID(k가 늘 1인지).
- `use_live_animation`이 바꾸는 것. 코드는 거짓일 때 몸과 머리 회전 일부를 0으로 맞추지만, 고개 각도로는 차이가 보이지 않았다.
- 직접 만든 서버에서 서버가 정한 ID로 그리는지, 콘솔과 모바일, 여러 플레이어 월드.
