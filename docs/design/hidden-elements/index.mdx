# 잘 알려지지 않은 요소 심층 조사

JSON UI는 바닐라 파일과 커뮤니티가 쓰는 범위만 알려져 있다. 클라이언트는 그보다 많은 이름을 읽는다. 이 기획은 클라이언트가 읽지만 바닐라가 거의 쓰지 않거나 어디에도 쓰는 법이 적혀 있지 않은 요소를 골라, 시험 팩으로 실제 동작을 확인하고 쓸 수 있는 것을 문서로 남긴다.

## 1. 찾는 방법

1. 바닐라 `resource_pack/ui`가 쓰는 속성, 바인딩, 렌더러 이름을 모두 모은다. `property_bag` 안의 키도 포함한다.
2. 클라이언트(Windows 1.26.63, Android 1.26.52)가 JSON UI를 해석하며 읽는 이름 가운데 1에 없는 것을 고른다. 해석 코드에서 그 이름을 실제로 읽는지 확인한다.
3. 이 위키, 커뮤니티 대화 기록, 다른 문서 사이트에서 그 이름을 찾는다. 이미 쓰는 법이 알려진 것은 뺀다.
4. 남은 것을 시험 팩에 늘어놓고 게임에서 확인한다. 실측한 것만 규칙과 하위 문서로 옮긴다.

2의 결과는 근거 수준 `코드`다. 게임에서 확인하기 전까지는 쓰는 법을 적지 않는다.

## 2. 후보와 상태

| 요소 | 바닐라 | 기존 기록 | 상태 |
| --- | --- | --- | --- |
| `actor_portrait_renderer`의 `property_bag` 키(`actor_id`, `scale_*`, `rotate_*`, `translate_*`, `rotate_mode`, `use_live_animation`, `skin`) | 렌더러 1회(NPC 화면), 키 0회 | 없음 | 실측 일부. [하위 문서](./actor-portrait-renderer.mdx) |
| `progress_bar_renderer`의 `is_durability`, `is_storage_bar`, `drop_shadow`, `round_value` | 내구도 막대, 꾸러미 막대 | 내구도 막대 설정을 옮겨 적은 것뿐 | 실측 일부(ANI-43). 정적 값으로 그리기와 내구도 색만 확인 |
| `vignette_renderer`의 `opacity_override` | 1회(제작진 화면, `0.0`) | 없음 | 미실측 |
| `toggle_manager_behavior`, `toggle_manage_groups` | 0회 | 없음 | 미실측. 토글 그룹 상태를 모으거나 지우는 관리자로 보인다 *(코드)* |
| `slider_manager_behavior`, `slider_manage_groups` | 0회 | 없음 | 미실측 |
| `follows_cursor_inside_parent`, `priority_rule`, `alternate_input_scope` | 0회 | 없음 | 미실측 |
| `slider_inverted`, `slider_speed` | 0회 | JSON UI LSP 사전에 이름만 | 미실측 |
| `vertical_scroll_delta` | 0회 | NetEase 문서에서 중국판 전용으로 분류 | 미실측. 국제판도 읽는다 *(코드)* |
| `tts_index_order` | 0회 | 없음 | 미실측 |
| 렌더러 `bohr_model_renderer`, `gfx_multithreaded_renderer` | 0회 | 없음 | 미실측 |

## 3. 하위 문서

| 문서 | 내용 | 예제 애드온 |
| --- | --- | --- |
| [actor_portrait_renderer로 엔티티 초상 그리기](./actor-portrait-renderer.mdx) | `property_bag`의 엔티티 ID와 변환 키로 HUD에 플레이어 초상을 그리는 법, 회전과 화면별 한계 | `actor-portrait` |

## 4. 남은 일

- 미실측 후보를 시험 팩에 넣어 확인한다. 토글 관리자처럼 동작을 짐작하기 어려운 것은 값마다 칸을 나눠 비교한다.
- `progress_bar_renderer`의 나머지 키는 막대를 크게 그려 픽셀 차이를 다시 본다.
- 실측은 터치 입력 기기 한 대뿐이다. PC와 콘솔은 시험하지 않았다.
