# grid 버튼 목록

[JSON UI 최적화](./index.mdx)의 규칙으로 서버 폼(액션 폼) 버튼 목록을 그리는 기획이다. 바닐라 서버 폼은 버튼이 수천 개면 여는 데 오래 걸리거나 멈춘다(커뮤니티 보고, [JSON UI 최적화](./index.mdx) 4절). 이 구성은 같은 버튼 데이터를 2열 grid로 그려 버튼 2000개 목록도 열고 끝까지 스크롤한다.

## 1. 목표

- 버튼 수천 개의 서버 폼을 멈춤 없이 연다.
- 이 폼이 아닌 서버 폼에서는 아무것도 만들지 않는다(생성 게이트, [JSON UI 최적화](./index.mdx) 2절).
- 칸마다 아이콘, 이름, 설명, 진행 막대를 그리고, 누르면 그 버튼이 서버로 간다.
- 다른 서버 폼 예제와 한 월드에 함께 켜도 서로 건드리지 않는다([JSON UI 최적화](./index.mdx) 9절).

## 2. 화면 구조

| 층 | 컨트롤 | 하는 일 |
| --- | --- | --- |
| 1 | `server_form.json`의 `main_screen_content` | `modifications`로 라우터를 `server_form_factory` 옆에 넣는다. 제목이 `§b§w`로 시작하면 바닐라 `long_form`을 숨긴다 |
| 2 | 라우터 `screen_router` (`collection_panel`) | 제목 앞 10바이트로 `property_bag`의 `#§b§wjp:J`를 조회해 `#collection_length`에 넣는다. 이 제목이면 창 하나, 아니면 0개를 만든다(HOST-06, COL-22, COL-23) |
| 3 | 창 `list_window` | 배경, 제목 줄, 닫기 버튼, 스크롤 영역. 스크롤 영역은 창 안에 둔다. 창 밖에 늘 두면 다른 폼의 터치를 가져갔다(LAY-57) |
| 4 | 스크롤 영역 `common.scrolling_panel` | `$scrolling_content`로 grid를 감싼 패널을 받는다 |
| 5 | grid `list_grid` | `collection_name: "form_buttons"`, `grid_item_template`로 칸을 만든다. 칸 수는 `#form_button_length`를 `#maximum_grid_items`에 넣어 정한다 |
| 6 | 칸 `list_cell` (`common.button`) | `collection_details`로 자기 버튼 번호를 받는다. 누르면 `button.form_button_click`이 그 번호로 나간다 |
| 7 | 칸 모양 `list_face` | default, hover, pressed 세 상태가 같은 정의를 쓰고 배경 텍스처만 다르다 |

게이트 팩토리가 만든 창 안에서 액션 폼 버튼 데이터는 grid + `collection_name`의 칸에만 닿았다. 고정 `collection_index` 칸과 안쪽 팩토리는 비었다(COL-40). 그래서 목록은 grid로 짠다. 화면 맨 위 라우터가 만든 창에서는 고정 칸과 스택 팩토리도 바인딩을 `always`로 두면 채워졌다(COL-47, C-65).

## 3. 칸의 바인딩

```json title="rp/ui/jup.json (일부)"
"name": {
  "type": "label", "layer": 3, "size": [ 76, 10 ], "offset": [ 22, 3 ],
  "anchor_from": "top_left", "anchor_to": "top_left",
  "color": [ 0.1, 0.1, 0.1 ], "localize": false, "text": "#text",
  "bindings": [
    { "binding_type": "collection", "binding_collection_name": "form_buttons", "binding_name": "#form_button_text" },
    { "binding_type": "view", "source_property_name": "('%.12s' * #form_button_text)", "target_property_name": "#text" }
  ]
},

"list_cell@common.button": {
  "size": [ 100, 30 ],
  "$focus_enabled": false,
  "$pressed_button_name": "button.form_button_click",
  "bindings": [ { "binding_type": "collection_details", "binding_collection_name": "form_buttons", "binding_condition": "always" } ],
  "controls": [
    { "default@jup.list_face": {} },
    { "hover@jup.list_face": { "$bg_texture": "textures/ui/button_borderless_lighthover" } },
    { "pressed@jup.list_face": { "$bg_texture": "textures/ui/button_borderless_lightpressed" } }
  ]
},

"list_grid": {
  "type": "grid",
  "size": [ 200, "100%c" ],
  "grid_rescaling_type": "horizontal",
  "grid_item_template": "jup.list_cell",
  "collection_name": "form_buttons",
  "bindings": [
    { "binding_name": "#form_button_length", "binding_name_override": "#maximum_grid_items", "binding_condition": "always" }
  ]
}
```

| 바인딩 | 조건 | 이유 |
| --- | --- | --- |
| grid 길이 `#maximum_grid_items` | `always` | 라우터 창 안에서 칸의 바인딩과 팩토리 길이 바인딩은 기본 조건이면 처음에 비었다(COL-47, COL-48). grid 길이를 기본 조건으로 둔 구성은 재지 않았다 |
| 칸의 `collection_details` | `always` | 같은 이유. 칸이 자기 버튼 번호를 잃으면 누른 버튼이 다른 번호로 간다 |
| 아이콘 `#form_button_texture` | 없음 | 컬렉션 바인딩 하나로 `#texture`에 바로 넣는다 |
| 이름, 설명, 진행 막대 | 없음 | 컬렉션 바인딩으로 `#form_button_text`를 먼저 받고, 뒤의 view 바인딩이 그 값을 잘라 쓴다. v1.3.1까지는 둘 다 `always`였다. 빼는 방법과 비교는 [always 없이 첫 화면 채우기](./collection-view-order.mdx)에 있다 |

- 라벨은 `layer: 3`, 아이콘은 `layer: 2`로 배경보다 위에 둔다. 배경과 같은 레이어면 스크롤 영역 안 글자가 무언가를 건드리기 전까지 비어 보였다(LAY-55).
- `$focus_enabled: false`로 칸이 게임패드·키보드 포커스를 받지 않는다.

## 4. 버튼 글 나누기

서버 폼 버튼은 글 하나와 아이콘 하나만 보낸다. 스크립트가 글을 고정 폭으로 붙여 보내고, 칸이 잘라 쓴다.

| 부분 | 스크립트가 만드는 것 | 칸의 식 |
| --- | --- | --- |
| 이름 | 12자로 채움 (`Item 7      `) | `('%.12s' * #form_button_text)` |
| 설명 | 20자로 채움 | `(('%.32s' * #form_button_text) - ('%.12s' * #form_button_text))` |
| 진행 값 | 0~100 숫자 글 | `(1 - (((#form_button_text - ('%.32s' * #form_button_text)) - 0) / 100))`를 `#clip_ratio`에 넣음 |

- `'%.Ns' * #text`는 앞 N바이트를 자르고, 문자열 `-` 문자열은 그 부분을 지운다.
- 진행 값은 지운 뒤에도 문자열이다. **나누기 전에 `- 0`으로 숫자로 바꾼다**(EXP-16). 문자열을 숫자로 나누면 Windows 1.26.65 클라이언트가 멈췄다(EXP-49). `* 1`은 문자열을 숫자로 바꾸지 않는다.
- 진행 막대의 채워진 부분은 v1.3.1 이후 보이지 않는다. 원인은 나누지 않았다(6절).

## 5. 예제 애드온

<AddonDownload id="json-ui-performance" />

1. 파일을 열어 가져온다(모바일은 파일을 눌러 Minecraft로 연다). 새 월드에서 행동 팩 `[bedrock-research]json-ui-performance-bp`로 시작하는 팩을 켠다. 리소스 팩은 의존성으로 함께 켜지고 실험 토글은 필요 없다.
2. 크리에이티브 인벤토리 아이템 분류의 맨 뒤에서 "JSON UI Optimization Test"를 꺼낸다. 검색창에 이름을 넣거나 `/give @s bwiki:json_ui_performance_test`를 써도 된다.
3. 아이템을 사용하면 버튼 수(100, 500, 1000, 2000)를 고르는 메뉴가 열리고, 고르면 그 수의 버튼 목록이 열린다. `/scriptevent bwiki:json_ui_performance`로도 열린다. 버튼을 누르면 몇 번째 버튼인지 채팅에 나온다.

<video controls preload="metadata" width="100%" src={require('@site/static/video/json-ui-performance-addon.mp4').default} />

예제 애드온 실측 영상(모바일, 2026-11-14, v1.2.0). 메뉴에서 버튼 수를 고르고 목록을 연다.

![버튼 2000개 목록의 끝까지 스크롤한 화면](/img/design/json-ui-performance-list-2000.png)

버튼 2000개 목록도 열리고, 끝까지 스크롤하면 마지막 칸까지 아이콘, 이름, 설명, 진행 막대가 그려진다. 누른 칸은 초록으로 바뀐다(v1.2.0, 모바일 1.26.63).

- 다른 서버 폼 예제와 같은 월드에 켜도 된다([JSON UI 최적화](./index.mdx) 9절, 실측). 테스트 아이템과 스크립트 이벤트 이름은 애드온마다 달라 겹치지 않는다.
- 애드온의 버전은 팩 이름, 설명, 파일 이름에 붙는다. 고친 판이 나오면 위 링크가 새 파일로 바뀌므로 이전 판은 지우고 새 판을 가져온다.
- 메뉴와 화면의 글은 영어다. 게임 언어나 글꼴과 상관없이 같은 화면이 나오게 하려는 것이다.

### 판 기록

| 판 | 바꾼 것 | 실측 |
| --- | --- | --- |
| v1.2.0 | 라우터, 창, 2열 grid | 모바일 1.26.63: 버튼 2000개 목록이 열리고 끝까지 그려졌다(2026-11-14) |
| v1.3.0 | 진행 막대 식이 `((... * 1) / 100)` | Windows 1.26.65: 목록을 열면 클라이언트가 멈췄다. 문자열을 숫자로 나누는 식이었다(EXP-49, 2026-11-18) |
| v1.3.1 | `* 1`을 `- 0`으로 | Windows 1.26.65: 버튼 100개 목록이 정상으로 열렸다. 진행 막대의 채워진 부분은 보이지 않았다(2026-11-18) |
| v1.4.0 | 이름, 설명 라벨의 바인딩에서 `always`를 뺌 | 같은 칸 구성의 시험 팩으로 잼: 첫 화면이 채워졌고 fps가 약 284에서 약 290으로 올랐다([always 없이 첫 화면 채우기](./collection-view-order.mdx), Windows 1.26.65, 2026-11-18). v1.4.0 팩 자체는 게임에서 다시 열어 보지 않았다 |

## 6. 남은 일

- 진행 막대의 채워진 부분이 v1.3.1부터 보이지 않는 원인.
- 2열 grid는 버튼 3000개(약 45000px)부터 칸이 맨 위에 겹쳐 그려졌다. 원인이 개수인지 높이인지 가리지 못했다(COL-49).
- 여는 시간은 모바일에서 재지 않았다.
