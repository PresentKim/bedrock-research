# 미검증 JSON UI 주장 실측

[JSON UI](../json-ui/index.mdx) 장에는 커뮤니티 보고나 코드 읽기에서 온 주장이 `미검증`, `추론`, `충돌`, *single report* 표시로 남아 있었다. 이 문서는 그중 Windows에서 잴 수 있는 것을 한 애드온으로 재고 결과를 모은 기록이다. 각 규칙 항목에는 결과를 짧게 옮겼고, 숫자와 조건은 여기에 둔다.

- 대상: Windows 1.26.65.1, 싱글플레이 월드, GUI 480x253(클라이언트 1920x1009, 배율 4). 측정일 2026-11-18.
- 공식 샘플 `preview` 브랜치(1.26.70.24)의 바닐라 파일이 이미 보여 주는 것(예: 컬렉션 `binding_name`의 식, `ignored`의 상태 변수 식)은 재지 않았다.
- 다른 플랫폼, Ore UI와 DDUI 내부, 멀티플레이가 필요한 것, 마켓플레이스 정책, 앞으로의 버전에 대한 소문은 제외했다.

## 1. 측정 방법

- 애드온은 서버 폼 제목 `§b§wjc:N`으로 창을 고른다. `server_form.json`의 `main_screen_content`에 라우터(`collection_panel`)를 `insert_back`으로 넣고, 제목 앞 10바이트를 `property_bag` 키로 찾는다. 다른 서버 폼 예제와 같은 방식이고 같은 월드에서 함께 켜진다.
- 입력 문자열은 스크립트가 버튼 글로 보낸다. 창의 칸은 `collection_index`를 고정한 `stack_panel` 칸이고, 라벨이 `#form_button_text`를 `#v`로 받아 view 식의 결과를 `#text`로 그린다.
- 측정은 MCP 도구로 했다. JSON을 고치고 UI를 다시 읽은 뒤(`ui_reload`) 컨트롤 트리의 사각형, 콘텐츠 로그, 화면 캡처의 글자를 읽었다. 사각형은 클라이언트 픽셀이고 GUI 1단위가 4픽셀이다.
- 결과 글자가 숫자 하나뿐이면 라벨에 아무것도 나오지 않았다(2.4절). 그래서 숫자와 참거짓은 `('R' + 식)`으로 감싸 읽었다.

## 2. 식

### 2.1 연산자

| 식 | 입력 | 결과 | 관련 |
|---|---|---|---|
| `('R' + (#v != '5'))` | `5` | `R`(값 없음) | EXP-02 |
| `('R' + ((#v - 0) >= 10))` | `10` | `R`(값 없음) | EXP-03 |
| `('R' + (not ((#v - 0) < 10)))` | `10` | `Rtrue` | EXP-03 |
| `('R' + ((#v - 0) % 5))` | `17` | `R`(값 없음) | D-07, C-06 |
| `('R' + ((#v - 0) - (((#v - 0) / 5) * 5)))` | `17` | `R2` | EXP-38, C-48 |
| 같은 식, 나누는 수 3 | `-7` | `R-1`(`-7 / 3`은 `R-2`) | EXP-38 |
| `('R' + (5 < (#v - 0) < 7))` | `10` | `Rtrue`(틀린 참) | C-41 |
| `('R' + (((#v - 0) > 5) and ((#v - 0) < 17)))` | `10` | `Rtrue` | EXP-04 |
| `('R' + ((5 < (#v - 0)) and ((#v - 0) < 7)))` | `10` | 라벨 전체가 빔 | 아래 참고 |
| `('R' + (#v < 'c'))`, `>`, `< 'a'` | `b` | `Rtrue`, `Rfalse`, `Rfalse` | D-10 |
| `('R' + ((#v - 0) + 1))` | `2147483647` | `R-2147483648` | D-27 |
| `(translate('gui.ok', #v))` | `b` | 빔 | D-21 |

- 창을 읽을 때마다 콘텐츠 로그에 `JSON UI parse failure: Invalid expression.`이 6줄 찍혔다. 값을 내지 못한 행도 6개(`!=`, `>=`, `%` 두 번, 왼쪽에 리터럴이 있는 `and` 비교, `translate`)였다. 로그에 컨트롤 경로가 없어 줄과 행을 하나씩 맞추지는 못했다.
- 왼쪽이 리터럴인 비교(`(5 < x)`)를 `and`로 묶은 식만 실패했고, 같은 내용을 `(x > 5)`로 쓰면 됐다. 원인은 나누지 않았다.

### 2.2 문자열 빼기와 앞 글자

| 입력과 식 | 결과 |
|---|---|
| `abab` - `'ab'` | 빈 문자열 |
| `xaxbx` - `'x'` | `ab` |
| `' x'` - `'zz'` | ` x`(앞 공백 유지) |
| `':x'` - `'zz'` | `:x` |
| `'-x'`, `'+x'`, `'1x'`, `'#x'`, `'/x'`, `'<x'` - `'zz'` | 빔 |
| `'Info: a'`, `'nancy'`, `'0x12'`, `'inf'` - `'zz'` | 빔 |
| `'' + '1x'`, `'' + 'Info: a'`, `'' + '0x12'` | 빔 |
| `'§r' + '1x'`, `'z' + '1x'`, `'z' + '/x'` | `1x`, `z1x`, `z/x` |

- 문자열 `-`는 모든 출현을 지운다(EXP-12, D-08).
- 결과가 `-`, `+`, 숫자, `#`, `/`, `<`, `inf`, `nan`, `0x`로 시작하면 라벨이 비었다(EXP-48). 공백과 `:`로 시작하는 결과는 그대로 나왔다. 가운데의 `/`는 두 번 쓰지 않아도 보였다. `\`는 재지 않았다.

### 2.3 `'%.Ns'` 자르기

| 입력 | N | 결과 |
|---|---|---|
| `§cAB` | 1, 2, 3, 4 | 깨짐, 깨짐, `§c`(빈 칸), `§cA` |
| `가나다` | 2, 3, 4, 6 | 깨짐, `가`, `가`+깨짐, `가나` |
| `😀xy` | 2, 4, 5 | 깨짐, 이모지 칸, 이모지+`x` |
| `abcdef` | `%7.4s`, `%-7.4s`, `%9s`, `%-9s`, `%09s`, `%4.2s` | 모두 `abcdef` 그대로 |
| `abcdef` | `%.4s` | `abcd` |

- `§`는 2바이트, 한글은 3바이트, 이모지는 4바이트로 잘린다(EXP-24). 글자 중간에서 자르면 그 조각과 함께 바로 뒤에 이어 붙인 글자(`']'`)까지 사라졌다.
- 폭과 패딩이 있는 서식은 자르지도 채우지도 않고 입력을 그대로 돌려줬다. 동작하는 서식은 `'%.Ns'` 하나였다(EXP-25, C-05).
- `(('%.3s' * 'abcdef') + (#v - #v))`는 `abc`였다. 리터럴도 잘린다. 같은 식에서 `#` 속성을 빼면 `Must define a source property name in the binding!` 오류로 바인딩이 성립하지 않았다(C-42, BND-05).
- 런타임에 만든 서식은 동작했다. `(('%.' + #v + 's') * 'abcdef')`(`#v`가 `3`), `('%.' + $n + 's')`(`$n`이 3), `('%.' + '3' + 's')` 모두 `abc`였다(EXP-43, D-04).

### 2.4 숫자

| 식 | 입력 | 결과 |
|---|---|---|
| `((#v - 0) * 2)`, `((#v - 0) * $two)` | `4` | `8`, `8` |
| `(#v * 1)` | `4` | 빈 문자열 |
| `((#v * 1) + 1)`, `((#v * 1) = 4)` | `4` | `1`, `false` |
| `(#v - 0)`, `((#v - 0) = 4)` | `4` | `4`, `true` |
| `(#v + 1)` | `4` | `41`(이어 붙임) |
| `(#v + $zero)`, `((#v + $zero) + 1)`, `$zero`는 JSON `0.0` | `4` | `4`, `5` |
| `((#v - 0) * 0.3)`, `* 1.5` | `10` | `0`, `10` |
| `(((#v - 0) * .3) = 3)` | `10` | `true` |
| `((#v - 0) * .3)`, `(((#v - 0) * .5) * 2)` | `10` | 라벨에 값 없음 |
| `((#v - 0) / 4)` | `10` | `2` |

- 리터럴 곱셈은 동작했다(커뮤니티 2026-09 단일 보고와 다름).
- `* 1`은 숫자로 바꾸지 않고 빈 문자열을 만든다(D-01). `- 0`이 숫자로 바꾼다.
- JSON 변수 `0.0`을 더한 `(#v + $zero)`는 숫자가 되어 `+ 1`이 `5`였다. 문자열에 정수를 더하면 `41`로 이어 붙는다. 그런데 콘텐츠 로그는 같은 행마다 `Expected variable not found in ancestor tree: '$zero'`를 남겼다(D-02).
- 앞자리가 있는 소수 리터럴은 정수가 된다(`0.3`은 0, `1.5`는 1, `100.0`은 100). `.3`은 소수로 계산된다(D-03, EXP-27).
- 실수 결과는 `'R' +`로 이어 붙여도 라벨에 나오지 않았다. 정수와 참거짓은 이어 붙이면 보였고, 숫자 하나만 `#text`에 넣으면 아무것도 나오지 않았다.
- `property_bag`의 문자열 값이 괄호식이면 계산된다. `"#pb": "('A' + 'B')"`를 라벨 `text: "#pb"`로 읽으면 `AB`, `"plain"`은 `plain`, `"(1 + 2)"`는 숫자라서 비었다.

## 3. 배치

부모는 100x40 상자다.

| 항목 | 결과(GUI 단위) | 관련 |
|---|---|---|
| `size: "default"`와 size 생략 | 같다. panel 100x40, label `Hello` 24x10, 세로 stack_panel 100x10(폭은 부모, 높이는 자식 합), 10x10 칸 2x2 grid 20x20 | C-36 |
| size 없는 panel(형제 30x10, 50x20) | 100x40, 부모 크기 | 커뮤니티 단일 보고 |
| `100%c` 부모 안의 `"50%"` 폭 자식(형제 40x10) | 부모 폭 0, `%` 자식 폭 0, 고정 형제는 40x10으로 그려짐 | LAY 순환 |
| `#size_binding_x` = .5(선언 10x10) | 폭 50(부모의 0.5배). `use_anchored_offset`을 줘도 50 | C-14, C-37 |
| `#size_binding_x` = 2 | 폭 200(부모를 넘어도 그대로) | C-14 |
| `#size_binding_x_absolute` = 20 | 폭 20 | D-22 |
| 정적 `#anchored_offset_value_x` = 10, `use_anchored_offset`, top_left | x가 1000 이동(부모 폭의 10배) | C-61 |
| 같은 값, center | 이동 없음 | C-61 |
| 같은 값, `use_anchored_offset` 없음 | 이동 없음 | C-61 |
| `#anchored_offset_value_x` = .1, bottom_left | x가 10 이동 | C-61 |
| `#anchored_offset_value_x_absolute` = 10, top_left | 이동 없음 | D-22 |
| grid [4,1]에서 1번 칸 `#visible` false | 2, 3번 칸이 x 40, 60에 그대로 | D-14, LAY-31 |
| 같은 칸을 가로 stack_panel에 | 2번 칸이 x 20으로 당겨짐 | LAY-04 |
| 정의 최상위 `"ignored": "$hide"`, 참조 지점에서 `"$hide": true` | 세 경우(true, false, 생략) 모두 컨트롤이 만들어졌고 로그에 `Expected variable not found in ancestor tree: '$hide'` | A.3 #22 |

- 정적 컨트롤의 `#anchored_offset_value_x`는 부모 크기에 대한 배수로 움직였고, 모서리 고정에서만 동작했다.
- `panel`에 `collection_name`을 주면 `Unknown property [collection_name]`, 그 자식의 `collection_index`는 `Unknown property [collection_index]`였다(COL-38과 같다).

## 4. 파일과 modifications

| 항목 | 결과 | 관련 |
|---|---|---|
| 바닐라 같은 경로 파일 `thanks_for_testing_screen.json`의 `text_panel`(자식 title, desc, desc2)에 `insert_after`(title), `insert_before`(desc2), `value`가 객체인 `insert_back` | title, after, desc, before, desc2, object 순서로 들어감 | C-39, MOD-14, MOD-01 |
| `move_front`(desc2) + `move_back`(title) | desc2, desc, title | C-39 |
| `swap`(title, `target_control` desc2) | desc2, desc, title | C-39 |
| `replace`(desc, 새 패널) | title, 새 패널, desc2 | C-39 |
| `move_after`(title, `target_control` desc2) | desc, desc2, title | C-39 |
| `move_before`(desc2, `target` title) | desc2, title, desc | MOD-24 |
| `array_name: "variables"`에 `insert_back` `{ "requires": "$multiline_description", "$description_text_line_2": "FROM_VARIABLES" }`(자기 `variables` 배열이 없는 정의) | 두 번째 줄 글자가 FROM_VARIABLES로 바뀜 | MOD-03, C-64 |
| 세 팩(json-ui-performance, collection-expr-probe, 이 애드온)이 같은 `main_screen_content`에 `insert_back` | `jup_router`, `jcx_router`, `juc_router` 모두 있음 | D-05, MOD-02 |
| 정의 중간에 없는 타입(`no_such_type`) | 앞뒤 정의 모두 만들어짐. 로그 `Type 'no_such_type' not ...` | D-06 |
| 정의 중간에 JSON 문법 오류(객체 안 뒤따르는 쉼표) | 오류 앞 정의와 오류가 난 정의는 만들어짐, 뒤 정의는 `UI control reference not found: 'b'` | D-06, FILE-30 |
| 같은 `controls` 배열에 이름 `dup` 두 개 | 둘 다 만들어짐, 로그 없음 | FILE-39 |
| namespace 하나를 두 파일에 나눔(`juc_split.outer`가 다른 파일의 `juc_split.inner` 참조) | 자식 생성됨 | 파일 분할 |

- `variables`에 대한 `modifications`는 이 경우 효과가 있었다. 기존 실측(MOD-03, `variables`는 무시)과 다르다. 대상 정의가 `variables`를 직접 갖지 않은 경우만 쟀다.
- 팩에 **새로** 넣은 바닐라 같은 경로 파일과 `_ui_defs.json`에 새로 등록한 파일은 `ui_reload`(Ctrl+R)로는 읽히지 않았고 월드에 다시 들어가야 했다. 이미 읽힌 파일의 수정은 `ui_reload`로 반영됐다.

1~5절 다음에 따로 잰 항목이다. 같은 날 같은 버전이고, 창은 `§b§wjc:5`(식, 길이, 버튼)와 `§b§wjc:6`(구조물 렌더러)이다.

|---|---|---|

| `(((#v = 'a') = false) or (#v = 'b'))` | `false`(맞음) | EXP-29 |
| `((#v = 'b') or (#v = 'c') or (#v = 'a'))` | `true` | EXP-29 |
| `main_screen_content` 아래 컨트롤의 `text: "#form_text"` | 빔 | 폼 본문 읽기 |
| `long_form` 안 컨트롤에서 `((#form_text - '~x') = #form_text)`, 본문 `first line` 줄바꿈 `second line ~x` | `false`(표식 찾음). 표식 없는 두 줄은 `true`, 표식 있는 한 줄은 `false` | 여러 줄 표식 |

- 괄호로 묶은 `(not ...)`를 `and`/`or`의 항으로 쓰거나 `not`이 괄호 묶음 `and` 전체에 걸리면 항 수와 상관없이 식 전체가 값을 내지 않았다. 세 항 이상에서 첫 항이 틀린다는 보고는 이 형태로 재현되지 않았다. `not` 항은 괄호 없이 쓰거나 `(... = false)`로 바꾼다.
- 식으로 계산한 팩토리·grid 길이는 동작했다. 앞선 기록(COL-36)과 다른 구조라서 그 기록의 원인은 따로 가리지 않았다. 라우터 창 안에서는 길이 바인딩에 `always`가 필요했다(COL-48과 같다).

### 6.2 HUD 타이틀

`hud.root_panel`에 `insert_front`로 넣은 패널에서 쟀다. 처음 측정 때는 팩에 `ui/hud_screen.json`을 넣고 월드에 들어가면 게임이 꺼졌다. 이 꺼짐은 측정 도구의 패킷 기록 모듈(DLL 주입) 문제였고, 도구를 고친 뒤에는 래치만, 타이틀 팩토리 1개, `destroy_at_end` 애니메이션 추가, 팩토리 3개와 래치를 모두 넣은 구성까지 차례로 넣으며 월드에 다시 들어가도 꺼지지 않았다. 그래서 HUD 파일 내용과 꺼짐의 관련은 확인되지 않았다.

- 12개 텍스처 엔티티가 저장된 월드는 그 엔티티 정의를 팩에서 빼야 다시 들어갈 수 있었다. 정의를 뺀 채 들어가도 엔티티는 월드에 남아 있어서, 정의를 다시 넣자 다음 입장에서 또 멈췄다.

### 6.5 소수 리터럴, alpha, 문자열 나누기, HUD, 렌더링 쿼리

- 바인딩한 `#alpha`는 이미지에 `"alpha": "#alpha"`가 있어야 적용됐다. 선언이 없으면 정수 1도 보이지 않았다. 선언이 있으면 0과 1 사이 값도 그대로 그려졌다.
- `('#if_' + 불리언)`의 결과 문자열은 `#`로 시작하므로 속성 이름으로 다시 읽혔다(EXP-30). 그래서 `property_bag`에 키가 있으면 값이 나오고, 다른 글자와 이어 붙이면 빈 속성이 된다.
- `(#v - 1 + 2)`의 9는 `'7abc' - 1`이 문자열 빼기(지울 `1`이 없음)로 `'7abc'`를 남기고, 그 결과가 정수 7로 다시 읽힌 뒤 2를 더한 값으로 보인다. 숫자로 시작하는 제목에서 `- 1`은 뺄셈이 아니다.
- `requires`와 바인딩에서 문자열 / 문자열은 멈추지 않았다. EXP-49의 멈춤은 문자열 / 숫자에서 났다.

## 7. 잴 수 없었던 항목

- **입력창 실시간 필터**(INP-25): 액션 폼 창 안의 `common.text_edit_box`가 마우스를 올린 테두리는 보였지만, 도구의 키 입력(PostMessage, SendInput)으로 글자가 들어가지 않았다. 도구 문제인지 화면이 입력을 넘기지 않는 것인지 나누지 못했다.
- 화면 픽셀 비교가 필요한 `#alpha` 0.5(C-45), 문자열 나누기처럼 멈춤 위험이 있는 식, 커스텀 아이템에 따른 `#item_id_aux` 범위, NPC 대화 버튼 수, 슬라이더로 움직이는 `#anchored_offset_value_x`는 이번 목록에서 뺐다. 파티클 재생 방식은 JSON UI 밖이라 다루지 않았다.
- 6.5절 때 함께 받은 후보 중 다음은 재지 않았다. 어태처블(`c.owning_entity` 없는 `q.property`, `q.mark_variant`, 갑옷 거치대 조건)은 속성을 가진 플레이어나 아이템을 드는 시험 엔티티가 필요하다. 게임패드 포커스(`#toggle_on_hover`)와 터치 기기의 `$touch`는 기기가 없다. `live_horse_renderer`의 `#entity_id`는 런타임 엔티티 번호가 필요하다. 상자 화면 `requires`의 `$container_title`, `flip_book`의 `frame_step` 생략, `q.time_stamp` 위상, 글리프 예열, MP3 내용의 `.fsb`, 사용자 이름공간을 두 파일로 나눈 경로 키 편집도 이번에 넣지 않았다.
