# Script API로 아이템 숫자 ID(aux) 추론하기

JSON UI의 `inventory_item_renderer`는 `#item_id_aux`에 `숫자 아이템 ID * 65536 + 데이터 값`을 받아 아이템을 그린다(ANI-06). 인챈트 반짝임은 32768을 더한다. 텍스처 경로로 그릴 때와 달리 블록이 3D로 나오고 반짝임도 나온다([연구 화면 8.1절](./server-form-research-screen.mdx#81-아이템-아이콘-v140)).

문제는 스크립트가 이 숫자를 알 방법이 없다는 것이다. 이 페이지는 행동 팩 스크립트가 아이템 이름(`minecraft:diamond`, `bwiki:ruby`)에서 숫자 ID를 계산하는 방법을 연구한다. 바닐라 아이템과 블록, 커스텀 아이템, 커스텀 블록을 모두 다룬다.

상태: 1차 실험에서 바닐라와 커스텀 아이템의 배치를 확인했다(5절). 커스텀 블록은 탐침 v1.0.1로 다시 시험한다.

## 1. Script API에는 숫자 ID가 없다

`@minecraft/server` 2.11.0(정식), 2.12.0-beta.1.26.63-stable, 2.13.0-beta.1.26.70-preview.24의 타입 정의를 확인했다.

| API | 주는 것 |
| --- | --- |
| `ItemType` | `id`(문자열), `localizationKey` |
| `ItemTypes` | `get(id)`, `getAll()` |
| `BlockType` | `id`, `localizationKey` |
| `BlockTypes` | `get(id)`, `getAll()` |
| `ItemStack` | 생성자는 `(itemType, amount)`. 데이터 값 멤버가 없다 |
| `BlockPermutation.getItemStack()`, `Block.getItemStack(amount, withData)` | `ItemStack`을 돌려준다. `withData`는 블록 엔티티 데이터다 |

- 숫자 ID, 런타임 ID, 레거시 ID, aux를 돌려주는 멤버는 없다. `getAll()`의 문서에는 결과 순서에 대한 설명이 없다.
- `@minecraft/server-ui`의 `ActionFormData.button(text, iconPath)`는 텍스처 경로만 받는다. 아이템 타입으로 아이콘을 그리는 오버로드는 없다.
- 스크립트가 쓸 수 있는 재료는 `ItemTypes.getAll()`과 `BlockTypes.getAll()`이 주는 커스텀 아이템, 커스텀 블록 목록과 그 순서뿐이다. 바닐라 번호는 버전별 표를 스크립트에 넣어야 한다.

## 2. 알려진 사실과 충돌

### 2.1 그려지는 번호는 아이템 레지스트리의 런타임 ID다

JSON UI가 그리는 번호는 서버가 아이템 레지스트리로 보내는 네트워크 런타임 ID와 같다.

- 2026-02-24 ProxyPass로 받은 1.26.0 월드의 아이템 목록(1905개)에서 다이아몬드 335, 사과 285, 돌풍구 284, 에메랄드 552, 상자 54다. Chest-UI의 26.20 표(2026-05-18)도 같은 값이고, 공통 이름 1824개 중 1813개가 같다.
- Dragonfly 서버는 커스텀 아이템에 바닐라 다음 번호를 그대로 이어 붙인다. 클라이언트가 스스로는 만들지 않는 배치인데, 1.26.52 Windows에서 이 런타임 ID * 65536으로 커스텀 아이템과 커스텀 블록이 그려졌다(Ore UI 로딩 조사).

그래서 숫자 ID를 정하는 것은 월드를 연 쪽(전용 서버, 또는 월드를 연 클라이언트)이 만드는 레지스트리다. 스크립트 추론은 그 레지스트리의 배치 규칙을 재현하는 일이다.

### 2.2 바닐라 배치

- Bedrock Wiki의 26.50 표: 바닐라는 -1246~883이다. 블록은 음수, 아이템은 0 이상이다.
- 26.40부터 데이터 기반 아이템 32개(창, 번들, 바람 막대, 시련 열쇠, 돌풍구, 사과, 발광 열매 등)가 표 끝으로 옮겨졌다. 26.50에서 852~883이다.
- 바닐라 번호는 버전마다 바뀐다. 다이아몬드는 26.30에서 335, 26.40에서 306이다(C-33).
- 1.26.63에서 26.50 표로 사과를 883(882 + 커스텀 아이템 1)으로 보냈더니 돌풍구가 그려졌다. 26.50 이후 이 범위의 배치가 바뀌었다. 852 미만의 아이템 15종은 그대로 맞았다.

### 2.3 커스텀 아이템이 들어가는 자리와 순서

| 항목 | 기록 | 근거 |
| --- | --- | --- |
| 들어가는 자리 | 26.30까지는 257부터. 1.26.0 캡처에서 커스텀 아이템 38개가 257~294이고 그 뒤 바닐라가 모두 +38 밀렸다 | ProxyPass 캡처(1.21.73, 1.26.0), Chest-UI `ID < 256` |
| 들어가는 자리 | 26.40은 850, 26.50은 852부터. 그 앞의 바닐라는 밀리지 않는다 | Bedrock Wiki, Chest-UI `ID < 850` |
| 커스텀 아이템끼리의 순서 | 식별자 문자열 순서(`color_1`, `color_10`, `color_11`, `color_2`) | ProxyPass 캡처 두 개 |
| 커스텀 아이템끼리의 순서 | 리소스 팩 쌓기 순서 | Bedrock Wiki 26.50 |
| 커스텀 아이템끼리의 순서 | 파일 이름 순서, 하위 폴더의 파일이 먼저 | 디스코드 2026-02-14, 2026-02-15 |
| 개수 세기 | `ItemTypes.getAll()`에서 `minecraft:`가 아닌 것을 세면 1개짜리 월드에서는 맞았다. 무료 마켓 애드온을 모두 켠 월드에서는 1518개로 셌는데 실제로 밀린 폭은 1560이었다 | 디스코드 2026-07-09 |
| 포화 | 커스텀 아이템이 1569개를 넘으면 더 밀리지 않는다 | Bedrock Wiki 26.50 |

순서에 대한 세 주장은 서로 다르다. 캡처 두 개는 팩 하나 안의 순서만 보여 주므로, 팩이 여럿일 때는 쌓기 순서가 먼저일 수도 있다.

### 2.4 커스텀 블록

| 기록 | 근거 |
| --- | --- |
| 바닐라 최소 번호 바로 아래부터 음수로 내려간다(1.21.100에서 -1039부터). 바닐라를 밀지 않는다. ID로는 그려지지 않는다 | Bedrock Wiki 1.20.20~1.21.100 판. 26.44 판부터 이 문장이 빠졌다 |
| 블록은 바닐라 번호를 밀지 않는다 | Chest-UI `constants.js` |
| 첫 커스텀 블록이 -9745(= -10000 + 255)이고, 파일 이름 역순으로 하나씩 내려간다. PC에서는 맞고 Android에서는 가끔, iOS에서는 틀린다 | 디스코드 2026-02-14, 2026-03-14 |
| 커스텀 블록은 aux ID로 그려지지 않는다. 번호는 -1091 근처다 | 디스코드 2026-05-12 |
| Dragonfly가 등록한 커스텀 블록이 런타임 ID * 65536으로 3D 그림이 그려졌다 | Ore UI 로딩 조사(1.26.52) |

커스텀 블록이 든 레지스트리 캡처는 아직 없다.

### 2.5 아이템이 칸에 있으면 진짜 번호를 읽을 수 있다

플레이어 핫바나 상자 칸의 `#item_id_aux`는 클라이언트가 직접 채운다. 스크립트가 계산할 필요가 없지만, 그 칸에 실제 아이템이 있어야 하고 서버 폼 화면에서는 인벤토리 컬렉션을 읽을 수 없다. 추론이 맞는지 확인하는 기준으로만 쓴다.

## 3. 추론 방법 초안

스크립트가 이름 `n`의 숫자 ID를 구하는 순서다. 굵은 글씨는 실험으로 정할 값이다.

1. `n`이 바닐라 아이템이고 표 번호가 **P** 미만이면 표 번호를 그대로 쓴다.
2. `n`이 바닐라 아이템이고 표 번호가 P 이상이면 커스텀 아이템 수 `C`를 더한다. `C`는 1569를 넘지 않는다.
3. `n`이 커스텀 아이템이면 커스텀 아이템을 **순서 O**로 늘어놓은 자리 `k`(0부터)로 `P + k`를 쓴다.
4. `n`이 바닐라 블록이면 표 번호를 쓴다.
5. `n`이 커스텀 블록이면 커스텀 블록을 **순서 O'** 로 늘어놓은 자리 `k`로 **B** `- k`를 쓴다.

정할 값:

| 값 | 후보 | 1차 실험 뒤 |
| --- | --- | --- |
| P (커스텀 아이템 시작) | 26.50은 852 | 1.26.63은 853(5.1절) |
| 순서 O | 식별자 순서, 파일 이름 순서(하위 폴더 먼저), 경로 순서, `ItemTypes.getAll()` 순서 | 팩 하나 안에서는 경로 문자열 순서. `getAll()`은 그 정반대(표본 하나) |
| C에 커스텀 블록의 블록 아이템이 들어가는지 | Chest-UI는 뺀다 | 미정(블록이 등록되지 않았다) |
| B (커스텀 블록 시작) | 바닐라 최소 번호 바로 아래, -9745 | 미정 |
| 순서 O' | 식별자 순서, 파일 이름 순서, 그 역순, `BlockTypes.getAll()` 순서 | 미정 |
| 바닐라 표 | 레지스트리 캡처 | 1.26.60 Dragonfly `vanilla_items.nbt`가 1.26.63 실측과 맞는다(5.2절) |

스크립트는 게임 버전을 읽을 수 없으므로 바닐라 표는 애드온이 대상으로 하는 버전 하나에 맞춘다.

## 4. 1차 실험: 아이템 Aux 탐침

탐침 애드온은 커스텀 아이템 4개와 커스텀 블록 3개를 등록하고, 숫자 ID 64개를 번호와 함께 아이템 렌더러로 그린다. 그려진 그림으로 각 번호에 무엇이 있는지 직접 읽는다.

### 4.1 등록하는 것

파일 이름과 식별자의 순서를 일부러 엇갈리게 두었다. 어느 순서 가설이 맞는지가 칸의 색 순서로 드러난다.

| 파일 | 식별자 | 그림 |
| --- | --- | --- |
| `items/z_first.json` | `bwiki:aux_probe_a` | 빨간 양털 |
| `items/a_last.json` | `bwiki:aux_probe_b` | 파란 양털 |
| `items/m_mid.json` | `bwiki:aux_probe_c` | 연두 양털 |
| `items/sub/k_sub.json` | `bwiki:aux_probe_d` | 노란 양털 |
| `items/aux_probe_test.json` | `bwiki:aux_probe_test` | 망원경(실행 아이템) |
| `blocks/z_first.json` | `bwiki:aux_probe_block_a` | 금 블록 |
| `blocks/a_last.json` | `bwiki:aux_probe_block_b` | 다이아몬드 블록 |
| `blocks/m_mid.json` | `bwiki:aux_probe_block_c` | 에메랄드 블록 |

가설마다 커스텀 아이템 5개가 늘어설 순서:

| 순서 가설 | 순서 |
| --- | --- |
| 식별자 | 빨강, 파랑, 연두, 노랑, 망원경 |
| 파일 이름, 하위 폴더 먼저 | 노랑, 파랑, 망원경, 연두, 빨강 |
| 경로 문자열 | 파랑, 망원경, 연두, 노랑, 빨강 |

커스텀 블록은 식별자 순서면 금, 다이아몬드, 에메랄드이고 파일 이름 순서면 다이아몬드, 에메랄드, 금이다.

### 4.2 화면

- 첫 메뉴 본문: `ItemTypes.getAll()`과 `BlockTypes.getAll()`이 돌려준 커스텀 아이템과 블록을 그 순서대로, 그리고 커스텀 블록의 블록 아이템이 `ItemTypes.getAll()`에 몇 개 있는지 보인다.
- 번호 64칸 화면: 버튼 텍스처 자리에 `aux:` + `번호 * 65536`을 보내고 칸 아래에 번호를 적는다. 메뉴에서 고르는 범위:

| 범위 | 보는 것 |
| --- | --- |
| 840~903 | 커스텀 아이템이 들어간 자리와 순서(P, O), 밀린 바닐라(사과, 돌풍구 등). 840~851은 밀리지 않는 바닐라라 기준이 된다 |
| -1278~-1215 | 바닐라 최소 번호 아래(-1278~-1247)에 커스텀 블록이 있는지. -1246~-1215는 바닐라 콘크리트 반 블록이라 기준이 된다 |
| -9776~-9713 | 디스코드의 -9745 주장 |
| 직접 입력 | 시작 번호를 넣어 64칸 |

### 4.3 시험 순서

1. 새 월드에 탐침 애드온만 켠다. 다른 시험 애드온의 커스텀 아이템도 레지스트리에 들어가므로 끈다.
2. 첫 메뉴 본문을 찍는다.
3. 세 범위를 차례로 열어 찍는다. 840~903에서 양털 4색과 망원경이 어디 있는지, -1278~-1247과 -9776~-9713에 금, 다이아몬드, 에메랄드 블록이 있는지 본다.
4. 커스텀 블록이 두 범위 어디에도 없으면 직접 입력으로 다른 범위를 찾는다.

PC에서는 ProxyPass로 같은 월드의 아이템 레지스트리를 받아 번호를 바로 대조할 수 있다. 1.26.63 바닐라 표도 이 캡처로 만든다.

- 커스텀 아이템 5개는 경로 문자열 순서(`a_last.json`, `aux_probe_test.json`, `m_mid.json`, `sub/k_sub.json`, `z_first.json`)로 853부터 놓였다. 식별자 순서도, 하위 폴더를 먼저 두는 파일 이름 순서도 아니다.

### 5.2 1.26.60 바닐라 표

Dragonfly가 1.26.60 지원 커밋(2026-10-28)에서 넣은 `server/world/vanilla_items.nbt`(gophertunnel 1.63.0)를 풀어 26.50 표와 비교했다. 아이템 2080개, 번호 -1251~884다.

- 1.26.60은 `frostbite_spawn_egg`를 791에 넣었다. 그래서 792 이후 번호가 26.50보다 1 크다. 생성 알 851, 엔드 수정 852, 붉은 관목 853, 돌풍구 882, 사과 883, 발광 열매 884다.
- 새 음수 번호 `icicle` -1247, `ice_crystal` -1248, `disc_press` -1251이 있다. 탐침의 -1247, -1248 칸은 비었다. 실험 기능을 켜지 않은 월드라 없는 것으로 보이지만 확인하지 않았다.
- 이 표에 커스텀 아이템 5개(853부터)를 넣으면 실측과 모두 맞는다. 붉은 관목 853 + 5 = 858, 사과 883 + 5 = 888이다. 연구 화면 시험에서 883(커스텀 1개)에 돌풍구가 나온 것도 882 + 1로 맞는다.

그래서 1.26.6x에서 커스텀 아이템까지의 규칙은 다음과 같다.

1. 바닐라 번호는 그 버전 서버 데이터(Dragonfly `vanilla_items.nbt`)의 런타임 ID다.
2. P는 밀리는 묶음의 첫 번호인 853(붉은 관목)이다. P 이상인 바닐라는 커스텀 아이템 수 C를 더한다.
3. 커스텀 아이템은 행동 팩 안 파일 경로의 문자열 순서로 P부터 놓인다. 스크립트에서는 `ItemTypes.getAll()`이 그 정반대 순서로 돌려준 것으로 보인다.

남은 것은 커스텀 블록, 팩이 여럿일 때의 순서, `getAll()` 순서가 늘 정반대인지다.

## 6. 예제 애드온

<AddonDownload id="item-aux-probe" />

1. 파일을 열어 가져온다(모바일은 파일을 눌러 Minecraft로 연다). 새 월드에서 행동 팩 "Bedrock Wiki Item Aux Probe BP"를 켠다. 리소스 팩은 의존성으로 함께 켜지고 실험 토글은 필요 없다.
2. 크리에이티브 인벤토리 아이템 분류의 맨 뒤에서 "Item Aux Probe"(망원경)를 꺼낸다. `/give @s bwiki:aux_probe_test`를 써도 된다.
3. 아이템을 사용하면 메뉴가 열린다. `/scriptevent bwiki:aux_probe`로도 열린다.

- 이 애드온도 `third_party_server_screen`의 `$screen_content`를 바꾸므로 다른 서버 폼 시험 애드온과 함께 켜지 않는다.
- 화면의 글은 영어다.
