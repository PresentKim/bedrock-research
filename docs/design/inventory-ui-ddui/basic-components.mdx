# 인벤토리 UI로 기본 컴포넌트 구현하기

서버 폼(DDUI, CustomForm)을 상자 화면으로 대신할 수 있는지 보려고, [ore-ui-react](https://github.com/PresentKim/ore-ui-react)가 지원하는 Ore UI 컴포넌트를 상자 화면에 옮겨 그린 갤러리 시험 팩(IUC)을 만들었다. 화면은 [엔티티 인벤토리 메뉴](../entity-inventory-ui.mdx)의 방식(보이지 않는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그리는 방식)으로 만들었다. 이 페이지는 그중 기본 컴포넌트 25개를 다룬다. 슬라이더는 [인벤토리 UI로 슬라이더 구현하기](./slider.mdx), 아이템 격자와 입력 같은 강화 컴포넌트는 [인벤토리 UI로 강화 컴포넌트 구현하기](./enhanced-components.mdx)에 있다.

상자 화면에서 서버로 가는 통로는 칸 버튼 누름(빠른 이동, [엔티티 인벤토리 메뉴 2.5절](../entity-inventory-ui.mdx#25-스크립트로-가는-버튼))뿐이다. 서버는 칸 아이템의 이름으로 화면에 값을 준다(같은 문서 2.4절). 모든 컴포넌트는 이 두 통로만으로 만든다.

표기는 다음과 같다.

- 실측: 위키 밖 시험 팩(IUC, `invui-components`)으로 모바일 1.26.63에서 확인했다(2026-11-16). 괄호 안의 버전은 그 시험 팩 버전이다.
- 테스터: [JSON UI 테스터](../../tools/jsonui-tester.mdx)(jsonui-tester) 정적 시뮬레이션.
- 모의: `@minecraft/server`를 흉내 낸 Node 실행.
- *추론*: 결과에서 짐작한 원인이다. 따로 시험하지 않았다.

크기와 색은 ore-ui-react의 CSS를 읽어 옮겼다(1 GUI px = 0.2rem). 원본 CSS도 값 대부분을 추정으로 적어 두었으므로 게임 Ore UI와 다를 수 있다.

## 1. 공통 틀

### 1.1 창

창은 410x214 어두운 판이다. 위 줄에 `InvUI`, 페이지 이름, `<` `>`, Pages 버튼, 버전과 쪽 번호가 있고, 아래 줄은 서버가 마지막으로 처리한 누름을 보이는 상태 줄이다. 페이지는 그 사이 394x168 영역에 그린다.

### 1.2 페이지는 보이기 판

페이지마다 판 하나를 처음에 모두 만들고, 1번 칸 이름(페이지 키)이 그 페이지 키와 같을 때만 판을 보인다.

```json
"gate": {
  "type": "panel", "size": [ 394, 168 ], "collection_index": 1,
  "bindings": [
    { "binding_type": "collection", "binding_collection_name": "container_items", "binding_name": "#hover_text", "binding_condition": "always" },
    { "binding_type": "view", "binding_condition": "always", "source_property_name": "((#hover_text - '§o' - '§f' - '§r') = 'toggle')", "target_property_name": "#visible" }
  ]
}
```

- 처음에는 페이지 키를 키로 한 팩토리 칸이 페이지를 만들게 했다. 페이지 안의 칸 읽기가 하나도 동작하지 않았다. 토글과 체크박스는 페이지를 바꾸는 순간에만 애니메이션과 함께 잠깐 보였다(실측, v1.1.0). 키 팩토리가 만든 컨트롤 안에서는 컬렉션 바인딩과 view 바인딩이 동작하지 않는 것으로 보인다(*추론*). 그래서 페이지를 보이기 판으로 바꿨고, 페이지 전환이 동작했다(실측, v1.2.1).
- 숨은 페이지가 칸을 계속 계산하지 않도록, 생성기는 페이지 안에서 `#visible`을 정하지 않는 바인딩의 `binding_condition`을 `always`에서 `visible`로 바꾼다. 페이지 판과 페이지 고르기 판의 보이기 바인딩은 `always`로 남긴다.
- 이 변환은 바인딩 객체를 복사해서 바꿔야 한다. 생성기가 공유 바인딩 객체를 직접 고치자 페이지 판의 칸 읽기까지 `visible` 조건이 되었다. 처음 연 페이지만 보였고, 다른 페이지로 옮긴 뒤에는 돌아와도 아무 페이지도 보이지 않았다. 숨은 판은 칸을 다시 읽지 않아 다시 보이지 않았다(실측, v1.2.0). 복사해서 바꾸자 해결됐다(실측, v1.2.1).

### 1.3 칸 배정

엔티티 칸은 243개다(HOST-16).

| 칸 | 내용 |
| --- | --- |
| 1 | 페이지 키 |
| 2, 3 | 페이지 이름, 상태 줄 |
| 4 | 페이지 고르기 상태(`open`, `closed`) |
| 5 | 바닥 글(버전, 쪽 번호) |
| 6, 7, 8 | Pages, `<`, `>` 버튼 |
| 10~189 | 지금 페이지가 쓰는 칸. 페이지 번호 n은 10 + n번 칸이다 |
| 190~214 | 페이지 고르기 버튼 25개 |

페이지를 바꾸면 스크립트가 10~189번을 모두 비우고 새 페이지의 버튼 칸만 버튼 아이템으로 채운다.

### 1.4 페이지 모듈

페이지 하나는 스크립트 모듈 `bp/scripts/pages/<key>.js`와 생성기 모듈 `tools/pages/<key>.mjs` 한 쌍이다.

| 스크립트 모듈 `page` | 내용 |
| --- | --- |
| `key`, `title` | 페이지 키(1번 칸), 화면에 보일 이름 |
| `slots` | 페이지 번호 이름표. 생성기와 스크립트가 같은 번호를 쓴다 |
| `buttons` | 버튼으로 쓰는 페이지 번호 목록 |
| `init()` | 처음 상태. 플레이어마다 페이지별로 기억해 다른 페이지에 다녀와도 남는다 |
| `render(state)` | `{ 번호: 글자 }`. 스크립트가 바뀐 칸만 종이 이름으로 쓴다 |
| `press(state, n)` | n번 버튼 처리. 돌려준 글자를 상태 줄에 쓴다 |
| `tick(state)` | 선택. 매 틱 부른다(토스트 수명, 자동 진행 막대) |

- 스크립트 모듈은 게임 API를 쓰지 않는다. 그래서 생성기가 그대로 불러 쓸 수 있다.
- 생성기 모듈은 `ui = { page, build(ctx) }`를 내보낸다. `ctx.slot(n)`은 페이지 번호를 칸 번호로 바꾸고 범위를 검사한다. `ctx.def(name, body)`는 `<key>_<name>` 정의를 만들고 참조 글자를 돌려준다.
- `gen-ui.mjs`는 UI 안에서 `button.container_auto_place`로 매핑한 버튼의 칸 번호를 모아 `buttons`와 같은지 확인하고, 다르면 생성을 멈춘다.
- `check-page.mjs`는 페이지마다 처음 상태에서 버튼을 하나씩 누르고 틱을 돌리며, `render`가 버튼 칸에 쓰지 않는지, 모든 값이 글자인지, 숫자만 있는 글자가 없는지(2절) 본다.

### 1.5 페이지 고르기

Pages를 누르면 서버가 4번 칸을 `open`으로 쓰고, 페이지 이름 버튼 25개(5열 5줄, 칸마다 74x14)가 레이어 40의 덮개 판으로 뜬다. 버튼을 누르면 그 페이지로 가고 덮개를 닫는다. 시험 팩은 같은 덮개에 고르기 버튼 45개를 두고 테스터에서 진단이 없었다(v1.4.0). 25개 배치는 이 예제 애드온에서 처음 쓴 것이고 테스터로도 보지 않았다.

## 2. 그리기 규칙

| 규칙 | 근거 |
| --- | --- |
| 라벨은 글자만 그린다. 숫자만 있는 칸 이름과, 식을 지나며 숫자로 시작하게 된 값은 숫자가 되어 그려지지 않는다 | [엔티티 인벤토리 메뉴 2.4절](../entity-inventory-ui.mdx#24-칸의-이름-lore-내구도로-그리기)(실측), EXP-30. NumberInput의 숫자만 있는 값이 보이지 않았다(실측, v1.2.1) |
| 숫자로 시작하는 값은 서식 코드를 앞에 붙이거나(`§0`, `§r`), `§o`만 빼고 `§f`를 남기는 라벨(`keepFormat`)로 읽는다 | Badge 숫자는 `§r`과 `keepFormat`으로 그려졌다(실측, v1.4.2) |
| 칸 버튼에 덧붙인 글자와 아이콘은 버튼 바탕보다 늘 위에 있는 레이어 20 판에 넣는다 | Accordion 제목이 버튼 바탕에 가려 보이지 않았다(실측, v1.3.0) |
| 글자는 그 아래 바탕보다 레이어 합이 높게 둔다 | 아래 |
| 슬라이더의 기본 막대와 호버 막대를 같은 컨트롤로 두지 않는다 | 아래 |

레이어 합. PlayerList의 이름과 Badge의 숫자가 보이지 않았다(실측, v1.4.1). 두 글자 모두 레이어 합(조상 레이어를 모두 더한 값)이 같은 바탕 위에 있었다. 이런 곳의 글자 레이어를 모두 올리자 보이지 않던 글자가 모두 보였다(실측, v1.4.2). 합이 같으면 바탕이 글자를 덮을 수 있다고 본다(*추론*). NumberInput 값 글자도 입력칸 바탕과 합이 4로 같았다(*추론*, v1.4.0에서 올림). 시험 팩은 v1.4.2부터 페이지마다 처음 상태와 버튼 네 번 누른 상태에서 레이어 합이 같거나 높은 그림이 글자 가운데를 덮는지 검사한다(테스터). 같은 이유로 Segment와 Tabs의 선택된 글자, Chips의 켜진 글자, Toast 글자도 올렸다. 이것들은 가려진 것을 본 적은 없다.

슬라이더 막대. 슬라이더 컨트롤 하나의 `default_control`과 `hover_control`을 같은 막대로 두자, 손가락이 슬라이더 위에 있는 동안 어두운 바탕이 사라졌다(실측, v1.1.0). 호버 막대를 따로 두어 해결했다. 자세한 것은 [인벤토리 UI 슬라이더](./slider.mdx)에 있다.

### 2.1 애니메이션 다시 재생

토글의 손잡이, 체크 표시, 탭 패널, 캐러셀 트랙, 토스트처럼 서버 값이 바뀔 때 다시 재생할 그림은 칸 이름을 키로 한 작은 팩토리 칸(`keyedCell`)에 둔다. 키가 바뀌면 컨트롤이 새로 만들어져 애니메이션이 처음부터 재생된다([엔티티 인벤토리 메뉴 8.2절](../entity-inventory-ui.mdx#82-애니메이션-다시-재생), ANI-37, COL-22). 이 칸 안에는 대부분 바인딩 없는 그림만 둔다. 1.2절의 *추론*대로라면 키 팩토리 안의 바인딩은 동작하지 않을 수 있다. TextBlock의 변형 칸만 안에 칸 라벨을 두며, 게임에서 어떻게 보이는지는 기록이 없다.

## 3. 컴포넌트

아래 "실측"이 없는 컴포넌트는 테스터에서 진단이 없었고 모의 실행에서 모든 버튼을 누르고 40틱을 돌려도 오류가 없었다는 것만 확인했다(v1.1.0, v1.4.0).

### 3.1 Toggle

- 보이는 것: 32x15 바탕(왼쪽 초록 반에 흰 막대, 오른쪽 회색 반에 고리)과 위로 2 솟은 17x17 손잡이. 옆에 누를 수 없는 비활성 예시.
- 구성: 스위치 전체가 칸 버튼이다. 그림은 서버가 쓴 `on`/`off`를 키로 한 팩토리 칸이라 값이 바뀔 때마다 손잡이가 0.18초 동안 미끄러진다.
- 실측: 같은 방식의 토글이 입력 시험 팩에서 누를 때마다 서버 응답에 맞게 바뀌었다(probe v1.3.0). IUC에서는 페이지가 키 팩토리이던 v1.1.0에서 페이지를 바꾸는 순간에만 보였다. 보이기 판으로 바꾼 뒤의 토글 페이지만 따로 적은 기록은 없다.

### 3.2 Checkbox

- 보이는 것: 13x13 칸(꺼짐은 어두운 칸과 회색 테두리, 켜짐은 초록 칸과 흰 체크)과 `Checked`/`Unchecked` 라벨, 비활성 예시.
- 구성: 칸과 라벨을 덮는 칸 버튼 하나. 체크 그림은 상태 키 팩토리이고 체크 표시가 0.15초 동안 나타난다.
- 실측: 같은 방식의 체크박스가 입력 시험 팩에서 동작했다(probe v1.3.0). IUC 기록은 Toggle과 같다.

### 3.3 Button

- 보이는 것: Secondary, Primary, Danger 세 버튼과 서버가 켜고 끄는 비활성 상태, 마지막으로 누른 버튼과 횟수.
- 구성: 버튼마다 칸 버튼이고 기본, 호버, 눌림 그림을 버튼 상태 컨트롤로 둔다. 비활성은 서버 값으로 칸 버튼을 숨기고 같은 자리에 반투명(0.5) 그림을 보인다. 원본은 누르는 순간 동작하지만 칸 버튼은 바닐라 버튼처럼 손을 뗄 때 보낸다.

### 3.4 RoundedButton

- 보이는 것: Small, Medium, Large 세 크기.
- 구성: Button과 같은 칸 버튼이다. 둥근 모서리(반지름 6, 8, 10)는 줄마다 폭이 다른 사각형 계단으로 그린다.

### 3.5 RadioGroup

- 보이는 것: Easy, Normal, Hard 중 하나 선택과 누를 수 없는 Hardcore.
- 구성: 줄마다 칸 버튼, 서버가 고른 값을 쓴다. 45도 돌린 마름모는 가로 줄 길이가 1씩 늘고 주는 계단으로 그린다(회전을 쓰지 않음).

### 3.6 Segment

- 보이는 것: 이웃과 테두리를 공유하는 Day, Night, Rain 중 하나 선택과 비활성 버튼 둘.
- 구성: 버튼마다 칸 버튼, 서버가 고른 값을 쓰면 그 자리에 초록 면을 보인다. 선택된 글자의 레이어를 올렸다(2절).

### 3.7 Stepper

- 보이는 것: 반복 없는 Difficulty(Peaceful~Hard), 반복하는 Season(Spring~Winter), 비활성 예시.
- 구성: 좌우 화살표가 칸 버튼이다. 서버가 지금 라벨과 끝 여부(`on`/`off`)를 쓰고, 끝에 닿은 화살표는 칸 버튼을 숨기고 흐린 그림을 보인다.

### 3.8 Pagination

- 보이는 것: 12쪽, 번호 칸 5개짜리 창, 이전과 다음, `Page n of 12`.
- 구성: 화살표 둘과 번호 칸 다섯이 칸 버튼이다. 번호 칸마다 서버가 `p7`(다른 쪽) 또는 `c7`(지금 쪽)을 쓰고, 그 키로 번호 그림 하나를 만든다. 지금 쪽은 초록 칸이다.

### 3.9 Tabs

- 보이는 것: General, Video, Audio 탭과 잠긴 탭, 탭마다 글 세 줄.
- 구성: 탭마다 칸 버튼. 서버가 고른 탭 id를 쓰면 그 id를 키로 한 팩토리 칸이 패널을 새로 만든다(원본의 `Mount`와 같다). 선택된 탭 글자의 레이어를 올렸다(2절).

### 3.10 Accordion

- 보이는 것: 세 항목과 비활성 항목, 하나만 열기와 여러 개 열기 전환.
- 구성: 머리 줄마다 칸 버튼. 열린 항목의 본문 높이만큼 아래 항목이 내려가야 하므로, 서버가 항목마다 `p1o`(위에 열린 항목 1개, 이 항목 열림)처럼 위치와 열림을 함께 쓰고, UI는 위치마다 미리 만든 판 중 하나를 보인다. 꺾쇠는 위아래 두 가지 계단 그림이다.
- 실측: 머리 줄 제목이 칸 버튼 바탕에 가려 보이지 않았다(v1.3.0). 글자를 레이어 20 판으로 옮겼다(2절). 옮긴 뒤의 결과는 테스터로만 봤다.

### 3.11 Dropdown

- 보이는 것: 다섯 선택지(하나는 비활성)와 지금 값.
- 구성: 트리거와 선택지마다 칸 버튼. 서버가 열림 상태를 쓰면 목록이 위 레이어 판으로 뜬다. 페이지 영역 전체를 맨 아래 레이어의 투명 칸 버튼 하나가 덮고 있어, 트리거와 목록 밖을 누르면 닫힌다. 비활성 선택지에는 칸 버튼이 없다. 원본의 화면 끝 뒤집기 계산은 없고 위치를 미리 정한다.

### 3.12 Modal

- 보이는 것: 반투명 배경, 밝은 창, Cancel과 Delete, 결과 글.
- 구성: 서버 상태로 높은 레이어 판을 보인다. 창 둘레의 배경은 같은 칸을 쓰는 칸 버튼 넷이고, 누르면 닫는다. 창 안에는 Cancel과 Delete 칸 버튼만 있다. Esc는 상자 화면 자체를 닫으므로 모달만 닫는 키는 없다.

### 3.13 Toast

- 보이는 것: 3초와 8초 알림, 최대 3개, 누르면 닫힘.
- 구성: 알림 자리 3개를 미리 두고 서버가 글을 쓴다. 서버가 매 틱 수명을 줄여 지운다. 새 알림 자리는 `a`~`f` 중 하나를 키로 쓰고 나머지는 `still`로 써서, 새로 생긴 알림만 0.15초 동안 나타난다. 상자 화면 밖(HUD)에는 그릴 수 없다. 글자 레이어를 올렸다(2절, 테스터).

### 3.14 Tooltip

- 보이는 것: 누르면 열리는 말풍선 네 방향(right, left, top, bottom)과 PC용 호버 말풍선.
- 구성: 휴대폰에는 호버가 없으므로 대상이 칸 버튼이고 서버가 열고 닫는다. 말풍선이 열려 있을 때만 페이지를 덮는 칸 버튼이 보여, 바깥을 누르면 닫힌다. 호버 말풍선은 버튼의 호버 상태 그림 안에 넣어 서버 없이 보인다. 휴대폰에서는 보이지 않는다(*추론*).

### 3.15 Carousel

- 보이는 것: 7장, 한 번에 3장, 넘길 때 미끄러짐, 점 표시, 반복 전환.
- 구성: 화살표, 점, Loop가 칸 버튼이다. 서버가 `p2f`(2쪽, 앞으로)처럼 쪽과 방향을 쓰면 그 키의 트랙이 새로 만들어지고 0.25초 동안 옆에서 밀려 들어온다. 원본에는 이 미끄러짐이 없다.

### 3.16 ProgressBar

- 보이는 것: 버튼(-10, -1, +1, +10, 0%, 100%)으로 바꾸는 막대와 매 틱 1씩 차오르는 막대, 값 글자.
- 구성: 채움은 101단계(`w0`~`w100`) 키 칸이다. 칸 하나의 정의에 변수로 칸 번호만 넘겨 두 막대가 같은 정의를 쓴다. 값 글자는 숫자로 시작하므로 `keepFormat` 라벨로 읽는다(2절).

### 3.17 ProgressCircle

- 보이는 것: 20조각 고리 두 크기와 가운데 값 글자, Play로 자동 진행.
- 구성: 회전과 둥근 모양을 그릴 수 없으므로 고리를 5%마다 한 조각씩 원둘레에 미리 놓고, 서버가 조각마다 `on`/`off`를 쓴다. 값 글자는 `§0`을 붙여 쓴다(2절).

### 3.18 TextBlock

- 보이는 것: title, body, caption 견본과 한 줄 안의 서식(InlineTextBlock), 서버가 쓴 글을 세 변형으로 바꿔 보기.
- 구성: 크기는 `font_scale_factor`, 굵게는 `§l`로 근사한다. 자간은 바꿀 수 없다. 한 라벨 안에서 서식 코드로 색과 굵기를 바꾼다. 변형은 키 칸이고 그 안에 칸 라벨이 있다(2.1절).

### 3.19 Scroll

- 보이는 것: 누를 수 있는 줄 14개의 목록과 긴 글, 둘 다 바닐라 스크롤 보기.
- 구성: `scroll_view`는 서버 없이 화면 안에서 끌린다. 서버는 스크롤 위치를 모르고, 목록 안 줄의 칸 버튼 누름만 받는다. 막대 길과 손잡이는 White 사각형이다. 바닐라처럼 스크롤 보기에 `#gesture_control_enabled` 바인딩을 둔다.
- 실측: 목록의 버튼 위를 끌면 스크롤되지 않고 버튼이 눌렸고, 스크롤 막대를 끌 때만 스크롤됐다(v1.2.1). 그 뒤 `#gesture_control_enabled` 바인딩을 더했지만(v1.3.0) 결과는 기록이 없다. 고른 줄 이름 레이어를 올렸다(v1.4.3, 테스터).

### 3.20 Badge

- 보이는 것: Mail, Friends, Alerts 아이콘 버튼의 빨간 알림 배지(0이면 숨김, 100부터 `99+`), 더하기, 빼기, 모두 지우기.
- 구성: 아이콘은 점 그림을 사각형으로 합쳐 그린다. 서버가 배지 크기 키(`none`, `one`, `two`, `many`)와 숫자 글을 따로 쓰고, 크기 키로 알맞은 폭의 둥근 배지를 보인다. 숫자는 `§r`을 붙이고 `keepFormat` 라벨로 읽는다.
- 실측: 숫자가 보이지 않았다(v1.4.1). 숫자 레이어를 올리자 보였다(v1.4.2).

### 3.21 Rating

- 보이는 것: 별 다섯 개로 매기기(같은 별을 다시 누르면 지움)와 반 별이 있는 읽기 전용 평균.
- 구성: 별은 점 그림이다. 서버가 별마다 `on`/`off`(내 점수) 또는 `full`/`half`/`none`(평균)을 쓴다. 반 별은 왼쪽 반만 금색인 그림이다.

### 3.22 Spinner

- 보이는 것: 점 고리, 점 셋, 오가는 막대, Start/Stop.
- 구성: 셋 다 서버 없이 클라이언트 애니메이션(`alpha`, `offset`을 `next`로 이은 고리)만으로 돈다. 서버는 `on`/`off`로 도는 판과 멈춘 판 중 하나를 보일 뿐이다.

### 3.23 Steps

- 보이는 것: 4단계 진행(완료, 지금, 남음), 단계 사이 선, 단계 설명, Back, Next(마지막에는 Finish).
- 구성: 서버가 단계마다 `done`/`current`/`pending`과 선마다 `on`/`off`, 버튼 활성 여부를 쓴다. 첫 단계의 Back은 누를 수 없는 그림이다.

### 3.24 Chips

- 보이는 것: x로 지울 수 있는 켜진 태그, 눌러서 다시 넣는 추천 태그, Reset.
- 구성: 태그 8개 모두 켜진 줄과 추천 줄 양쪽에 칸 버튼이 있다. 서버가 태그마다 `a0`(켜진 줄 0번 자리) 또는 `s2`(추천 줄 2번 자리)를 쓰면, UI는 태그를 그 자리에 보인다. 켜진 글자의 레이어를 올렸다(2절).

### 3.25 Breadcrumb

- 보이는 것: 5단계까지의 경로와 지금 단계의 아래 항목 최대 4개.
- 구성: 경로 칸 5개와 아래 항목 칸 4개가 칸 버튼이다. 서버가 경로 칸마다 `link`/`current`/`none`, 항목마다 `dir`/`leaf`/`none`과 이름을 쓴다. 앞 단계를 누르면 돌아가고 항목을 누르면 들어간다. 이름은 `§7`, `§f`, `§r`을 붙여 쓰고 `keepFormat`으로 읽는다.

1. 파일을 열어 가져온다(모바일은 파일을 눌러 Minecraft로 연다). 새 월드에서 행동 팩 `[bedrock-research]inventory-ui-basic-components-bp`로 시작하는 팩을 켠다. 리소스 팩은 의존성으로 함께 켜진다.

3. 아이템을 든 채 화면 가운데를 누르면 갤러리가 열린다(시선 앞 엔티티, [엔티티 인벤토리 메뉴 3절](../entity-inventory-ui.mdx#3-화면을-여는-방법)의 C2).
4. `<` `>`와 Pages로 페이지를 바꾸며 컴포넌트를 눌러 본다. 아래 상태 줄에 서버가 받은 누름이 나온다.

- 엔티티 이름은 `§b§w§b§c`이다([엔티티 인벤토리 메뉴 2.2.1절](../entity-inventory-ui.mdx#221-이름-규약)). 바닐라 숨기기는 다른 엔티티 인벤토리 예제와 같은 표식 `entity_ui_hide_vanilla`와 속성 `#entity_ui_vanilla_visible`을 쓰므로 같은 월드에 함께 켜도 된다(같은 문서 2.2.2절).
- `tools/gen-ui.mjs`가 `rp/ui/iubc.json`을 만든다. `node tools/check-page.mjs <key>`로 페이지 하나를 검사한다.
- 화면의 글은 영어다.
- 위 실측은 IUC 시험 팩으로 했다. 예제 애드온은 그 시험 팩(v1.4.9)에서 이 25페이지만 남기고 이름, 식별자, 엔티티 이름, 네임스페이스를 바꾼 것이다. 예제 애드온 자체는 아직 게임에서 돌려 보지 않았다(*미검증*).
