# 엔티티 인벤토리로 메뉴 화면 만들기

서버 폼 버튼은 아이템 아이콘을 텍스처 경로나 숫자 ID로만 그린다. 숫자 ID는 스크립트가 확정할 수 없는 경우가 많다([아이템 숫자 ID 기획 3절](./item-aux-id.mdx#3-스크립트가-할-수-있는-것)). 엔티티 인벤토리 화면은 엔티티 칸에 든 실제 아이템을 엔진이 그리므로 바닐라, 커스텀, 다른 팩 아이템이 모두 맞게 나온다.

이 페이지는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그려 연구 화면 같은 메뉴로 쓰는 구성을 다룬다.

상태: 1.26.63 모바일에서 시험했다(2026-11-14). 시험한 것은 화면 라우팅, 아이콘 격자, 클라이언트 선택, 칸의 이름과 내구도로 그리는 요소, 스크립트로 가는 버튼, 여는 방법이다. 여러 플레이어와 다른 기기는 남았다(5절).

## 1. 서버 폼과 비교

| 항목 | 서버 폼 | 엔티티 인벤토리 화면 |
| --- | --- | --- |
| 여는 방법 | 스크립트가 바로 연다 | 스크립트가 강제로 열 수 없다. 플레이어 동작이 한 번 필요하다(3절) |
| 아이콘 | 텍스처 경로, 또는 숫자 ID | 엔진이 엔티티 칸을 그린다. 모든 아이템, 3D, 반짝임 |
| 아이콘 수 | 버튼 수만큼 | 엔티티 인벤토리 칸 수만큼(27칸 화면에서도 칸은 더 읽힌다, HOST-16) |
| 내용 바꾸기 | 폼을 닫고 다시 연다 | 스크립트가 칸을 바꾸면 열린 화면에 바로 반영된다 |
| 글, 조건, 텍스처, 막대 | 폼 글자로 넘긴다 | 칸 아이템의 이름, lore, 내구도로 넘긴다(2.4절) |
| 스크립트로 가는 입력 | 버튼 번호 | 칸 조작뿐이다. 버튼은 칸 빠른 이동으로 우회한다(2.5절) |
| 화면 안 동작 | 라디오 토글로 클라이언트 처리 | 같다 |

## 2. 구성

### 2.1 엔티티

```json
"minecraft:inventory": {
  "container_type": "container",
  "inventory_size": 27,
  "private": false,
  "can_be_siphoned_from": false
}
```

- `container_type: "container"`이고 `private: false`여야 `chest_screen.json`으로 열린다(HOST-16).
- 메뉴용 엔티티는 `minecraft:physics`(중력, 충돌 끔), `minecraft:pushable`(밀리지 않음), `minecraft:damage_sensor`(피해 없음)를 둔다.
- 리소스 팩 엔티티는 뼈가 없는 빈 지오메트리로 두어 보이지 않게 한다.

### 2.2 화면 라우팅

`chest_screen.json`에서 `small_chest_screen`을 다시 선언해 `$screen_content`를 바꾼다(HOST-18). 0번 칸에 표식 아이템(`max_durability` 4242인 숨긴 커스텀 아이템)을 넣고, 그 값이 맞을 때만 우리 창을 그린다. 다른 상자와 엔티티는 바닐라 화면 그대로다.

```json
"small_chest_screen@common.inventory_screen_common": {
  "variables": [
    { "requires": "$desktop_screen", "$screen_content": "menu_box.root_desktop" },
    { "requires": "$pocket_screen", "$use_custom_pocket_toast": true, "$screen_content": "menu_box.root_pocket" }
  ]
}
```

```json
"gate": {
  "type": "panel", "size": [ "100%", "100%" ],
  "bindings": [
    { "binding_type": "collection_details", "binding_collection_name": "container_items" },
    { "binding_type": "collection", "binding_collection_name": "container_items", "binding_name": "#item_durability_total_amount", "binding_name_override": "#identity" },
    { "binding_type": "view", "source_property_name": "$gate_rule", "target_property_name": "#visible" }
  ]
},
"root_pocket": {
  "type": "panel", "size": [ "100%", "100%" ],
  "controls": [
    { "vanilla@menu_box.host": { "$gate_rule": "(not (#identity = 4242))", "$content": "pocket_containers.small_chest_panel" } },
    { "menu@menu_box.host": { "$gate_rule": "(#identity = 4242)", "$content": "menu_box.window" } }
  ]
}
```

`host`는 `collection_name: "container_items"`인 패널 안에 `collection_index: 0`인 `gate`를 두고, 그 안에 `$content`를 넣는다. 데스크톱은 `chest.small_chest_panel`을 바닐라 쪽에 둔다. 우리 창에서는 플레이어 인벤토리(보관함) 영역이 그려지지 않는다.

표식 값은 `#item_durability_total_amount`(최대 내구도)로 읽는다. 닳지 않은 표식이면 `#item_durability_current_amount`도 같은 값이다. `#item_durability_max`는 칸 바인딩에 없다. 실험에서 `(#item_durability_max = 4242)`와 그 부정을 조건으로 둔 표시가 둘 다 보였다. 식이 계산되지 않았다는 뜻이다(HOST-17).

### 2.3 아이콘 격자와 선택

- 칸마다 `inventory_item_renderer`가 `container_items`의 `#item_id_aux`를 `collection_index`로 읽는다.
- 칸은 연구 화면과 같은 라디오 토글(`radio_toggle_group`, `toggle_group_forced_index`)이다. 선택하면 테두리와 큰 상세 아이콘이 보인다. 선택은 클라이언트에서만 처리되고 서버로 가지 않는다.
- 아이템을 칸에 묶어 두는 것은 토글이다. 토글이 칸 누름을 가로채므로 아이템은 움직이지 않았다.
- `lockMode`는 엔티티 칸의 아이템을 지키지 못한다. 실험에서 none, inventory, slot 잠금 아이템을 바닐라 상자 화면에 두었더니 셋 다 바로 꺼내졌다. 잠금은 플레이어 인벤토리에서만 작동했다. inventory 잠금은 인벤토리 안에서 옮겨지고, slot 잠금은 움직이지 않았다.
- 잠금 아이템의 툴팁에는 "이동할 수 없다"는 줄이 붙는다. 이 줄은 2.4절의 `#hover_text`에도 들어간다.

### 2.4 칸의 이름, lore, 내구도로 그리기

`container_items`의 `#hover_text`는 칸마다 따로 읽힌다. 한 화면에서 여러 칸의 값이 서로 다르게 나왔다. 스크립트가 칸의 아이템을 바꾸면 열린 화면의 값도 바로 바뀌었다(1초마다 lore 갱신, 버튼을 누를 때마다 이름 갱신, HOST-17).

`#hover_text`에는 툴팁에 보이는 줄이 모두 들어 있다.

- 이름. 이름을 바꾼 아이템은 흰 기울임꼴이고, 등급이 있는 아이템은 그 색이다(불사의 토템은 노랑).
- 바닐라 설명 줄(상자의 "보관", 검의 "+8 공격 피해").
- lore(보라 기울임꼴).
- 잠금 안내 줄.

그래서 값을 넘기는 데이터 아이템은 바닐라 설명 줄이 없는 아이템(종이)에 이름만 붙이고, 잠그지 않는다. 그러면 `(#hover_text - '§o' - '§f' - '§r')`이 이름만 남긴다. 잠금 아이템은 잠금 줄이 붙어 텍스처 경로와 숫자 변환이 실패했다.

| 그리는 것 | 식 | 결과 |
| --- | --- | --- |
| 라벨 | `#hover_text` → `#text` | 이름, lore, 설명 줄이 툴팁 서식 그대로 나온다 |
| 선택한 칸의 이름과 lore | 칸 토글의 선택 상태 컨트롤 안에 같은 라벨 | 선택한 칸의 값이 나온다 |
| 보이기 조건 | `(not ((#hover_text - 'STATE_ON') = #hover_text))` → `#visible` | 이름에 따라 1초마다 바뀌었다 |
| 텍스처 | `('textures/blocks/wool_colored_' + (#hover_text - '§o' - '§f' - '§r'))` → `#texture` | 이름에 따라 양털 색이 바뀌었다 |
| 막대(이름) | `(1 - ((#hover_text - '§o' - '§f' - '§r') * .1))` → `#clip_ratio` | 이름의 0~10에 따라 찼다 |
| 막대(내구도) | `(1 - (#item_durability_current_amount * .004))` → `#clip_ratio` | 철 검의 남은 내구도를 따라 줄었다 |

![Entity Menu Lab 화면. 활을 선택해 오른쪽에 큰 아이콘과 이름, lore, 잠금 줄이 보인다. 양털 텍스처는 이름 blue를 따랐고, 이름 막대는 7에 맞게 70% 찼다. 고정값을 넣은 막대 여섯 개는 비어 있다](/img/design/entity-menu-lab.png)

막대에는 두 가지 조건이 있다.

- 실수 리터럴은 점으로 시작한다. `0.1`은 0으로 계산되어(EXP-27) 막대가 비었다. `.1`로 바꾸자 찼다.
- `#clip_ratio`는 칸 값을 읽는 바인딩으로 넣는다. 실험에서 `clip_direction`을 준 채움은 다음 방식으로 비율을 넣으면 모두 비었다.
  - `property_bag`의 0과 0.5
  - 칸 값을 쓰지 않는 식 `(1 - 1)`, `(5 * .1)`
  - 크기, `clip_pixelperfect`, 방향을 바꾼 경우
  - 칸을 읽는 줄 밖에 둔 경우

  `clip_direction`이 없는 채움은 보였다.

![v1.5.0 화면. 자르기 없는 채움만 초록으로 보이고, 자르기를 준 막대는 property_bag 0.5와 고정값 식 모두 비어 있다](/img/design/entity-menu-lab-clip.png)

숫자를 글자로 바꾸는 방법은 찾지 못했다. `('v' + #item_durability_total_amount)`는 `v`만 그렸고, 숫자 바인딩을 `#text`에 바로 넣으면 아무것도 나오지 않았다. 화면에 보일 숫자는 이름이나 lore에 글자로 넣는다.

크기에 `[160, "$line_h"]`처럼 배열 안에 변수를 넣으면 높이가 0이 되어 줄이 겹쳤다. 크기는 `"size": "$line_size"`처럼 배열 통째의 변수로 넘긴다.

### 2.5 스크립트로 가는 버튼

JSON UI에서 스크립트로 바로 가는 통로는 서버 폼 버튼뿐이다. 컨테이너 화면에서 서버까지 가는 것은 칸 조작이므로, 보이는 버튼을 숨긴 칸의 빠른 이동으로 바꾼다.

```json
"start_button": {
  "type": "button", "size": [ 144, 20 ], "layer": 2,
  "default_control": "default", "hover_control": "hover", "pressed_control": "pressed",
  "bindings": [ { "binding_type": "collection_details", "binding_collection_name": "container_items" } ],
  "button_mappings": [
    { "from_button_id": "button.menu_select", "to_button_id": "button.container_auto_place", "mapping_type": "pressed", "consume_event": false },
    { "from_button_id": "button.menu_ok", "to_button_id": "button.container_auto_place", "mapping_type": "focused", "consume_event": false }
  ]
}
```

1. 버튼은 `collection_name: "container_items"`인 스택 패널 안에 `collection_index: 26`으로 둔다.
2. 스크립트는 26번 칸에 표식 이름이 붙은 버튼 아이템을 넣어 둔다.
3. 누르면 빠른 이동으로 그 아이템이 플레이어 인벤토리로 간다.
4. 스크립트는 2틱마다 26번 칸을 보고, 표식 아이템이 없으면 누름으로 세고 칸을 다시 채운다.
5. `world.afterEvents.playerInventoryItemChange`에서 플레이어 인벤토리에 들어온 표식 아이템을 지운다.

누름의 결과를 데이터 아이템 이름에 쓰면 열린 화면이 바로 반응한다. 실험에서 버튼을 누를 때마다 12번 칸 이름 `Pressed N`이 바뀌어 라벨에 나왔다.

칸을 직접 누르는 방식은 터치 화면에서 2회 뒤로 감지되지 않았다. 아이템이 커서에 들려 칸의 아이템과 서로 바뀌기만 하는 것으로 보인다(HOST-20의 "터치에서는 커서가 채워지지 않는다"와 관련). 빠른 이동은 커서를 거치지 않는다.

## 3. 화면을 여는 방법

Script API에는 컨테이너 화면을 여는 함수가 없다. 디스코드에서도 "강제로 열 수 없다"는 답이 반복됐다(2025-10-23, 2026-03-09, 2026-09-10). 그래서 플레이어 동작이 한 번은 필요하다.

| 방법 | 동작 | 1.26.63 모바일 결과 |
| --- | --- | --- |
| C: 보이는 엔티티를 누름 | 플레이어 앞에 엔티티를 소환하고 플레이어가 그것을 누른다 | 열린다. 엔티티가 보여야 찾을 수 있어 메뉴로는 어색하다 |
| C2: 시선 앞 엔티티 | 메뉴 아이템을 든 동안 보이지 않는 1.2x1.2 엔티티를 매 틱 눈 위치에서 시선 방향 1.2칸, 아래로 0.6칸에 옮긴다. 화면 가운데를 누르면 그 엔티티를 누르게 된다 | 한 번 눌러 바로 열린다. 다른 아이템으로 바꿔 들면 엔티티를 지운다. 사용성이 가장 좋았다 |
| C3: 탑승 + 인벤토리 버튼 | 스크립트가 `Rideable.addRider`로 플레이어를 보이지 않는 엔티티에 태운다. 플레이어가 인벤토리 버튼을 누르면 플레이어 인벤토리 대신 그 엔티티의 화면이 열린다 | 열린다. 웅크리면 내린다. 내리면 엔티티를 지운다 |

메뉴 엔티티는 C2로 연다.

메뉴 엔티티를 플레이어에게 태우는 방법은 쓰지 않는다. 엔티티에 `parrot_tame` 집단을 주면 바닐라 player.json의 어깨 좌석에 탈 수 있다. 하지만 실험에서 화면을 눌러도 탑승한 엔티티가 한 번도 눌리지 않았다.

C2 시선 앞 위치:

```js
function spotInFront(player, distance, drop) {
  const view = player.getViewDirection();
  const eye = player.getHeadLocation();
  return { x: eye.x + view.x * distance, y: eye.y + view.y * distance - drop, z: eye.z + view.z * distance };
}
```

C3 엔티티는 `minecraft:rideable`에 `family_types: ["player"]`, 좌석 `position: [0, 0, 0]`을 둔다. 탑승 중에는 `action.hint.exit.<엔티티 식별자>` 안내가 번역되지 않은 채 보였다. 리소스 팩 언어 파일에 이 키를 넣어야 한다.

디스코드에 나온 다른 우회법은 시험하지 않았다.

- 가구 블록 안에 엔티티를 두고 판정 상자를 블록보다 조금 크게 해, 블록을 누르면 엔티티가 눌리게 한다(2025-10-22, 2026-03-09).
- 컨테이너를 가진 커스텀 블록과 상호작용하면 인벤토리 화면이 열린다는 26.50 프리뷰 언급(2026-08-21). 정식 버전에 들어갔는지는 확인하지 않았다.
- 좌석이 엔티티 중심에서 멀면 화면이 열렸다 바로 닫힌다는 보고(2026-05-05). C3는 좌석을 중심에 두었다.

## 4. 실측 요약 (1.26.63 모바일, 2026-11-14)

| 확인한 것 | 결과 |
| --- | --- |
| 0번 칸 표식으로 우리 창만 바꾸기 | 된다. 바닐라 상자 화면은 그대로다 |
| 표식 바인딩 | `#item_durability_total_amount`, `#item_durability_current_amount`는 4242. `#item_durability_max`는 없다 |
| 아이콘 격자 | 바닐라, 3D 블록, 커스텀 아이템 모두 그려졌다 |
| 토글 선택과 상세 아이콘, 이름, lore | 된다. 아이템은 움직이지 않는다 |
| 잠금 아이템 | 엔티티 칸에서는 잠금과 상관없이 꺼내졌다 |
| 칸별 `#hover_text` | 칸마다 다르고, 열린 화면에서 바로 갱신된다 |
| 이름으로 조건, 텍스처, 막대 | 된다. 데이터 아이템은 잠그지 않은 종이 |
| 내구도로 막대 | 된다 |
| 고정값 `#clip_ratio` | 막대가 비었다 |
| 숫자를 글자로 | 그려지지 않았다 |
| 칸 직접 누르기 버튼 | 터치에서 2회 뒤로 감지되지 않았다 |
| 빠른 이동 버튼 | 10번 넘게 눌러도 매번 횟수가 올랐다. 닫은 뒤 플레이어 인벤토리에 버튼 아이템이 남지 않았다(C, C2, C3 모두) |
| C, C2, C3 열기 | 모두 열린다. C2가 가장 쓰기 쉬웠다 |
| C2 | 걷거나 고개를 돌려도 한 번 눌러 열렸다. 열린 동안 엔티티를 매 틱 옮겨도 화면이 닫히거나 깜빡이지 않았다. 메뉴 아이템을 든 채 하는 다른 동작도 불편하지 않았다 |
| C3 | 인벤토리 버튼으로 플레이어 인벤토리 대신 메뉴가 열렸다. 웅크리면 내렸다 |
| 플레이어에게 탑승한 엔티티 | 눌리지 않았다 |

## 7. 예제: 연구 화면

[서버 폼 연구 화면](./server-form-research-screen.mdx)과 같은 창(위쪽 탭 두 개, 왼쪽 8x6 칸과 페이지 화살표, 오른쪽 상세와 진행 버튼)을 엔티티 인벤토리 화면으로 그린 예제다. 연구 120개 중 3의 배수 번째가 처음부터 완료 상태이고, 재료가 있으면 실제로 연구가 진행된다.

![연구 화면 예제. 위쪽 To do 110, Done 10 탭, 왼쪽 8x6 칸과 페이지 화살표, 오른쪽 Pick a research. 안내, 아래쪽 Researched Item 117. 메시지](/img/design/entity-research-screen.png)

### 7.1 칸 배치

엔티티 칸은 243개다(HOST-16).

| 칸 | 내용 |
| --- | --- |
| 0 | 표식(내구도 4244) |
| 1~48 | 연구 필요 탭의 현재 페이지 48칸 |
| 49~96 | 연구 완료 탭의 현재 페이지 48칸 |
| 97, 98 | 탭 머리(아이콘, `To do N`, `Done N`) |
| 99~102 | 탭마다 이전, 다음 페이지 버튼 |
| 103~124 | 연구 필요 탭 상세: 아이콘과 이름, 상태, 설명, 재료 8, 보상 8, 진행 버튼, 완료 표시, 메시지 |
| 125~146 | 연구 완료 탭 상세(같은 구성) |
| 147~242 | 칸마다 하나씩 둔 선택 버튼 칸 |

### 7.2 서버 폼 판과 다른 점

| 항목 | 서버 폼 연구 화면 | 엔티티 연구 화면 |
| --- | --- | --- |
| 아이콘 | 숫자 ID | 엔진이 칸 아이템을 그린다 |
| 칸 선택 | 칸 토글. 상세 20칸을 칸마다 미리 보낸다 | 칸을 누르면 그 칸의 선택 버튼 칸이 빠른 이동되고, 스크립트가 상세 22칸을 그 연구로 채운다 |
| 탭 전환 | 라디오 토글 | 같다 |
| 페이지, 진행 | 폼 버튼. 폼이 닫혔다 다시 열린다 | 빠른 이동 버튼. 화면은 열린 채 칸만 바뀐다 |
| 재료, 보상 개수 | 버튼 글자 | 칸 아이템의 수량을 `#inventory_stack_count`로 그린다 |

칸 선택은 서버를 거치지만 상세가 바뀌는 데 걸리는 시간은 거의 느껴지지 않았다. 선택 표시(노란 테두리)는 칸 아이템 lore의 `SELECTED`를 포함 검사해 그린다.

### 7.3 정할 것

- **선택 버튼은 아이콘 칸과 다른 칸에 둔다.** 아이콘 칸 아이템을 빠른 이동시키면, 그 칸이 비는 동안 빈 칸 숨김 조건에 걸려 가로 줄이 줄었다가 다시 늘어났다. 칸마다 숨긴 선택 칸을 따로 두고, 칸 자리는 비어 있어도 크기를 유지한다.
- **진행 버튼의 상태는 버튼 칸 아이템으로 넘긴다.** 스크립트가 0.5초마다 재료를 세어 버튼 아이템 lore에 `READY`를 넣거나 뺀다. 버튼은 `READY`가 있으면 초록 `Start research`, 없으면 회색 `Not enough materials`를 그린다.
- **처음 열 때 첫 탭 내용을 보이게 한다.** 첫 탭의 내용은 둘째 탭 토글이 꺼져 있을 때 보이게 하고(`(not #toggle_state)`), 첫 탭 토글에 `toggle_default_state: true`를 준다.
