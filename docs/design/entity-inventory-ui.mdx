# 엔티티 인벤토리로 메뉴 화면 만들기

서버 폼 버튼은 아이템 아이콘을 텍스처 경로나 숫자 ID로만 그린다. 숫자 ID는 스크립트가 확정할 수 없는 경우가 많다([아이템 숫자 ID 기획 3절](./item-aux-id.mdx#3-스크립트가-할-수-있는-것)). 엔티티 인벤토리 화면은 엔티티 칸에 든 실제 아이템을 엔진이 그리므로 바닐라, 커스텀, 다른 팩 아이템이 모두 맞게 나온다.

이 페이지는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그려 연구 화면 같은 메뉴로 쓰는 구성을 다룬다.

상태: 1.26.63 모바일에서 시험했다(2026-11-14). 시험한 것은 화면 라우팅, 아이콘 격자, 클라이언트 선택, 칸의 이름과 내구도로 그리는 요소, 스크립트로 가는 버튼, 여는 방법이다. 2026-11-15에는 2048 시험으로 `modifications` 라우팅, 엔티티 이름 선택, 애니메이션 다시 재생, 깜빡임을 시험했다(2.2절, 8절). 여러 플레이어와 다른 기기는 남았다(5절).

## 1. 서버 폼과 비교

| 항목 | 서버 폼 | 엔티티 인벤토리 화면 |
| --- | --- | --- |
| 여는 방법 | 스크립트가 바로 연다 | 스크립트가 강제로 열 수 없다. 플레이어 동작이 한 번 필요하다(3절) |
| 아이콘 | 텍스처 경로, 또는 숫자 ID | 엔진이 엔티티 칸을 그린다. 모든 아이템, 3D, 반짝임 |
| 아이콘 수 | 버튼 수만큼 | 엔티티 인벤토리 칸 수만큼(27칸 화면에서도 칸은 더 읽힌다, HOST-16) |
| 내용 바꾸기 | 폼을 닫고 다시 연다 | 스크립트가 칸을 바꾸면 열린 화면에 바로 반영된다 |
| 글, 조건, 텍스처, 막대 | 폼 글자로 넘긴다 | 칸 아이템의 이름, lore, 내구도로 넘긴다(2.4절) |
| 스크립트로 가는 입력 | 버튼 번호 | 칸 조작뿐이다. 버튼은 칸 빠른 이동으로 우회한다(2.5절) |
| 화면 안 동작 | 라디오 토글로 클라이언트 처리 | 같다 |

## 2. 구성

### 2.1 엔티티

```json
"minecraft:inventory": {
  "container_type": "container",
  "inventory_size": 27,
  "private": false,
  "can_be_siphoned_from": false
}
```

- `container_type: "container"`이고 `private: false`여야 `chest_screen.json`으로 열린다(HOST-16).
- 메뉴용 엔티티는 `minecraft:physics`(중력, 충돌 끔), `minecraft:pushable`(밀리지 않음), `minecraft:damage_sensor`(피해 없음)를 둔다.
- 리소스 팩 엔티티는 뼈가 없는 빈 지오메트리로 두어 보이지 않게 한다.

### 2.2 화면 라우팅

예제 애드온은 바닐라 상자 패널(`chest.small_chest_panel`, `pocket_containers.panel`)에 `modifications`로 자기 창을 넣고, 엔티티 이름(`$container_title`)으로 자기 창을 고른다. 화면 정의 `small_chest_screen`은 다시 선언하지 않는다.

같은 화면을 재선언하는 애드온 둘을 켜면 팩 순서로 한쪽만 쓰였다. 다른 시험 애드온의 `chest_screen.json`이 위에 있어 재선언한 쪽 대신 바닐라 화면이 나왔다(실측, HOST-49). 그래서 예제는 `small_chest_screen`을 재선언해 `$screen_content`를 바꾸는 방식(HOST-18)도, 0번 칸 표식 아이템으로 고르는 방식도 쓰지 않는다. 예제의 0번 칸은 비어 있다. 칸 아이템의 내구도로 화면을 식별하는 규칙은 HOST-17에 있다.

`modifications`만 쓰는 창은 화면을 재선언한 다른 애드온이 위에 있어도 그 애드온이 바닐라 쪽에 둔 상자 패널 안에서 그려진다. 이것은 [JSON UI 테스터](../tools/jsonui-tester.mdx)(jsonui-tester) 정적 시뮬레이션으로만 확인했다(*미검증*).

#### 2.2.1 이름 규약

스크립트는 메뉴 엔티티의 `nameTag`를 서식 코드만으로 된 공통 접두사 `§b§w`와 예제마다 다른 접미사로 짓는다. 엔티티 상자 화면의 `$container_title`은 이 nameTag다(HOST-19).

| 예제 | 엔티티 이름 |
| --- | --- |
| 2048(8절) | `§b§w§2§0` |
| Entity Menu Lab(6절) | `§b§w§m§l`. 메뉴 모드만 이름을 붙이고, 잠금 실험 엔티티는 이름이 없어 바닐라 상자 화면이 열린다 |
| 연구 화면(7절) | `§b§w§r§s` |
| 매치메이킹(9절) | `§b§w§m§m` |
| 인형 로비(10절) | `§b§w§m§f` |

메뉴 엔티티의 이름표는 1인칭에서 보이지 않았다(실측). 3인칭이나 다른 플레이어에게 보이는지는 시험하지 않았다(*미검증*, 8.4절).

#### 2.2.2 바닐라 숨기기(예제 공통)

바닐라 정의의 속성은 하나도 덮어쓰지 않는다. 숨길 바닐라 컨트롤의 `bindings`에 `modifications`로 view 바인딩 하나를 넣고, 그 바인딩이 예제 창 안의 표식 컨트롤을 읽는다.

`pocket_containers.json`(2048 예제 파일. `panel`에 넣는 `overlay` 이름만 예제마다 다르다):

```json
"panel": {
  "modifications": [
    {
      "array_name": "controls",
      "operation": "insert_back",
      "value": [ { "e2048_overlay@e2048.overlay": {} } ]
    }
  ]
},

"header_area": {
  "modifications": [
    {
      "array_name": "bindings",
      "operation": "insert_back",
      "value": [ { "binding_type": "view", "source_control_name": "entity_ui_hide_vanilla", "source_property_name": "#entity_ui_vanilla_visible", "target_property_name": "#visible", "binding_condition": "always" } ]
    }
  ]
}
```

`background_panel`, `half_screen`에도 같은 바인딩을 넣는다. `chest_screen.json`은 경로 키 `small_chest_panel/root_panel`에 같은 바인딩을 넣는다. 이 정의들에는 원래 `bindings`가 없다(MOD-04, MOD-08).

표식 컨트롤은 2.2.3절 `overlay`의 `host` 안에 있다.

```json
"entity_ui_hide_vanilla": { "type": "panel", "size": [ 0, 0 ], "property_bag": { "#entity_ui_vanilla_visible": false } }
```

- 바인딩은 `source_control_name`으로 화면에서 표식을 찾아 `#visible`을 false로 만든다. 표식은 `host` 안에 있어 이름이 맞을 때만 만들어진다. 숨긴 컨트롤도 이름 찾기에 걸리므로(BND-25) 표식은 `visible`이 아니라 `ignored`로 빠져 있어야 한다.
- 표식이 없는 화면(보통 상자, 통)에서는 바인딩이 바닐라를 숨기지 않았다(실측, 호환 시험 팩).
- 휴대폰에서 회색 배경판까지 사라져 창이 클래식 UI처럼 월드 위에 떠 보였고, 칸 아이템이 0.5초마다 바뀌어도 깜빡이지 않았다(실측, 호환 시험 팩).
- 같은 바닐라 컨트롤에 여러 팩이 바인딩을 넣어도 모두 같은 이름의 표식을 읽어 같은 값을 쓴다. `modifications`는 여러 팩의 것이 쌓인다(MOD-02). 그래서 표식 이름 `entity_ui_hide_vanilla`와 속성 `#entity_ui_vanilla_visible`을 따르는 위키 밖 애드온과도 함께 켤 수 있다. 서로 모르는 두 시험 팩과, 같은 방식으로 바꾼 2048·매치메이킹 시험 팩을 한 월드에 켠 시험에서 각자 자기 창만 열렸다(실측).
- 바닐라 컨트롤을 `ignored`로 빼면 아예 만들지 않아 가볍지만, `ignored`는 `$` 변수만 받는 속성이라(FILE-16) 바닐라 정의에 직접 써야 하고, 같은 속성을 쓰는 다른 팩과 덮어쓰기 경쟁을 한다(MOD-13). `modifications`로는 속성을 바꾸지 못한다(MOD-03). 그래서 바닐라를 만든 뒤 숨긴다. 매치메이킹 시험 화면의 컨트롤 수가 369개에서 2,375개로 늘었지만(*미검증*, 정적 시뮬레이션) 게임에서 느려짐은 느끼지 못했다(실측).
- 데스크톱은 jsonui-tester가 경로 키의 `modifications`를 적용하지 않아 확인하지 못했다(*미검증*).

#### 2.2.3 자기 창 넣기

각 예제는 같은 두 패널에 자기 `overlay` 하나만 `modifications`로 넣는다(`chest_screen.json`의 `small_chest_panel`, `pocket_containers.json`의 `panel`). 여러 예제의 `overlay`는 같은 패널에 쌓인다.

```json
"small_chest_panel": {
  "modifications": [
    {
      "array_name": "controls",
      "operation": "insert_back",
      "value": [ { "e2048_overlay@e2048.overlay": {} } ]
    }
  ]
}
```

`overlay`는 이름 전체가 맞을 때만 만들어진다. 2048 예제(`rp/ui/e2048.json`)의 정의다.

```json
"overlay": {
  "type": "panel",
  "size": [ "100%", "100%" ],
  "layer": 1,
  "$bwiki_title": "$container_title",
  "controls": [
    {
      "host": {
        "type": "panel",
        "size": [ "100%", "100%" ],
        "ignored": "(not ($bwiki_title = '§b§w§2§0'))",
        "controls": [
          { "entity_ui_hide_vanilla": { "type": "panel", "size": [ 0, 0 ], "property_bag": { "#entity_ui_vanilla_visible": false } } },
          {
            "cover": {
              "type": "input_panel",
              "modal": true,
              "size": [ "100%", "100%" ],
              "layer": 1,
              "controls": [
                {
                  "sync_grid": {
                    "type": "grid",
                    "size": [ 162, 54 ],
                    "layer": 1,
                    "grid_rescaling_type": "horizontal",
                    "maximum_grid_items": 27,
                    "collection_name": "container_items",
                    "grid_item_template": "e2048.empty_cell"
                  }
                },
                { "window@e2048.factory_window": { "layer": 2 } }
              ]
            }
          }
        ]
      }
    }
  ]
}
```

- `ignored`는 그 컨트롤 자신의 `$` 선언을 보지 않고 부모 스코프에서 평가된다(FILE-34). 그래서 복사 변수는 부모 `overlay`에 두고 자식 `host`가 비교한다. 게임에서는 부모에 둔 구성만 시험했다(실측).
- `ignored`가 참이면 컨트롤이 만들어지지 않으므로 이름이 다른 상자에는 그 예제의 컨트롤이 하나도 없다. jsonui-tester에서 휴대폰 보통 상자의 컨트롤 수가 `visible`로만 가렸을 때 3,569개에서 2,207개로 줄었다(*미검증*, 정적 시뮬레이션).
- `sync_grid`는 칸이 바뀔 때의 깜빡임을 막는 빈 격자다(8.3절).
- `overlay`와 `cover`의 `layer`는 1이다. `overlay`를 50, `cover`를 100에 두었을 때는 창의 `inventory_item_renderer` 아이콘만 그려지지 않고 이름, 개수, 배경은 그려졌다(실측). 둘 다 1로 낮추자 아이콘이 그려졌다(실측, ANI-38). 아이템 렌더러를 layer 100에 두면 아이템이 숨고 4와 50은 괜찮았다는 커뮤니티 보고와 맞는다.
- 경계는 컨트롤 자신의 `layer`가 아니라 조상 레이어를 모두 더한 값에 달려 있다. 상자 화면에 바깥 창 1, 덮개 1, 창 2를 두고 그 안에 아이템 렌더러와 `live_player_renderer`를 레이어 0~999로 나란히 두었더니, 예제 안에서 더한 합이 94까지는 둘 다 그려지고 99부터는 둘 다 그려지지 않았다. 같은 칸들을 레이어 148을 더한 패널로 감싸면(합 152 이상) 모두 그려지지 않았다(실측, 모바일, 2026-11-16). 바닐라 상자 패널 쪽 조상 레이어는 합에 넣지 않았으므로 정확한 경계 값은 94와 99 사이로만 말할 수 있다. 같은 화면의 `live_horse_renderer`는 합과 상관없이 그려졌다(실측).
- jsonui-tester에 네 예제와 위키 밖 시험 팩 세 개의 리소스 팩을 순서를 바꿔 함께 넣은 확인에서, 이름마다 자기 창만 보이고 바닐라는 숨었으며, 이름 없는 보통 상자는 바닐라만 보였다. 네 예제를 한 월드에 켠 게임 시험에서도 엔티티마다 바닐라 없이 자기 창이 열렸고, 이름 없는 Entity Menu Lab 잠금 실험 엔티티는 바닐라 상자 화면이 열렸다(실측).

### 2.3 아이콘 격자와 선택

- 칸마다 `inventory_item_renderer`가 `container_items`의 `#item_id_aux`를 `collection_index`로 읽는다.
- 칸은 연구 화면과 같은 라디오 토글(`radio_toggle_group`, `toggle_group_forced_index`)이다. 선택하면 테두리와 큰 상세 아이콘이 보인다. 선택은 클라이언트에서만 처리되고 서버로 가지 않는다.
- 아이템을 칸에 묶어 두는 것은 토글이다. 토글이 칸 누름을 가로채므로 아이템은 움직이지 않았다.
- `lockMode`는 엔티티 칸의 아이템을 지키지 못한다. 실험에서 none, inventory, slot 잠금 아이템을 바닐라 상자 화면에 두었더니 셋 다 바로 꺼내졌다. 잠금은 플레이어 인벤토리에서만 작동했다. inventory 잠금은 인벤토리 안에서 옮겨지고, slot 잠금은 움직이지 않았다.
- 잠금 아이템의 툴팁에는 "이동할 수 없다"는 줄이 붙는다. 이 줄은 2.4절의 `#hover_text`에도 들어간다.

### 2.4 칸의 이름, lore, 내구도로 그리기

`container_items`의 `#hover_text`는 칸마다 따로 읽힌다. 한 화면에서 여러 칸의 값이 서로 다르게 나왔다. 스크립트가 칸의 아이템을 바꾸면 열린 화면의 값도 바로 바뀌었다(1초마다 lore 갱신, 버튼을 누를 때마다 이름 갱신, HOST-17).

`#hover_text`에는 툴팁에 보이는 줄이 모두 들어 있다.

- 이름. 이름을 바꾼 아이템은 흰 기울임꼴이고, 등급이 있는 아이템은 그 색이다(불사의 토템은 노랑).
- 바닐라 설명 줄(상자의 "보관", 검의 "+8 공격 피해").
- lore(보라 기울임꼴).
- 잠금 안내 줄.

그래서 값을 넘기는 데이터 아이템은 바닐라 설명 줄이 없는 아이템(종이)에 이름만 붙이고, 잠그지 않는다. 그러면 `(#hover_text - '§o' - '§f' - '§r')`이 이름만 남긴다. 잠금 아이템은 잠금 줄이 붙어 텍스처 경로와 숫자 변환이 실패했다.

| 그리는 것 | 식 | 결과 |
| --- | --- | --- |
| 라벨 | `#hover_text` → `#text` | 이름, lore, 설명 줄이 툴팁 서식 그대로 나온다 |
| 선택한 칸의 이름과 lore | 칸 토글의 선택 상태 컨트롤 안에 같은 라벨 | 선택한 칸의 값이 나온다 |
| 보이기 조건 | `(not ((#hover_text - 'STATE_ON') = #hover_text))` → `#visible` | 이름에 따라 1초마다 바뀌었다 |
| 텍스처 | `('textures/blocks/wool_colored_' + (#hover_text - '§o' - '§f' - '§r'))` → `#texture` | 이름에 따라 양털 색이 바뀌었다 |
| 막대(이름) | `(1 - ((#hover_text - '§o' - '§f' - '§r') * .1))` → `#clip_ratio` | 이름의 0~10에 따라 찼다 |
| 막대(내구도) | `(1 - (#item_durability_current_amount * .004))` → `#clip_ratio` | 철 검의 남은 내구도를 따라 줄었다 |

![Entity Menu Lab 화면. 활을 선택해 오른쪽에 큰 아이콘과 이름, lore, 잠금 줄이 보인다. 양털 텍스처는 이름 blue를 따랐고, 이름 막대는 7에 맞게 70% 찼다. 고정값을 넣은 막대 여섯 개는 비어 있다](/img/design/entity-menu-lab.png)

막대에는 두 가지 조건이 있다.

- 실수 리터럴은 점으로 시작한다. `0.1`은 0으로 계산되어(EXP-27) 막대가 비었다. `.1`로 바꾸자 찼다.
- `#clip_ratio`는 칸 값을 읽는 바인딩으로 넣는다. 실험에서 `clip_direction`을 준 채움은 다음 방식으로 비율을 넣으면 모두 비었다.
  - `property_bag`의 0과 0.5
  - 칸 값을 쓰지 않는 식 `(1 - 1)`, `(5 * .1)`
  - 크기, `clip_pixelperfect`, 방향을 바꾼 경우
  - 칸을 읽는 줄 밖에 둔 경우

  `clip_direction`이 없는 채움은 보였다.

![v1.5.0 화면. 자르기 없는 채움만 초록으로 보이고, 자르기를 준 막대는 property_bag 0.5와 고정값 식 모두 비어 있다](/img/design/entity-menu-lab-clip.png)

숫자를 글자로 바꾸는 방법은 찾지 못했다. `('v' + #item_durability_total_amount)`는 `v`만 그렸고, 숫자 바인딩을 `#text`에 바로 넣으면 아무것도 나오지 않았다. 화면에 보일 숫자는 이름이나 lore에 글자로 넣는다.

크기에 `[160, "$line_h"]`처럼 배열 안에 변수를 넣으면 높이가 0이 되어 줄이 겹쳤다. 크기는 `"size": "$line_size"`처럼 배열 통째의 변수로 넘긴다.

### 2.5 스크립트로 가는 버튼

JSON UI에서 스크립트로 바로 가는 통로는 서버 폼 버튼뿐이다. 컨테이너 화면에서 서버까지 가는 것은 칸 조작이므로, 보이는 버튼을 숨긴 칸의 빠른 이동으로 바꾼다.

```json
"start_button": {
  "type": "button", "size": [ 144, 20 ], "layer": 2,
  "default_control": "default", "hover_control": "hover", "pressed_control": "pressed",
  "bindings": [ { "binding_type": "collection_details", "binding_collection_name": "container_items" } ],
  "button_mappings": [
    { "from_button_id": "button.menu_select", "to_button_id": "button.container_auto_place", "mapping_type": "pressed", "consume_event": false },
    { "from_button_id": "button.menu_ok", "to_button_id": "button.container_auto_place", "mapping_type": "focused", "consume_event": false }
  ]
}
```

1. 버튼은 `collection_name: "container_items"`인 스택 패널 안에 `collection_index: 26`으로 둔다.
2. 스크립트는 26번 칸에 표식 이름이 붙은 버튼 아이템을 넣어 둔다.
3. 누르면 빠른 이동으로 그 아이템이 플레이어 인벤토리로 간다.
4. 스크립트는 2틱마다 26번 칸을 보고, 표식 아이템이 없으면 누름으로 세고 칸을 다시 채운다.
5. `world.afterEvents.playerInventoryItemChange`에서 플레이어 인벤토리에 들어온 표식 아이템을 지운다.

누름의 결과를 데이터 아이템 이름에 쓰면 열린 화면이 바로 반응한다. 실험에서 버튼을 누를 때마다 12번 칸 이름 `Pressed N`이 바뀌어 라벨에 나왔다.

칸을 직접 누르는 방식은 터치 화면에서 2회 뒤로 감지되지 않았다. 아이템이 커서에 들려 칸의 아이템과 서로 바뀌기만 하는 것으로 보인다(HOST-20의 "터치에서는 커서가 채워지지 않는다"와 관련). 빠른 이동은 커서를 거치지 않는다.

## 3. 화면을 여는 방법

Script API에는 컨테이너 화면을 여는 함수가 없다. 디스코드에서도 "강제로 열 수 없다"는 답이 반복됐다(2025-10-23, 2026-03-09, 2026-09-10). 그래서 플레이어 동작이 한 번은 필요하다.

| 방법 | 동작 | 1.26.63 모바일 결과 |
| --- | --- | --- |
| C: 보이는 엔티티를 누름 | 플레이어 앞에 엔티티를 소환하고 플레이어가 그것을 누른다 | 열린다. 엔티티가 보여야 찾을 수 있어 메뉴로는 어색하다 |
| C2: 시선 앞 엔티티 | 메뉴 아이템을 든 동안 보이지 않는 1.2x1.2 엔티티를 매 틱 눈 위치에서 시선 방향 1.2칸, 아래로 0.6칸에 옮긴다. 화면 가운데를 누르면 그 엔티티를 누르게 된다 | 한 번 눌러 바로 열린다. 다른 아이템으로 바꿔 들면 엔티티를 지운다. 사용성이 가장 좋았다 |
| C3: 탑승 + 인벤토리 버튼 | 스크립트가 `Rideable.addRider`로 플레이어를 보이지 않는 엔티티에 태운다. 플레이어가 인벤토리 버튼을 누르면 플레이어 인벤토리 대신 그 엔티티의 화면이 열린다 | 열린다. 웅크리면 내린다. 내리면 엔티티를 지운다 |

메뉴 엔티티는 C2로 연다.

메뉴 엔티티를 플레이어에게 태우는 방법은 쓰지 않는다. 엔티티에 `parrot_tame` 집단을 주면 바닐라 player.json의 어깨 좌석에 탈 수 있다. 하지만 실험에서 화면을 눌러도 탑승한 엔티티가 한 번도 눌리지 않았다.

C2 시선 앞 위치:

```js
function spotInFront(player, distance, drop) {
  const view = player.getViewDirection();
  const eye = player.getHeadLocation();
  return { x: eye.x + view.x * distance, y: eye.y + view.y * distance - drop, z: eye.z + view.z * distance };
}
```

C3 엔티티는 `minecraft:rideable`에 `family_types: ["player"]`, 좌석 `position: [0, 0, 0]`을 둔다. 탑승 중에는 `action.hint.exit.<엔티티 식별자>` 안내가 번역되지 않은 채 보였다. 리소스 팩 언어 파일에 이 키를 넣어야 한다.

디스코드에 나온 다른 우회법은 시험하지 않았다.

- 가구 블록 안에 엔티티를 두고 판정 상자를 블록보다 조금 크게 해, 블록을 누르면 엔티티가 눌리게 한다(2025-10-22, 2026-03-09).
- 컨테이너를 가진 커스텀 블록과 상호작용하면 인벤토리 화면이 열린다는 26.50 프리뷰 언급(2026-08-21). 정식 버전에 들어갔는지는 확인하지 않았다.
- 좌석이 엔티티 중심에서 멀면 화면이 열렸다 바로 닫힌다는 보고(2026-05-05). C3는 좌석을 중심에 두었다.

| 1~48 | 연구 필요 탭의 현재 페이지 48칸 |
| 49~96 | 연구 완료 탭의 현재 페이지 48칸 |
| 97, 98 | 탭 머리(아이콘, `To do N`, `Done N`) |
| 99~102 | 탭마다 이전, 다음 페이지 버튼 |

| 125~146 | 연구 완료 탭 상세(같은 구성) |

### 7.2 서버 폼 판과 다른 점

| 항목 | 서버 폼 연구 화면 | 엔티티 연구 화면 |
| --- | --- | --- |
| 아이콘 | 숫자 ID | 엔진이 칸 아이템을 그린다 |
| 칸 선택 | 칸 토글. 상세 20칸을 칸마다 미리 보낸다 | 칸을 누르면 그 칸의 선택 버튼 칸이 빠른 이동되고, 스크립트가 상세 22칸을 그 연구로 채운다 |
| 탭 전환 | 라디오 토글 | 같다 |
| 페이지, 진행 | 폼 버튼. 폼이 닫혔다 다시 열린다 | 빠른 이동 버튼. 화면은 열린 채 칸만 바뀐다 |
| 재료, 보상 개수 | 버튼 글자 | 칸 아이템의 수량을 `#inventory_stack_count`로 그린다 |

칸 선택은 서버를 거치지만 상세가 바뀌는 데 걸리는 시간은 거의 느껴지지 않았다. 선택 표시(노란 테두리)는 칸 아이템 lore의 `SELECTED`를 포함 검사해 그린다.

### 7.3 정할 것

- **선택 버튼은 아이콘 칸과 다른 칸에 둔다.** 아이콘 칸 아이템을 빠른 이동시키면, 그 칸이 비는 동안 빈 칸 숨김 조건에 걸려 가로 줄이 줄었다가 다시 늘어났다. 칸마다 숨긴 선택 칸을 따로 두고, 칸 자리는 비어 있어도 크기를 유지한다.
- **진행 버튼의 상태는 버튼 칸 아이템으로 넘긴다.** 스크립트가 0.5초마다 재료를 세어 버튼 아이템 lore에 `READY`를 넣거나 뺀다. 버튼은 `READY`가 있으면 초록 `Start research`, 없으면 회색 `Not enough materials`를 그린다.
- **처음 열 때 첫 탭 내용을 보이게 한다.** 첫 탭의 내용은 둘째 탭 토글이 꺼져 있을 때 보이게 하고(`(not #toggle_state)`), 첫 탭 토글에 `toggle_default_state: true`를 준다.

## 8. 2048 시험: 애니메이션 다시 재생과 깜빡임

엔티티 칸으로 2048을 그려, 열린 상자 화면에서 타일이 미끄러지는 애니메이션을 수마다 다시 재생할 수 있는지 시험했다(모바일 1.26.63, 2026-11-15). 화면은 C2로 열고 2.2절 방식으로 넣는다. 그 시험 팩을 정리한 것이 예제 애드온 Entity 2048(8.5절)이고, 아래 코드는 그 파일에서 옮겼다. 예제 애드온은 이름, 식별자, 2.2절의 접두사 규약, 2.2.3절의 레이어가 시험 팩과 다르다. 예제 애드온도 게임에서 자기 화면이 열렸다(실측, 위키 예제 열 개를 한 월드에 켠 시험).

### 8.1 칸 배치

엔티티는 `inventory_size: 243`이다.

| 칸 | 내용 |
| --- | --- |
| 1~16 | 이동 층. 옛 위치에 옛 값. 이름 예 `L2at5`(왼쪽으로 2칸, 표식 a, 값 2의 5제곱) |
| 17~32 | 결과 층. 새 위치에 새 값. 이름 예 `Mbt6`(합쳐짐), `Pat1`(새로 생김), `Nat3`(그대로) |
| 33, 34 | 점수, 상태 글 |
| 36~40 | 위, 아래, 왼쪽, 오른쪽, New 버튼(빠른 이동 버튼, 2.5절) |

이동 코드는 `S0`(제자리)와 방향 `U`, `D`, `L`, `R` 뒤에 거리 1~3이다. 결과 코드는 `N`, `M`, `P`다. 빈 칸에는 아이템이 없다. 데이터 아이템은 종이에 이름만 붙이고 `(#hover_text - '§o' - '§f' - '§r')`로 이름만 읽는다(2.4절).

### 8.2 애니메이션 다시 재생

열린 화면에서 애니메이션을 처음부터 다시 재생하려면 팩토리가 컨트롤을 새로 만들게 한다(실측, ANI-37).

`rp/ui/e2048.json`의 `factory_mover_cell`에서 키 두 개만 남긴 것이다. 실제 파일은 키를 모두 적는다.

```json
"factory_mover_cell": {
  "type": "stack_panel",
  "size": [ 30, 30 ],
  "factory": {
    "name": "e2048_mover",
    "control_ids": {
      "S0at1": "@e2048.ft_S0_1",
      "S0bt1": "@e2048.ft_S0_1"
    }
  },
  "property_bag": {
    "#k": [],
    "#kS0at1": [ "S0at1" ],
    "#kS0bt1": [ "S0bt1" ]
  },
  "bindings": [
    {
      "binding_type": "collection",
      "binding_collection_name": "container_items",
      "binding_name": "#hover_text",
      "binding_condition": "always"
    },
    {
      "binding_type": "view",
      "binding_condition": "always",
      "source_property_name": "('#k' + (#hover_text - '§o' - '§f' - '§r'))",
      "target_property_name": "#collection_length"
    }
  ]
}
```

- 칸마다 `stack_panel` 팩토리 하나가 `('#k' + 이름)`으로 `property_bag`을 조회해 `#collection_length`를 정하고(COL-22, COL-23), `control_ids`에서 그 키의 컨트롤 하나를 만든다. 빈 칸은 `#k`가 빈 배열이라 아무것도 만들지 않는다. 실제 팩은 생성기로 이동 코드 13개와 결과 코드 3개에 값 13개, 표식 2개를 곱한 키를 만든다.
- 스크립트는 수마다 이름의 표식을 `a`와 `b`로 바꾼다. 같은 타일이 같은 자리에 남아도 키가 바뀌므로 팩토리가 컨트롤을 새로 만들고, 그 컨트롤의 `anims`가 처음부터 재생됐다(실측).
- 표식마다 변형 패널을 한 벌씩 두고 `#visible`만 바꾸는 방식은 슬라이드가 보이지 않았다. 숨었다 보이는 것으로는 애니메이션이 다시 재생되지 않는다(실측).

타일 애니메이션은 다음과 같다.

- 이동 타일은 0.12초 동안 `offset`으로 목적지까지 가고, 0.17초에 `alpha` 0이 된다.
- 결과 타일은 0.12초 동안 `alpha` 0이었다가 보인다. 합쳐진 칸은 `size` 28에서 34로 커졌다 돌아오고, 새 칸은 0에서 커진다.
- 기다리는 단계는 `from`과 `to`가 같은 `alpha`, `size` 애니메이션을 `next`로 잇는다.
- 결과 층은 이동 층보다 위 레이어다.

### 8.3 깜빡임과 빈 격자

칸 아이템이 바뀌는 순간 `container_items` 격자의 칸 그림이 한 프레임 동안 다른 컨트롤 위에 그려졌다. 회색 칸이 우리 창 위로 잠깐 올라와 판 전체가 깜빡이는 것처럼 보였다(실측, HOST-50).

| 창 뒤의 구성 | 결과 |
| --- | --- |
| 바닐라 상자 화면을 숨기지 않음 | 깜빡임이 보이지 않았다. 바닐라 상자 화면이 창 옆에 보였다 |
| 바닐라를 `visible: false`로 숨기고 격자 없음 | 판 전체가 회색으로 깜빡였다 |
| 바닐라 숨김, `common.pocket_ui_container_item` 칸 27개 격자 | 판 전체가 깜빡였다 |
| 바닐라 숨김, 바닐라 칸 1개 격자 | 그 칸 자리만 깜빡였다 |
| 바닐라 숨김, 빈 패널 칸 27개 `container_items` 격자 | 깜빡이지 않았다 |
| 바닐라를 숨기지 않고 화면 전체를 불투명 배경으로 덮음 | 깜빡이지 않았지만, 화면 전체가 덮여 폼처럼 보이지 않았다 |

모두 실측이다. 수마다 폭이 바뀌는 라벨로 레이아웃을 다시 계산하게 해도 깜빡임은 그대로였다(실측). 그래서 창 뒤에 빈 패널 칸으로 된 격자를 하나 둔다. 2.2.3절 `overlay`의 `cover` 안 `sync_grid`가 그 격자이고, 칸 템플릿은 다음과 같다.

```json
"empty_cell": {
  "type": "panel",
  "size": [ 18, 18 ]
}
```

- 위 표의 시험은 바닐라를 `visible: false`로 숨긴 구성에서 했다. 바인딩으로 `#visible`을 끄는 지금 구성(2.2.2절)에서도 빈 격자를 두고 깜빡임이 없었다(실측, 호환 시험 팩).
- 격자 없이 깜빡인 회색이 숨긴 바닐라 칸인지, 빈 격자를 두면 왜 깜빡임이 사라지는지는 모른다.
- 바닐라 칸이 보이는 구성에서 깜빡임이 보이지 않은 것은 바닐라 칸이나 배경에 가려 눈에 띄지 않았기 때문일 수 있다(*추론*).

### 8.4 컨테이너 제목과 이름표

- 엔티티 상자 화면의 제목은 nameTag다(실측, HOST-19). `minecraft:inventory`, Script API의 `Container`와 `EntityInventoryComponent`에는 제목을 nameTag와 따로 정하는 필드나 함수가 없다(Microsoft Learn 문서).
- nameTag가 없을 때 언어 파일의 `entity.<id>.name`이 제목이 되는지는 커뮤니티 보고가 엇갈린다(**충돌**).
- 커스텀 블록은 `minecraft:block_entity`의 `container.title`(언어 키 또는 글자)로 제목을 줄 수 있고, `show_ui_on_interaction`(기본 켬)으로 블록을 누르면 열린다. 26.50, 26.60에서 실험 기능이라는 사용자 보고가 있다(*단일 보고*).
- `minecraft:nameable`에는 이름표를 숨기는 필드가 없다(`allow_name_tag_renaming`, `always_show`, `default_trigger`, `name_actions`). 클라이언트 엔티티 파일이 없는 행동 팩 전용 엔티티는 이름표가 그려지지 않는다는 보고가 있다(*단일 보고*).
- 이름표를 숨길 후보로 `Entity.nameplateRenderDistance`(`@minecraft/server` 2.8.0부터 쓰기 가능)가 있다. 0이 숨김인지는 시험하지 않았다(*미검증*).

## 9. 예제: 매치메이킹 대기열

미니게임 여러 개가 있는 서버를 가정한 매치메이킹 목업이다. 게임마다 대기열이 있고, Play를 누르면 대기열에 들어가 인원 칸이 차오른다. 대기 중에는 취소할 수 있고, 인원이 다 차면 10초 준비 확인이 뜬다. 다른 인원은 행동 팩이 난수로 넣고 빼는 가상 인원이고, 같은 월드의 실제 플레이어가 같은 게임 대기열에 들어오면 한 로비로 묶인다. 열린 화면은 스크립트가 칸 아이템을 바꿀 때마다 바로 바뀐다(1절).

![대기 중 화면. 왼쪽에 게임 네 개가 있고 대기 중인 Hide and Seek 줄이 초록 테두리다. 오른쪽에 Finding match., 대기 시간 0:12, Estimated 0:21, 인원 칸 10개 중 노란 나 하나와 파란 다른 사람 일곱, 8 / 10 players, Nightowl joined the queue, Cancel 버튼](/img/design/entity-matchmaking-queue.png)

![준비 확인 화면. Match found!, 남은 6초, 수락한 칸 넷은 초록 체크이고 나머지는 파랗다. 4 / 10 accepted, Nightowl accepted, 절반쯤 줄어든 초록 막대](/img/design/entity-matchmaking-ready.png)

### 9.1 상태

| 상태 | 화면 | 버튼 |
| --- | --- | --- |
| 대기열 밖 | 고른 게임 이름, 설명, "Not in queue", 보통 대기 시간, 한 판 인원 | Play |
| 대기 중 | "Finding match...", 대기 시간, 예상 시간, 인원 칸(나, 다른 사람, 빈 칸), `5 / 8 players`, 마지막 입장과 퇴장 소식 | Cancel |
| 매치 찾음 | "Match found!", 남은 초, 10초 동안 줄어드는 막대, 수락한 사람 칸은 초록 체크 | Accept, Decline |
| 시작 | "Match starting", 4초 세기 | 없음 |

- 왼쪽 목록은 Sky Duels(2명), Bed Rush(8명), Parkour Race(6명), Hide and Seek(10명)다. 줄을 누르면 고른다. 대기 중에는 다른 게임으로 바꿀 수 없다. 고른 줄은 파란 테두리, 대기 중인 줄은 초록 테두리와 깜빡이는 점이다. "N playing" 숫자는 3초마다 조금씩 바뀐다.
- 화면을 닫아도 대기열은 유지되고, 액션바에 게임, 대기 시간, 인원이 뜬다. 매치를 찾으면 소리와 함께 액션바가 수락을 안내한다.
- 누가 거절하면 준비 확인은 곧바로 실패한다. 거절한 사람은 대기열에서 빠지고 나머지는 대기 시간을 유지한 채 대기열로 돌아간다. 10초 안에 답하지 않은 사람은 빠진다. 모두 수락하면 4초 뒤 처음 상태로 돌아간다. 실제 게임은 없다.

### 9.2 칸 배치

엔티티는 `inventory_size: 243`이고 이름은 `§b§w§m§m`이다(2.2.1절).

| 칸 | 내용 |
| --- | --- |
| 1~20 | 게임 줄 4개 x 5칸: 버튼, 이름, 부제(모드 또는 "In queue 0:12"), 플레이 수, 줄 상태 키(`S` 고름, `Q` 대기 중) |
| 21~28 | 게임 이름, 설명, 머리글, 시계, 예상 시간, 인원 글, 소식, 바닥 글(알림 또는 버전) |
| 29, 30 | 주 버튼(Play, Cancel, Accept), 보조 버튼(Decline) |
| 31 | 준비 확인 막대 키(`Ta`, `Tb`) |
| 32~41 | 인원 칸 키 10개(`E` 빈 칸, `F` 다른 사람, `Y` 나, `A` 수락, `X` 거절). 정원이 10보다 작으면 가운데 칸만 쓴다 |
| 42, 43 | 주 버튼, 보조 버튼 글 |

### 9.3 화면 구성

- 글은 칸 이름을 `(#hover_text - '§o' - '§f' - '§r')`로 읽는다(2.4절). 글꼴 크기와 정렬은 `$emm_scale`, `$emm_align` 변수로 준다.
- 인원 칸, 줄 테두리, 준비 막대는 2048의 타일처럼 `stack_panel` 팩토리가 칸 이름을 키로 `property_bag`을 조회해 컨트롤 하나를 만든다(COL-22). 키가 바뀌면 컨트롤이 새로 만들어지므로 칸이 채워질 때 커지는 애니메이션이 그때마다 재생된다(ANI-37).
- 준비 막대는 `size` 애니메이션 하나로 10초 동안 줄어든다. 스크립트는 남은 시간을 보내지 않고, 준비 확인마다 키를 `Ta`와 `Tb`로 번갈아 바꿔 막대를 새로 만든다.
- 버튼은 칸 빠른 이동으로 스크립트에 알린다(2.5절). 주 버튼과 보조 버튼은 자기 칸이 비면 `#visible`이 false가 되어 숨는다. 버튼 글은 다른 칸에서 읽어 버튼 위에 그린다.
- 숫자로 시작하는 글은 앞에 색 코드를 붙인다(`§1` 시계, `§8` 인원 글). 식을 지나며 숫자로 읽혀 `0 / 8 accepted`가 `0`이 되기 때문이다(EXP-30, EXP-44, jsonui-tester).

### 9.4 난수

| 값 | 범위 |
| --- | --- |
| 처음 로비에 있던 가상 인원 | 0 ~ min(정원 - 2, 정원의 절반) |
| 다음 입장까지 | Sky Duels 3~12초, Bed Rush 1.5~6초, Parkour Race 3~10초, Hide and Seek 1~5초 |
| 파티 입장 | 15%, 2~3명(자리가 있을 때) |

## 10. 예제: 인형 로비

9절 매치메이킹과 같은 대기열 흐름에, 로비 사람마다 서 있는 모습(엔티티 인형)을 그린 예제다. 인원 칸 대신 2줄 x 4칸 인형 칸이 있고(최대 8명, 나 포함), 감정 표현 버튼 4개가 있으며, 가상 인원은 천천히 주변을 둘러본다. 9절 예제와 이름, 식별자가 달라 같은 월드에 함께 켜도 된다.

### 10.1 인형 그리기

칸마다 `live_horse_renderer` 하나가 엔티티 하나를 그린다. 렌더러의 `#entity_id`에 Script API의 `entity.id` 문자열을 주면 그 엔티티를 그린다는 커뮤니티 보고가 여럿 있고, 상자 화면에서 칸 이름으로 넘기는 방법은 아래처럼 실측으로 찾았다.

| 넘기는 방법 | 칸 이름 | 바인딩 | 결과(실측) |
| --- | --- | --- | --- |
| 그대로 | `-4294967295` | `#hover_text`를 그대로 `#entity_id`에 | 그려지지 않음. 값에 서식 코드가 섞임 |
| 큰따옴표 이름 | `"-4294967295"` | `(#hover_text - '§o' - '§f' - '§r')` | 그려짐. 받은 값은 따옴표 없는 `-4294967295` |
| 두 숫자 합치기 | `-4294`, `967295`(두 칸) | `('"' + #hi + #lo + '"')` | 그려짐 |
| 숫자만 | `-4294967295` | `(#hover_text - '§o' - '§f' - '§r')` | 그려지지 않음. 숫자로 바뀜(EXP-30) |
| 화면 기본값 | 없음 | 전역 `#entity_id` | 그려지지 않음. 상자 화면은 이 값을 주지 않음 |

- 예제는 큰따옴표 이름을 쓴다. 실제 플레이어 칸은 `p"<id>"`, 가상 인원 칸은 `b"<id>"`로 쓰고, 칸마다 렌더러 두 개가 각각 `p`, `b`를 뺀 값을 받는다. 빼서 값이 바뀐 쪽만 보인다(`#visible`).
- 같은 칸에 둔 `live_player_renderer`는 나도, 다른 엔티티도 그리지 않았다(실측). 이 시험은 바깥 창 50, 덮개 100 안이었다. 레이어 합을 94 이하로 낮추자 `live_player_renderer`도 상자 화면에서 나를 그렸다(2.2.3절, 실측). 다른 엔티티는 레이어가 낮아도 그려지는지 시험하지 않았다(*미검증*).
- 모델 키는 렌더러 컨트롤 크기의 약 2배라 칸 밖으로 넘친다. 칸에 `clips_children: true`를 주어 자른다(실측).
- 플레이어는 머리가 컨트롤 위끝에 오지만, 커스텀 엔티티는 같은 컨트롤에서 위로 떠서 그려진다. 컨트롤을 크기의 1.35배만큼 내리면 플레이어와 같은 자리에 온다(실측, 크기 16, 24, 32).
- 시야 밖(10블록 뒤)에 있는 엔티티도 그려졌다(실측). 다른 실제 플레이어 칸은 시험하지 않았다(*미검증*).
- 렌더러는 커서를 따라 모델을 돌리고 `#look_at_cursor: false`로도 끌 수 없다는 커뮤니티 보고가 있다(*미검증*). 모바일에서는 확인하지 못했다.

### 10.2 가상 인원 엔티티

가상 인원은 보는 사람마다 엔티티 `bwiki:entity_matchmaking_figures_bot`(스티브 또는 알렉스)을 하나씩 만들어 그 사람 발밑에 둔다. 충돌 상자는 0.1이라 화면을 여는 탭을 가로채지 않는다.

| 월드에서 숨기는 방법 | 결과(실측) |
| --- | --- |
| 렌더 컨트롤러 `part_visibility`에 `{ "*": "q.is_in_ui" }` | 월드에서 안 보이고 인형 칸에는 그려짐. 예제가 쓰는 방법 |
| 뿌리 뼈 `scale`을 `q.is_in_ui ? 1.0 : 0.0`으로 두는 애니메이션 | 같음 |
| `part_visibility`에 `!q.property('…') \|\| q.is_in_ui`(불리언 속성과 함께) | 월드에서도 보임 |

### 10.3 감정 표현과 둘러보기

- 감정 표현은 Hi(손 흔들기), Clap(박수), Jump(점프), Nod(끄덕이기)다. 누르면 내 플레이어 엔티티에 `playAnimation`을 틀고, 가상 인원은 보는 사람마다 있는 엔티티에 함께 튼다. 인형 칸에서 그대로 보였다(실측). 플레이어 엔티티 정의에 애니메이션을 적지 않아도 됐다.
- `setRotation`으로 바꾼 몸 방향과 고개 각도는 인형에 나타나지 않았다(실측).
- 그래서 시선은 정수 엔티티 속성(`bwiki:yaw`, `bwiki:head_yaw`, `bwiki:pitch`)으로 넘기고, 늘 도는 애니메이션이 뿌리 뼈(`root`)와 머리 뼈(`head`)를 돌린다. 애니메이션 안의 `q.property`는 읽혔다(실측).
- 속성은 목표 값이다. 클라이언트 엔티티의 `pre_animation`이 변수를 매 프레임 목표 쪽으로 `q.delta_time`에 비례해 옮기고(몸은 느리게, 머리는 빠르게), 애니메이션은 그 변수를 쓴다. 사이 값을 거치며 부드럽게 돌았다(실측). 서버는 시선을 바꿀 때만 속성을 보낸다.
- 가상 인원은 1.5~4초마다 새 시선을 정한다. 머리 좌우는 -50~50도, 위아래는 -25~25도이고, 몸 방향은 40% 확률로 -45~45도(정면 근처)에서 바꾼다.

### 10.4 칸 배치

엔티티는 `inventory_size: 243`이고 이름은 `§b§w§m§f`이다(2.2.1절). 1~43번 칸은 9.2절과 같고, 인원 칸 키(32~41)를 쓰지 않는다.

| 칸 | 내용 |
| --- | --- |
| 44~67 | 인형 칸 8개 x 3칸: 엔티티 ID(`p"<id>"` 또는 `b"<id>"`), 칸 키(`E` 빈 자리, `M` 다른 사람, `Y` 나, 뒤에 `A` 수락 또는 `X` 거절), 이름 |
| 68~71, 72~75 | 감정 표현 버튼 4개, 그 글 |
