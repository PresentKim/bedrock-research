# 엔티티 인벤토리로 메뉴 화면 만들기

서버 폼 버튼은 아이템 아이콘을 텍스처 경로나 숫자 ID로만 그린다. 숫자 ID는 스크립트가 확정할 수 없는 경우가 많다([아이템 숫자 ID 기획 5.7절](./item-aux-id.mdx#57-결론-스크립트가-할-수-있는-것)). 엔티티 인벤토리 화면은 엔티티 칸에 든 실제 아이템을 엔진이 그리므로 바닐라, 커스텀, 다른 팩 아이템이 모두 맞게 나온다.

이 페이지는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그려 연구 화면 같은 메뉴로 쓰는 구성을 다룬다.

상태: 1.26.63 모바일에서 화면 라우팅, 아이콘 격자, 클라이언트 선택, 스크립트로 가는 버튼, 세 가지 여는 방법을 시험했다(2026-11-14). 예제 애드온은 아직 없다.

## 1. 서버 폼과 비교

| 항목 | 서버 폼 | 엔티티 인벤토리 화면 |
| --- | --- | --- |
| 여는 방법 | 스크립트가 바로 연다 | 스크립트가 강제로 열 수 없다. 플레이어 동작이 한 번 필요하다(3절) |
| 아이콘 | 텍스처 경로, 또는 숫자 ID | 엔진이 엔티티 칸을 그린다. 모든 아이템, 3D, 반짝임 |
| 아이콘 수 | 버튼 수만큼 | 엔티티 인벤토리 칸 수만큼(27칸 화면에서도 칸은 더 읽힌다, HOST-16) |
| 내용 바꾸기 | 폼을 닫고 다시 연다 | 스크립트가 칸을 바꾸면 열린 화면에 바로 반영된다 |
| 스크립트로 가는 입력 | 버튼 번호 | 칸 조작뿐이다. 버튼은 칸 빠른 이동으로 우회한다(2.4절) |
| 화면 안 동작 | 라디오 토글로 클라이언트 처리 | 같다 |

## 2. 구성

### 2.1 엔티티

```json
"minecraft:inventory": {
  "container_type": "container",
  "inventory_size": 27,
  "private": false,
  "can_be_siphoned_from": false
}
```

- `container_type: "container"`이고 `private: false`여야 `chest_screen.json`으로 열린다(HOST-16).
- 메뉴용 엔티티는 `minecraft:physics`(중력, 충돌 끔), `minecraft:pushable`(밀리지 않음), `minecraft:damage_sensor`(피해 없음)를 둔다.
- 리소스 팩 엔티티는 뼈가 없는 빈 지오메트리로 두어 보이지 않게 한다.

### 2.2 화면 라우팅

`chest_screen.json`에서 `small_chest_screen`을 다시 선언해 `$screen_content`를 바꾼다(HOST-18). 0번 칸에 표식 아이템(`max_durability` 4242인 숨긴 커스텀 아이템)을 넣고, 그 값이 맞을 때만 우리 창을 그린다. 다른 상자와 엔티티는 바닐라 화면 그대로다.

```json
"small_chest_screen@common.inventory_screen_common": {
  "variables": [
    { "requires": "$desktop_screen", "$screen_content": "menu_box.root_desktop" },
    { "requires": "$pocket_screen", "$use_custom_pocket_toast": true, "$screen_content": "menu_box.root_pocket" }
  ]
}
```

```json
"gate": {
  "type": "panel", "size": [ "100%", "100%" ],
  "bindings": [
    { "binding_type": "collection_details", "binding_collection_name": "container_items" },
    { "binding_type": "collection", "binding_collection_name": "container_items", "binding_name": "#item_durability_total_amount", "binding_name_override": "#identity" },
    { "binding_type": "view", "source_property_name": "$gate_rule", "target_property_name": "#visible" }
  ]
},
"root_pocket": {
  "type": "panel", "size": [ "100%", "100%" ],
  "controls": [
    { "vanilla@menu_box.host": { "$gate_rule": "(not (#identity = 4242))", "$content": "pocket_containers.small_chest_panel" } },
    { "menu@menu_box.host": { "$gate_rule": "(#identity = 4242)", "$content": "menu_box.window" } }
  ]
}
```

`host`는 `collection_name: "container_items"`인 패널 안에 `collection_index: 0`인 `gate`를 두고, 그 안에 `$content`를 넣는다. 데스크톱은 `chest.small_chest_panel`을 바닐라 쪽에 둔다. 우리 창에서는 플레이어 인벤토리(보관함) 영역이 그려지지 않는다.

### 2.3 아이콘 격자와 선택

- 칸마다 `inventory_item_renderer`가 `container_items`의 `#item_id_aux`를 `collection_index`로 읽는다.
- 칸은 연구 화면과 같은 라디오 토글(`radio_toggle_group`, `toggle_group_forced_index`)이다. 선택하면 테두리와 큰 상세 아이콘이 보인다. 선택은 클라이언트에서만 처리되고 서버로 가지 않는다.
- 토글이 칸 누름을 가로채므로 아이템은 움직이지 않았다.
- 보여 주는 아이템에는 `lockMode = slot`을 걸었다. 화면에서 빨간 잠금 모서리가 보였다.

### 2.4 스크립트로 가는 버튼

JSON UI에서 스크립트로 바로 가는 통로는 서버 폼 버튼뿐이다. 컨테이너 화면에서 서버까지 가는 것은 칸 조작이므로, 보이는 버튼을 숨긴 칸의 빠른 이동으로 바꾼다.

```json
"start_button": {
  "type": "button", "size": [ 144, 20 ], "layer": 2,
  "default_control": "default", "hover_control": "hover", "pressed_control": "pressed",
  "bindings": [ { "binding_type": "collection_details", "binding_collection_name": "container_items" } ],
  "button_mappings": [
    { "from_button_id": "button.menu_select", "to_button_id": "button.container_auto_place", "mapping_type": "pressed", "consume_event": false },
    { "from_button_id": "button.menu_ok", "to_button_id": "button.container_auto_place", "mapping_type": "focused", "consume_event": false }
  ]
}
```

1. 버튼은 `collection_name: "container_items"`인 스택 패널 안에 `collection_index: 26`으로 둔다.
2. 스크립트는 26번 칸에 표식 이름이 붙은 버튼 아이템을 넣어 둔다.
3. 누르면 빠른 이동으로 그 아이템이 플레이어 인벤토리로 간다.
4. 스크립트는 2틱마다 26번 칸을 보고, 표식 아이템이 없으면 누름으로 세고 칸을 다시 채운다.
5. `world.afterEvents.playerInventoryItemChange`에서 플레이어 인벤토리에 들어온 표식 아이템을 지운다.

칸을 직접 누르는 방식은 터치 화면에서 2회 뒤로 감지되지 않았다. 아이템이 커서에 들려 칸의 아이템과 서로 바뀌기만 하는 것으로 보인다(HOST-20의 "터치에서는 커서가 채워지지 않는다"와 관련). 빠른 이동은 커서를 거치지 않는다.

## 3. 화면을 여는 방법

Script API에는 컨테이너 화면을 여는 함수가 없다. 디스코드에서도 "강제로 열 수 없다"는 답이 반복됐다(2025-10-23, 2026-03-09, 2026-09-10). 그래서 플레이어 동작이 한 번은 필요하다.

| 방법 | 동작 | 1.26.63 모바일 결과 |
| --- | --- | --- |
| C: 보이는 엔티티를 누름 | 플레이어 앞에 엔티티를 소환하고 플레이어가 그것을 누른다 | 열린다. 엔티티가 보여야 찾을 수 있어 메뉴로는 어색하다 |
| C2: 시선 앞 엔티티 | 메뉴 아이템을 든 동안 보이지 않는 1.2x1.2 엔티티를 매 틱 눈 위치에서 시선 방향 1.2칸, 아래로 0.6칸에 옮긴다. 화면 가운데를 누르면 그 엔티티를 누르게 된다 | 한 번 눌러 바로 열린다. 다른 아이템으로 바꿔 들면 엔티티를 지운다. 사용성이 가장 좋았다 |
| C3: 탑승 + 인벤토리 버튼 | 스크립트가 `Rideable.addRider`로 플레이어를 보이지 않는 엔티티에 태운다. 플레이어가 인벤토리 버튼을 누르면 플레이어 인벤토리 대신 그 엔티티의 화면이 열린다 | 열린다. 웅크리면 내린다. 내리면 엔티티를 지운다 |

C2 시선 앞 위치:

```js
function spotInFront(player, distance, drop) {
  const view = player.getViewDirection();
  const eye = player.getHeadLocation();
  return { x: eye.x + view.x * distance, y: eye.y + view.y * distance - drop, z: eye.z + view.z * distance };
}
```

C3 엔티티는 `minecraft:rideable`에 `family_types: ["player"]`, 좌석 `position: [0, 0, 0]`을 둔다. 탑승 중에는 `action.hint.exit.<엔티티 식별자>` 안내가 번역되지 않은 채 보였다. 리소스 팩 언어 파일에 이 키를 넣어야 한다.

디스코드에 나온 다른 우회법은 시험하지 않았다.

- 가구 블록 안에 엔티티를 두고 판정 상자를 블록보다 조금 크게 해, 블록을 누르면 엔티티가 눌리게 한다(2025-10-22, 2026-03-09).
- 컨테이너를 가진 커스텀 블록과 상호작용하면 인벤토리 화면이 열린다는 26.50 프리뷰 언급(2026-08-21). 정식 버전에 들어갔는지는 확인하지 않았다.
- 좌석이 엔티티 중심에서 멀면 화면이 열렸다 바로 닫힌다는 보고(2026-05-05). C3는 좌석을 중심에 두었다.

## 4. 실측 요약 (1.26.63 모바일, 2026-11-14)

| 확인한 것 | 결과 |
| --- | --- |
| 0번 칸 표식으로 우리 창만 바꾸기 | 된다. 바닐라 상자 화면은 그대로다 |
| 아이콘 격자 | 바닐라, 3D 블록, 커스텀 아이템 모두 그려졌다 |
| 토글 선택과 상세 아이콘 | 된다. 아이템은 움직이지 않는다 |
| 칸 직접 누르기 버튼 | 터치에서 2회 뒤로 감지되지 않았다 |
| 빠른 이동 버튼 | 열린 뒤 동작이 잘 됐다(C, C2, C3 모두) |
| C, C2, C3 열기 | 모두 열린다. C2가 가장 쓰기 쉬웠다 |

## 5. 남은 것

- 빠른 이동 버튼을 10번 넘게 눌렀을 때 횟수가 매번 오르는지, 닫은 뒤 플레이어 인벤토리에 버튼 아이템이 남지 않는지 따로 기록하지 않았다.
- `lockMode = slot`을 건 아이템을 엔티티 화면에서 꺼낼 수 없는지 확인하지 않았다. HOST-20은 "읽기 전용 잠금은 없다"고 적는다.
- C2: 열린 동안 매 틱 순간이동하는 영향(화면이 닫히거나 깜빡이는지), 메뉴 아이템을 든 채 블록 부수기나 공격이 엔티티에 막히는지 확인하지 않았다.
- 여러 플레이어: 다른 플레이어가 남의 메뉴 엔티티를 누를 수 있는지, 엔티티를 플레이어마다 둘 때의 정리.
- Windows, iOS, 컨트롤러 입력(`button.menu_ok` 매핑)에서의 동작.
- 표식 바인딩: 이 구성은 `#item_durability_total_amount`로 표식을 읽었다. HOST-17 기록의 `#item_durability_max`와 같은 값인지 확인하지 않았다.
- 예제 애드온.
