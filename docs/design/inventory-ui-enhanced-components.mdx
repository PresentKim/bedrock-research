# 인벤토리 UI로 강화 컴포넌트 구현하기

서버 폼(DDUI, CustomForm)을 상자 화면으로 대신할 수 있는지 보려고 Ore UI 모양의 컴포넌트를 상자 화면에 그린 갤러리 시험 팩(IUC)의 결과를 다루는 문서 가운데 하나다. 화면은 [엔티티 인벤토리로 메뉴 화면 만들기](./entity-inventory-ui.mdx)의 방식(보이지 않는 컨테이너 엔티티의 상자 화면을 리소스 팩으로 다시 그리는 방식)으로 만들었다. 토글, 버튼, 탭 같은 기본 컴포넌트는 [인벤토리 UI로 기본 컴포넌트 구현하기](./inventory-ui-basic-components.mdx)에, 슬라이더와 끌기 나눔(drag split) 실험은 [인벤토리 UI로 슬라이더 구현하기](./inventory-ui-slider.mdx)에 있다. 이 문서는 칸 버튼 여러 개를 엮거나 서버 계산이 많은 컴포넌트 17개를 다룬다.

상자 화면에서 서버로 가는 통로는 칸 누름(빠른 이동)과 칸 아이템 변화뿐이다. 서버는 칸 아이템의 이름으로 화면에 값을 준다(엔티티 인벤토리 문서 2.4절, 2.5절). 아래 컴포넌트는 모두 이 두 통로만 쓴다.

표기:

- **실측**: IUC 시험 팩(`invui-components`)으로 게임에서 확인한 것. 1.26.63 모바일, 2026-11-16. 괄호 안은 그 기록이 나온 시험 팩 판이다.
- **테스터**: [JSON UI 테스터](../tools/jsonui-tester.mdx) 정적 시뮬레이션에서 진단이 없었던 것.
- **모의**: `@minecraft/server`를 흉내 낸 Node 실행에서 모든 버튼을 누르고 틱을 돌려 오류가 없었던 것.
- *추론*: 시험으로 가르지 않은 해석.

## 1. 공통 틀

### 1.1 창과 칸 배정

창은 410x214 어두운 판이다. 위 줄에 페이지 이름, `<` `>`, Pages 버튼이 있고, 아래 줄에 서버가 쓰는 상태 글이 있다. 엔티티는 `inventory_size: 243`이다.

| 칸 | 내용 |
| --- | --- |
| 1~8 | 틀: 페이지 키, 페이지 제목, 상태 줄, 고르기 상태(`open`/`closed`), 바닥 글, Pages, `<`, `>` |
| 10~189 | 지금 페이지가 쓰는 칸. 페이지 안에서는 0~179번으로 부른다 |
| 190~206 | 페이지 고르기 버튼 17개(5열) |

페이지를 바꾸면 서버는 10~189번을 비우고 새 페이지의 버튼 칸만 채운다.

### 1.2 페이지는 보이기 판

모든 페이지를 처음에 만들어 두고, 1번 칸 이름(페이지 키)이 맞는 판만 보인다. 보이는 판 밖의 바인딩은 생성기가 `binding_condition: "visible"`로 바꿔 숨은 페이지에서는 계산하지 않는다. 보이기를 정하는 바인딩만 `always`로 둔다.

- 처음에는 페이지를 페이지 키로 고르는 팩토리 칸으로 만들었다. 그 안의 칸 읽기가 하나도 동작하지 않았다(실측, v1.1.0). 팩토리가 만든 컨트롤 안에서는 컬렉션과 view 바인딩이 동작하지 않는 것으로 보인다(*추론*).
- 보이기 판으로 바꾼 첫 판은 처음 연 페이지만 보였다. 생성기가 공유 바인딩 객체를 직접 고쳐 페이지 판의 칸 읽기까지 `visible` 조건이 되었고, 숨은 판은 칸을 다시 읽지 않아 다시 보이지 않았다(실측, v1.2.0). 바인딩을 복사해서 바꾸자 페이지 전환이 동작했다(실측, v1.2.1).

### 1.3 페이지 모듈

페이지마다 스크립트 모듈 하나(`bp/scripts/pages/<key>.js`)와 UI 모듈 하나(`tools/pages/<key>.mjs`)가 있다. 스크립트 모듈은 게임 API를 쓰지 않으므로 생성기가 그대로 불러, UI에 놓인 칸 버튼과 스크립트의 버튼 목록이 같은지 확인한다.

| 항목 | 내용 |
| --- | --- |
| `buttons` | 칸 버튼으로 쓰는 페이지 칸 번호 목록 |
| `init(env)` | 플레이어별, 페이지별 처음 상태. `env`는 `playerId`, `playerName` |
| `render(state, env)` | 칸 번호마다 글자(종이 이름) 또는 `{ item, count, name, marker }`(진짜 아이템)를 돌려준다 |
| `press(state, slot, env)` | 칸 버튼 누름 처리. 돌려준 글은 상태 줄에 쓴다 |
| `tick(state, env)` | 매 틱 처리(카운트다운, 끌기 정착) |
| `sense(state, read, env)` | 매 틱 페이지 칸의 아이템을 읽는다. `read(n)`은 `{ item, count, marker }` 또는 빈 값 |

페이지는 게임 API 대신 상태에 요청을 남긴다. 틀은 `press` 뒤와 `tick` 뒤에 요청을 처리하고 지운다.

```js
function applyRequests(player, state) {
  if (state.animation) {
    player.playAnimation(state.animation);
    delete state.animation;
  }
  if (state.collectMarkers) {
    collectMarkers(player);
    delete state.collectMarkers;
  }
}
```

`marker: true`로 쓴 아이템에는 이 애드온만의 lore가 붙는다. `collectMarkers`는 플레이어 인벤토리와 커서(`cursor_inventory`)에서 그 lore가 붙은 아이템을 지운다. 칸 버튼 아이템은 다른 lore를 달고, 서버가 매 틱 플레이어 인벤토리에서 지운다.

### 1.4 글자와 미리 만든 변형

- 서버가 쓰는 값이 숫자로만 된 칸 이름이면 라벨에 그려지지 않았다(실측, v1.2.1, NumberInput). 숫자를 보일 칸은 앞에 `§r`를 붙인다. `tools/check-page.mjs`는 숫자로만 된 값을 쓰면 실패로 알린다.
- 숫자로 시작하는 값이나 색 코드를 살릴 값은 `§o`만 빼고 읽는 라벨로 그린다(표의 칸, 카운트다운 시간, 상점 알림).
- 글자와 그 아래 바탕의 레이어 합이 같으면 바탕이 글자를 덮을 수 있다(*추론*). 그런 자리의 글자 레이어를 올리자 보이지 않던 글자가 모두 보였다(실측, v1.4.2). 칸 버튼에 덧붙인 글자와 아이콘은 레이어 20의 판에 넣어 버튼 바탕보다 늘 위에 그린다.
- 연속값(막대 폭, 차트 높이, 색)은 미리 만든 변형 중 하나를 칸 이름 키로 고른다. 키로 고르는 팩토리 칸 안에는 바인딩 없는 정적인 그림만 둔다(1.2절의 실측). 팩토리 칸은 키가 바뀔 때 다시 만들어지므로, 그 안의 애니메이션은 처음부터 다시 재생된다(엔티티 인벤토리 문서 8.2절).

## 2. 입력 컴포넌트

### 2.1 TextInput

이름 칸(16자)과 비밀번호 칸(12자)이 있고, 아래에 화면 자판이 있다. 자판은 숫자 줄, `qwertyuiop`, `asdfghjkl`, `zxcvbnm` 네 줄과 Shift(대문자 고정), Back, Clear, Space다. 비밀번호는 `*`로 가리고 눈 버튼으로 보인다. 아래 줄에 지금 칸의 글자 수가 나온다.

- 바닐라 입력창(`text_edit_box`)은 상자 화면에서 글을 읽을 수 없었다. 입력창의 `#item_name`, 입력창 안 라벨의 `#text`, 전역 `#item_name`, 입력창의 `#text` 네 경로가 모두 비었다(실측, 입력 시험 팩 `invui-input-probe` v1.1.0, 모바일, 2026-11-16). 그래서 글자마다 칸 버튼 하나를 둔다. 버튼은 43개다.
- 서버가 두 칸의 글을 들고 있다가 칸 이름으로 쓴다. 지금 칸 뒤에 `_`를 붙이고, 빈 칸에는 placeholder 글을 따로 쓴다.
- 포커스(`name`/`pass`)는 칸 이름 하나로 넘기고, 그 값이 맞는 칸에 흰 테두리가 보인다.
- 대문자 고정은 칸 이름 `lower`/`upper` 하나로 넘긴다. 글자 키마다 소문자 글과 대문자 글을 두고 그 값으로 하나만 보인다.
- 확인한 것: 테스터, 모의(v1.1.0). 이 페이지의 게임 기록은 없다.

### 2.2 NumberInput

-와 +로 1씩 바꾸고(0~64), 값을 누르면 숫자 자판(7 8 9 Back, 4 5 6 -, 1 2 3 ., 0 OK)이 값 칸의 입력을 받는다. OK를 누르면 숫자로 읽어 범위 안으로 자른다. 입력은 8자까지다. 아래에 비활성 예시(`alpha` 0.5)가 있다.

- 값 칸은 바탕 위의 칸 버튼 셋(-, 값, +)이고, 편집 중이면 흰 테두리가 보인다.
- 누름은 서버가 받았지만 숫자가 보이지 않았다(실측, v1.2.1). 숫자만 있는 칸 이름이었다. 앞에 `§r`를 붙인 뒤에도 보이지 않았다(실측, v1.3.0). 값 글자를 입력칸 바탕보다 높은 레이어로 올렸다(v1.4.0). 같은 레이어 합에서 바탕이 글자를 덮을 수 있었다고 본다(*추론*). v1.4.0 이후 이 페이지의 숫자가 보이는지는 기록이 없다.

### 2.3 Keybinds

동작 여섯 개(Jump, Sneak, Attack, Use item, Inventory, Drop item)마다 키 칸이 있다. 키 칸을 누르면 그 칸이 흰 테두리와 "Pick a key"로 바뀌고 오른쪽에 키 목록 30개와 Cancel이 뜬다. 충돌 처리는 swap(맞바꿈), replace(원래 키를 비움), block(막음) 중 하나를 고른다.

- 실제 키 입력은 상자 화면에서 잡을 수 없으므로 키 이름 목록에서 고른다. 고른 키는 화면에만 보이고 게임 조작은 바뀌지 않는다.
- 듣는 중인 동작은 칸 이름 하나(`none`, `l0`~`l5`)로, 목록은 `open`/`closed`로 넘긴다.
- 확인한 것: 테스터, 모의(v1.1.0).

### 2.4 ColorPicker

채도와 밝기 5x5 칸, 색상 막대 12칸, 염료 견본 16색, 16진수 자판(0~f와 Back), 미리보기 견본, 16진수 글과 HSV 글이 있다. 버튼은 70개다.

- 5x5 칸의 색 그림은 색상 12가지마다 미리 만든 판이고, 색상 칸 이름(`h0`~`h11`)을 키로 한 팩토리 칸에서 고른다. 그 위에 칸 버튼 25개와 손잡이 25개(칸 이름 `s<채도>v<밝기>`로 하나만 보임)가 있다.
- 미리보기 견본은 격자 색과 염료 색을 모은 213가지 정적 견본 중 하나를 팩토리 칸으로 고른다. 자판으로 친 16진수가 그 안에 없으면 가장 가까운 격자 색을 보이고, 16진수 글은 친 값 그대로다.
- 확인한 것: 테스터, 모의(v1.1.0).

### 2.5 RadialMenu

지름 120의 원판(2px 띠를 쌓아 그림)과 둘레의 항목 8개다. 항목마다 칸 버튼이고, 고른 항목이 가운데와 오른쪽 글에 나온다.

- 각도 판정 대신 둘레 자리마다 버튼을 둔다. PC 마우스는 버튼의 hover 모양으로 항목이 밝아지고, 휴대폰은 hover가 없어 누를 때 고른다.
- 잘 동작했다(실측, v1.2.1).

## 3. 안내와 차트

### 3.1 Tutorial

가짜 화면(검색 칸, Play 버튼, 설정 판)에서 Start tutorial을 누르면 단계마다 어두운 덮개, 강조 테두리, 안내 카드(제목, 설명, "1 of 3", Back, Next 또는 Finish)가 뜬다. 첫 단계의 Back은 누를 수 없는 그림이다.

- 단계 번호를 칸 이름(`off`, `s0`~`s2`)으로 넘기고, 단계마다 미리 만든 덮개 판 하나가 보인다. 강조 자리와 카드 자리는 생성기가 미리 계산한다(카드는 대상 아래, 자리가 없으면 위).
- 확인한 것: 테스터, 모의(v1.1.0).

### 3.2 BarChart

막대 8개, 음수는 빨강이다. 데이터셋 넷(Monthly sales, Profit, Losses, All zero)을 Prev와 Next로 고르고, Random과 Negate가 있다.

- 막대 높이는 2px 단위 40단계(0~39)다. 서버가 막대마다 채움 키(`p<k>` 양수, `n<k>` 음수)와 덮개 키(`m<k>`)를 쓴다. 채움은 기준선과 값 중 높은 쪽까지 칠하고, 바탕색 덮개가 낮은 쪽까지 덮어 그 사이만 남긴다. 기준선 높이도 키(`l<k>`)로 고른다.
- 칸마다 같은 팩토리 칸 정의 하나를 쓰고, 칸 번호만 변수(`$iuenh_slot`)로 넘긴다([바인딩 계산식 캐싱](./binding-expression-caching.mdx)과 같은 방식).
- 확인한 것: 테스터, 모의(v1.1.0).

### 3.3 LineChart

점 8개와 계단식 선이다. 데이터셋 넷과 Random이 있다.

- 회전한 선분은 그릴 수 없으므로 선을 4px 폭 기둥 37개로 그린다. 서버가 점 사이를 이은 선이 기둥마다 지나는 높이의 아래끝과 위끝을 계산해, 채움 키(`f<k>`)와 덮개 키(`m<k>`)로 쓴다. 점도 높이 키(`d<k>`)로 고른다.
- 확인한 것: 테스터, 모의(v1.1.0).

## 4. 진짜 아이템을 쓰는 컴포넌트

`render`가 `{ item, count }`를 돌려주면 틀이 그 칸에 진짜 아이템을 둔다. UI는 그 칸을 `inventory_item_renderer`(`#item_id_aux`)와 개수 라벨(`('§r' + #inventory_stack_count)`)로 그린다. 칸 버튼 칸과 아이템을 보이는 칸은 서로 다른 칸이다.

### 4.1 ItemGrid

진짜 아이템 아이콘과 개수가 있는 9x3 격자다. 칸을 누르면 선택 테두리가 생기고, 오른쪽에 이름과 개수가 나온다. Shuffle(섞기), Add diamond(다이아 묶음에 한 개 더, 묶음이 64개면 빈 칸에 새 묶음), Clear selected(선택 칸 비우기)가 있다.

- 칸 버튼 27개(0~26번)와 아이템 칸 27개(30~56번)가 같은 자리에 겹친다. 선택은 칸 이름 하나(`none`, `s0`~`s26`)로 넘긴다.
- 확인한 것: 테스터, 모의(v1.4.0).

### 4.2 ShopCard

상품 카드 셋(Apple 2, Ender Pearl 8, Diamond 25 coins)이다. 카드마다 아이콘, 이름, 값, 수량 스테퍼(1~16), 합계, Buy가 있다. 위에 코인 잔액(처음 50)과 Earn 10이 있다.

- 카드 아이콘은 수량만큼의 진짜 아이템이라 수량이 아이콘의 개수로도 보인다.
- 서버가 잔액을 들고 구매마다 확인한다. 모자라면 빨간 실패 글을, 사면 초록 글을 쓴다.
- 확인한 것: 테스터, 모의(v1.4.0).

### 4.3 RecipeView

3x3 재료 아이콘, 화살표, 결과 아이콘(개수 포함)이다. 조합법 다섯 개(Crafting Table, Stick, Torch, Chest, Iron Pickaxe)를 Prev와 Next로 넘기고, 아래에 쓰는 재료 수가 나온다.

- 확인한 것: 테스터, 모의(v1.4.0).

### 4.4 PlayerCard

보는 플레이어의 살아 있는 모습, 이름, 상태 점(Online, Away, Busy), 레벨 줄, Activity 줄과 Wave, Change status 버튼이다.

- 모습은 `live_horse_renderer` 하나가 그린다. 서버가 칸 이름에 큰따옴표로 감싼 플레이어 id(`"<id>"`)를 쓰고, 렌더러가 `(#hover_text - '§o' - '§f' - '§r')`를 `#entity_id`로 받는다([엔티티 인벤토리 문서 10.1절](./entity-inventory-ui.mdx#101-인형-그리기)).
- Wave는 `state.animation`에 애니메이션 id를 남기고, 틀이 `playAnimation`으로 플레이어 팔을 흔든다. 같은 방법은 인형 로비 예제에서 인형 칸에 보였다(실측, 엔티티 인벤토리 문서 10.3절).
- 글만 바꾸는 Wave 버튼이었을 때는 상태 줄과 횟수는 바뀌었지만 인형은 움직이지 않았다(실측, v1.4.2). `playAnimation`으로 바꾼 판(v1.4.3) 뒤로 이 페이지에서 팔이 움직였는지는 기록이 없다.
- Activity 제목은 레이어 합이 같은 바탕 위에 있어 레이어를 올렸다(v1.4.2, 1.4절).

### 4.5 PlayerList

로비 플레이어 8줄이다. 줄마다 이름, 역할 태그(Host, Member), 상태 배지(Ready, Waiting, AFK, Not in lobby), Kick 또는 Invite가 있다. 호스트 줄은 누를 수 없는 Kick 그림이다. 오른쪽에 "Ready x of y"와 마지막 동작이 나온다.

- 버튼은 호스트를 뺀 7개다. 줄마다 상태 칸(`ready`, `waiting`, `afk`, `out`)이 배지를, 버튼 종류 칸(`host`, `kick`, `invite`)이 버튼 그림을 고른다.
- 이름이 보이지 않았다(실측, v1.4.1). 이름 글자의 레이어를 올리자 보였다(실측, v1.4.2).

## 5. 서버가 줄을 계산하는 컴포넌트

줄 수가 바뀌는 목록은 UI가 줄을 만들지 않는다. 서버가 보일 줄을 계산해 고정된 줄 칸에 차례로 쓰고, 남는 줄에는 빈 값(`off`, `none`)을 쓴다.

### 5.1 Table

12명 순위표(Player, Kills, Deaths, Score)다. 머리글을 누르면 그 열로 정렬하고, 다시 누르면 방향을 바꾼다. 줄을 누르면 선택되고, 5줄씩 Prev와 Next로 넘긴다. 끝 쪽에서는 넘김 버튼이 누를 수 없는 그림이 된다.

- 서버가 정렬과 쪽 나눔을 하고 줄 칸 5개(셀 20칸, 줄 상태 5칸)에 쓴다. 정렬 열과 방향은 칸 이름 하나(`c3d` 등)로 넘겨 머리글의 화살표를 고른다.
- 줄 버튼은 칸 번호가 아니라 화면의 줄 자리다. 서버가 지금 보이는 목록에서 그 자리의 플레이어를 찾는다.
- 확인한 것: 테스터, 모의(v1.4.0).

### 5.2 TreeView

맨 위 노드 Worlds, Packs, options.txt를 포함한 3단계 노드 12개다. 화살표를 누르면 펼치고 접고, 이름을 누르면 선택한다. 오른쪽에 선택한 노드, 경로, 보이는 줄 수가 나온다.

- 서버가 펼친 노드를 따라 보일 줄을 계산해 줄 칸 12개에 쓴다. 줄마다 단계와 모양 키(`L<단계><c|o|l>`, 접힘, 펼침, 잎), 단계 키(`L<단계>`), 단계별 글 칸을 쓴다.
- 줄마다 단계별 버튼을 미리 놓고 단계 키로 하나만 보인다. 자식이 있을 수 있는 단계(0, 1)는 펼치기/접기 버튼과 선택 버튼, 마지막 단계는 선택 버튼만 있다. 버튼은 60개다.
- 접을 때 선택한 노드가 그 아래에 있으면 선택을 접은 노드로 옮긴다.
- 확인한 것: 테스터, 모의(v1.4.0).

### 5.3 Countdown

매 틱 줄어드는 MM:SS(처음 1분), Start, Pause, Reset, +30s(59:59까지), 101단계 막대, 0이 되면 깜빡이는 알림이다.

- 서버의 `tick`이 남은 틱을 하나씩 줄이고 시간 글을 쓴다. 막대는 폭 키(`w0`~`w100`)로 미리 만든 101가지 중 하나를 고른다.
- 알림은 키(`idle`/`up`)로 고르는 팩토리 칸이다. `up` 판에는 투명도 애니메이션 세 번이 이어져 있고, 키가 바뀌어 판이 새로 만들어질 때 처음부터 재생된다.
- 확인한 것: 테스터, 모의(v1.4.0).

## 6. PatternLock

3x3 점 칸에 막대기를 끌어 지나가며 그리는 잠금 패턴이다. 그린 순서가 점 위에 숫자로 나온다. 처음 그린 4점 이상을 저장하고, 다음부터는 같은 패턴인지 판정한다. Set / Unlock으로 모드를 바꾸고, Forget으로 저장을 지운다.

### 6.1 끌기 나눔으로 그리기

점 칸과 막대기 칸에는 칸 버튼 대신 바닐라 상자 칸 매핑을 단다(`button.container_take_all_place_all`, `button.container_take_half_place_one`, `button.coalesce_stack`, `button.shape_drawing`, `button.container_slot_hovered`). 막대기 칸에는 표시 막대기 64개를 둔다.

1. 막대기 칸을 탭해 막대기를 든다.
2. 손가락을 떼지 않고 점 칸 위를 끌고 지나간다. 엔진이 지나간 칸에 막대기를 나눠 놓는다.
3. 서버는 `sense`로 매 틱 점 칸의 표시 막대기 개수를 읽어, 개수가 늘어난 칸을 경로에 더한다.
4. 칸 변화가 20틱 동안 없으면 정착으로 보고 판정한다. 같은 점은 한 번만 센다.
5. 판정 뒤 서버는 점 칸을 비우고 막대기 칸을 64개로 다시 채우며, `collectMarkers`로 플레이어 인벤토리와 커서의 표시 막대기를 거둔다.

판정은 4점보다 적으면 "Too short", 저장 모드면 저장, 풀기 모드면 "Unlocked" 또는 "Wrong pattern"이다.

### 6.2 확인한 것

- 저장, "Wrong pattern", "Unlocked"이 맞게 나왔다(실측, v1.4.8). 판정은 정착 뒤에만 나오므로 정착 처리도 게임에서 지나간 것으로 본다(*추론*).
- 같은 끌기 방식을 시험한 DragLab에서, 막대기 칸을 탭한 뒤 끌면 서버가 지나간 칸을 거의 매 틱 차례로 받았다. 칸 11개를 지나자 칸마다 5개씩 놓이고 손에 9개가 남았다. 막대기 칸을 누른 채 바로 끌면 아무것도 놓이지 않았다. 이미 지나간 칸을 다시 지나도 바뀌지 않았다. 칸이 아닌 곳에서 멈추면 아이템을 쥔 상태가 남았다(실측, v1.4.5).
- 그래서 정착과 되돌리기를 서버가 스스로 한다. 끌기를 흉내 내고 25틱 기다리자 칸이 비고 막대기 64개가 돌아오고 플레이어 인벤토리의 표시 막대기가 지워졌다(모의, v1.4.6). 게임에서 커서의 표시 막대기가 거둬지는지는 기록이 없다.
- 끄는 도중에 서버가 막대기 칸을 다시 채우자 손에 쥔 상태가 풀려 끌기가 끊겼다(실측, v1.4.9). 칸을 비우기만 하면 막대기가 바닥난다(실측, v1.4.8). 그래서 한 번 끄는 동안 같은 칸을 다시 지나는 것은 서버가 알 수 없고, PatternLock은 점마다 한 번만 센다. 자세한 실험은 [인벤토리 UI로 슬라이더 구현하기](./inventory-ui-slider.mdx)에 있다.
- 테스터, 모의(v1.4.8): 1-2-3-6을 그리면 저장되고 점 위에 1, 2, 3, 4가 붙었다. 같은 패턴은 "Unlocked", 1-4-7-8은 "Wrong pattern", 두 점은 "Too short"였다.

## 7. 남은 것

- 실측은 모두 휴대폰이다. PC의 hover 모양(RadialMenu, 칸 버튼)과 마우스 끌기는 기록이 없다.
- TextInput, Keybinds, ColorPicker, Tutorial, 차트, 4장과 5장의 대부분은 테스터와 모의만 거쳤다. 게임에서 모양이 맞는지는 기록이 없다.
- 예제 애드온 자체는 게임에서 돌려 보지 않았다(*미검증*). IUC 시험 팩과는 이름, 식별자, 페이지 묶음(48개 중 17개)만 다르다.

## 8. 예제 애드온

<AddonDownload id="inventory-ui-enhanced-components" />

1. 파일을 열어 가져온다(모바일은 파일을 눌러 Minecraft로 연다). 새 월드에서 행동 팩 `[bedrock-research]inventory-ui-enhanced-components-bp`로 시작하는 팩을 켠다. 리소스 팩은 의존성으로 함께 켜지고 실험 토글은 필요 없다. 다른 엔티티 인벤토리 예제와 같은 월드에 켜도 된다([엔티티 인벤토리 문서 2.2.2절](./entity-inventory-ui.mdx#222-바닐라-숨기기예제-공통)).
2. 크리에이티브 인벤토리 아이템 분류의 맨 뒤에서 "Inventory UI Enhanced Components"(그림 아이콘)를 꺼낸다. `/give @s bwiki:inventory_ui_enhanced_components_test`를 써도 된다.
3. 아이템을 든 채 화면 가운데를 누르면 창이 열린다. 첫 페이지는 TextInput이다.
4. `<` `>`로 페이지를 넘기거나 Pages를 눌러 17개 중 하나를 고른다. 아래 줄에 서버가 마지막으로 처리한 누름이 나온다.
5. PatternLock 페이지에서는 왼쪽 막대기 칸을 한 번 탭해 들고, 떼지 않은 채 점을 지나간 뒤 손을 뗀다. 1초 뒤에 판정이 나온다. 다른 페이지에 갔다가 돌아오면 틀이 페이지 칸을 비우므로, 페이지의 `enter`가 막대기를 다시 채운다.

- 화면의 글은 영어다.
- 엔티티 이름은 `§b§w§i§u§e`, UI 네임스페이스는 `iuenh`다. 바닐라 숨기기는 다른 예제와 같은 표식 `entity_ui_hide_vanilla`와 속성 `#entity_ui_vanilla_visible`을 쓴다.
- `tools/`에 생성기가 있다. `node tools/gen-ui.mjs`가 `rp/ui/iuenh.json`을 다시 만들고, `node tools/check-page.mjs <key>`가 페이지의 버튼 목록과 칸 이름을 검사한다.
