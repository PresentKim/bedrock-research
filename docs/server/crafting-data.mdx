## 개념

클라이언트는 서버가 `CraftingData` 패킷으로 보낸 레시피만 안다(레시피 책과 조합 칸 결과). 서버는 BDS처럼 BP의 `recipes/*.json`을 읽어 보내거나, Dragonfly처럼 코드의 레시피 목록을 패킷으로 만들어 보낸다. 이 패킷은 `ClearRecipes` 플래그로 **언제든 다시 보내 목록을 통째로 바꿀 수 있어**, 게임 중에 레시피를 잠그고 여는 일이 가능하다. 클라이언트 레시피 책은 **창작 인벤토리 목록**(`CreativeContent` 패킷)에 있는 결과의 레시피만, 그것도 **블록 상태까지 같을 때만** 나열한다. (출처: 비공개 조사)

```text
서버 -> 클라이언트:  CraftingData { Recipes: [...], ClearRecipes: true }   // 목록 교체
서버 -> 클라이언트:  CreativeContent { Items: [...] }                       // 레시피 책이 보는 결과 목록
클라이언트 -> 서버:  ItemStackRequest ... CraftRecipe(networkID) / AutoCraftRecipe  // 레시피를 ID 로 고른다
```

## 플레이어별 레시피 잠금과 실시간 개방 (Dragonfly)

레시피를 잠갔다가 게임 중에 하나씩 열면, 연 레시피가 바로 레시피 책과 조합 칸에 나오게 할 수 있다.

- Dragonfly 는 접속 때 한 번 전체 목록을 보내고, 세션마다 `네트워크 ID -> 레시피` 표를 만들어 조합 요청(`CraftRecipe`·`AutoCraftRecipe`·대장장이·석재 절단기)을 그 표로만 받는다. 표에 없는 ID 는 동적 레시피(장식된 도자기)로 넘어가고 거기도 없으면 거절한다.
- 업스트림에는 플레이어별 필터가 없어 포크에서 세션에 더한다: 필터가 고른 레시피만 `CraftingData` 로 보내고 표에 넣는다. 네트워크 ID 는 전체 목록의 순번 그대로 두어 바뀌지 않게 한다. 필터를 바꾸면 바로 다시 보낸다. 필터가 있으면 동적 레시피는 막는다.
  - 따라서 잠긴 레시피는 레시피 책·조합 칸에 안 나오고, 패킷을 위조해도 서버가 거절한다.
- 결과 아이템 이름 단위로 열면 색·나무 종류 변형이 함께 열린다.

### 레시피 목록에 없는 것(따로 막아야 함)

- **화로·훈연기·용광로 굽기**: Dragonfly 는 레시피 목록이 아니라 아이템의 `Smeltable` 로 굽는다. 잠그려면 화로에 넣을 때·구울 때 검사를 따로 둔다.
- 커스텀 블록의 가공은 서버 코드이므로 그 코드에서 잠금 상태를 직접 본다.
- 양조(물약)는 목록에 있어 같이 잠긴다.

## 레시피 책과 창작 인벤토리

클라이언트 레시피 책은 **창작 인벤토리 목록**(`CreativeContent`)에 있는 결과의 레시피만, 그것도 **블록 상태까지** 같을 때만 나열한다.

- 커스텀 아이템·블록: 레시피 결과가 되는 것은 모두 창작 목록에 등록해야 레시피 책에 나온다. 레시피 결과가 모두 창작 목록에 있는지 검사하는 테스트를 두면 빠뜨림을 잡는다.
- 바닐라 블록: 바닐라 레시피 데이터(`crafting_data.nbt`)의 블록 결과는 창작 항목과 상태가 다른 것이 많다(상자·퇴비통 등 30여 종). 레시피 결과의 블록 런타임 ID 를 그 아이템의 창작 항목(항목이 하나뿐일 때)의 것으로 맞춰 보내면 나열된다.

## 업스트림 제작 처리에서 고칠 것 (Dragonfly)

- **모양 검사**: 업스트림은 클라이언트가 고른 레시피의 재료를 칸 위치와 상관없이 가져간다. 서버에서 제작 칸의 아이템이 레시피 모양(격자 안 어디든, 대칭은 허용할 때만)인지 검사해 아니면 거절한다. 좌우 대칭 배치를 막는 레시피는 클라이언트에 `AssumeSymmetry=false`를 보낸다.
- **레시피 캐시**: 레시피와 창작 데이터를 블록 레지스트리당 한 번만 만들어 공유하고 레시피 네트워크 ID를 고정한다(출처: 비공개 조사).

## BDS와 비교

BDS는 BP `recipes/*.json`(형식 `format_version`은 [../basics/format-version.mdx](../basics/format-version.mdx) 참고)을 읽어 클라이언트에 보내고 레시피 해금 조건을 manifest와 레시피 JSON으로 다룬다. 서버 코드로 레시피를 만드는 Dragonfly 계열에서는 위 필터 방식으로 플레이어별 해금을 직접 구현한다.

레시피 결과를 스폰 알로 만드는 BDS 쪽 기법: `"result":{"item":"minecraft:spawn_egg","data":"query.get_actor_info_id('type:id')"}`(출처: 비공개 조사).
