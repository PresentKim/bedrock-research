## 개념: BDS와 무엇이 다른가

BDS에서는 커스텀 블록·아이템·엔티티를 **BP JSON과 Script API**로 정의한다. Dragonfly(Go) 서버에는 BP와 Script API 실행기가 없다. 대신 **게임 로직은 서버 언어 코드**로 쓰고, 보이는 것(텍스처, 모델, 애니메이션, 사운드, 언어, 파티클, JSON UI)은 **리소스팩**에 둔다. 서버는 정의를 접속 때 클라이언트에 컴포넌트 형태로 전송한다. 즉 "애드온 = Go로 짠 게임 로직 + 리소스팩"이다. (출처: 비공개 조사)

| 구분 | BDS | Dragonfly 서버 |
|---|---|---|
| 리소스팩(텍스처, 모델, 애니메이션, 사운드, 언어, 파티클, JSON UI) | 클라이언트에 전송 | 그대로 사용 가능. 클라이언트에 전송되어 적용 |
| BP JSON(블록/아이템/엔티티 정의, 루트 테이블, 레시피, 스폰 규칙) | 서버가 실행 | 실행되지 않음. 같은 내용을 Go 코드로 정의 |
| Script API | 서버가 실행 | 실행되지 않음. Go 코드로 구현 |
| 커스텀 블록/아이템 정의 | BP JSON | Go 타입이 정의하고 서버가 컴포넌트를 클라이언트에 전송 |

| 애드온에서 하던 것 | Dragonfly에서 할 곳 |
|---|---|
| `blocks/*.json` | Go 블록 타입 |
| `items/*.json` | Go 아이템 타입 |
| `entities/*.json` (BP) | Go `EntityType`과 동작 코드 |
| `entity/*.entity.json` (RP), 모델, 애니메이션 | 리소스팩 |
| `loot_tables`, `recipes` | Go 데이터. 바닐라 레시피는 Dragonfly 내장 |
| Script API 이벤트 | Dragonfly 플레이어/월드 핸들러 |
| `ui/*.json`, `sounds`, `particles`, `texts` | 리소스팩 |

## 커스텀 블록

Go에서 `world.CustomBlock`을 구현하면 Dragonfly가 블록 정의를 클라이언트에 보낸다.

| 기능 | 지원 | 방법 |
|---|---|---|
| 텍스처(면별 포함), 렌더 방식 | 예 | `Properties().Textures` (`customblock.Material`) |
| 커스텀 모델(geometry) | 예 | `Properties().Geometry`에 식별자, `.geo.json`은 리소스팩 `models/blocks/` |
| 충돌/선택 박스, 회전·크기·이동 | 예 | `Properties()` |
| 상태별 외형(permutation) | 예 | `States()` / `Permutations()` 구현 |
| 빛 방출/차단, 채굴 시간, 마찰, 가연성 | 예 | `LightEmitter`, `BreakInfo` 등 인터페이스 구현 |
| 블록 엔티티 데이터, 매 틱 로직, 상호작용 | 예 | `NBTer`, `TickerBlock`, `Activatable` 등 |
| 위 목록에 없는 BP 블록 컴포넌트 | 제한 | Dragonfly 내부 패키지가 컴포넌트를 만들므로 확장하려면 포크 필요 |
| 클라이언트측 블록 애니메이션 | 제한 | 텍스처 flipbook만 가능. 모양이 움직이는 연출은 엔티티로 대체 |

블록 모델 파일은 리소스팩 `models/blocks/<이름>.geo.json`이다. 상자 면마다 16x16 텍스처의 (0,0)부터 면 크기만큼을 쓴다. 한 파일에 채움 단계별 geometry(`geometry.custom_<종류>_<0..8>`)를 여러 개 넣을 수 있고, 꽉 찬 블록은 바닐라 `minecraft:geometry.full_block`을 쓰므로 모델 파일이 없다. 블록 텍스처는 `textures/blocks/<이름>.png`와 `terrain_texture.json` 키(`custom_<이름>`)이고, 파일만 바꾸면 텍스처가 바뀐다. 빠진 파일과 키는 테스트가 잡는다.

### 블록 텍스처 애니메이션 (flipbook)

`textures/flipbook_textures.json`의 항목 하나가 `terrain_texture.json`의 타일 하나를 움직인다. 이미지는 세로 띠(폭 16, 높이 16 x 프레임 수)이고 `ticks_per_frame`, `frames`(순서 배열), `blend_frames`(기본 켬)를 준다. 커스텀 블록은 `material_instances`의 텍스처가 그 타일이면 다른 컴포넌트 없이 움직인다. 두 파일은 팩끼리 병합된다. 모든 블록이 같은 박자로 움직이고 켜고 끄기는 블록 상태 퍼뮤테이션으로 텍스처를 바꿔서 한다. 아이템 아이콘에서는 판에 따라 움직이지 않는다(출처: private-research; Bedrock Wiki blocks/flipbook-textures).

## 커스텀 아이템

- `world.CustomItem`(이름, 크리에이티브 분류) 구현과 `world.RegisterItem`. 아이콘은 리소스팩 `textures/item_texture.json`의 아이템 식별자 키로 찾는다.
- 내구도, 음식, 갑옷, 쿨다운, 투척물 등은 아이템이 해당 인터페이스를 구현하면 자동으로 컴포넌트가 붙는다.
- 텍스처는 리소스팩의 PNG다: `textures/items/<이름>.png`(`item_texture.json` 키는 아이템 식별자. 블록 아이템은 블록 모양으로 보이므로 아이콘이 없다), `textures/blocks/<이름>.png`.

## 커스텀 엔티티

- Go: `world.EntityType`(식별자 `custom:xxx`, 히트박스, NBT)을 만들고 서버 엔티티 레지스트리에 등록한다. 등록된 식별자는 접속 시 클라이언트로 전송된다(`AvailableActorIdentifiers`).
- RP: 같은 식별자로 클라이언트 엔티티 정의(`entity/*.entity.json`), 지오메트리, 텍스처, 애니메이션, 렌더 컨트롤러를 만든다.
- AI·이동·상호작용은 전부 Go로 구현한다.
- 엔티티가 `item.Carrier`를 구현하면 들고 있는 아이템이 클라이언트로 전송되고 지오메트리의 `rightItem` 본에 그려진다.
- 주의: 지오메트리를 바꿔도 팩 버전이 같으면 클라이언트가 캐시를 쓴다. 팩 버전을 내용 해시로 자동 계산해 해결한다([resource-pack-delivery.mdx](resource-pack-delivery.mdx)).

## 클라이언트 컴포넌트 더하기 (접속 때 항목 고치기)

Dragonfly가 만드는 커스텀 아이템·블록 항목에는 Dragonfly가 아는 컴포넌트만 들어간다. 다른 BP 컴포넌트를 더하려면 접속 때 클라이언트로 가는 항목(아이템 목록과 블록 항목)을 패킷 훅에서 고친다. 아이템이나 블록이 인터페이스를 구현하면 그 값을 읽어 컴포넌트를 더하는 식으로 만들면 게임 코드가 Dragonfly 내부를 몰라도 된다. (출처: 비공개 조사)

이렇게 더해 쓸 만한 것:

- 아이템: `minecraft:digger`(블록별·도구 태그별 캐기 속도), `minecraft:use_modifiers`, `minecraft:fuel`.
- 블록: `BreakInfo`의 도구 태그(`tag:...`)와 곡괭이 등급, 클릭을 서버로 보내는 상호작용 표시, 퍼뮤테이션별 충돌 상자와 지오메트리 뼈 보임, 재질의 렌더 방식 이름(예: `alpha_test` 대신 `alpha_test_single_sided`).
- 블록 속성은 이름 순으로 정렬한다. 클라이언트가 상태 번호를 매기는 순서와 맞추기 위해서다.

## 이름과 번역

- **이름은 번역 키로 보낸다.** 블록·아이템 이름은 클라이언트가 자기 언어로 바꾼다. 바닐라는 `tile.stone.name`, `item.stick.name` 같은 키이고, 커스텀 블록·아이템은 리소스팩 `texts/<언어>.lang`의 `item.<id>.name`, `tile.<id>.name`이다.
- **Dragonfly는 커스텀 아이템의 `minecraft:display_name`에 `Name()` 글자를 그대로 넣는다.** 그러면 모든 클라이언트에 그 언어 하나로 보인다. 언어별로 보이게 하려면 접속 때 보내는 아이템 목록에서 그 값을 번역 키 `item.<id>.name`으로 바꾼다.
- 커스텀 블록·아이템 이름은 쓰는 언어의 lang 파일과 `en_US.lang` **둘 다**에 둔다. `en_US.lang`은 클라이언트에서 다른 모든 언어의 대체다. 언어를 더하면 `texts/<코드>.lang`을 만들고 `languages.json`에 적는다.
- **서버가 보내는 글(메시지, 폼, 사이드바) 속 이름은 서버가 플레이어 언어로 바꿔야 한다.** 커스텀 것은 서버가 시작할 때 팩의 `texts/*.lang`을 읽어 쓰고, 바닐라 것은 `bedrock-samples`의 `resource_pack/texts/*.lang`에서 만든 표를 쓴다(아래 "구형 번역 키"). 게임 버전을 올리면 최신 `bedrock-samples`로 표를 다시 만든다.

## 리소스팩 운영 규칙

Dragonfly는 BP 역할만 한다. 자동 팩 생성(커스텀 블록·아이템의 텍스처/모델/이름으로 서버 시작 시 생성)은 끄고(`DisableResourceBuilding`) 손으로 쓴 리소스팩을 쓴다. 팩만 따로 고쳐 시험하기 쉽고 Blockbench로 모델을 바로 열 수 있다. 리소스팩에는 블록·아이템 텍스처와 아틀라스, 블록 모델, 이름(`texts/ko_KR.lang`, `en_US.lang`: `item.<id>.name`, `tile.<id>.name`), 엔티티 모델, 애니메이션, 사운드, JSON UI, 파티클을 둔다.

- 식별자 네임스페이스는 하나(`custom:`)로 통일한다.
- 서버 코드가 이름으로 가리키는 것(모델 식별자, 재질 텍스처 키, 아이템 아이콘, 이름 줄)은 테스트가 팩에 있는지 확인한다. 아이템 이름은 Go `Name()`과 lang 줄이 같아야 한다.
- Dragonfly에 없는 바닐라 블록: 피스톤, 관측기, 공급기, 발사기, 중계기, 비교 회로. 있는 것은 호퍼, 상자, 화로, 레드스톤 가루·횃불·레버 등 일부다. 없는 장치가 필요하면 커스텀 블록으로 만든다.

## UI 수단

| 방식 | 용도 |
|---|---|
| Ore UI DDUI 화면 | 메뉴, 설정. 팩의 `hbui/`가 게임 중 Ore UI 페이지를 바꾼다 |
| JSON UI로 폼 꾸미기 | RP의 `ui/server_form.json` 등을 고쳐 메뉴를 게임 UI처럼 표현. 폼 제목에 표식을 넣어 화면별 레이아웃을 고르는 방식이 일반적 |
| 상자형 인벤토리 UI | 인벤토리 보기, 블록 작업 창. 보이지 않는 엔티티를 상자로 연다([fake-blocks-and-chunks.mdx](fake-blocks-and-chunks.mdx)) |
| 사이드바, 보스바, 타이틀, 액션바 | 퀘스트 창과 HUD. Dragonfly API가 지원 |

## 클라이언트 표시에서 확인된 것 (서버 개발 기록)



- **번역 키를 아이템 이름에** [실측]: 아이템의 커스텀 이름과 설명(lore)에 번역 키를 넣으면 클라이언트 툴팁에 글자 그대로 보였다. `item.diamond.name`, `%item.diamond.name`, `%item.diamond.name%` 모두, 한 줄 전체로 넣어도 글 중간에 넣어도 같았다(1.26.50).
- **구형 번역 키** [기록]: 많은 블록은 `tile.<현대 ID>.name`으로 이름을 찾지 못한다. 이름은 구형 키에 있다(`oak_planks`는 `tile.planks.oak.name`, `oak_sapling`은 `tile.sapling.oak.name`). 그냥 보내면 키 글자나 식별자가 보인다. `bedrock-samples`의 `en_US.lang`에서 ID를 제목 형태("Oak Planks")로 바꿔 영어 값과 짝지으면 표를 만들 수 있고, 약 190개(교육판·테스트 블록·`element_*` 등)는 짝이 없다.
- **언어 대체** [기록]: 클라이언트에서 `en_US.lang`은 다른 모든 언어의 대체다. 팩의 블록·아이템 이름은 `en_US.lang`에도 둔다.
- **손에 쥐는 모양** [기록]: 막대기와 뼈는 3인칭 손에서 도구처럼 쥐는 모양으로 그려지지만 바닐라 데이터에 `minecraft:hand_equipped`가 없다(`component_based` 0). 클라이언트 코드에 박혀 있다. 데이터(`vanilla_items.nbt`, `bedrock-samples` `behavior_pack/items`)에서 이 구성 요소가 참인 것은 `breeze_rod`와 창(`*_spear`)뿐이다.
- **블록 앞에 아이템 보이기** [기록]: 아이템 엔티티는 클라이언트에서 늘 돌고 흔들리며, 가까운 같은 아이템과 합쳐지고, 아래 호퍼에 빨려 든다. 대신 아이템을 손에 든 커스텀 엔티티(`MobEquipment`, `enable_attachables`)를 쓴다.
  - 본 구조는 `root > body > rightarm > rightitem_pose > rightitem_handheld > rightitem`, `body > leftarm > leftitem`이다. 3인칭 손 자세를 상쇄하는 값은 `rightitem_pose` pivot [-1, -6, -6], rotation [-75, -12, -16], `leftitem` pivot [5.5, 1, -3], rotation [-20, 45, 0]이다(Storage Drawers Bedrock 애드온 참고).
  - 엔티티에서 `query.is_item_name_any('slot.weapon.mainhand', 0, ...)`로 주 손 아이템을 보고 손에 쥐는 모양 아이템만 따로 돌려 보정할 수 있다. 3인칭 아이템 변환 값은 공개 자료에 없어, 막대기는 크기 0.65가 맞았다.
  - 클라이언트 엔티티 텍스처는 아이템마다 고를 수 없다(렌더 컨트롤러 배열과 변형 값이 아이템 수만큼 필요).
  - 꽉 찬 큐브 블록은 손에서 입체로 그려져 각도가 다르다. 큐브 블록은 보조 손, 그 밖은 주 손에 쥐여 맞췄다.
- **부수기 균열과 파편** [기록]: 클라이언트는 부수기 균열과 파편을 블록 지오메트리 큐브 위에 그린다. 큐브가 작거나 투명하면 보이지 않고, 파편은 텍스처 픽셀에서 색을 딴다.
- **블록 아이템 그림** [기록]: 블록 아이템은 인벤토리·폼에서 블록 모양 그대로 그려지고, 칸에 꽉 차게 키워진다. 9/16 크기로 보이게 하려면 투명한 16픽셀 틀 큐브 안에 넣는다. 인벤토리에서는 남쪽 면이 보이므로 정면을 남쪽에 둔다. 아이템 아이콘 텍스처는 따로 없어도 된다.
- **블록 상태 순서** [기록]: 클라이언트는 블록 런타임 ID를 블록 상태 순서대로 짝짓는다. 상태를 하나로 합쳐 번호로 담으면 서버와 순서가 어긋날 일이 없다.
- **엔티티 모델 방향** [기록]: 엔티티 모델은 월드와 반 바퀴 돌아 그려진다(모델 앞면이 북쪽). 월드 좌표를 모델 좌표로 옮길 때 z 부호만 바꾸고 x는 그대로 둔다.
- **블록 텍스처 애니메이션** [문서, 기록]: `textures/flipbook_textures.json`의 항목 하나가 `terrain_texture.json`의 타일 하나를 움직인다. 이미지는 세로 띠(폭 16, 높이 16 × 프레임 수)이고 `ticks_per_frame`, `frames`(순서 배열), `blend_frames`(기본 켬)를 준다. 커스텀 블록은 `material_instances`의 텍스처가 그 타일이면 다른 컴포넌트 없이 움직인다. 두 파일은 팩끼리 병합된다. 모든 블록이 같은 박자로 움직이고, 켜고 끄기는 블록 상태 퍼뮤테이션으로 텍스처를 바꿔서 한다. 아이템 아이콘에서는 판에 따라 움직이지 않는다(Bedrock Wiki).
- **상호작용 블록** [기록]: 서버가 상호작용 블록(Dragonfly `Activatable`)으로 보낸 블록 위에서는 클라이언트가 든 블록을 놓는 것을 예측하지 않는다.
- **디버그 셰이프 글자 방향** [기록]: 디버그 셰이프의 `Rotation`은 [pitch, yaw, roll] 도 단위이고, yaw 0이면 북쪽에서 읽힌다. 엔티티 yaw(남 0, 북 180)와 기준이 달라 그대로 쓰면 남북이 뒤집힌다. 라디안 값을 넣으면 사실상 0도다.
