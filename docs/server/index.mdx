이 섹션은 서버 쪽을 다룬다. 공식 BDS 운영과 설정, 네트워크 프로토콜(RakNet, NetherNet), 서버가 리소스팩을 내려보내는 방법, BP 없이 서버 코드로 커스텀 블록·아이템·레시피를 정의하는 방식(Dragonfly 사례), 한 플레이어에게만 보내는 카메라·HUD·가짜 블록·청크, 서버 성능이 주제다. 클라이언트에서 도는 JSON UI와 Ore UI는 다른 섹션이 다루고, 여기서는 서버가 그 UI에 데이터를 싣는 통로를 설명한다.

[rendering/particles.mdx](../rendering/particles.mdx)의 `SpawnParticleEffect` 항목은 소프트웨어 이름 없이 "커스텀 서버"로 적혀 있어 표에 넣지 않았다.

Endstone과 LeviLamina는 BDS 위에서 돌므로 BDS 쪽 방법(Script API, `world_resource_packs.json`)이 그대로 적용된다. [server-software.mdx](server-software.mdx)가 Endstone을 "BDS 위에 Python/C++ 플러그인을 얹는 래퍼"로, LeviLamina를 "BDS 모드 로더이자 API"로 적고, 도입부에서 커스텀 소프트웨어 중 일부는 "BDS를 감싼다"고 적는다. 다만 같은 페이지에는 Endstone의 ScriptSDK가 `.whl` 플러그인을 필요로 하고 `config/commands.json`이 Endstone 0.10에서 동작하지 않았다는 기록이 있어, BDS 설정이 모두 그대로 통한다고 단정할 수는 없다.

PocketMine-MP와 Nukkit, PowerNukkitX는 위키에 전용 설명이 거의 없다. 다른 페이지가 비교나 예로 이름을 들 뿐이고, 표의 `언급` 칸이 그 전부다.

## 읽는 순서

BDS를 운영한다면 서버 소프트웨어, 성능, 팩 전달 순으로 읽는다. 커스텀 서버를 만든다면 프로토콜 기초부터 보고, 리소스팩 전달과 커스텀 콘텐츠로 넘어간다. 버전 체계와 팩 manifest는 기초 섹션에 있다.
