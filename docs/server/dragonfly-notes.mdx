## 개념

Dragonfly(df-mc, Go, MIT)는 Bedrock 서버 소프트웨어를 Go로 만들 수 있게 하는 라이브러리다. 프로토콜은 gophertunnel 위에서 처리한다. Dragonfly의 동작을 바꾸는 길은 두 가지다: Dragonfly를 포크해 패치하거나, 포크 없이 패킷과 세션에 훅을 다는 것이다. 이 페이지의 업스트림 동작은 Dragonfly master `1bf4e242`(v0.11.5 이후, 2026-10-24)에 1.26.60 지원 PR(gophertunnel v1.63.0)을 더한 커밋 `d86aefd9ff9b6a357d6dfadab2093af811545256` 기준이다. (출처: 비공개 조사)

## 층

| 층 | 하는 일 |
|---|---|
| Dragonfly 패치 | Dragonfly의 동작 자체(블록 규칙, 저장, 틱, 청크 전송, 월드 훅) |
| 패킷 훅 층 | 세션과 패킷에 닿는 훅. 서버가 클라이언트에 보내는 패킷을 가로채 고치고 세션의 비공개 메서드와 필드를 쓴다. Dragonfly 내부는 여기서만 건드린다 |
| 클라이언트 항목 층 | 클라이언트가 접속 때 받는 아이템·블록 항목에 더하는 컴포넌트. 공개 레지스트리만 쓰고 게임을 모른다 |
| 게임 | 아이템과 블록이 클라이언트 항목 층의 인터페이스를 구현한다 |

위에서 아래로 시도한다. 패킷을 가로채거나 세션 내부를 읽고 쓰는 것으로 되면 패킷 훅 층에 둔다. 클라이언트 쪽 컴포넌트만 더하면 되면 클라이언트 항목 층에 둔다. **Dragonfly의 동작 자체를 바꿔야 하거나, 패치 없이 같은 결과를 내는 것을 증명할 수 없을 때만 패치한다.** 패치한 곳에는 패치 표시 주석을 달고 패치 목록을 함께 고친다.

### 포크 없이 훅으로 하는 일

패킷을 가로채거나 세션 내부를 읽고 쓰기만 하면 되는 일은 `bedrock-gophers/inv` 방식을 쓴다: 리스너를 감싼 연결에서 패킷 훅, `go:linkname`으로 세션의 비공개 메서드, 리플렉션으로 비공개 필드. 엔티티 상자, 한 플레이어에게만 보내는 화면 조작(카메라, 시야각, HUD 숨김, 입력 잠금, 가짜 블록, 청크 중심, 제목)이 이렇게 된다. 훅이 이름으로 기대는 내부를 검사하는 테스트를 하나 두면 Dragonfly를 올린 뒤 깨지는 곳이 바로 보인다.

### 패치에 두는 것

- 저장, 청크 캐시, 틱 성능, 월드 트랜잭션의 panic 회복처럼 Dragonfly 안쪽의 일.
- 훅이 없는 곳에 훅을 다는 일(호퍼 이동 규칙 바꾸기, 블록이 바뀐 뒤 알림, 칼럼 로드·언로드 알림).
- 실제 클라이언트에서만 맞는지 볼 수 있는 일: 한 플레이어에게만 보이는 청크, `Activate` 뒤 재전송, 커스텀 블록의 서버 쪽 부수기, 잔디 퍼짐 검사.
- 같은 결과임을 증명할 수 없는 일: 블록 규칙(퇴비통, 나뭇잎), NetherNet 리스너 주소, 플레이어별 레시피 필터, 로딩 중 틱당 청크 수.

## 클라이언트 데이터 검증

서버를 실제 실행과 같은 방식으로 세워 가짜 클라이언트를 한 번 접속시키고, 받은 블록 항목·아이템 등록·제작 데이터·창작 목록을 항목마다 해시해 골든 파일과 맞추는 테스트를 둔다. 패치를 바꾸거나 Dragonfly를 올린 뒤 골든이 그대로면 클라이언트가 받는 데이터가 같다는 뜻이다. 골든 파일은 아이템 id 외에 아이템 **이름**으로 적은 것도 둔다. 커스텀 아이템의 id는 등록 순서라서 패키지 초기화 순서만 바뀌어도 id 기준 골든은 수백 줄이 바뀌지만 이름 기준 골든은 그대로다.

클라이언트 데이터를 옮기거나 패치를 바꾼 변경은 골든이 그대로여야 한다. 클라이언트가 받는 것을 바꾸려는 변경만 골든을 다시 기록한다. 항목을 읽는 코드가 기대와 다른 모양을 만나면 블록 이름을 담아 panic 하게 해 두면 Dragonfly를 올린 뒤 먼저 여기서 걸린다.

## 업스트림 동작과 고치는 방법

| 업스트림 동작 | 결과 | 고치는 방법 |
|---|---|---|
| 패킷 처리 오류로 세션이 끝나면 Debug 로그만 남기고 조용히 끊는다 | 원인을 찾기 어렵다 | ERROR 로그를 남기고 이유를 담은 Disconnect 를 보낸다 |
| 월드 트랜잭션(블록 틱, 이벤트·패킷 핸들러)의 panic 은 프로세스를 죽인다. `Do`/`DoAfter` 작업만 잡는다 | 월드 하나의 오류로 서버 전체가 멈춘다 | 트랜잭션 실행에서 panic 을 잡아 스택과 함께 ERROR 로그로 남기고 월드는 계속 돌린다 |
| 인벤토리 변경은 청크를 바뀜으로 표시하지 않는다 | 같은 청크에 다른 변경이 없으면 상자·통·호퍼·화로 내용이 저장되지 않는다 | 로드된 칼럼을 바뀜으로만 표시하는 함수(패킷·이웃 갱신 없음)를 두고 각 컨테이너의 `Inventory(tx, pos)` 와 불이 켜진 화로의 `Tick` 에서 부른다 |
| 블록 `Activate` 전에 읽은 손 아이템을 `Activate` 뒤에 되쓴다 | `Activate` 안에서 손 아이템을 받아 가는 블록에 넣은 아이템이 복사된다 | `Activate` 뒤 손 아이템을 다시 읽어 차감한다 |
| 블록 `Activate` 가 성공해도 주변 블록을 다시 보내지 않는다 | 클라이언트가 예측 설치한 블록이 유령으로 남는다 | `Activate` 성공 뒤 주변 블록을 다시 보낸다 |
| 실제 클라이언트는 커스텀 블록의 금 가기를 끝내도 파괴 동작을 보내지 않는다 | 커스텀 블록이 안 부서진다 | 부수기 시간이 지나면 서버가 직접 부순다. 같은 블록을 계속 캐는 동안(ContinueDestroyBlock 반복) 시작 시각은 유지한다 |
| 다 자란 작물을 캘 때 떨어지는 작물·씨앗이 다 자란 상태를 복사한다 | 심으면 바로 다 자란 작물이 된다 | 성장 0의 새 아이템을 떨어뜨린다 |
| 클라이언트가 고른 레시피의 재료를 칸 위치와 상관없이 가져간다 | 모양 레시피를 아무 배치로나 만들 수 있다 | 제작 칸의 아이템이 레시피 모양(격자 안 어디든, 대칭은 허용할 때만)이 아니면 거절한다. 좌우 대칭을 막는 레시피는 클라이언트에 `AssumeSymmetry=false` 로 보낸다 |
| 바닐라 레시피 데이터의 결과 블록 상태(상자 방향 등)가 창작 목록과 다를 수 있다 | 클라이언트 레시피 책은 결과가 창작 항목과 같을 때만 레시피를 나열하므로 일부 레시피가 안 보인다 | 레시피 결과의 블록 런타임 ID 를 그 아이템의 창작 항목(항목이 하나뿐일 때)과 같게 보낸다 |
| 잔디·균사체 퍼짐(`spreadDirt`)이 빛만 본다 | 빛을 막지 않는 커스텀 고체 블록 아래에서도 잔디가 남고 퍼진다 | 위에 꽉 찬 고체 블록(`model.Solid`)이 있으면 잔디를 흙으로 되돌리고 그런 흙으로는 퍼지지 않게 한다(바닐라와 같게) |
| NetherNet 리스너에 묶을 로컬 주소와 알릴 공개 주소를 따로 정하는 설정이 없다 | 1:1 NAT·터널 뒤 서버가 맞지 않는 주소를 알린다 | 리스너 설정에 로컬 주소(묶고 알리는 주소 하나)와 공개 주소(로컬 주소 대신 알리는 주소)를 더한다 |

## 포크에서 해 볼 수 있는 최적화

- 무작위·블록 엔티티 틱 대상 청크 목록을 캐시하고, 로더 추가·제거·이동, 청크 추가·삭제, `SetTickRange` 때만 다시 계산한다(안전망으로 100틱마다 강제 재계산). 블록 엔티티 위치 버퍼를 재사용한다.
- 증분 저장: 수정된 칼럼을 1초마다 최대 16개까지 오래된 순으로 저장해 저장 멈춤을 나눈다(`Save`/`Close` 는 전체 저장).
- 팔레트 항목 NBT 를 런타임 ID 별로 한 번만 인코딩해 재사용한다.
- LevelDB 에 값이 안 바뀐 `Put` 은 건너뛴다(키별 해시). 빈 서브청크는 지운다.
- 서브청크 네트워크 데이터를 칼럼 버전별로 캐시한다.
- 레시피·창작 데이터를 블록 레지스트리당 한 번만 만들어 공유한다.
- 클라이언트가 청크를 받는 중이면 틱마다 보내는 청크 수를 늘린다(4개에서 16개로).
- 날씨 패킷은 값이 바뀔 때만 보낸다.
- 표시용 엔티티처럼 저장하지 않는 임시 엔티티 종류를 두고, 그 엔티티는 칼럼을 수정됨으로 표시하지 않는다.
