## 개념

Dragonfly(df-mc, Go, MIT)는 Bedrock 서버 소프트웨어를 Go로 만들 수 있게 하는 라이브러리다. 프로토콜은 gophertunnel 위에서 처리한다. 이 페이지는 Dragonfly를 포크해 쓰는 한 Dragonfly 기반 서버(MIT)의 실제 운영 기록이다. 기준은 Dragonfly master `1bf4e242`(v0.11.5 이후, 2026-10-24)에 1.26.60 지원 PR(gophertunnel v1.63.0)을 더한 커밋 `d86aefd9ff9b6a357d6dfadab2093af811545256`이다. (출처: 비공개 조사)

## 층

| 층 | 하는 일 |
|---|---|
| Dragonfly 패치 | Dragonfly의 동작 자체(블록 규칙, 저장, 틱, 청크 전송, 월드 훅) |
| 패킷 훅 층 | 세션과 패킷에 닿는 훅. 서버가 클라이언트에 보내는 패킷을 가로채 고치고 세션의 비공개 메서드와 필드를 쓴다. Dragonfly 내부는 여기서만 건드린다 |
| `clientext` | 클라이언트가 접속 때 받는 아이템·블록 항목에 더하는 컴포넌트. 공개 레지스트리만 쓰고 게임을 모른다 |
| 게임 | 아이템과 블록이 `clientext`의 인터페이스를 구현한다 |

위에서 아래로 시도한다. 패킷을 가로채거나 세션 내부를 읽고 쓰는 것으로 되면 패킷 훅 층에 둔다. 클라이언트 쪽 컴포넌트만 더하면 되면 `clientext`에 둔다. **Dragonfly의 동작 자체를 바꿔야 하거나, 패치 없이 같은 결과를 내는 것을 증명할 수 없을 때만 패치한다.** 패치한 곳에는 패치 표시 주석을 달고 패치를 바꾸면 표를 함께 고친다.

### 왜 포크하는가

Dragonfly의 동작 자체(블록 규칙, 패킷 처리, 세션 기능)를 바꿔야 하는 곳만 패치한다. 패킷을 가로채거나 세션 내부를 읽고 쓰기만 하면 되는 일은 `bedrock-gophers/inv` 방식을 쓴다: 리스너를 감싼 연결에서 패킷 훅, `go:linkname`으로 세션의 비공개 메서드, 리플렉션으로 비공개 필드. 엔티티 상자, 한 플레이어에게만 보내는 화면 조작(카메라, 시야각, HUD 숨김, 입력 잠금, 가짜 블록, 청크 중심, 제목), `ForgetHiddenEntities`, 실험 설정(`SendBasicVoxelShapes`, `BlockActionDebug`)이 이렇게 동작한다. 패킷 훅 층이 이름으로 기대는 내부는 `TestInternals`가 검사한다(업그레이드 후 깨지면 여기서 보인다).

### 패치에 두는 것

- 저장, 청크 캐시, 틱 성능, 월드 트랜잭션의 panic 회복처럼 Dragonfly 안쪽의 일.
- 훅이 없는 곳에 훅을 다는 일(`HopperTransfer`, `BlockChangeHook`, `ColumnHandler`).
- 실제 클라이언트에서만 맞는지 볼 수 있는 일: 가짜 청크, `Activate` 뒤 두 번의 재전송, 커스텀 블록의 서버 쪽 부수기, 잔디 퍼짐 검사.
- 같은 결과임을 증명할 수 없는 일: 퇴비통 규칙, 나뭇잎, NetherNet `LocalIP`와 `PublicIP`, 레시피 필터, 창작 항목 맞춤, 로딩 중 틱당 청크 수, 값이 바뀔 때만 보내는 날씨 패킷.

## 클라이언트 데이터 검증

`TestWire`는 서버를 실제 실행과 같은 방식으로 세워 가짜 클라이언트를 한 번 접속시키고, 받은 블록 항목·아이템 등록·제작 데이터·창작 목록을 항목마다 해시해 골든 파일과 맞춘다. 접속을 흉내 내는 도구는 `hooktest`(`Join`, `Canon`, `CanonWith`, `Golden`)다. 골든 파일은 아이템 id 외에 아이템 **이름**으로 적은 것(`items.byname`, `recipes.byname`, `creative.byname`)도 있다. 커스텀 아이템의 id는 등록 순서라서 패키지 초기화 순서만 바뀌어도 id 기준 골든은 수백 줄이 바뀌지만 이름 기준 골든은 그대로다.

```sh
go test ./content/server/wire/                              # 골든과 비교
SERVER_GOLDEN=update go test ./content/server/wire/        # 골든 다시 기록
SERVER_GOLDEN_DUMP=/tmp/a go test ./content/server/wire/   # 항목마다 전체 글을 /tmp/a 에 씀
diff -r /tmp/a /tmp/b                                        # 두 트리의 덤프 비교
```

클라이언트 데이터를 옮기거나 패치를 바꾼 변경은 골든이 그대로여야 한다. 클라이언트가 받는 것을 바꾸려는 변경만 골든을 다시 기록하고 커밋 메시지에 이유를 쓴다. 항목의 모양이 기대와 다르면 `BlockEntry`가 블록 이름을 담아 panic 하므로 Dragonfly를 올린 뒤 먼저 여기서 걸린다.
