## 개념

서버는 접속 중에 **리소스팩을 클라이언트에 내려보낸다**. 클라이언트는 팩을 `UUID + 버전`으로 캐시하고, 이미 가진 UUID+버전의 팩은 서버가 다시 보내지 않는다. 그러므로 내용을 바꿨는데 `manifest.json`의 버전이 같으면 클라이언트는 바뀐 팩을 받지 못한다. 협상은 `ResourcePacksInfo`, `ResourcePackStack`, `ResourcePackClientResponse` 패킷으로 하고, 팩 데이터는 `ResourcePackDataInfo`와 `ResourcePackChunkData` 청크로 전달된다. BDS는 월드의 팩 목록(`world_resource_packs.json`)과 `texturepack-required`로, 커스텀 서버는 라이브러리 설정으로 이 단계를 맡는다. BDS 쪽 설정은 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다.

## gophertunnel의 전달 설정 (MIT)

gophertunnel `Listener`는 팩 데이터를 청크로 쪼개 보낸다. (출처: gophertunnel-repo, minecraft/resource_pack_delivery.go)

<Excerpt src="gophertunnel" title="resource_pack_delivery.go" path="minecraft/resource_pack_delivery.go">

```go
const (
	// DefaultResourcePackChunkSize is the size of a single chunk of data from a resource pack sent by a
	// Listener: 128 KiB.
	DefaultResourcePackChunkSize = 1024 * 128
	// DefaultResourcePackChunkSendDelay is the delay a Listener leaves between ResourcePackChunkData
	// packets, so slow clients are not flooded while downloading packs. Clients after 1.26.30 may fail
	// resource pack downloads when pack chunks are sent too aggressively.
	DefaultResourcePackChunkSendDelay = 200 * time.Millisecond
)
```

</Excerpt>

- `ResourcePackDeliveryConfig`의 `ChunkSize`(0이면 128KiB)와 `ChunkSendDelay`(0이면 200ms, 음수면 지연 없음)로 조절한다. 1.26.30 이후 클라이언트는 청크를 너무 공격적으로 보내면 다운로드에 실패할 수 있다.
- 팩 객체는 `Name`, `UUID`, `Version`, `Modules`, `Dependencies`, `HasScripts`, `HasBehaviours`, `HasTextures`, `HasWorldTemplate`, `DownloadURL`, `Checksum`, `Encrypted` 같은 메서드를 가진다(`resource.Pack`). `Pack.WithContentKey`로 암호화 팩의 콘텐츠 키를 준다.

## 서버 쪽 팩 가공

커스텀 서버는 리소스팩을 실행 파일에 넣고(Go라면 `go:embed`) 서버를 켤 때 클라이언트에 보낼 모양으로 가공할 수 있다. 소스 파일은 그대로 두고 임시 복사본만 바꾼다. (출처: 비공개 조사)

1. **버전**: 팩 내용 해시로 `manifest.json` 버전을 자동으로 정한다. 같은 내용이면 같은 버전이라 클라이언트 캐시가 유지되고, 바뀌면 버전이 바뀌어 다시 받는다. 암호화한다면 비밀값도 해시에 넣는다.
2. **JSON minify**: `.json`의 `//`·`/* */` 주석과 공백을 지운다(키 순서·문자열은 그대로). `manifest.json`은 건드리지 않는다. 주석을 지운 뒤에도 올바른 JSON이 아니면 서버를 켜지 않게 한다(그런 파일은 게임도 못 읽는다). JSON UI 파일에 주석이 많아 용량이 꽤 준다.
3. **암호화**: 바닐라 마켓 팩과 같은 방식이다. 게임은 게임 중 Ore UI 페이지를 암호화되었거나 `content.zipe`이 있는 팩에서만 가져간다. 그래서 암호화하지 않는 팩에도 빈 `content.zipe`을 넣어 보내야 팩의 DDUI·Ore UI 화면이 그대로 그려진다 `{실측}`.
   - 파일마다 32글자 키로 AES-256-CFB8(IV는 키 앞 16바이트)로 암호화한다. `manifest.json`·`pack_icon.png`는 그대로 둔다.
   - `contents.json`에 경로와 키를 적고(앞 256바이트는 머리: 버전 0, 매직 `FC B9 CF 9B`, 팩 UUID), 목록은 팩의 **콘텐츠 키**로 같은 방식으로 암호화한다. 콘텐츠 키는 접속할 때 서버가 클라이언트에 준다(gophertunnel `Pack.WithContentKey`).
   - 키를 서버 비밀값에서 HMAC으로 만들면 같은 내용이면 같은 키와 버전이 나온다. **비밀값을 잃거나 바꾸면 모든 팩의 키와 버전이 바뀌어 클라이언트가 팩을 다시 받는다.** 비밀값은 저장소에 넣지 않는다.
   - 형식은 커뮤니티 도구(`akmalfairuz/bedrockpack`, `EncryptMyPack`)와 같다.
4. **한계**: 암호화는 파일을 줍는 것을 번거롭게 할 뿐이다. 키를 클라이언트에 주므로 접속하는 클라이언트는 풀 수 있고 도구(`bedrockpack steal`)로 한 번에 풀린다. 실질적 보호가 아니라 억제다. 보이면 안 되는 것은 팩에 두지 않는다.

Dragonfly에서는 서버 설정 `Resources.Required = true`로 접속 시 팩 적용을 강제한다.

암호화 팩이 Ore UI 파일 조회에서 신뢰된다는 근거와 `content.zipe`의 정체는 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다(출처: repo-ore-ui-loading).

## 팩 암호화와 CDN (커뮤니티)

- **CDN(`cdn_config.json`)**: 클라이언트가 까다롭다. Content-Type은 zip(`application/zip`. GitHub Pages의 `application/x-zip-compressed`도 받는다)이어야 하고 `Content-Length` 헤더가 필수다. Cloudflare Workers 응답에 Content-Length가 없어 "loading resources"에서 무한 대기한 사례가 있다. BDS가 CDN 링크를 주려면 팩이 필수로 등록돼 있어야 한다(예: `system_resource_packs`의 uuid/version). system 폴더로는 바닐라 루트 테이블이나 crafting catalogue를 제대로 덮어쓰지 못하므로, 월드에 팩을 넣는 방법도 있다. Geyser도 원격 팩 URL을 지원한다: https://geysermc.org/wiki/geyser/packs *(확인됨)*
- **CDN 호스팅**: Cloudflare R2(무료 티어)를 쓰는 사례가 있다. BDS가 리소스 팩을 인식하지 않으면 `world_resource_packs.json`의 `pack_id`와 `version`부터 확인한다.
- **서버가 암호화한 팩과 Ore UI**: 서버가 암호화해 보낸 팩은 Ore UI가 그 팩의 `hbui/`를 불러오게 한다. gophertunnel에서는 `pack.WithContentKey(key)`로 키를 준다.
- **팩 암호화(EncryptMyPack 등)**: RP 전용이고 바닐라 BDS에서는 동작하지 않는다. PocketMine, Endstone, Dragonfly(Geyser 사용자에게 권장)나 BDS 앞 프록시가 필요하다. 복호화 키는 애드온이면 로컬에, 서버 팩이면 데이터 교환 중에 받는다. 스킨 팩은 키 하나를 공유한다.
- **오디오 제약**: 프로토콜상 미리 보낸 동적 RP로만 오디오를 낼 수 있다. 클라이언트 음악에는 `PlaySoundPacket`이 언급됐다.

### CDN 요약 예 (cdn_config.json)

```json
{ "<pack UUID>_<pack version>": "https://cdn.example.com/my_pack.zip" }
```

세부 요구(모든 비바닐라 RP를 정확한 버전으로 나열, 직접 링크, 올바른 `Content-Length`)는 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다.
