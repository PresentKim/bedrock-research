## 개념

서버는 접속 중에 **리소스팩을 클라이언트에 내려보낸다**. 클라이언트는 팩을 `UUID + 버전`으로 캐시하고, 이미 가진 UUID+버전의 팩은 서버가 다시 보내지 않는다. 그러므로 내용을 바꿨는데 `manifest.json`의 버전이 같으면 클라이언트는 바뀐 팩을 받지 못한다. 협상은 `ResourcePacksInfo`, `ResourcePackStack`, `ResourcePackClientResponse` 패킷으로 하고, 팩 데이터는 `ResourcePackDataInfo`와 `ResourcePackChunkData` 청크로 전달된다. BDS는 월드의 팩 목록(`world_resource_packs.json`)과 `texturepack-required`로, 커스텀 서버는 라이브러리 설정으로 이 단계를 맡는다. BDS 쪽 설정은 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다.

## gophertunnel의 전달 설정 (MIT)

gophertunnel `Listener`는 팩 데이터를 청크로 쪼개 보낸다. (출처: gophertunnel-repo, minecraft/resource_pack_delivery.go)

<Excerpt src="gophertunnel" title="resource_pack_delivery.go" path="minecraft/resource_pack_delivery.go">

```go
const (
	// DefaultResourcePackChunkSize is the size of a single chunk of data from a resource pack sent by a
	// Listener: 128 KiB.
	DefaultResourcePackChunkSize = 1024 * 128
	// DefaultResourcePackChunkSendDelay is the delay a Listener leaves between ResourcePackChunkData
	// packets, so slow clients are not flooded while downloading packs. Clients after 1.26.30 may fail
	// resource pack downloads when pack chunks are sent too aggressively.
	DefaultResourcePackChunkSendDelay = 200 * time.Millisecond
)
```

</Excerpt>

- `ResourcePackDeliveryConfig`의 `ChunkSize`(0이면 128KiB)와 `ChunkSendDelay`(0이면 200ms, 음수면 지연 없음)로 조절한다. 1.26.30 이후 클라이언트는 청크를 너무 공격적으로 보내면 다운로드에 실패할 수 있다.
- 팩 객체는 `Name`, `UUID`, `Version`, `Modules`, `Dependencies`, `HasScripts`, `HasBehaviours`, `HasTextures`, `HasWorldTemplate`, `DownloadURL`, `Checksum`, `Encrypted` 같은 메서드를 가진다(`resource.Pack`). `Pack.WithContentKey`로 암호화 팩의 콘텐츠 키를 준다.

## 서버 쪽 팩 가공

커스텀 서버는 리소스팩을 실행 파일에 넣고(Go라면 `go:embed`) 서버를 켤 때 클라이언트에 보낼 모양으로 가공할 수 있다. 소스 파일은 그대로 두고 임시 복사본만 바꾼다. (출처: 비공개 조사)

1. **버전**: 팩 내용 해시로 `manifest.json` 버전을 자동으로 정한다. 같은 내용이면 같은 버전이라 클라이언트 캐시가 유지되고, 바뀌면 버전이 바뀌어 다시 받는다. 암호화한다면 비밀값도 해시에 넣는다.
2. **JSON minify**: `.json`의 `//`·`/* */` 주석과 공백을 지운다(키 순서·문자열은 그대로). `manifest.json`은 건드리지 않는다. 주석을 지운 뒤에도 올바른 JSON이 아니면 서버를 켜지 않게 한다(그런 파일은 게임도 못 읽는다). JSON UI 파일에 주석이 많아 용량이 꽤 준다.
3. **암호화**: 바닐라 마켓 팩과 같은 방식이다. 26.63까지 게임은 게임 중 Ore UI 페이지를 암호화되었거나 `content.zipe`이 있는 팩에서만 가져갔다. 그래서 암호화하지 않는 팩에도 빈 `content.zipe`을 넣어 보내면 팩의 DDUI·Ore UI 화면이 그려졌다 `{실측}`. 26.64에서 Mojang이 보안 문제로 리소스팩의 Ore UI 접근을 막아, 지금은 암호화 팩과 `content.zipe` 팩 모두 Ore UI 페이지를 바꾸지 못한다(출처: 비공개 조사).
   - 파일마다 32글자 키로 AES-256-CFB8(IV는 키 앞 16바이트)로 암호화한다. `manifest.json`·`pack_icon.png`는 그대로 둔다.
   - `contents.json`에 경로와 키를 적고(앞 256바이트는 머리: 버전 0, 매직 `FC B9 CF 9B`, 팩 UUID), 목록은 팩의 **콘텐츠 키**로 같은 방식으로 암호화한다. 콘텐츠 키는 접속할 때 서버가 클라이언트에 준다(gophertunnel `Pack.WithContentKey`).
   - 키를 서버 비밀값에서 HMAC으로 만들면 같은 내용이면 같은 키와 버전이 나온다. **비밀값을 잃거나 바꾸면 모든 팩의 키와 버전이 바뀌어 클라이언트가 팩을 다시 받는다.** 비밀값은 저장소에 넣지 않는다.
   - 형식은 커뮤니티 도구(`akmalfairuz/bedrockpack`, `EncryptMyPack`)와 같다.
   - 암호화한 파일은 압축이 거의 되지 않아 암호화 팩의 전송 크기는 압축 전 크기에 가깝다 `{추론}`. 그래서 암호화 항목은 zip에 압축 없이(Store) 넣어도 손해가 없고, 암호화하지 않으면 Deflate가 큰 JSON을 잘 줄인다. 잰 값 `{실측}`: 주 팩이 최적화 전 암호화 없이 636 KB, 암호화 2,507 KB였고 최적화 뒤 554 KB와 846 KB였다. 팩 6개 합계는 암호화 없이 764 KB에서 666 KB, 암호화 2,961 KB에서 1,260 KB였다. zip 항목마다 머리가 약 150 B이므로 파일 수도 크기에 든다. 줄인 크기에 따른 접속 시간은 [performance.mdx](performance.mdx)의 "접속 시간 측정"에 있다.
4. **한계**: 암호화는 파일을 줍는 것을 번거롭게 할 뿐이다. 키를 클라이언트에 주므로 접속하는 클라이언트는 풀 수 있고 도구(`bedrockpack steal`)로 한 번에 풀린다. 실질적 보호가 아니라 억제다. 보이면 안 되는 것은 팩에 두지 않는다.

Dragonfly에서는 설정 파일용 `server.UserConfig`의 `Resources.Required = true`로 접속 시 팩 적용을 강제한다. 이 값은 코드용 `server.Config`의 `ResourcesRequired`로 옮겨지며, 두 이름은 같은 설정이다 `{코드}`([chest-ui.mdx](../server-ui/chest-ui.mdx)는 `ResourcesRequired`로 적는다).

### 예: 내장 팩을 내용 해시 버전으로 보내기 (Go)

`go:embed`로 실행 파일에 넣은 `pack/` 폴더를 서버를 켤 때 메모리에서 가공한다. 파일 이름과 내용의 SHA-256 앞 3바이트를 `manifest.json`의 `header.version`으로 쓰고(3바이트로 자르는 것은 이 예의 선택이다), 가공한 zip을 `resource.Read`로 읽는다. `NewServer`는 `Resources.Required`를 켜 Dragonfly 서버로 보낸다. `ListenConfig`는 gophertunnel `ListenConfig`로 직접 듣는 경우의 같은 설정이고, 청크 크기와 전송 지연에 기본값을 그대로 적었다.

```go
package packdelivery

import (
	"archive/zip"
	"bytes"
	"crypto/sha256"
	"embed"
	"encoding/json"
	"io/fs"
	"log/slog"
	"strings"

	"github.com/df-mc/dragonfly/server"
	"github.com/sandertv/gophertunnel/minecraft"
	"github.com/sandertv/gophertunnel/minecraft/resource"
)

//go:embed all:pack
var packFS embed.FS

func hashedPack() (*resource.Pack, error) {
	hash := sha256.New()
	files := map[string][]byte{}
	err := fs.WalkDir(packFS, "pack", func(path string, d fs.DirEntry, err error) error {
		if err != nil || d.IsDir() {
			return err
		}
		data, err := packFS.ReadFile(path)
		if err != nil {
			return err
		}
		name := strings.TrimPrefix(path, "pack/")
		files[name] = data
		hash.Write([]byte(name))
		hash.Write(data)
		return nil
	})
	if err != nil {
		return nil, err
	}

	var manifest map[string]any
	if err := json.Unmarshal(files["manifest.json"], &manifest); err != nil {
		return nil, err
	}
	sum := hash.Sum(nil)
	manifest["header"].(map[string]any)["version"] = []int{int(sum[0]), int(sum[1]), int(sum[2])}
	if files["manifest.json"], err = json.Marshal(manifest); err != nil {
		return nil, err
	}

	var archive bytes.Buffer
	zw := zip.NewWriter(&archive)
	for name, data := range files {
		w, err := zw.Create(name)
		if err != nil {
			return nil, err
		}
		if _, err := w.Write(data); err != nil {
			return nil, err
		}
	}
	if err := zw.Close(); err != nil {
		return nil, err
	}
	return resource.Read(&archive)
}

func NewServer(log *slog.Logger) (*server.Server, error) {
	pack, err := hashedPack()
	if err != nil {
		return nil, err
	}
	user := server.DefaultConfig()
	user.Resources.Required = true
	conf, err := user.Config(log)
	if err != nil {
		return nil, err
	}
	conf.Resources = append(conf.Resources, pack)
	return conf.New(), nil
}

func ListenConfig(pack *resource.Pack) minecraft.ListenConfig {
	return minecraft.ListenConfig{
		ResourcePacks:        []*resource.Pack{pack},
		TexturePacksRequired: true,
		ResourcePackDelivery: minecraft.ResourcePackDeliveryConfig{
			ChunkSize:      minecraft.DefaultResourcePackChunkSize,
			ChunkSendDelay: minecraft.DefaultResourcePackChunkSendDelay,
		},
	}
}
```

Dragonfly v0.11.7-0.20261107232451-0f9a3a573626과 gophertunnel v1.63.0에 대해 컴파일만 확인했고 게임에서 실행하지 않았다 `{코드}`. 그 Dragonfly의 `server.Config`는 듣기 설정을 만들 때 `ResourcePackDelivery`를 넘기지 않으므로 `NewServer`의 청크 전송 지연은 gophertunnel 기본값(200ms)이다 `{코드}`. `server.Config`에서 이 지연을 바꾸는 항목은 찾지 못했다. `Config.Listeners`에 위 `ListenConfig`로 만든 리스너를 꽂아 바꾸는 길이 있는지는 확인하지 않았다 `{실측 필요}`. 위 예의 버전 계산과 접속 시 팩 수락은 게임에서 확인하지 않았다 `{실측 필요}`.

26.63까지 암호화 팩이 Ore UI 파일 조회에서 신뢰되던 근거와 `content.zipe`의 정체는 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다(출처: repo-ore-ui-loading).

## 팩 암호화와 CDN (커뮤니티)

- **CDN(`cdn_config.json`)**: 클라이언트가 까다롭다. Content-Type은 zip(`application/zip`. GitHub Pages의 `application/x-zip-compressed`도 받는다)이어야 하고 `Content-Length` 헤더가 필수다. Cloudflare Workers 응답에 Content-Length가 없어 "loading resources"에서 무한 대기한 사례가 있다. BDS가 CDN 링크를 주려면 팩이 필수로 등록돼 있어야 한다(예: `system_resource_packs`의 uuid/version). system 폴더로는 바닐라 루트 테이블이나 crafting catalogue를 제대로 덮어쓰지 못하므로, 월드에 팩을 넣는 방법도 있다. Geyser도 원격 팩 URL을 지원한다: https://geysermc.org/wiki/geyser/packs *(확인됨)*
- **CDN 호스팅**: Cloudflare R2(무료 티어)를 쓰는 사례가 있다. BDS가 리소스 팩을 인식하지 않으면 `world_resource_packs.json`의 `pack_id`와 `version`부터 확인한다.
- **서버가 암호화한 팩과 Ore UI**: 26.63까지는 서버가 암호화해 보낸 팩이 Ore UI가 그 팩의 `hbui/`를 불러오게 했다. 26.64부터는 막혔다. gophertunnel에서는 `pack.WithContentKey(key)`로 키를 준다.
- **팩 암호화(EncryptMyPack 등)**: RP 전용이고 바닐라 BDS에서는 동작하지 않는다. PocketMine, Endstone, Dragonfly(Geyser 사용자에게 권장)나 BDS 앞 프록시가 필요하다. 복호화 키는 애드온이면 로컬에, 서버 팩이면 데이터 교환 중에 받는다. 스킨 팩은 키 하나를 공유한다.
- **오디오 제약**: 프로토콜상 미리 보낸 동적 RP로만 오디오를 낼 수 있다. 클라이언트 음악에는 `PlaySoundPacket`이 언급됐다.

### CDN 요약 예 (cdn_config.json)

```json
{ "<pack UUID>_<pack version>": "https://cdn.example.com/my_pack.zip" }
```

세부 요구(모든 비바닐라 RP를 정확한 버전으로 나열, 직접 링크, 올바른 `Content-Length`)는 [../basics/pack-delivery-and-encryption.mdx](../basics/pack-delivery-and-encryption.mdx)에 있다.
