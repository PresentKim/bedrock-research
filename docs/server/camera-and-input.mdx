## 개념

카메라, HUD 요소, 입력은 모두 **서버가 한 플레이어의 클라이언트에만 보내는 패킷**으로 조작한다. BDS에서는 `/camera` 명령과 Script API가 같은 일을 하고, 커스텀 서버에서는 패킷을 직접 보낸다. 월드는 바뀌지 않으므로 다른 플레이어에게는 영향이 없다. 아래 패킷은 gophertunnel(MIT)의 정의 기준이다. (출처: gophertunnel-repo, minecraft/protocol/packet)

## CameraInstruction 패킷

`CameraInstruction`은 필드가 모두 선택(Optional)이라 하나의 패킷에 여러 명령을 담을 수 있다.

| 필드 | 설명 |
|---|---|
| `Set` | 카메라를 지정한 프리셋으로 설정(위치, 회전, 이동 시간 등) |
| `Clear` | true면 모든 카메라 명령을 해제 |
| `Fade` | 화면을 지정한 색으로 페이드 |
| `Target` | 특정 엔티티를 겨냥 |
| `RemoveTarget` | true면 현재 겨냥 해제 |
| `FieldOfView` | 시야각 갱신 |
| `Spline` | 카메라가 따라갈 스플라인 경로 |
| `AttachToEntity` | 카메라를 붙일 엔티티 ID |
| `DetachFromEntity` | true면 현재 엔티티에서 분리 |

프리셋은 접속 때 `CameraPresets` 패킷으로 미리 알려 준다. 시작 시 자유 카메라 프리셋 하나를 보내 두고, 이후 `Set`으로 위치와 회전을 바꾸는 방식이 흔하다.

## SetHud와 UpdateClientInputLocks

```go
// HUD 요소를 숨기거나 되돌리기
&packet.SetHud{Elements: []int32{packet.HudElementHotBar, packet.HudElementHealth}, Visibility: packet.HudVisibilityHide}
// 입력 잠금: 플래그 조합, 0이면 모두 해제
&packet.UpdateClientInputLocks{Locks: packet.ClientInputLockCamera | packet.ClientInputLockMovement}
```

| HUD 요소 상수 | 순번 |
|---|---|
| `HudElementPaperDoll` | 0 |
| `HudElementArmour` | 1 |
| `HudElementToolTips` | 2 |
| `HudElementTouchControls` | 3 |
| `HudElementCrosshair` | 4 |
| `HudElementHotBar` | 5 |
| `HudElementHealth` | 6 |
| `HudElementProgressBar` | 7 |
| `HudElementHunger` | 8 |
| `HudElementAirBubbles` | 9 |
| `HudElementHorseHealth` | 10 |
| `HudElementStatusEffects` | 11 |
| `HudElementItemText` | 12 |

`Visibility`는 `HudVisibilityHide`(0)와 `HudVisibilityReset`(1)이다. 입력 잠금 플래그는 `ClientInputLockCamera`, `Movement`, `LateralMovement`, `Sneak`, `Jump`, `Mount`, `Dismount`, `MoveForward`, `MoveBackward`, `MoveLeft`, `MoveRight`(`1 << (iota+1)`부터 비트, 자리 하나는 비어 있다)다. **`SetHud`로 숨겨도 리소스팩이 HUD에 더한 요소(사이드바 등)는 남는다.**

## Dragonfly에서 한 플레이어 전용 화면 조작 (패킷 훅)

Dragonfly는 이런 API가 없어, 세션에 패킷을 보내는 훅을 만든다. 모두 한 플레이어의 클라이언트에만 보낸다. (출처: 비공개 조사)

| 하는 일 | 방법 |
|---|---|
| 카메라를 위치와 회전으로 옮기기 | 접속 때 보낸 자유 카메라 프리셋으로 `CameraInstruction.Set`(이징 시간 포함). 그동안 이동 키는 카메라 기준이다 |
| 카메라를 정상으로 | `CameraInstruction.Clear` |
| 시야각 바꾸기와 되돌리기 | `CameraInstruction.FieldOfView` |
| 바닐라 HUD 모두 숨기기 | `SetHud`에 모든 요소. 리소스팩 HUD 요소는 남는다 |
| 입력 잠금 | `UpdateClientInputLocks`, 0이면 해제 |
| 리소스팩 애니메이션을 자기 플레이어에게만 한 번 재생 | 그 클라이언트에만 `AnimateEntity`(스크립트 `playAnimation`과 비슷) |
| 어느 월드에도 없는 플레이어 모델 | [fake-blocks-and-chunks.mdx](fake-blocks-and-chunks.mdx) |
| 제목과 부제목 | 부제목을 제목보다 먼저 보낸다. 클라이언트는 부제목을 다음 제목과 함께 보여 주기 때문이다. raw JSON 제목으로 보내면 번역 키를 클라이언트가 자기 언어로 바꾼다 |

## 폼·HUD에서 더 본 것 (서버 개발 실측)

### 화면 호스트

- **폼 화면 애니메이션** [실측]: `third_party_server_screen`에 `"$screen_animations": []`, `"$background_animations": []`. 창이 움직이는 동안 다음 폼이 오면 두 창이 겹쳐 보였고, 닫고 다시 여는 폼이 깜빡였다.
- **폼 뒤 배경** [실측]: `third_party_server_screen`의 `$screen_bg_content`(안전 영역 밖, 화면 전환 때 밀리지 않음)를 바꿔 원하는 틀을 폼 뒤에 그린다. 거기의 `#title_text` 바인딩을 `once`로 두면 폼 내용이 오기 전에 평가돼 보이지 않았다.
- **사이드바 스코어보드를 HUD 채널로** [실측]: 목표 이름에 표식(`§d§h§u§d`), 줄마다 부분 표식(`§d§1`~`§d§4`)을 붙이고, `scoreboards.json`이 `scoreboard_sidebar`를 화면 전체 패널로 바꿔 부분마다 `scoreboard_players` 컬렉션 스택(`#scoreboard_sidebar_size`를 `#collection_length`로)으로 나눠 그린다. 같은 글자 줄은 클라이언트가 합치므로 뒤에 `§r`을 붙여 구분한다(최대 15줄). 타이틀과 서로 덮지 않는다.
- **HUD 숨김 중 폼** [실측]: 폼이 열려 있는 동안 HUD는 그려지지 않는다. 폼 뒤에도 같은 틀을 보이려면 폼 배경(`$screen_bg_content`)에도 그린다.


### 폼과 HUD 잡다한 사실


- **바닐라 확인 폼** [기록]: 모달 폼(`modal_form`)은 `server_form.json` 테마를 받지 않고 밝은 기본 창으로 떴다. 확인·취소는 액션 폼 두 버튼으로 보냈다.
- **격자 높이** [기록]: 격자 높이를 `#form_button_contents`나 `default`로 두면 버튼이 하나도 생기지 않았다. `100%c`로 둔다.
- **가로 스택의 `100%c`** [기록]: 가로 스택의 높이 `100%c`는 자식 높이를 모두 더해 탭 줄 아래에 큰 공백이 생겼다. 가장 큰 자식을 따르는 `100%cm`을 쓴다.
- **크기 배열 안의 숫자 변수** [기록]: `"size": [ "$w", "100%c" ]`처럼 배열 안에 숫자 변수를 두면 "Dangling number" 오류가 났다. 크기는 배열 전체를 변수로 준다(`"size": "$window_size"`).
- **입력 폼 글자** [기록]: 바닐라 입력 칸의 글자는 흰색이라 밝은 카드 위에서는 보이지 않는다.
- **숫자만 든 글** [기록]: 숫자로 읽히는 값(`" 219"`, `"1,532/4,096"`)은 라벨에 보이지 않았다. 색 코드로 시작하는 글로 보내거나 변수 식 안에서 `'§r' + 값`으로 문자열로 만든다. 숫자 한 글자 플래그도 숫자가 되어 글자 비교가 맞지 않으므로 플래그는 글자(`a`~`k`)로 쓴다.
- **변수 블록의 식** [기록]: 개수 식은 라벨 자신의 `variables` 블록에 두어야 계산됐다. 부모 패널 `variables`의 식이나 `text` 안의 `('§r' + $변수)`는 계산되지 않았다. 변수 블록의 식을 다른 식 안에서 쓴 것도 계산되지 않았다.
- **HUD 부제목으로 아이템 그리기** [기록]: 타이틀의 부제목에 아이템 런타임 ID × 65536을 실어 아이콘을 그릴 때, 바인딩 `#hud_subtitle_text_string`에서 칸을 꺼내면 어떤 식(자르기, 고정 폭, 더하고 빼기, 채움 글자 지우기)으로도 아이콘이 비었다. 제목 팩토리가 주는 변수 `$var_subtitle_text`에서 `'%.11s'`로 잘라 `property_bag`의 `#item_id_aux`에 넣으면 그려졌다. 부제목을 숫자만으로 보내면 바닐라의 블록 상태 칸 검사가 깨져 "expected a string" 경고가 났다.
- **토스트** [기록]: 클라이언트는 토스트를 하나씩 차례로 보여 준다. 폼이 열려 있어도 토스트는 보이고 다음 폼을 막지 않는다.
- **아이템 사용 반복** [기록]: 클라이언트는 사용 버튼을 누르고 있는 동안 아이템 사용 패킷을 반복해서 보낸다. 사용마다 폼을 보내면 같은 폼이 쌓여 하나를 닫을 때마다 다음 것이 뜬다.
- **`SetHud`로 숨긴 HUD** [기록]: 바닐라 HUD를 `SetHud`로 숨겨도 리소스팩이 HUD에 더한 요소는 남는다.
- **포켓 배치** [기록]: 터치 화면에서 UI 프로필이 포켓이면 바닐라 HUD가 `not_centered_gui_elements`로 하트를 왼쪽 위, 배고픔을 오른쪽 위에 그린다. `hud_screen.json`에서 그 판을 다시 정의해 클래식 터치 배치(`centered_gui_elements_at_bottom_middle_touch`와 같은 자리)로 옮길 수 있다.
- **화면 어둡게 하기** [기록]: 바닐라는 폼 뒤를 `screen_background` 투명도 0.4로 어둡게 한다.
- **빠른 이동 버튼** [기록]: 상자 창 옆에 보이는 버튼 하나와 그 밑에 칸 수만큼 보이지 않는 버튼을 겹쳐 두고, 각 버튼의 누름을 그 칸의 바닐라 빠른 이동(`button.container_auto_place`, `consume_event: false`)으로 바꾸면 클릭 한 번이 모든 칸의 쉬프트 클릭이 된다(Quick Container 팩의 기법). 서버에는 칸마다 평범한 아이템 이동 요청이 온다. 예제는 ../bedrock-core/samples/pack.chest.json에도 있다.
- **칸 장식(아이템 이름 속 표식)** [기록]: JSON UI는 칸의 아이템 데이터를 읽지 못하고 칸 컬렉션의 `#hover_text`(이름 + 설명)만 읽는다. 아이템 이름에 `§k§r§a`처럼 `§k` 뒤에 바로 `§r`을 둔 표식을 넣으면 화면에는 아무것도 남지 않고, 바인딩 `(not ((#hover_text - '표식') = #hover_text)) * 번호`를 더해 번호를 만들어 텍스처를 고를 수 있다.
  - 칸 템플릿은 두 곳을 고친다: `container_item`(`ui_common.json`, 상자 등)과 `inventory_container_item`(`inventory_screen.json`, 가방·조합 칸). 뒤쪽은 따로 `controls`를 가져 앞쪽 수정이 미치지 않는다. 층은 칸 배경 1, 아이템 7이라 뒤 장식은 6, 앞 장식은 9에 둔다.
  - PC의 호버 상자는 엔진이 그려 틀을 바꿀 수 없다. 터치 UI의 선택 아이템 말풍선(`item_panel_image`)에는 위에 겹쳐 그릴 수 있다.
  - 표식의 색 코드는 뒤의 글에 이어지므로 표식이 든 이름을 문장 중간에 넣으면 색이 번진다.
