## 개념

클라이언트는 서버가 보낸 블록 갱신(`UpdateBlock`)과 청크(`LevelChunk`, `SubChunk`) 패킷을 그대로 그린다. 그래서 서버는 **월드를 바꾸지 않고 한 플레이어에게만 다른 블록이나 청크를 보내** 그 사람에게만 다른 풍경을 보일 수 있다. 이를 가짜 블록, 가짜 청크라 부른다. 되돌리려면 진짜 값을 같은 방식으로 다시 보낸다. 이 방법은 지도 보기, 미리보기, 클라이언트가 예측해 그린 유령 블록 바로잡기에 쓴다. (출처: 비공개 조사)

## 가짜 블록 (`ViewFakeBlock`)

한 Dragonfly 기반 서버의 패킷 훅의 함수다.

```go
hook.ViewFakeBlock(p, pos, b)              // p 에게만 pos 에 b 를 보인다. 월드는 그대로
hook.ViewFakeBlockLayer(p, pos, b, layer)  // 0 블록 층, 1 액체 층. 블록 엔티티 데이터 없음
hook.ViewFakeBlock(p, pos, tx.Block(pos))  // 진짜 블록을 보내 되돌린다
```

- 놓이지 않았을 때 클라이언트가 예측해 그린 블록은 `ViewFakeBlock`으로 바로잡는다. Dragonfly 패치는 블록 `Activate`에 성공한 뒤 주변 블록을 다시 보내 클라이언트가 예측 설치한 유령 블록을 지우고, 두 번 재전송한다.
- 서버가 상호작용 블록(Dragonfly `Activatable`)으로 보낸 블록 위에서는 클라이언트가 든 블록을 놓는 것을 예측하지 않는다.

## 가짜 청크 (`ViewFakeChunk`)

Dragonfly 패치 `ViewFakeChunk`/`ClearFakeChunk`는 **그 플레이어에게만 보이는 청크**를 만든다. 그동안 그 청크의 월드 블록 갱신은 그 플레이어에게 보내지 않고, 청크 재전송이나 서브청크 요청은 가짜 청크로 응답한다(가짜 청크는 서브청크 캐시를 거치지 않는다). `ViewChunkCentre(p, pos)`는 클라이언트가 플레이어가 아니라 `pos` 주변 청크를 유지하고 그리게 한다(다음에 다른 청크로 움직일 때까지). 텔레포트 직후 가짜 청크를 보일 때 필요하다. 클라이언트 청크 중심 밖의 청크는 버려지기 때문이다. SubChunk 요청 프로토콜은 [protocol-basics.mdx](protocol-basics.mdx)에 있다.

### 예: 섬 확장 지도

섬을 멀리 떨어진 곳(x, z 약 +30000)에 지도처럼 보인다. (출처: 비공개 조사)

1. 커서 주변 청크마다 각 칸의 가장 위 블록만 섬 표면 바로 아래로 눌러 담고 그 위에 유리를 깐 가짜 청크를 그 플레이어에게만 보낸다.
2. 몸도 지도로 옮겨 카메라 4칸 위에 고정한다. 카메라는 시야각 30도로 좁히고 65칸 위에서 내려다본다([camera-and-input.mdx](camera-and-input.mdx)).
3. 끝나면 몸과 시야각을 되돌린다(나갈 때도 저장 전에 돌아간다).
4. 맨 위 블록이 꽉 찬 불투명 블록이 아니면 그 아래 첫 블록도 한 칸 아래에 함께 깐다(2층). 커서는 섬 끝까지 갈 수 있다. 지도를 누르면 그 청크를 다시 보낸다.

이 가짜 청크는 실기 확인 항목이었다: 지도가 제대로 그려지는지, 닫으면 실제 월드가 돌아오는지, 그동안 월드 블록 변화가 지도에 끼지 않는지.

## 한 플레이어에게만 보이는 엔티티

`ViewFakePlayer`는 어느 월드에도 없는 플레이어 모델을 한 클라이언트에만 보인다. 스킨은 모델이 추가된 동안만 플레이어 목록에 올렸다가 지워 목록에는 새 사람이 보이지 않는다. 같은 런타임 ID의 모델은 먼저 제거된다. `RemoveFakeEntity`로 지운다. `ForgetHiddenEntities`는 플레이어가 월드를 떠나기 직전에 숨겼던 엔티티를 이후 다시 보이게 한다(바로 생성하지는 않고, 새 월드가 청크가 오는 대로 자기 엔티티를 보인다. 플레이어의 트랜잭션 안에서 실행해야 한다). 글자는 `minecraft:falling_block`으로 보내는 떠 있는 글자(변형이 없으면 공기 블록 지정)가 이렇게 동작한다.

## 엔티티 상자: 칸 수를 고른 상자 창

PocketMine의 CustomSizedInvMenu, Muqsit/InvMenu, bedrock-gophers/inv와 같은 방식이다. 서버 구현에서 기대는 클라이언트 동작만 적는다. (출처: 비공개 조사)

PocketMine 의 CustomSizedInvMenu, Muqsit/InvMenu, bedrock-gophers/inv와 같은 방식이다. 서버 구현에서 기대는 클라이언트 동작만 적는다 [기록].

- 보이지 않는 클라이언트 전용 엔티티를 `AddActor`로 보낸다. 메타데이터는 투명·NoAI, `ContainerType` = INVENTORY(-1), `ContainerSize` = 칸 수, 이름 = 창 제목이다. 식별자는 접속 때 보내는 `AvailableActorIdentifiers`에 덧붙이면 되고 엔티티 정의 파일은 필요 없다.
- 이어서 `ContainerOpen`(`ContainerTypeContainer` + `ContainerEntityUniqueID`)과 내용물을 보내면 상자 창이 열린다.
- 엔티티 상자가 열린 동안 클라이언트는 폼이 닫히거나 블록 클릭과 겹칠 때 창 255 닫기를 보낸다. 서버는 이것을 무시해야 창이 유지된다.
- 클라이언트는 창이 닫히는 중에 온 열기를 무시한다. 창을 닫고 곧바로 다른 창을 열 때는 `NetworkStackLatency` 왕복으로 닫기 처리를 확인한 뒤 연다.
- 플레이어가 움직여 엔티티와 멀어지면 클라이언트가 창을 닫는다. 엔티티를 플레이어에 탑승 링크로 붙이면 움직여도 닫히지 않는다.
- 이미 열린 창에 `ContainerOpen`이 또 오면 클라이언트는 `PacketViolationWarning`(type -1)으로 답한다.
- 리소스팩 tedo0627/InventoryUIResourcePack(MIT)은 제목 앞의 `§{줄 수 1~6}§{스크롤 0/1}`과 `§r` 9개를 읽어 창 크기를 정한다. 54칸을 넘으면 6줄 높이로 스크롤한다. 팩이 없으면 27칸 상자로만 보인다.


예: 패킷 순서

```text
1. AvailableActorIdentifiers 에 식별자를 덧붙여 접속 때 보냄 (엔티티 정의 파일 불필요)
2. AddActor { 투명, NoAI, ContainerType=INVENTORY(-1), ContainerSize=칸 수, 이름=창 제목 }
3. ContainerOpen { ContainerTypeContainer, ContainerEntityUniqueID }
4. 내용물(InventoryContent) 전송
5. 창을 닫고 곧바로 다른 창을 열 때는 NetworkStackLatency 왕복으로 닫기 처리를 확인한 뒤 연다
```

## 블록 상태 순서와 방향

- 클라이언트는 블록 런타임 ID를 **블록 상태 순서대로** 짝짓는다. 서버와 순서가 어긋나지 않게 상태를 하나로 합쳐 번호로 담았다. 속성은 이름 순으로 정렬한다(클라이언트가 상태 번호를 매기는 순서와 맞춘다). `block-network-ids-are-hashes`(BDS 기본 true)면 순번 대신 안정된 해시 ID를 쓴다.
- 엔티티 모델은 월드와 반 바퀴 돌아 그려진다(모델 앞면이 북쪽). 월드 좌표를 모델 좌표로 옮길 때 z 부호만 바꾸고 x는 그대로 둔다.
- 디버그 셰이프의 `Rotation`은 [pitch, yaw, roll] 도 단위이고 yaw 0이면 북쪽에서 읽힌다. 엔티티 yaw(남 0, 북 180)와 기준이 달라 그대로 쓰면 남북이 뒤집힌다. 라디안 값을 넣으면 사실상 0도다.
