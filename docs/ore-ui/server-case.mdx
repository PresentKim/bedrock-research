# 한 Dragonfly 기반 서버 적용 사례

한 Dragonfly 기반 서버는 섬과 로비의 메뉴를 모두 게임의 Ore UI에 그린 서버 주도 DDUI 화면으로 만든다. 서버는 화면 이름과 데이터만 보내고, 레이아웃은 `web/oreui`의 React 페이지가 정한다. 앞 페이지들의 실험을 제품 수준으로 옮긴 사례이며 한 Dragonfly 기반 서버 문서 비공개 조사가 근거다. JSON UI는 HUD와 창고 창에만 남는다. (출처: 비공개 조사)

## 1. 구조

- `web/oreui`: React 18 + react-facet 페이지(TypeScript). 컴포넌트는 ore-ui-react(고정한 커밋)와 `@react-facet/dom-fiber` 위에 짠다. 폴더 구성: `src/runtime`(엔진 쿼리·명령, 이벤트 보내기, 설정 유지), `src/screens`(화면마다 하나), `src/components`(창·버튼·칸·스크롤·캔버스·입력칸), `src/text`(§ 색 코드와 클라이언트 표식), `src/interact`(누름, 툴팁, 키보드), `src/app.css`(새 CSS는 여기에만). 모양은 변하지 않은 `oui-ddui.css`와 `oui-mc.css`가 정한다.
- 데이터 계약: TypeScript 타입은 `web/oreui/src/protocol.ts`에 있고, Go 쪽은 `common/ui`의 화면별 `이름Data` 구조체가 같은 JSON 이름을 쓴다. 서버가 보내는 루트는 `{screen, data, keys?, lobby?, debug?}`다.
- 화면 이름: `menu`, `cards`, `pick`, `result`, `equip`, `grid`, `board`, `sieve`, `split`, `search`, `listsplit`, `input`, `slotmenu`, `choice`, `sides`, `plane`, `quest`, `home`, `loading`, `console`, `probe`, `inventory`. 이름은 `src/screens/registry.ts`에서 컴포넌트로 이어진다. `pick`(창 없이 어두운 화면 위에 희귀도 색 테두리의 큰 카드가 차례로 올라온다. 마우스, 숫자 키·방향키·WASD로 고른 카드는 떠오르며 빛나고 같은 숫자·Enter·Space로 정한다), `result`(제목·줄·별·보상이 CSS 애니메이션으로 차례로 나온다), `equip`(바닐라 인벤토리처럼 장비 칸 열과 빈 칸 실루엣, 아래 가방)은 `src/screens/showcase.tsx`에 있다.
- 리소스팩 `assets/resourcepack/oreui`: 게임 중 페이지 `hbui/gameplay.html`을 바꾼다. 바닐라 번들을 불러온 뒤 `oui-ddui.css`, `oui-mc.css`, `oui-app.css`, `oui-app.js`(지연 로드)를 더한다. 암호화하지 않은 팩에는 로더가 빈 `content.zipe`를 넣는다(`common/resourcepack`).
- `common/oreui`: DDUI 화면을 열고 루트를 데이터 저장소로 보내고 누름을 받는다. 클라이언트의 DDUI 패킷은 패킷 훅 층에서 가로챈다.
- `common/ui`: `Menu`(`Confirm`), `CardMenu`, `ItemBoard`, `SplitMenu`, `SieveBoard`, `ListSplitMenu`, `Input`, `ItemGrid`, `SearchGrid`, `SlotMenu`, `ChoiceMenu`, `SidesMenu`, `PlaneMenu`, `QuestBookMenu`, `HomeScreen`, `LoadingScreen`, `ConsoleScreen`, `ProbeScreen`이 화면 데이터를 만들어 `showScreen`으로 보낸다. 버튼의 `Run`은 그 플레이어 월드에서 돈다. 탭·뒤로·도움말·쪽 버튼은 라벨 앞 표식(`ui.Tab`, `ui.Back`, `ui.Help`, `ui.BarPager`)으로 창 위·컨트롤 막대에 놓이고 표식은 글에서 빠진다(`chromeOf`). 누름 뒤에 새 화면을 보이지 않으면 화면이 닫힌다(폼 버튼을 누르면 폼이 닫히는 것과 같다).
- 같은 폼의 새 루트가 오면 페이지는 React가 달라진 부분만 고치므로 창·스크롤 위치·입력칸 글·퀘스트 판의 끌기와 확대 배율·불러온 아이템 그림은 그대로다. 다른 폼의 루트는 새로 그린다.
- 누를 수 있는 요소에는 `data-oui-press` 속성이 있다(`src/interact/press.ts`). Gameface는 일반 `div`에 `click`을 보내지 않으므로 `mousedown`으로 누름을 받는다.

## 2. 패킷과 데이터 저장소

| 방향 | 패킷 | 쓰는 법 |
| --- | --- | --- |
| S to C | `ClientBoundDataDrivenUIShowScreen` | `ScreenID` `minecraft:custom_form`, `FormID`는 폼마다 새 번호, `DataInstanceID` 1 |
| S to C | `ClientBoundDataStore` | 저장소 `minecraft`의 `custom_form_data_1`(`oui`: 폼 번호, 루트, 설정)에 쓴다 |
| S to C | `ClientBoundDataDrivenUICloseScreen` | 화면 닫기 |
| C to S | `ServerBoundDataStore` | 페이지가 `oui_event`에 쓴 이벤트 |
| C to S | `ServerBoundDataDrivenScreenClosed` | 화면이 닫힘 |

- 시험 서버의 값 패치(`oui_vars_1_n`)와 달리 한 Dragonfly 기반 서버는 바뀔 때마다 같은 폼의 루트 전체를 새로 보내고 클라이언트는 가장 새 것을 쓴다. 모든 쓰기는 `Change`이고 `UpdateCount`는 서버 전체에서 하나씩 올린다. 경로 갱신 `Update`를 쓰려면 `PropertyUpdateCount`를 그 속성의 마지막 `Change.UpdateCount`와 같게 두고 `PathUpdateCount`만 올린다([DDUI 가이드](./ddui-server-guide.mdx)).
- 화면을 바꿔 열면 클라이언트는 앞 폼의 닫힘을 새 폼이 열린 뒤에 알리므로, 닫힘은 `FormID`가 지금 폼과 같을 때만 처리한다.
- 페이지는 Esc와 함께 휴대폰 뒤로 버튼으로 올 수 있는 키(Android `KEYCODE_BACK` 4, 브라우저 뒤로 166·`GoBack`·`BrowserBack`)를 닫기로 보낸다(`src/interact/keys.ts` `isBack`). 클라이언트가 화면을 스스로 닫으면 서버 로그(`ore ui screen closed by client`, `reason`)가 남는다. 숨긴 바닐라 폼(`custom_form` 루트)이 `oui_event` 밖의 경로에 쓰는 것은 로그(`ore ui vanilla form write`)에 남기고, 경로에 `close`가 들어 있으면 Esc로 받는다.
- 팩으로 할 수 없는 것: 바닐라 DDUI 레이아웃 바꾸기, 진짜 컨테이너를 Ore UI로 열기, HUD. 컨테이너 화면은 JSON UI로 꾸민다.

## 3. 화면 동작 규칙

- 창은 퀘스트 책까지 모두 바닐라 인벤토리 크기(326×166) 하나다. 그래서 한 화면에서 다른 화면으로 가는 누름은 열린 화면을 그 자리에서 바꾼다. 창 크기가 바뀌면 Gameface가 누름을 바뀌기 전 자리로 판정하므로 크기가 다른 창은 화면을 새로 연다(`showScreen`).
- 글 속의 클라이언트 표식(아이템 이름, 날짜)은 페이지가 클라이언트 언어로 바꿔 그린다(`src/text/localize.ts`). 창 위의 글은 어두운 변형 색으로 그린다(`src/text/Rich.tsx`의 `InkContext`).
- 터치 화면: 툴팁이 있는 요소를 탭하면 바로 눌리고 툴팁도 뜬다. 다른 곳을 탭하면 툴팁이 닫힌다. 툴팁이 이름뿐인 뒤로·쪽 넘김 버튼과 탭은 툴팁 없이 눌린다(`quick`). 툴팁은 오른쪽에 자리가 없으면 왼쪽에 뜨고 화면 밖으로 잘리지 않게 끌어온다(`src/interact/Tooltip.tsx`).
- 입력 화면(`ui.Input`): 창 안의 입력칸과 확인 버튼. 버튼을 누르면 입력칸 글이 함께 오고(이벤트의 `inputs`) Enter도 확인을 누른다.
- 소셜 화면(`ui.ListSplitMenu`): 아이콘 탭(이름은 툴팁), 왼쪽 판의 스크롤 줄, 오른쪽의 본문과 동작 버튼(첫 버튼은 전체 폭, 나머지는 두 칸씩). 확인 질문·친구 추가 입력도 같은 창에서 바뀐다.
- 선택 판(`ui.ChoiceMenu`): 위에 수치 판(`ui.Stat`)과 한 줄 메모, 아래에 갈래(`ui.ChoiceGroup`)마다 한 줄. 지금 것(`On`)은 초록 테두리로 눌리지 않고, 지금 못 하는 것(`Dim`)은 흐리다.
- 도감 검색 탭(`ui.SearchGrid`): 글을 치면 250ms 뒤 `change` 이벤트가 가고 서버가 새 루트를 보내므로 검색칸의 글과 커서가 남는다. 빈 검색에서는 즐겨찾기와 최근 본 아이템이 위에 나온다.
- 키보드: 화면이 받지 않는 방향키·WASD는 키보드 선택을 옮긴다. 누를 수 있는 요소 가운데 그 방향으로 가장 가까운 것이 마우스를 올린 것처럼 보이고(`oui-kb`), Enter·스페이스바가 그것을 누른다. 마우스를 움직이면 선택이 사라진다. 화면이 받는 키는 루트의 `keys`(`{up, down, left, right, ok: id}`)로 정하고 같은 키는 120ms에 한 번까지, 입력칸에 글을 칠 때는 받지 않는다.
- 아이템 도관 설정(`ui.SidesMenu`): 여섯 면의 카드를 세 장씩 두 줄로 놓는다. 채널은 아이템이 아닌 색 칸으로 그리고 색 네모를 우클릭하면 이전 값이 된다.
- 발전과제 퀘스트 책(`ui.QuestBookMenu`): 왼쪽은 챕터 목록(달성 수, 80u 폭), 오른쪽은 끌어서 움직이는 판 위의 노드와 선행마다 오는 꺾은선이다. 모양은 과제 마름모·연구 네모·도전 원이다. 판은 마우스 휠, 두 손가락 벌리기·오므리기, +·- 버튼으로 확대·축소(0.5~3배)한다. 판은 노드가 있는 곳까지만 끌린다(`src/components/Canvas.tsx` `clampPan`). 확대 배율과 끈 자리는 챕터마다 남는다.

### 인벤토리 화면(`ui.ShowInventory`)

서버가 바닐라 인벤토리 조작을 직접 구현한다. 클릭 규칙은 `common/invclick`에 있고 칸 묶음(`Area`)과 커서 아이템만 다룬다. 규칙은 베드락판을 따른다(분명하지 않을 때는 Cinnabar의 동작을 참고했고, 라이선스가 비상업용이라 코드는 쓰지 않았다).

- 왼쪽 클릭: 빈 커서는 칸 전체를 집고, 든 묶음은 빈 칸·같은 아이템에 들어갈 만큼 놓고, 다른 아이템과는 맞바꾼다.
- 오른쪽 클릭: 빈 커서는 반(올림)을 집고, 든 묶음은 빈 칸·같은 아이템에 하나를 놓는다. 다른 아이템 위에서는 아무 일도 없다.
- 두 번 클릭: 같은 칸을 250ms 안에 같은 쉬프트 상태로 다시 왼쪽 클릭하면(사이에 오른쪽 클릭이 없을 때) 두 번 클릭이다. 아이템을 든 채일 때만 같은 아이템을 커서로 모으고(`Collect`), 빈 커서면 보통 클릭이다. 쉬프트 두 번 클릭은 처음 쉬프트 클릭한 아이템을 인벤토리에서 모두 옮긴다(`MoveAll`).
- 끌기(`Split`): 아이템을 든 누름은 바로 그 칸에 놓고, 끄는 동안 새 칸에 닿을 때마다 누르기 전 든 묶음을 닿은 칸 모두에 다시 나눈다(왼쪽은 고르게, 남는 것은 커서, 오른쪽은 하나씩).
- 창 밖 누름: 든 묶음을 발밑에 떨어뜨린다(오른쪽은 하나, `DropCarried`).
- 화면은 줄(`ui.InvRow`)마다 칸 묶음(`ui.InvPart`), 화살표, 작은 버튼을 놓고 `Grow` 줄이 남는 높이를 채워 스크롤된다. Gameface는 자라는 상자의 `min-height`를 받을 높이에서 빼므로 `Grow` 줄에는 `min-height`를 두지 않는다. 칸 id는 `영역:번호`이고 누름은 `SlotAct`, 끌기는 닿은 칸이 늘 때마다 `DragAct`, 창 밖 누름은 `drop`으로 온다.
- 커서 아이템은 서버가 플레이어마다 들고(`ui.Carried`, `ui.SetCarried`) 화면 데이터의 `cursor`로 보낸다. 화면이 닫히거나 인스턴스를 떠나면 인벤토리로 돌아가고(`ui.ReturnCarried`) 자리가 없으면 발밑에 떨어진다.
- 페이지(`src/inventory/`): `InvSlotView`, `InvRows`, `RecipeBook`, `CursorStack`, `gesture.ts`. Gameface는 비어 있는 투명한 요소에 누름을 주지 않으므로 문서(`document`)의 `mousedown`·`touchstart`에서 대상이 창 안인지 본다. 터치는 탭이 왼쪽 클릭, 400ms 길게 누르기가 오른쪽 클릭이고, 아이템을 든 채 손가락을 끌면 끌기이며, 빈 커서로 끌면 스크롤이다. 탭 뒤 700ms 안의 `mousedown`은 같은 탭으로 보고 무시한다. 터치 화면에는 칸 툴팁이 없어 마지막으로 닿은 칸의 이름을 창 위쪽 줄에 쓴다.

## 4. 클라이언트 설정

Ore UI 페이지는 게임의 설정 화면이 쓰는 설정을 읽고 바꿀 수 있다([페이지 환경](./page-environment.mdx)). 서버는 접속한 동안 몇 가지를 정해 둔다(`platform` `keepClientSettings`, `common/oreui.SetClientSettings`).

- 동의한 플레이어: UI 프로필 클래식(`video.ui_profile` 0). 로그인 데이터의 `UIProfile`이 클래식이 아니면 접속할 때 클래식 UI를 권하는 창을 먼저 띄운다(`askClassicUI`).
- 운영자가 아닌 플레이어: 콘텐츠 로그 끔(`creator.contentLog.gui.enable`, `creator.contentLog.gui.showErrors`, `creator.contentLog.file.enable`, `creator.scriptDiagnostic.enableClient`).
- 설정은 다음에 열리는 DDUI 화면 루트와 함께 가고(`oui`의 `settings`), 페이지가 값이 다를 때만 쓴다(`src/runtime/settings.ts` `keepSettings`). 쓴 뒤에도 값을 지켜보아 플레이어가 접속 중에 바꾸면 되돌린다.
- 설정은 기기에 저장되는 게임 옵션이라 서버를 나간 뒤에도 남는다. 설정 id는 설정 화면 트리의 이름이다.

## 5. 로비 화면

- 메인 화면(`ui.HomeScreen`, `platform/home.go`)은 화면 전체를 채우고 로비에 있는 동안 닫히지 않는다. 하위 DDUI 화면(세이브 선택, 멀티 플레이, 친구, 칭호·치장, 설정, 안내, 입력·확인)은 같은 모양으로 그 자리에 열린다. 루트에 `lobby`가 실려 페이지가 `mc-lobby`(터치 기기는 `mc-touch`)와 그늘·머리(로고·이름)를 더하고 모든 글을 밝은 색으로 그린다.
- 로비 섬이 가운데에 보이도록 버튼은 가장자리에 둔다. 메인 화면은 그늘이 없고 하위 화면은 전체가 어두워진다.
- 휴대폰·태블릿(Android·iOS·Fire OS)에서는 `mc-touch`로 버튼을 양옆에서 8rem 안쪽에 두고 왼쪽 타일·오른쪽 위 아이콘 버튼을 크게 그린다(카메라 구멍·시스템 핸들이 누름을 가로채지 않게).
- 왼쪽 위 프로필: 얼굴 읽기가 클라이언트에 따라 잘못되어 지금은 게임 로고(`textures/ui/sg/logo`, 16px)를 그린다. 얼굴을 다시 쓸 때는 서버가 스킨의 머리 앞면(모자 겹 포함, 8×8)을 픽셀 목록으로 보내고(`platform/skinface.go`), 페이지에 캔버스(`getContext`)가 없어 8줄×8칸 상자로 그린다. Gameface는 빈 flex 항목을 늘리지 않으므로 줄과 칸 크기는 퍼센트로 정한다.
- 오른쪽 위: 알림(수는 빨간 표시 `ui.HomeButton.Badge`), 설정, 서버 나가기. 운영자에게는 맨 앞에 명령어가 더 있다. 페이지에서 게임 채팅창을 여는 엔진 명령이 없어 명령은 콘솔 화면(`ui.ConsoleScreen`)에 친다(`ExecuteCommand`, 결과 `CommandOutput`과 채팅 줄 `Text`를 최근 80줄 기록에 더해 다시 그린다).
- Esc는 화면을 닫지 않고 시스템 메뉴(계속하기, 설정, 서버 안내, 서버 나가기)를 메인 화면 위에 띄운다(`ui.Home.Overlay`). 서버 나가기는 확인 뒤 페이지가 바닐라 `vanillaGameplayLeaveGameCommandGroup.leaveGame()`을 불러 클라이언트가 스스로 나간다. 이 명령이 없는 클라이언트에서만 서버가 접속을 끊는다.
- 메인 화면은 창과 같은 크기 키(`common/ui.windowW`·`windowH`)라 하위 화면이 열린 화면을 그대로 바꾸고 돌아올 때도 그렇다. 하위 화면의 Esc·닫기나 누름 뒤에 새 화면이 없으면 `ui.Idle`이 불려 메인 화면이 다시 그려진다.
- 창·버튼·탭·컨트롤 막대는 남색 버튼 그림(`launcher_button`, 호버·누름은 `_hover`·`_pressed`)이고 글은 밝은 색이다.

## 6. 세이브 로딩 화면

세이브에 들어갈 때 전체 화면 로딩 화면(`ui.LoadingScreen`)을 띄우고, 섬의 청크가 서버와 클라이언트에 모두 와서 플레이어가 땅에 놓이면 닫는다(`ui.CloseLoading`). 화면은 하늘 배경, 네모 구름 5개, 떠다니는 세이브 그림, 이름과 일차·플레이 시간, 미끄러지는 막대, 점이 깜빡이는 "섬으로 가는 중"이다(`.mc-load*`, CSS 애니메이션). 너무 빨리 끝나 깜빡이지 않게 최소 1.2초(`minLoading`)는 보인다. 들어가지 못하면(호스트 오프라인, 서버 바쁨 등) 메인 화면으로 돌아오고 사유는 토스트로 보낸다(`enterFailed`).

## 7. 알림(토스트)

화면이 열려 있으면 채팅이 보이지 않으므로 알림은 토스트로 보낸다.

- `ui.Notify`: 지금만 필요한 알림(재료 부족 등). 토스트만, 제목 "알림"(빨강).
- `ui.Flash`: 결과가 중요한 알림. 토스트와 같은 줄을 채팅에도, 제목 "완료"(초록).
- 로비에는 채팅이 없어 `ui.Flash`는 토스트만 보내고, 채팅으로 보낼 글은 `ui.Tell`(세이브 안이면 채팅, 로비면 토스트)로 보낸다.
- 클라이언트는 토스트를 하나씩 차례로 보여 주므로 플레이어마다 `ui.ToastGap`(3초)에 하나만 보낸다. 그 사이의 알림은 하나로 합쳐 앞 토스트가 끝날 때 가장 최근 메시지 + `(외 n건)`으로 보낸다.
- 클라이언트는 아이템 사용 버튼을 누르고 있는 동안 사용 패킷을 되풀이해 보낸다. 메뉴 아이템 등으로 화면을 여는 사용은 0.5초 디바운스한다.

## 8. GUI 배율과 안전 영역

GUI 배율은 `html` 글자 크기로 오므로 `rem` 크기가 따라간다. 안전 영역은 facet `core.safeZone`(`src/runtime/safezone.ts`)으로 받아 body의 `--oui-safe-*` 변수에 두고, 화면(`.mc-screen`)과 가장자리에 붙은 상자는 그 여백을 안쪽·바깥 여백으로 더한다. 디버그 줄(`/uidebug`)의 `safe=`가 받은 여백이다.

## 9. 지킬 것

- **게임이 업데이트되면 `assets/resourcepack/oreui/hbui/gameplay.html`의 바닐라 번들 파일 이름(해시)을 설치본과 맞춘다.** 틀리면 게임 중 Ore UI 전체가 뜨지 않는다. `oui-mc.css`의 `@font-face` 글꼴 파일 이름도 맞춘다.
- 화면 크기 상자(`#oui-ddui`, `.mc-screen`, 창의 최대 크기)는 퍼센트가 아닌 `vw`·`vh`로 잡는다(iPad에서 body 높이가 0).
- 화면은 바닐라 CSS·JS에 기대지 않는다(iOS에서는 팩의 `hbui` 폴더가 게임 것을 통째로 대신). 글꼴은 팩 CSS가 `ui://hbui/fonts`로 직접 선언하고 한글 줄은 Noto Sans KR을 먼저 둔다.
- `/uidebug`는 화면 위에 페이지의 디버그 줄(화면 상태, 지역 글꼴 변수, 페이지 언어, 글꼴, `@font-face` 목록, 화면 크기)을 띄운다. 화면은 플레이어마다 하나다.

## 10. 빌드와 번들

- 소스는 `web/oreui/src`다. 바꾼 뒤 `web/oreui`에서 `npm ci --ignore-scripts`(처음 한 번)와 `npm run build`를 돌려 `oui-app.js`·`oui-app.css`를 만들고 **커밋한다**(서버 빌드에 Node가 필요 없다). 의존성은 `package-lock.json`으로 고정하고 설치는 늘 `--ignore-scripts`로 한다.
- 번들 첫 줄은 `/* oui-app src 해시 */`다. 해시는 소스 파일과 `package-lock.json` 내용에서 나오고, `TestOreUIBundleFresh`가 소스 해시와 번들 해시를 견준다.
- 테스트: `cd web/oreui && npx vitest run`, 타입 검사: `npm run typecheck`.
- 화면 비교(parity): `OREUI_FIXTURES=절대경로 go test ./common/ui -run TestDumpFixtures`가 화면마다 JSON을 쓰고, `node visual/capture.mjs --renderer app --fixtures 폴더 --out 폴더 --compare visual/baseline`이 Playwright로 그려 기준 그림과 다른 픽셀 비율을 찍는다. 한 화면이라도 `--max`(기본 0.5%)를 넘으면 종료 코드 1이다.

## 11. 운영자 시험 화면

Ore UI 페이지가 무엇을 받고 무엇을 불러오는지 실제 클라이언트에서 보는 운영자 명령이다. `/sgdebug oreres`는 서버가 보낸 리소스 길을 시험하고, `/sgdebug oreinput`은 입력 이벤트를 받아 서버로 보낸다. 결과와 해석은 [페이지 환경](./page-environment.mdx)에 정리했다. 시험 화면은 창 위에 서버가 받은 줄 수와 마지막 줄, 화면이 열린 동안 클라이언트가 보낸 패킷 종류와 수(늘 오는 `PlayerAuthInput`, `NetworkStackLatency`, `SubChunkRequest`, `Animate`는 뺀다)를 보여 준다. 줄마다 서버 로그(`ore ui probe`)에 남는다.
