# 서버 주도 Ore UI 화면 운영 노트

앞 페이지들의 실험을 실제 서버에서 메뉴 화면으로 운영하며 확인한 것이다. 서버는 화면 이름과 데이터만 보내고, 레이아웃은 팩의 게임 중 페이지가 정한다. (출처: 비공개 조사)

## 1. 구조

- 페이지: React 18 + react-facet(TypeScript)으로 짤 수 있다. 컴포넌트는 ore-ui-react와 `@react-facet/dom-fiber` 위에 짠다.
- 리소스팩: 게임 중 페이지 `hbui/gameplay.html`을 바꾼다. 바닐라 번들을 불러온 뒤 자기 CSS와 JS를 더한다. 암호화하지 않은 팩에는 빈 `content.zipe`를 넣어야 페이지가 쓰인다([리소스팩 전달](../server/resource-pack-delivery.mdx)).
- 서버: DDUI 화면을 열고 루트를 데이터 저장소로 보내고 누름을 받는다. 클라이언트의 DDUI 패킷은 패킷 훅에서 가로챈다. 누름 뒤에 새 화면을 보이지 않으면 화면을 닫으면 폼 버튼과 같은 느낌이 난다.
- 같은 폼의 새 루트가 오면 React가 달라진 부분만 고치므로 창·스크롤 위치·입력칸 글·불러온 아이템 그림은 그대로다. 다른 폼의 루트는 새로 그린다.
- Gameface는 일반 `div`에 `click`을 보내지 않으므로 `mousedown`으로 누름을 받는다.

## 2. 패킷과 데이터 저장소

| 방향 | 패킷 | 쓰는 법 |
| --- | --- | --- |
| S to C | `ClientBoundDataDrivenUIShowScreen` | `ScreenID` `minecraft:custom_form`, `FormID`는 폼마다 새 번호, `DataInstanceID` 1 |
| S to C | `ClientBoundDataStore` | 저장소 `minecraft`의 `custom_form_data_1`에 폼 번호, 루트, 설정을 쓴다 |
| S to C | `ClientBoundDataDrivenUICloseScreen` | 화면 닫기 |
| C to S | `ServerBoundDataStore` | 페이지가 이벤트 경로에 쓴 이벤트 |
| C to S | `ServerBoundDataDrivenScreenClosed` | 화면이 닫힘 |

- 값 패치 대신 바뀔 때마다 같은 폼의 루트 전체를 새로 보내고 클라이언트가 가장 새 것을 쓰게 해도 된다. 그때 모든 쓰기는 `Change`이고 `UpdateCount`는 서버 전체에서 하나씩 올린다. 경로 갱신 `Update`를 쓰려면 `PropertyUpdateCount`를 그 속성의 마지막 `Change.UpdateCount`와 같게 두고 `PathUpdateCount`만 올린다([DDUI 가이드](./ddui-server-guide.mdx)).
- 화면을 바꿔 열면 클라이언트는 앞 폼의 닫힘을 새 폼이 열린 뒤에 알리므로, 닫힘은 `FormID`가 지금 폼과 같을 때만 처리한다.
- 휴대폰 뒤로 버튼은 Esc 외의 키로 올 수 있다(Android `KEYCODE_BACK` 4, 브라우저 뒤로 166·`GoBack`·`BrowserBack`). 페이지는 이 키들도 닫기로 보낸다.
- 숨긴 바닐라 폼(`custom_form` 루트)도 자기 경로에 쓴다. 경로에 `close`가 들어 있으면 Esc로 받으면 된다.
- 팩으로 할 수 없는 것: 바닐라 DDUI 레이아웃 바꾸기, 진짜 컨테이너를 Ore UI로 열기, HUD. 컨테이너 화면은 JSON UI로 꾸민다.

## 3. Gameface 입력과 레이아웃 동작

- 창 크기가 바뀌면 Gameface가 누름을 바뀌기 전 자리로 판정한다. 그래서 크기가 같은 창끼리는 열린 화면을 그 자리에서 바꾸고, 크기가 다른 창은 화면을 새로 연다.
- Gameface는 비어 있는 투명한 요소에 누름을 주지 않는다. 창 안 빈 곳의 누름은 문서(`document`)의 `mousedown`·`touchstart`에서 대상이 창 안인지 보고 처리한다.
- 터치에서는 탭 뒤에 `mousedown`이 따라온다. 탭 뒤 700ms 안의 `mousedown`은 같은 탭으로 보고 무시한다.
- Gameface는 자라는 상자의 `min-height`를 받을 높이에서 빼므로 자라는 줄에는 `min-height`를 두지 않는다.
- Gameface는 빈 flex 항목을 늘리지 않으므로 격자의 줄과 칸 크기는 퍼센트로 정한다.
- 페이지에 캔버스(`getContext`)가 없다. 픽셀 그림(예: 스킨 얼굴 8x8)은 서버가 픽셀 목록으로 보내고 상자를 줄과 칸으로 놓아 그린다.
- 페이지에서 게임 채팅창을 여는 엔진 명령이 없다. 명령은 페이지의 입력칸에서 받아 서버로 보낸다.
- 서버 나가기는 페이지가 바닐라 `vanillaGameplayLeaveGameCommandGroup.leaveGame()`을 불러 클라이언트가 스스로 나가게 할 수 있다. 이 명령이 없는 클라이언트에서만 서버가 접속을 끊는다.

## 4. 서버가 구현하는 인벤토리 클릭 규칙

진짜 컨테이너를 Ore UI로 열 수 없으므로, Ore UI로 인벤토리 화면을 그리면 서버가 바닐라 인벤토리 조작을 직접 구현해야 한다. 베드락판 규칙은 다음과 같다.

- 왼쪽 클릭: 빈 커서는 칸 전체를 집고, 든 묶음은 빈 칸·같은 아이템에 들어갈 만큼 놓고, 다른 아이템과는 맞바꾼다.
- 오른쪽 클릭: 빈 커서는 반(올림)을 집고, 든 묶음은 빈 칸·같은 아이템에 하나를 놓는다. 다른 아이템 위에서는 아무 일도 없다.
- 두 번 클릭: 같은 칸을 짧은 시간(250ms) 안에 같은 쉬프트 상태로 다시 왼쪽 클릭하면 두 번 클릭이다. 아이템을 든 채일 때만 같은 아이템을 커서로 모으고, 빈 커서면 보통 클릭이다. 쉬프트 두 번 클릭은 처음 쉬프트 클릭한 아이템을 인벤토리에서 모두 옮긴다.
- 끌기: 아이템을 든 누름은 바로 그 칸에 놓고, 끄는 동안 새 칸에 닿을 때마다 누르기 전 든 묶음을 닿은 칸 모두에 다시 나눈다(왼쪽은 고르게, 남는 것은 커서, 오른쪽은 하나씩).
- 창 밖 누름: 든 묶음을 발밑에 떨어뜨린다(오른쪽은 하나).
- 커서 아이템은 서버가 플레이어마다 들고 있어야 한다. 화면이 닫히면 인벤토리로 돌려놓고 자리가 없으면 발밑에 떨어뜨린다.
- 터치 화면에는 칸 툴팁이 없다.

## 5. 클라이언트 설정

Ore UI 페이지는 게임의 설정 화면이 쓰는 설정을 읽고 바꿀 수 있다([페이지 환경](./page-environment.mdx)).

- UI 프로필은 `video.ui_profile`(0이 클래식)이다. 로그인 데이터의 `UIProfile`로 접속한 클라이언트의 프로필을 알 수 있다.
- 콘텐츠 로그는 `creator.contentLog.gui.enable`, `creator.contentLog.gui.showErrors`, `creator.contentLog.file.enable`, `creator.scriptDiagnostic.enableClient`다.
- 설정은 기기에 저장되는 게임 옵션이라 서버를 나간 뒤에도 남는다. 설정 id는 설정 화면 트리의 이름이다. 서버가 바꿀 때는 플레이어 동의를 받는다.

## 6. 알림과 입력

- 화면이 열려 있으면 채팅이 보이지 않으므로 알림은 토스트로 보낸다.
- 클라이언트는 토스트를 하나씩 차례로 보여 준다. 몰려 오는 알림은 서버에서 간격을 두고 합쳐 보낸다.
- 클라이언트는 아이템 사용 버튼을 누르고 있는 동안 사용 패킷을 되풀이해 보낸다. 아이템 사용으로 화면을 연다면 디바운스한다.

## 7. GUI 배율과 안전 영역

GUI 배율은 `html` 글자 크기로 오므로 `rem` 크기가 따라간다. 안전 영역은 facet `core.safeZone`으로 받아 CSS 변수에 두고, 화면과 가장자리에 붙은 상자에 그 여백을 더한다. 휴대폰·태블릿에서는 카메라 구멍과 시스템 핸들이 가장자리 누름을 가로챌 수 있다.

## 8. 지킬 것

- **게임이 업데이트되면 팩의 `hbui/gameplay.html`에 적은 바닐라 번들 파일 이름(해시)을 설치본과 맞춘다.** 틀리면 게임 중 Ore UI 전체가 뜨지 않는다. CSS `@font-face`의 글꼴 파일 이름도 맞춘다.
- 화면 크기 상자는 퍼센트가 아닌 `vw`·`vh`로 잡는다(iPad에서 body 높이가 0).
- 화면은 바닐라 CSS·JS에 기대지 않는다(iOS에서는 팩의 `hbui` 폴더가 게임 것을 통째로 대신한다). 글꼴은 팩 CSS가 `ui://hbui/fonts`로 직접 선언한다.
