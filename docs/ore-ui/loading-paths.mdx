# 로딩 경로와 신뢰 판정

주소는 Android 1.26.52.3 arm64 분석 기본 주소(ELF 주소 + 0x100000)다. (출처: repo-ore-ui-loading)

## 0. 개념: 팩 스택과 "신뢰"

JSON UI는 리소스팩의 `ui/*.json`이 바닐라 정의를 덮어쓰는 방식이다. Ore UI는 다르다. 화면은 설치 폴더의 `hbui/*.html`·`*.js`·`*.css` 번들이고, 이 번들이 `ui://`로 시작하는 주소로 파일을 요청한다. 엔진은 요청을 받으면 설치 폴더로 가기 전에 팩 스택(켜진 리소스팩의 쌓인 목록)을 위에서부터 훑고, **신뢰된 팩**에 같은 경로의 파일이 있으면 그것을 준다. 그래서 "어떤 팩이 신뢰되는가"가 Ore UI를 바꿀 수 있는지를 정한다. 신뢰 여부는 팩을 여는 방식(접근 전략)으로 정해지고 팩의 내용과는 무관하다.

가장 작은 탐침 팩은 다음처럼 생긴다(서버가 암호화해 보내면 Ore UI 배경이 자홍이 된다).

```text
probe-pack/
  manifest.json                 resources 모듈 하나
  hbui/gameplay-theme-cb1e5471975ef2c1abb9.css   바닐라 CSS 내용 + 마지막 줄 body 규칙
```

```css
/* 바닐라 gameplay-theme CSS 맨 끝에 덧붙인 한 줄 */
body { background-color: rgba(255, 0, 255, 0.6) !important; }
```

파일 이름의 해시(`cb1e5471975ef2c1abb9`)는 게임 판마다 다르다. 설치본 `data/gui/dist/hbui/`에서 이름을 확인한다.

## 1. Ore UI 파일 요청은 어떻게 풀리나 `{코드}`

1. **URL 정규화** (`@0x09cf635c`): 요청 경로가 `ui://`로 시작하지 않으면 앞의 `/`를 떼고 `ui://`를 붙인다. 문자열로 `ui://`, `ui://hbui/fonts/`, `coui://uiresources/...`(Gameface 인스펙터)가 있다.
2. **파일 찾기** (`@0x09cf68d4`)
   - 경로에 `../`나 `..\`가 있으면 거부한다.
   - 경로를 정규화한 뒤 **팩 스택(0x110바이트 팩 항목 배열)을 앞에서부터 돈다.** 각 팩에서 팩 접근 전략의 가상 함수(+0x30)가 참일 때만 그 팩에 파일이 있는지(`@0x112ac30c`, 하위 팩, 팩 순, 가상 함수 +0x38 = `hasAsset(path, false, false)`) 본다. 있으면 그 팩에서 준다.
   - 없으면 `gui/dist/` + 기준 폴더 + 경로를 **앱 패키지 파일 시스템**(`Core::FileSystem`, `@0x09cf66f8`)에서 연다.
3. **필터는 `isTrusted()`다**: 바로 다음 슬롯(+0x38)이 `hasAsset`이고, 배드락 `PackAccessStrategy`의 가상 함수 순서(`... isWritable`, `setIsTrusted`/`isTrusted`, `hasAsset` ...)와 맞는다. "내장 팩과 마켓플레이스 팩만 신뢰된다"는 처음 짐작은 틀렸다. 서버가 보낸 암호화 팩도 신뢰된다.
4. `routes.json`(`@0x09cd39dc`)과 폰트(`gui/dist/hbui/fonts`, `@0x096de4bc`)는 설치 폴더에서만 읽는다.

8Crafter Ore UI Customizer의 "Export as RP"가 "RP에서 Ore UI를 불러오게 하는 모드가 필요하다"고 적은 것은 평문 팩 기준으로 맞다. 클라이언트 모드 없이도 암호화 팩이면 된다.

## 2. 암호화 팩은 신뢰된다

### 접근 전략별 판정 `{코드}`

팩 접근 전략 클래스의 vtable을 RTTI 이름(`18PackAccessStrategy` 등)으로 찾고, 슬롯 +0x30(`isTrusted`)을 역어셈블했다(11차 분석, `DumpVtables.java`).

| 접근 전략 | +0x30 `isTrusted` | +0x28 `isWritable` |
| --- | --- | --- |
| `ZipPackAccessStrategy` (`@0x1125865c`) | `위치.파일시스템 == 1` 또는 `+0x170` 플래그 | `+0x171` 플래그 |
| `DirectoryPackAccessStrategy` (`@0x112ee564`) | `위치.파일시스템 == 1` | 언제나 참 |
| `EncryptedFileAccessStrategy` (`@0x112f456c`) | **언제나 참** | 언제나 거짓 |
| `ZippedEncryptedFilesAccessStrategy` (`@0x112f456c`, 같은 함수) | **언제나 참** | 언제나 거짓 |
| `DirectoryPackWithEncryptionAccessStrategy` (`@0x112f0a70`) | **언제나 참** | 언제나 참 |

- `위치`는 팩의 `ResourceLocation`(접근 전략의 +0x18 슬롯이 돌려주는 필드)이고, 첫 필드가 파일 시스템 종류다. 1은 앱 패키지(`AppPackage`), 곧 게임 설치 폴더의 내장 팩으로 본다 `{추론, 배드락 ResourceFileSystem 열거 순서}`.
- **팩 UUID나 manifest 내용은 신뢰 판정에 쓰이지 않는다.** "마켓플레이스 애드온의 UUID를 쓰면 되지 않나"는 통하지 않는다. UUID를 흉내 내도 평문 팩은 Zip/Directory 전략으로 열리고, 그 판정은 설치 위치만 본다.
- 바이너리의 `Failed encrypted file signature check` 문구는 월드 저장소(LevelDB) 쪽 코드였다. 팩 서명(`signatures.json`)을 확인하는 코드는 따라가지 않았다. 실측에서는 서명 없이 암호화만 한 팩이 신뢰되었다.
- 콘텐츠 키는 `ClientContentKeyProvider`가 서버가 보낸 키, 엔타이틀먼트, 내장 표에서만 찾는다. 팩 옆 키 파일이나 월드 db는 보지 않는다(출처: 비공개 조사).

### 서버 실측 (Windows 1.26.52, 2026-10-23) `{실측}`

- 시험 서버에 두 번째 인자로 32바이트 키를 주면, 팩을 마켓플레이스 암호화 형식으로 바꿔 키와 함께 보낸다(형식은 [Ore UI 페이지 바꾸기](./modifying-pages.mdx)).
- 같은 탐침 팩을 평문과 암호화로 번갈아 보냈다. 클라이언트가 받아 둔 팩을 다시 쓰지 않게 팩 버전을 매번 올렸다.

| 보낸 팩 | Ore UI 사망 화면 배경 |
| --- | --- |
| 평문 (1.0.2, 1.0.4) | 바닐라 그대로 |
| 암호화 (1.0.3) | **자홍**(탐침 CSS `body{background-color:rgba(255,0,255,0.6)}`) |

- 사용자가 따로 교차 검증했을 때도 자홍 화면은 암호화 팩일 때만 나왔다.
- 서버 접속을 끊은 뒤 메뉴 화면에도 자홍이 남은 적이 있다. 메뉴 `index.html`도 `gameplay-theme-*.css`를 불러오고, 서버 팩이 접속 뒤에도 잠시 팩 스택에 남는 것으로 보인다 `{실측, 추론}`.

### 로컬 팩(`content.zipe`) `{실측, 2026-10-27}`

평문 팩 폴더에 `content.zipe`를 더하면 키 없이도 `DirectoryPackWithEncryptionAccessStrategy`로 열리고, 신뢰되어 Ore UI 파일을 바꾼다. 엔진은 이 파일이 있는지만 본다. 자세한 시험 결과는 [Ore UI 페이지 바꾸기](./modifying-pages.mdx)의 로컬 시험 절에 있다.

## 3. 버튼 스타일 다리 `vanilla.resourcePackOverrides` `{코드}`

### 엔진 쪽

- facet `vanilla.resourcePackOverrides`(`OreUI::ResourcePackOverridesFacet`)는 `definitions`와 `lastUpdated` 두 속성을 낸다(`@0x09ef8760`).
- 정의 하나는 `identifier`, `control`, `propertyData[]`(`UI::Resources::ResolvedPropertyData`: `name`, `value`=JSON 문자열), `textureData[]`(`ResolvedTextureData`: `identifier`, `path`, `sliceSize`, `uvSize`, `uvScale`)다.
- **엔진이 푸는 정의는 하드코딩된 두 개다** (`@0x09ef8a7c`).

| 정의 | 텍스처 변수 | 속성 변수 |
| --- | --- | --- |
| `common_buttons.light_text_button` | `$new_ui_button_texture` | `$text_color`, `$border_color` |
| `common_buttons.focus_border` | `texture` | 없음 |

- 값은 팩 스택이 합쳐진 JSON UI 정의에서 변수를 끝까지 풀어 얻는다. 그래서 `_global_variables.json`의 `$light_button_*_text_color`나 텍스처 파일을 바꿔도 반영된다.

### 게임 중 번들 쪽 (`gameplay-*.js`)

- `control`(하위 컨트롤 이름)을 Ore UI 상태로 바꾼다: `default` = 기본, `hover` = `hovered`·`focused`, `pressed`/`press` = `pressed`·`selected`, `locked` = `disabled`.
- 대상 컴포넌트는 `pressable`(배경·테두리)과 `button`(글자), 역할은 `primary`·`secondary`다.
- 변환
  - 텍스처는 CSS `borderImageSource: pack://경로.png?filtering=point`가 된다. `border-image-slice`는 `sliceSize`×`uvScale`, `border-image-width`는 `uvSize`×0.2rem이다. 나인슬라이스(`.json`)가 그대로 따라온다.
  - `$text_color`([r,g,b] 0~1)는 `color: rgb(...)`가 된다.
  - `$border_color`는 `filter: coh-color-matrix(...)`(테두리 텍스처에 색을 곱함)가 된다.
- 이 공급자가 **`gameplay.html` 앱 전체를 감싼다**(라우터의 `wrapperComponent`). 사망, 침대, 인벤토리, DDUI(`/gameplay/data-driven`), 거래, 블록 화면이 모두 받는다.
- 메뉴 번들(`index-*.js`)은 facet 이름만 선언하고 쓰지 않는다. 게임 밖 메뉴에는 이 다리가 없다.

### 탐침 팩과 결과 `{실측}`

서버는 Dragonfly(인증 끔, 포트 19140, 리소스팩 필수)이고 `/die`로 공허 피해 1000을 줘 사망 화면을 연다. 탐침 팩은 서버 팩이라 신뢰되지 않는다.

| 팩 파일 | 내용 |
| --- | --- |
| `ui/_global_variables.json` | `$light_button_default/hover/pressed_text_color` = 빨강/초록/파랑 |
| `textures/ui/button_borderless_light(hover/pressed).png` | 16×16 단색 노랑/하늘/자홍 |
| `hbui/`, `gui/dist/hbui/`, 팩 루트의 `gameplay-theme-cb1e5471975ef2c1abb9.css` | 바닐라 CSS + `body{background-color:rgba(255,0,255,0.6)!important}` |
| `ui/death_screen.json` | JSON UI 사망 화면의 `buttons_panel`·`labels_panel`을 `ignored: true` |
| `ui/pause_screen.json` | 대조군. `pause.take_screenshot_icon`의 텍스처를 자홍 텍스처로 |

| 관찰 | 결과 |
| --- | --- |
| 일시정지 화면(JSON UI) | 버튼이 노랑 바탕·빨강 글자, hover는 하늘·초록. 카메라 아이콘이 자홍. 팩과 최상위 요소 수정이 적용됨 |
| 사망 화면 | 제목과 버튼 두 개가 **그대로 보인다**. JSON UI 사망 화면의 패널을 모두 숨겼으므로 이 화면은 **Ore UI**다 |
| 사망 화면 버튼 | **노랑 바탕·빨강 글자, hover는 하늘 바탕·초록 글자.** 팩의 텍스처와 글자색이 Ore UI 버튼에 들어갔다 |
| 사망 화면 배경 | 자홍이 아니다. 평문 팩의 `hbui/...css`는 쓰이지 않았다 |

정리: 다리와 `pack://` 텍스처는 신뢰하지 않는 서버 팩으로도 된다. Ore UI 파일 조회는 평문 서버 팩에서는 되지 않는다. 같은 팩을 암호화해 보내면 된다.

탐침 요령: JSON UI 화면의 패널을 `ignored: true`로 숨겼는데 화면이 그대로 보이면 그 화면은 Ore UI다. 이 방법으로 어떤 화면이 어느 기술로 열렸는지 가릴 수 있다.

## 4. DDUI 레이아웃은 팩에서 읽지만 내장 팩만 `{코드}`

- 로더(`@0x0b96ab2c`)가 팩 스택을 돌며 각 팩의 `ddui/root`와 `ddui/composition` 폴더를 연다. 파일은 `minecraft:ui-root`(`@0x0b96b304`, 오류 문구 `DataDrivenUI Root .json file '{}'`, `Failed to load DataDrivenUI file`)와 `minecraft:ui-composition`(`@0x0b96c468`)으로 해석한다. 팩 UUID를 함께 기록하고, 이것이 JS로 가는 `sourcePackId`가 된다(`vanilla.CoreDataDrivenUIDefinitionQuery`).
- **팩 거르기**: 팩 객체의 bool 두 개(+0x88 `@0x112ac54c`, +0x89 `@0x112ac55c`) 중 하나라도 참인 팩만 읽는다. 같은 두 함수가 POI 로더(`@0x10a29438`, `@0x10a2b6e8`)에서 "둘 다 거짓인 팩이 `minecraft:` 식별자를 쓰면 `Cannot use minecraft namespace found %s`"를 내는 데 쓰인다. 그러니 이 두 값은 "게임 내장(퍼스트파티) 팩" 표시다 `{추론}`. 사용자·서버 팩의 `ddui/root/*.json`은 읽히지 않는다.
- `/reload`에 DDUI 분기가 있다(`commands.reload.ddui.success`, `@0x0ebd02fc`).
- **프런트엔드는 크리에이터 팩을 받을 준비가 되어 있다** (`gameplay-*.js`)
  - 엔진이 준 레이아웃은 `isCreatorDataDriven: true`, `pack: sourcePackId`로 그린다.
  - 이미지 규칙: 레이아웃의 출처 팩이 바닐라(`0575c61f-...`)면 이미지가 다른 팩(`packId`)을 가리킬 수 있다. 바닐라가 아니면 자기 팩 이미지만 쓸 수 있다(오류 문구 `RequestedPack is not supported.`, `Cannot load vanilla images.`, `Image cannot look like a URL.`).
  - 커뮤니티에서 Mojang 개발자가 말한 "2단계(전체 레이아웃) 전까지 커스텀 RP 패널은 내부 팩 전용"과 정확히 맞는다.

## 5. 화면 전환 스위치와 컨테이너 `{코드}`

컨테이너 화면을 Ore UI로 여는 스위치와 서버가 그것을 켤 수 없다는 결론은 [아이콘과 컨테이너](./geo-item-and-containers.mdx)에 있다.

## 6. 규칙 요약

1. 평문 팩(Zip, Directory 접근 전략)은 신뢰되지 않으므로 `hbui/`의 파일이 무시된다.
2. 암호화 접근 전략 세 종류는 팩 UUID, 서명, manifest와 상관없이 언제나 신뢰된다.
3. 평문 팩으로도 버튼 스타일 다리와 `pack://` 텍스처는 닿는다.
4. 폰트와 `routes.json`은 팩이 아닌 설치 폴더에서만 읽는다.
5. DDUI 레이아웃(`ddui/root`)은 내장 팩만 읽힌다.
6. 판이 바뀔 때마다 접근 전략 표의 +0x30 구현과 번들 파일 이름 해시를 다시 확인한다.
