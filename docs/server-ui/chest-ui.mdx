"상자 UI"는 두 가지를 가리킨다. 하나는 스크립트의 `ActionFormData`를 리소스팩으로 재스킨해 상자 모양으로 보이게 하는 **폼 방식**이다(아이템은 오가지 않고 버튼일 뿐이다). 다른 하나는 클라이언트가 진짜 상자 창을 열게 만드는 **엔티티 상자 방식**이다(아이템이 실제로 옮겨진다). 이 페이지는 둘을 차례로 설명한다. 둘의 선택 기준은 한 줄이다: 넣고 빼는 것이 없는 화면은 폼, 실제 아이템이 오가는 곳만 상자다.

## 1. 폼 방식: Chest-UI

Chest-UI는 스크립트 API의 `ActionFormData`를 리소스팩으로 재스킨해 자바 서버 같은 상자 GUI(1~54칸, 화로, 플레이어 인벤토리 미러)로 보이게 하는 행동팩 + 리소스팩이다. 2023-07에 시작해 마인크래프트 버전마다 숫자 아이템 ID 표를 갱신해 왔고 마지막 갱신은 26.40(2026-08-14, `115d95c`, 커밋 112개)이다. 원작 LeGend077, 유지 Herobrine64·LeGend077이며 `pattern()` 함수는 Aex66이 썼다. 라이선스는 CC BY 4.0이다(저장소 `License` 파일을 확인함) (출처: chest-ui-pack, repo-chest-ui).

포크 Aex66/Chest-UI(`7dbfd13`, 2026-01-06)는 원본의 부분집합으로 독자 커밋이 없고 원본보다 8커밋 뒤처져 있다. 26.20~26.40의 ID 갱신, 인벤토리 수정, 화로 레이아웃 정리가 없다. 그래서 1.21.131 이후에는 ID가 맞지 않고 인벤토리 아이콘이 `* 1` 식 그대로라 1.21.130 이후에는 나오지 않을 것이다 `{추론}`. 근거로는 원본만 쓴다.

### 1.1 구성과 동작

manifest는 RP·BP 모두 `min_engine_version [1, 21, 0]`, 버전 1.5.0이고 BP는 `@minecraft/server` 1.18.0, `@minecraft/server-ui` 1.3.0을 쓴다. 실제 대상 버전은 `min_engine_version`이 아니라 커밋 메시지의 버전(26.40)이다. 숫자 ID 표가 버전마다 다르기 때문이다.

파일: `RP/ui/server_form.json`, `chest_server_form.json`, `chest_inventory_system.json`, `furnace_server_form.json`, `_global_variables.json`, `BP/scripts/extensions/forms.js`(폼 빌더), `typeIds.js`(아이템 → 숫자 ID 표 2,364개 + 데이터 값 표), `constants.js`.

동작 순서는 다음과 같다 `{확인}`.

1. 스크립트가 `ActionFormData`를 만든다. 제목 rawtext 맨 앞에 `§c§h§e§s§t§2§7§r`(크기 플래그), 버튼마다 글 `stack#NNdur#NN§r이름§r\n설명…`과 아이콘 문자열을 넣는다. 아이콘은 텍스처 경로(`textures/…`)이거나 숫자 문자열 `(ID + 보정) * 65536 + (인챈트 ? 32768 : 0)`이다. 인벤토리를 켜면 플레이어 인벤토리 36칸을 같은 형식의 버튼으로 뒤에 붙인다.
2. `server_form.json`이 바닐라와 같은 경로에서 `long_form`을 `@` 없이 재선언해 `type: panel`과 `controls`를 바꾼다. 안에 바닐라 모양(제목에 플래그가 없을 때만 보임), 상자 패널, 화로 패널이 있고 각자 제목 포함 검사로 보인다.
3. `chest_panel`에 1·5·9·18·27·36·45·54칸 템플릿이 있고 각각 `$condition`(예 `§c§h§e§s§t§5§4`) 포함 검사로 보인다. 쓰지 않는 크기는 `_global_variables.json`의 `$disable_N_slots_layout: true`로 `ignored`되어 만들어지지 않는다. 기본값은 54칸과 화로만 켜져 있다.
4. 상자 칸은 `grid`(`grid_dimensions: "$grid_size"`, `collection_name: form_buttons`)가 만들고, 인벤토리·핫바는 `collection_name: form_buttons`인 스택 패널 안에 `collection_index`가 고정된 자식 36개로 만든다(COL-06).
5. 칸 하나는 `#form_button_texture`를 받아, 앞 8바이트가 `textures`면 이미지, 아니면 아이템 렌더러(`beacon.item_renderer`)에 `#item_id_aux`를 넣어 그린다(PAT-11). hover 상태에는 `hover_text_renderer` 툴팁, 하이라이트, 포커스 테두리가 붙는다.

상자형 폼의 레시피(PAT-13)는 이렇게 요약된다: 제목 플래그로 크기 선택 → 크기별 템플릿은 `ignored`로 쓰는 것만 생성 → `grid` + `collection_name: form_buttons` → 칸마다 `'%.8s' = 'textures'`로 이미지와 아이템 렌더러 분기 → 버튼 글 고정 폭 머리말로 수량·내구도 → hover에 툴팁. 숫자 ID는 `(#v - 0)`으로 넣는다. 이 기법들의 JSON 조각은 [서버 폼 재스킨](./reskinning-server-forms.mdx)의 10절에 있다.

## 2. 아이템 아이콘: `#item_id_aux`와 `%` 식

### 2.1 현재 식

세 파일(`chest_server_form.json`, `chest_inventory_system.json`, `furnace_server_form.json`)이 이 바인딩으로 아이템 아이콘을 정한다.

<Excerpt src="chest-ui" title="Chest-UI chest_server_form.json" path="RP/ui/chest_server_form.json">

```json
{
    "binding_type": "view",
    "source_property_name": "((#form_button_texture - (#form_button_texture % 65536)) / 65536)",
    "target_property_name": "#item_id_aux"
}
```

</Excerpt>

`#form_button_texture`는 스크립트가 넣은 숫자 문자열이다(다이아몬드 `'20054016'` = 306 × 65536, 인챈트면 `'20086784'`).

### 2.2 이 식이 실제로 하는 일 `{코드}` `{추론}`

Cinnabar 평가기(26.30 네이티브 클라이언트를 재구성한 코드 근거이며 게임 실측이 아니다. PolyForm Noncommercial 라이선스에 따라 비상업 조사 목적으로만 실행함)로 돌린 결과다.

| 식 | 결과 | 읽는 법 |
| --- | --- | --- |
| `((#t - (#t % 65536)) / 65536)` | `Int(20054016)` | ID(306)가 아니라 원래 값 전체. 바깥 `/ 65536`이 적용되지 않았다 |
| 인챈트 값에 같은 식 | `Int(20086784)` | 인챈트 비트(32768)도 그대로 남는다 |
| `(#t % 65536)` | `Json(Null)` | `%`는 연산자가 아니다(EXP-02) |
| `(#t - (#t % 65536))` | `Int(20054016)` | 문자열 − null → 원래 값이 숫자로 재해석 |
| `((#t - (#t % 65536)) / 2)` | `Int(20054016)` | 나누는 수와 무관하게 바깥 연산이 사라진다 |
| `(((#t - (#t % 65536)) / 65536) + 1)` | `Int(20054017)` | `+ 1`은 적용, `/ 65536`만 빠진다 |
| `((#t - #missing) / 65536)` | `Int(306)` | 비교: 없는 속성(null)을 빼면 나눗셈은 정상 |
| `((#t - 0) / 65536)` | `Int(306)` | 비교 |
| `(#fbt_num * 1)` | `Text("")` | 2026-01 이전 Chest-UI가 쓰던 식. 문자열 `*` 숫자는 빈 문자열(EXP-31) |
| `(#fbt_num - 0)` | `Int(20054016)` | 권장 변환 |
| `(#fbt_num / 65536)` | `Int(1)` | 문자열 `/` 숫자는 1(EXP-32) |

결론: `%` 묶음이 null이 되면서 바로 바깥 연산까지 빠지므로 식 전체는 `ID × 65536 (+ 32768)` 그대로가 된다. 이것이 바닐라 `#item_id_aux` 규약(ID × 65536 + 데이터)과 맞아 팩이 동작한다. 즉 "`%`가 된다"는 증거가 아니라 우연히 `(T - 0)`과 같은 숫자 변환이다(EXP-38). 이유가 우연이고 개발 빌드에서 `Invalid expression` assert가 날 수 있으므로 같은 결과를 내는 정상 식 `(#form_button_texture - 0)`을 쓴다(EXP-16).

### 2.3 `* 1`에서 `%` 식으로 바뀐 경위 `{확인}`

| 시점 | 커밋 | `#item_id_aux` 식 |
| --- | --- | --- |
| 2023-08-09 | `022ccf2` "Added Blocks and Item Renderer Support + Enchants" | `(#form_button_texture * 1)` |
| 2024-12 ~ 2025-11 | `c80a963`, `010aac1`, `e095704`, `0dac8e2` | 그대로 `* 1` |
| 2026-01-06 | `7dbfd13` "1.21.131 Update — … UI will now display items properly" | 상자 칸을 `%` 식으로 교체 |
| 2026-02-01 | `deddb15` "fix inventory issues" | 인벤토리 칸도 `%` 식으로 교체 |

`* 1`의 피연산자는 버튼 아이콘에서 온 원본 컬렉션 문자열이다. 이 식이 2년 넘게 아이콘을 그리다 1.21.130 무렵 깨졌다. 그래서 문자열 `* 1`의 의미는 그 무렵 바뀌었다(그 전: 숫자 변환, 그 뒤: 빈 문자열)고 보는 것이 자연스럽다 `{추론}` (충돌 C-04의 갱신 근거).

### 2.4 인챈트 비트와 데이터 값

`#item_id_aux`의 하위 16비트는 데이터 값(0~32767)이고 여기에 32768을 더하면 인챈트 반짝임이 켜진다: `ID × 65536 + 데이터 + (인챈트 ? 32768 : 0)`(ANI-23). 데이터 값 표는 `-272 + (1 / 65536)`처럼 하위 16비트에 데이터 값을 넣는다(리스폰 앵커 충전 단계, 레드스톤 신호 세기, 색 막대 등).

### 2.5 바닐라 상수와의 차이 (미해결, C-49)

바닐라 `beacon_screen.json`의 `property_bag` 상수는 네더라이트 주괴 48627712(742 × 65536), 에메랄드 25427968(388), 다이아몬드 17301504(264), 금 17432576(266), 철 17367040(265)이다. 옛 레거시 ID 번호다. Chest-UI 26.40 런타임 표에서 264는 대구, 388은 사탕수수, 742는 보라색 하네스다. 정적 값과 런타임 값이 같은 체계인지는 확인되지 않았다. 비콘 화면을 열어 아이콘을 보면 판정된다.

## 3. 숫자 아이템 ID 표의 변화 `{확인}`

`typeIds.js`와 `forms.js`의 커밋별 값이다(ANI-24, 충돌 C-33 판정 자료).

| 커밋 | 대상 | 밀림 경계 | 사과 | 다이아몬드 | 최대 ID |
| --- | --- | --- | --- | --- | --- |
| `8683ef1` 2025-03-28 | 1.21.70 | `ID < 256` | 278 | 328 | 798 |
| `e095704` 2025-10-01 | 1.21.111 | `ID < 256` | 278 | 328 | 828 |
| `7dbfd13` 2026-01-06 | 1.21.131 | `ID < 256` | 285 | 335 | 840 |
| `24f76f7` 2026-05-18 | 26.20 | `ID < 256` | 285 | 335 | 844 |
| `b5397cd` 2026-06-20 | 26.30 | `ID < 256` | 285 | 335 | 845 |
| `115d95c` 2026-08-14 | 26.40 | `ID < 850` | 880 | 306 | 881 |

- 26.30까지는 번들 17종(257~273), 바람 막대(274), 사과 등이 256 바로 뒤에 있어 256 이상 전부가 커스텀 아이템 수만큼 밀렸다.
- 26.40에서는 밀리는 무리가 표 끝으로 옮겨졌다: 850 `red_shrub`, 851 `shelf_mushroom`, 852~858 창 7종, 859~875 번들 17종, 876 `breeze_rod`, 877 `ominous_trial_key`, 878 `trial_key`, 879 `wind_charge`, 880 `apple`, 881 `glow_berries`(32개). 나머지(다이아몬드 306 등)는 밀리지 않는다.
- Bedrock Wiki의 26.50 표는 852~883(32개)만 밀리고 -1246~851은 안정이다. 26.40의 850·851이 실제로 밀리는 무리인지, Chest-UI가 경계를 2만큼 넓게 잡았는지는 확인하지 못했다.
- 블록(음수 ID)은 커스텀 블록으로 밀리지 않는다.
- 판정: 충돌 C-33은 출처 다툼이 아니라 버전 변화다. 26.30 이하 256, 26.40 850(Chest-UI), 26.50 852(위키).
- 다른 애드온의 커스텀 아이템 수는 `constants.js`에 손으로 적어야 보정이 맞는다. 그래서 가능하면 텍스처 경로를 쓰는 것이 낫다.

## 4. 그 밖의 기법과 문제점

- **커서를 따라가는 툴팁**: hover 컨트롤 안에 `{"type": "custom", "renderer": "hover_text_renderer", "allow_clipping": false, "layer": 30}`을 두고 `#hover_text`에 툴팁 글을 바인딩한다. hover 상태에서만 생성된다(INP-25).
- **따옴표 없는 문자열**: 화로 파일의 `(not ((#title_text - §l§i§t) = #title_text))`, `(%.14s * #form_button_text)`는 따옴표가 있을 때와 같은 결과를 냈다(평가기 `{코드}`, 게임도 받아 왔다는 작동팩 근거). 공백·연산자 문자가 들어가면 끊기므로 따옴표를 쓴다(EXP-36, EXP-39).
- **내구도 막대는 평가기 모델에서 동작하지 않는다**: `"$one": 1.0`, `(($clip_max - #ratio_1) / $clip_max)`는 바인딩 식에 글자 `1.0`이 끼워져 정수가 되고 정수 나눗셈 결과 0이 되어 막대가 늘 가득 찬다. `((99 - #ratio) * .0101)`처럼 점으로 시작하는 리터럴 곱이 안전하다(EXP-40, 충돌 C-48 미해결).
- **다른 서버 폼 팩과 공존 불가**: `long_form`을 같은 경로에서 재선언하므로 upgrader 같은 팩과 함께 켜면 나중 것만 남는다(MOD-20).

### 반영안(미적용)

원본 분석이 가이드에 제안한 새 규칙 후보들이며 아직 가이드에 반영되지 않았다: EXP-38(`%` 식은 나머지가 아니다), EXP-39(따옴표 없는 문자열), EXP-40(실수 변수), COL-31(`collection_index`에 생성 시점 식), ANI-23(인챈트 비트), ANI-24(ID 표 버전 변화), TXT-18(`§z` 보이지 않는 접두), INP-25(커서 툴팁), HOST-34(글자마다 `§`를 붙인 표식), MOD-20(`long_form` 공존 불가), PAT-13(상자형 폼 레시피). 실측이 필요한 것: `%` 식과 `(#v - 0)`의 아이콘 일치와 콘텐츠 로그, 실수 변수 비율, 850·851의 밀림, 비콘 아이콘, +32768의 블록·아이템 반짝임, `§z`의 글꼴별 가시성.

## 5. 엔티티 상자: 실제 아이템이 오가는 창

PocketMine의 CustomSizedInvMenu, Muqsit/InvMenu, bedrock-gophers/inv와 같은 방식이다. 서버가 클라이언트 전용 엔티티를 만들어 그 엔티티의 컨테이너로 상자 창을 열게 한다. 서버 구현이 기대는 클라이언트 동작은 다음과 같다 `{기록}` (출처: 비공개 조사).

1. 보이지 않는 클라이언트 전용 엔티티를 `AddActor`로 보낸다. 메타데이터는 투명·NoAI, `ContainerType` = INVENTORY(-1), `ContainerSize` = 칸 수, 이름 = 창 제목이다. 식별자는 접속 때 보내는 `AvailableActorIdentifiers`에 덧붙이면 되고 엔티티 정의 파일은 필요 없다.
2. 이어서 `ContainerOpen`(`ContainerTypeContainer` + `ContainerEntityUniqueID`)과 내용물을 보내면 상자 창이 열린다.
3. 엔티티 상자가 열려 있는 동안 클라이언트는 폼이 닫히거나 블록 클릭과 겹칠 때 창 255 닫기를 보낸다. 서버는 이것을 무시해야 창이 유지된다. 같은 인벤토리를 다시 열면 무시한다(블록 연타 대비).
4. 클라이언트는 창이 닫히는 중에 온 열기를 무시한다. 상자에서 다른 상자로 바꿀 때(닫힌 지 1초 안)는 `NetworkStackLatency` 왕복으로 클라이언트가 닫기를 처리했는지 확인한 뒤 엔티티를 만들고 연다.
5. 플레이어가 움직여 엔티티와 멀어지면 클라이언트가 창을 닫는다. 엔티티를 플레이어에 탑승 링크로 붙이면 움직여도 닫히지 않는다. 탑승 링크를 쓰지 않으려면 열린 동안 엔티티를 플레이어 위치로 옮긴다.
6. 이미 열린 창에 `ContainerOpen`이 또 오면 클라이언트는 `PacketViolationWarning`(type -1)으로 답한다.
7. 팩이 없으면 27칸 상자로만 보인다. 그래서 리소스팩은 필수(`ResourcesRequired`)로 보낸다.

### 5.1 Dragonfly에서의 구현 (한 Dragonfly 기반 서버 `common/chestui`)

Dragonfly를 패치하지 않고 패킷 훅(`hook.Wrap`)으로 세션에 닿는다. 훅은 서버 리스너를 감싸 연결마다 양방향 패킷이 훅을 먼저 지나게 하며(바꾸기·버리기 가능), 연결이 끊기면 닫힘 훅이 돈다. 세션의 비공개 메서드(`writePacket`, `sendInv`, `nextWindowID`, `closeCurrentContainer`)는 `go:linkname`, 비공개 필드(`openedWindow` 등)는 리플렉션으로 쓴다. 이름이 바뀌면 테스트가 깨지도록 해 둔다.

- 세션의 열린 창(`openedWindow`)을 그 인벤토리로 두므로 아이템 이동은 Dragonfly의 `ContainerLevelEntity → openedWindow` 경로를 그대로 탄다.
- 창이 닫히면 엔티티를 지우고 닫힘 콜백을 부른다. 서버가 닫으면 그 트랜잭션에서, Dragonfly가 닫으면(클라이언트 닫기 응답 `ContainerClose`를 훅이 봄) 플레이어 트랜잭션에서, 접속이 끊기면 닫힘 훅에서 플레이어 없이 부른다. 콜백의 플레이어와 트랜잭션은 접속이 끊겨 닫힌 경우 `nil`이다.
- 단계별 설정(InvMenu의 `PlayerWindowDispatcher` 단계를 하나씩 켠다). 기본은 `Ride`만 켜져 있다. 셋을 모두 켜면 상자가 바로 닫히므로 문제를 좁힐 때 하나씩 켠다.

| 설정 | 동작 |
| --- | --- |
| `Ride` | 엔티티를 플레이어에 탑승 링크로 붙인다. 기본 켜짐 |
| `WaitLatency` | `AddActor` 뒤 `NetworkStackLatency` 응답을 받고 연다(최대 1초) |
| `Retry` | 클라이언트가 초과 열기에 대한 `PacketViolationWarning`(type -1)으로 확인할 때까지 매 틱 닫기 + 열기 재전송(최대 20회). 그동안 그 창의 닫기는 무시 |
| `Debug` | 열기·닫기·클라이언트 닫기·위반 경고를 INFO 로그로 남긴다 |

- 사용: 실제 아이템이 오가는 창고 타입(`chestui.Storage`)은 여러 명이 같이 봐도 변경이 모두에게 보인다. 이동 검증은 `Inventory().Handle`, 변경 반영은 `OnChange`로 한다. 버튼 동작은 플레이어의 현재 월드 트랜잭션에서 실행된다. 열린 창은 `chestui.Close(p)`로 닫고, 월드·인스턴스를 옮기기 전에 닫는다. 클라이언트가 보낸 것을 다 처리한 뒤에 할 일은 `NetworkStackLatency` 왕복(최대 1초)으로 기다린다.

### 5.2 크기를 고르는 리소스팩

tedo0627/InventoryUIResourcePack(MIT, 서버 문서가 이렇게 밝힘. 저장소의 LICENSE는 직접 열어 보지 못했다)은 제목 앞의 `§{줄 수 1~6}§{스크롤 0/1}` + `§r` 9개를 읽어 창 크기를 정한다. 54칸을 넘으면 6줄 높이로 스크롤한다. 접두어 없는 일반 상자는 바닐라 화면 그대로다. 서버는 이 접두어를 제목에 붙여 엔티티 상자를 연다. 제목에 서식 코드가 붙으므로 표식 마지막이 색 코드면 뒤에 `§r`을 붙여야 창 제목이 물들지 않는다.

### 5.3 모두 꺼내기·모두 넣기 버튼 (Quick Container 기법)

창고 창 옆에 버튼 하나를 두고 그 밑에 칸 수만큼 보이지 않는 버튼을 겹쳐 둔다. 각 버튼의 누름을 그 칸의 바닐라 빠른 이동(`button.container_auto_place`, `consume_event: false`)으로 바꾸면 클릭 한 번이 모든 칸의 쉬프트 클릭이 된다. 서버에는 칸마다 평범한 아이템 이동 요청이 오므로 서버 코드가 필요 없다. 꺼내기는 창고 칸(`$quick_container_size`), 넣기는 인벤토리 27칸(`$quick_put_hotbar`면 핫바까지)을 옮긴다. "있는 것만 넣기"는 창고 앞 54칸 중 어느 칸에 같은 아이템(`#item_id_aux`)이 있는 인벤토리 칸만 옮긴다. JSON UI에는 반복이 없어 창고 칸마다 이름 붙은 컨트롤(`sg_quick_c<n>`)과 인벤토리 칸마다 54개의 비교 바인딩을 생성기가 파일로 써 둔다. 숨은 버튼이 `source_control_name`으로 그 칸 컨트롤의 `#item_id_aux`를 읽어(화면 루트부터 첫 일치) 같은 것이 있을 때만 보인다. 툴팁은 버튼 hover 상태 안의 라벨이라 번역 키가 풀린다(`common.hover_text`의 `#hover_text`는 번역되지 않는다). 아이콘은 바닐라 `up_arrow`·`down_arrow`·`store_filter_icon`이다 (출처: 비공개 조사).

## 6. 규칙 요약

1. 넣고 빼는 것이 없으면 폼으로, 실제 아이템이 오가면 엔티티 상자로 만든다.
2. 폼 방식 상자는 제목 플래그 + 크기별 템플릿 + 고정 인덱스 슬롯이고, 쓰지 않는 크기는 `ignored`로 생성을 막는다.
3. 아이콘 숫자는 `(#form_button_texture - 0)`으로 받고 `ID × 65536 + 데이터 + 32768(인챈트)`로 만든다. ID 표는 버전마다 다시 만든다.
4. 엔티티 상자는 서버가 닫기 255를 무시하고, 상자 전환은 `NetworkStackLatency`로 확인하고, 탑승 링크로 엔티티를 붙인다.
5. 같은 `server_form.json`을 재선언하는 팩과는 공존하지 못한다. 감싸기를 쓴다.
