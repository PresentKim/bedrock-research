이 페이지는 "인벤토리처럼 보이는 화면"을 서버가 만들 때 필요한 것을 모은다. 바닐라 화면의 조각과 값(그림, 색, 크기), 아이템 칸 위에 배지와 등급 테두리를 그리는 칸 장식, 상자 창을 화로 같은 블록 작업 창으로 바꾸는 법, 그리고 이런 화면이 서버에서 아이템·블록·이름·레시피를 보낼 때 보이는 클라이언트 동작이다. 상자 창을 여는 방법은 [상자 UI](./chest-ui.mdx)에 있다.

## 1. 바닐라 화면의 그림과 값

바닐라 `resource_pack/ui`의 `furnace_screen_pocket.json`, `inventory_screen.json`, `ui_common.json`, `ui_template_tabs.json`, `_global_variables.json`에서 읽은 것이다(출처: bedrock-samples 1.26.50.4, 사실만 옮김). **그림은 클라이언트에 이미 있으므로 팩은 `textures/ui/...` 경로로 가리키기만 하고 파일을 복사하지 않는다** (출처: 비공개 조사).

| 조각 | 바닐라 그림·컨트롤 |
| --- | --- |
| 창 바탕(밝은 회색) | `textures/ui/dialog_background_opaque` (`common.common_panel`의 `$dialog_background`) |
| 위쪽 컨트롤 막대 | `textures/ui/toolbar_background` (`common.toolbar_background_image`, 크기 `["100%cm", "100% + 8px"]`) |
| 닫기 버튼(밝은 바탕) | `common.light_close_button`: `close_button_default_light`·`_hover_light`·`_pressed_light`, 그림 15×15, 버튼 21×21 |
| 도움말 버튼 | `common.help_button`(15×15): `how_to_play_button_default_light`·`_hover_light`·`_pressed_light` |
| 위 탭 | `TabTopBack`(안 고른 탭), `TabTopFront`(고른 탭), 호버 `...Hover`, 양 끝 `...LeftMost`·`...RightMost`. 옆 탭은 `TabLeft*`·`TabRight*`. 아이콘만 있는 탭은 24×25 |
| 레이아웃 토글 | `common.layout_toggle`(25×18), `recipe_book_button_borderless_light...` |
| 아이템 칸 | `textures/ui/cell_image`, 선택 `highlight_slot`·`pocket_ui_highlight_slot` |
| 레시피 목록 안쪽 | `recipe_book_pane_bg`, `recipe_back_panel` |
| 검색 칸 | `edit_box_indent`(`_hover`) |
| 스크롤 | `ScrollHandle`, `ScrollRail`, `ScrollGutterWithBG` |
| 구분선 | `dialog_divider`, `divider2`, `divider3` |

글자색 변수는 다음과 같다.

| 변수 | 값 |
| --- | --- |
| `$pocket_title_text_color` | `[0.3, 0.3, 0.3]`(제목, 그림자 없음, 가운데 정렬) |
| `$tab_unchecked_text_color` | `[0.8784, 0.8784, 0.8784]`(안 고른 탭, 밝음) |
| `$tab_checked_text_color` | `[0.3, 0.3, 0.3]`(고른 탭) |
| `$pocket_item_details_color` | 흰색(툴팁·상세 글) |

안 고른 탭 그림은 어둡고 고른 탭 그림은 밝다. 구조에서 배울 점은 다음과 같다.

- **탭은 토글이다**(`common_tabs.base_tab` 안의 `common.toggle`). 상태(unchecked, unchecked_hover, locked, checked 등)마다 같은 `tab_panel`에 그림과 글자색·아이콘색 변수만 바꿔 넣는다. 서버가 탭을 다시 보내는 화면에서는 토글 대신 "선택된 탭" 스타일로 같은 모양을 낸다.
- **컨트롤 막대**는 가로 스택에 패딩, 레이아웃 토글들, 도움말, 닫기, 패딩 순서다(`inventory_screen.json`의 `toolbar_panel`). 닫기 칸 폭은 15, 도움말은 `100%c`.
- 창 제목은 `anchor center`로 가운데에 쓴다. 헤더 높이는 28(`furnace_screen_pocket.json`의 `header`).
- 슬롯은 `common.pocket_ui_container_item`로 `$background_images`에 `cell_image`를 둔다. 이름 지을 때 `$item_collection_name`으로 컬렉션을 가리킨다.

서버 폼 모양을 바닐라 인벤토리처럼 맞춰 그린 서버는 이 값들을 그대로 쓴다: 창은 `dialog_background_opaque`, 컨트롤 막대는 `toolbar_background`, 닫기는 `light_close_button`, 도움말은 `how_to_play_button_*_light`, 위 탭은 `TabTopBack`/`TabTopFront`, 칸은 `cell_image`.

## 2. 칸 장식: 아이템 이름 속 표식으로 배지 그리기 `{기록}`

### 2.1 원리

JSON UI는 칸의 아이템 데이터(종류, 개수, 내구도)를 읽지 못한다. 칸 컬렉션에서 읽을 수 있는 것은 `#hover_text`(호버 상자에 보일 글: 이름 + 설명)뿐이다. 그래서 **아이템 이름 안에 화면에 보이지 않는 표식을 넣고**, 팩의 바인딩이 그 표식을 찾는다.

보이지 않는 표식을 만드는 방법은 `§k`(깜빡이는 글자) 바로 뒤에 `§r`을 두는 것이다. `§k`가 `§r`로 바로 풀려 화면에 아무것도 남지 않는다 (출처: 비공개 조사).

| 표식 | 모양 | 뜻 |
| --- | --- | --- |
| 등급 | 이름 앞 `§k§r§a` / `§k§r§b` / `§k§r§d` / `§k§r§6` | 고급 / 희귀 / 영웅 / 전설. 뒤에 이어지는 색 코드가 이름도 같은 색으로 칠한다 |
| 전면 | 이름 뒤 `§k§l§r§N§r` (N = 1~6) | 1~4 단계 점(철·금·다이아·보라), 5 경고(빨간 느낌표), 6 잠금 |

표식끼리는 서로의 일부가 아니게 만든다(예: 등급과 전면이 서로의 부분 문자열이 되지 않게 확인).

### 2.2 바인딩

표식이 있으면 1, 없으면 0인 값에 번호를 곱해 더해서 번호 하나를 만든다. 칸 하나에 컨트롤 하나(앞), 바인딩 넷이다.

```json
{
  "binding_type": "view",
  "source_property_name": "(not ((#hover_text - '§k§l§r§1§r') = #hover_text)) * 1",
  "target_property_name": "#tier_1"
}
```

여러 표식의 값을 더해 `#tier` 같은 번호를 만들고, `('textures/ui/my_pack/front_' + 번호)`로 텍스처를 고르고, `번호 > 0`일 때만 보이게 한다. 식에 변수를 넣지 않고 표식을 글자로 적는다.

### 2.3 칸 템플릿 두 곳에 끼운다

- `container_item`(`ui_common.json`): 상자·블록 작업 창·인벤토리 보기 등.
- `inventory_container_item`(`inventory_screen.json`): 가방·조합 칸. 이 쪽은 따로 `controls`를 가져 앞쪽 수정이 미치지 않는다.

둘 다 `insert_front`로 컨트롤을 끼운다. 층(layer)은 칸 배경 1, 아이템 7이라 뒤 장식은 6, 앞 장식은 9에 둔다.

### 2.3.1 한계

- PC의 호버 상자는 엔진(`hover_text_renderer`)이 그려서 틀을 바꿀 수 없다. 이름 색만 등급 색이 된다. 터치 UI의 선택 아이템 말풍선(`item_panel_image`) 위에는 등급 테두리를 겹쳐 그릴 수 있다.
- 한 칸에 컨트롤이 하나 늘어 칸 수에 비례해 비용이 든다. 인벤토리 보기(72칸)처럼 칸이 많은 창은 여는 시간을 잰다.
- 표식의 색 코드는 뒤의 글에 이어지므로 표식이 든 이름을 문장 중간에 넣으면 색이 번진다. 이름을 비교·검색하는 서버 코드는 색 코드를 건너뛰거나 표식을 먼저 지운다.
- Ore UI(DDUI) 화면의 칸은 같은 표식을 팩이 아니라 페이지 CSS로 처리한다. 툴팁 첫 줄의 희귀도 표식을 서버 모듈이 떼고 등급 번호를 페이지에 보내 칸의 툴팁 테두리를 등급 색으로 칠한다. 단계 점·배지는 그리지 않는다.

### 2.4 서버 쪽 규약

- 표식을 붙이는 함수(등급, 전면 번호, 이름 -> 이름), 지우는 함수, 읽는 함수 셋을 둔다.
- 이름이 직접 없는 고정 아이템은 언어 파일(`texts/<언어>.lang`)의 이름에 표식을 넣는다. 언어 파일을 코드에서 생성하면 등급과 단계가 어긋나지 않는다.
- 스택마다 이름이 있는 아이템은 이름을 만들 때 붙인다.
- 표식 없는 이름을 돌려주는 함수를 따로 두고, 표식은 칸 위의 이름에만 쓴다.
- 팩을 켜고 끄는 설정을 둔다. 바닐라 칸 템플릿을 바꾸므로 화면이 이상하면 끈다(표식은 이름에 남아도 보이지 않는다).
- 새 배지를 늘리려면 번호, `front_N.png`, 팩의 식 두 곳을 같이 늘린다. 텍스처는 9-슬라이스 `.json`을 두고 PNG를 바꿔도 된다.

## 3. 블록 작업 창 `{기록}`

화로처럼 입력·진행·출력 칸이 있는 커스텀 블록 창이다. 엔티티 상자 창(27칸)을 그대로 쓰면서 제목 표식으로 블록별 레이아웃을 골라 입력·진행·출력·회수 칸만 보이게 한다.

- 제목 표식 `§d§m§<n>`으로 분기한다. 마지막 코드가 색 코드라 서버가 표식 뒤에 `§r`을 붙인다. PC 화면에만 있고, 모바일은 크기 지정 상자 그대로 보인다.
- 진행도 칸에는 `progress_0`~`progress_10` 아이템(채워지는 화살표)이 들어가 화살표가 차오르는 것처럼 보인다.
- 창 오른쪽 위 어두운 컨트롤 막대에 닫기 버튼 왼쪽으로 정보 아이콘이 칸 배경 없이 18×18로 놓이고 툴팁이 블록 설명이다.
- 모양은 바닐라 화로 화면과 같다. 밝은 회색 창(`dialog_background_opaque`), 칸(`cell_image`), 제목은 창 위 가운데 4px 아래. 출력이 하나인 창의 출력 칸은 화로 결과 칸처럼 26×26이다. 진행도 칸은 칸 배경 없이 그림만이고, 화살표·링·배터리의 빈 부분은 바닐라 화로 화살표(`arrow_inactive`)와 같은 밝은 회색, 찬 부분은 흰색·주황이다.
- 모두 꺼내기·모두 넣기는 [상자 UI](./chest-ui.mdx)의 5.3절 방식이다. 블록 작업 창은 식으로 꺼낼 칸을 거른다.
- `collection_index`는 `collection_name`을 가진 요소의 바로 아래 자식에서만 먹는다. `collection_panel` 안의 `stack_panel` 자식에 쓰면 "Unknown property [collection_index]" 오류가 나므로 `stack_panel` 자체에 `"collection_name": "container_items"`를 준다.
- 팩토리 `control_ids`에 변수를 쓰면 "UI control reference not found" 오류가 난다. `grid_item_template`·상속한 `$scrolling_content` 같은 자리도 변수 대신 컨트롤을 따로 정의한다.

## 4. 인벤토리 보기와 엔티티 상자 응용

- **인벤토리 보기**(다른 플레이어의 인벤토리를 상자 창으로, 72칸, 8줄, 스크롤): 인벤 27 + 핫바 9 / 갑옷 4 + 보조손 1 / 엔더상자 27. 대상이 같은 월드에 있으면 실시간으로 맞춘다(1초마다 + 이동 직전 동기화, 화면과 대상이 다르면 그 이동은 취소). 접속하지 않은 대상은 저장된 상태를 잠그고 고치며, 잠글 수 없으면 읽기 전용으로 연다.
- 메뉴(넣고 빼는 것이 없는 화면)는 상자가 아니라 폼으로 만든다(Ore UI 화면이면 DDUI).

## 5. 서버가 아이템·블록·이름을 보낼 때의 클라이언트 동작

서버 개발에서 모은 동작이다. 표기는 `{실측}`(게임에서 확인)과 `{기록}`(서버 구현이 기대는 동작으로 문서에 적혀 있으나 측정 조건이 남지 않음)이다 (출처: 비공개 조사).

### 5.1 이름과 번역

- **번역 키를 아이템 이름에** `{실측}`: 아이템의 커스텀 이름과 설명에 번역 키를 넣으면 툴팁에 글자 그대로 보였다. `item.diamond.name`, `%item.diamond.name`, `%item.diamond.name%` 모두, 한 줄 전체로 넣어도 글 중간에 넣어도 같았다(1.26.50). 번역이 필요하면 rawtext 번역(`{ translate: ... }`)을 쓴다.
- **구형 번역 키** `{기록}`: 많은 블록은 `tile.<현대 ID>.name`으로 이름을 찾지 못한다. 이름은 구형 키에 있다(`oak_planks`는 `tile.planks.oak.name`, `oak_sapling`은 `tile.sapling.oak.name`). 그냥 보내면 키 글자나 식별자가 보인다. `bedrock-samples`의 `en_US.lang`에서 ID를 제목 형태("Oak Planks")로 바꿔 영어 값과 짝지으면 표를 만들 수 있고, 약 190개(교육판·테스트 블록·`element_*` 등)는 짝이 없다.
- **언어 대체** `{기록}`: 클라이언트에서 `en_US.lang`은 다른 모든 언어의 대체다. 팩의 블록·아이템 이름은 `en_US.lang`에도 둔다.
- **번역을 거치면 `%`가 사라진다** `{실측}`: 스코어보드 줄 라벨이 번역을 거치면 `%`가 없어졌다. `localize: false`.

### 5.2 아이템·블록의 그림

- **손에 쥐는 모양** `{기록}`: 막대기와 뼈는 3인칭 손에서 도구처럼 쥐는 모양으로 그려지지만 바닐라 데이터에 `minecraft:hand_equipped`가 없다. 클라이언트 코드에 박혀 있다. 데이터에서 이 구성 요소가 참인 것은 `breeze_rod`와 창(`*_spear`)뿐이다.
- **블록 앞에 아이템 보이기** `{기록}`: 아이템 엔티티는 클라이언트에서 늘 돌고 흔들리며, 가까운 같은 아이템과 합쳐지고, 아래 호퍼에 빨려 든다. 대신 아이템을 손에 든 커스텀 엔티티(`MobEquipment`, `enable_attachables`)를 쓴다.
  - 본 구조는 `root > body > rightarm > rightitem_pose > rightitem_handheld > rightitem`, `body > leftarm > leftitem`이다. 3인칭 손 자세를 상쇄하는 값은 `rightitem_pose` pivot [-1, -6, -6], rotation [-75, -12, -16], `leftitem` pivot [5.5, 1, -3], rotation [-20, 45, 0]이다.
  - 엔티티에서 `query.is_item_name_any('slot.weapon.mainhand', 0, ...)`로 주 손 아이템을 보고 손에 쥐는 모양 아이템만 따로 돌려 보정할 수 있다. 3인칭 아이템 변환 값은 공개 자료에 없어 막대기는 크기 0.65가 맞았다.
  - 클라이언트 엔티티 텍스처는 아이템마다 고를 수 없다(렌더 컨트롤러 배열과 변형 값이 아이템 수만큼 필요).
  - 꽉 찬 큐브 블록은 손에서 입체로 그려져 각도가 다르다. 큐브 블록은 보조 손, 그 밖은 주 손에 쥐여 맞췄다.
- **부수기 균열과 파편** `{기록}`: 클라이언트는 부수기 균열과 파편을 블록 지오메트리 큐브 위에 그린다. 큐브가 작거나 투명하면 보이지 않고, 파편은 텍스처 픽셀에서 색을 딴다.
- **블록 아이템 그림** `{기록}`: 블록 아이템은 인벤토리·폼에서 블록 모양 그대로 그려지고 칸에 꽉 차게 키워진다. 9/16 크기로 보이게 하려면 투명한 16픽셀 틀 큐브 안에 넣는다. 인벤토리에서는 남쪽 면이 보이므로 정면을 남쪽에 둔다. 아이템 아이콘 텍스처는 따로 없어도 된다.
- **블록 상태 순서** `{기록}`: 클라이언트는 블록 런타임 ID를 블록 상태 순서대로 짝짓는다. 상태를 하나로 합쳐 번호로 담으면 서버와 순서가 어긋날 일이 없다.
- **엔티티 모델 방향** `{기록}`: 엔티티 모델은 월드와 반 바퀴 돌아 그려진다(모델 앞면이 북쪽). 월드 좌표를 모델 좌표로 옮길 때 z 부호만 바꾸고 x는 그대로 둔다.
- **블록 텍스처 애니메이션** `{기록}`: `textures/flipbook_textures.json`의 항목 하나가 `terrain_texture.json`의 타일 하나를 움직인다. 이미지는 세로 띠(폭 16, 높이 16 × 프레임 수)이고 `ticks_per_frame`, `frames`(순서 배열), `blend_frames`(기본 켬)를 준다. 커스텀 블록은 `material_instances`의 텍스처가 그 타일이면 다른 컴포넌트 없이 움직인다. 두 파일은 팩끼리 병합된다. 모든 블록이 같은 박자로 움직이고 켜고 끄기는 블록 상태 퍼뮤테이션으로 텍스처를 바꿔서 한다. 아이템 아이콘에서는 판에 따라 움직이지 않는다 (출처: bedrock-wiki의 flipbook 문서).
- **상호작용 블록** `{기록}`: 서버가 상호작용 블록(Dragonfly `Activatable`)으로 보낸 블록 위에서는 클라이언트가 든 블록을 놓는 것을 예측하지 않는다.
- **디버그 셰이프 글자 방향** `{기록}`: `Rotation`은 [pitch, yaw, roll] 도 단위이고 yaw 0이면 북쪽에서 읽힌다. 엔티티 yaw(남 0, 북 180)와 기준이 달라 그대로 쓰면 남북이 뒤집힌다. 라디안 값을 넣으면 사실상 0도다.

### 5.3 레시피와 성능

- **레시피 목록 바꾸기** `{기록}`: 클라이언트는 서버가 `CraftingData`로 보낸 레시피만 안다(레시피 책, 조합 칸 결과). 이 패킷을 `ClearRecipes`로 다시 보내면 언제든 목록을 통째로 바꿀 수 있어 게임 중에 레시피를 열 수 있다.
- **레시피 책** `{기록}`: 레시피 책은 결과가 창작 인벤토리 목록(`CreativeContent`)에 있고 블록 상태까지 같은 레시피만 나열한다. 바닐라 `crafting_data.nbt`의 블록 결과는 창작 항목과 상태가 다른 것이 많아(상자, 퇴비통 등 30여 종) 런타임 ID를 맞춰 주지 않으면 책에서 빠진다.
- **클라이언트가 먼저 무거워진다** `{실측}`: 표시용 엔티티 1000개와 커스텀 블록 모델 수천 개가 있는 월드에서 서버 틱은 예산의 20% 아래로 여유가 있었지만 클라이언트가 렉을 일으켰다. 렌더링 부담으로 보인다 `{추론}`.
- 칸과 폼 컨트롤은 비용이다. 칸이 많은 화면은 여는 시간을 재고, 보내는 레코드 수를 줄인다([재스킨](./reskinning-server-forms.mdx)의 5절).

## 6. 규칙 요약

1. 바닐라 그림은 복사하지 않고 `textures/ui/...` 경로로 가리킨다.
2. 칸 위의 정보는 아이템 이름 속 `§k§r` 표식으로 싣고 `#hover_text`에서 읽는다. 칸 템플릿은 두 곳(`container_item`, `inventory_container_item`)에 끼운다.
3. 표식이 든 이름을 문장 중간에 넣지 않는다.
4. 서버 이름·설명에 번역 키를 직접 넣지 않는다. rawtext 번역을 쓴다.
5. 칸 수에 비례하는 비용을 열기 시간으로 잰다.
