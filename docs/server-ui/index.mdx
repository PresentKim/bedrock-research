서버가 플레이어 화면에 무엇을 띄우는 방법은 크게 네 가지다. 어느 것을 쓸지는 플레이어가 응답해야 하는지, 아이템이 오가는지, 서버가 Script API를 쓸 수 있는지에 따라 정해진다.

| 하고 싶은 일 | 수단 | 페이지 |
| --- | --- | --- |
| 버튼 목록·확인창·입력 폼을 띄우고 응답을 받는다 | 서버 폼(`ActionFormData`, `MessageFormData`, `ModalFormData`) 또는 폼 JSON | [서버 폼 API와 폼 종류](./modal-forms.mdx) |
| 모달 폼에 체크박스 목록을 넣는다 | 폼 JSON의 `multiselect` 행(Script API에는 없음) | [multiselect](./multiselect.mdx) |
| 폼 하나를 상점·표·트리 같은 다른 모양으로 그린다 | 리소스팩의 `server_form.json` 재스킨 | [서버 폼 재스킨](./reskinning-server-forms.mdx) |
| 상자 모양 GUI를 띄우거나 아이템이 오가는 창을 연다 | Chest-UI(폼 방식), 엔티티 상자 | [상자 UI](./chest-ui.mdx) |
| 인벤토리처럼 보이는 화면, 칸 배지, 블록 작업 창을 만든다 | 바닐라 화면 값, 칸 장식, 클라이언트 동작 | [인벤토리형 메뉴](./inventory-menus.mdx) |
| 플레이어가 응답하지 않는 HUD 요소를 그린다 | 타이틀·부제목·액션바·스코어보드 채널 | [HUD와 타이틀 채널](./hud-and-titles.mdx) |

## 공통 원리

- 폼 JSON과 타이틀은 모두 **서버에서 팩으로 가는 글 채널**이다. 서버는 화면 모양을 모르고 글(제목, 본문, 버튼 글, 아이콘 경로)을 보내며, 팩이 표식을 읽어 모양을 정한다.
- 서버 폼의 모양은 바닐라 `server_form.json`이 그린다. 이 화면은 JSON UI 방식이다. 새 방식(Ore UI)으로 그리는 `CustomForm`·`MessageBox`(DDUI)는 [DDUI 서버 가이드](../ore-ui/ddui-server-guide.mdx)에 있다.
- 서버 소프트웨어(Dragonfly, PocketMine, Nukkit)는 Script API가 없으므로 같은 화면을 패킷과 JSON으로 직접 만든다. 이 섹션의 `{실측}` 항목 대부분이 그런 서버에서 나왔다.
- 검증 수준은 `{실측}`(게임에서 확인), `{코드}`(바이너리·타입 정의·평가기에서 읽음), `{바닐라}`(바닐라 팩에서 읽음), `{확인}`(저장소 파일·커밋에서 확인), `{기록}`(문서에만 있고 측정 조건이 남지 않음), `{추론}`으로 적는다.
