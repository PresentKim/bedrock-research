HUD는 게임 중 대부분의 시간 동안 보이는 화면이다. 서버 폼과 달리 플레이어가 응답하지 않고, 서버는 화면에 글만 흘려 보낸다. 그래서 HUD에 커스텀 요소(토스트, 바라보는 블록 정보 패널, 상태 줄)를 그리려면 서버가 **타이틀·부제목·액션바·스코어보드**라는 기존 글 채널에 데이터를 실어 보내고, 리소스팩의 `hud_screen.json`이 그 글을 읽어 그림으로 바꾼다. 이 페이지는 채널, 요소 추가법, 데이터 싣는 형식, 그리고 실제 사례를 정리한다.

## 1. 데이터 채널

| 채널 | Script API | 팩이 읽는 바인딩 | 특징 |
| --- | --- | --- | --- |
| 타이틀 | `player.onScreenDisplay.setTitle(title, options?)` | `#hud_title_text_string` | 가운데에 크게 뜨는 글. 한 번에 하나, 다른 기능과 공유 |
| 부제목 | `setTitle`의 `options.subtitle`, 이후 `updateSubtitle(text)` | 제목 팩토리가 주는 변수 `$var_subtitle_text`, 바인딩 `#hud_subtitle_text_string` | 타이틀 아래 글 |
| 액션바 | `setActionBar(text)` | 액션바 글 바인딩 | 타이틀 아래, 핫바 위 글 |
| 스코어보드 사이드바 | `/scoreboard objectives setdisplay sidebar` | `scoreboard_players` 컬렉션 | 줄은 바꾸기 전까지 남는다 |

(출처: ms-learn ScreenDisplay, private-research.) 서버 소프트웨어(Dragonfly 등)는 `SetTitle`·`SetSubTitle` 패킷이나 `titleraw` 명령으로 같은 채널을 쓴다.

### 1.1 Script API: `ScreenDisplay`

`player.onScreenDisplay`는 `ScreenDisplay`다 (출처: ms-learn, 문서 커밋 `a9fd1c0`).

| 메서드 | 뜻 |
| --- | --- |
| `setTitle(title, options?)` | 타이틀을 띄운다. 빈 문자열이면 지운다. `title`은 문자열·`RawMessage`·그 배열 |
| `updateSubtitle(subtitle)` | 이전에 `setTitle`로 띄운 부제목만 바꾼다 |
| `setActionBar(text)` | 액션바 글(타이틀 아래, 핫바 위) |
| `setHudVisibility(visible, hudElements?)` | HUD 요소 숨기기·복원. `HudVisibility.Hide = 0`, `Reset = 1` |
| `hideAllExcept(hudElements?)` | 나열한 것만 남기고 모두 숨김 |
| `resetHudElementsVisibility()` | 모두 기본으로 되돌림 |
| `getHiddenHudElements()` | 숨겨진 요소 목록 |
| `isForcedHidden(hudElement)` | 해당 요소가 강제로 숨겨졌는지 |

`TitleDisplayOptions`의 속성이다.

| 속성 | 뜻 |
| --- | --- |
| `fadeInDuration` | 나타나는 시간(틱, 초당 20틱) |
| `stayDuration` | 머무는 시간(틱) |
| `fadeOutDuration` | 사라지는 시간(틱) |
| `subtitle?` | 부제목 |

`HudElement`는 `PaperDoll`(0), `Armor`(1), `ToolTips`(2), `TouchControls`(3), `Crosshair`(4), `Hotbar`(5), `Health`(6), `ProgressBar`(7), `Hunger`(8), `AirBubbles`(9), `HorseHealth`(10), `StatusEffects`(11), `ItemText`(12)다. 이 메서드들은 제한 실행 모드에서 호출할 수 없고, `setTitle`은 `ArgumentOutOfBoundsError`·`InvalidEntityError`·`RawMessageError`를 던질 수 있다.

```js
const d = player.onScreenDisplay;
d.setTitle("CUSTOMHUD:toast:ready", {
  fadeInDuration: 0, stayDuration: 60, fadeOutDuration: 10,
  subtitle: "부제목"
});
d.updateSubtitle("바뀐 부제목");           // 이후 부제목만 갱신
d.setHudVisibility(HudVisibility.Hide, [HudElement.PaperDoll, HudElement.Armor]);
```

HUD 요소 숨기기(`SetHud`)는 바닐라 HUD만 숨긴다. **리소스팩이 HUD에 더한 요소는 남는다** `{기록}` (출처: 비공개 조사).

## 2. HUD에 요소 추가하기

HUD 화면(`hud_screen.json`)에 요소를 넣는 기본은 `root_panel`에 `modifications`로 컨트롤을 끼우는 것이다. `root_panel`은 HUD에 보이는 거의 모든 것을 담은 `panel`이다 (출처: bedrock-wiki, 추가 HUD 요소 문서).

```json
"hud_square": {
	"type": "image",
	"texture": "textures/ui/Black",
	"anchor_from": "top_middle",
	"anchor_to": "top_middle",
	"size": [ 64, 64 ],
	"offset": [ 0, 4 ]
},
"hud_text": {
	"type": "label",
	"text": "hud text",
	"anchor_from": "top_right",
	"anchor_to": "top_right",
	"offset": [ -4, 4 ]
},
"root_panel": {
	"modifications": [
		{
			"array_name": "controls",
			"operation": "insert_front",
			"value": [
				{ "hud_square@hud.hud_square": {} },
				{ "hud_text@hud.hud_text": {} }
			]
		}
	]
}
```

- `value`에 나열한 요소의 네임스페이스(`@hud.hud_square`)는 요소가 정의된 파일의 네임스페이스에 맞춘다. 요소를 `scoreboards.json`의 `scoreboard` 네임스페이스에 정의했다면 `@scoreboard.hud_square`다.
- 요소가 많으면 `panel`로 묶어(`hud_elements_panel`) 그 패널 하나만 `root_panel`에 넣는다. 묶는 패널에 `size`를 주지 않으면 부모(`root_panel`)의 크기를 물려받아 자식의 앵커·퍼센트 크기가 HUD 화면 기준으로 동작한다.
- `insert_front`는 앞(아래 층), `insert_back`은 뒤(위 층)에 넣는다.

## 3. 글을 읽어 그림으로 바꾸기

### 3.1 숫자 한 자리로 그림 고르기

타이틀이 `1`~`5`일 때 해당 그림을 보이려면 컨트롤 다섯 개를 따로 평가하지 말고 하나로 합친다 (출처: bedrock-wiki, 모범 사례 문서).

```json
{
  "binding_type": "view",
  "source_property_name": "(((#hud_title_text_string * 1) > 0) and ((#hud_title_text_string * 1) < 6))",
  "target_property_name": "#visible"
},
{
  "binding_type": "view",
  "source_property_name": "('textures/wiki/ui/example_' + #hud_title_text_string)",
  "target_property_name": "#texture"
}
```

### 3.2 키워드가 있을 때만 갱신하고 값을 보존하기 (Preserve Title Texts)

타이틀은 명령이 올 때마다 바뀌므로, 요소가 특정 키워드가 든 글에만 반응하고 나머지는 무시하게 하는 컴포넌트가 필요하다. 아래 컴포넌트는 `property_bag`로 인스턴스마다 자기 "기억"(`#preserved_text`)을 가져 같은 화면에 여러 번 써도 충돌하지 않는다 (출처: bedrock-wiki, CC BY 4.0).

```json
"preserved_title_display": {
    "$update_string": "update",
    "type": "label",
    "text": "#text",
    "controls": [
        {
            "data_control": {
                "type": "panel",
                "size": [0, 0],
                "property_bag": { "#preserved_text": "" },
                "bindings": [
                    { "binding_name": "#hud_title_text_string" },
                    {
                        "binding_name": "#hud_title_text_string",
                        "binding_name_override": "#preserved_text",
                        "binding_condition": "visibility_changed"
                    },
                    {
                        "binding_type": "view",
                        "source_property_name": "(not (#hud_title_text_string = #preserved_text) and not ((#hud_title_text_string - $update_string) = #hud_title_text_string))",
                        "target_property_name": "#visible"
                    }
                ]
            }
        }
    ],
    "bindings": [
        {
            "binding_type": "view",
            "source_control_name": "data_control",
            "source_property_name": "(#preserved_text - $update_string)",
            "target_property_name": "#text"
        }
    ]
}
```

동작은 이렇다.

1. 보이지 않는 `data_control` 패널이 판단을 맡는다. `property_bag`가 로컬 변수를 만들므로 `global`을 쓰던 옛 방법의 충돌이 없다.
2. 새 타이틀이 (저장된 값과 다르고) 키워드를 포함하면 패널이 한 프레임 동안 보였다 숨겨진다. `visibility_changed` 바인딩이 그 순간 현재 타이틀을 `#preserved_text`에 복사한다.
3. 라벨은 자식 `data_control`의 `#preserved_text`에서 키워드를 뺀 글을 `#text`로 받아 보인다.

## 4. 토스트: 타이틀 팩토리로 알림 띄우기 (BedrockAdvancements)

(출처: 비공개 조사) 발전과제 달성 알림 토스트의 구조다.

```jsonc
"root_panel": { "modifications": [{ "array_name": "controls", "operation": "insert_front",
  "value": [{ "ba_toast_factory@ba_toast.toast_factory": {} }] }] },
"hud_title_text/title_frame": { "modifications": [{ "array_name": "bindings", "operation": "insert_back",
  "value": [
    { "binding_name": "#hud_title_text_string" },
    { "binding_type": "view",
      "source_property_name": "(not (('%.19s' * #hud_title_text_string) = 'CUSTOMHUD:ba_toast:'))",
      "target_property_name": "#visible" } ] }] }
```

- `toast_factory`는 `hud_title_text_factory`를 하나 더 만들어 `toast_notification`을 생성한다. 타이틀이 올 때마다 컨트롤이 새로 만들어지므로 **애니메이션이 매번 처음부터 재생된다**.
- 데이터는 `"CUSTOMHUD:ba_toast:" + category(20) + title(200) + icon(200)`이고 `$`로 채운다. 헤더는 `('ba.toast.' + #toast_category)`를 `localize: true` 라벨로 번역한다(lang: `ba.toast.task=§eAdvancement Made!` 등).
- 애니메이션 체인: `toast_slide_in`(offset, out_back, 0.5초) → `toast_wait`(4.5초) → `toast_slide_out`(in_back, 0.5초). `from: ["100%c + 40px", 20]`처럼 화면 밖에서 들어온다.
- 형제 스코프 바인딩: 자식 라벨이 `source_control_name: "toast_notification"` + `resolve_sibling_scope: true`로 부모가 계산한 `#toast_title_key` 등을 받는다. 파싱은 부모에서 한 번만 하고 자식은 결과만 참조한다. 아이콘 `#visible`은 `binding_condition: "once"`로 한 번만 평가한다.
- 스크립트: 플레이어별 큐, 110틱(애니메이션 5.5초) 간격, `setTitle` 후 사운드 재생, 끝날 때 다음 토스트를 보낸다.
- **한계**: 바닐라 숨김을 `title_frame`에만 걸어 가운데에 텍스트가 잠깐 번쩍이는 문제가 있었고(2.0.5에서 수정됨), 타이틀 채널이 하나뿐이라 다른 애드온이 `setTitle`을 부르면 토스트가 사라진다. 수정 방법은 2.0.5 원본이 없어 확인하지 못했다. 타이틀 채널은 다른 기능과 공유하므로 덮어쓰기를 전제로 설계한다.

## 5. 바라보는 블록 정보 패널 `{기록}`

바라보는 블록의 이름·아이콘·정보를 화면 위에 띄우는 HUD 패널(Java 모드 WAILA·Jade와 같은 것)이다. 리소스팩이 그리고 서버가 데이터를 제목 문자열로 보낸다. Script API가 없는 서버는 시선 추적·제목 만들기·보내기를 서버가 한다 (출처: 비공개 조사).

### 5.1 제목과 부제목에 싣기

- 제목에 긴 접두어를 붙여 패널용 제목을 가리고, 이름과 정보 줄을 그 뒤에 싣는다. 팩의 위치 자르기(`'%.Ns' * $var_title_text`)는 접두어 길이에 맞춘다. `'%.Ns'`는 바이트로 자르므로, 위치로 자르는 앞쪽 칸은 ASCII로 두고 한글은 맨 뒤에 둔다.
- 아이콘은 부제목에 고정 폭 칸으로 싣는다. 칸마다 아이템 런타임 ID x 65536을 글자로 채워 넣고(빈 자리는 `x` 같은 글자로 채움), 앞뒤에 글자를 붙여 문자열 형태를 지킨다. 숫자만 보내면 팩이 부제목을 문자열로 다루는 블록 상태 검사가 깨진다(회색 칸, "expected a string" 경고).
- 팩은 제목 팩토리가 주는 **변수** `$var_subtitle_text`에서 칸을 잘라 채움 글자를 지우고 `property_bag`의 `#item_id_aux`에 넣는다. 패널 글자도 모두 이 변수로 그린다.
- 부제목을 제목보다 먼저 보낸다. 일반 제목(레벨 업 등)을 보낼 때는 그 제목이 끝날 때까지 패널을 멈춘다.
- 시선 추적은 움직이거나 돌 때와 짧은 주기마다 눈에서 몇 블록까지 광선 검사(공기·액체 제외)로 한다. 작물은 단계에 따라 높이가 자라는 상자로 판정하고, 충돌 상자 없는 블록은 칸 전체로 판정하면 클라이언트 조준선과 맞는다. 바뀐 것만 보내고 가끔 다시 보낸다.

### 5.2 JSON UI에서 피할 것

- **바인딩** 식(`#hud_subtitle_text_string`)으로 칸을 꺼내면 어떤 형식(자르기, 고정 폭, 더하고 빼기, `x` 채우고 지우기)으로도 아이콘이 비어 있다. 변수 `$var_subtitle_text`를 쓴다. 부제목을 숫자만으로 보내면 블록 상태 칸 검사가 깨져 "expected a string" 경고가 난다.
- 숫자로 바뀐 값은 글자에 보이지 않는다(`" 219"`, `"1,532/4,096"`). 수량·줄 글자는 `§f`로 시작하는 바이트 칸으로 보내고, 변수 식 안에서 `'§r' + 값`으로 문자열로 만든다. 개수 식은 라벨 자신의 변수 블록에 둔다(부모 패널의 식이나 `text` 안의 `('§r' + $변수)`는 계산되지 않는다).
- 숫자 한 글자 플래그는 팩에서 숫자가 되어 글자 비교가 맞지 않는다. 플래그는 글자(`a`~`k`)로 쓰고, 변수 블록에 식이 아닌 고정 글자로 고른다.
- 바인딩 식이 `#바인딩`을 하나도 쓰지 않으면 "Must define a source property name" 오류가 난다.

## 6. 사이드바 스코어보드를 HUD 채널로 `{실측}`

제목(title)은 한 번에 하나만 담겨서, 블록 정보 패널처럼 제목을 쓰는 기능과 늘 떠 있어야 하는 글자를 같이 실으면 서로 덮는다. 사이드바 스코어보드 한 장을 HUD 부분으로 나눠 그리면 겹치지 않는다 (출처: 비공개 조사).

- **서버**: 목표(objective) 이름에 표식(`§d§h§u§d`)을, 줄마다 부분 표식을 앞에 붙인다. 예: `§d§1` 왼쪽 위, `§d§2` 오른쪽 위, `§d§3` 퀘스트 제목, `§d§4` 퀘스트 줄. 줄 순서는 부분 안에서 그대로다. Dragonfly의 앞 공백(padding)은 끈다. **같은 글자 줄은 클라이언트가 합치므로** 뒤에 `§r`을 붙여 구분한다(최대 15줄).
- **팩**: `scoreboards.json`이 바닐라 `scoreboard.scoreboard_sidebar`를 화면 전체 패널로 바꾸고, 목표 이름에 표식이 있으면 HUD 틀, 없으면 단순한 상자(다른 보드용)를 보인다. 부분마다 `scoreboard_players` 컬렉션 스택(`#scoreboard_sidebar_size` → `#collection_length`)을 두고, 줄 라벨은 `#player_name_sidebar`에 그 표식이 있을 때만 보이며 표식을 뺀 글자를 쓴다. 라벨은 `localize: false`(번역을 거치면 `%`가 사라진다).
- 숨겨진 줄은 스택에서 자리를 차지하지 않는다.
- 터치 화면(`$touch`)은 채팅을 왼쪽 위에, 점프·웅크리기 버튼을 오른쪽 가운데에 그리므로 왼쪽 위 줄을 오른쪽 위(오른쪽 맞춤)에 그리고 퀘스트 창을 그 아래에 둔다. 경험치 바는 바닐라 그대로다.
- 폼이 열려 있는 동안 HUD는 그려지지 않으므로, 폼 뒤에도 같은 틀을 보이려면 폼 배경에도 그린다([재스킨](./reskinning-server-forms.mdx)의 8절).

## 7. 터치 포켓 배치 `{기록}`

터치 화면에서 UI 프로필이 포켓이면 바닐라 HUD가 `not_centered_gui_elements`로 하트를 왼쪽 위, 배고픔을 오른쪽 위에 그린다. 그 자리가 서버의 줄과 겹치면 `hud_screen.json`에서 그 판을 다시 정의해 하트·갑옷·배고픔·공기 방울·탈것 하트를 핫바 위(클래식 터치 배치, 바닐라 `centered_gui_elements_at_bottom_middle_touch`와 같은 자리)에 둔다. 핫바는 포켓 배치가 따로 그리므로 넣지 않고 종이 인형만 왼쪽 위에 남긴다 (출처: 비공개 조사).

## 8. HUD 부제목으로 아이템 그리기 `{기록}`

타이틀의 부제목에 아이템 런타임 ID × 65536을 실어 아이콘을 그릴 때, 바인딩 `#hud_subtitle_text_string`에서 칸을 꺼내면 어떤 식으로도 아이콘이 비었다. 제목 팩토리가 주는 변수 `$var_subtitle_text`에서 `'%.11s'`로 잘라 `property_bag`의 `#item_id_aux`에 넣으면 그려졌다. 부제목을 숫자만으로 보내면 바닐라의 블록 상태 칸 검사가 깨져 "expected a string" 경고가 난다 (출처: 비공개 조사).

## 9. 규칙 요약

1. HUD 요소는 `root_panel`에 `modifications`로 끼운다. 여러 개는 `panel`로 묶는다.
2. 타이틀 채널은 공유 자원이다. 길고 고유한 표식(`CUSTOMHUD:...`)을 붙이고, 자기 표식일 때만 바닐라 타이틀을 숨기고, 다른 기능이 덮어쓸 수 있다고 가정한다.
3. 늘 떠 있어야 하는 글은 타이틀이 아니라 사이드바 스코어보드나 액션바에 싣는다.
4. 같은 글의 스코어보드 줄은 합쳐지므로 `§r` 같은 보이지 않는 꼬리로 구분한다.
5. 부제목에서 값을 꺼낼 때는 바인딩이 아니라 `$var_subtitle_text` 변수를 쓰고, 숫자 한 글자 플래그는 글자로 쓴다.
6. `SetHud`로 바닐라 HUD를 숨겨도 팩이 더한 요소는 남는다.
