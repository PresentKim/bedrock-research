# 블록 커뮤니티 보고 - 지오메트리, 렌더링, 채굴, 배치

커뮤니티 조사(2025-10-22 ~ 2026-10-23)에서 본 페이지의 앞 문서가 요약하지 못한 개별 보고를 모았다. 각 항목 끝의 `[uNNN 날짜]`는 조사 노트 번호와 보고 날짜이고, `(single report)`는 한 사람만 보고한 내용이다.

#### 모델 크기와 형식

- **크기 한도**: 회전을 포함해 약 30x30x30px다(축당 "1 + 14/16ths", 즉 16 큐브 밖으로 14px). 오류는 "Total length of parts for schematic ... greater than 1 + 14/16ths"다. 약 30px(1.8블록)보다 높은 모델은 게임에서 사라진다. 큐브만 허용되며 poly_mesh와 locator는 "is not included within the unit cube" 오류를 낸다. 복잡한 회전 큐브는 피한다. 더 큰 모양은 여러 블록, 멀티블록, 엔티티로 만든다. 크기는 transformation 적용 전에 검사된다(MCPE-236317).
- **잘못된 지오메트리의 파급**: 서브청크 하나에 잘못된 지오메트리 블록이 있으면 그 서브청크의 지오메트리 기반 블록 전부(거미줄 포함)가 렌더링되지 않는다("A block must have baked material data in order to tessellate"). 콘텐츠 로그에서 원인(너무 큰 모델, 16x16이 아닌 텍스처 등)을 찾는다.
- **소수점**: 좌표는 소수 첫째 자리로 반올림된다(15.98/7.99 → 반올림). z-fighting은 7.9나 `inflate`로 고친다. 둘째 자리를 쓰면 틈과 렌더 오류가 생긴다.
- **UV**: Bedrock은 명시적 UV가 없는 면을 버린다. Blockbench에서는 멀쩡한데 게임에서 구멍이 나면 박스 UV `[0,0]` 대신 면별 UV(`north/south/east/west/up/down`에 `uv`, `uv_size`)를 쓴다. 안 보일 면은 구석에 몰지 말고 끈다(https://wiki.bedrock.dev/blocks/block-models#removing-faces). 두께 0인 평면도 지원된다. 패딩을 없앤 프리뷰 이후 텍스처 밖 UV가 이웃 아틀라스 타일로 번지며 경고는 없다(크기가 너무 크거나 0인 UV를 지우는 스크립트로 우회).
- **한 모델엔 한 PNG**: 한 모델에 PNG 여러 장을 쓰면 실패했다.
- **스케일 상한(옛 형식)**: 새 버전에서 지오메트리 `scale`이 약 [2,1,2]로 묶이자 format 1.20.80으로 내려 `onBreak`와 큰 scale을 되살린 사례가 있다(옛 방식, 비권장). (single report)

#### 바닐라 지오메트리

- **쓸 수 있는 것**: `minecraft:geometry.full_block`과 `minecraft:geometry.cross` 등이다(앞에 `minecraft:` 필수, 목록 https://wiki.bedrock.dev/blocks/vanilla-block-models). cross에는 깜빡임을 막으려 `alpha_test_single_sided`를 쓴다. 슬라임, 랜턴, 가마솥, 표지판 같은 다른 바닐라 모델은 직접 만들어야 한다. full_block을 재사용하면 팩 용량이 준다.
- **cross 내부 구조**: BDS `.rdata`에서 뽑은 `minecraft:geometry.cross`는 큐브 2개(origin [-10.2,0,0], size [20.4,16,0], Y축 ±45도, pivot [0,8,0], material instance "cross", format 1.21.60)다.
- **full_block의 특성**: 아랫면이 180도 회전돼 있다(format 1.26에서 수정). 이름 있는 메인 뼈가 없어 컬링 규칙에서 뼈를 참조할 수 없고, UV lock도 적용되지 않는다. `opaque`인 full_block은 단위 큐브 컬링이 강제된다(2026-06-02부터 opaque만). full_block을 transformation으로 변형하면 컬링이 틀어진다(MCPE-241209). 이웃에 그림자를 드리우는 유일한 방법은 `minecraft:geometry.full_block` + `opaque`다(하드코딩).
- **`minecraft:embedded_visual`**: 화분 전용이다.

#### bone_visibility

- **형식**: `minecraft:geometry` 객체 안에 `{"identifier": ..., "bone_visibility": {...}}`로 쓰며 값은 boolean이나 Molang이다. 1.26.20+에서는 raw boolean이 `invalid string`으로 실패하므로 `"true"`/`"false"` 문자열이나 0/1을 쓴다(MCPE-238524, 스키마 버그, Mojang이 나중에 수정했다는 언급도 있음). 키는 그 뼈 바로 아래 큐브만 제어하고 중첩 그룹은 무시하며, 키 끝에 `*`를 붙이면 중첩 뼈도 포함된다. 뼈 가시성은 퍼뮤테이션 사이에 누적되지 않으므로 발광이끼식 6면 블록은 64 퍼뮤테이션이 모두 필요하다.
- **용도**: 화분에 꽃 보이기, 문/경첩, 케이크 단계, 횃불 벽 변형, 울타리 연결 등이다. 꽃 화분 예: 뼈 여러 개에 뼈 이름을 키로 한 material instance를 준다. `"minecraft:material_instances": {"*":{"texture":"pot","render_method":"opaque"},"flower":{"texture":"flower_1","render_method":"alpha_test_single_sided"}}`.

#### 충돌/선택 박스

- **다중 충돌 박스**: `minecraft:collision_box`는 박스 배열을 받는다(박스만, 곡면 없음). 1.21.130 프리뷰(1.21.130.26, 2025-11)에서 Upcoming Creator Features 실험으로 나왔고 26.0에서 안정됐다. 확장된 충돌 높이는 실험에서 나와 1.21.130+ 형식이 더는 필요 없다. 1.20.80에서도 동작했다는 보고가 있다. 박스 16개 한도라는 단일 보고가 있다(unverified). 계단 예: `[{"origin":[-8,0,-8],"size":[16,8,16]},{"origin":[-8,8,0],"size":[16,8,8]}]`. 1.21.130 전에는 꽉 차지 않은 지오메트리에서 플레이어가 밀려났다.
- **충돌 크기**: 대략 16x30x16(위로 약 8px)까지다. `random_offset` 버그로 충돌이 한 블록 밀린 사례가 있다. `collision_box: []`는 충돌 없음이 아니라 꽉 찬 충돌이다. transformation으로 박스가 블록 공간을 벗어날 수 있다(MCPE-236325, 고치지 않음). 높이 24로 늘었다는 보고도 있다(unverified).
- **선택 박스**: 하나뿐이다(배열 미지원). 24 모델 단위까지 정의할 수 있지만 엔진이 블록 경계로 자르며 시각적으로만 밖으로 나간다(Mojang 조사 중). 외곽선은 감싸는 큐브다. 투사체는 선택 박스를 쓰므로 화살이 맞게 하려면 `selection_box`를 끄지 말아야 한다. 반대로 충돌만 두면 "투사체가 통과하는 방벽"을 만들 수 있다. 외곽선을 전역으로 숨기는 방법은 모험 모드뿐이다.
- **밟기 판정**: 충돌 높이가 약 3.2px(0.2블록) 이하면 "얇은" 블록이라 서 있을 수 없고(아래 블록의 발소리와 파티클이 남) `onStepOn`/`onEntityFallOn`이 발생하지 않는다(위키 3.2, 측정 약 3.25, 실무 4px 권장). 한 보고자는 약 0.4블록 이상이어야 한다고 보고해 **conflicting**이다. 가시 블록은 4px 바닥 큐브 위에 가시를 올리거나, `onEntityFallOn`(낙하 거리 제공, 걷기에는 발생 안 함)이나 스크립트를 쓴다. `GetBlocksStandingOnOptions` 참고.
- **스폰**: 엔티티는 꽉 찬 충돌 블록 위에서 스폰된다.
- **충돌 확인 API 없음**: 충돌 박스가 꽉 찼는지 일부인지 알려주는 API가 없다. 엔티티를 소환해 밀려나는지 보거나 레이캐스트하는 핵이 있다.
- **도구**: Kaioga의 Collision Box Editor https://kaioga5.github.io/block-collision-viewer/ (소스 https://github.com/kaioga5/block-collision-viewer/), Blockbench 플러그인 https://www.blockbench.net/plugins/block_multi_collisions(자동 생성, 큐브 회전 무시, 뼈를 옮긴 뒤 자동 생성하면 옛 origin을 쓰는 버그). 미리보기와 게임에서 east/west가 뒤집혀 보인다는 보고가 있다(재현 안 됨).

#### transformation

- **`minecraft:transformation`**: rotation/scale/translation을 지정하고, 스케일은 블록 중심 기준이다. 충돌/선택 박스 스케일은 그 컴포넌트를 명시했을 때만 적용된다(MCPE-238027, "invalid" 판정, 논란). 블록 회전에서 특정 뼈를 뺄 수 없고 UV lock만 있다. `uv_lock`은 정사각 면을 블록 중심이 아니라 면 중심으로 돌린다. 눈 묻힘(snowlogging)은 transformation을 무시한다(MCPE-240710).
- **좌표계 다섯 가지**: 모델/충돌/선택(모델 단위, 바닥 중심, x+가 서쪽), leashable 오프셋(x+가 동쪽), transformation translation/pivot(블록 단위, 중심), voxel shape(모델 단위, 바닥 북서 모서리), item_display_transforms. Mojang은 placement/support를 voxel shape로 올릴 계획이며, voxel shape는 월드 로드 시 중복 제거 후 고유 4500개 한도가 있다.

#### 아이템 표시

- **`minecraft:item_visual`**: `{geometry, material_instances}`(여기선 `minecraft:` 접두사 없음)로 손/인벤토리 모델을 바꾼다. `blocks.json`의 `carried_textures`는 동작하지 않는다. 기본 `block_face`가 down이라 아이템이 거꾸로 보이면 item_visual을 정의해 고친다.
- **item_display_transforms**: 블록 지오메트리 format 1.21.110+가 필요하다(이전엔 GUI 모델이 어긋남, https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/itemdisplaytransforms?view=minecraft-bedrock-stable). 기본값: firstperson_righthand rotation [0,45,0] scale 0.4, thirdperson_righthand translation [0,2.5,0] rotation [75,225,0] scale 0.375. 바닐라 반블록에 맞추려면 `thirdperson_righthand.translation [0,2.9,1.5]`, `firstperson_righthand [0,1.58,0]`. 잘못된 속성 이름(`translate`)은 게임을 크래시시킨다. `fit_to_frame:false`는 아이콘에서 강제 중앙 정렬된다(MCPE-240720). 회전은 아이콘 그림자도 돌린다(MCPE-235788). GUI 수정은 여러 번 퇴행했다(MCPE-234752). 떨어진 아이템 크기는 ground 변환으로 조정한다.
- **블록을 아이템처럼**: 블록과 같은 식별자의 아이템에 `minecraft:block_placer {block, replace_block_item:true}`를 둔다. 같은 ID여야 픽블록이 되며(아니면 `<ns>:item.<id>`가 나옴), 평면 2D 아이콘, `max_stack_size`, 머리 착용 `minecraft:wearable`, `minecraft:glint`를 쓸 수 있다. 아이콘을 생략하면 블록으로 렌더링된다. 커스텀 블록은 블록 아이템 없이 존재할 수 없다. 문서: https://wiki.bedrock.dev/blocks/blocks-as-items(#replacing-block-items).
- **아이템 오버라이드의 부작용**: 블록 태그를 상속한다(MCPE-235805). `move_to_block`, `lay_egg` 같은 블록 지향 AI가 실패하고(MCPE-240457), `lay_egg`는 크래시한다. `move_to_block` target_blocks에 `tile.ns:block` 접두사를 쓰면 아이템과 ID를 공유하는 블록은 고쳐지지만 replace_block_item 블록은 아니다. 같은 ID 아이템을 쓰면 몹 스폰과 `avoid_block`이 블록을 무시한다는 버그도 있다. 아이템 오버라이드는 빠른 브리징을 끈다(MCPE-234686). 화로 레시피북 "items" 분류에 나오던 문제(MCPE-236444)는 수정됐다.
- **`aligned_placement`**: `minecraft:block_placer`의 이 값은 `block_face` 상태에 영향을 준다.
- **3D 블록 모델**: 3D 블록 모델을 얻는 방법은 커스텀 블록뿐이다(바닐라는 폐기된 blockshape에 묶임).

#### material_instances

- **기본**: 지오메트리를 쓰는 블록은 반드시 `minecraft:material_instances`를 쓴다. 키는 면 이름(`up`, `down`, `north` ... top/bottom 아님, `*`가 기본, Blockbench의 커스텀 면 이름도 가능)이다. 각 인스턴스의 필드는 `texture`(`textures` 아님), `render_method`, `face_dimming`(bool), `ambient_occlusion`(1.26.20+ 숫자, 모래식 부분 어둡힘 `0.55`), `tint_method`, `isotropic`이다. `eau_occlusion`/`brightness_gamma`는 없다. 텍스처 이름은 `terrain_texture.json`의 키다(경로 아님). 바닐라 텍스처도 terrain_texture에 정의해야 하며 짧은 이름(`diamond_ore`)만으로는 안 된다(blocks.json에도 있으면 된다는 단일 보고).
- **render_method 혼용 금지**: 한 블록의 인스턴스끼리 render_method를 섞을 수 없다("MaterialInstances can't mix and match"). 불투명과 반투명이 섞인 블록은 불가능하다고 여겨진다. 비콘식은 둘 다 blend로 둔다.
- **render method 선택**: `alpha_test_to_opaque`는 멀리서 사라지는 문제를 고치며 잎에 쓴다. `alpha_test`는 컷아웃용이다. `blend`는 순서 문제가 있어 반투명 큐브를 마지막에 두거나 `alpha_test_single_sided`/`double_sided`를 쓴다. 복잡한 지오메트리에서 blend는 앞 블록 위에 그려진다. `double_sided` 블록은 렌더 거리 절반에서 사라진다. 투명 픽셀이 있는 opaque는 검게 보인다. 거미줄/외곽선 스타일은 `alpha_test_single_sided`. 애드온 메이커 앱으로 만들면 `blend`/`alpha_test`가 무시되니 JSON을 손으로 쓴다. `render_method`는 blocks.json이 아니라 material instance 필드다.
- **emissive/shaded**: `emissive`는 `shaded`(face_dimming/ambient_occlusion 별칭)로 이름이 바뀌었다. 진짜 발광은 Vibrant Visuals에서만 되며, format 1.21.120+와 Upcoming Creator Features에서 `"emissive": true`가 있었다(잠깐 존재). VV/RTX 없이 빛나는 텍스처는 불가능하므로 플립북으로 빛나는 착시를 만든다(https://wiki.bedrock.dev/blocks/flipbook-textures).
- **틴트**: `tint_method: grass`는 알파가 아닌 모든 픽셀을 물들인다(바닐라 grass_side를 쓰면 흙 부분까지). `alpha_masked_tint`는 1.21.120+와 토글이 필요하며, 프리뷰에서 다시 실험이 되고 26.0 전까지 투명 픽셀을 물들이는 문제가 있었다. 투명 블록에는 `overlay_color`가 아니라 `tint_color`를 쓴다(https://wiki.bedrock.dev/blocks/block-tinting#texture-tinting). 틴트된 바닐라 잎 위에 커스텀 텍스처를 덮어도 틴트는 막을 수 없었다.
- **텍스처 크기**: 16x16이 아니어도 되지만 일반 큐브 UV는 16을 가정하므로, 다른 크기는 커스텀 지오메트리가 필요하다. 텍스처는 정사각이어야 한다(아니면 애니메이션 프레임으로 읽히거나 잘림). 8x8은 16x16으로 늘어난다. 64x64 전체 모델 아틀라스는 거대한 균열과 파괴 파티클을 만드니 면별 16x16 텍스처 여러 장을 쓴다(Blockbench에서 "blank" 텍스처 생성). 카펫(1px 모델)도 16x16 하나를 쓴다.
- **RP 편집 후 8x8로 줄어드는 현상**: RP를 복사해 사본을 수정한 뒤 원본을 덮어쓰는 우회법이 있다. `contents.json`은 두지 않는다. 텍스처가 정의되지 않았다는 오류는 이름 앞 공백이 의심됐고 캐시를 비워 해결됐다.
- **"Invalid or incomplete texture list" 경고**: 동작은 하는데 뜨는 경고가 있다.

#### 음영, AO, 그림자

- **커스텀 블록 AO**: AO가 깨져 있어, 이웃 안에 모델이 있는 꽃/작물이 어둡거나 검게 보인다. `ambient_occlusion: false`는 조금만 도움이 되다가 1.26.10 프리뷰/26.10에서 완전히 끄는 것으로 고쳐졌다. 불투명하면서 꽉 찬 블록만 AO를 드리운다. `ambient_occlusion` 속성은 받는 AO를 뜻하며 드리우는 AO가 아니다(기능 요청). 수정된 것: 바닐라 반블록이 커스텀 블록에 AO를 드리우던 문제(MCPE-236307), 커스텀/바닐라 AO 차이(MCPE-237493). 모래 반블록 측면이 더 어두운 것은 게임 버그로 보인다(모래는 면당 0.55). PBR 텍스처가 바닐라와 달라 보이는 원인이기도 하다.
- **완전 밝은 블록**: 빛을 내지 않고 음영 없는 블록은 `face_dimming` false + `ambient_occlusion` 0으로 만든다(https://wiki.bedrock.dev/blocks/block-visuals-intro#shading). 어두운 애니메이션 아이템 블록이나 바닐라보다 어두운 가마솥도 이렇게 고쳤다. 너무 밝으면 `minecraft:light_dampening`을 조정한다. 퍼뮤테이션으로 AO/디밍을 토글할 수 있다.
- **벽에 붙은 검은 면**: 평면을 더하거나 면을 0.1 앞으로 옮기거나 커스텀 컬링을 쓴다(또는 감수한다). 머리 그림자는 바닥 위 0.125에 위쪽 UV 평면을 하나 더 둔다. 작물 밑 그림자는 모델을 위로 올려 줄인다.
- **조명 아티팩트**: 커스텀 반블록/계단의 조명 아티팩트는 `minecraft:light_dampening`과 지오메트리 컬링 규칙으로 줄인다. `light_dampening`이 1 이상이면 그 아래 몹이 햇빛에 타지 않고, 15면 빛 번짐도 막는다. 풀블록에는 빛이 새지 않게 넣는다. dampening이 높으면 아래 잔디가 흙으로 바뀌고 길 블록이 되돌아간다(고체성과 연관, dampening을 낮추는 것 외엔 방법 없음).
- **26.0 / VV 문제**: 26.0에서 일부 커스텀 블록이 핫픽스 전까지 검게 나왔다. VV의 밝기 불일치는 MER/subsurface scattering 경로를 점검해 고쳤다. VV에서만 텍스처 레이어링이 깨진다. VV는 엔티티의 face dimming을 끄지만 블록은 끄지 않는다. VV의 블록 동적 아틀라스 합성(MCPE-237912)은 수정됐지만 아이템은 아직이다. 들고 있는 블록의 자동 attachable은 MER을 무시한다(MCPE-237517). `blend`와 반사 MER의 조합은 미해결이다.
- **PBR/MER**: `*.texture_set.json` + `_mer`와 팩 capability "pbr"로 동작한다. 한 사용자의 실패 원인은 terrain_texture 경로의 `.png`뿐이었다.

#### 텍스처 변형과 플립북

- **가중치 변형**: `terrain_texture.json`에 다음처럼 쓴다. 블록(머티리얼) format 1.21.110 이상이 필요하며 그 아래는 가중치 없이 처리된다. 바닐라 흙은 `flattened_dirt`, 돌은 `flattened_stone`, 모래는 `flattened_sand`/`red_sand` 키를 쓴다(`stone`은 호환용으로 유지). 커스텀 블록은 바닐라 텍스처 배열의 첫 항목만 참조할 수 있다. 진홍/뒤틀린 판자는 `textures/blocks/huge_fungus/crimson_planks`에 있다. 파괴 파티클은 변형을 따르지 않는다. 눈에 묻히면 첫 변형으로 돌아간다. 문서: https://learn.microsoft.com/en-us/minecraft/creator/documents/variationsblocktexture?view=minecraft-bedrock-stable.
  ```json
  {"textures": {"variations": [{"path": "textures/blocks/x", "weight": 50}, {"path": "textures/blocks/x2", "weight": 50}]}}
  ```
- **바닐라 블록에 변형 추가**: 바닐라 키의 terrain_texture 항목을 `variations`로 바꾼다(예 stone_bricks). blocks.json으로 바닐라 면을 바꾸려면 `"textures": {"up","side","down"}`.
- **플립북**: `flipbook_textures.json` 항목(`flipbook_texture`, `atlas_tile`, `ticks_per_frame`)을 쓰고 atlas_tile을 terrain_texture에도 등록한다. 밉매핑 때문에 멀리서 terrain_texture의 텍스처로 돌아가므로 거기에 정의하지 않으면 검정/보라 텍스처가 된다. `minecraft:geometry.full_block`과 `blend`를 쓰는 플립북 예가 있다. 얇은 줄무늬도 밉매핑으로 흐려지므로 얇은 별도 블록을 쓴다.
- **파괴 파티클**: `minecraft:destruction_particles {texture}`(format 1.21.90+)로 부술 때 텍스처를 정한다. 균열은 텍스처 전체에 걸쳐 커진다. 파티클 텍스처 버그(MCPE-234708)는 수정됐다.
- **blocks.json**: 데이터 드리븐 테셀레이션을 쓰는 블록에서는 `sound`만 유효하다. 지오메트리 블록에 `textures`를 두면 "trying to override the Geometry component with blocks.json settings" / "override geometry ... not supported" 오류가 난다. blocks.json은 바닐라 블록을 terrain 이름에 매핑한다. 상태별 텍스처를 blocks.json으로 하려던 시도는 상태가 둘이면 실패했다.
- **하드코딩된 바닐라 렌더링**: 상자, 침대, 깃발은 블록 엔티티로 렌더링된다. 구리 골렘 석상 텍스처는 하드코딩이고 blocks.json은 파괴 파티클만 바꾼다(Mojang 언급). 침대에는 색 상태가 없다(블록 엔티티에 저장, 모두 `minecraft:bed`). 색은 `block.getItemStack().localizationKey`("item.bed.red.name")로 얻지만 흰색이 나온다는 보고가 있다.

### 컬링 규칙

- **설정**: `minecraft:block_culling_rules`(format 1.21.80)를 RP `block_culling/` 파일에 두고 `minecraft:geometry`에서 참조한다. 바닐라식 잎:
  ```json
  "minecraft:geometry": {"identifier": "geometry.x", "culling": "namespace:culling.example", "culling_layer": "minecraft:culling_layer.leaves"}
  ```
  규칙 필드는 `cull_against_full_and_opaque`, `condition`(`same_block`, `same_culling_layer`), `geometry_part`다. `geometry_part.face`는 문자열 하나여야 하며 배열은 "Failed to parse block culling file"이 된다. 문서: https://wiki.bedrock.dev/blocks/block-culling, https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockcullingreference/examples/blockcullingrules/block_culling.
- **제약**: 규칙은 모델 일부를 지울 뿐 켜지는 못하고, 한 방향 이웃만 검사한다. 면당 규칙 하나지만 뼈당 하나이기도 해서, 위아래를 함께 지우려면 뼈를 나눈다. full_block 지오메트리에는 컬링 규칙을 쓸 수 없으니 직접 모델을 만든다. 3D 광석이 둘러싸여도 렌더링되면 컬링 규칙이 필요하다. `cull_against_full_and_opaque:false`가 무시된다(MCPE-240757). 퍼뮤테이션마다 transformation이 다르면 컬링 레이어가 깨진다(MCPE-234754). 정의되지 않은 컬링 레이어에 대한 경고("same_culling_layer but geometry has no culling layer defined")가 남는다.
- **연결 텍스처**: 유리식 모델의 컬링(같은 블록 옆의 면/뼈 숨기기)이나 모드(https://www.curseforge.com/minecraft-bedrock/addons/connecting-textures)로만 가능하다. 스크립트로 4방향 이웃을 검사하는 연결 유리 템플릿도 있다. 연결 테이블은 뼈별 컬링 `"condition": "same_block"`, `cull_against_full_and_opaque: false`로 만들 수 있지만 T자 교차에서 실패한다. 그 외에는 onPlace/onBreak 스크립트로 다리별 상태를 설정한다. "동굴 블록"(아래가 비쳐 보이는 블록)도 컬링으로 만든다.
- **voxel shape**: BP `shapes` 폴더의 voxel shape는 새 기능이며 현재 다른 블록에 가려진 면을 컬링하는 데만 쓰인다. 26.40 프리뷰에서 실험에서 기본 바닐라 BP로 옮겨졌지만, regex 검증 때문에 바닐라 voxel shape를 커스텀 블록이 쓸 수 없다(MCPE-240758, "당분간" 의도된 동작). 바닐라 블록 shape ID는 위키 값에서 밀렸다: sculk_sensor 125, azalea/flowering_azalea 132, glow_frame 133, glow_lichen 134, 문서에 없는 sculk_shrieker와 sculk_vein(발광이끼처럼 64상태 값 필요)이 있다. voxel shape 경계 검사는 2026-02-17에 수정됐다.
- **voxel shape 실험과 잎**: 잎이 비쳐 보이게 됐을 때 voxel shapes 실험을 끄자 해결됐다.

### 사운드

- **blocks.json `sound`**: 여전히 유효하다. `default`는 음높이만 다른 돌 소리다(https://wiki.bedrock.dev/blocks/block-sounds). blocks.json 사운드는 그 이름의 블록 모두를 바꾸고, 전역으로 바꾸려면 같은 이름의 오디오 파일을 교체한다. 엔드 이끼 소리는 `moss_block`, `moss_carpet`, 나무 설치 소리는 `use.wood`다. 금 블록은 돌과 같은 "metal" 소리를 쓰고 철/구리는 자기 ID가 있다. 물속에 놓을 때 설치 소리가 나지 않는다(바닐라도 같은 버그). 1.26.30에 instrument sound 컴포넌트가 추가됐다.

#### 채굴 속도

- **도구 태그**: `destructible_by_mining` 밖에 `"tag:minecraft:is_pickaxe_item_destructible": {}`(또는 axe/shovel/hoe)를 컴포넌트로 두면 바닐라 도구가 빠르게 캐고 효율 인챈트도 자동 적용된다. 태그는 경도(hardness)에 비례해 조정되므로 도끼는 `item_specific_speeds`보다 `tag:minecraft:is_axe_item_destructible`이 낫고, `<material>_tier` 태그는 등급을 잠글 때만 쓴다. 커스텀 곡괭이는 digger 컴포넌트에서 이 태그를 확인해야 한다. `tag:stone`은 알려진 효과가 없다. 문서: https://wiki.bedrock.dev/blocks/tool-based-destruction(루트 테이블 절과 채굴 페널티 포함).
- **`item_specific_speeds`**: `minecraft:destructible_by_mining`의 `{item, destroy_speed}` 배열이며 item은 `{"tags": "q.all_tags('minecraft:is_pickaxe','minecraft:stone_tier')"}`처럼 쓴다. 등급 태그 `minecraft:wooden_tier` 등은 있지만 `minecraft:is_wooden_pickaxe`는 없다. 바닐라 곡괭이 태그는 `minecraft:digger`, `is_pickaxe`, `is_tool`, `<tier>_tier`다. format 1.21.30 미만에서는 경고 없이 실패한다(1.20.60에서 안 된 보고도 있음). 도구 항목별 지정이 Efficiency를 덮는지는 논란이다.
- **바닐라 속도 맞추기**: `seconds_to_destroy`는 실제 초가 아니며, 기본적으로 실제 시간은 값의 1.5배다. 바닐라는 틀린 도구로 캘 때 3.33배 느리지만 커스텀 블록은 그렇지 않으니 직접 곱한다. 방법: `seconds_to_destroy` = 바닐라 경도 x 3.33(맨손), `item_specific_speeds[].destroy_speed` = 경도(예 벽돌 6.66과 `q.any_tag('minecraft:is_pickaxe')`에 2) + 곡괭이 태그. 다른 공식은 위키 기본값 x 2/3이다. 위키 페널티 공식: 맞는 도구 경도 x 1.5, 틀린 도구 x 5인데 Bedrock은 1.5를 항상 적용하므로 틀린 도구 = H x 5/1.5, 맞는 도구 = H. 참고값: 통나무식 도끼 1.975, 돌식 6.63에 도구별 약 1.9.
- **동작하지 않는 태그**: 등급 파괴 태그(`minecraft:iron_tier_destructible`), 검/철퇴 태그(`is_sword_item_destructible`)는 커스텀 블록의 드롭과 페널티에 아무 영향이 없다(MCPE-189586). `minecraft:is_shears_item_destructible`은 2026-08쯤 수정됐다. "맞는 도구일 때만 드롭" 옵션은 없다. 블록 태그(`is_pickaxe_item_destructible`, 등급)는 채굴 속도용, 아이템 태그(`minecraft:is_pickaxe`, `minecraft:diamond_tier`, 아이템 `minecraft:tags`의 커스텀 태그)는 루트 조건/레시피용이다. 드롭 여부는 루트 테이블만이 결정한다.
- **`minecraft:digger` 한계(2026-02 기준)**: digger가 있는 커스텀 아이템은 바닐라 블록에 대해 항상 맞는 도구로 취급되어(커스텀 검이 돌을 더 빨리 캠) 등급과 무관하게 드롭한다. 내구도를 깎지 않고 정수 속도만 지원하며(바닐라 검 속도 불가), `sword_efficient` 블록 태그나 커스텀 등급은 없다. 1인칭 도구 애니메이션도 깨져 있다. 스크립트로 내구도를 깎을 수 있지만 API 호출이 10회 넘게 들고 즉시 파괴 블록을 거를 수 없다. `use_efficiency`는 1.20.30부터 동작한다. 커스텀 블록에서 도구 내구도 감소는 스크립트로 해야 한다.
- **부술 수 있는지 판정**: API가 없으니 목록을 직접 관리한다. 바닐라 파괴 불가 블록: command_block, chain_command_block, repeating_command_block, end_portal_frame, bedrock, structure_block, barrier, allow/deny.

#### 폭발

- **`minecraft:destructible_by_explosion`**: `explosion_resistance`에는 minecraft.wiki의 blast resistance를 쓴다. 음수는 받지 않는다(문서는 음수/0이 쉽게 폭발한다고 잘못 적음). 폭발 파괴 저항은 바닐라 값보다 약 5배 약하므로 기대값 x5를 주석과 함께 쓰라는 조언이 있다. `false`여도 위더는 블록을 부순다. 저항을 매우 높이거나 커스텀 컴포넌트로 파괴를 취소한다.

#### 루트 테이블

- **기본**: `"minecraft:loot": "loot_tables/..."`로 지정한다. 커스텀 테이블을 쓰면 직접 나열하지 않는 한 블록 자신이 떨어지지 않으며, 아이템과 블록을 둘 다 떨구려면 풀을 두 개 쓴다. 퍼뮤테이션 안의 루트 테이블도 동작한다. 엔트리 이름은 실제 아이템 ID여야 한다(`item:xyz` 형식이 됐다는 보고와 네임스페이스 문제라는 의견이 있어 미해결). `set_data` 함수와 `count {min,max}`로 데이터 값 드롭(예 눈덩이 data 2)을 만든다.
- **`match_tool`**: `minecraft:match_tool_filter_all/any/none`에 아이템 태그(예 `["minecraft:is_shears"]`)를 준다. `"count": 1`이 없으면 빈손도 매칭된다. 들고 있는 아이템이 필요하므로 잎 루트는 재현할 수 없다. 등급 전용 드롭은 허용 곡괭이를 `items` 목록에 나열한다. 26.30부터(사용자 보고) match_tool 때문에 광석이 폭발이나 빈손으로 떨어지지 않고, `match_tool_filter_none`으로 "빈손" 조건을 더는 표현할 수 없으니 스크립트를 쓴다. Count 1 드롭은 폭발을 무시하며, 피스톤이나 지지 상실은 두 풀을 모두 떨굴 수 있으니 정확히 제어하려면 onBreak를 쓴다.
- **실크터치**: 하드코딩되어 루트 테이블을 무시하고, 빈 루트 테이블로도 막을 수 없다. 우회법은 `world.beforeEvents.playerBreakBlock`을 취소하고 `system.run`에서 `block.setType("minecraft:air")`와 소리 재생, 기본 드롭을 없애고 실크터치를 확인하는 스크립트로 아이템 생성, 또는 `onBreak`에서 공기로 교체다. 위키: https://wiki.bedrock.dev/meta/blocks-items-qna#disabling-silk-touch.
- **포춘**: 루트 테이블로 바닐라 포춘 공식을 재현하거나 확실하게 너프할 수 없으니 스크립트를 권한다. 위키의 인챈트 매칭은 레벨 2까지만 된다.
- **광석 XP**: XP는 루트로 못 주므로, `onPlayerBreak`에서 실크터치가 아니면 `minecraft:xp_orb`를 생성하는 스크립트를 쓴다(https://wiki.bedrock.dev/blocks/ore-loot-tables#xp-reward-script). 합의안은 아이템은 루트 테이블, XP만 스크립트다. 스크립트에서는 `getLootTableManager()`로 블록 + 도구 루트를 읽을 수 있다(https://stirante.com/script/server/2.10.0/classes/LootItemCondition.html).
- **바닐라 루트 변경 불가**: 바닐라 블록 드롭은 26.50의 새 "데이터 드리븐" 바닐라 블록 외에는 바꿀 수 없다. 드롭을 지우고 스크립트로 생성하는 방식만 있다. 묘목 확률도 잎 파괴 스크립트로 바꾼다. 조각된 책장 루트는 간접적으로만 된다.
- **상태별 드롭**: 떨어진 아이템 텍스처는 상태별로 바뀌지 않으니 별도 아이템이 필요하다. 낙엽 더미식 블록은 상태마다 루트 테이블을 두는 것이 스크립트보다 쉽다.
- **업적**: 행동 팩이 있어도 업적을 유지하려면 매니페스트에 `"metadata": {"product_type": "addon"}`를 둔다.

#### placement_filter

- **형식**: `{"conditions":[{"allowed_faces":["up"],"block_filter":["minecraft:glass",{"tags":"q.any_tag('dirt')"}]}]}`. 블록 필터 목록은 64개로 제한된다. "고체/비고체" 일반 검사나 꽉 찬 지지를 요구하는 효율적인 태그는 없고, 모든 조건을 동시에 요구할 수도 없다. 바닐라식 필터는 `"block_filter":[{"tags":"q.any_tag('dirt')"}]`(태그 목록 https://wiki.bedrock.dev/blocks/vanilla-block-tags). ciosciaa가 바닐라 준수 필터 data.json을 공유했다.
- **지지 상실 시 부서짐**: 불안정하다. 필터에 블록을 구체적으로 나열했을 때만 동작하고(유리류는 태그로 안 잡힘), cardinal+tag이면 한쪽만 유효해도 남는다. `allowed_faces`만 있고 `block_filter`가 없으면 다른 면 설치만 막는다. 클라이언트 예측은 항상 기본 퍼뮤테이션/`block_face="down"`을 쓴다. 필터는 회전을 무시한다(MCPE-236323). 의존 블록(문, 받침)이 정확히 따라 부서지게 하려면 파괴 이벤트로 이웃을 지운다. 예: `allowed_faces: ["up"]`와 `query.any_tag('minecraft:is_pickaxe_item_destructible',...) && !query.any_tag('minecraft:crop','one_way_collidable','plant')`.
- **모든 면 설치(자수정 덩어리식)**: `placement_position`은 기본이 "down"이라 설치 전에 그 퍼뮤테이션이 활성화된다. down 퍼뮤테이션이 모든 면에서 살아남게 두거나, `beforeOnPlayerPlace`에서 `e.face`와 `e.block.above()/below()` 태그로 `e.permutationToPlace = ...withState("ns:hanging","true")`를 정하고 아니면 `e.cancel = true`로 처리한다.

#### support와 connection_rule

- **`minecraft:support`**: `{"shape": "fence"|"stair"}`. 블록에 무엇이 붙을 수 있는지만 정하고 충돌과는 무관하다. 횃불, 레버, 버튼, 레드스톤 가루가 면에 붙는 것을 막는다. `stair`에 cardinal_direction/vertical_half가 없으면 어떤 면도 꽉 찬 것으로 치지 않는다. fence는 측면을 막고 윗면만 허용한다. 트레이트가 없으면 횃불을 붙일 수 없다. 퍼뮤테이션에는 쓸 수 없다. 커스텀 울타리에서 `{shape:"fence"}`는 자기 연결을 깨뜨린다. 바닐라 면 지지 유형은 none, center, edges, both다(압력판은 윗면 center, 버튼 both, 문 edges, edges는 퇴비통과 가마솥 윗면에만 있음).
- **`minecraft:connection_rule`**: 1.21.130 베타 실험에서 26.0 안정이 됐고 format 1.26.0+가 필요하다. 이 블록에 무엇이 연결되어 오는지를 정하며, 이 블록이 무엇에 연결되는지가 아니다. `accepts_connections_from`: `"none"`(울타리/벽/판유리/창살 연결 차단, 자기 타입 연결도 막음, 커스텀 식물 등에 유용), `"only_fences"`(나무 울타리 + 트레이트/태그가 있는 커스텀만, 판유리·벽·창살·네더벽돌 울타리 제외), `"all"`(모든 울타리, 벽, 판유리, 창살, 커스텀). "같은 블록" 옵션이 없어 자기끼리 연결하려면 스크립트나 컬링이 필요하다. `enabled_directions`는 퍼뮤테이션의 울타리 문에 쓸 수 있지만 크래시(MCPE-236302)도 있었고 무시하라는 조언도 있다. 퍼뮤테이션별 필터는 안 되며 스크립트로 읽을 수 없다. 문서: https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/traits/connection?view=minecraft-bedrock-stable.
- **connection_rule과 회전 버그**: Mojang 우회법은 `enabled_directions`에 transformation 후 방향을 넣는 것이다(예 rotation [0,180,0]에 `"enabled_directions":["north"]`). `minecraft:cardinal_connections` 트레이트를 더해도 됐다. base components의 connection_rule에서 `minecraft:connection_north` 등을 조회하면 모두 false가 나오고 업데이트 루프로 크래시할 수 있다. 연결은 회전을 무시한다(MCPE-235806). 새 트레이트로 멀티플레이가 깨지던 문제(울타리 연결 MCPE-235104)는 26.0 릴리스에서 수정됐다.
- **커스텀 울타리와 바닐라**: 커스텀 울타리가 바닐라 네더벽돌 울타리와 연결되려면 `minecraft:has_fence_connections` 태그가 필요하다(바닐라 네더 울타리는 나무 울타리와 연결되지 않음). 판유리/벽이 커스텀 블록에 연결되는 것을 막는 태그는 26.0 전에는 없었다. 바닐라 `minecraft:connection_up/down`은 프리뷰에서 일부 바닐라 블록에 나타났지만 커스텀 블록은 쓸 수 없다.
- **`tag:one_way_collidable`**: 블록 안의 플레이어를 밀어내지 않게 한다(https://wiki.bedrock.dev/blocks/vanilla-block-tags).

#### 액체

- **`minecraft:liquid_detection`**: 물에 잠김과 물에 부서짐을 정한다. 액체 종류는 물뿐이고 용암 상호작용은 설정할 수 없다.
  ```json
  "minecraft:liquid_detection": {"detection_rules":[{"can_contain_liquid":true,"liquid_type":"water","on_liquid_touches":"no_reaction"}]}
  ```
  `on_liquid_touches`는 `"blocking"`, `"popped"`, `"no_reaction"`이다. 흐르는 물은 "popped" 블록을 부수지만 물속에 놓은 블록은 부수지 않는다. `stops_liquid_flowing_from_direction`으로 특정 방향의 물 흐름을 막는다(https://wiki.bedrock.dev/blocks/block-components#liquid-detection). transformation 회전을 무시하고(MCPE-234654) 흐름 버그(MCPE-234648)가 있다. 2026-02 당시 실험/프리뷰였다.
- **`use_liquid_clipping`**: 26.0에 있지만 한 번도 동작한 적이 없는 알려진 버그다(MCPE-236319). 커스텀 계단 뒤로 물 텍스처가 비치는 z-clipping은 지오메트리를 약 0.001 inflate하는 것 외에 방법이 없다.
- **`liquid_clipped`(아이템)**: `minecraft:liquid_clipped`는 아이템 컴포넌트다. 26.10부터 block placer 아이템에 true면 물 위에만 놓인다(수련잎식). 일반적인 물속 설치는 false로 둔다. 수련잎식 설치는 아이템의 `liquid_clipped: true`로 되며 스크립트는 생존 동작에만 필요하다.
- **물속 생존**: 해초식 블록은 `isWaterlogged`를 확인하는 틱 커스텀 컴포넌트가 필요하다. 피처의 `enforce_survivability_rules`와는 무관하다. 흐르는 물에 놓은 투명 블록은 물 텍스처 변형을 주고 `/stopsound`로 첨벙 소리를 지운다. 커스텀 유체, 물/가루눈 안개, 커스텀 가마솥 액체는 불가능하다(스크립트 + `/fog`로 흉내).

#### 눈 묻힘(snowlogging)

- **컴포넌트**: `"minecraft:precipitation_interactions": {"precipitation_behavior": "snowlogging"}`(체인지로그/스키마 이름은 `snow_log_no_collision`). 충돌이 없어야 하며 1.26.30까지 실험이었다. 눈 속 꽃처럼 묻히지 않게 하려면 `none`을 쓴다.
- **버그**: 스크립트는 추가 레이어에 접근할 수 없다(onPlace는 눈 레이어에 대해 발생). 한 축만 0인 크기나 빈 배열은 충돌 0 검증을 통과하고(MCPE-240708 "invalid"), 퍼뮤테이션에서는 임의 충돌이 허용된다. 눈에 묻히면 컨테이너는 아이템을 떨구고, 정적 색 `light_emission`이 실패할 수 있으며, 텍스처 변형이 첫 값으로 돌아간다. random_offset이 중앙으로 돌아가던 버그는 26.30 프리뷰에서 수정됐다. 눈 레이어가 눈 묻힘 가능 블록 위로 갱신되지 않을 수 있다(MCPE-237495). 월드젠에서 커스텀 블록 위의 눈 레이어는 막을 수 없다.

### 레드스톤

- **`minecraft:redstone_producer`**: 버튼에 쓰던 "블록 교체 + 아래 레드스톤 블록" 핵을 대체한다. 퍼뮤테이션별로 power(0 또는 15)를 준다. `strongly_powered_face`는 방향 하나(문자열, "all"이나 배열 불가)이고 생략하면 경고가 난다. 레드스톤 가루가 블록에 연결되게 하려면 `connected_faces`를 쓴다. `transform_relative: true`면 면은 블록 자체 기준이다(뒤집힌 모델은 south가 아닌 north가 필요했다). `connected_faces`는 transform을 따르지만 `strongly_powered_face`는 모든 퍼뮤테이션에 항목이 있어야 한다. 출력이 바뀌는 모든 퍼뮤테이션에 정의해야 갱신된다는 보고도 있다. 1.26.20부터 base `components`에도 있어야 퍼뮤테이션에 둘 수 있다. 같은 블록이 main components에서 producer이면서 consumer일 수는 없다.
  ```json
  "minecraft:transformation": {"rotation": [0,180,0]},
  "minecraft:redstone_producer": {"power": 15, "connected_faces": ["east","south"], "strongly_powered_face": "east", "transform_relative": true}
  ```
- **producer 버그**: 퍼뮤테이션이 바뀌어도 출력 방향이 갱신되지 않고(MCPE-242205), 인접 가루를 제대로 향하지 않는다(MCPE-242204). 강한 출력 요구 조건(MCPE-234635)과 방출 갱신(MCPE-234647)은 2026-03 프리뷰에서 수정됐다. 퍼뮤테이션에서 신호 세기를 바꿔도 적용되지 않는다는 보고가 있었다.
- **`minecraft:redstone_consumer`**: `min_power`, `propagates_power`. format 1.26.0+와 `onRedstoneUpdate`(`e.powerLevel`) 커스텀 컴포넌트를 함께 쓰며, 매 틱 검사보다 싸다(26.0 안정). `propagates_power`를 켜지 않으면 꽉 찬 지오메트리여도 전도하지 않는다(`redstone_conductor`로 기본값이 바뀌지 않음, MCPE-232715 의도된 동작). 측면 가루가 연결되려면 `redstone_conductivity.redstone_conductor`가 필요하다. consumer는 방향성이 없어 리피터를 만들 수 없고, 가루를 꺾거나 끌어당길 수 없다. 옆에 놓인 레드스톤 횃불로도 켜진다(바닐라 레드스톤 램프와 다름). consumer이기도 한 블록은 비교기 출력을 낼 수 없다.
- **onRedstoneUpdate 주의**: 첫 설치와 청크 로드에도 발생하므로 문/뚜껑문 같은 토글 블록은 변화를 감지할 별도의 전원 상태가 필요하다. 베타의 `firstUpdate` boolean이 초기 로드 이벤트를 거른다(2026-07에도 베타). `previousPowerLevel`은 consumer의 `min_power`보다 작을 수 있고(문서 오류), 청크가 틱을 시작할 때 첫 업데이트에서는 0이다. 레드스톤 동작에 onTick을 쓰지 않는다.
- **켜짐/꺼짐 광석**: `pro:lit` 상태와 `query.block_state('pro:lit') == true` 퍼뮤테이션으로 light_emission과 텍스처를 바꾸고, random tick이나 tick으로 되돌린다.

### 기타 컴포넌트

- **`minecraft:friction`(conflicting)**: 기본값이 0.4라 위키의 0.6은 틀렸다는 보고가 있다. 방향에 대해서는 의견이 갈린다. 한 보고자와 한 보고자는 위키 설명이 거꾸로라고 본다(한 보고자: 높을수록 더 미끄럽고 낮을수록 끈적, 0.2는 거의 슬라임, 한 보고자: 낮을수록 마찰이 크고 높을수록 작으며 보트에만 제대로 동작). 한 보고자는 마찰이 높으면 미끄러움은 줄지만 속도가 올라간다고 하며, 한 값이 내부의 두 가지를 같이 바꿔 영혼 모래식 블록은 불가능하다고 본다. 한 보고자는 너무 높으면 날아가거나 매우 미끄럽다고 했다. 바닐라 슬라임만큼 느리게 하는 것은 0.1로도 안 된다. 기본값을 원하면 생략한다.
- **`minecraft:flammable`**: 값은 객체다(`catch_chance_modifier`, `destroy_chance_modifier`, `lava_flammable`), `false`가 아니다. `lava_flammable`은 format 1.26.20+에서 동작하고 그 아래는 조용히 무시된다. 기본값은 `flammable:true`여도 `"never"`라서(MCPE-240718, 의도된 동작) 문서의 "true = 판자와 같음(catch 5, destroy 20)"은 더 이상 사실이 아니다. 이 컴포넌트 이전에는 항상 용암도 불붙음으로 취급했고, 영원히 타는 블록(네더랙)이나 용암에 면역인 가연 블록은 만들 수 없었다. 불과 영혼불은 하드코딩이다(soul_fire base blocks 태그는 아이템 태그).
- **`minecraft:replaceable`**: `{}`만 받으며 블록을 잔디처럼 교체 가능하게 만든다.
- **`minecraft:crafting_table`**: 커스텀 조합 UI를 준다(https://wiki.bedrock.dev/blocks/block-components#crafting-table). 화로 컴포넌트는 없다. 화로가 양동이를 돌려주는 것은 인벤토리 변경 스크립트로 한다.
- **`minecraft:map_color`, `minecraft:display_name`**: 블록 지도 색을 지정한다(바닐라 블록 지도 색은 바꿀 수 없음). `BlockMapColorComponent`는 바닐라 블록에서 동작하지 않는다(MCPE-240722). 이름 조합은 localization 쪽이 아니라 display_name 컴포넌트 안에서 한다. `Block#localizationKey`가 display_name을 무시하던 문제(MCPE-235802)는 수정됐다.
- **`minecraft:flower_pottable` + `minecraft:embedded_visual`**: format 1.21.124+가 필요하다(이전엔 식물이 화분 위에 얹힘). 모든 퍼뮤테이션에 지오메트리 + material_instances가 있어도 root에 따로 있어야 한다(MCPE-237910). 1.26.20부터 퍼뮤테이션에서는 금지된다. 화분 고정/픽블록/투명 버그(234585/234586/234599)는 수정됐다.
- **`minecraft:chest_obstruction`**: 상자, 엔더, 덫, 구리 상자에 적용되고 셜커에는 아니다. `"shape"` 모드는 충돌 박스를 쓰며 origin [-7,0,-7] size [14,8,14]와 겹치면 실패한다. 여러 박스는 하나의 AABB로 합쳐지고 transformation을 따른다. 1.26 이전 형식에서는 퍼뮤테이션 차이를 무시한다. Kaioga 계단은 never로 둔다.
- **태그(conflicting)**: 이전 형식은 블록 태그를 `"tag:ns:name": {}` 컴포넌트로 쓴다(아이템/바이옴은 `minecraft:tags`). format 1.26.20부터는 `"minecraft:tags": ["ns:tag"]` 배열이 대체하고 새 형식에서는 `tag:*`를 못 쓰며, 1.21.130에는 `minecraft:tags`가 없다. 다만 1.26.20 무렵 반대로 배열이 로드되지 않고 `tag:` 형식이 필요했다는 보고가 있어 **conflicting**이다(block-format-history 확인). 태그 이름의 슬래시 허용은 확인되지 않았다. 레시피용 판자 태그는 planks 태그를 가진 블록 아이템이 필요하다. `query.block_neighbor_has_any_tag`/`block_has_any_tag`는 더 쓸 수 없다.
- **leashable**: 기본 `[0,0,0]`은 블록 중심이어야 한다. 채굴 파괴 속성 이름은 잘못 지어져 있다. 걸 곳(hook)이 없는데도 스케줄 틱이 발생할 수 있다.
- **술퍼 큐브(26.20 프리뷰)**: `minecraft:sulfur_cube_archetype_bouncy` 태그를 준 커스텀 블록을 집는다(https://wiki.bedrock.dev/items/vanilla-item-tags). material_instances 블록이 아주 작게 그려지던 문제(MCPE-238028)는 2026-05-14에 수정됐다.
- **쿠션**: 꽃/잎 쿠션은 커스텀 블록을 고체로 취급한다.
- **몹 스폰**: 오래된 형식의 커스텀 풀블록 위에는 몹(커스텀 포함)이 스폰되지 않았지만 format 1.21.90+에서 고쳐졌다(한 사용자는 1.26.0 필요). 블록이 고체/불투명이어야 한다. 한 보고자는 커스텀 블록을 바이옴 `top_material`로 쓰면 엔티티가 스폰되지 않는다고 했다(2026-06).
- **trial spawner**: 자연 몹 스폰 규칙이 켜져 있어야 스폰한다. 우회법은 BP spawn_rules로 자연 적대 몹 스폰을 막는 것이다(format 1.8.0 `minecraft:spawns_on_block_filter: ["minecraft:deny"]` / weight 0). 볼트의 ominous setblock과 루트는 위치로 시드가 정해진다.
- **컴포넌트 정리 순서(ciosciaa 제안)**: METADATA(display name, loot, transformation, random offset, tags) → PRESENTATION(geometry, material instances, item visuals, embedded visuals, destruction particles, map color) → PHYSICS(selection/collision box, friction, light dampening/emission, precipitation, destructible by mining/explosion, liquid detection, flammable, movable) → RELATIONS(placement filter, replaceable, support, connection rule) → FEATURES(redstone, crafting table, leashable, flower pottable) → EVENTS(tick, fall-on).

### 블록으로 만드는 패턴(문, 반블록, 계단, 울타리, 작물 등)

- **문**: `onPlayerInteract(event, definition)`에서 `permutation.withState`로 불리언 상태를 토글하고 `dimension.playSound(sound, block.center())`로 소리를 낸다. 파라미터 예: `"ns:door": {"block_state":"ns:open_bit","enable_sound":"open.wooden_door","disable_sound":"close.wooden_door"}`. 열림/경첩은 `bone_visibility` Molang(`"door_open": "q.block_state('ns:open_bit') && !q.block_state('ns:door_hinge_bit')"`)으로 처리한다. 2칸 문은 두 반쪽을 모두 설정한다(멀티블록 이전엔 블록 2개, 아래가 위를 스크립트로 놓음). 지오메트리는 base에 한 번 정의하고, 퍼뮤테이션이 정하면 base의 충돌/선택 박스는 생략한다. 블록과 아이템은 `block_placer` + `replace_block_item`으로 합치고, `minecraft:is_axe_item_destructible` 태그를 쓴다. 바닐라 울타리 문의 경첩/방향 논리는 마지막 상호작용을 기억해 재현이 어렵다(상태 3비트 + 플레이어 회전 검사 스크립트).
- **뚜껑문과 압력판**: 뚜껑문은 `onPlayerInteract({block, dimension})`에서 `block.permutation.withState("ns:open", !isOpen)`을 하고 `open.wooden_trapdoor`/`close.wooden_trapdoor`를 `block.center()`에 재생한다. 압력판은 `onStepOn`/`onStepOff`로 불리언을 토글하지만 높이 제약 때문에 얇은 판은 어렵다(바닐라 판은 박스 위 스케줄 틱을 씀). Kaioga는 block_entity를 권한다. 바닐라 문은 projectile-hit으로 돌풍구에 반응하고, 커스텀 블록은 틱 컴포넌트나 projectile hit 이벤트가 필요하다.
- **반블록**: 두 뼈를 가진 full-block 지오메트리 하나를 `vertical_half`로 전환하고 double 상태를 둔다. 바닐라 반블록 동작을 복제하려면 `minecraft:support {shape:"stair"}` + `minecraft:vertical_half`(cardinal/facing 트레이트 없이)를 쓴다. support는 퍼뮤테이션에 둘 수 없으니 겹반블록은 별도 블록 파일로 둔다. 자동으로 겹쳐지지 않으므로 스크립트가 필요하다.
  - 방법 1: `ns:is_double_slab` 상태와 `beforeEvents.playerInteractWithBlock`(`isFirstEvent`)에서 `minecraft:vertical_half`, `blockFace`, 들고 있는 아이템을 확인한다. `event.cancel = true` 후 `system.run`에서 `withState(state, true)`를 하고 아이템을 줄인다. 빈 `beforeOnPlayerPlace` 컴포넌트를 등록하면 클라이언트가 서버 측 검사를 해 글리치가 고쳐졌다.
  - 방법 2(Sky Dimensions): 아이템 `"minecraft:block_placer": {"aligned_placement": true, "block": "...", "replace_block_item": true, "use_on": [{"tags": "q.any_tag('this_tag_should_not_be_used_on_any_block')"}]}`(또는 `"tags": "false"`)로 스스로 설치하지 않게 하고 아이템 커스텀 컴포넌트가 설치와 병합을 처리한다. 휘두르기 애니메이션은 남고, 두 이벤트를 다 쓰면 `activeUses` 추적이 필요하다.
  - 방법 3: 아이템 컴포넌트 `onUseOn`에서 `usedOnBlockPermutation`, `blockFace`, `faceLocation.y`, `minecraft:vertical_half`를 보고 인접 칸에 반쪽을 놓거나 `namespace:double`을 true로 한다(`BlockPermutation.resolve(typeId, {...})`). `faceLocation.y`는 y&lt;=0에서 뒤집혀 있어(MCPE-236442, 2026-08-29에도 열림) 보정해야 한다.
  - 26.20 이후 겹반블록 설치 시 유령 블록이 보인다(설치 취소 버그). 겹반블록은 픽블록이 안 된다.
- **계단**: 26.0 안정 트레이트(`placement_direction` + `vertical_half` + `corner_and_cardinal_direction`) 조합으로 40 퍼뮤테이션이 된다. 바닐라 모양을 따르려면 뼈와 가시성이 많이 필요하거나 지오메트리 여러 개를 쓴다. UV lock은 UV 매핑만 바꾸고 방향 바인딩에는 영향이 없으며, 회전된 계단에서 제대로 동작하지 않는다. 퍼뮤테이션별 지오메트리(메인 + 동/서)나 뼈 UV 조정, `"isotropic": false`, 일부 텍스처(매끄러운 돌)엔 `uv_lock` false가 필요했다. 충돌은 다중 박스 두 개를 쓴다. 선택 박스는 꽉 찬 큐브로 남는다(바닐라처럼 빈 모서리 뒤를 고를 수 없음). 계단 자기 코너링 버그 MCPE-234801이 있다. dmahonjr 템플릿(물잠김, 방향, uv_lock, 코너)은 format 1.26.20에서 83KB에서 27KB로 줄었지만 1.26.50에서 깨진다는 보고가 있다.
- **울타리, 벽, 판유리**: 울타리 템플릿에서 충돌 폭이 정확히 16이면 물 글리치가 나니 15.999를 쓴다. 템플릿의 `use_beta_features`는 클라이언트 접속을 깨뜨렸다. 울타리 문은 커스텀 컴포넌트(`dma:fence_gate`, 스크립트 모듈 2.5.0+/2.6.0-beta)가 필요하고, 울타리는 문의 앞뒤에도 연결된다. 벽 템플릿(26.0+ connection 트레이트)에서 `sticky:"same"`은 피스톤 이동을 막으니 "none"을 쓰고, 판유리는 벽에 붙을 수 있게 취급해야 한다. 벽 윗부분은 연결과 위 벽에 달려 있어 불리언 상태가 6개 필요하다. 커스텀 판유리는 1.26 이전 안정판에서 네이티브로 불가능해 스크립트(100-300줄, 퍼뮤테이션 전환)가 필요하다(https://wiki.bedrock.dev/blocks/custom-glass-blocks). 수직 연결 트레이트가 없고 바닐라 벽 상태(벽 모양 165개)는 노출되지 않는다. Mojang(2026-06-23)은 바닐라 계단/벽 모양을 아직 데이터 드리븐으로 만들 수 없다고 했다.
- **작물과 덩굴**: `minecraft:tick`(또는 `onRandomTick`, 더 쌈) + `permutation.withState(state, value+1)`로 키우고, 다 자란 단계는 퍼뮤테이션 조건 컴포넌트로 처리한다. 밟아도 안전한 작물은 https://wiki.bedrock.dev/blocks/custom-crops. 농지가 아래 있으면 slow_falling을 줘서 짓밟힘을 막는다(10칸 검사, mobGriefing은 플레이어가 아닌 것에만 영향). 덩굴(끝/몸통 블록, `ns:age`, `ns:sheared`)은 `onRandomTick`이 끝을 몸통으로 바꾸고 아래에 새 끝을 놓는다. 뼛가루는 `playerInteractWithBlock`에서 `cancel = true` 후 `system.run`으로 처리한다. 생존 모드 소모는 `getEquipmentSlot(EquipmentSlot.Mainhand)`로 `stack.amount--; slot.setItem(stack)`을 하고 `GameMode.Creative`에서는 건너뛴다(v2는 대문자, v1은 `GameMode.creative`). 커스텀 니륨 뼛가루는 이웃을 `dimension.getBlock`으로 훑어 유효한 바닥 위 공기를 찾고 `spawnParticle("minecraft:crop_growth_emitter")`, `playSound("item.bone_meal.use")`를 부른다. 바닐라 식물은 커스텀 블록 위에 놓을 수 없고, 사탕수수식 지지는 sand 태그로 되지 않았다.
- **묘목**: 피처는 묘목 위에 놓이므로 묘목이 피처의 `may_replace`에 있거나 먼저 지워져야 한다. `dimension.placeFeature`를 쓴다. 바닐라 묘목 복제는 새 API로 가능해졌다.
- **통나무 벗기기**: 주손에 도끼가 있으면 `onPlayerInteract`에서 `block.setType(stripped)`를 하고, 내구도는 `item.getComponent("minecraft:durability").damage++` 후 `slot.setItem(item)`로 깎는다(`ItemStack.damage()`는 없음).
- **지연 교체와 2칸 블록**: 지연 후 블록 교체는 `system.runTimeout`으로 한다. 2칸 블록은 `beforeOnPlayerPlace`에서 `permutationToPlace`로 위 블록을 놓고 `minecraft:cardinal_direction`을 복사한다(미리보기에 1틱 지연). 주사위는 설치 시 무작위 상태 + 회전 퍼뮤테이션으로 만든다.
- **바닐라식 기타**: 쌓이는 블록(바다 피클식) https://scriptlabsmc.vercel.app/templates/stackable-block, 거북알/양초식 숫자 상태 템플릿은 커뮤니티 스레드 1434287459591782442. 탄력 블록은 `onEntityFallOn` 낙하 거리 → `applyImpulse`(착지 1틱 뒤 튐), 낙하 피해는 before entity hurt에서 원인 fall과 아래 블록을 확인해 취소한다. 기어오르기는 onTick + impulse로만 된다. 선인장 피해는 블록별 틱 대신 `system.runInterval`을 쓴다. 불 감지는 주변의 `minecraft:fire`를 확인하는 틱 컴포넌트로 한다. 포털은 커스텀 지오메트리, 충돌, 애니메이션 텍스처, 축 상태를 가진 일반 블록으로 만든다(1x2 벽 포털은 미해결).
- **구조 공허(structure void)식 블록**: 손에 들 때만 보이는 투명 블록은 `minecraft:geometry.full_block`, `minecraft:collision_box: false`, `"*": {texture:"invisible", render_method:"blend"}`, `minecraft:selection_box: true`, `minecraft:tick` interval [1,1] 반복, 그리고 플레이어가 아이템을 들면 `minecraft:shulker_bullet` 파티클을 내는 onTick으로 만든다(format 1.21.90). `player.spawnParticle`을 쓰면 그 플레이어만 본다. 방벽(barrier) 가시성은 하드코딩이다.
- **블록에서 엔티티 소환**: `complete` 불리언 상태를 두고 complete=false 퍼뮤테이션의 tick이 엔티티를 소환한 뒤 complete를 true로 바꾼다. 구조물 속 엔티티도 같은 "틱하는 블록이 소환하고 자신을 지움" 방식을 쓴다.
- **동적 조명**: 동적 조명 애드온은 모두 플레이어 위치에 `light_block`을 놓거나 옮긴다.
- **다중 블록 구조물 갱신**: BFS 큐와 `x,y,z` 키 visited Set으로 이웃을 훑으며 typeId와 `minecraft:cardinal_direction`을 비교한다(visited 없는 재귀는 무한 루프). setblock air 대신 `block.permutation`을 `setPermutation`으로 넘긴다. `Block` 객체는 접근할 때마다 새로 만들어지므로 위치 + 퍼뮤테이션을 쓰는 편이 빠를 수 있다. 스크립트에서 블록을 부수려면 runCommand로 `/setblock ... destroy`를 쓴다.
- **템플릿 모음**: Kaioga's Block Templates(https://github.com/Kaioga5/Kaioga-s-Block-Templates)는 바닐라 블록 재현 71개로 시작해 약 80개다. 각각 BP+RP 쌍과 더블클릭용 .mcaddon이며 주석이 달렸고 실험 토글이 없다. 1.26.40 안정판을 대상으로 했다가 2026-09-16에 1.26.50으로 갱신됐다(안정판에서만 배포). 선인장, 케이크, 덩굴(랜덤 틱 번식, 가위 전용), 사다리, 벽, 눈 레이어, 광석, 문(교육용으로 커스텀 컴포넌트 4개로 나눔), 슬라임 블록을 포함한다. 1.26.50에서 반블록/울타리/뚜껑문 아이콘이 바뀌었다. 바닐라 지오메트리는 대부분 자바 바닐라 팩에서 가져왔고 PR은 받지 않으며 이슈는 환영한다.

### 블록으로 불가능한 것과 엔티티 대안

- **불가능(엔티티나 스크립트로 대체)**: 낙하/중력 블록(같은 텍스처의 커스텀 낙하 엔티티), 애니메이션 컨트롤러와 연속 애니메이션, 상자/컨테이너(26.50 block_entity 이전), 표지판/텍스트(뼈 기반 "Primitive Shapes" 텍스트가 임시 대안), 커스텀 유체, 방벽 가시성, 엔드 관문 효과, 벽 너머로 보이는 블록, 붙을 수 없는(사다리/버튼식) 비고체, 몹 경로 차단(엔티티 쪽 `behavior.avoid_block`이 결정), 바닐라 지도 색 설정, 바닐라 블록 수정/교체(상자 등, 같은 ID로 바꿀 수 없음), 디스펜서 감지와 디스펜서식 동작(커스텀 디스펜서를 다시 만드는 것 외), 블록에서 XP 드롭(스크립트 필요), 보이지 않는 호박(텍스처가 검게 됨), 이웃 변화 이벤트(onNeighbourUpdate, ".60/.70쯤" 예상).
- **엔티티 대안 패턴**: 상호작용 가구, 아이템 진열대, 수납 서랍, 받침대는 보이지 않는 엔티티로 만든다(설치 시 소환, 파괴 시 제거, 충돌은 엔티티 컴포넌트). 인벤토리 블록 = 인벤토리 엔티티이며 `player.openInventory`는 없고, 상호작용 경로에서 엔티티가 죽지 않게 해야 한다. 엔티티 상자는 닫을 때 디스폰하고 인벤토리를 스크립트로 저장할 수 있지만 엔티티가 많으면 렉이 생긴다. 상태 전환 트릭은 블록을 숨기고 상호작용 불가 엔티티를 소환한 뒤 지우고 새 상태를 설정하는 것이다. `/kill @e`에서 지키려면 최소 체력 1을 주고, `/tp`는 좌표를 저장해 다시 텔레포트하는 스크립트로만 막을 수 있다. 가구 엔티티를 한 번 더 클릭해야 하는 것은 히트박스가 작아서이니 히트박스를 키우거나 엔티티 상호작용을 추적한다. 통(barrel) 템플릿은 엔티티 컨테이너 + 블록 상태다(https://github.com/Alien-Edds/Barrel).
- **커스텀 머리**: 16방향, 착용 가능. 충전된 크리퍼 드롭은 하드코딩이고 위더 해골 루트만 데이터 드리븐(`chance` 조건)이다. 블록 지오메트리에 Molang이 없어 머리 뼈는 4개뿐이다. N-way 회전이 스크립트를 줄인다.
- **커스텀 나무 세트에 빠진 것(2026-02)**: 표지판 텍스트, 겹반블록 픽블록, 선반 아이템 표시/비교기, 소리 블록 소리, 용암 가연성(이후 1.26.20에서 추가).
