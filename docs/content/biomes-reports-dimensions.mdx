# 바이옴·차원·제한·버전 커뮤니티 보고

커뮤니티 조사(2025-10-22 ~ 2026-10-23)에서 본 페이지의 앞 문서가 요약하지 못한 개별 보고를 모았다. 각 항목 끝의 `[uNNN 날짜]`는 조사 노트 번호와 보고 날짜이고, `(single report)`는 한 사람만 보고한 내용이다.

### 바이옴

- **형식 버전**: 행동 바이옴 `1.21.110`, 클라이언트/리소스 바이옴 `1.21.120`(Mojang 최신 샘플 기준, 한 회원은 1.21.120만 동작했다고 함). 옛 1.13.0 클라이언트 바이옴은 "Cannot load client_biome with format_version 1.13.0"으로 실패하고, 1.20.70 등은 `[BiomeRegistry] unsupported version: no parser available`이 난다. 오류 "format_version must be 1.21.110 or higher". 클라이언트 바이옴은 네임스페이스 형식이어야 한다. 1.26.30 형식도 보였다. 옛 위키 바이옴 정보(1.16.210)는 낡았고 MS 문서가 최신이다. 위키의 "experimental" 표시도 낡았다.
- **`minecraft:replace_biomes`**: 이것이 있어야 커스텀 바이옴이 생성된다. 커스텀 바이옴은 스스로 생성되지 못하고 대체로만 나온다(아무것도 대체하지 않는 바이옴은 불가, 바이옴 + 클라이언트 바이옴 파일 필요). `targets`는 `minecraft:` 접두사가 붙은 바닐라 바이옴 ID여야 한다(태그 불가). 이웃 바이옴 기준 필터(정글 옆 해변만 등)는 없다. 대체는 바이옴/블록 종류만 바꾸고 지형 모양은 유지한다. 바닐라 바이옴 배치를 같은 시드에서 섞거나, 대체 외의 방법으로 기본 바이옴을 막을 수 없다("바다만" 시도는 돌만 나옴).
  ```json
  "minecraft:replace_biomes": {"replacements":[{"dimension":"minecraft:overworld","targets":["minecraft:plains"],"amount":1,"noise_frequency_scale":25}]}
  ```
- **패치 모양**: 정사각형이거나 듬성듬성한 대체는 `noise_frequency_scale`(MS 예 25)을 올리고 `amount`를 낮추고 대상을 늘려 해결한다. "청크 경계" 정사각형은 디스크에 저장된 오래된 청크 때문이니 월드를 다시 만든다. 많은 바닐라 바이옴을 대체하면 월드 로딩이 느려진다. `/locate biome`은 반경이 약 500블록으로 제한되니 테스트할 땐 `amount`를 올리거나 멀리 텔레포트하고, 콘텐츠 로그에서 실제 로드 실패를 확인한다. 완전히 대체된 바닐라 바이옴은 `/locate biome`이 실패하므로 커스텀 바이옴을 찾는다.
- **차원(시기별)**: 2025-11에는 오버월드만 지원했다(네더/엔드 대체 없음). 2026-01에는 커스텀 네더 바이옴이 프리뷰에만 있었다. 문서상 네더 대체(`"dimension": "minecraft:nether"`, targets `soul_valley`, `basalt_deltas` 등)는 버그가 있다가 2026-05 프리뷰/핫픽스에서 수정됐다(MCPE-236399, 2026-05-21경). 커스텀 네더 바이옴에는 스크립트나 베타 모듈이 필요 없다. 엔드 커스텀 바이옴은 불가능하다. 비VV 조명에서 엔드 커스텀 바이옴은 오버월드 하늘을 보여준다(미해결).
- **컴포넌트(1.21.110에서 동작 확인)**: `minecraft:climate`, `minecraft:overworld_height {noise_type}`, `minecraft:surface_builder {builder:{type:"minecraft:overworld", sea_floor_depth, sea_floor_material, foundation_material, mid_material, top_material, sea_material}}`(옛 `minecraft:surface_parameters` 대체). 네더는 `type: "minecraft:capped"`에 `floor_materials`, `ceiling_materials`, `beach_material`, `foundation_material`. `minecraft:surface_material_adjustments`는 피처가 아니라 바이옴 컴포넌트다(`minecraft:hell` 등 약 17개 바이옴이 피처 없이 표면 장식에 사용). 유효한 `noise_type` 프리셋(1.21.110 샘플): default, default_mutated, river, ocean, deep_ocean, lowlands, taiga, mountains, highlands, extreme, less_extreme, beach, stone_beach, mushroom, swamp(`forest`는 무효).
- **지형 영향 없음**: `overworld_generation_rules`는 레거시/비동작이고, `minecraft:overworld_height`는 효과가 거의 없으며(카브 앤 클리프 이전 높이 파라미터는 사라짐), `sea_floor_depth`는 표면 층 두께만 바꾸거나 아무 효과도 없어 보인다(미해결). 바이옴 높이는 최대 약 128(noise 파라미터 정체)이다. foundation material은 심층암 층을 덮어쓰지 못하므로 "기반암까지" 블록은 실패한다. `multinoise_generation_rules`는 바닐라 바이옴에 대해 덮어쓸 수 있지만 커스텀 바이옴 배치에는 못 쓴다. 바닐라 바이옴 분포/noisemap은 노출되지 않는다. 바다 커스텀 바이옴은 `multinoise_generation_rules`, `overworld_height` `noise_type: ocean`, `generate_for_climates` 등이 필요하다는 조언이 있었지만 /locate로 못 찾았다(미해결).
- **`minecraft:noise_gradient` 표면 빌더(1.26.30 신규)**: `noise_descriptor`(`name`, `first_octave`, `amplitudes`)와 `noise_block_specifiers`(`range` min/max)를 쓴다. 문서상 지형 아래 높이 범위용이다. 여러 블록 깊이의 층을 교체했고 diamond_block 범위 -1..-0.9는 나타나지 않았다. 옥타브와 범위의 의미는 미해결이다.
- **태그와 바닐라 구조물**: 태그 자체는 아무 일도 하지 않고 스폰 규칙, 피처 룰, 지그소에 쓰인다. 바닐라 바이옴을 대체하면 마을, 신전, 난파선, 트라이얼 챔버를 잃는다(바닐라 ID/태그를 찾기 때문). 대체된 바이옴의 태그를 더하면 바닐라 구조물이 나온다(예 `plains` 태그는 평원 마을, 얼음 평원은 `ice_plains`와 `mutated` 둘 다). 바닐라 ID와 태그를 유지하면 구조물은 나오지만 커스텀 효과(비 등)를 잃는다. 대체 바이옴 태그를 자동 추가하는 Python 스크립트가 있다(마켓플레이스 비호환). 마을 생성은 바이옴 JSON으로 켜고 끌 수 있다(변형 선택 포함). 위키 태그 페이지는 의미 없이 나열만 하며, `tags.json` / `tags_per_biome.json`에서 생성되어 pale_garden이 재생성 전까지 빠져 있었다.
- **동굴 바이옴**: 무성한 동굴/점적석/깊은 어둠을 대체하거나 표면에 맞춘 커스텀 "X-동굴" 바이옴을 만든다. 동굴 바이옴은 영역에 태그만 달므로 피처(cave_carver, snap_to_surface, ore, growing_plant, vegetation_patch)로 직접 꾸민다. 커스텀 피처로 동굴을 생성하는 것은 무겁다.
- **풀 측면 색**: 커스텀 바이옴의 풀 윗면은 컬러맵을 쓰지만 측면은 terrain_textures에 고정돼 있어 색이 맞지 않는다(오래된 버그). `terrain_texture.json` `grass_side`에 `overlay_color`(`{"textures":[{"overlay_color":"#2eabf9","path":"textures/blocks/grass_side"}]}`)를 주는 우회법은 한 사람에겐 되고 다른 사람에겐 안 됐다. 커스텀 블록을 쓰는 우회도 있다.
- **날씨와 대기**: 날씨는 전역이라 항상 비 오는 바이옴은 불가능하다(스크립트 검사나 충돌 파티클로 가짜 비). 음수 fog 값은 화면을 물들인다(바이옴 대기 트릭). 대체된 얼음 평원의 눈 레이어를 없애려면 temperature/downfall을 바꾼다. Realms에서는 수정한 늪 바이옴이 안 됐다(미해결).
- **자료**: biomes 위키 개편 https://github.com/Supernova3695/nova_bedrock_wiki(patch-9), 바이옴 문서 https://bedrock.dev/docs/stable/Biomes. 옛 바이옴 템플릿 대신 현재 기술을 쓰고, 추가 바이옴은 파일을 모두 복제해 이름을 바꾼다. 슈퍼플랫 + 바이옴 스레드는 2026년에도 나무 문제를 빼면 동작한다.

### 커스텀 차원

- **등록과 상태**: 스크립트 `system.beforeEvents.startup`에서 `event.dimensionRegistry.registerCustomDimension(id)`로 등록한다(startup 전용, `/reload`로 재실행 불가). 튜토리얼: https://learn.microsoft.com/en-us/minecraft/creator/documents/scripting/custom-dimension-api-tutorial?view=minecraft-bedrock-stable. 26.30에 실험에서 나왔고 2026-06-23에는 안정판/릴리스에 있었다(초기엔 불안정하고 렉).
- **생성**: `void` 생성기("generator_type": "void")뿐이고 기본 바이옴은 `minecraft:ocean`이다(바다 몹이 스폰된다). 오버월드 지형/바이옴을 상속하지 않고, 오버월드 메커니즘을 가진 공허일 뿐이다. 구조물 세트와 피처 룰은 자연적으로 돌지 않는다. ocean 바이옴 태그 룰도 놓이지 않았다. 명령/스크립트로만 배치하며(지그소 + 스크립트 월드젠, 작은 추가물은 피처), 지형은 스크립트로 흉내 낸다. 이는 느리다: QuickJS noise와 큰 볼륨의 `Dimension.fillBlocks`가 병목이니 볼륨을 나누고 `system.runJob`으로 스케줄하며 네이티브 호출을 묶는다. 차원 바이옴은 런타임에 바꿀 수 없다(Editor 모드, 오프라인 Amulet API, Java→Bedrock Chunker 사용). 커스텀 바이옴으로 바꾸려다 게임 오류가 났다.
- **JSON 차원 정의(26.50+)**: 프리뷰 26.50.25에 `BP/dimensions/<name>.json`이 추가됐다. 스크립트와 JSON 등록이 모두 동작하며 JSON이 스크립트 등록을 덮는다. 높이 범위와 기본 바이옴을 정하려면 JSON이 낫다. 스크립트 등록은 "당분간" 유지된다. 차원 경계가 오버월드 -64..320으로 묶이던 버그(MCPE-241528)는 고쳐져 -512..512가 돌아왔다(2026-08-18 체인지로그). 컴포넌트는 min_y/max_y 대신 `minecraft:dimension_height {min_y, height_range}`(Java 대응, 커뮤니티는 min/max 선호)로 바뀌었다. `minecraft:default_biome {biome}`는 확장을 위한 객체다. 26.45에서는 높이 한도를 설정할 수 없었다. 1.26.60 동작 예(스키마에서 도출, 스키마 검증기가 format_version을 잘못 표시할 수 있음):
  ```json
  {"format_version":"1.26.60","minecraft:dimension":{"description":{"identifier":"ns:dimension"},"components":{"minecraft:clouds":{"height":-64},"minecraft:dimension_height":{"min_y":-512,"height_range":1024},"minecraft:generation":{"generator_type":"void"},"minecraft:default_biome":{"biome":"minecraft:forest"}}}}
  ```
- **이전의 데이터 드리븐 차원 파일**: `minecraft:dimension`에 `minecraft:dimension_bounds`(min/max)와 `minecraft:generation`(void)를 쓴 format 1.18.0 파일은 vanilla 차원의 void 생성 등에 쓰였다(https://learn.microsoft.com/en-us/minecraft/creator/documents/datadrivenoverworldheight?view=minecraft-bedrock-stable). 1.26.20에서 여러 개 있으면 팩 로드가 크래시했고(MCPE-238456, 1.26.13에선 동작, 2026-05-14경 수정) 바닐라 차원에 커스텀 경계를 주면 오류가 났다. 공허 생성과 커스텀 생성을 겹치는 것은 불가능하다.
- **ID**: 26.10 월드 NBT에 차원 ID 맵이 있다. 커스텀 차원 숫자 ID는 1000부터 최대 57089(58079/65376을 봤다는 말도 있음)이고, 총 한도는 디스크에 저장된다. 차원 3은 미사용이다. 네임스페이스 ID에 유니코드를 대부분 쓸 수 있다.
- **월드 편집과 이전**: Chunker(https://github.com/HiveGamesOSS/Chunker/releases/tag/1.17.0)로 leveldb에 청크를 넣어 커스텀 차원에 미리 지은 월드를 넣을 수 있다(Sky Dimensions by Starfish, 여러 차원 성공, Mojang이 1.18에 기여한 권장 방식이지만 문서 없음). Amulet은 커스텀 차원을 지원하지 않는다. Bedrock World Editor(https://github.com/8Crafter-Studios/Bedrock-World-Editor)는 지원한다(DimensionNameIdTable 지원 추가 중). 암호화된 마켓플레이스 월드는 편집할 수 없다.
- **요청(미출시)**: 차원별 시간/월드 시계(월드 데이터에 WorldClocks 있음), 중력, 게임룰, 날씨, 하늘, 포털 API(우회: 히트박스 없는 커스텀 블록 + step/inside 감지, player.json `inside_block_notifier`, `onInside`/선택 박스 교차 커스텀 컴포넌트 요청), 차원 초기화/임시 차원, dimension_types 템플릿, Java 같은 월드젠 JSON(noise settings, 바이옴 분포), RP의 클라이언트 측 차원 정의. 구조물 세트 파라미터는 바이옴 JSON으로 마을을 켜고 끌 수 있어 불필요하다는 의견이 있다.
- **기타 참고**: Hytale worldgen v2와 큐빅 청크가 모델로 언급됐다. Bedrock은 서브청크를 아래부터 저장하다 공기만 남으면 멈춘다. 피처 패턴 추상화, 공간 인식 피처, noise 옵션 확대가 요청됐다. 스크립트로 바이옴/구조물 알고리즘을 재구현해 locate 기능을 만든 사례가 있다.

### 알려진 제한과 우회법

- **onPlayerInteract가 설치를 막음** → `world.beforeEvents.playerInteractWithBlock` + `system.run`.
- **월드젠으로 놓인 블록이 틱하지 않음** → x/z를 0..15(음수 extent 없이)로, `final_pass`, search + feature, 또는 플레이어 근처를 스크립트로 검사.
- **블록 크기 30px 초과** → 멀티블록, 여러 블록, 엔티티.
- **선택 박스 하나뿐** → 멀티블록 + voxel shape(예정), 엔티티.
- **얇은 블록에서 onStepOn 미발생** → 4px 바닥 큐브, `onEntityFallOn`, 플레이어 틱 검사.
- **실크터치/포춘/바닐라 루트 하드코딩** → 파괴 이벤트 취소 + 스크립트 드롭.
- **커스텀 도구 내구도와 digger 정확도** → 스크립트로 내구도 감소.
- **`use_liquid_clipping` 미동작, 계단 뒤 물 비침** → 지오메트리 ~0.001 inflate.
- **겹반블록 자동 병합 없음** → 상호작용 스크립트나 아이템 대체 방식(위 반블록 절).
- **블록에 텍스처 변경 API 없음** → 상태 + 퍼뮤테이션별 material_instances(https://wiki.bedrock.dev/blocks/block-permutations).
- **AO로 어둡게 보임** → `ambient_occlusion` 0, `face_dimming` false, 면을 0.1 앞으로.
- **큰 아틀라스 텍스처의 거대한 균열/파티클** → 면별 16x16 텍스처.
- **커스텀 잔디에 식물 안 남** → 바닐라 배치 피처의 블록 목록을 복사해 추가.
- **피처 3x3 청크 잘림** → 구조물을 청크 중앙에, 16x16 이하, 음수 extent, `rotate_around_center` + 8,8 오프셋, 아니면 지그소.
- **피처 구조물의 엔티티 미생성** → 지그소 사용, 또는 틱하는 소환 블록.
- **지그소 개수/방향 강제 불가** → 필수 방을 시작 조각으로 만든다.
- **구조물끼리 겹침** → 같은 structure_set에 둔다.
- **지그소 길이 집을 덮음** → 길 조각을 Y 25로 저장.
- **피처가 지그소 안에 생성** → 피처에 `block_allowlist`, grass/dirt 태그 없는 바닥, structure void.
- **시드 기반 noise 없음** → 좌표 오프셋 salt.
- **지형 수정 불가** → 피처로 공기/돌/물 배치, Molang noise 지형.
- **커스텀 차원에서 피처 룰 미동작** → 스크립트 배치(`runJob`으로 분할), Chunker로 미리 지은 청크 삽입.
- **커스텀 바이옴이 바닐라 구조물을 잃음** → 대체된 바이옴의 태그를 커스텀 바이옴에 추가.
- **엔드 커스텀 바이옴 불가** → 저주파 noise 구역을 모든 관련 룰에서 공유.
- **스크립트로 동적 블록 데이터 유지(26.50 이전)** → 월드 동적 속성(위치 키).

### 미해결 질문

- 커스텀 블록에서 레드스톤 토치를 옆에 놓으면 consumer가 켜지는 문제의 해결책.
- 블록 엔티티 컨테이너에 커스텀 UI를 연결하는 공식 방법.
- 1x2 커스텀 벽 포털을 만드는 방법.
- `beforeOnPlayerPlace`/아이템 설치와 관련해, 아이템이 놓은 블록이 이 훅을 부르지 않는 조건의 정확한 범위.
- `minecraft:destructible_by_explosion: false`에도 위더가 블록을 부수는 이유(취소 외 해결책).
- 블록에서 `connection_rule`을 스크립트로 읽는 방법, 구조물 회전 후 연결 상태 재계산 방법.
- 엔티티가 들어간 몹 스포너를 퍼뮤테이션으로 만드는 방법, 구조물 배치 시 뚜껑문 회전 설정 문제.
- 바닐라 블록 지도 색 변경, 아이템 액자 테두리가 birch_planks로 하드코딩됐는지.
- Preview 1.26.10.20에서 랜덤 틱 덩굴 블록이 1.20.60~1.21.130 모든 형식에서 "unexpected version"을 낸 원인.
- 흐르는 용암 등 피처에 틱하는 블록 넣기.
- 커스텀 지오드 결정 싹이 항상 아래(또는 위)를 향하는 문제의 해결(`block_face` 방향 블록).
- 천장 블록을 single_block_feature로 회전시키는 방법.
- `noise_gradient` 표면 빌더의 옥타브/범위 의미, `sea_floor_depth`가 실제로 하는 일.
- 약 35x64x50 구조물이 structure_template_feature로 전혀 생성되지 않는 이유.
- `inherits`(예 mushroom_fields)를 쓴 커스텀 눈 바이옴이 `/locate biome`에 나타나지 않는 문제, 커스텀 바다 바이옴이 /locate에 안 잡히는 문제.
- Realms에서 수정한 바닐라 바이옴(늪)이 적용되지 않는 이유.
- 지그소로 특정 방을 정확히 한두 번 생성하게 하는 방법(요새식).
- 피처 기반 랜덤 클러스터링(scatter_chance 1/1500에서도 두 개가 붙어 나옴)의 원인.
- 엔드 섬을 structure void로 막을 수 있는지.
- `Dimension.placeFeatureRule()`의 성능 오버헤드, 스크립트/명령으로 놓은 피처에도 3x3 청크 한도가 있는지.
- 차원 변경이 BDS를 크래시시킬 때 BDS에서 커스텀 차원이 동작하는지.
- 업데이트된 커스텀 나무 생성 예제(위키 페이지 낡음).
- 마을을 제거하거나 바닐라 마을을 생성 규칙 그대로 덮어쓰는 공식 방법.
- 기존 .mcaddon에 MC Block Wizard로 만든 여러 블록을 합치는 작업 흐름.
