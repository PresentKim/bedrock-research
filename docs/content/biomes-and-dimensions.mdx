# 바이옴과 커스텀 차원

바이옴은 지형 모양을 바꾸지 못하고, 표면 블록, 기후, 태그, 클라이언트 효과(색, 대기)를 정하는 파일이다. 피처와 구조물은 [월드젠](./worldgen-and-features.mdx)에서 다룬다. 근거는 커뮤니티 조사(2025-10~2026-11), MS Learn, Bedrock Wiki(0930b39)다(출처: 비공개 조사). 검증 수준은 `(conflicting)`, `(single report)`, `(unverified)`로 적는다.

## 핵심 요약

1. 지형 모양은 바이옴 파일로 바꿀 수 없다. 커스텀 바이옴은 `minecraft:replace_biomes`로 바닐라 바이옴 일부를 대체할 뿐이며 오버월드와(2026-05경 수정 이후) 네더만 가능하고 엔드는 불가능하다.
2. 커스텀 차원은 26.30에 실험에서 나왔다. 생성기는 `void`뿐이며 피처 룰과 구조물 세트가 자연 실행되지 않으므로 내용은 스크립트로 배치한다. 26.50부터 BP `dimensions/` JSON 정의도 지원한다.
3. `/locate`는 지그소 구조물과 커스텀 바이옴만 찾는다.

## 1. 바이옴

### 형식과 개념

바이옴은 행동 바이옴(BP `biomes/`)과 클라이언트 바이옴(RP `biomes/`) 두 파일로 이뤄진다. 행동 바이옴은 `1.21.110`, 클라이언트/리소스 바이옴은 `1.21.120`을 쓴다(Mojang 최신 샘플 기준, 한 회원은 1.21.120만 동작했다고 함). 옛 1.13.0 클라이언트 바이옴은 `Cannot load client_biome with format_version 1.13.0`으로 실패하고 1.20.70 등은 `[BiomeRegistry] unsupported version: no parser available`이 난다. `format_version must be 1.21.110 or higher` 오류도 있다. 클라이언트 바이옴은 네임스페이스 형식이어야 한다. 옛 위키 바이옴 정보(1.16.210)와 "experimental" 표시는 낡았고 MS 문서가 최신이다.

### replace_biomes

- `minecraft:replace_biomes`가 있어야 커스텀 바이옴이 생성된다. 커스텀 바이옴은 스스로 생성되지 못하고 대체로만 나온다(아무것도 대체하지 않는 바이옴은 불가, 바이옴 + 클라이언트 바이옴 파일 필요). `targets`는 `minecraft:` 접두사가 붙은 바닐라 바이옴 ID여야 한다(태그 불가). 이웃 바이옴 기준 필터(정글 옆 해변만 등)는 없다. 대체는 바이옴/블록 종류만 바꾸고 지형 모양은 유지한다. 바닐라 바이옴 배치를 같은 시드에서 섞거나 대체 외의 방법으로 기본 바이옴을 막을 수 없다("바다만" 시도는 돌만 나옴).

```json
"minecraft:replace_biomes": {
  "replacements": [
    { "dimension": "minecraft:overworld", "targets": [ "minecraft:plains" ], "amount": 1, "noise_frequency_scale": 25 }
  ]
}
```

- 패치 모양: 정사각형이거나 듬성듬성한 대체는 `noise_frequency_scale`(MS 예 25)을 올리고 `amount`를 낮추고 대상을 늘려 해결한다. "청크 경계" 정사각형은 디스크에 저장된 오래된 청크 때문이니 월드를 다시 만든다. 많은 바닐라 바이옴을 대체하면 월드 로딩이 느려진다. `/locate biome`은 반경이 약 500블록으로 제한되니 테스트할 땐 `amount`를 올리거나 멀리 텔레포트하고 콘텐츠 로그에서 실제 로드 실패를 확인한다. 완전히 대체된 바닐라 바이옴은 `/locate biome`이 실패하므로 커스텀 바이옴을 찾는다.
- 차원(시기별): 2025-11에는 오버월드만 지원했다. 문서상 네더 대체(`"dimension": "minecraft:nether"`, targets `soul_valley`, `basalt_deltas` 등)는 버그가 있다가 2026-05 프리뷰/핫픽스에서 수정됐다(MCPE-236399). 커스텀 네더 바이옴에는 스크립트나 베타 모듈이 필요 없다. 엔드 커스텀 바이옴은 불가능하다. 비VV 조명에서 엔드 커스텀 바이옴은 오버월드 하늘을 보여 준다(미해결).

### 컴포넌트

- 1.21.110에서 동작이 확인된 컴포넌트: `minecraft:climate`, `minecraft:overworld_height {noise_type}`, `minecraft:surface_builder {builder:{type:"minecraft:overworld", sea_floor_depth, sea_floor_material, foundation_material, mid_material, top_material, sea_material}}`(옛 `minecraft:surface_parameters` 대체)다. 네더는 `type: "minecraft:capped"`에 `floor_materials`, `ceiling_materials`, `beach_material`, `foundation_material`을 쓴다. `minecraft:surface_material_adjustments`는 피처가 아니라 바이옴 컴포넌트다(`minecraft:hell` 등 약 17개 바이옴이 피처 없이 표면 장식에 사용).
- 유효한 `noise_type` 프리셋(1.21.110 샘플): default, default_mutated, river, ocean, deep_ocean, lowlands, taiga, mountains, highlands, extreme, less_extreme, beach, stone_beach, mushroom, swamp(`forest`는 무효).
- 지형 영향 없음: `overworld_generation_rules`는 레거시/비동작이고 `minecraft:overworld_height`는 효과가 거의 없으며 `sea_floor_depth`는 표면 층 두께만 바꾸거나 아무 효과도 없어 보인다. 바이옴 높이는 최대 약 128이다. foundation material은 심층암 층을 덮어쓰지 못하므로 "기반암까지" 블록은 실패한다(그 아래는 동굴 바이옴이 맡으며 피처로 돌을 교체하는 것만 된다). `multinoise_generation_rules`는 바닐라 바이옴에 대해 덮어쓸 수 있지만 커스텀 바이옴 배치에는 못 쓴다. 바닐라 바이옴 분포/noisemap은 노출되지 않는다.
- `minecraft:noise_gradient` 표면 빌더(1.26.30 신규)는 `noise_descriptor`(`name`, `first_octave`, `amplitudes`)와 `noise_block_specifiers`(`range` min/max)를 쓴다. 옥타브와 범위의 의미는 미해결이다.

### 태그와 바닐라 구조물

태그 자체는 아무 일도 하지 않고 스폰 규칙, 피처 룰, 지그소에 쓰인다. 바닐라 바이옴을 대체하면 마을, 신전, 난파선, 트라이얼 챔버를 잃는다(바닐라 ID/태그를 찾기 때문). 대체된 바이옴의 태그를 더하면 바닐라 구조물이 나온다(예 `plains` 태그는 평원 마을, 얼음 평원은 `ice_plains`와 `mutated` 둘 다). 바닐라 ID와 태그를 유지하면 구조물은 나오지만 커스텀 효과(비 등)를 잃는다. 마을 생성은 바이옴 JSON으로 켜고 끌 수 있다(변형 선택 포함). 위키 태그 페이지는 나열만 하며 `tags.json` / `tags_per_biome.json`에서 생성된다.

### 기타

- 동굴 바이옴: 무성한 동굴/점적석/깊은 어둠을 대체하거나 표면에 맞춘 커스텀 "X-동굴" 바이옴을 만든다. 동굴 바이옴은 영역에 태그만 달므로 피처(cave_carver, snap_to_surface, ore, growing_plant, vegetation_patch)로 직접 꾸민다.
- 풀 측면 색: 커스텀 바이옴의 풀 윗면은 컬러맵을 쓰지만 측면은 terrain_textures에 고정돼 있어 색이 맞지 않는다(오래된 버그). `terrain_texture.json` `grass_side`에 `overlay_color`(`{"textures":[{"overlay_color":"#2eabf9","path":"textures/blocks/grass_side"}]}`)를 주는 우회법은 한 사람에겐 되고 다른 사람에겐 안 됐다.
- 날씨는 전역이라 항상 비 오는 바이옴은 불가능하다(스크립트 검사나 충돌 파티클로 가짜 비). 음수 fog 값은 화면을 물들인다. 대체된 얼음 평원의 눈 레이어를 없애려면 temperature/downfall을 바꾼다. Realms에서는 수정한 늪 바이옴이 안 됐다(미해결).
- 추가 바이옴은 파일을 모두 복제해 이름을 바꾼다. 슈퍼플랫 + 바이옴은 2026년에도 나무 문제를 빼면 동작한다.

## 2. 커스텀 차원

### 등록

스크립트 `system.beforeEvents.startup`에서 `event.dimensionRegistry.registerCustomDimension(id)`로 등록한다(startup 전용, `/reload`로 재실행 불가). 26.30에 실험에서 나왔고 2026-06-23에는 안정판/릴리스에 있었다(초기엔 불안정하고 렉이 있었다).

```javascript
import { system } from "@minecraft/server";

system.beforeEvents.startup.subscribe((event) => {
  event.dimensionRegistry.registerCustomDimension("ns:dimension");
});
```

### 생성

`void` 생성기(`"generator_type": "void"`)뿐이고 기본 바이옴은 `minecraft:ocean`이다(바다 몹이 스폰된다). 오버월드 지형/바이옴을 상속하지 않고 오버월드 메커니즘을 가진 공허일 뿐이다. 구조물 세트와 피처 룰은 자연적으로 돌지 않는다. ocean 바이옴 태그 룰도 놓이지 않았다. 명령/스크립트로만 배치하며(지그소 + 스크립트 월드젠, 작은 추가물은 피처) 지형은 스크립트로 흉내 낸다. QuickJS noise와 큰 볼륨의 `Dimension.fillBlocks`가 병목이니 볼륨을 나누고 `system.runJob`으로 스케줄하며 네이티브 호출을 묶는다. 차원 바이옴은 런타임에 바꿀 수 없다(Editor 모드, 오프라인 Amulet API, Java→Bedrock Chunker 사용).

### JSON 차원 정의 (26.50 이상)

프리뷰 26.50.25에 `BP/dimensions/<name>.json`이 추가됐다. 스크립트와 JSON 등록이 모두 동작하며 JSON이 스크립트 등록을 덮는다. 높이 범위와 기본 바이옴을 정하려면 JSON이 낫다. 스크립트 등록은 당분간 유지된다. 차원 경계가 오버월드 -64..320으로 묶이던 버그(MCPE-241528)는 고쳐져 -512..512가 돌아왔다(2026-08-18). 컴포넌트는 min_y/max_y 대신 `minecraft:dimension_height {min_y, height_range}`로 바뀌었다. `minecraft:default_biome {biome}`는 확장을 위한 객체다. 26.45에서는 높이 한도를 설정할 수 없었다. 1.26.60 동작 예(스키마에서 도출, 스키마 검증기가 format_version을 잘못 표시할 수 있음):

```json
{
  "format_version": "1.26.60",
  "minecraft:dimension": {
    "description": { "identifier": "ns:dimension" },
    "components": {
      "minecraft:clouds": { "height": -64 },
      "minecraft:dimension_height": { "min_y": -512, "height_range": 1024 },
      "minecraft:generation": { "generator_type": "void" },
      "minecraft:default_biome": { "biome": "minecraft:forest" }
    }
  }
}
```

- 이전의 데이터 드리븐 차원 파일(format 1.18.0)은 `minecraft:dimension`에 `minecraft:dimension_bounds`(min/max)와 `minecraft:generation`(void)을 써서 vanilla 차원의 void 생성 등에 쓰였다. 1.26.20에서 여러 개 있으면 팩 로드가 크래시했고(MCPE-238456, 2026-05-14경 수정) 바닐라 차원에 커스텀 경계를 주면 오류가 났다. 공허 생성과 커스텀 생성을 겹치는 것은 불가능하다.
- ID: 26.10 월드 NBT에 차원 ID 맵이 있다. 커스텀 차원 숫자 ID는 1000부터 최대 57089(58079/65376을 봤다는 말도 있음)이고 총 한도는 디스크에 저장된다. 차원 3은 미사용이다. 네임스페이스 ID에 유니코드를 대부분 쓸 수 있다.
- 하늘, 구름, 날씨: 하늘/안개 색은 차원 안의 커스텀(클라이언트) 바이옴으로만 정한다. 26.60에 `minecraft:clouds`(height) 컴포넌트가 추가됐다(처음엔 오버월드 높이로 제한, MCPE-242282). `in_clouds` 엔티티 필터는 어느 높이의 커스텀 구름에서도 동작한다. 날씨/주변 파티클은 바이옴이 제어한다.
- 버그와 동작: 커스텀 차원에서는 `/setworldspawn`이 동작하지 않는다. `/execute in <dim> run tp`로는 들어갈 수 있지만 changedimension은 안 된다. 커스텀 차원 안에서 저장 후 종료하면 오버월드를 다녀올 때까지 화면이 파랗다. 싱글플레이에서 아무도 목적지를 로드하지 않을 때 `entity.teleport`로 차원 사이를 옮기면 영구 몹이 디스폰되거나 잘못된 곳에 놓였다(2026-07-28 수정 확인). BDS에서 커스텀 차원이 동작하는지는 미해결이다.
- 월드 편집과 이전: Chunker(HiveGamesOSS)로 leveldb에 청크를 넣어 커스텀 차원에 미리 지은 월드를 넣을 수 있다(여러 차원 성공, 문서 없음). Amulet은 커스텀 차원을 지원하지 않는다. Bedrock World Editor(8Crafter-Studios)는 지원한다. 암호화된 마켓플레이스 월드는 편집할 수 없다.
- 요청(미출시): 차원별 시간/월드 시계, 중력, 게임룰, 날씨, 하늘, 포털 API(우회: 히트박스 없는 커스텀 블록 + step/inside 감지, player.json `inside_block_notifier`), 차원 초기화/임시 차원, dimension_types 템플릿, Java 같은 월드젠 JSON, RP의 클라이언트 측 차원 정의.

## 3. 알려진 제한과 우회법

- 커스텀 컴포넌트가 퍼뮤테이션에서 사라짐(MCPE-234714): 모든 퍼뮤테이션에 모든 커스텀 컴포넌트를 정의한다.
- 월드젠으로 놓인 블록이 틱하지 않음: x/z를 0..15(음수 extent 없이)로, `final_pass`, search + feature, 또는 플레이어 근처를 스크립트로 검사한다.
- 블록 크기 30px 초과: 멀티블록, 여러 블록, 엔티티를 쓴다. 선택 박스 하나뿐: 멀티블록 + voxel shape(예정), 엔티티.
- 얇은 블록에서 onStepOn 미발생: 4px 바닥 큐브, `onEntityFallOn`, 플레이어 틱 검사를 쓴다.
- 지형 변경: 바이옴으로 불가능하므로 [월드젠](./worldgen-and-features.mdx)의 피처로 공기/돌을 놓는다.
