# 블록

커스텀 블록을 만드는 방법과 알려진 제한을 정리한다. 근거는 커뮤니티 조사(2025-10~2026-10)와 Bedrock Wiki(0930b39)의 blocks 문서, bedrock-samples(15701fa9)의 바닐라 블록 JSON이다(출처: 비공개 조사). 검증 수준은 `(confirmed)`, `(conflicting)`, `(single report)`, `(unverified)`로 적는다.

## 핵심 요약

1. 블록 기능은 블록 파일의 `format_version`이 결정한다(manifest `min_engine_version`은 BP의 Molang/명령에만 영향). 커스텀 컴포넌트 v2는 1.21.90 이상, `connection_rule`과 새 트레이트는 1.26.0 이상, `minecraft:tags` 배열은 1.26.20 이상이 필요하다.
2. 커스텀 컴포넌트는 `system.beforeEvents.startup`의 `blockComponentRegistry.registerCustomComponent("ns:id", {...})`로 등록하고 블록 `components`에 `"ns:id": {}`로 직접 쓴다. `minecraft:custom_components` 배열과 `world.beforeEvents.worldInitialize`는 폐기됐다.
3. 퍼뮤테이션에 커스텀 컴포넌트를 두면 base `components`의 커스텀 컴포넌트가 사라진다(MCPE-234714, 미해결). 모든 퍼뮤테이션에 다시 정의한다.
4. 블록 모델은 축마다 약 30px(블록 밖으로 최대 14px), 큐브만 허용된다. 너무 크거나 잘못된 지오메트리는 그 서브청크의 모든 커스텀 블록을 보이지 않게 만든다.
5. `minecraft:collision_box`는 여러 박스 배열을 받는다(1.21.130 실험 → 26.0 안정). 선택 박스는 하나뿐이다.
6. 바닐라 블록의 JSON, 루트 테이블, 동작은 애드온으로 수정할 수 없다. 실크터치와 포춘은 하드코딩이라 스크립트로 처리한다.
7. 월드젠으로 놓인 커스텀 블록은 `onTick`/`onPlace`가 실행되지 않는 경우가 많다.

## 1. 개념과 최소 예제

블록 파일은 `BP/blocks/*.json`에 있고 `description`, `components`, 선택적 `permutations`, `traits`를 가진다. 텍스처는 `RP/textures/terrain_texture.json`에 정의하고 `minecraft:material_instances`로 참조한다. 이름은 lang 키 `tile.<ns>:<id>.name`이다. 다음이 1.26.30에서 유효한 발광 블록의 최소 예제다.

```json
{
  "format_version": "1.26.30",
  "minecraft:block": {
    "description": {
      "identifier": "wiki:glow_block",
      "menu_category": { "category": "construction" }
    },
    "components": {
      "minecraft:geometry": { "identifier": "minecraft:geometry.full_block" },
      "minecraft:material_instances": {
        "*": { "texture": "glow_block", "render_method": "opaque" }
      },
      "minecraft:light_emission": 15
    }
  }
}
```

```json
{
  "resource_pack_name": "wiki",
  "texture_name": "atlas.terrain",
  "texture_data": { "glow_block": { "textures": "textures/blocks/glow_block" } }
}
```

```lang
tile.wiki:glow_block.name=Glow Block
```

철자는 `light_dampening`이다(damping 아님). 지오메트리를 쓰는 블록은 `blocks.json`에 `textures`를 두면 안 되며 `sound`만 유효하다.

## 2. format_version과 파일 규칙

### format_version

- 블록 파일의 format_version만 중요하다. 1.21.90 블록은 숫자만 1.26.0으로 올려도 새 트레이트가 동작했다(1.21.90~26.0 사이에 형식이 바뀐 컴포넌트는 없다). Realm이 아직 그 버전이 아니면 무시되거나 실패한다.
- format_version별 효과(ciosciaa 정리, 공식 체인지로그는 자주 틀린다): 1.19.10 map color/flammability, 1.19.20 friction, 1.19.40 geometry + material_instances, 1.19.50 collision + crafting table, 1.19.60 display name/selection/adjacency filter, 1.19.80 transformation, 1.20.10 geometry의 Molang bone visibility, 1.21.30 mining destructibility hardness override, 1.21.70 intrinsic particles + `isotropic`, 1.21.90 UV lock + destruction particle count, 1.21.110 texture variations의 atlas tile, 1.21.120 alpha 기반 tint masking, 1.26 하드코딩 full-block 아랫면 회전 수정, 1.26.20 trailing comma/tags 컴포넌트/block entity 컴포넌트/geometry의 visual rotation 상태 바인딩/lava flammability/퍼뮤테이션 조건의 versioned Molang/식별자·상태 이름 검증 완화/placement_direction·geometry 검증 강화/퍼뮤테이션 내 flower_pottable 금지, 1.26.30 instrument sound 컴포넌트. 다중 충돌 박스는 1.20.80에서도 동작했다(버그 수정은 1.26.30).
- 1.26.20 새 파서: `ambient_occlusion` boolean이 제거되고 0-10 숫자를 받는다(boolean을 쓰면 엉뚱한 `invalid string` 오류). 오류 메시지에 위치 정보가 없다. 1.26.20에는 아이템 오버라이드가 있는 블록에 `menu_category`가 잘못 필수였다(`"menu_category": {"category": "none"}`으로 우회, 2026-03-31까지 수정). 예전 버전으로 내리면 로드는 되지만 새 컴포넌트를 잃는다.
- `components` 밖의 컴포넌트는 조용히 무시된다. 예를 들어 `"minecraft:collision_box": false`를 밖에 두면 오류 없이 단위 큐브 충돌이 된다.
- 1.16.100식 문법은 폐기됐다. 1.16 시절 블록은 마이그레이션 전까지 "?" / "update block"으로 보인다.

### 레거시 이름 변경

`minecraft:entity_collision` → `minecraft:collision_box`, `minecraft:block_light_dampening` → `minecraft:light_dampening`, `minecraft:pick_collision` → `minecraft:selection_box`, `minecraft:block_light_emission` → `minecraft:light_emission`, `minecraft:destroy_time` → `minecraft:destructible_by_mining.seconds_to_destroy`, `minecraft:rotation` → `minecraft:transformation`, `minecraft:block_property` 쿼리 → `q.block_state`, `properties` → `states`(1.20.30). `minecraft:ticking`은 없고 `minecraft:tick`이다. 블록 이벤트(`events`, `minecraft:on_placed`, `set_block_state`)는 2024년경 제거됐으니 스크립트를 쓴다.

### 파일 위치와 이름

- `terrain_texture.json`(단수)과 `item_texture.json`은 `RP/textures/`에 둔다. 경로에 `.png` 확장자를 넣으면 PBR 텍스처 세트가 깨진다. 잘못된 JSON이나 UTF-8-SIG(BOM) 파일은 `failed to parse`가 된다.
- lang 키는 `tile.<ns>:<id>.name`이다. 식별자에 대문자를 쓰지 않는다.
- `menu_category`는 `description` 바로 안에 둔다(`traits` 안이 아님). 값은 소문자다(`"Construction"`이나 `menu_catagory` 오타는 조용히 크리에이티브에서 숨긴다). 숨기려면 `"none"`을 쓰거나 생략한다(생략은 프리뷰 26.20.23부터 다시 허용). `replace_block_item`을 쓰면 아이템의 menu_category가 우선한다. `register_to_creative_menu`는 1.26.20에서 동작을 멈췄다. `traits`도 `description` 안에 둔다.

### 콘텐츠 로그 읽기

- 블록 오류의 순서: 첫 줄은 블록이 무효라는 것, 둘째는 어느 컴포넌트, 셋째는 이유(진짜 원인), 넷째는 format_version에 맞지 않는 데이터다. `Unexpected version for the loaded data`는 보통 앞선 진짜 오류에 딸려 나오므로 로그를 위로 올려 본다.
- 누락 레지스트리 경고는 팩이 켜지지 않았거나 완전히 리로드되지 않은 경우다. 지오메트리/텍스처를 바꾼 뒤에는 development 팩에 두고 `/reload all`을 쓴다.
- 편집기 오탐: Blockception VS Code 확장은 `minecraft:geometry.full_block`과 `wool`/`carpet` 블록 필터를 잘못 표시한다. bridge. 스키마는 `block_face`, 정수 `count`, 숫자 `ambient_occlusion`을 잘못 거부한다.

## 3. 커스텀 컴포넌트(스크립트)

### 등록

블록 JSON에는 `"ns:id": {}`를 `components`에 직접 쓰고, 스크립트가 등록한다. 필요 조건은 블록 format 1.21.90 이상, BP manifest의 `@minecraft/server` 2.0.0 이상, `modules`의 script 항목, 그리고 엔트리 파일에서 컴포넌트 파일을 import하는 것이다.

```javascript
import { system } from "@minecraft/server";

system.beforeEvents.startup.subscribe(({ blockComponentRegistry }) => {
  blockComponentRegistry.registerCustomComponent("ns:id", {
    onPlace(e) {},
    onTick(e) {},
  });
});
```

```json
{ "type": "script", "language": "javascript", "entry": "scripts/main.js", "uuid": "...", "version": [1, 0, 0] }
```

- 한 노트는 `minecraft:custom_components` 배열이 필요하다고 적었지만 1.21.90 이후 무효인 옛 형식이다.
- gametest 의존성 버전이 충돌하면 스크립트 로딩이 깨진다. 당시 안정판 기준 `@minecraft/server` 2.7.0, server-ui 2.0.0을 쓰고 쓰지 않는 `@minecraft/server-gametest`는 뺀다. (single report)
- `child 'x:y' not valid here` / `component found in input but not present in Schema`의 원인: 컴포넌트가 API로 등록되지 않음, 잘못된 레지스트리(itemComponentRegistry)에 등록, 옛 format_version(예 1.20.80), manifest에 script 모듈 없음, 스크립트 오류나 잘못된 import, 한 폴더의 여러 manifest 중 하나. `minecraft:geometry` 밖에 둔 `bone_visibility`도 같은 오류를 낸다. 가짜 `minecraft:components` 객체로 감싸는 것은 해결책이 아니다.
- 등록 타이밍: `system.run(() => import("./main"))`처럼 main을 한 틱 늦게 import하면 startup 등록이 깨진다. 스크립트 오류가 하나라도 있으면 블록/아이템 컴포넌트가 붙지 않을 수 있다. `/reload`로는 startup이 다시 실행되지 않는다.
- `Block custom component 'x' is not being used by a block`은 format_version이나 위치가 잘못됐다는 뜻이다. `component used on block but not registered in script`는 미등록이거나 `@minecraft/server` 메타데이터 버전이 잘못된 경우다. 2026-03 블록 스키마 변경 직후 모든 커스텀 컴포넌트에 `No transformer found for component ... Cannot downgrade from modern slice to legacy component`가 났다(MCPE-237057).
- 커스텀 컴포넌트 파라미터의 중첩 깊이는 최대 2다. `tag`도 유효한 커스텀 컴포넌트 네임스페이스다.

### 훅

- 사용 가능한 훅: `onPlace`, `onTick`, `onRandomTick`, `onPlayerInteract`, `beforeOnPlayerInteract`, `onPlayerBreak`(이전 `onPlayerDestroy`), `onBreak`, `onStepOn`, `onStepOff`, `onEntityFallOn`, `beforeOnPlayerPlace`, `onRedstoneUpdate`. `beforeEvents.blockTick`, `permutation.getMaterial()`, `onEntityStepOn`, `onEntityInside`는 존재하지 않는다.
- `onBreak`는 1.21.130에서 실험으로 나왔다. `brokenBlockPermutation`과 `entitySource`를 주며 피스톤, 폭발, 지지 상실로 깨질 때도 발생한다. 생존성(survivability) 실패로 부서질 때는 발생하지 않는다(MCPE-240755).
- `onPlayerInteract`는 그 블록에 대고 하는 일반 사용과 설치를 막는다(웅크려야 설치 가능). 한 퍼뮤테이션에만 있어도 모든 퍼뮤테이션이 상호작용 가능해진다(MCPE-225746). 활성 커스텀 컴포넌트가 하나라도 있으면 블록이 interactable이 된다. 막지 않으려면 `world.beforeEvents.playerInteractWithBlock`을 쓰고 `system.run` 안에서 처리한다.
- `beforeOnPlayerPlace`는 `e.permutationToPlace`를 바꾸거나 `e.cancel = true`로 막는다. 이 훅을 쓰면 클라이언트 예측이 꺼져 빠른 브리징이 어려워진다. `replace_block_item` 블록에서는 블록이 놓인 뒤에 실행된다.
- `onPlace`는 모든 설치에서 발생한다. 같은 틱에 부서지면 `e.block`이 `minecraft:air`일 수 있다. 이웃이 자리 잡기 전에 실행될 수 있으니 `system.run`으로 늦춘다.
- 틱 타이머: `minecraft:tick`은 개수 제한이 없고 지연이 있는 queued tick을 지원하지만 한 블록이 틱 타이머를 둘 가질 수는 없다. 성능을 위해 `onRandomTick`을 선호한다. 틱을 끄려면 상태 하나와 퍼뮤테이션 둘(하나만 `minecraft:tick` 포함)을 쓴다.
- 스케줄 틱 처리량: 청크-차원 쌍마다 틱당 100개 블록만 scheduled-tick 동작을 실행하고 나머지는 순환한다. 압력판 30여 개가 블록 `onTick`을 쓰자 10-15ms 스파이크가 났다. 플레이어 쪽 틱이나 projectile hit 이벤트를 권장한다.
- 놓인 블록의 퍼뮤테이션을 `onTick`/레드스톤 클럭으로 바꾸면 그 틱 동안 플레이어가 그 블록에 대고 설치할 수 없다. 블록 컴포넌트 이벤트 절반은 손 흔들기 애니메이션을 강제한다.

### 퍼뮤테이션과 커스텀 컴포넌트 버그(MCPE-234714)

매칭되는 퍼뮤테이션 중 마지막(가장 아래) 퍼뮤테이션의 커스텀 컴포넌트만 적용되고 다른 곳에 정의한 것은 무시된다. 루트와 기본 퍼뮤테이션 양쪽에 있으면 퍼뮤테이션 쪽만 읽힌다. 우회법은 모든 퍼뮤테이션에 모든 커스텀 컴포넌트를 정의하는 것이다. 2026-10 기준 미해결이다.

## 4. 상태, 트레이트, 퍼뮤테이션

### 상태

상태는 `description.states`에 정의하고 `q.block_state('ns:name')`으로 읽는다.

```json
"description": {
  "identifier": "wiki:crop",
  "states": {
    "wiki:growth": { "values": { "min": 0, "max": 7 } },
    "wiki:kind": [ "a", "b" ]
  }
},
"permutations": [
  { "condition": "q.block_state('wiki:growth') < 7",
    "components": { "minecraft:tick": { "interval_range": [ 20, 40 ] } } }
]
```

- 상태 이름에는 네임스페이스가 필요하다(`gen:type`). 없으면 `Identifier must have a namespace / Failed to create Block State Description`가 난다. 상태당 값은 최대 16개이고 더 필요하면 상태를 둘 쓴다.
- 비트마스크: 이끼/스컬크 덩굴처럼 6면을 붙이려면 면을 1,2,4,8,16,32로 두고 합 1-63을 쓴다.
- 블록은 상태의 모든 퍼뮤테이션을 항상 만든다. 값이 더 적은 바닐라 상태를 재사용할 수 없다. 기존 월드에서 바뀐 상태는 틱이 돌 때만 갱신된다.
- 블록 컴포넌트는 저장되지 않는다. 컴포넌트는 퍼뮤테이션(식별자 + 상태값)에서 파생되며 저장되는 것은 `minecraft:tick`의 queued tick뿐이다. `block.setTexture`는 없다. 스크립트로 지오메트리를 바꾸려면 상태에 퍼뮤테이션을 묶고 `block.setPermutation`을 쓴다.
- 스크립트 API: 많은 상태 값은 문자열이다(`turtle_egg_count: "one_egg"`). `BlockStates.get(name).validValues`는 평탄화된 레거시 타입(`stone_type`, `sand_type` 등)에서 `[]`를 준다. `BlockPermutation.getAllStates()`는 현재 값만 준다. 폐기 상태(`color`, `old_log_type`)도 호환용으로 노출된다.
- 상태는 블록 타입별로 지역적이다. 모든 조합을 만들면 존재하지 않는 퍼뮤테이션이 생기니 `BlockPermutation#withState`를 시도해 실패를 건너뛴다. 메타데이터에 없지만 팔레트에 있는 내부 블록: chalkboard, client_request_placeholder_block, deprecated_anvil, deprecated_purpur_block_1/2, end_gateway, glowingobsidian, info_update, info_update2, invisible_bedrock, moving_block, netherreactor, reserved6, stonecutter.
- 아이템 데이터 값은 `testfor`/`give`에서 동작하지만 블록 데이터 값은 동작하지 않는다. 블록 aux ID는 고정이고 아이템 숫자 ID는 런타임에 배정된다. 명령 자동완성은 숫자 상태 값을 0부터 다시 매긴다(MCPE-236301).

### 퍼뮤테이션 규칙과 한도

- 컴포넌트는 퍼뮤테이션끼리나 base와 겹쳐도 되지만 같은 조건을 반복하지 않는다. 퍼뮤테이션은 기능별로 따로 둬도 되며(회전 4 + 텍스처 2) 데카르트 곱일 필요가 없다. 조건에는 `&&`, `||`, 괄호를 쓸 수 있고 자기 상태만 볼 수 있다(이웃은 못 본다).
- 한도: 블록 타입당 최대 65,536 퍼뮤테이션(별도의 두 번째 한도도 있고 바닐라는 약 16,000). 한 애드온은 바닐라를 포함해 블록 32,767개까지 등록할 수 있다. 월드 전체 퍼뮤테이션 경고도 있다(한 애드온 40k, 약 93,220). 연결 텍스처 블록은 한도를 넘으니 숫자 상태 하나를 X,Y 그리드로 매핑하거나 엔티티를 쓴다.
- 상태 대 별도 블록: 성능 차이는 없다는 의견과 레드스톤·조명에는 별도 블록이 낫다는 의견이 있다. 변형마다 자체 아이템이 필요한지로 정한다. 트레이트도 상태처럼 퍼뮤테이션 수에 계산될 가능성이 크다.

### 방향 트레이트

```json
"traits": {
  "minecraft:placement_direction": { "enabled_states": [ "minecraft:cardinal_direction" ], "y_rotation_offset": 180 },
  "minecraft:placement_position": { "enabled_states": [ "minecraft:block_face" ] }
}
```

트레이트 없이 `q.block_state('minecraft:block_face')`를 쓰면 `making use of non-registered block state`가 난다.

- `placement_direction`(`minecraft:cardinal_direction` N/E/S/W 또는 `minecraft:facing_direction`)은 플레이어가 보는 방향에 따르며 화로식이다. `placement_position`(`minecraft:block_face`, `minecraft:vertical_half`)은 클릭한 면에 따르며 통나무/기둥식이다. 모델 앞면은 north를 향하게 만들고 `y_rotation_offset: 180`을 준다. `y_rotation_offset`은 하드코딩된 `enabled_states` 일부에서만 지원된다. corner+cardinal에서는 cardinal을 포함하지 않으면 실패한다(MCPE-240709).
- 기둥 회전 퍼뮤테이션은 `q.block_state('minecraft:block_face')`에 따라 `minecraft:transformation` rotation을 west/east `[0,0,90]`, north/south `[90,0,0]`, up/down `[0,0,0]`으로 준다.
- `/setblock`으로 `block_face` 트레이트 블록을 놓으면 기본 `down`이 된다(바닐라 item frame도 같음). cardinal 블록도 손으로 놓을 때와 다르게 향하니 상태를 명시한다. `cardinal_direction` 순서(NWSE)가 예상과 달라 west는 -90/270이 아니다.
- 16방향 회전 `minecraft:sixteen_way_rotation` / `n_way_visual_rotation`은 2026-08-04 안정판으로 확인됐다. 퍼뮤테이션 안에서는 쓸 수 없고 지오메트리를 덮는 퍼뮤테이션은 이를 지운다. 하드코딩 full-block 모델에서는 동작하지 않는다. 원격 플레이어/BDS/Realms에서 회전이 보이지 않던 버그(MCPE-241952)는 26.60.28/29에 수정됐다고 하지만 Realms에서 안 된다는 보고가 남아 있다. 구조물 회전을 따르지 않는다(MCPE-243539).
- 랜덤 회전: 수련잎식 텍스처는 material instance `"isotropic": true`로 위치 기반 무작위 회전을 준다. 설치마다 무작위로 하려면 `beforeOnPlayerPlace`에서 `e.permutationToPlace = e.permutationToPlace.withState("minecraft:cardinal_direction", directions[Math.floor(Math.random()*4)])`를 쓴다.
- 상태 기반 회전 커스텀 방향 블록은 구조물로 저장해 회전하면 잘못 돈다. 스크립트로 놓은 파이프/연결 블록은 구조물 로드 후 연결 상태를 다시 계산해야 한다(미해결).

### 연결과 계단 트레이트

- `minecraft:connection` 트레이트: `enabled_states: ["minecraft:cardinal_connections"]`가 자동 관리되는 `minecraft:connection_north/south/east/west` 상태를 더한다. `bone_visibility`나 퍼뮤테이션에서 스크립트 없이 쓸 수 있고 스크립트 방식보다 빠르게 반영된다. 상하 연결은 없고 비슷한 블록이나 태그로 제한할 수 없다. 바닐라 풀블록, `connection_rule` 없는 커스텀 블록, "none"이 아닌 규칙에 `minecraft:has_fence_connections` 태그가 있는 블록에 연결된다. `y_rotation_offset`을 쓰면 오프셋 없는 블록과 연결이 깨진다. 퍼뮤테이션에 connection 트레이트나 `has_fence_connections` 태그를 두면 게임이 크래시한다(MCPE-236302).

```json
"minecraft:geometry": {
  "identifier": "geometry.fence",
  "bone_visibility": { "north": "q.block_state('minecraft:connection_north')", "centre": "true" }
}
```

- `minecraft:corner_and_cardinal_direction`은 `placement_direction`의 enabled state로 쓰며 4방향 x 5코너(none, inner_left, outer_left, inner_right, outer_right) = 20 퍼뮤테이션이고 `minecraft:corner` 상태를 더한다. `blocks_to_corner_with`에는 블록 ID 목록이나 `{"tags":"q.any_tag('mytag')"}`를 준다. `minecraft:cornerable_block` 태그는 없으니 커스텀 태그나 자기 ID를 쓴다. 바닐라 계단과의 연결은 26.0에서 Beta APIs 실험이 필요했고 2026-04에도 미연결 버그가 남아 있었다. inner 조각 옆에서 corner가 none이 되던 버그(MCPE-232019)는 26.10에 수정됐다.
- `minecraft:vertical_half`는 `placement_position` enabled state로 반블록 위/아래를 정한다.

## 5. 멀티블록

```json
"traits": { "minecraft:multi_block": { "enabled_states": [ "minecraft:multi_block_part" ], "parts": 2, "direction": "up" } }
```

(출처: ms-learn multi-blocks, bedrock-wiki multi-blocks)

- 안정화 경과(일부 conflicting): 수직 멀티블록은 1.26.40 안정 예정이었지만 빠졌고 Mojang은 1.26.50 릴리스에서 안정이라고 했다. 수평 멀티블록(침대)은 1.26.40 프리뷰 실험을 거쳐 26.50에 안정됐다. 최종 안정은 26.50으로 본다.
- 필수와 제한: `minecraft:movable`을 반드시 정의해야 한다(immovable 또는 popped, 피스톤 이동 미지원). `placement_filter`, `replaceable`, `random_offset`, `movable`, `precipitation_interactions`, `minecraft:block_entity`는 root 전용이다(퍼뮤테이션에 두면 `Component ... is not valid in multi block permutations`). block_entity는 약 1.26.50에 다시 유효해졌고 부품당 하나씩 붙는다. `precipitation_interactions`를 퍼뮤테이션에 두면 26.30.25부터 블록 전체가 로드되지 않는다. 방향 트레이트는 `cardinal_direction`만 동작한다(connection, placement_position, n-way 미지원).
- 방향: `placement_direction`이 `cardinal_direction`을 켜면 트레이트의 `direction`은 무시되고 배치 방향(`y_rotation_offset` 포함)을 따른다. 한 축만 지원하므로 3D/다축은 스크립트로 만든다.
- 동작: 기본 부품을 놓으면 나머지가 놓인다. 기본이 아닌 부품을 `setblock`/`fill`로 놓으면 실패한다(2026-03-11 수정). 어느 부품을 부수든 전부 부서지고 먼저 부서진 부품의 루트만 떨어진다. 부품마다 루트를 다르게 하려면 `q.block_state('minecraft:multi_block_part')` 조건 퍼뮤테이션에 루트를 둔다. `onBreak`는 한 번 발생하고 `onPlayerBreak`는 발생하지 않는다. 비기본 부품은 설치 시 엔티티 충돌 검사를 건너뛴다. 각 부품은 pending tick 하나로 계산된다.
- 상태 변경: 2026-05(1.26.20 무렵)부터는 같은 틱에 모든 부품의 상태를 바꿔야 하며 part 0만 바꾸면 블록이 깨진다. Mojang은 스크립트/명령으로 부품 하나씩 설정하는 것을 의도적으로 막았다고 했다. `beforeOnPlayerPlace`의 `permutationToPlace`는 모든 부품을 갱신한다.
- 스크립트: `block.setType(typeId)`는 기본 퍼뮤테이션(첫 부품)을 놓아 전체를 만든다. `setPermutation()`은 한 부품만 놓고 part 0에 쓰면 클라이언트에 유령 부품만 생긴다. 상태를 바꾸려면 `block.getParts()`(순서 보장)로 각 부품에 설정한다.

```javascript
part.setPermutation(BlockPermutation.resolve(part.typeId, {
  ...states,
  "minecraft:multi_block_part": part.getState("minecraft:multi_block_part"),
}));
```

  랜덤 틱에서는 `minecraft:multi_block_part`를 읽어 0이 아니면 건너뛴다. 바닐라 문은 위쪽 상태만 바꾸는 레거시 방식이다.
- 블록 엔티티와 인벤토리: 부품마다 별도 블록 엔티티가 붙고 동기화되지 않는다(바닐라 겹상자도 연결된 엔티티 2개). 인벤토리 변경을 감지할 방법이 없어 두 플레이어가 다른 부품을 쓰면 복제 위험이 있다.
- 기타 버그: 선택 박스를 끈 부품은 외곽선 계산에서 16x16x16으로 취급된다. 커스텀 멀티블록으로 `fill ... replace bed[...]`를 채팅에서 실행하면 크래시할 수 있다. 지오메트리/머티리얼을 퍼뮤테이션에만 정의한 멀티블록은 root에 `minecraft:flower_pottable`이 있으면 오류가 난다(MCPE-237910). 블록 경계 밖 외곽선에는 멀티블록 + voxel shape를 쓰는 것을 Mojang이 의도한다고 했다.

## 6. 블록 엔티티, 컨테이너, 동적 속성

- `minecraft:block_entity`는 프리뷰 26.30.28에 들어왔다. 26.40에서 실험, 26.50에서 블록 엔티티 자체(동적 속성 저장)는 실험이 아니게 됐고 `container {slot_count}`는 여전히 실험이다. UI는 통(barrel)식뿐이며(JSON UI로 수정 가능) 상자 렌더링과 호퍼 흡입은 없다.
- 할 수 없는 것: 낙하 블록(하드코딩된 `minecraft:falling_block` 엔티티)과 애니메이션. 상자 열림 애니메이션은 상태와 퍼뮤테이션으로 지오메트리를 단계별로 바꿔 흉내 낸다. 멀티블록이 블록 엔티티 하나를 공유하는 것도 아직 안 된다.
- 버그: 레드스톤 업데이트 뒤 스크립트로 컨테이너 아이템을 바꾸면 열린 UI가 닫힌다(26.50). 눈에 묻힌 컨테이너 블록 엔티티는 아이템을 떨어뜨린다.
- 루트 함수 `carry_over_block_entity_data`에 `dynamic_properties:true`를 주면 블록 동적 속성이 아이템으로 넘어간다(26.40).
- 블록 엔티티 이전의 저장 방법: 블록별 데이터는 월드나 엔티티 동적 속성에 둔다. 엔티티 기반 저장은 블록이 많으면 렉이 생기고 `/kill @e`로 사라진다. 블록 엔티티는 attachable로 아이템을 보여줄 수 있다.

## 7. 지오메트리, 크기, 충돌/선택 박스

### 모델 크기와 형식

- 크기 한도는 회전을 포함해 약 30x30x30px다(축당 "1 + 14/16ths", 16 큐브 밖으로 14px). 오류는 `Total length of parts for schematic ... greater than 1 + 14/16ths`다. 약 30px보다 높은 모델은 게임에서 사라진다. 큐브만 허용되며 poly_mesh와 locator는 `is not included within the unit cube` 오류를 낸다. 더 큰 모양은 여러 블록, 멀티블록, 엔티티로 만든다. 크기는 transformation 적용 전에 검사된다(MCPE-236317).
- 잘못된 지오메트리의 파급: 서브청크 하나에 잘못된 지오메트리 블록이 있으면 그 서브청크의 지오메트리 기반 블록 전부(거미줄 포함)가 렌더링되지 않는다(`A block must have baked material data in order to tessellate`). 원인은 너무 큰 모델, 16x16이 아닌 텍스처 등이다.
- 소수점: 좌표는 소수 첫째 자리로 반올림된다. z-fighting은 7.9나 `inflate`로 고친다. 둘째 자리를 쓰면 틈과 렌더 오류가 생긴다.
- UV: Bedrock은 명시적 UV가 없는 면을 버린다. Blockbench에서는 멀쩡한데 게임에서 구멍이 나면 박스 UV 대신 면별 UV(`north/south/east/west/up/down`에 `uv`, `uv_size`)를 쓴다. 안 보일 면은 끈다. 두께 0인 평면도 지원된다. 한 모델에 PNG 여러 장을 쓰면 실패했다.

### 바닐라 지오메트리

- 쓸 수 있는 것은 `minecraft:geometry.full_block`과 `minecraft:geometry.cross` 등이다(앞에 `minecraft:` 필수). cross에는 깜빡임을 막으려 `alpha_test_single_sided`를 쓴다. 슬라임, 랜턴, 가마솥, 표지판 같은 다른 바닐라 모델은 직접 만들어야 한다. full_block을 재사용하면 팩 용량이 준다.
- `minecraft:geometry.cross` 내부 구조(BDS에서 추출): 큐브 2개(origin [-10.2,0,0], size [20.4,16,0], Y축 ±45도, pivot [0,8,0], material instance "cross", format 1.21.60).
- full_block의 특성: 아랫면이 180도 회전돼 있다(format 1.26에서 수정). 이름 있는 메인 뼈가 없어 컬링 규칙에서 뼈를 참조할 수 없고 UV lock도 적용되지 않는다. `opaque`인 full_block은 단위 큐브 컬링이 강제된다. full_block을 transformation으로 변형하면 컬링이 틀어진다(MCPE-241209). 이웃에 그림자를 드리우는 유일한 방법은 `minecraft:geometry.full_block` + `opaque`다(하드코딩). `minecraft:embedded_visual`은 화분 전용이다.

### bone_visibility

- `minecraft:geometry` 객체 안에 `{"identifier": ..., "bone_visibility": {...}}`로 쓰며 값은 boolean이나 Molang이다. 1.26.20 이상에서는 raw boolean이 `invalid string`으로 실패하므로 `"true"`/`"false"` 문자열이나 0/1을 쓴다(MCPE-238524). 키는 그 뼈 바로 아래 큐브만 제어하고 중첩 그룹은 무시하며 키 끝에 `*`를 붙이면 중첩 뼈도 포함된다. 뼈 가시성은 퍼뮤테이션 사이에 누적되지 않으므로 발광이끼식 6면 블록은 64 퍼뮤테이션이 모두 필요하다.
- 용도: 화분에 꽃 보이기, 문/경첩, 케이크 단계, 횃불 벽 변형, 울타리 연결. 꽃 화분 예:

```json
"minecraft:material_instances": {
  "*": { "texture": "pot", "render_method": "opaque" },
  "flower": { "texture": "flower_1", "render_method": "alpha_test_single_sided" }
}
```

### 충돌/선택 박스

- 다중 충돌 박스: `minecraft:collision_box`는 박스 배열을 받는다(박스만, 곡면 없음). 1.21.130 프리뷰(2025-11)에서 Upcoming Creator Features 실험으로 나왔고 26.0에서 안정됐다. 계단 예:

```json
"minecraft:collision_box": [
  { "origin": [ -8, 0, -8 ], "size": [ 16, 8, 16 ] },
  { "origin": [ -8, 8, 0 ], "size": [ 16, 8, 8 ] }
]
```

  박스 16개 한도라는 단일 보고가 있다(unverified). 1.21.130 전에는 꽉 차지 않은 지오메트리에서 플레이어가 밀려났다.
- 충돌 크기는 대략 16x30x16(위로 약 8px)까지다. `collision_box: []`는 충돌 없음이 아니라 꽉 찬 충돌이다. transformation으로 박스가 블록 공간을 벗어날 수 있다(MCPE-236325).
- 선택 박스는 하나뿐이다(배열 미지원). 24 모델 단위까지 정의할 수 있지만 엔진이 블록 경계로 자른다. 투사체는 선택 박스를 쓰므로 화살이 맞게 하려면 `selection_box`를 끄지 말아야 한다. 반대로 충돌만 두면 "투사체가 통과하는 방벽"을 만들 수 있다.
- 밟기 판정: 충돌 높이가 약 3.2px(0.2블록) 이하면 "얇은" 블록이라 서 있을 수 없고 `onStepOn`/`onEntityFallOn`이 발생하지 않는다(위키 3.2, 측정 약 3.25, 실무 4px 권장). 다른 보고는 약 0.4블록 이상이어야 한다고 했다. (conflicting) 가시 블록은 4px 바닥 큐브 위에 가시를 올리거나 `onEntityFallOn`(낙하 거리 제공, 걷기에는 발생 안 함)이나 스크립트를 쓴다.
- 엔티티는 꽉 찬 충돌 블록 위에서 스폰된다. 충돌 박스가 꽉 찼는지 알려 주는 API는 없다.
- 도구: Kaioga의 Collision Box Editor(웹), Blockbench 플러그인 block_multi_collisions(자동 생성, 큐브 회전 무시).

### transformation

- `minecraft:transformation`은 rotation/scale/translation을 지정하고 스케일은 블록 중심 기준이다. 충돌/선택 박스 스케일은 그 컴포넌트를 명시했을 때만 적용된다(MCPE-238027). 블록 회전에서 특정 뼈를 뺄 수 없고 UV lock만 있다. `uv_lock`은 정사각 면을 블록 중심이 아니라 면 중심으로 돌린다. 눈 묻힘은 transformation을 무시한다(MCPE-240710).
- 좌표계는 다섯 가지다: 모델/충돌/선택(모델 단위, 바닥 중심, x+가 서쪽), leashable 오프셋(x+가 동쪽), transformation translation/pivot(블록 단위, 중심), voxel shape(모델 단위, 바닥 북서 모서리), item_display_transforms. voxel shape는 월드 로드 시 중복 제거 후 고유 4500개 한도가 있다.

### 아이템 표시

- `minecraft:item_visual`은 `{geometry, material_instances}`(이 안에서는 `minecraft:` 접두사 없음)로 손/인벤토리 모델을 바꾼다. `blocks.json`의 `carried_textures`는 동작하지 않는다. 기본 `block_face`가 down이라 아이템이 거꾸로 보이면 item_visual을 정의해 고친다.
- `item_display_transforms`는 블록 지오메트리 format 1.21.110 이상이 필요하다. 기본값은 firstperson_righthand rotation [0,45,0] scale 0.4, thirdperson_righthand translation [0,2.5,0] rotation [75,225,0] scale 0.375다. 바닐라 반블록에 맞추려면 `thirdperson_righthand.translation [0,2.9,1.5]`, `firstperson_righthand [0,1.58,0]`을 쓴다. 잘못된 속성 이름(`translate`)은 게임을 크래시시킨다. `fit_to_frame:false`는 아이콘에서 강제 중앙 정렬된다(MCPE-240720).
- 블록을 아이템처럼: 블록과 같은 식별자의 아이템에 `minecraft:block_placer {block, replace_block_item:true}`를 둔다. 같은 ID여야 픽블록이 된다. 평면 2D 아이콘, `max_stack_size`, 머리 착용 `minecraft:wearable`, `minecraft:glint`를 쓸 수 있다. 아이콘을 생략하면 블록으로 렌더링된다. 커스텀 블록은 블록 아이템 없이 존재할 수 없다.
- 아이템 오버라이드의 부작용: 블록 태그를 상속한다(MCPE-235805). `move_to_block`, `lay_egg` 같은 블록 지향 AI가 실패한다(MCPE-240457). 빠른 브리징이 꺼진다(MCPE-234686). `minecraft:block_placer`의 `aligned_placement`는 `block_face` 상태에 영향을 준다.

## 8. 텍스처, material_instances, 렌더링

### material_instances

- 지오메트리를 쓰는 블록은 반드시 `minecraft:material_instances`를 쓴다. 키는 면 이름(`up`, `down`, `north` 등, top/bottom 아님, `*`가 기본, Blockbench의 커스텀 면 이름도 가능)이다. 각 인스턴스의 필드는 `texture`(`textures` 아님), `render_method`, `face_dimming`(bool), `ambient_occlusion`(1.26.20 이상 숫자, 모래식 부분 어둡힘 `0.55`), `tint_method`, `isotropic`이다. 텍스처 이름은 `terrain_texture.json`의 키다(경로 아님). 바닐라 텍스처도 terrain_texture에 정의해야 하며 짧은 이름만으로는 안 된다.
- 한 블록의 인스턴스끼리 `render_method`를 섞을 수 없다(`MaterialInstances can't mix and match`). 불투명과 반투명이 섞인 블록은 불가능하다고 여겨지며 비콘식은 둘 다 blend로 둔다.
- render method 선택: `alpha_test_to_opaque`는 멀리서 사라지는 문제를 고치며 잎에 쓴다. `alpha_test`는 컷아웃용이다. `blend`는 순서 문제가 있어 반투명 큐브를 마지막에 두거나 `alpha_test_single_sided`/`double_sided`를 쓴다. 복잡한 지오메트리에서 blend는 앞 블록 위에 그려진다. `double_sided` 블록은 렌더 거리 절반에서 사라진다. 투명 픽셀이 있는 opaque는 검게 보인다. 거미줄/외곽선 스타일은 `alpha_test_single_sided`다. 애드온 메이커 앱은 `blend`/`alpha_test`를 무시하므로 JSON을 손으로 쓴다. `render_method`는 blocks.json이 아니라 material instance 필드다.
- `emissive`는 `shaded`(face_dimming/ambient_occlusion 별칭)로 이름이 바뀌었다. 진짜 발광은 Vibrant Visuals에서만 되고 VV/RTX 없이 빛나는 텍스처는 불가능하므로 플립북으로 착시를 만든다.
- 틴트: `tint_method: grass`는 알파가 아닌 모든 픽셀을 물들인다(바닐라 grass_side를 쓰면 흙 부분까지). `alpha_masked_tint`는 1.21.120 이상과 토글이 필요하며 26.0 전까지 투명 픽셀을 물들이는 문제가 있었다. 투명 블록에는 `overlay_color`가 아니라 `tint_color`를 쓴다.
- 텍스처 크기: 16x16이 아니어도 되지만 일반 큐브 UV는 16을 가정하므로 다른 크기는 커스텀 지오메트리가 필요하다. 텍스처는 정사각이어야 한다. 8x8은 16x16으로 늘어난다. 64x64 전체 모델 아틀라스는 거대한 균열과 파괴 파티클을 만드니 면별 16x16 텍스처 여러 장을 쓴다. RP 편집 후 8x8로 줄어드는 현상은 RP를 복사해 사본을 수정한 뒤 원본을 덮어쓰는 우회법이 있고 `contents.json`은 두지 않는다.

### 음영, AO, 그림자

- 커스텀 블록 AO는 이웃 안에 모델이 있는 꽃/작물이 어둡거나 검게 보이는 문제가 있다. `ambient_occlusion: false`가 26.10에서 완전히 끄는 것으로 고쳐졌다. 불투명하면서 꽉 찬 블록만 AO를 드리운다. 모래 반블록 측면이 더 어두운 것은 게임 버그로 보인다(면당 0.55).
- 완전 밝은 블록(빛을 내지 않고 음영 없음)은 `face_dimming` false + `ambient_occlusion` 0으로 만든다. 너무 밝으면 `minecraft:light_dampening`을 조정한다. 퍼뮤테이션으로 AO/디밍을 토글할 수 있다.
- 벽에 붙은 검은 면은 평면을 더하거나 면을 0.1 앞으로 옮기거나 커스텀 컬링을 쓴다. 머리 그림자는 바닥 위 0.125에 위쪽 UV 평면을 하나 더 둔다.
- `light_dampening`이 1 이상이면 그 아래 몹이 햇빛에 타지 않고 15면 빛 번짐도 막는다. dampening이 높으면 아래 잔디가 흙으로 바뀌고 길 블록이 되돌아간다.
- Vibrant Visuals: 26.0에서 일부 커스텀 블록이 핫픽스 전까지 검게 나왔다. VV에서만 텍스처 레이어링이 깨진다. VV는 엔티티의 face dimming을 끄지만 블록은 끄지 않는다. 들고 있는 블록의 자동 attachable은 MER을 무시한다(MCPE-237517). `blend`와 반사 MER의 조합은 미해결이다. PBR/MER은 `*.texture_set.json` + `_mer`와 팩 capability "pbr"로 동작하며 terrain_texture 경로에 `.png`를 쓰면 실패한다.

### 텍스처 변형, 플립북, 파괴 파티클

- 가중치 변형은 `terrain_texture.json`에 쓴다. 블록(머티리얼) format 1.21.110 이상이 필요하다. 바닐라 흙은 `flattened_dirt`, 돌은 `flattened_stone`, 모래는 `flattened_sand`/`red_sand` 키를 쓴다. 커스텀 블록은 바닐라 텍스처 배열의 첫 항목만 참조할 수 있다. 파괴 파티클은 변형을 따르지 않고 눈에 묻히면 첫 변형으로 돌아간다.

```json
{ "textures": { "variations": [ { "path": "textures/blocks/x", "weight": 50 }, { "path": "textures/blocks/x2", "weight": 50 } ] } }
```

- 플립북은 `flipbook_textures.json` 항목(`flipbook_texture`, `atlas_tile`, `ticks_per_frame`)을 쓰고 atlas_tile을 terrain_texture에도 등록한다. 밉매핑 때문에 멀리서 terrain_texture의 텍스처로 돌아가므로 거기에 정의하지 않으면 검정/보라 텍스처가 된다. 얇은 줄무늬도 밉매핑으로 흐려지니 얇은 별도 블록을 쓴다.
- `minecraft:destruction_particles {texture}`(format 1.21.90 이상)로 부술 때 텍스처를 정한다.
- blocks.json은 데이터 드리븐 테셀레이션을 쓰는 블록에서 `sound`만 유효하다. 지오메트리 블록에 `textures`를 두면 `trying to override the Geometry component with blocks.json settings` 오류가 난다. blocks.json은 바닐라 블록을 terrain 이름에 매핑한다.
- 하드코딩된 바닐라 렌더링: 상자, 침대, 깃발은 블록 엔티티로 렌더링된다. 구리 골렘 석상 텍스처는 하드코딩이다. 침대에는 색 상태가 없다(블록 엔티티에 저장, 모두 `minecraft:bed`).

## 9. 컬링 규칙

`minecraft:block_culling_rules`(format 1.21.80)를 RP `block_culling/` 파일에 두고 `minecraft:geometry`에서 참조한다.

```json
"minecraft:geometry": {
  "identifier": "geometry.x",
  "culling": "namespace:culling.example",
  "culling_layer": "minecraft:culling_layer.leaves"
}
```

- 규칙 필드는 `cull_against_full_and_opaque`, `condition`(`same_block`, `same_culling_layer`), `geometry_part`다. `geometry_part.face`는 문자열 하나여야 하며 배열은 `Failed to parse block culling file`이 된다.
- 규칙은 모델 일부를 지울 뿐 켜지는 못하고 한 방향 이웃만 검사한다. 면당 규칙 하나지만 뼈당 하나이기도 해서 위아래를 함께 지우려면 뼈를 나눈다. full_block 지오메트리에는 컬링 규칙을 쓸 수 없다. `cull_against_full_and_opaque:false`가 무시된다(MCPE-240757). 퍼뮤테이션마다 transformation이 다르면 컬링 레이어가 깨진다(MCPE-234754).
- 연결 텍스처는 유리식 모델의 컬링이나 모드로만 가능하다. 연결 테이블은 뼈별 컬링 `"condition": "same_block"`, `cull_against_full_and_opaque: false`로 만들 수 있지만 T자 교차에서 실패한다. 그 외에는 onPlace/onBreak 스크립트로 다리별 상태를 설정한다.
- BP `shapes` 폴더의 voxel shape는 새 기능이며 현재 다른 블록에 가려진 면을 컬링하는 데만 쓰인다. regex 검증 때문에 바닐라 voxel shape를 커스텀 블록이 쓸 수 없다(MCPE-240758). 바닐라 블록 shape ID는 위키 값에서 밀렸다(sculk_sensor 125, azalea/flowering_azalea 132, glow_frame 133, glow_lichen 134). 잎이 비쳐 보이면 voxel shapes 실험을 끈다.

## 10. 사운드

blocks.json의 `sound`는 여전히 유효하다. `default`는 음높이만 다른 돌 소리다. blocks.json 사운드는 그 이름의 블록 모두를 바꾸고 전역으로 바꾸려면 같은 이름의 오디오 파일을 교체한다. 엔드 이끼 소리는 `moss_block`, `moss_carpet`, 나무 설치 소리는 `use.wood`다. 금 블록은 돌과 같은 "metal" 소리를 쓰고 철/구리는 자기 ID가 있다. 물속에 놓을 때 설치 소리가 나지 않는다(바닐라도 같음). 1.26.30에 instrument sound 컴포넌트가 추가됐다.

## 11. 채굴, 도구, 루트 테이블

### 채굴 속도

- `destructible_by_mining` 밖에 `"tag:minecraft:is_pickaxe_item_destructible": {}`(또는 axe/shovel/hoe)를 컴포넌트로 두면 바닐라 도구가 빠르게 캐고 효율 인챈트도 자동 적용된다. 태그는 경도에 비례해 조정되므로 도끼는 `item_specific_speeds`보다 `tag:minecraft:is_axe_item_destructible`이 낫고 `<material>_tier` 태그는 등급을 잠글 때만 쓴다. 커스텀 곡괭이는 digger 컴포넌트에서 이 태그를 확인해야 한다.
- `item_specific_speeds`는 `minecraft:destructible_by_mining`의 `{item, destroy_speed}` 배열이며 item은 `{"tags": "q.all_tags('minecraft:is_pickaxe','minecraft:stone_tier')"}`처럼 쓴다. 등급 태그 `minecraft:wooden_tier` 등은 있지만 `minecraft:is_wooden_pickaxe`는 없다. 바닐라 곡괭이 태그는 `minecraft:digger`, `is_pickaxe`, `is_tool`, `<tier>_tier`다. format 1.21.30 미만에서는 경고 없이 실패한다.
- 바닐라 속도 맞추기: `seconds_to_destroy`는 실제 초가 아니며 기본적으로 실제 시간은 값의 1.5배다. 바닐라는 틀린 도구로 캘 때 3.33배 느리지만 커스텀 블록은 그렇지 않으니 직접 곱한다. 방법은 `seconds_to_destroy` = 바닐라 경도 x 3.33(맨손), `item_specific_speeds[].destroy_speed` = 경도 + 곡괭이 태그다. 위키 페널티 공식은 맞는 도구 경도 x 1.5, 틀린 도구 x 5인데 Bedrock은 1.5를 항상 적용하므로 틀린 도구 = H x 5/1.5, 맞는 도구 = H다.
- 동작하지 않는 태그: 등급 파괴 태그(`minecraft:iron_tier_destructible`), 검/철퇴 태그(`is_sword_item_destructible`)는 커스텀 블록의 드롭과 페널티에 영향이 없다(MCPE-189586). `minecraft:is_shears_item_destructible`은 2026-08쯤 수정됐다. "맞는 도구일 때만 드롭" 옵션은 없다. 블록 태그는 채굴 속도용, 아이템 태그는 루트 조건/레시피용이며 드롭 여부는 루트 테이블만 결정한다.
- `minecraft:digger` 한계(2026-02 기준): digger가 있는 커스텀 아이템은 바닐라 블록에 대해 항상 맞는 도구로 취급되어 등급과 무관하게 드롭한다. 내구도를 깎지 않고 정수 속도만 지원하며 `sword_efficient` 블록 태그나 커스텀 등급은 없다. 1인칭 도구 애니메이션도 깨져 있다.
- 부술 수 있는지 판정하는 API가 없으니 목록을 직접 관리한다. 바닐라 파괴 불가 블록: command_block, chain_command_block, repeating_command_block, end_portal_frame, bedrock, structure_block, barrier, allow/deny.

### 폭발

`minecraft:destructible_by_explosion`의 `explosion_resistance`에는 minecraft.wiki의 blast resistance를 쓴다. 음수는 받지 않는다. 폭발 파괴 저항은 바닐라 값보다 약 5배 약하므로 기대값 x5를 주석과 함께 쓰라는 조언이 있다. `false`여도 위더는 블록을 부순다. 저항을 매우 높이거나 커스텀 컴포넌트로 파괴를 취소한다.

### 루트 테이블

- `"minecraft:loot": "loot_tables/..."`로 지정한다. 커스텀 테이블을 쓰면 직접 나열하지 않는 한 블록 자신이 떨어지지 않으며 아이템과 블록을 둘 다 떨구려면 풀을 두 개 쓴다. 퍼뮤테이션 안의 루트 테이블도 동작한다. `set_data` 함수와 `count {min,max}`로 데이터 값 드롭을 만든다.
- `match_tool`은 `minecraft:match_tool_filter_all/any/none`에 아이템 태그(예 `["minecraft:is_shears"]`)를 준다. `"count": 1`이 없으면 빈손도 매칭된다. 등급 전용 드롭은 허용 곡괭이를 `items` 목록에 나열한다. 26.30부터(사용자 보고) `match_tool_filter_none`으로 "빈손" 조건을 더는 표현할 수 없으니 스크립트를 쓴다. Count 1 드롭은 폭발을 무시하며 피스톤이나 지지 상실은 두 풀을 모두 떨굴 수 있으니 정확히 제어하려면 `onBreak`를 쓴다.
- 실크터치는 하드코딩되어 루트 테이블을 무시하고 빈 루트 테이블로도 막을 수 없다. 우회법은 `world.beforeEvents.playerBreakBlock`을 취소하고 `system.run`에서 `block.setType("minecraft:air")`와 소리 재생, 기본 드롭 제거, 실크터치 확인 후 아이템 생성, 또는 `onBreak`에서 공기로 교체다. 포춘은 루트 테이블로 바닐라 공식을 재현할 수 없으니 스크립트를 쓴다.
- 광석 XP는 루트로 줄 수 없으니 `onPlayerBreak`에서 실크터치가 아니면 `minecraft:xp_orb`를 생성한다. 합의안은 아이템은 루트 테이블, XP만 스크립트다. 스크립트에서는 `getLootTableManager()`로 블록 + 도구 루트를 읽을 수 있다.
- 바닐라 블록 드롭은 26.50의 새 "데이터 드리븐" 바닐라 블록 외에는 바꿀 수 없다. 드롭을 지우고 스크립트로 생성하는 방식만 있다. 떨어진 아이템 텍스처는 상태별로 바뀌지 않으니 별도 아이템이 필요하고, 낙엽 더미식 블록은 상태마다 루트 테이블을 두는 것이 쉽다.
- 행동 팩이 있어도 업적을 유지하려면 manifest에 `"metadata": {"product_type": "addon"}`를 둔다.

## 12. 배치, 지지, 액체

- `placement_filter` 형식: `{"conditions":[{"allowed_faces":["up"],"block_filter":["minecraft:glass",{"tags":"q.any_tag('dirt')"}]}]}`. 블록 필터 목록은 64개로 제한된다. "고체/비고체" 일반 검사나 꽉 찬 지지를 요구하는 태그는 없고 모든 조건을 동시에 요구할 수도 없다.
- 지지 상실 시 부서짐은 불안정하다. 필터에 블록을 구체적으로 나열했을 때만 동작하고(유리류는 태그로 안 잡힘) cardinal+tag이면 한쪽만 유효해도 남는다. `allowed_faces`만 있고 `block_filter`가 없으면 다른 면 설치만 막는다. 클라이언트 예측은 항상 기본 퍼뮤테이션/`block_face="down"`을 쓴다. 필터는 회전을 무시한다(MCPE-236323). 의존 블록(문, 받침)이 정확히 따라 부서지게 하려면 파괴 이벤트로 이웃을 지운다.
- `minecraft:support`는 `{"shape": "fence"|"stair"}`이며 블록에 무엇이 붙을 수 있는지만 정하고 충돌과는 무관하다. 횃불, 레버, 버튼, 레드스톤 가루가 면에 붙는 것을 막는다. `stair`에 cardinal_direction/vertical_half가 없으면 어떤 면도 꽉 찬 것으로 치지 않는다. fence는 측면을 막고 윗면만 허용한다. 퍼뮤테이션에는 쓸 수 없다. 커스텀 울타리에서 `{shape:"fence"}`는 자기 연결을 깨뜨린다. 바닐라 면 지지 유형은 none, center, edges, both다.
- `minecraft:connection_rule`은 1.21.130 베타 실험에서 26.0 안정이 됐고 format 1.26.0 이상이 필요하다. 이 블록에 무엇이 연결되어 오는지를 정한다. `accepts_connections_from`은 `"none"`(울타리/벽/판유리/창살 연결 차단, 자기 타입 연결도 막음), `"only_fences"`(나무 울타리 + 트레이트/태그가 있는 커스텀만), `"all"`(모든 울타리, 벽, 판유리, 창살, 커스텀)이다. "같은 블록" 옵션이 없어 자기끼리 연결하려면 스크립트나 컬링이 필요하다. 회전된 블록은 `enabled_directions`에 transformation 후 방향을 넣는다(예 rotation [0,180,0]에 `"enabled_directions":["north"]`). 연결은 회전을 무시한다(MCPE-235806). 커스텀 울타리가 바닐라 네더벽돌 울타리와 연결되려면 `minecraft:has_fence_connections` 태그가 필요하다. `tag:one_way_collidable`은 블록 안의 플레이어를 밀어내지 않게 한다.

### 액체와 눈

- `minecraft:liquid_detection`은 물에 잠김과 물에 부서짐을 정한다. 액체 종류는 물뿐이다. `on_liquid_touches`는 `"blocking"`, `"popped"`, `"no_reaction"`이다. `stops_liquid_flowing_from_direction`으로 특정 방향의 물 흐름을 막는다. transformation 회전을 무시하고(MCPE-234654) 흐름 버그(MCPE-234648)가 있다.

```json
"minecraft:liquid_detection": {
  "detection_rules": [ { "can_contain_liquid": true, "liquid_type": "water", "on_liquid_touches": "no_reaction" } ]
}
```

- `use_liquid_clipping`은 한 번도 동작한 적이 없는 알려진 버그다(MCPE-236319). `minecraft:liquid_clipped`는 아이템 컴포넌트이며 26.10부터 block placer 아이템에 true면 물 위에만 놓인다(수련잎식). 해초식 블록은 `isWaterlogged`를 확인하는 틱 커스텀 컴포넌트가 필요하다. 커스텀 유체, 물/가루눈 안개, 커스텀 가마솥 액체는 불가능하다.
- 눈 묻힘: `"minecraft:precipitation_interactions": {"precipitation_behavior": "snowlogging"}`(스키마 이름은 `snow_log_no_collision`). 충돌이 없어야 하며 1.26.30까지 실험이었다. 눈 속 꽃처럼 묻히지 않게 하려면 `none`을 쓴다. 눈에 묻히면 컨테이너는 아이템을 떨구고 텍스처 변형이 첫 값으로 돌아간다. 월드젠에서 커스텀 블록 위의 눈 레이어는 막을 수 없다.

## 13. 레드스톤

- `minecraft:redstone_producer`는 버튼에 쓰던 "블록 교체 + 아래 레드스톤 블록" 핵을 대체한다. 퍼뮤테이션별로 power(0 또는 15)를 준다. `strongly_powered_face`는 방향 하나(문자열)이고 생략하면 경고가 난다. 레드스톤 가루가 블록에 연결되게 하려면 `connected_faces`를 쓴다. `transform_relative: true`면 면은 블록 자체 기준이다. 1.26.20부터 base `components`에도 있어야 퍼뮤테이션에 둘 수 있다. 같은 블록이 main components에서 producer이면서 consumer일 수는 없다.

```json
"minecraft:transformation": { "rotation": [ 0, 180, 0 ] },
"minecraft:redstone_producer": { "power": 15, "connected_faces": [ "east", "south" ], "strongly_powered_face": "east", "transform_relative": true }
```

- producer 버그: 퍼뮤테이션이 바뀌어도 출력 방향이 갱신되지 않고(MCPE-242205) 인접 가루를 제대로 향하지 않는다(MCPE-242204).
- `minecraft:redstone_consumer`는 `min_power`, `propagates_power`를 가지며 format 1.26.0 이상과 `onRedstoneUpdate`(`e.powerLevel`) 커스텀 컴포넌트를 함께 쓰고 매 틱 검사보다 싸다. `propagates_power`를 켜지 않으면 꽉 찬 지오메트리여도 전도하지 않는다. 측면 가루가 연결되려면 `redstone_conductivity.redstone_conductor`가 필요하다. consumer는 방향성이 없어 리피터를 만들 수 없다. consumer이기도 한 블록은 비교기 출력을 낼 수 없다.
- `onRedstoneUpdate`는 첫 설치와 청크 로드에도 발생하므로 문/뚜껑문 같은 토글 블록은 변화를 감지할 별도의 전원 상태가 필요하다. 베타의 `firstUpdate` boolean이 초기 로드 이벤트를 거른다. 레드스톤 동작에 onTick을 쓰지 않는다.
- 켜짐/꺼짐 광석은 `pro:lit` 상태와 `query.block_state('pro:lit') == true` 퍼뮤테이션으로 light_emission과 텍스처를 바꾸고 random tick이나 tick으로 되돌린다.

## 14. 기타 컴포넌트

- `minecraft:friction`(conflicting): 기본값이 0.4라 위키의 0.6은 틀렸다는 보고가 있다. 방향은 의견이 갈린다(높을수록 더 미끄럽다는 쪽과 낮을수록 마찰이 크다는 쪽). 한 값이 내부의 두 가지를 같이 바꿔 영혼 모래식 블록은 불가능하다. 기본값을 원하면 생략한다.
- `minecraft:flammable`의 값은 객체다(`catch_chance_modifier`, `destroy_chance_modifier`, `lava_flammable`). `lava_flammable`은 format 1.26.20 이상에서 동작한다. 기본값은 `"never"`(MCPE-240718, 의도된 동작)다. 영원히 타는 블록이나 용암에 면역인 가연 블록은 만들 수 없다. 불과 영혼불은 하드코딩이다.
- `minecraft:replaceable`은 `{}`만 받으며 블록을 잔디처럼 교체 가능하게 만든다. `minecraft:crafting_table`은 커스텀 조합 UI를 준다(화로 컴포넌트는 없음).
- `minecraft:map_color`는 블록 지도 색을 지정한다(바닐라 블록 지도 색은 바꿀 수 없음). `BlockMapColorComponent`는 바닐라 블록에서 동작하지 않는다(MCPE-240722).
- `minecraft:flower_pottable` + `minecraft:embedded_visual`은 format 1.21.124 이상이 필요하다. 모든 퍼뮤테이션에 지오메트리 + material_instances가 있어도 root에 따로 있어야 하고(MCPE-237910) 1.26.20부터 퍼뮤테이션에서는 금지된다.
- `minecraft:chest_obstruction`은 상자, 엔더, 덫, 구리 상자에 적용되고 셜커에는 아니다. `"shape"` 모드는 충돌 박스를 쓰며 origin [-7,0,-7] size [14,8,14]와 겹치면 실패한다.
- 태그(conflicting): 이전 형식은 블록 태그를 `"tag:ns:name": {}` 컴포넌트로 쓴다. format 1.26.20부터는 `"minecraft:tags": ["ns:tag"]` 배열이 대체한다고 하지만 1.26.20 무렵 배열이 로드되지 않고 `tag:` 형식이 필요했다는 보고가 있다. `query.block_neighbor_has_any_tag`/`block_has_any_tag`는 더 쓸 수 없다.
- 몹 스폰: 오래된 형식의 커스텀 풀블록 위에는 몹이 스폰되지 않았지만 format 1.21.90 이상에서 고쳐졌다(한 사용자는 1.26.0 필요). 블록이 고체/불투명이어야 한다. 커스텀 블록을 바이옴 `top_material`로 쓰면 엔티티가 스폰되지 않는다는 보고가 있다.
- trial spawner는 자연 몹 스폰 규칙이 켜져 있어야 스폰한다. 우회법은 BP spawn_rules로 자연 적대 몹 스폰을 막는 것이다(format 1.8.0 `minecraft:spawns_on_block_filter: ["minecraft:deny"]` 또는 weight 0).
- 컴포넌트 정리 순서(ciosciaa 제안): METADATA(display name, loot, transformation, random offset, tags) → PRESENTATION(geometry, material instances, item visuals, embedded visuals, destruction particles, map color) → PHYSICS(selection/collision box, friction, light dampening/emission, precipitation, destructible by mining/explosion, liquid detection, flammable, movable) → RELATIONS(placement filter, replaceable, support, connection rule) → FEATURES(redstone, crafting table, leashable, flower pottable) → EVENTS(tick, fall-on).

## 15. 블록으로 만드는 패턴

- 문: `onPlayerInteract(event, definition)`에서 `permutation.withState`로 불리언 상태를 토글하고 `dimension.playSound(sound, block.center())`로 소리를 낸다. 파라미터 예는 `"ns:door": {"block_state":"ns:open_bit","enable_sound":"open.wooden_door","disable_sound":"close.wooden_door"}`다. 열림/경첩은 `bone_visibility` Molang(`"door_open": "q.block_state('ns:open_bit') && !q.block_state('ns:door_hinge_bit')"`)으로 처리한다. 2칸 문은 멀티블록을 쓴다. 지오메트리는 base에 한 번 정의한다. 블록과 아이템은 `block_placer` + `replace_block_item`으로 합치고 `minecraft:is_axe_item_destructible` 태그를 쓴다.
- 뚜껑문은 `onPlayerInteract({block, dimension})`에서 `block.permutation.withState("ns:open", !isOpen)`을 하고 `open.wooden_trapdoor`/`close.wooden_trapdoor`를 `block.center()`에 재생한다. 압력판은 `onStepOn`/`onStepOff`로 불리언을 토글하지만 높이 제약 때문에 얇은 판은 어렵다.
- 반블록은 두 뼈를 가진 full-block 지오메트리 하나를 `vertical_half`로 전환하고 double 상태를 둔다. 바닐라 반블록 동작을 복제하려면 `minecraft:support {shape:"stair"}` + `minecraft:vertical_half`(cardinal/facing 트레이트 없이)를 쓴다. support는 퍼뮤테이션에 둘 수 없으니 겹반블록은 별도 블록 파일로 둔다. 겹치기는 스크립트가 필요하다. 방법 1: `ns:is_double_slab` 상태와 `beforeEvents.playerInteractWithBlock`에서 `minecraft:vertical_half`, `blockFace`, 들고 있는 아이템을 확인하고 `event.cancel = true` 후 `system.run`에서 `withState(state, true)`를 한다. 방법 2: 아이템 `"minecraft:block_placer": {"aligned_placement": true, "block": "...", "replace_block_item": true, "use_on": [{"tags": "q.any_tag('this_tag_should_not_be_used_on_any_block')"}]}`로 스스로 설치하지 않게 하고 아이템 커스텀 컴포넌트가 설치와 병합을 처리한다. 방법 3: 아이템 컴포넌트 `onUseOn`에서 `usedOnBlockPermutation`, `blockFace`, `faceLocation.y`를 보고 인접 칸에 반쪽을 놓는다(`faceLocation.y`는 y가 0 이하일 때 뒤집혀 있어 MCPE-236442 보정 필요). 26.20 이후 겹반블록 설치 시 유령 블록이 보인다.
- 계단은 26.0 안정 트레이트(`placement_direction` + `vertical_half` + `corner_and_cardinal_direction`) 조합으로 40 퍼뮤테이션이 된다. UV lock은 UV 매핑만 바꾸고 회전된 계단에서 제대로 동작하지 않는다. 충돌은 다중 박스 두 개를 쓰고 선택 박스는 꽉 찬 큐브로 남는다. 계단 자기 코너링 버그는 MCPE-234801이다.
- 울타리: 충돌 폭이 정확히 16이면 물 글리치가 나니 15.999를 쓴다. 울타리 문은 커스텀 컴포넌트가 필요하고 울타리는 문의 앞뒤에도 연결된다. 벽 템플릿에서 `sticky:"same"`은 피스톤 이동을 막으니 "none"을 쓰고 판유리는 벽에 붙을 수 있게 취급해야 한다. 벽 윗부분은 연결과 위 벽에 달려 있어 불리언 상태가 6개 필요하다. 커스텀 판유리는 1.26 이전 안정판에서 네이티브로 불가능해 스크립트(100-300줄)가 필요하다. 바닐라 벽 상태(벽 모양 165개)는 노출되지 않는다.
- 작물과 덩굴: `minecraft:tick`(또는 더 싼 `onRandomTick`) + `permutation.withState(state, value+1)`로 키우고 다 자란 단계는 퍼뮤테이션 조건 컴포넌트로 처리한다. 농지가 아래 있으면 slow_falling을 줘서 짓밟힘을 막는다. 덩굴은 `onRandomTick`이 끝을 몸통으로 바꾸고 아래에 새 끝을 놓는다. 뼛가루는 `playerInteractWithBlock`에서 `cancel = true` 후 `system.run`으로 처리하고 생존 모드 소모는 `getEquipmentSlot(EquipmentSlot.Mainhand)`로 `stack.amount--; slot.setItem(stack)`을 하며 `GameMode.Creative`에서는 건너뛴다. 바닐라 식물은 커스텀 블록 위에 놓을 수 없고 사탕수수식 지지는 sand 태그로 되지 않았다.
- 묘목: 피처는 묘목 위에 놓이므로 묘목이 피처의 `may_replace`에 있거나 먼저 지워져야 한다. `dimension.placeFeature`를 쓴다.
- 통나무 벗기기는 주손에 도끼가 있으면 `onPlayerInteract`에서 `block.setType(stripped)`를 하고 내구도는 `item.getComponent("minecraft:durability").damage++` 후 `slot.setItem(item)`로 깎는다. 지연 후 블록 교체는 `system.runTimeout`, 2칸 블록은 `beforeOnPlayerPlace`에서 `permutationToPlace`로 위 블록을 놓고 `minecraft:cardinal_direction`을 복사한다.
- 탄력 블록은 `onEntityFallOn` 낙하 거리 → `applyImpulse`, 낙하 피해는 before entity hurt에서 원인 fall과 아래 블록을 확인해 취소한다. 선인장 피해는 블록별 틱 대신 `system.runInterval`을 쓴다. 불 감지는 주변의 `minecraft:fire`를 확인하는 틱 컴포넌트로 한다. 포털은 커스텀 지오메트리, 충돌, 애니메이션 텍스처, 축 상태를 가진 일반 블록으로 만든다.
- 구조 공허식 블록(손에 들 때만 보이는 투명 블록): `minecraft:geometry.full_block`, `minecraft:collision_box: false`, `"*": {texture:"invisible", render_method:"blend"}`, `minecraft:selection_box: true`, `minecraft:tick` interval [1,1], 플레이어가 아이템을 들면 `minecraft:shulker_bullet` 파티클을 내는 onTick(format 1.21.90). `player.spawnParticle`을 쓰면 그 플레이어만 본다. 방벽 가시성은 하드코딩이다.
- 블록에서 엔티티 소환은 `complete` 불리언 상태를 두고 complete=false 퍼뮤테이션의 tick이 엔티티를 소환한 뒤 complete를 true로 바꾼다. 동적 조명은 모두 플레이어 위치에 `light_block`을 놓거나 옮긴다.
- 다중 블록 구조물 갱신은 BFS 큐와 `x,y,z` 키 visited Set으로 이웃을 훑으며 typeId와 `minecraft:cardinal_direction`을 비교한다(visited 없는 재귀는 무한 루프). `Block` 객체는 접근할 때마다 새로 만들어지니 위치 + 퍼뮤테이션을 쓰는 편이 빠를 수 있다. 스크립트에서 블록을 부수려면 runCommand로 `/setblock ... destroy`를 쓴다.
- 템플릿 모음 Kaioga's Block Templates는 바닐라 블록 재현 약 80개(BP+RP 쌍과 .mcaddon, 주석, 실험 토글 없음)이며 1.26.50으로 갱신됐다. 선인장, 케이크, 덩굴, 사다리, 벽, 눈 레이어, 광석, 문, 슬라임 블록을 포함한다.

## 16. 블록으로 불가능한 것과 엔티티 대안

- 불가능(엔티티나 스크립트로 대체): 낙하/중력 블록(같은 텍스처의 커스텀 낙하 엔티티), 애니메이션 컨트롤러와 연속 애니메이션, 상자/컨테이너(26.50 block_entity 이전), 표지판/텍스트, 커스텀 유체, 방벽 가시성, 엔드 관문 효과, 벽 너머로 보이는 블록, 붙을 수 없는 비고체, 몹 경로 차단(엔티티 쪽 `behavior.avoid_block`이 결정), 바닐라 지도 색 설정, 바닐라 블록 수정/교체, 디스펜서 감지, 블록에서 XP 드롭(스크립트 필요), 이웃 변화 이벤트(`onNeighbourUpdate`).
- 엔티티 대안 패턴: 상호작용 가구, 아이템 진열대, 수납 서랍, 받침대는 보이지 않는 엔티티로 만든다(설치 시 소환, 파괴 시 제거, 충돌은 엔티티 컴포넌트). 인벤토리 블록 = 인벤토리 엔티티이며 `player.openInventory`는 없다. 엔티티 상자는 닫을 때 디스폰하고 인벤토리를 스크립트로 저장할 수 있지만 엔티티가 많으면 렉이 생긴다. `/kill @e`에서 지키려면 최소 체력 1을 준다. 가구 엔티티를 한 번 더 클릭해야 하는 것은 히트박스가 작아서이니 히트박스를 키운다. 자세한 엔티티 쪽 규칙은 [엔티티](./entities.mdx)의 16절에 있다.
- 커스텀 머리는 16방향, 착용 가능하다. 충전된 크리퍼 드롭은 하드코딩이고 위더 해골 루트만 데이터 드리븐이다. 블록 지오메트리에 Molang이 없어 머리 뼈는 4개뿐이다.
- 커스텀 나무 세트에 빠진 것(2026-02): 표지판 텍스트, 겹반블록 픽블록, 선반 아이템 표시/비교기, 소리 블록 소리, 용암 가연성(이후 1.26.20에서 추가).

## 17. 사례: 활성 시에만 움직이는 블록 텍스처 (한 Dragonfly 기반 서버)

기계가 동작 중일 때만 움직이는 텍스처를 보여 주는 방법이다(출처: 비공개 조사). 블록 텍스처 애니메이션은 리소스팩의 `textures/flipbook_textures.json`으로 한다. 이미지는 폭 16, 높이 16 x 프레임 수의 세로 띠이고 항목 하나가 아틀라스 타일 하나(`terrain_texture.json`의 키)를 움직인다.

```json
[
  {
    "flipbook_texture": "textures/blocks/harvester_side_on",
    "atlas_tile": "custom_harvester_side_on",
    "ticks_per_frame": 2,
    "blend_frames": false
  }
]
```

- `ticks_per_frame`은 프레임당 틱(20틱 = 1초)이며 `frames`(프레임 순서 배열)로 순서·반복을 직접 줄 수도 있다. `blend_frames`는 프레임 사이를 섞어 부드럽게 한다(기본 켜짐, 픽셀 느낌은 `false`). 그 밖에 `atlas_index`, `atlas_tile_variant`, `replicate`가 있다. 커스텀 블록은 `material_instances`의 텍스처 이름이 그 아틀라스 타일이면 그대로 움직인다. `terrain_texture.json`·`flipbook_textures.json`은 팩끼리 병합된다.
- flipbook은 클라이언트가 항상 돌리므로 켜고 끄는 것은 블록 상태(permutation)로 텍스처를 바꿔서 한다. 꺼진 상태는 정지 텍스처, 켜진 상태는 움직이는 타일(`..._on`)을 쓴다. 서버는 기계가 일을 시작하거나 멈출 때만 `SetBlock`한다. 한 Dragonfly 기반 서버는 블록 상태 `custom:active`(`off`/`on`)를 쓰고 마지막 작업 뒤 40틱은 켜진 채로 둬 깜빡임을 막는다.
- 제약: 모든 블록이 같은 박자로 움직이며(켜지는 순간 0프레임부터 시작하지 않음), 서버 값에 맞춘 진행도 그림은 안 된다(상태별 텍스처/모델 사용). 텍스처만 움직이므로 부품이 도는 모습이 필요하면 엔티티를 겹쳐 띄워야 해 훨씬 무겁다. 아이템 아이콘에서는 flipbook이 버전에 따라 동작하지 않으니 정지 이미지로 둔다. `alpha_test` 재질에서 움직이지 않거나 전환이 늦으면 `blend_frames`와 렌더 방식을 바꿔 본다.
