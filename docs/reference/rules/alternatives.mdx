이 페이지는 `scripts/gen-rules.mjs`가 `rules/*.json`에서 만든다. 직접 고치지 않고 JSON을 고친 뒤 `npm run gen-rules`를 실행한다. 주제 페이지의 규칙 글머리(`- **[ID]**`)도 같은 원본에서 채워진다.

설명과 예제는 주제 페이지 [JSON UI가 맞지 않을 때](../../json-ui/alternatives.mdx)에 있다.

| ALT-11 | 26.64부터 리소스 팩은 Ore UI 파일을 바꿀 수 없다. 26.64가 보안 문제로 리소스 팩의 Ore UI 접근을 막았다(커뮤니티 보고). 이 규칙의 나머지는 26.63까지의 동작이다. Ore UI 화면은 설치 폴더 `data/gui/dist/hbui/`의 해시 붙은 압축 JS·CSS·HTML 번들이다. 엔진은 Ore UI 파일(`ui://…`)을 찾을 때 설치 폴더보다 팩 스택을 먼저 보지만, 신뢰된 팩만 본다. 신뢰 판정은 팩을 여는 형태가 정하고 UUID·마켓플레이스 서명은 보지 않는다. 평문 팩(평문 zip·폴더 팩)은 설치 폴더의 내장 팩만 신뢰되므로 일반 리소스팩·평문 서버 팩으로는 배치·동작·CSS를 바꿀 수 없다. 암호화 팩 전략 세 종류는 언제나 신뢰되므로, 그 전략으로 열린 팩의 `hbui/<파일>`은 게임 중 Ore UI 페이지(`gameplay.html`: 사망·침대·인벤토리·DDUI·거래·블록 화면)의 HTML·JS·CSS를 바꾼다. 그렇게 여는 길은 두 가지다. **(1) 서버 없이: 로컬 리소스팩 폴더의 루트에 0바이트 빈 파일 `content.zipe`를 두면** 엔진이 그 팩을 암호화 폴더 팩으로 연다. 엔진은 이 파일이 있는지만 보고, 키 없이 팩 폴더의 평문 파일을 그대로 읽는다. `.mcpack`으로 가져올 때는 zip 맨 위에 `manifest.json`과 `content.zipe`가 바로 있어야 한다(한 단계 깊으면 아무 메시지 없이 가져오기가 되지 않는다). 같은 가짜 암호화 헤더를 `contents.json`에 단 팩은 바뀌지 않는다. **(2) 서버가 아무 32바이트 콘텐츠 키로 암호화해 키와 함께 보낸 팩**(같은 팩을 평문으로 보내면 바뀌지 않음을 실측). 이 페이지의 JS가 바닐라 DDUI 데이터 저장소를 읽고 써서, 서버가 보낸 레이아웃대로 그리고 누름·입력을 돌려받는 화면을 만들 수 있다(OL 3장·6장~9장). 바꾼 `gameplay.html`에는 바닐라 번들의 해시 붙은 파일 이름이 들어가므로 게임 업데이트마다 설치본과 맞춘다. 클라이언트 설치 폴더를 직접 패치하는 도구(OUC)는 그 클라이언트에만 적용되고 업데이트마다 다시 적용해야 한다. | 코드(소스), 실측 | 모름 | OUC 2장·3장, OL 3장·6장·7장·8장·9장, 커뮤니티 |
| ALT-12 | Ore UI가 게임 텍스처를 쓸 때는 `pack://textures/…png` URL로 요청하고, 이 경로는 신뢰하지 않는 서버 팩의 텍스처로도 풀린다(버튼 텍스처로 실측). 따라서 텍스처를 바꾸는 리소스팩은 Ore UI의 아이템·블록 아이콘에도 반영될 것이다(아이콘 자체는 따로 확인하지 않음). 번들 자체 이미지(`/hbui/assets/`)와 폰트(`gui/dist/hbui/fonts`)는 설치 폴더에서 읽어 팩으로 바뀌지 않는다. | 코드(소스), 실측, 추론 | 모름 | OUC 3장·4.6, OL 4장·6장 |
| ALT-13 | 화면마다 JSON UI와 Ore UI 중 무엇을 쓸지 고르는 facet `vanilla.screenTechStack`(`getTechStackForScreen`, `getPreferredTechStackForScreen`, `selectTechStackForScreen`)이 있다. 두 구현이 공존하는 화면에서는 JSON UI 수정이 JSON UI 쪽이 선택됐을 때만 보인다고 보고, 수정이 안 보이면 먼저 그 화면이 어느 쪽으로 열렸는지 확인한다. Windows 1.26.65.1 클라이언트의 선택기는 경로 14개(`/play`, `/main-menu`, `/pre-start`, `/create-new-world`, `/start-from-template`, `/edit-world`, `/gameplay/death`, `/player-permissions`, `/send-invites`, `/gameplay/bedtime`, `/settings`, `/safezone`, `/oreui-marketplace/wishlist`, `/oreui-marketplace/search`)를 기록하고 경로마다 조건 함수가 둘이고 기본 결과는 둘이 모두 참일 때 참이다. 조건 표는 Ore UI 개요에 있다. | 코드(소스), 추론 | - | OUC 0장 |
| ALT-14 | Ore UI의 데이터 채널은 바인딩이 아니라 facet이다(`engine.trigger("facet:request", 이름)` → `facet:updated:<이름>`). 게임 중 화면용 `vanilla.gameplay.*` facet(화로 진행도, 컨테이너 아이템·크기, 사망 정보, 리스폰, 침대, 좌표 HUD 등)이 있다는 것은 해당 화면이 Ore UI로 옮겨 가는 중이거나 옮겨 갔다는 신호다. JSON UI로 그 화면을 재스킨하는 작업은 이전 위험을 감안한다. | 코드(소스), 추론 | - | OUC 3장 |
| ALT-15 | 엔진은 JSON UI 정의 두 개를 팩 스택에서 풀어 facet `vanilla.resourcePackOverrides`로 게임 중 Ore UI(`gameplay.html` 전체: 사망·침대·인벤토리·DDUI·거래 등)에 넘긴다. `common_buttons.light_text_button`의 하위 컨트롤 `default`·`hover`·`pressed`·`locked`에서 `$new_ui_button_texture`(배경, 나인슬라이스 포함), `$text_color`(글자색), `$border_color`(테두리색)를, `common_buttons.focus_border`에서 `texture`를 가져가 primary·secondary 버튼의 기본·hover/focus·pressed/selected·disabled 상태에 입힌다. 따라서 `_global_variables.json`의 `$light_button_*_text_color`나 `textures/ui/button_borderless_light*.png`를 바꾼 팩은 Ore UI 사망 화면 버튼까지 바꾼다(서버 팩으로 실측). 다른 정의·속성은 넘어가지 않고, 게임 밖 메뉴 번들은 이 facet을 쓰지 않는다. | 코드(소스), 실측 | 모름 | OL 4장·6장 |
| ALT-16 | DDUI 레이아웃(`ddui/root/*.json` = `minecraft:ui-root`, `ddui/composition` = `minecraft:ui-composition`)은 리소스팩 폴더에서 읽지만, 엔진은 게임 내장(퍼스트파티) 팩으로 표시된 팩만 읽는다(POI의 `minecraft:` 이름공간 허용 판정과 같은 플래그). 사용자·서버 팩에 `ddui/root/custom_form.json`을 넣어도 쓰이지 않을 것이다. JS는 바닐라가 아닌 출처 팩의 레이아웃(`isCreatorDataDriven`, 자기 팩 이미지만 허용)을 이미 처리하므로, 엔진 검사가 풀리면 열릴 통로다. | 코드(소스), 추론 | - | OL 5장 |
