# 애니메이션과 애니메이션 컨트롤러

## 개념

**애니메이션**은 본의 회전·위치·크기를 시간에 따라 바꾸는 키프레임 파일이다(`animations/*.json`). **애니메이션 컨트롤러**(AC)는 상태 기계다. 상태마다 "지금 무엇을 재생할지"와 "어떤 조건에서 다른 상태로 넘어갈지"를 정한다. 컨트롤러는 리소스 팩(RP)과 비헤이비어 팩(BP) 양쪽에 있다. RP 컨트롤러는 본 애니메이션, 사운드, 파티클을 재생하고, BP 컨트롤러는 명령, 이벤트, Molang 식을 실행한다(출처: bedrock-wiki `animation-controllers/animation-controllers-intro`).

상태 기계는 한 번에 한 상태에만 있다. 컨트롤러는 매 틱마다 (1) 현재 상태의 애니메이션을 재생하고 `on_entry` 명령을 실행하며(막 들어온 경우), (2) `transitions`를 위에서 아래로 검사해 처음 참인 전환으로 이동하고 `on_exit`를 실행한다. 그래서 한 틱에 최대 한 번만 상태를 옮긴다. `initial_state`가 없으면 `default`라는 이름의 상태를 쓰고, 그것도 없으면 콘텐츠 로그 오류다. 엔티티가 다시 로드되면(플레이어 입퇴장, 청크 재로드) 컨트롤러는 기본 상태로 돌아가므로, 기본 상태에는 핵심 애니메이션을 다시 시작하는 논리를 둔다.

## 예제: 지상과 비행의 두 상태

<Excerpt src="bedrock-wiki" title="Intro to Animation Controllers" path="docs/animation-controllers/animation-controllers-intro.md">

```json
{
    "format_version": "1.10.0",
    "animation_controllers": {
        "controller.animation.helicopter.blade": {
            "initial_state": "ground",
            "states": {
                "ground": {
                    "transitions": [ { "flying": "!q.is_on_ground" } ]
                },
                "flying": {
                    "animations": ["flying"],
                    "transitions": [ { "ground": "q.is_on_ground" } ]
                }
            }
        }
    }
}
```

</Excerpt>

컨트롤러는 파일에 정의하는 것만으로는 아무것도 하지 않는다. 클라이언트 엔티티의 `animations`에 짧은 이름을 주고 `scripts.animate`에서 실행해야 한다. 조건을 붙이면 그 식이 참일 때만 돈다.

```json
"description": {
  "identifier": "wiki:helicopter",
  "animations": {
    "blade_controller": "controller.animation.helicopter.blade",
    "flying": "animation.helicopter.flying"
  },
  "scripts": {
    "animate": [ { "blade_controller": "q.has_rider" } ]
  }
}
```

RP 컨트롤러의 상태는 사운드와 파티클도 재생한다. 먼저 클라이언트 엔티티에 `sound_effects`와 `particle_effects` 짧은 이름을 정의하고 상태에서 `effect`로 부른다(`locator`도 줄 수 있다). 모든 파티클이 여기서 동작하지는 않으니 문제가 있으면 다른 파티클(예: 블레이즈 컨트롤러가 쓰는 것)을 시도한다(출처: bedrock-wiki).

```json
"explode_state": {
  "sound_effects": [ { "effect": "explosion" } ],
  "particle_effects": [ { "effect": "fuse_lit" } ],
  "transitions": [ { "default": "q.mark_variant == 0" } ]
}
```

BP 컨트롤러는 `on_entry`와 `on_exit`에 슬래시 명령(`/say hi`), 엔티티 이벤트(`@s wiki:transform_into_plane`), Molang 식(`v.tickets += 1;`)을 넣는다. 아래 규칙은 커뮤니티 조사 결과다(출처: 비공개 조사).

## 클라이언트 엔티티 연결

- 1.10.0 이상 클라이언트 엔티티에서는 애니메이션과 컨트롤러를 `animations`에 짧은 이름으로 두고 `scripts.animate`에서 참조한다. 목록에 없으면 실행되지 않는다. `confirmed`
- `animation_controllers` 배열은 1.8.0 전용이라 섞으면 엔티티가 사라지고 "client_entity child 'animation controllers' not valid there"가 난다.
- `"animate": {"controller": {}}`나 `" controller "`(공백)는 "unknown child schema option type. Allowed types: 'molang'"을 낸다.
- 애니메이션을 추가한 직후 몹과 스폰 알이 안 보이면 대개 깨진 클라이언트 엔티티 JSON이다. 콘텐츠 로그(설정, Creator, Content Log GUI)를 확인하고, 손으로 고쳤다면 Blockbench에서 다시 내보낸다. 1.8 클라이언트 엔티티는 컨트롤러를 포함해 1.10.0으로 갱신한다.

## 이름 규칙

- 파일 안의 애니메이션 id는 `animation.name` 형식이어야 한다("child pose_1 not valid here"는 `animation.pose_1`로 바꿔 해결).
- 애니메이션·모델·본 이름은 공백 없는 소문자로 쓴다. `animation.unwfoxyfm.showtime`은 되고 `animation.UnwFoxy FM.Showtime`과 본 그룹 `Right Eyelid`는 게임에서 깨졌다.
- 두 컨트롤러나 파일이 같은 식별자를 쓰면 "detected loop in animation controller creation... controller already exists"가 난다.
- Blockbench 내보내기는 Animation 탭, file, export이며 RP `animations/`에 둔다. Bridge는 애니메이션을 미리 보지 못하니 컨트롤러는 손으로 설정한다.

## 대기와 걷기 전환

- `default`와 `moving` 상태를 가진 컨트롤러에서 `query.ground_speed > 0.1`(또는 `query.is_moving`)로 전환하고 애니메이션을 상태 안에 나열한다. 애니메이션마다 컨트롤러 하나보다 상태 여러 개를 가진 컨트롤러 하나가 낫다.
- `q.is_moving && !q.is_swimming && !q.is_sprinting && q.is_on_ground`는 `query.ground_speed > 0.1 && query.is_on_ground`로 단순화할 수 있다. `query.ground_speed`는 속력이지 방향이 아니므로 앞뒤에는 `query.movement_direction`을 쓴다.

## 공격과 걷기를 동시에

- 걷기를 `scripts.animate`에 두거나(`{"walk":"q.ground_speed"}`) 컨트롤러 두 개를 병렬로 돌린다(`"animate": ["controller1","controller2"]`). `override_previous_animation`이 블렌딩에 영향을 준다.
- 공격 감지는 `variable.attack_time > 0`(애니메이션, 컨트롤러, 어태처블, 클라이언트 엔티티 어디서나)과 `variable.has_target`이다. `query.is_delayed_attacking`은 `delayed_attack` 준비 동안 계속 참이라 긴 공격 애니메이션에 쓰고(`v.attack_time`은 약 0.2초), 랜덤 공격은 `math.random_integer(1, 5) == 1 && query.is_delayed_attacking`처럼 애니메이션마다 숫자를 준다. 활 당김은 `query.main_hand_item_use_duration`이다.

## 한 번 재생 후 전환

- `q.all_animations_finished`를 쓰고 즉시 반복되지 않도록 대기 루프 상태를 세 번째로 둔다.
- 레버 같은 토글은 `up`, `down`, `pull_up`, `pull_down` 상태와 `q.property(...)` 전환을 쓴다. `q.all_animations_finished`는 한 프레임 깜빡임을 일으켜 `q.anim_time > N`이 더 나았다.

## 마지막 프레임 유지와 깜빡임

- hold-on-last-frame은 불안정하다. 모든 본의 마지막 키프레임을 선형으로 하면 된다는 보고가 있고, `loop: "hold_on_last_frame"`이 마지막 자세를 유지한다.
- 루프 애니메이션 끝에서 기본 자세로 튀면 첫 키프레임과 마지막 키프레임을 같게 하고(본이 시작 자세로 돌아와야 한다) 마지막 키프레임을 smooth가 아닌 linear로 한다.
- 상태 사이에 간격이 있으면 컨트롤러 전환에서도 같은 깜빡임이 생기니 대기 끝 자세와 공격 끝 자세가 같은지 확인한다.
- 마지막 타임스탬프에 키프레임이 없으면 눕기 루프 중 엔티티가 사라졌다. `animation_length`에 같은 키프레임을 추가한다.
- smooth 키프레임은 앞뒤를 linear 키프레임으로 감싸야 게임에서 글리치가 없다(최소 0 0 0에 선형 프레임).

## Molang 수식 애니메이션

스폰마다 랜덤 크기를 주는 예다. `??`는 null 병합, `;`는 문장 구분이다.

```json
"scale": "v.size = v.size ?? math.random_integer(1,10); v.anim_time = v.anim_time ?? 0; v.scale = v.size*math.sin(math.min(v.anim_time,3)*30); v.anim_time = v.anim_time + q.delta_time; return v.scale;"
```

- 타이머가 진행되지 않으면 `q.anim_time` 대신 `q.delta_time`을 쓴다. `/playanimation`은 랜덤 크기에 거의 쓸 수 없으니 클라이언트 엔티티 `animations`와 `scripts.animate`에 정의한다.
- 숨쉬기 대기: `math.cos(query.life_time * 120) * 10`(속도 120, 진폭 10)을 별도 루프 애니메이션으로 두고 팔다리 애니메이션과 분리한다.
- 애니메이션 속도: `anim_time_update: "query.anim_time + query.delta_time * 1.05"`(상수 대신 `query.ground_speed`도 가능).
- Molang에는 `%`가 없다("unrecognized token %"). `math.mod(a, b)`를 쓴다.
- property 기반 부드러운 본 회전: pre-animation에서 `q.bone_orientation_trs(bone)`(`queryable_geometry` 필요, 특수 좌표계)로 `t.old_rotation`을 얻고 `v.rotation = math.lerprotate(t.old_rotation, q.property('pack:rotation_y'), q.delta_time)`로 한다. property 범위는 0~360이다. `q.bone_orientation_trs().r.y`는 -90~90(오일러)으로 제한되므로 완전한 360도 회전에는 z도 바꿔야 한다.
- 랜덤 `loop_delay`: 랜덤 변수를 쓴 `loop_delay`는 업데이트 후 한 번만 무작위가 된다. 대안은 `override_previous_animation`과 더 긴 `animation_length`, 또는 비헤이비어의 랜덤 루프 타이머로 깜빡임을 일으키는 것이다.
- 이징과 스냅: 한 본 채널 안의 축별 이징은 지원되지 않는다. Blockbench 키프레임이 0.833 등에 스냅되면 애니메이션 스냅 설정을 바꾼다(애니메이션 더블클릭). 인간형 애니메이션에서 머리·팔에 위치 키프레임을 두면 자세가 깨지니 위치 키를 지운다.

## 스폰 애니메이션과 명령어

- "처음 스폰됨" 쿼리는 없으므로 BP 엔티티의 `on_spawn` 이벤트(또는 스크립트 `entitySpawn` after 이벤트)에서 `/playanimation`을 실행한다.
- 컨트롤러 안의 이벤트·명령 타임라인은 실행되지 않을 수 있으니 BP 애니메이션 타임라인에 명령을 둔다: `"timeline": {"0.0": ["/playanimation @s animation.x"]}`.
- RP 컨트롤러는 `/scriptevent`나 명령어를 실행할 수 없고, BP 애니메이션·컨트롤러는 실행할 수 있다.
- 지연 반복 사운드는 루프 BP 애니메이션 안에서 재생하고 컨트롤러로 켜고 끈다. 0.59초 루프 공격 애니메이션의 이벤트가 실행되지 않던 문제는 `loop: true`로 고쳤다.
- `/playanimation`을 부주의하게 쓰면 플레이어에 새 애니메이션 컨트롤러가 계속 만들어져 메모리가 샌다.

## property를 읽는 변수

- `scripts.pre_animation`에서 `v.x = query.property('ns:prop')`을 쓰고, property에는 `client_sync: true`가 필요하며 id에는 `.`이 아닌 `:`을 쓴다.
- `variable.melee_spear_equipped` "unknown variable"은 `"scripts": {"initialize": ["variable.melee_spear_equipped = 0.0;"]}`로 고친다. 창이 없는 플레이어 오류 수정 예: `"v.melee_spear_equipped = query.equipped_item_any_tag('slot.weapon.mainhand', 'minecraft:is_spear');"`.
- 수정한 바닐라 플레이어 컨트롤러·엔티티가 다른 것과 버전이 맞지 않으면 `first_person_melee_spear_controller`, `swimming.no_right_arm` 누락 오류가 난다. bedrock-samples의 최신 바닐라 `player.json`을 쓴다.
- `q.above_top_solid`는 월드 생성 컨텍스트에서만 동작하고("Failed to resolve query"), `query.scoreboard`는 리소스 팩에서 쓸 수 없다.
- `t.` 임시 변수는 플레이어와 어태처블 애니메이션 사이에서 새고 렉에서 리셋된다. `v.x = (v.x == 1) ? 1 : (t.x ?? 0)`처럼 고정하고 누수는 데이터를 보내는 데만 쓴다(MCPE-240457).

## 회전

- 목표를 향하기(투사체 pitch, yaw): 본에 `"rotation": ["query.target_x_rotation","query.target_y_rotation",0]`(화살은 `arrow.animation.json` 복사). `target_y_rotation`이 일부 경우 안 됐다는 보고가 있고, 플레이어 회전에 맞추려 애니메이션으로 돌리는 것은 잘못이니 BP에서 엔티티 회전을 설정한다.
- 탈것의 시각 회전 고정은 `-q.body_y_rotation` 애니메이션 후 `query.movement_direction`, `q.position`, 삼각함수로 직접 계산한다(좌석이 회전 원점이 아니면 문제). `rotation.y = -q.body_y_rotation`으로 몸 일부를 독립적으로 돌리는 것은 불안정했다.
- 컷신에서 머리가 돌지 않으면 루트와 같은 회전을 머리 본에도 적용한다. `playanimation`으로 몸 루트에 준 스케일은 머리에 영향을 주지 않으니 머리에 따로 설정한다.
- 돌고래식 수영 방향은 컴포넌트가 아니라 애니메이션 수식이다(bedrock-samples의 `dolphin.animation.json`).

## 1인칭 애니메이션

- 바닐라 평면 아이템은 1인칭에서 애니메이션에 반응하지 않는다(창, 삼지창, 방패 같은 3D 지오메트리 어태처블만). 3인칭은 동작한다.
- 어태처블이 재생하는 애니메이션은 어태처블에만 영향을 주니 플레이어는 `player.entity.json`으로 애니메이션한다. 1인칭 전용 애니메이션에는 자체 1인칭 컨트롤러 항목이 필요하다.
- 페이퍼돌 렌더링(`v.is_paperdoll`)이 일시정지 화면을 열 때 크래시를 일으킨 사례가 있다.

## 갑옷 거치대와 기타 쿼리

- 갑옷 거치대는 bedrock-samples의 `armor_stand.animation.json`을 복사해 엔티티 `animations`와 `scripts.animate`에서 참조한다. 자세는 runtime identifier 변수에 하드코딩돼 있으므로(12~13개) 자세를 추가하려면 `pose_index` property가 있는 자체 엔티티를 쓴다.
- 이름 의존 애니메이션은 `q.is_name_any('steve','alex')`. 컨트롤러 전환의 `query.is_name_any('Alex')`가 실행되지 않은 사례에는 전환식 끝에 `;`가 있었다.
- 장착 여부로 본 보이기: `1*(query.is_item_equipped(0)||query.is_item_equipped(1))` 스케일.
