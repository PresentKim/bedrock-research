# 렌더링 개요

이 섹션은 Bedrock 리소스 팩이 화면과 소리를 만드는 방식을 다룬다. 엔티티·블록·아이템 모델, 클라이언트 애니메이션과 컨트롤러, 렌더 컨트롤러, 머티리얼과 셰이더, 파티클, 텍스처와 아틀라스, 사운드, Vibrant Visuals(VV)와 PBR, RTX, 그리고 중국판(NetEase)의 종이 인형까지 포함한다. 바탕 자료는 2025-10-22부터 2026-11-13까지의 커뮤니티 조사(커뮤니티 대화의 노트 84개), Bedrock Wiki, Microsoft Learn, bedrock-samples, Particle Jester 저장소, NetEase 문서다.

표기 규칙: `confirmed`는 여러 사람이 확인했거나 문서·코드로 확인한 것, `single report`는 한 사람의 보고, `conflicting`은 보고끼리 어긋나는 것이다. 버전 번호는 게임 버전이며, 2026년 이후 번호(26.30 등)는 새 번호 체계다.

## 핵심 요약

1. **VV 켜기**: 리소스 팩 `manifest.json`의 **최상위**(`header` 안이 아님)에 `"capabilities": ["pbr"]`가 없으면 그 팩이 활성인 동안 VV 옵션이 꺼진다. 애드온 하나만 빠져도 월드 전체 VV가 꺼진다.
2. **PBR**: `<색 텍스처 이름>.texture_set.json`을 텍스처와 같은 폴더에 두고, 값에는 확장자 없는 파일 이름만 쓴다. MER는 R 금속성, G 발광, B 거칠기(255가 완전 거침)이고, MERS는 네 번째 채널이 SSS다.
3. **엔티티 발광**: VV 없이는 `entity_emissive_alpha` 계열(알파가 낮을수록 밝다)을 쓰고, VV에서는 MER 발광 채널과 texture_set과 pbr capability를 쓴다.
4. **블록 발광**: VV 없이 커스텀 블록의 일부 픽셀만 빛나게 하는 방법은 없다. VV에서는 `material_instances`의 `"emissive": true`(포맷 1.21.120+) 또는 MER를 쓴다.
5. **밉맵과 아틀라스**: 먼 곳에서 플립북이 첫 프레임에 멈추거나 줄무늬가 생기거나 물·용암이 깨지는 현상은 대부분 밉맵 때문이다. `num_mip_levels`를 0(또는 3)으로 하고 정사각형·2의 거듭제곱·16의 배수 텍스처를 쓴다. 26.30에서 아틀라스 패딩이 제거된 뒤 줄무늬 버그가 늘었다(MCPE-240144).
6. **엔티티 머티리얼**은 문서가 사실상 Bedrock Wiki뿐이고 버전마다·VV에서 깨진다. 파일 이름은 `materials/entity.material`(`.json` 확장자 없음), 상속은 `"자식:부모"`다.
7. **스텐실**은 아웃라인, 벽 너머 보이기, 포털 효과의 핵심이다. 바닐라 엔티티 그림자가 `stencilRef` 1을 쓰므로 2 이상을 쓰고 32를 넘기지 않는다.
8. **렌더 컨트롤러**의 `textures`는 항상 배열, `geometry`는 문자열이다. 형태가 틀리면 충돌 판정만 있는 투명 엔티티가 된다. 텍스처 배열이 3개를 넘으면 크래시가 났으므로 렌더 컨트롤러를 나눈다.
9. **본·애니메이션 이름**은 소문자에 공백 없이. 공백이나 특수문자가 있으면 Blockbench에서는 보여도 게임에서 렌더링되지 않는다.
10. **어태처블**: 루트 본에 `"binding": "q.item_slot_to_bone_name(c.item_slot)"`을 두고 지오메트리 포맷은 1.16.0 이상이어야 한다.
11. **VV 설정은 바이옴 단위**다. 전 바이옴 기본값은 `minecraft:default_water` 같은 `minecraft:` 식별자로 덮어쓴다.
12. **자동 노출, 그림자 해상도, 반사 품질**은 게임 설치 폴더의 파일에만 있고 리소스 팩으로 바꿀 수 없다.
13. **톤매퍼**: VV에서는 generic, reinhard, reinhard_luminance, reinhard_luma, hable, aces만 쓸 수 있다.
14. **포인트 라이트**는 VV 전용이고 블록만 가능하다(엔티티 불가).
15. **VV의 디퍼드 렌더링은 투명 처리에 약하다**. 투명 파티클(비)은 GPU 시간이 1.6 ms에서 20 ms 이상으로 늘 수 있다.
16. **디더링**: GDK 릴리스(2025-10-31) 이후 카메라가 가까우면 엔티티·어태처블·블록이 디더링되며 사라진다. "모델이 안 보인다"는 보고가 오면 먼저 설정의 접근성에서 끈다.
17. **파티클**: `emitter_rate_manual`에는 항상 `max_particles`(최대 1000)를 지정한다. 없으면 메모리 누수가 크다.
18. **RTX**는 엔티티 PBR, 오버레이 텍스처, 단면 렌더링을 지원하지 않는다. VV와 RTX는 texture_set을 공유하지만 fog 설정은 호환되지 않는다.

## 이 섹션을 읽는 순서

모델을 만들고 게임에 붙이려면 모델과 지오메트리, 애니메이션과 컨트롤러, 렌더 컨트롤러 순서로 읽는다. 빛나는 효과나 투명 효과가 필요하면 머티리얼과 셰이더를 읽고, 그래픽 모드(Simple, Fancy, Vibrant Visuals, 레이 트레이싱)별 차이는 VV와 RTX 페이지에서 찾는다. 증상에서 시작한다면 제한과 우회법 표가 가장 빠르다.
