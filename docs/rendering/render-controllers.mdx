# 렌더 컨트롤러

## 개념

렌더 컨트롤러는 클라이언트 엔티티가 정의한 짧은 이름(shortname)을 받아 "무엇을 어떻게 겹쳐 그릴지"를 정하는 논리 묶음이다. 엔티티 파일이 자산을 *가져오는* 단계라면, 렌더 컨트롤러는 가져온 것을 *사용*하는 단계다. 컨트롤러는 기본 텍스처가 무엇인지 모르고 `Texture.default`라는 이름만 적용한다. 따라서 같은 컨트롤러를 여러 엔티티가 재사용할 수 있고, 지오메트리·텍스처·머티리얼이 각각 하나뿐인 단순 엔티티는 커스텀 컨트롤러가 필요 없다(출처: bedrock-wiki, `entities/render-controllers`).

```json
{
  "format_version": "1.8.0",
  "render_controllers": {
    "controller.render.cow": {
      "geometry": "Geometry.default",
      "materials": [ { "*": "Material.default" } ],
      "textures": [ "Texture.default" ]
    }
  }
}
```

엔티티 파일이 `materials`, `textures`, `geometry`에 `default` 짧은 이름을 정의하고 `"render_controllers": ["controller.render.cow"]`로 참조하면 된다. 이 컨트롤러를 쓰려면 `default` 지오메트리, 텍스처, 머티리얼을 모두 제공해야 한다. `materials` 항목의 `"*"`는 모든 본에 적용한다는 뜻이고, 본 이름이나 와일드카드로 본별 머티리얼을 줄 수 있다.

### 텍스처 레이어와 변형

`textures` 배열은 위에서 아래로 겹친다. 위 레이어에 알파 픽셀이 있으면 아래가 비친다. 레이어는 `villager_v2_masked` 같은 마스크 머티리얼과 함께 쓴다. 변형은 `arrays`로 만든다.

```json
{
  "format_version": "1.10.0",
  "render_controllers": {
    "controller.render.wool_only": {
      "arrays": {
        "textures": { "Array.top": ["Texture.top_1", "Texture.top_2", "Texture.top_3"] }
      },
      "geometry": "Geometry.default",
      "materials": [ { "*": "Material.default" } ],
      "textures": [ "Texture.bottom_layer", "Array.top[query.variant]" ]
    }
  }
}
```

(출처: bedrock-wiki. 바닐라 horse, bee, cat, wolf 렌더 컨트롤러와 bedrock-samples의 `horse_v3.entity.json`이 참고 자료다.) 아래는 커뮤니티 조사에서 모은 규칙이다(출처: 비공개 조사).

## 기본 형태와 오류

- 렌더 컨트롤러 파일에 `geometry`, `textures`, `materials`를 두고 `Geometry.default`, `Texture.default`, `Material.default`를 쓴다. `textures`는 반드시 배열이고 `geometry`는 문자열이다. 형태가 틀리면 충돌 판정만 있는 투명 엔티티가 된다. 변형 배열은 변형 id 순서와 맞춘다. 예: `"textures": ["query.is_baby ? Array.baby[query.variant] : Array.shade[query.variant]"]`. `confirmed`
- 1.8.0식 옛 형식과 새 형식을 혼동하면 "Error parsing render Controllers"가 난다. 렌더 컨트롤러 이름은 클라이언트 엔티티의 텍스처 짧은 이름과 정확히 일치해야 한다. 렌더 컨트롤러 파일에는 `format_version`과 `render_controllers` 래퍼가 필요하다.
- 클라이언트 엔티티에서 `"materials": {"default": "invert_culling"}`처럼 키를 정의하고 렌더 컨트롤러가 그 키를 쓴다. `materials`에 여러 머티리얼을 쓰면 그 이름들이 클라이언트 엔티티에 정의돼 있어야 하고, 아니면 "Mesh Material doesn't exist"가 난다. 모바일에서는 캐시된 팩을 지우고, 개발 폴더의 팩인지도 확인한다.

## 텍스처 배열과 변형

- `"arrays":{"textures":{"Array.skins":["Texture.default","Texture.blue",...]}}`와 `"textures":["Array.skins[query.property('your_skins_property')]"]`(int property, `client_sync: true`)를 쓴다. `minecraft:variant`와 `q.variant`, `query.skin_id`도 된다. 컴포넌트 그룹으로 값을 지정하고 같은 방식이 머티리얼과 지오메트리에도 통한다.
- 이벤트에는 "set_variant"가 없으니 property를 설정하거나 `minecraft:variant` 컴포넌트 그룹을 추가한다.
- 렌더 컨트롤러의 `math.random`, `math.random_integer`는 매 프레임(틱) 다시 굴려져 깜빡인다. `scripts.initialize`나 `pre_animation`에서 한 번만 정한다(예: `"variable.Xvar = query.anim_time>0 ? variable.Xvar : Math.random(0,999);"`를 인덱스로 감싼다). 클라이언트 재로드 때 리셋되므로 재접속하면 바뀐다. 지속적인 변형은 BP property(`query.property`)를 쓴다.
- 레이어 텍스처(말 스타일): `Array.base`, `Array.overlay`에 `v.base = q.variant; v.overlay = q.mark_variant`를 쓰고 `textures`에 두 항목을 둔다. 정의되지 않은 `v.index`는 분홍 머리가 떠다니게 만들었다. 말 갑옷 같은 동적 배열은 `Array.armor[variable.armor_texture_slot]`. 첫 텍스처만 읽혀 쌓이지 않았다는 보고도 있고, 안장 레이어 `query.is_saddled ? Texture.saddle : Texture.empty`는 스레드에서 미해결이었다.
- **텍스처 배열 3개 초과 크래시**: 한 렌더 컨트롤러에 `Array.layerN[query.property(...)]` 텍스처 배열을 3개보다 많이 쓰자 게임이 크래시했다. 여러 렌더 컨트롤러로 나눠 `render_controllers`에 나열한다.

## 조건부 지오메트리와 텍스처

- `"geometry": "query.is_item_name_any(...) ? Geometry.tridentdrowned : Geometry.default"`(`get_equipped_item_name`은 폐기, `q.is_item_name_any`를 쓴다), `query.variant==2 ? Geometry.captain : Geometry.default`. 문자열을 이어 붙여 지오메트리 이름을 만들 수는 없다.
- property가 값과 같을 때만 보이기: `"geometry":"q.property('ns:prop')==2?Geometry.default:Geometry.empty"`(빈 지오메트리).
- 이름 기반: `query.is_name_any('alex','Alex') ? Geometry.x : Geometry.default`, `query.get_name == 'Jade' ? Texture.jade : (...)`(바닐라 토끼 RP 파일 참고). 부분 일치를 피하려면 `query.is_name_any('NAME1')`을 쓴다.
- 죽음 텍스처 해킹: `"textures": ["Array.Textures[!q.is_alive]"]`. 클라이언트 엔티티는 로컬 플레이어가 아니라 엔티티 데이터 기준으로 렌더링한다.
- 프레임 애니메이션 텍스처: `"textures":["Array.frames[query.life_time*24]"]`, `array.frames[Math.mod(math.floor(query.anim_time * 5), 9)]`. 개구리 텍스처 선택에는 `query.variant` 중첩 삼항식이 쓰였다. 애니메이션 활 여러 단계: `"geometry": "array.bow_geo_frames[query.get_animation_frame]"`와 `arrays.geometries`, `arrays.textures`. 대기 플립북과 당김 프레임을 `temp` 수식으로 `textures`에서 합치는 예시는 실패했다.

## uv_anim

```json
"uv_anim": {
  "offset": [0.0, "math.mod(math.floor(query.life_time * 2), 10) / 10"],
  "scale": [1.0, "1/10"]
}
```

- 한 엔티티에 UV 애니메이션 텍스처 여러 개는 렌더 컨트롤러 여러 개(레이어)로 한다. 합친 텍스처는 머티리얼을 고치기 전까지 한 프레임에 멈췄다. 크기가 다른 텍스처에는 `uv_anim.scale`이 필요하다. 한 테스터의 팩에서는 `Math.mod(Math.floor(query.life_time*10),4)/4`가 실패했다.
- 어태처블에서의 동작은 보고가 어긋난다([어태처블과 아이템 렌더링](./attachables-and-items.mdx)). 애니메이션 엔티티 텍스처의 모델 텍스처 크기는 한 프레임 크기(64x256이 아니라 64x64)여야 하고 머티리얼 파일은 `entity.material`이어야 한다. 속도는 `query.life_time * N`으로 정한다(180이 약 1초)([텍스처와 아틀라스](./textures-and-atlases.mdx)).

## part_visibility

```json
"part_visibility": [
  { "*": false },
  { "giant_*": true },
  { "*saddle*": "query.is_saddled" }
]
```

- 와일드카드 본 이름과 Molang을 받는다(`{"Bag*": "query.is_chested"}`, `"*spear*": false`). 모르는 쿼리는 "unrecognized token"을 낸다.
- 본별 텍스처·머티리얼은 렌더 컨트롤러 여러 개와 `part_visibility`로 하는데, 첫 규칙을 `"*": false`로 두고 접두사로 다시 켠다. 본에 모델별 접두사를 붙이면 와일드카드로 숨기기 쉽다.
- part_visibility가 안 먹는 것 같으면 같은 엔티티에서 다른 렌더 컨트롤러가 아직 활성인지 확인한다(원래 것은 조건으로 숨긴다). 두 번째 렌더 컨트롤러에서 `query.property('x')>0`은 되고 `==4`는 안 된 사례가 있다(미해결). `query.distance_from_camera`를 part_visibility에 쓰는 것은 안 됐다.
- `part_visibility: false`(Molang이 아닌 값)는 지오메트리를 진짜로 컬링하지만, Molang으로 숨긴 본은 여전히 드로 콜을 제출한다(래스터라이저만 컬링).

## 여러 렌더 컨트롤러

- 엔티티와 어태처블 모두 `render_controllers`에 여러 개를 나열할 수 있고 한 엔티티에서 두 지오메트리를 동시에 그릴 수 있다. 렌더 컨트롤러는 여러 번 쌓을 수 있다.
- 바닐라 지오메트리를 숨기려면 모든 본을 숨기는 part_visibility를 가진 렌더 컨트롤러 사본을 앞에 둔다.
- 플레이어 모델을 다른 것(예: T-Rex)으로 바꾸려면 플레이어 렌더 컨트롤러를 고쳐 지오메트리 하나만 쓰게 한다(플레이어를 여전히 그리는 추가 컨트롤러는 안 된다). property로 플레이어 지오메트리를 바꾸려면 쿼리로 새 렌더 컨트롤러를 켜고 바닐라 것에는 `&& !query...`를 붙인다.
- 코스메틱: BP 플레이어 정의에 슬롯별 enum property(예: head는 none, hat1, hat2)를 `client_sync`로 만들고 `{ "controller.render.cosmetic_1": "v.cosmetic_1" }` 같은 조건으로 추가 렌더 컨트롤러를 나열한다.

## 1인칭과 3인칭

1인칭 렌더 컨트롤러는 3인칭과 별개라 필요하면 둘 다 정의한다. 1인칭에서 플레이어 머리가 보이면 1인칭 렌더 컨트롤러에서 head와 hat 파트를 false로 한다.

## 색과 틴트

- `overlay_color`(rgba)는 위에 블렌드되며 알파에 영향을 주지 않는다. `color`는 알파를 포함한 곱셈이고, 특정 runtime-id 엔티티(warden, player 등)나 이를 지원하는 머티리얼에서만 동작한다(염색 파트는 `entity_alpha_color_change` 머티리얼).
- 엔티티별 틴트: `overlay_color`를 `q.property('ct:r')` 등(r, g, b, a)으로 구동하고 엔티티 JSON에 property를 정의한 뒤 스크립트 `entity.setProperty("ct:r", 0.5)`로 설정한다(`player.json` 수정으로 플레이어에도 동작). `"overlay_color": {"r": "array.red[query.property('x')]", ...}`처럼 property 배열도 된다. `Math.sin`을 쓴 overlay 식은 깜빡이는 알파를 준다(`a`는 Molang 문자열).
- 1.21.130 쇼케이스에서는 overlay가 아니라 텍스처 교체로 색을 바꿨다. 크리퍼 깜빡임도 렌더 컨트롤러 오버레이 색이다. 염색 목걸이 틴트가 낮은 불투명도 기본 텍스처로 번지는 문제는 미해결이다.
- 피격 색 제거: `"is_hurt_color": {"r":"1.0","g":"1.0","b":"1.0","a":"0.0"}`. 죽을 때 기울어지는 것은 이 방법으로 없앨 수 없다.
- 참고 문서: Microsoft Learn의 animation render controller 문서.

## 액터 없는 쿼리 문제

페이퍼돌·UI에서 "has_property doesn't have an actor"를 피하려면 클라이언트 엔티티 `pre_animation`에서 `v.class = q.is_on_screen ? q.property('prefix:class') : v.fallback;`을 설정하고 `initialize`에 `v.fallback = 0`을 두며, 렌더 컨트롤러에서는 `v.class`를 쓴다. `player.entity.json` 변수에서도 액터가 없는 곳의 `query.property`는 "does not have an actor"를 낸다. 렌더 컨트롤러 조건에는 `query.`가 아니라 `context.is_first_person`을 쓴다.

## 팀별 플레이어 가시성

`player.json`과 클라이언트 애니메이션에서 `variable.invisible = temp.self_team != query.property('visible:team') && query.property('visible:invisible')==1;`과 client_sync property를 쓰고, 렌더 컨트롤러에서 투명 머티리얼로 바꾼다. `temp`는 플레이어별이다. 몹에는 이 방법을 쓸 수 없으니 특정 플레이어로 제한한 스크립트 `playAnimation`을 쓴다. 플레이어별 가시성으로 엔티티 클라이언트 애니메이션을 재생하는 `setPropertyOverrideForEntity`(서버 모듈 2.6.0 `Player` 클래스)도 있다.

## 성능

렌더 컨트롤러를 많이 쓰면(모델 75개 x RC 5개) 크래시하거나 느려진다. 1200개 대 40개의 RAM 영향 질문은 답이 없었다.
