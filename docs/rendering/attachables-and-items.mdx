# 어태처블과 아이템 렌더링

(출처: 비공개 조사)

## 언제 필요한가

16x16보다 크거나 3D인 아이템, 긴 도구, 3D 활·석궁에는 어태처블이 필요하다. 어태처블은 리소스 팩 `attachables/*.json`이고 아이템과 같은 `identifier`를 쓴다. 기본 구성은 다음과 같다.

- `render_controllers`: `["controller.render.item_default"]`
- `materials`: `default`는 `entity_alphatest`, `enchanted`는 `entity_alphatest_glint`
- `textures`: `default`와 `textures/misc/enchanted_item_glint`
- `geometry`, `animations`
- `scripts.animate`: `first_person_hold`는 `c.is_first_person`, `third_person_hold`는 `!c.is_first_person`

바닐라 아이템을 3D 모델로 바꾸려면 어태처블 식별자를 바닐라 것으로 한다(예: `minecraft:mace`). 오류 없이 아이템이 안 보이면 바닐라 어태처블(예: 활)을 복사해서 조금씩 고친다. 커스텀 횃불 어태처블이 조용히 실패하다가 콘텐츠 로그로 원인을 찾은 사례가 있다.

## 바인딩

- 지오메트리 루트 본에 `"binding": "q.item_slot_to_bone_name(c.item_slot)"`이 필요하다. `binding`은 지오메트리 포맷 1.16.0 이상이어야 한다(1.12.0은 무시해서 아이템이 발밑에 생긴다). `confirmed`.
- 바인딩된 최상위 본은 하나만 두고 나머지는 자식으로 둔다. 플레이어 본과 같은 이름(`body`)은 바꾼다.
- Blockbench에서는 루트 폴더 우클릭, Edit binding, item slot 순서다.
- 바인딩이 어긋나 보이면 아이템 본들을 감싸는 루트 본을 추가한다. 어태처블 본 구조는 플레이어의 손 본을 따라야 한다. `q.item_slot_to_bone_name('leftArm')`처럼 플레이어 지오메트리(`humanoid.geo.json`)의 본 이름에 바인딩할 수도 있다.
- 아이템이 플레이어 발밑이나 가운데에 렌더링되면 손 바인딩이 없는 것이다(바닐라 활 샘플 참고). 애니메이션 파일도 필요하다.

## 위치 맞추기

- 위치·회전·크기는 어태처블 애니메이션에서 1인칭과 3인칭을 나눠(`c.is_first_person`) 잡는다. 피벗이 회전 원점을 바꾸고, `visible_bounds` 밖이면 1인칭에서 안 보인다.
- Blockbench의 정렬과 1인칭·3인칭 원근 미리보기는 근사일 뿐이므로 게임에서 축별로 이분 탐색하며 조정한다.
- 아이템 모델을 인간형 모델에 임포트하려면 Edit, Import, Import recent geometry를 쓰고, X로 텍스처를 숨긴 뒤 1인칭·3인칭 애니메이션을 만든다. Item Wizard Blockbench 플러그인이 재사용할 어태처블 애니메이션을 만들어 준다.
- 스킨의 망토 때문에 무기가 무작위로 어긋난 사례가 있다.

## 큐브 수와 texture mesh

- 큐브가 수백 개면 렉이 걸리거나 손을 따라가지 않는다. `texture_meshes` 본(`texture`는 `default`, `position`, `rotation`, `local_pivot`, `scale`, 포맷 1.16.0)으로 바꾼다.
- 대형 아이템 템플릿은 본 `rightitem`, `local_pivot [7,0,7]`을 쓴다. 옆 픽셀이 빠진 큐브 지오메트리는 texture mesh로 다시 만들어 고쳤다.
- `texture_meshes`는 텍스처당 지오메트리 하나가 필요하고(가변 텍스처 불가) geo들을 한 파일에 합칠 수는 있다.
- 인챈트된 고큐브 블록 모델 무기(256큐브 16x16 템플릿)는 FPS를 떨어뜨린다.
- PBR에서 texture mesh는 블록 모델에서 조용히 나타나지 않는다(문서 없음, 버그일 수 있음)([VV와 RTX](./vibrant-visuals-and-rtx.mdx)).

## 휘두르기와 공격 애니메이션

- 포맷 1.10 아이템(어태처블 아님)은 정상적으로 휘두르지만 대형 어태처블은 플레이어 공격 애니메이션이 팔을 움직여 이상하게 휘두른다.
- `player.entity`를 고치지 않는 방법: 1인칭에서 모델 바인딩을 풀고 직접 배치한 뒤 `c.owning_entity->v.attack_time > 0`일 때 애니메이션한다.
- 또는 `animation.player.first_person.attack_rotation`을 `query.equipped_item_any_tag('slot.weapon.mainhand','tag') ? 0 : normal`로 고치거나, 어태처블에서 반대로 상쇄한다(Actions & Stuff 팩과 충돌).
- `variable.attack_time`은 어태처블 애니메이션에서 쓸 수 없으니 `player.entity.json`에서 public으로 만들고 `c.owning_entity->variable.attack_time`을 쓴다.
- 무기를 든 플레이어 자세는 플레이어 애니메이션 컨트롤러를 `q.is_item_name_any('slot.weapon.mainhand','<id>')`로 고친다.

## 활과 석궁

- 커스텀 석궁·활 1인칭 애니메이션은 아이템 식별자에 의존한다. 식별자가 정확히 `crossbow`여야 하고(`ns:crossbow`는 되지만 접미사를 붙이면 깨진다) 하드코딩이다. Mojang이 나중에 사격 무기 버그 3개 중 2개를 고쳤다.
- 활 어태처블 `pre_animation`:

```json
"pre_animation": [
  "variable.charge_amount = math.clamp((query.main_hand_item_max_duration - (query.main_hand_item_use_duration - query.frame_alpha + 1.0)) / 10.0, 0.0, 1.0f);"
]
```

그리고 `query.main_hand_item_use_duration > 0.0f && c.is_first_person` 조건으로 `wield_first_person_pull`을 애니메이션한다.

## 보조손

- 위치가 다르니 `leftItem`을 빼고 `c.item_slot`으로 변환을 바꾼다. 바닐라 낚싯대 어태처블은 samples에 없다(보조손 텍스처 뒤집힘 수정에는 새 어태처블이 필요).
- `leftItem`이 `rightItem`보다 반응이 없다는 보고가 있고, 플레이어 지오메트리를 바꾸면 아이템 피벗이 깨진다(MCPE-177602). 보조손 지도의 위치·크기는 geo 파일의 손 앵커나 지도 애니메이션을 바꾼다.
- 한 어태처블이 한 아이템의 여러 data value를 다룰 수는 없다.
- 리소스 팩에서도 `query.is_item_name_any('slot.weapon.mainhand',0,'ns:item')`로 주손·보조손 모델을 고를 수 있다(손 아이템 쿼리가 BP 전용이 아니다).

## 손에서 숨기고 아이콘만 남기기

큐브 없는 어태처블, 빈 텍스처, 또는 스케일 0 애니메이션을 쓴다.

## 3D 아이템을 인벤토리·땅·액자에

- 같은 식별자의 블록과 아이템을 만들고 아이템에 `minecraft:block_placer`의 `replace_block_item: true`를 쓴다(공기에 `use_on`으로 설치할 수 없다).
- Blockbench 블록 Display 탭으로 GUI를 미리 보고 face dimming을 끈다. 광택에는 opaque render method가 필요하고 손·땅 광택에는 어태처블이 필요하다. 크기 초과 블록은 폐기됐다.
- 아이템 모델에 제대로 된 display transform이 없으면 손에서 풀 큐브로 렌더링된다.
- `item_display_transforms`는 1.26.40에서 버그가 있었고 .40과 .50에서 다르게 깨졌다. 반 블록 인벤토리 아이콘 정렬 문제는 프리뷰에서 고쳐졌지만 Pocket UI에서는 어긋났다. 블록 모델 크기는 변환 전에 검증되고(MCPE-236317), 아이템 아이콘 면 셰이딩은 display transform 전에 적용된다(MCPE-235788). 3인칭 회전 수정(3인칭에서 180도 돌아간 블록 수정)이 머리·계단·heavy core의 잡는 각도를 바꿨고 바닐라 머리 display transform은 이상하다.

## 광택(glint)

어태처블에서는 `entity_alphatest_glint` 머티리얼이나 `minecraft:glint`(항상 켜짐)를 쓴다. 갑옷식 렌더 컨트롤러는 인챈트됐을 때만 보인다.

## 애니메이션 아이템 텍스처

- 아이템 텍스처 애니메이션은 불가능하다. 본 보이기 애니메이션, 렌더 컨트롤러 텍스처 교체, 설치할 수 없는 애니메이션 블록으로 흉내 낸다.
- 어태처블의 커스텀 머티리얼은 존중되지 않는다는 보고(2026-01)가 있다.
- 어태처블에서 렌더 컨트롤러의 `light_color_multiplier`, `overlay_color`, `held_item_ignores_lighting` 같은 필드는 동작하지 않는다. 어태처블 색을 `color`나 `overlay_color`로 바꾸는 방법은 답이 없었다.
- `uv_anim`은 어태처블에서 안 된다는 노트(2025-10)와, 어태처블 렌더 컨트롤러의 `uv_anim`(`offset: [0,"math.mod(math.floor(query.life_time*12),12)/12"]`, `scale:[1,"1/12"]`)이나 프레임별 텍스처 배열로 플립북이 된다는 노트(2026-06)가 어긋난다(`conflicting`, 최신 보고는 동작).

## 글로우

빛나는 부분에는 `entity_emissive_alpha`, 언셰이드 글로우에는 `breeze_wind_charge`를 쓴다. VV에서는 texture set PBR과 리소스 팩 manifest의 `"capabilities": ["pbr"]`가 필요하다([머티리얼과 셰이더](./materials-and-shaders.mdx)).

## 조명 끄기

- 렌더 컨트롤러 `ignore_lighting`이 어태처블에서 안 된다는 노트와, `ignores_lighting`에 머티리얼 `"-defines": ["FANCY"]`를 함께 쓰면 된다는 노트가 어긋난다(`conflicting`).
- `filter_lighting: false`는 "Value 'false' not allowed"로 거부되고 `true`만 받는다. 손에 든 아이템 글로우는 클라이언트 엔티티 `held_item_ignores_lighting`(bedrock-samples 프리뷰의 `allay.entity.json` 참고)인데, `held_item`을 참조하는 것은 모두 어태처블을 제외하므로 어태처블 자체를 발광 머티리얼로 만든다. 어태처블은 전반적으로 버그가 많다(MCPE-241087).

## 파티클과 사운드

- 어태처블 애니메이션의 파티클은 동작하지만 커스텀 로케이터에서는 안 된다(Mojang 버그). 어태처블은 새 로케이터를 추가할 수 없으니 플레이어 로케이터(`lead_hold` 등, 플레이어 팔 lead 로케이터 재사용)나 오프셋을 쓴다.
- 어태처블 파티클의 로케이터는 머리가 아닌 몸 Y 회전을 가진 body 루트가 된다. 1인칭에서는 FOV 때문에 로케이터가 밀리고, 애니메이션 사운드가 재생되지 않을 수 있다.
- 트릭: 플레이어 렌더 컨트롤러로 (로케이터가 있는) 플레이어 모델을 그리고 애니메이션을 연결한다. 방향성 파티클은 Molang으로 방향을 넘기거나 플레이어 머리의 로케이터에 파티클을 묶는다.

## 코스메틱 어태처블(아이템 없이)

- 렌더 컨트롤러 조건 `query.property('ns:cosmetic')=='hat'`과 `entity.setProperty`를 쓴다.
- 3인칭에서만 애니메이션: `scripts.animate` 항목 `{"third_person": "!c.is_first_person"}`.
- 상태 조건: 렌더 컨트롤러 `part_visibility`·`geometry` 조건(예: `q.property('seal:scope') == 'dot_sight'`).
- 총 조준경 효과는 변형·태그(웅크릴 때 태그)로 조준경 모델을 보이는 렌더 컨트롤러를 쓰거나 `player.json`으로 조준경을 머리에 붙인다.
- 쿨다운 동안 손 아이템 텍스처를 바꾸려면 남은 쿨다운 쿼리를 어태처블 렌더 컨트롤러에서 쓴다(인벤토리 아이콘은 아니다).

## 갑옷

- `controller.render.armor`는 옛것이다. `controller.render.armor.v2`(인간형 몹)와 `controller.render.armor.player`(플레이어, 별도 파일 필요)를 쓴다.
- 갑옷 지오메트리는 `models/entity/`에 두고 렌더 컨트롤러 part visibility가 각 본을 켜야 한다. 애니메이션 갑옷은 `.player` 식별자를 가진 어태처블에 애니메이션을 추가한다.
- 갑옷 어태처블(포맷 1.21.130)의 빈 `pre_animation: []`이 오류를 내서 지우자 해결됐다.
- 일부 스킨에서 커스텀 갑옷 팔 본이 따라오지 않는 문제에 폴더 이름 변경이 제안됐다(`unverified`).
- 몹에 갑옷·아이템을 렌더링하려면 클라이언트 엔티티에 정확히 `"enable_attachables": true`가 있어야 한다. 철자가 틀리면 엔티티가 투명해진다. 손에 든 것과 입은 것 두 지오메트리가 겹치면 렌더 컨트롤러 조건과 쿼리로 고친다.
- 겉날개: 망토 텍스처가 겉날개 텍스처 전체를 덮어쓰고, 추가 지오메트리 텍스처는 망토와 함께 깨진다(미해결).
- VV에서 바닐라 갑옷 장식을 MERS PNG로 발광시키려 한 시도(min_engine 1.26.0, PBR·VV capability 설정)는 빛나지 않았다(미해결).

## 낚싯줄

바닐라 같은 낚싯줄은 재현할 수 없으니 파티클이나 현수선(cosh, sinh, tanh) 수식을 쓴 엔티티 선을 쓴다.

## 아이템 텍스처 크기

- 아이콘은 16x16이어야 한다. 32x32 무기 텍스처에는 맞는 지오메트리·텍스처 크기와 어태처블 텍스처 키가 필요하다.
- 16x16보다 큰 아이템 스프라이트(예: 20x20)는 인벤토리 칸에서 축소되고, 엔티티 아이템 아이콘 배경 크기는 내림 처리된다(최대치 미상).
- 16x16보다 큰 아이템 텍스처가 거대해지거나 잘리던 버그는 2026-01-13 무렵 프리뷰에서 고쳐졌고, 크기 초과 2D 손 아이템 버그는 "곧 수정"이라고 했다(2026-04-12).

## 기타

- 투명 아이템 액자는 리소스 팩에 빈 아이템 액자 텍스처를 넣는다.
- 투척·잔류 포션 텍스처의 가장자리에 픽셀이 있으면 그 행에 가로줄이 생긴다.
- 아웃라인과 인챈트 광택을 함께 유지하는 방법, 어태처블 스텐실은 [머티리얼과 셰이더](./materials-and-shaders.mdx)의 스텐실 절을 본다.
