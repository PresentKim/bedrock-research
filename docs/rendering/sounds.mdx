# 사운드

이 페이지는 커뮤니티 조사에 사운드 절이 없어서 Bedrock Wiki(커밋 0930b39)와 Microsoft Learn(a9fd1c0)을 읽고 새로 채웠다. 마지막에 커뮤니티 조사의 사운드 관련 단편을 붙인다.

## 개념

사운드는 네 층으로 이뤄진다.

- **사운드 파일**: `.wav`, `.ogg`, `.fsb`. 동시에 최대 32개까지 재생된다(출처: ms-learn, Introduction to Sounds).
- **사운드 이벤트**(짧은 이름): 파일 하나 이상을 묶은 게임 안의 사건이다. 같은 파일이 여러 이벤트에 들어갈 수 있다(`mob.drowned.sim`과 `random.swim`이 `sounds/random/swim1`을 함께 쓴다).
- **카테고리**: 엔진이 사운드를 어떤 채널로 재생할지 정하는 분류(날씨는 ambient의 하위)이고 설정의 볼륨 슬라이더와 이어진다.
- **거리**: `min_distance`와 `max_distance`로 감쇠를 조절한다. 기본은 최소 1.0 m, 최대 10,000 m다. `volume`은 세기가 아니라 "이 거리 안에 있어야 재생을 시도한다"는 범위로도 작용하며, 기본으로 청취자가 소리 근원에서 16블록 이하여야 한다.

바닐라의 모든 사운드는 bedrock-samples `resource_pack/sounds`에서 구조를 참고할 수 있다.

## 두 파일

리소스 팩에서 사운드를 추가할 때 건드리는 파일은 두 개다. `sound_definitions.json`은 `sounds` 폴더 안에, `sounds.json`은 팩 루트에 둔다. 사운드 파일은 `sounds/` 아래에 둔다(출처: bedrock-wiki `concepts/sounds`).

```
RP/sounds/example.ogg
RP/sounds/sound_definitions.json
RP/sounds.json
```

### sound_definitions.json: 짧은 이름을 파일에 잇기

<Excerpt src="bedrock-wiki" title="Sounds" path="docs/concepts/sounds.md">

```json
{
    "format_version": "1.14.0",
    "sound_definitions": {
        "example.toot": {
            "category": "neutral",
            "sounds": ["sounds/trumpet"]
        }
    }
}
```

</Excerpt>

이렇게 만든 사운드는 `/playsound`로 재생한다. `playsound`는 자동 보정이 없으므로 이름 오타에 주의한다. 새 파일 경로(사운드 등)는 **월드 새로고침이 아니라 클라이언트 전체 재시작**이 있어야 로드된다.

`sounds` 배열에 여러 항목을 넣으면 재생할 때 무작위로 고른다. 항목은 문자열이거나 객체이며 섞어 쓸 수 있다.

| 키 | 뜻 |
| --- | --- |
| `category` | 최상위 키. `block`, `bottle`, `bucket`, `hostile`, `music`, `neutral`, `player`, `record`, `ui`, `weather`. `ui`는 범위 제한을 무시한다 |
| `min_distance` | 이 거리 이후 감쇠를 시작한다. 기본 0.0. 반드시 float(예: `1.0`)여야 하고, 아니면 무시된다 |
| `max_distance` | 이 거리 이후 가장 조용하다. 반드시 float |
| `name` | (객체 항목) 파일 경로. 예: `sounds/music/game/creative/creative1` |
| `stream` | 동시 재생 수를 제한하고 전체를 메모리에 올리지 않고 조각으로 읽는다. 사운드가 많은 월드의 성능에 좋다 |
| `volume` | 0.0~1.0, 기본 1.0. 인코딩된 것보다 크게 만들 수 없다. 커스텀 리소스 팩에서는 1.0보다 큰 값이 동작한다는 설명도 있다 |
| `pitch` | 양수. 2.3이면 2.3배 빠르고 높게 재생. 기본 1.0 |
| `is3D` | true면 방향성. 기본 true. `music`과 `ui`에서는 무시. false일 때만 스테레오 |
| `interruptible` | 기본 true |
| `weight` | 정수. 목록에서 선택될 상대 확률(10과 2이면 83.3% 대 16.7%). 기본 1 |
| `subtitle` | 자막(Closed Captions)에 보일 현지화 키 |
| `load_on_low_memory` | 메모리가 부족해도 강제 로드. 1.16.0부터 폐기 |

더 현실적인 예:

```json
"block.beehive.drip": {
    "category": "block",
    "max_distance": 8,
    "sounds": [
        { "name": "sounds/block/beehive/drip1", "load_on_low_memory": true },
        "sounds/block/beehive/drip2",
        "sounds/block/beehive/drip3"
    ]
}
```

### sounds.json: 게임 이벤트에 자동으로 잇기

`sounds.json`은 정의를 게임 이벤트에 묶어 `/playsound` 없이 자동 재생한다. 최상위 카테고리는 `block_sounds`(블록의 hit, step, break), `entity_sounds`(엔티티의 death, ambient, hurt 등. 커스텀 엔티티 포함), `individual_event_sounds`(신호기 활성화, 상자 닫힘, 폭발 등), `interactive_sounds`(미완성)다. 엔티티에서 흔한 이벤트는 다음과 같다.

| 이벤트 | 뜻 |
| --- | --- |
| `ambient` | 무작위로 나는 소리(꿀꿀, 꼬꼬 등) |
| `attack`, `attack.strong` | 근접 공격, `behavior.delayed_attack` 공격 |
| `cast.spell`, `prepare.attack` | 소환 시작, 소환 끝 |
| `death`, `hurt` | 죽음, 피해 |
| `fall.big`, `fall.small` | 높은 곳, 낮은 곳에서 착지 |
| `roar`, `shoot`, `splash`, `step` | 포효, 발사, 물에 첨벙, 걸음 |

그 밖에 `ambient.in.water`, `breathe`, `death.in.water`, `eat`, `hurt.in.water`, `jump`, `mad`, `scream`, `sleep`, `sniff`, `spit`, `stare`, `swim`, `warn` 등이 있으나 자동 발동 조건은 위키도 확인하지 못했다.

```json
{
    "entity_sounds": {
        "entities": {
            "wiki:elephant": {
                "volume": 1,
                "pitch": [0.9, 1.0],
                "events": {
                    "step": { "sound": "elephant.step", "volume": 0.18, "pitch": 1.1 },
                    "ambient": { "sound": "elephant.trumpet", "volume": 0.11, "pitch": 0.9 }
                }
            }
        }
    }
}
```

## 바닐라 사운드 교체

바꾸려는 바닐라 파일을 bedrock-samples에서 찾아 같은 폴더 구조를 팩에 만들고, **확장자 앞 파일 이름이 정확히 같은** 파일을 둔다. 형식은 달라도 된다(`rain1.fsb`를 `rain1.ogg`로 대체할 수 있다). 예를 들어 상자 열림은 `sounds/random/chestopen`이다. 이벤트 자체를 바꾸거나 새 이벤트를 만들려면 위의 두 파일을 쓴다. 예: `sounds.json`에 `"individual_event_sounds": {"events": {"chest.open": {"pitch": [0.9, 1.0], "sound": "random.chestopen", "volume": 0.5}}}`로 이벤트를 정의한다(출처: ms-learn, Add Custom Sounds). 오디오는 Audacity 등 `.ogg`로 내보낼 수 있는 어떤 도구든 된다.

## `/playsound`의 볼륨과 범위

(출처: bedrock-wiki)

- 게임은 명령의 볼륨을 1.0으로 자른 뒤 사운드 정의의 `volume`과 곱한다. `/playsound`에서 들을 수 있는 최대 거리는 `min(max_distance, max(volume * 16, 16))`이다. 정의에 `max_distance`가 없으면 `playsound` 볼륨 x 16과 같다.
- 최종 볼륨은 `min(playsound_volume, 1) * graph_volume * sound_definition_volume`이다. 여기서 `graph_volume`은 거리에 따른 감쇠 계수로, 선형이 아닐 수 있는 근사 그래프다.
- 명령의 볼륨 인자는 들리는 소리의 거리별 감쇠 모양에는 영향을 주지 않고 가청 범위만 늘린다. 예: `mob.ghast.affectionate_scream`은 `min_distance: 100.0`이지만 볼륨 1로 `/playsound`하면 최대 16블록까지만 들린다. 볼륨을 크게 주면 더 멀리서 들리고, 100.0을 넘는 거리에서야 작아지기 시작한다.
- 멀리서도 들리면서 거리에 따라 계속 작아지는 소리를 만들려면 정의에 `"volume": 0.01`처럼 작은 값을 두고 명령에 큰 볼륨(예: 4는 64블록)을 쓴다. 높은 명령 볼륨은 가청 범위를, 낮은 정의 볼륨은 소리가 일찍 1.0에서 막히는 것을 막는다.

## 애니메이션과 컨트롤러에서 사운드 재생

사운드는 클라이언트 엔티티의 짧은 이름 정의를 거쳐 재생된다. 먼저 엔티티 파일에서 짧은 이름을 사운드 정의에 잇고:

```json
"sound_effects": { "wing_flap": "wiki.dragon.wing_flap" }
```

애니메이션 키프레임에서 시간에 맞춰 부른다.

```json
"sound_effects": { "3.16": { "effect": "wing_flap" } }
```

애니메이션 컨트롤러에서는 상태 안에서 같은 방식으로 부른다.

```json
"explode_state": {
    "sound_effects": [ { "effect": "explosion" } ],
    "transitions": [ { "default": "q.mark_variant == 0" } ]
}
```

(출처: bedrock-wiki. 지연 반복 사운드와 BP 애니메이션 쪽 사용은 [애니메이션과 컨트롤러](./animations-and-controllers.mdx)를 본다.)

## 서버 사운드 정의 (BP, 베타)

비헤이비어 팩에도 `BP/sounds/sound_definitions.json`이 있지만 이름만 같을 뿐 형식과 목적이 완전히 다르다. 스크립트로 재생하는 사운드에 길이, 음악 정보 같은 메타데이터를 붙인다. **오디오를 등록하지는 않는다.** 사운드 이벤트는 반드시 리소스 팩의 `sound_definitions.json`에 커스텀 사운드로 있어야 한다. 바닐라는 서버 사운드 정의 파일을 제공하지 않으며, `sound_event_name`은 네임스페이스가 있어야 하므로 바닐라 이벤트(`random.pop` 등)에는 정의를 붙일 수 없다(출처: bedrock-wiki `concepts/server-sounds`).

```json
{
    "format_version": "beta",
    "minecraft:server_sound_definitions": [
        {
            "sound_event_name": "wiki:my_cool_song",
            "duration_info": { "mode": "game_time", "seconds": 180.0 },
            "music_info": { "genres": ["electronic"], "moods": ["calm"], "artist": "A", "title": "T" },
            "tags": { "category": "background", "regions": ["overworld", "nether"] },
            "broadcast_range": 64
        }
    ]
}
```

| 키 | 뜻 |
| --- | --- |
| `sound_event_name` | 필수. 네임스페이스가 있어야 하며 공백 불가, 대소문자 무시 |
| `duration_info` | 선택. `seconds`(float)와 `mode`(`game_time`은 틱 기준이라 일시정지·틱 속도 저하에서 멈추고, `real_time`은 벽시계 시간). 있으면 둘 다 필수 |
| `music_info` | 선택. `genres`, `moods`(배열), `artist`, `title`(문자열) |
| `tags` | 선택. 태그 이름에서 문자열 또는 문자열 배열로 가는 맵. 공백 불가. 게임은 해석하지 않고 스크립트의 필터용 |
| `broadcast_range` | 선택. XZ 거리(블록). `dimension.playSound()`를 대상 플레이어 없이 방송할 때 이 수평 범위 안의 플레이어만 받는다 |

스크립트 API(`@minecraft/server`의 `beta`): `world.soundDefinitionRegistry.getDefinitions(filter?)`(필터는 `minDuration`, `maxDuration`, `genres`, `moods`, `artists`, `titles`, `tags`. 문자열은 대소문자 무시, 배열은 하나라도 겹치면 일치), `SoundDefinition`(`soundEventId`, `durationInfo`, `musicInfo`, `tags`), `player.playSound(definition)`(정의 객체나 ID 문자열), `SoundInstance`(`id`, `soundEventId`, `recipient`, `durationInfo`의 `isActive`와 `getPlaybackPosition()`), `world.afterEvents.soundCompleted`(선언한 길이가 지나면 발생, `soundInstanceId`가 `SoundInstance.id`와 일치).

```js
import { world } from "@minecraft/server";

world.afterEvents.playerSpawn.subscribe(({ player, initialSpawn }) => {
    if (!initialSpawn) return;
    const songs = world.soundDefinitionRegistry.getDefinitions({ moods: ["calm"], minDuration: 60 });
    if (songs.length === 0) return;
    const song = songs[Math.floor(Math.random() * songs.length)];
    const instance = player.playSound(song);
    const done = world.afterEvents.soundCompleted.subscribe(({ soundInstanceId }) => {
        if (soundInstanceId !== instance.id) return;
        world.afterEvents.soundCompleted.unsubscribe(done);
    });
});
```

이 클래스들은 베타라 프리뷰마다 바뀔 수 있다.

## 커뮤니티 조사의 사운드 관련 단편

(출처: 비공개 조사)

- 1.21.90부터 사운드가 카메라 거리로 감쇠하며, 카메라와 플레이어 중 청취자를 고를 수 없다(던전식 카메라).
- 파티클 이벤트의 사운드는 Snowstorm 문서상 바닐라 사운드 이벤트만 쓸 수 있고(버그), 서버 측에서 사운드를 재생하는 문제는 열린 질문이다.
- 어태처블 애니메이션의 사운드는 1인칭에서 재생되지 않을 수 있다([어태처블과 아이템 렌더링](./attachables-and-items.mdx)).
- RP 애니메이션 컨트롤러는 명령을 실행하지 못하므로 지연 반복 사운드는 루프 BP 애니메이션 안에서 재생하고 컨트롤러로 켜고 끈다.
