## 2. 이미 알던 것을 다시 확인한 것

새 정보는 아니지만 근거가 재구성 코드(`CN`)에서 실제 바이너리로 바뀌었다.


새 정보는 아니지만 근거가 재구성 코드(`CN`)에서 실제 바이너리로 바뀌었다. 가이드에서는 출처를 `NB`로 적었다.

- 팩토리는 `control_name`을 먼저 읽고, 비어 있을 때만 `control_ids`를 읽는다(NB-06, COL-28·COL-43).
- `insert_location`은 기본 `back`, 값이 `front`일 때만 앞이다(NB-06, CN-43).
- `array_name`이 비어 있고 `control_name`이 있으면 `controls`가 대상이다(NB-03, CN-10).
- view 바인딩은 `source_control_name`이 없으면 자기 컨트롤을 읽고, 두 스코프를 함께 켜면 형제 범위로 동작한다(NB-09, BND-24·BND-25). 새로 안 것은 그때의 오류 문구(`resolve_ancestor_scope and resolve_sibling_scope cannot both be set!`)뿐이다.
- `button.menu_*` 31개 중 27개는 바닐라도 쓴다(R-09의 4개 제외).
- `grid_rescaling_type` 값 후보 `horizontal`, `vertical`, `none`은 공식 enum과 같다(NB 4장).


## 3. 리버싱으로도 아직 못 얻은 것


엔진 내부 장의 각 페이지 끝 "남은 것"에 있다. 요약하면 바인딩 식 평가기(연산자, `'%.Ns'`), `binding_type` 문자열 해석과 기본값, `$x|default`가 들어가는 단계, `#hyperlink` 접두사 목록의 조건 함수, `grid_rescaling_type`·`propagate_alpha`·`clip_direction`을 읽는 함수다. 식 규칙(가이드 5장)은 여전히 실측과 `CN`이 근거다.


## 4. 근거 수준과 사용법

| 수준 | 이 장에서의 뜻 |
| --- | --- |
| `코드` | 컴파일 결과를 읽었다. 엔진이 그렇게 읽는다는 뜻이지 게임 화면 결과까지 보장하지는 않는다 |
| `추론` | 함수 일부나 타입 이름만 읽고 판단했다 |
| `실측` | 같은 주제를 Windows 1.26.52에서 게임으로 확인했다(`OL`, `MS`, `DF`) |

규칙이 `코드` 수준이면 쓰기 전에 게임에서 확인한다. 바이너리 결과와 게임 실측이 다르면 실측을 따른다.
